Lecture Summary

This lecture develops classical search as the computational heart of problem-solving agents. After a concise recap of PEAS and agent architectures, the five problem components — initial state, actions, transition model, goal test, and path cost — are used to define state-space graphs and search trees.

Uninformed (blind) strategies are analysed systematically. Breadth-first search (BFS) expands the shallowest nodes first and is optimal when step costs are uniform. Depth-first search (DFS) uses less memory but risks infinite loops and non-optimal solutions. Uniform-cost search (UCS) generalises BFS to non-uniform costs by expanding the lowest g(n) first, guaranteeing optimality with non-negative costs. Iterative deepening search (IDS) combines DFS memory advantages with BFS-like completeness.

Informed search introduces heuristics h(n) to estimate cost-to-goal. Greedy best-first search orders by h(n) alone — fast but not always optimal or complete. A* uses f(n) = g(n) + h(n), integrating path cost with heuristic guidance. With admissible heuristics (never overestimating the true remaining cost), A* is guaranteed optimal. Consistency ensures f values are non-decreasing along paths, supporting efficient implementations.

Worked examples on graphs and puzzles illustrate frontier management, duplicate detection, and optimality arguments. The lecture prepares students for heuristic design (Lecture 4) and local search (Lecture 5).

Key Learning Objectives

  • Formulate search problems with states, operators, goal tests, and path costs.
  • Compare BFS, DFS, UCS, and IDS on completeness, optimality, time, and space.
  • Apply greedy best-first and A* with correct frontier ordering and duplicate handling.
  • Define admissible and consistent heuristics and explain their role in A* optimality.
  • Select appropriate search algorithms based on problem structure and cost assumptions.

Search Algorithms and Problem-Solving Agents

1. Intelligent Agents: A Quick Recap

Before diving into search algorithms, let us briefly recall the fundamental vocabulary of intelligent agents.

1.1 PEAS Specification

Every intelligent agent can be described using the PEAS framework:

Key Concept 1: PEAS

  • Performance Measure — How do we evaluate success? (e.g., number of correct answers, points scored, clean floor)
  • Environment — Where does the agent operate? (e.g., a chess board, a road network, a hospital)
  • Actuators — What can the agent do to affect the environment? (e.g., move a piece, turn the steering wheel, display text)
  • Sensors — How does the agent perceive the environment? (e.g., camera, GPS, keyboard input)

Example 1.1 (PEAS for a Chess-Playing Agent).

  • P: Win the game (or maximize win rate).
  • E: The chess board and the opponent.
  • A: Moving pieces on the board.
  • S: Vision of the board (or digital representation).

1.2 Types of Environments

The environment in which an agent operates can be classified along several dimensions:

PropertyValuesMeaning

Episodic vs SequentialEpisodic / SequentialDo actions affect future episodes?

Example 1.2 (Chess Environment). Chess is fully observable (you see the whole board), deterministic (a move always produces the same result), sequential (moves build on each other), static (the board waits for you), discrete, and multi-agent.

1.3 Agent Architectures

Different situations call for different agent designs:

  1. Simple Reflex Agent — acts only on current percept; no memory.
  2. Model-Based Reflex Agent — maintains internal state to handle partial observability.
  3. Goal-Based Agent — chooses actions that lead to a desired goal.
  4. Utility-Based Agent — uses a utility function to compare desirability of states.
  5. Learning Agent — improves behavior over time through experience.

2. Problem Formulation

2.1 The Five Components

When we want an agent to solve a problem, it follows a four-phase problem-solving process: (1) Goal formulation — adopt a goal that limits the objectives and thus the actions to be considered. (2) Problem formulation — devise a description of states and actions necessary to reach the goal, an abstract model of the relevant part of the world. (3) Search — before taking any action in the real world, simulate sequences of actions in the model until a sequence reaching the goal (a solution) is found. (4) Execution — carry out the actions in the solution one at a time.

Formulation means extracting five essential ingredients from a real-world (or abstract) problem:

Key Concept 2: Five Components of Problem Formulation

  1. Initial State — Where does the agent start?
  2. Goal State (or Goal Test) — What is the desired outcome? Sometimes we have a specific state; sometimes we have a test that checks "Are we done?".
  3. Actions — What moves/operations are available at any state?
  4. Transition Model — Given a state s and action a, what is the resulting state s'? Also called the successor function.
  5. Path Cost — A numeric cost associated with each action; we typically seek a minimal-cost path from start to goal.

Example 2.1 (8-Puzzle Formulation). The 8-puzzle is a 3 × 3 grid with tiles numbered 1–8 and one blank.

  • Initial state: Any configuration, e.g., [[7,2,4],[5,_,6],[8,3,1]].
  • Goal state: The ordered configuration [[1,2,3],[4,5,6],[7,8,_]].
  • Actions: Slide the blank Up, Down, Left, Right (where legal).
  • Transition model: Swapping the blank with the adjacent tile.
  • Path cost: Each move costs 1.

Example 2.2 (Route-Finding in Romania). Given a map of Romanian cities with distances (km), an agent wants to travel from Arad to Bucharest.

  • Initial state: "At Arad."
  • Goal state: "At Bucharest."
  • Actions: Drive to a neighboring city.
  • Transition model: Reaching the neighbor city.
  • Path cost: Sum of distances traveled.

2.2 Search as a Problem-Solving Paradigm

In the early days of AI, many problems were cast as search problems:

Real-world problem → Search problem (graph/tree) → Apply search algorithm → Find path to goal

Once a path from the initial state to the goal is found, the agent has "solved" the problem. The sequence of actions along that path is the solution. We assume action costs are additive — the total cost of a path is the sum of individual action costs. An optimal solution has the lowest path cost among all solutions. We also assume all action costs are positive to avoid complications with negative cycles.

In a fully observable, deterministic, known environment, the solution is a fixed sequence of actions — an open-loop system where the agent can ignore percepts during execution because the solution is guaranteed. If the model might be incorrect or the environment is nondeterministic, a closed-loop approach that monitors percepts is safer.

Abstraction in Problem Formulation

Formulating a problem involves abstraction — removing detail from a representation while retaining validity. A good problem formulation has the right level of detail: abstract enough that actions are easy to carry out, but detailed enough that solutions in the abstract model correspond to solutions in the real world. For example, "drive from Arad to Sibiu" abstracts away radio programs, scenery, weather, and traffic — all irrelevant to route-finding. If actions were specified at the level of "turn the steering wheel one degree left," the agent would never find its way out of the parking lot.

3. Uninformed (Blind) Search Algorithms

Uninformed search means the algorithm has no extra information beyond what is given in the problem formulation itself — the initial state, goal test, actions, transition model, and path cost. The algorithm cannot "guess" which direction is more promising. These algorithms are sometimes called blind searches.

We evaluate search algorithms along four dimensions:

  • Completeness: Is the algorithm guaranteed to find a solution when one exists, and correctly report failure when there is not?
  • Cost optimality: Does it find a solution with the lowest path cost?
  • Time complexity: How long does it take? Measured by number of states/actions considered.
  • Space complexity: How much memory is needed during search?

Complexity is typically measured in terms of b (branching factor), d (depth of shallowest solution), and m (maximum depth of the state space). We distinguish between graph search (tracks all reached states to avoid redundant paths) and tree-like search (does not track reached states — uses less memory but may revisit states).

3.1 Breadth-First Search (BFS)

Key Concept 3: BFS — Cautious Exploration

BFS explores all nodes at a given depth (or "level") before moving deeper.

Mechanism

BFS uses a FIFO queue:

  1. Enqueue the initial node.
  2. Dequeue a node; if it is the goal, stop.
  3. Otherwise, enqueue all its unvisited neighbors.
  4. Repeat from step 2.

BFS order: A, B, C, D, E, G, H, F — Level by level.

Key Property: Completeness

BFS is complete: if a goal exists in a finite graph, BFS will find it. In infinite graphs with finite branching, BFS will also eventually find a goal if the goal is at a finite depth.

Drawback: Branching Factor

If the branching factor b (number of children per node) is large, BFS may waste enormous time and memory exploring siblings before reaching a goal that lies just one level deeper.

Example 3.1 (Bad Case for BFS). Suppose node A has 2000 children, and the goal is the first child of A's second child. BFS must explore all 2000 siblings first.

Applications

  • Finding the shortest path in an unweighted graph.
  • Testing bipartiteness of a graph.
  • Web crawling (limited depth).

Complexity Analysis

For a uniform tree with branching factor b and solution depth d, the number of nodes generated is 1 + b + b2 + b3 + … + bd = O(bd). All nodes remain in memory, so both time and space complexity are O(bd). As a concrete example: with b = 10, processing 1 million nodes/second, and 1 KB/node, a search to depth d = 10 would take under 3 hours but require 10 terabytes of memory. At depth d = 14, even with infinite memory, the search would take 3.5 years. The memory requirements are the bigger bottleneck for BFS than execution time.

Early vs. Late Goal Test

With uniform-cost edges, BFS can use an early goal test — checking whether a node is a solution as soon as it is generated, rather than waiting until it is popped off the queue (the late goal test). This is valid because BFS explores in order of increasing depth, so when a goal is generated at depth d, all nodes at depth d−1 have already been checked and are not goals.

3.2 Depth-First Search (DFS)

Key Concept 4: DFS — Aggressive Exploration

DFS picks one path and plunges as deep as possible; only when it cannot go further does it backtrack.

Mechanism

DFS uses a LIFO stack (or recursion):

  1. Push the initial node.
  2. Pop a node; if goal, stop.
  3. Push all its unvisited neighbors.
  4. Repeat from step 2.

DFS order: A, B, D, E, F, C, G, H — Go deep, then backtrack.

Drawback: Skewed Trees

If the tree is skewed (very deep in one direction) and the goal lies in a shallow branch elsewhere, DFS may waste time exploring an irrelevant deep path.

Example 3.2 (Good Use of DFS: Social Network Connectivity). Given two people Sunanda and Mukesh, are they connected? DFS from Sunanda follows one chain of friends until it either finds Mukesh or exhausts that chain, then backtracks. This is often more intuitive than exploring everyone at each degree of separation.

Applications

  • Topological sorting.
  • Finding connected components.
  • Maze solving (naturally fits "try a path till dead end, then backtrack").

Memory Advantage & Backtracking Variant

For tree-shaped state spaces, DFS has memory complexity of only O(bm) where m is the maximum depth — the frontier stores just one path. Some problems requiring exabytes of memory with BFS can be handled with kilobytes using DFS. This is why DFS is the workhorse for constraint satisfaction, propositional satisfiability, and logic programming.

A variant called backtracking search uses even less memory: only one successor is generated at a time, and successors modify the current state description directly rather than allocating new memory. This reduces memory to just one state description and an O(m) path of actions. Backtracking is critical for problems with large state descriptions such as robotic assembly — but we must be able to undo each action when backtracking.

3.3 Uniform Cost Search (UCS)

Key Concept 5: UCS — Cheapest-First

UCS is a generalization of BFS for weighted graphs. It expands the node with the lowest cumulative path cost from the start, regardless of depth.

Mechanism

UCS maintains a priority queue (sorted by g(n), the cost from start to node n):

  1. Insert the start node with cost 0.
  2. Remove the node with the smallest g(n).
  3. Goal test is applied upon expansion (not upon generation).
  4. For each neighbor, compute g(neighbor) = g(n) + cost(n, neighbor) and insert.
  5. Repeat.

Trace Example

Starting at Arad (g = 0):

  1. Generate Zerind (g = 75), Sibiu (g = 140), Timisoara (g = 118). Queue: [Z(75), T(118), S(140)].
  2. Expand Zerind: generate Oradea (g = 75 + 71 = 146). Queue: [T(118), S(140), O(146)].
  3. Expand Timisoara: generate Lugoj (g = 118 + 111 = 229). Queue: [S(140), O(146), L(229)].
  4. Expand Sibiu: generate Fagaras (g = 140 + 99 = 239), Rimnicu (g = 140 + 80 = 220). Queue: [O(146), R(220), F(239), L(229)].
  5. Continue until Bucharest is expanded (not just generated).

Goal Test on Expansion. UCS must apply the goal test when a node is expanded (popped from the frontier), not when it is generated. If we test upon generation, a suboptimal path reaching the goal first would be returned prematurely. The Sibiu-to-Bucharest example illustrates this clearly: Fagaras generates Bucharest first with cost 310 (via 99+211), but Pitesti later generates a cheaper path to Bucharest with cost 278 (via 80+97+101). The cheaper path is only discovered because we waited to test the goal upon expansion. UCS guarantees finding the optimal (lowest-cost) path when all edge costs are non-negative.

Dijkstra's Algorithm & Complexity

UCS is known as Dijkstra's algorithm in theoretical computer science. While BFS spreads out in waves of uniform depth, UCS spreads out in waves of uniform path-cost. UCS is complete and cost-optimal for all non-negative edge costs.

Complexity is characterized in terms of C* (cost of optimal solution) and ε (minimum action cost, ε > 0). Worst-case time and space is O(b1+⌊C*/ε⌋), which can be much larger than bd because UCS may explore large trees of cheap actions before exploring paths with an expensive but useful action. When all action costs are equal, b1+⌊C*/ε⌋ reduces to bd+1, making UCS similar to BFS.

3.4 Iterative Deepening Search (IDS)

Key Concept 6: IDS — The Best of Both Worlds?

IDS combines the space-efficiency of DFS with the completeness of BFS by running DFS with a gradually increasing depth limit.

Why IDS?

Recall the two problems:

  • BFS: Suffers when the branching factor b is large (explores too many siblings).
  • DFS: Suffers when the tree is skewed (may go infinitely deep in a wrong direction).

IDS mitigates both by not showing the whole graph at once:

  1. Set depth_limit = 0.
  2. Run DFS restricted to depth_limit.
  3. If goal is found, return it.
  4. Otherwise, increment depth_limit and repeat.

Analogue: Iterative Lengthening Search

Just as IDS applies DFS iteratively, we can apply BFS iteratively — this is called iterative lengthening search, where we restrict the path cost rather than depth. It mitigates the branching-factor problem of BFS.

Remark 3.1. IDS may appear wasteful because it revisits nodes at each iteration, but the overhead is surprisingly small: the majority of nodes are at the deepest level anyway.

Overhead Analysis

In IDS, nodes at the bottom level (depth d) are generated once, those at depth d−1 are generated twice, and so on, up to the children of the root which are generated d times. The total number of nodes generated in the worst case is:

N(IDS) = (d)b1 + (d−1)b2 + (d−2)b3 + … + bd

This gives a time complexity of O(bd) — asymptotically the same as BFS. For example, with b = 10 and d = 5: N(IDS) = 50 + 400 + 3,000 + 20,000 + 100,000 = 123,450 vs. N(BFS) = 10 + 100 + 1,000 + 10,000 + 100,000 = 111,110. The overhead is only about 11%.

Depth-Limited Search

IDS builds on depth-limited search: a version of DFS where we supply a depth limit ℓ and treat all nodes at depth ℓ as if they had no successors. Time complexity is O(bℓ), space O(bℓ). If ℓ is chosen poorly, the algorithm fails to reach the solution. A good depth limit can sometimes be chosen from domain knowledge — for instance, the diameter of the Romania state-space graph is 9 (any city can be reached from any other in at most 9 actions), making ℓ = 9 a valid limit.

4. Informed (Heuristic) Search Algorithms

4.1 The Problem with Blind Search

All uninformed algorithms — BFS, DFS, UCS, IDS — are slow on large state spaces. They treat every direction equally because they have no "sense of direction." They are sometimes called blind searches.

What if we had extra knowledge? What if a domain expert could whisper to us: "Going this way looks promising"?

4.2 Heuristics: The Guiding Light

Key Concept 7: Heuristic Function h(n)

A heuristic function h(n) takes a node n as input and returns an estimated cost from n to the goal. It is:

  • Not the actual cost — merely an informed guess.
  • Usually designed by domain experts (or learned from data).
  • Deterministic (for now; learning heuristics comes later).

Example 4.1 (Road Trip Analogy). You ask a local guide, "How long to reach Bucharest from Sibiu?" The guide says "About 253 km." This is h(Sibiu) = 253. The actual shortest distance might be different, but the guide's intuition helps you choose which road to try next.

Why Use Heuristics?

  • In huge state spaces (e.g., chess has ≈1047 states), blind search is hopeless.
  • A good heuristic lets us focus on promising paths — "being smart about what paths to try."
  • Guided search is generally faster and uses less memory.

The Best-First Search Framework

All informed (and many uninformed) search algorithms can be understood as special cases of best-first search, a general framework where we choose a node n with minimum value of an evaluation function f(n). The algorithm maintains:

  • A frontier — a priority queue of generated-but-not-expanded nodes, ordered by f(n).
  • A reached table — a lookup structure (hash table) mapping states to their best-known node. Each child node is added to the frontier only if it reaches a new state or improves the path cost to a previously reached state.
  • A node data structure with four components: STATE, PARENT, ACTION, and PATH-COST (also denoted g(n)). Following PARENT pointers back from a goal node recovers the solution path.

By choosing different f(n) functions, we obtain different algorithms: f(n) = depth gives BFS, f(n) = g(n) gives UCS, f(n) = h(n) gives GBFS, and f(n) = g(n) + h(n) gives A*.

A graph search keeps the reached table to detect redundant paths. A tree-like search omits the reached table, using less memory but risking repeated visits to the same state. Redundant paths are a major efficiency concern — in a 10×10 grid with 8-direction movement, the average cell can be reached by over a million different paths of length 9. Eliminating redundant paths can speed up search by a factor of a million.

4.3 Greedy Best-First Search (GBFS)

Key Concept 8: GBFS — "Trust the Heuristic Alone"

GBFS uses the evaluation function f(n) = h(n) and expands whichever node appears closest to the goal according to the heuristic only. It completely ignores the actual cost incurred so far.

How GBFS Works

  1. Start at the initial node.
  2. Among all frontier (generated but not expanded) nodes, pick the one with the smallest h(n).
  3. Expand it: generate its successors and compute their h values.
  4. Repeat until a goal is generated and expanded.

Trace

Arad (h = 366) → Generate {Zerind(374), Sibiu(253), Timisoara(329)}. Pick Sibiu (smallest h, 253).

Sibiu → Generate {Oradea(380), Fagaras(176), Rimnicu(193)}. Pick Fagaras (smallest h, 176).

Fagaras → Generate {Bucharest(0)}. Goal!

The path found is Arad — Sibiu — Fagaras — Bucharest with actual cost 140 + 99 + 211 = 450. This is not optimal (the optimal path via Rimnicu and Pitesti costs 418). GBFS was greedy and only trusted the heuristic.

Why GBFS Is Not Optimal

GBFS is a greedy algorithm: it optimizes for the immediate next step without regard to future consequences. Greedy algorithms, in general, do not guarantee optimal solutions.

Remark 4.1. GBFS ignores the actual cost g(n) that was already spent to reach node n. This is its fundamental weakness — it can be "fooled" by an optimistic heuristic that leads down an expensive path.

4.4 A* Search

Key Concept 9: A* — Best of Both Worlds

A* combines the actual cost incurred so far with the heuristic estimate:

f(n) = g(n) + h(n)

where:

  • g(n) = actual cost from the start to node n.
  • h(n) = estimated (heuristic) cost from node n to the goal.
  • f(n) = estimated total cost of the cheapest solution through n.

Intuition

A* says: "I already spent g(n) to get here, and you promise to take me to the goal in h(n). If their sum f(n) is already too high, why should I pick you?" Unlike GBFS (which believes only the heuristic), A* balances past cost (g) with future promise (h).

Algorithm

  1. Initialize the frontier with the start node; g(start) = 0, f(start) = h(start).
  2. While frontier is not empty:
    1. Remove the node with the smallest f(n).
    2. If it is the goal, stop and return the path.
    3. For each neighbor n':
      • g(n') = g(n) + cost(n, n')
      • f(n') = g(n') + h(n')
      • Add n' to frontier if new or if this path is cheaper.

Worked Example

Consider the following graph where node 1 is the start and node 5 is the goal:

Step 1: At node 1, g(1) = 0, f(1) = h(1) = 60. Expand 1.

Neighbors of 1:

  • f(2) = g(2) + h(2) = 70 + 120 = 190
  • f(3) = g(3) + h(3) = 125 + 70 = 195
  • f(4) = g(4) + h(4) = 100 + 40 = 140 ← smallest!

Step 2: Expand node 4 (smallest f). Its only neighbor is 5:

f(5) = g(5) + h(5) = (100 + 50) + 0 = 150

Goal reached! Path: 1 → 4 → 5, cost 150.

Note: Nodes 2 and 3 were generated but never expanded — A* smartly avoided them because their f values were higher.

Full Romania Trace with A*

Remark 4.2. A* is complete: it will find a solution if one exists (given reasonable conditions on branching factor and step costs). It is also optimal under certain conditions on the heuristic — which we now discuss.

Optimal Efficiency of A*

A* with a consistent heuristic is optimally efficient: no other optimal algorithm that extends search paths from the initial state and uses the same heuristic can expand fewer nodes than A* (up to tie-breaking). This means A* is the best possible algorithm for optimally solving a search problem with a given heuristic.

Weighted A* for Satisficing

When optimality is not required and we want faster solutions, weighted A* uses f(n) = g(n) + W × h(n) with weight W > 1. This places more emphasis on the heuristic, making the search more "greedy" and often dramatically faster, at the cost of possible suboptimality. With W = 1 it reduces to standard A*; as W → ∞ it approaches pure greedy best-first search. Weighted A* is considered a "somewhat-greedy" search — it focuses on the goal but still keeps some pressure toward optimal paths via g(n).

5. When Is A* Optimal? Heuristic Quality

A* is not automatically optimal. Its optimality depends on the quality of the heuristic. Two properties determine whether a heuristic is "good enough":

5.1 Admissibility

Key Concept 10: Admissible Heuristic

A heuristic h(n) is admissible if it never overestimates the true cost to reach the goal:

h(n) ≤ h*(n)  ∀n

where h*(n) is the actual optimal cost from node n to the goal.

What This Means

  • The heuristic must be optimistic: it may underestimate the cost (e.g., say 50 when the truth is 101), but it must never exaggerate (e.g., say 200 when the truth is 101).
  • An admissible heuristic guarantees that A* will find the optimal path.
  • Underestimating is acceptable; overestimating breaks optimality.

Why Admissibility Guarantees Optimality

The proof is by contradiction. Suppose a suboptimal goal G2 is on the frontier, but an optimal path goes through node n (still on the frontier) to the optimal goal G*. We have:

f(G2) = g(G2) + h(G2) = g(G2) (since h = 0 at goal)

f(n) = g(n) + h(n) ≤ g(n) + h*(n) = g(G*) (by admissibility, h(n) ≤ h*(n))

Since G2 is suboptimal, g(G2) > g(G*). Therefore f(G2) > f(n), meaning A* will never expand G2 before n — it will follow the optimal path.

Example 5.1 (Straight-Line Distance). For route planning on a map, the straight-line (Euclidean) distance between two cities is always ≤ the actual road distance. Hence, straight-line distance is an admissible heuristic.

Example 5.2 (Checking Admissibility). In the Romania map, h(Pitesti) = 100, but the actual shortest path from Pitesti to Bucharest is h*(Pitesti) = 101. Since 100 ≤ 101, this estimate is admissible.

5.2 Consistency (Monotonicity)

Key Concept 11: Consistent Heuristic

A heuristic is consistent (or monotonic) if for every node n and every successor n' generated by action a:

h(n) ≤ cost(n, a, n') + h(n')

What This Means

The heuristic must not "drop too suddenly." As we move from a node to its neighbor, the estimated remaining cost should decrease gradually, and the drop should never exceed the actual step cost. In graph terms: the heuristic satisfies the triangle inequality.

Example 5.3 (Consistency Check). Let n = Arad and n' = Sibiu. We check:

  • h(Arad) = 366
  • cost(Arad, Sibiu) + h(Sibiu) = 140 + 253 = 393
  • Since 366 ≤ 393, consistency holds for this pair. We must verify this for every edge.

Theorem 5.1 (Consistency ⇒ Admissibility). If a heuristic is consistent, then it is also admissible. (The converse is not necessarily true.)

Theorem 5.2 (A* Optimality). A* using a consistent (or admissible) heuristic is guaranteed to find the optimal (lowest-cost) path to the goal.

Why Consistency Matters

When a heuristic is consistent, the sequence of f(n) values along any path is non-decreasing. This means once A* expands a node, the best path to that node has already been found — we never need to re-expand it. This property is crucial for the efficiency of graph-search A*.

5.3 Good Heuristic vs. Poor Heuristic

Key Concept 12: What Makes a Heuristic "Good"?

A heuristic is better if it is closer to the true cost h*(n) without exceeding it. Formally, if both h1 and h2 are admissible and h1(n) ≥ h2(n) for all n, then h1 dominates h2 and will lead A* to expand fewer nodes.

  • A heuristic of h(n) = 0 for all n is admissible but useless — A* reduces to UCS.
  • A heuristic that exactly equals h*(n) is the perfect oracle — A* goes straight to the goal.
  • In practice, we want heuristics that are as large as possible while remaining admissible.

Effective Branching Factor

The quality of a heuristic can be characterized by the effective branching factor b*. If A* generates N nodes to find a solution at depth d, then b* is the branching factor a uniform tree of depth d would need to contain N+1 nodes: N+1 = 1 + b* + (b*)2 + … + (b*)d. A well-designed heuristic brings b* close to 1, while no heuristic (b* = b) results in exponential explosion. For the 8-puzzle, using only misplaced tiles gives b* ≈ 1.5, while Manhattan distance gives b* ≈ 1.25 — both dramatic improvements over blind search's b ≈ 3.

Generating Heuristics from Relaxed Problems

An important technique for inventing admissible heuristics is relaxation: take the original problem, remove some constraints, and use the exact solution cost of the relaxed problem as h(n). Because the relaxed problem is easier, its optimal cost is ≤ the true cost — making it admissible. For the 8-puzzle:

  • h1 (misplaced tiles): Relax by allowing tiles to teleport to their goal position in one move. Count out-of-place tiles.
  • h2 (Manhattan distance): Relax by allowing tiles to move through each other. Sum the city-block distances to goal positions. Since h2 ≥ h1 for all states, h2 dominates h1.

If multiple admissible heuristics are available, we can take their maximum: h(n) = max(h1(n), h2(n), …, hm(n)). This composite heuristic dominates each individual one and remains admissible (and consistent if all components are consistent). The only cost is the computation time of evaluating all component heuristics.

When to Use Which?

  • Maze solving: DFS is natural — try a path to the end, backtrack on dead ends.
  • Shortest path in unweighted graph: BFS gives the optimal path.
  • Weighted graph, no heuristic: UCS (equivalent to Dijkstra's algorithm).
  • Large / unknown depth, balanced trees: Iterative Deepening Search.
  • Large state space with domain knowledge: A* (if you have a good admissible heuristic).

Test Your Knowledge

Q: Which search algorithm is complete and optimal for non-negative step costs when using f(n) = g(n) + h(n) with admissible h?

Explanation: A* with admissible h never overestimates the true remaining cost, so the first goal dequeued is guaranteed optimal. Greedy uses only h; DFS lacks optimality guarantees.

Q: What is the main advantage of iterative deepening search over depth-first search?

Explanation: IDS repeats depth-limited DFS with increasing limits — finding shallow goals like BFS but storing only a single path like DFS. It's useful when space is tight and solution depth is unknown.

Q: A heuristic h(n) is admissible if:

Explanation: Admissibility means h(n) ≤ h*(n) for all n. Overestimating can cause A* to skip optimal paths. Consistency is a stronger condition that implies admissibility.

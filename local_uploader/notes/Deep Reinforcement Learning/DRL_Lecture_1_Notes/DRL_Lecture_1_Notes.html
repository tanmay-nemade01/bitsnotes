Lecture Summary

This lecture establishes reinforcement learning as a distinct learning paradigm. Unlike supervised learning (which uses labelled examples) or unsupervised learning (which finds structure in data), RL agents learn through trial and error — interacting with an environment to maximise cumulative scalar reward without any teaching signal.

The agent–environment interaction is formalised as a repeating loop: observe a state, choose an action, receive a reward and a next state, then update internal estimates. Five core elements are defined — agent, environment, state, action, and reward — with the critical point that rewards are specified by the environment and define the problem, not by the learner.

Policies π(a|s) describe how the agent behaves, while value functions V^π(s) capture expected long-term return under a policy. Discounted returns G_t = Σ γ^k R_{t+k+1} make infinite-horizon objectives well-defined and encode preference for nearer outcomes.

The tic-tac-toe case study illustrates tabular TD(0) learning in action: initialise terminal states, use greedy moves with value-based selection, and apply the update V(A) ← V(A) + α[V(A′) − V(A)] after exploitation moves. Exploration via ε-greedy is introduced to prevent locking onto suboptimal play. The lecture explains why RL differs from exhaustive game-tree search and why tabular methods eventually give way to deep networks for large state spaces.

Key Learning Objectives

  • Distinguish reinforcement learning from supervised and unsupervised learning using data type, feedback signal, and sequential decision structure.
  • Describe the agent–environment loop and define state, action, reward, policy π(a|s), and state-value function V^π(s).
  • Compute and interpret discounted returns and explain why the discount factor γ is used in continuing tasks.
  • Apply the tic-tac-toe TD(0) update rule, greedy action selection, and the exploration–exploitation trade-off.
  • Explain bootstrapping, tabular value storage, and when deep function approximation becomes necessary.

What is Reinforcement Learning?

Definition: Reinforcement Learning (RL) is the paradigm of learning by interacting with an environment so as to maximize a numerical reward signal. The learner is not told which actions to take, but instead must discover which actions yield the most reward through trial and error.

This is, arguably, the most natural form of learning: it is how humans, animals, and even infants learn. A baby is not given labelled examples of “how to walk”; it tries, falls, gets feedback (pain, support from a parent, balance restored), and gradually improves.

The Three Paradigms of Learning

To appreciate RL, contrast it with the two paradigms you may already know:

Paradigm Data Goal
Supervised Learning Labelled pairs \(\{(x_i, y_i)\}_{i=1}^N\) Learn mapping \(x \mapsto y\); minimize classification error / MSE.
Unsupervised Learning Unlabelled data \(\{x_i\}\) Find structure (clusters, low-dim representations).
Reinforcement Learning Trajectories of \((s_t, a_t, r_t, s_{t+1})\) obtained by acting Learn a policy that maximizes expected cumulative reward.
Key Concept: RL has no labelled targets. The only learning signal is a scalar reward. Crucially, the reward may be delayed (it may come many steps after the action that caused it).

Sutton & Barto identify three characteristics as the most important distinguishing features of reinforcement learning problems:

  1. Closed-loop in an essential way: The learning system's actions influence its later inputs. This creates a feedback cycle that does not exist in supervised learning, where predictions do not affect future training examples.
  2. No direct instructions: The agent is not told which actions to take. Unlike supervised learning, there are no labelled examples of correct behaviour. The agent must discover which actions yield the most reward by trying them out.
  3. Consequences play out over extended time periods: Actions may affect not only the immediate reward but also the next situation, and through that, all subsequent rewards. In the most interesting and challenging cases, these effects unfold over many steps.

Why "Deep" Reinforcement Learning?

Classical RL is built on tables and tabular updates (we will see exactly this in the tic-tac-toe example). But for problems with huge state spaces (Atari frames, robotic joint configurations, Go boards), we cannot store one entry per state.

Deep Reinforcement Learning replaces those tables with deep neural networks that approximate value functions and/or policies. The foundations, however, remain the same as classical RL—so we will spend a lot of time on the classical ideas before bringing in deep learning.

The Agent–Environment Interface

The two fundamental entities in RL are the agent and the environment.

Definition (Agent): The learner and decision-maker. It senses the state, chooses actions, and improves its behaviour over time.
Definition (Environment): Everything outside the agent’s direct control that responds to the agent’s actions and provides observations and rewards.
Intuition: A useful rule of thumb (Sutton & Barto): anything that cannot be changed arbitrarily by the agent is part of the environment. If the agent decides to press the brake, "pressing the brake" is an action—but how the brake actually responds (it might fail, skid, or work perfectly) is part of the environment. The boundary is problem-dependent and sometimes a modelling choice.

The Interaction Loop

At every discrete time step \(t = 0, 1, 2, \dots\) the following loop runs:

  1. The agent observes the current state \(S_t\).
  2. The agent picks an action \(A_t\).
  3. The environment transitions to a new state \(S_{t+1}\) and emits a scalar reward \(R_{t+1}\).
  4. The agent uses \((S_{t+1}, R_{t+1})\) to update its internal knowledge and choose the next action.
Agent
→ \(A_t\) →
Environment
← State \(S_{t+1}\) & Reward \(R_{t+1}\) ←

This loop is the heart of all RL. Every algorithm we study—tabular methods, Q-learning, policy gradients, deep RL—fits inside this loop.

The Five Core Elements

  1. Agent – the entity that learns.
  2. Environment – everything outside the agent.
  3. State \(S_t\) – a description of the current situation. Could be a chess board, a sensor reading, an image.
  4. Action \(A_t\) – what the agent does at time \(t\). May be discrete (left/right/up/down) or continuous (steering angle in \([-30^\circ, 30^\circ]\)).
  5. Reward \(R_{t+1}\) – a single scalar number returned by the environment after the agent acts.
Important Note: The reward is a property of the environment, not the agent. The agent must not be allowed to design or modify its own reward—that would be like a student deciding their own marks. The reward function defines the problem; the agent’s job is to maximize it.

The Fourth Sub-Element: Model of the Environment

Definition (Model): A model mimics the behaviour of the environment. Given a state and action, it can predict the resultant next state and next reward. Models are used for planning—deciding on a course of action by considering possible future situations before they are actually experienced.

Beyond the agent and the environment, Sutton & Barto identify four main sub-elements in a reinforcement learning system:

  1. Policy: Defines the learning agent's way of behaving at a given time — a mapping from perceived states to actions. It corresponds to what psychology would call a set of stimulus–response rules or associations. The policy alone is sufficient to determine behaviour; it is the core of an RL agent. In general, policies may be stochastic.
  2. Reward signal: Defines the goal of the RL problem. On each time step, the environment sends a single number to the agent. The agent's sole objective is to maximize the total reward it receives over the long run. The reward signal is the primary basis for altering the policy. Reward signals may be stochastic functions of the environment state and the actions taken.
  3. Value function: Specifies what is good in the long run. The value of a state is the total amount of reward an agent can expect to accumulate over the future, starting from that state. Whereas rewards are primary (given directly by the environment), values are secondary (estimated and re-estimated from sequences of observations). The most important component of almost all RL algorithms is a method for efficiently estimating values.
  4. Model of the environment (optional): Something that mimics the behaviour of the environment, allowing inferences about how the environment will behave. Given a state and action, a model might predict the resultant next state and next reward.

The presence or absence of a model leads to a fundamental taxonomy:

Approach Description
Model-Based Methods Use a model of the environment for planning and prediction. The agent can simulate “what-if” scenarios before taking real actions. Examples: Dynamic Programming, AlphaGo (MCTS + learned model).
Model-Free Methods Learn directly from experience (trial and error) without explicitly modelling environment dynamics. The agent does not predict how states transition—it just learns which actions produce reward. Examples: Q-learning, Policy Gradients, TD learning.

The tic-tac-toe player in this lecture is model-free with respect to its opponent: it has no model predicting what the opponent will do. Modern RL spans the whole spectrum—the most powerful systems often combine both approaches. AlphaGo Zero, for instance, learns a value function via self-play (model-free) and uses Monte Carlo Tree Search for planning at decision time (model-based).

When to Use Reinforcement Learning

RL is well-suited to problems in large environments when any of these hold:

  1. A model of the environment is known, but an analytic solution is not available (e.g., the equations exist but are intractable).
  2. Only a simulation model of the environment is given (simulation-based optimisation).
  3. The only way to collect information about the environment is to interact with it—no offline dataset of correct actions exists.

Examples of Agent–Environment Pairs

Concrete Examples:
  • Chess: Agent = the player. Environment = the board + the opponent. Action = a legal move. Reward = \(+1\) on win, \(-1\) on loss, \(0\) on draw, all emitted only at the end of the game (a strongly delayed reward).
  • Autonomous driving: Agent = the driving controller. Environment = road, other vehicles, passengers, traffic. Reward = smooth motion (\(+")), passenger discomfort or collisions (\(-")).
  • Industrial control (refinery): Agent = adaptive controller. Environment = the refinery with sensors and actuators. Reward = yield / cost / quality trade-off, measured continuously. The controller optimises without sticking to engineer-specified set points (Sutton & Barto).
  • Robotics: Agent = the robot controller. Environment = the physical world including joint dynamics, friction, sensors. Reward = progress toward goal (e.g., distance covered), penalties for falling or high torque. RL excels in continuous control tasks like walking, grasping, and manipulation.
  • Phil preparing breakfast (Sutton & Barto): A rich multi-level example. Phil navigates to the cupboard, selects cereal, fetches a bowl, pours milk—each sub-action driven by nested goals. Even a mundane everyday task involves a complex web of conditional behaviour and interlocking goal–subgoal relationships. Each step is guided by goals (grasping the spoon, getting to the refrigerator) in service of higher goals (having the spoon to eat with, obtaining nourishment).
  • A gazelle calf: Minutes after birth, struggles to stand; half an hour later runs at 20 mph. This is nature’s reinforcement learning—trial-and-error interaction with gravity and muscle coordination, driven by reward signals of stability and locomotion.
  • Vacuum cleaner robot: Agent = the robot. Environment = the house. Reward = \(+\) for dust collected, \(-\) for time and battery used.
  • Stock trading: Agent = trading bot. Environment = market. Reward = profit / loss.
  • New employee in a company: You take actions (do work, send emails). Reward = manager’s feedback. Often delayed: your manager may only comment on something you did two weeks ago.

Key Characteristics of Reinforcement Learning

RL differs from supervised learning in several important ways:

  1. Reward-based interaction: Learning is driven by a single scalar reward signal from the environment. The feedback is evaluative (how good was that action?) rather than instructive (here is the correct action). This is a fundamental distinction: in supervised learning, a teacher explicitly says “this is the right answer”; in RL, the environment only says “that got you +5” or “that got you −2”.
  2. Sequential decision making: The agent does not solve a one-shot prediction problem; it must choose a sequence of actions that interact with each other. The present action changes the next state, and the next state changes what actions are available later.
  3. Delayed consequences: A reward (positive or negative) may arrive long after the action that caused it. Think of setting a trap in chess: the payoff arrives many moves later. This creates the credit assignment problem—deciding which earlier actions contributed to later success or failure.
  4. Trial-and-error learning: The agent must try actions to discover their effects. There is no oracle telling it the “correct” action. The agent may know that an outcome was good, but it may not know which action should have been chosen instead.
  5. Exploration vs. exploitation: The agent must balance using what it already knows (exploit) with trying new things to discover better strategies (explore). We will return to this in Section 6. This dilemma does not even arise in the purest forms of supervised or unsupervised learning.
  6. Non-i.i.d. data: Successive states are highly correlated; the data distribution depends on the policy. This breaks many assumptions of supervised learning.
  7. Uncertainty: The agent normally operates with incomplete knowledge of the environment. Outcomes may be stochastic—the same action may not always lead to the same result. RL explicitly considers the whole problem of a goal-directed agent interacting with an uncertain environment.
Intuition: A short reflection: in life you sometimes endure short-term pain (study late, exercise, save money) for long-term gain. Other times, short-term pleasure (skipping a workout) leads to long-term regret. RL formalises exactly this: maximize cumulative reward over the long run, not the immediate reward.

Rewards, Returns, and Value Functions

From Reward to Return

Maximizing the immediate reward \(R_{t+1}\) is not enough. The agent should maximize the cumulative reward—called the return—starting from time \(t\).

Definition (Return): The return \(G_t\) at time \(t\) is a sum of future rewards: \[G_t = R_{t+1} + R_{t+2} + R_{t+3} + \dots\] For tasks that may continue indefinitely, we typically use a discounted return: \[G_t = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}, \quad 0 \le \gamma \le 1\] where \(\gamma\) (the discount factor) controls how much the agent cares about the distant future.
Intuition (Why discount?): If the agent lives forever and every step gives a finite reward, the undiscounted sum can be infinite—and we cannot compare two infinite sums to decide which is better. The discount factor \(\gamma < 1\) ensures the sum is finite, and it also encodes a meaningful preference: rewards now are worth more than rewards far in the future (just like money today is worth more than money in ten years).

Policy: The Agent's Way of Working

Definition (Policy): A policy \(\pi\) is the agent's strategy—a (possibly stochastic) rule that maps states to actions: \[\pi(a \mid s) = \Pr(A_t = a \mid S_t = s)\] A deterministic policy chooses one action with probability 1; a stochastic policy assigns a probability distribution over actions.

Intuitively: the policy is “my way of working.” Given a situation, what do I do? Two different agents in the same state can choose different actions because they have different policies.

Value Function: Long-Term Desirability

Definition (State-Value Function): The state-value function \(V^\pi(s)\) of a policy \(\pi\) is the expected return starting in state \(s\) and following \(\pi\) thereafter: \[V^\pi(s) = \mathbb{E}_\pi [ G_t \mid S_t = s ]\]
Key Concept (Reward vs. Value): Memorize this distinction!
  • Reward = immediate, short-term feedback for one action.
  • Value = long-term desirability of being in a state, assuming the agent follows policy \(\pi\) from now on.
A state with low immediate reward may still have high value if it leads to a great long-term outcome.
Sutton & Barto's Analogy: Rewards are somewhat like pleasure (if high) and pain (if low) — they are the immediate, defining features of the problem faced by the agent. Values, in contrast, correspond to a more refined and farsighted judgment of how pleased or displeased we are that the environment is in a particular state. In decision-making, it is values with which we are most concerned: we seek actions that bring about states of highest value, not highest reward, because these obtain the greatest amount of total reward in the long run.

A Two-State Toy Example

Consider an environment with only two states \(S_1\) and \(S_2\), and two actions: \(L\) (left) and \(R\) (right).

S₁
R (reward +2) →
← L (reward +2)
S₂
Note: \(L\) in \(S_1\) bumps the wall (reward \(-1\)), and \(R\) in \(S_2\) bumps the wall (reward \(-1\)).

Suppose my policy \(\pi\) in state \(S_2\) always picks \(R\) (i.e., I bump the wall). My trajectory from \(S_1\) looks like:

\(S_1 \xrightarrow{R,\; +2} S_2 \xrightarrow{R,\; -1} S_2 \xrightarrow{R,\; -1} S_2 \xrightarrow{R,\; -1} \dots\)

The return from \(S_1\) is small. But your policy might always choose \(L\) from \(S_2\), giving:

\(S_2 \xrightarrow{L,\; +2} S_1 \xrightarrow{R,\; +2} S_2 \xrightarrow{L,\; +2} S_1 \xrightarrow{R,\; +2} \dots\)

which has a much higher return. Hence:

  1. Different policies \(\implies\) different value functions.
  2. Therefore, values are always with respect to a particular policy.

The Policy–Value Duality

Key Concept: Policies and value functions are two sides of the same coin:
  • Given a policy \(\pi\), we can evaluate it by computing \(V^\pi\).
  • Given accurate values of all neighbouring states, we can improve our policy by simply choosing the action that leads to the highest-valued next state.
This bootstrapping—evaluate → improve → evaluate → \(\dots\) —is the engine behind nearly every RL algorithm (it is called generalized policy iteration).

A Worked Example: Learning Tic-Tac-Toe with RL

We now apply RL to a concrete game. This example is adapted from Sutton & Barto, Chapter 1, and it illustrates almost every idea from the lecture.

Problem Setup

Two players (agent vs. opponent) alternate placing \(\times\) and \(\circ\) on a \(3 \times 3\) grid. The agent plays \(\times\). There are three possible outcomes:

  • Agent wins \(\implies\) reward \(+1\).
  • Agent loses \(\implies\) reward \(0\) (or \(-1\)).
  • Draw \(\implies\) reward \(0\).
Important Note: The reward is only emitted at the end of a game. Intermediate moves get no immediate reward. This is a classic case of delayed rewards.

Why Not Just Use Exhaustive Search?

In the AI course you may study minimax search or alpha-beta pruning for games. These methods:

  • Assume the opponent plays optimally.
  • Search the entire game tree (or a heuristic-pruned version).
  • Find the theoretically optimal move.

But what if the opponent is not optimal? A suboptimal opponent might have specific weaknesses we can exploit. RL learns to play against the opponent it actually faces, not an idealised optimal one.

RL is also scalable: exhaustive search is impossible for games like Go or StarCraft.

The Tabular Value Function

We maintain a table with one row per possible board state. Each row stores a single number \(V(s)\) representing the current estimate of the value of that state.

Initialization:

  • For states where the agent has already won (three \(\times\)’s in a line): set \(V(s) = 1\).
  • For states where the opponent has won: set \(V(s) = 0\).
  • For all other states: set \(V(s) = 0.5\) (we are uncertain—roughly 50/50).
Intuition: The initial values reflect prior knowledge. We know the value of terminal states (we can see who won). For unknown intermediate states, \(0.5\) is a neutral starting guess; learning will adjust these values over many games.

This is called a tabular method: each state is one row, and updating one row does not affect any other row. Tabular methods are simple and powerful when the state space is small enough to enumerate. (For tic-tac-toe there are only a few thousand legal states; for chess there are \(\sim 10^{43}\), so tables won't fit and we need deep learning.)

Choosing Moves: Greedy Action Selection

Suppose the opponent has just moved, giving the agent a board configuration \(B\). From \(B\), the agent has several possible moves leading to states \(C_1, C_2, \dots, C_k\).

The greedy (exploitation) move: look up \(V(C_1), V(C_2), \dots, V(C_k)\) in the table, and play the move that leads to the highest-valued state.

In the figure above: the opponent moved \(A \to B\). The agent considers all moves from \(B\) and chooses the one leading to a state with value \(0.7\) (the highest among its options).

The Temporal-Difference (TD) Update Rule

After the agent makes a greedy move from state \(A\) to a state \(A'\) (via the opponent and the agent’s greedy choice), it updates the value of \(A\) to be closer to the value of \(A'\ tribute\):

TD(0) Update Rule: \[V(A) \leftarrow V(A) + \alpha [ V(A') - V(A) ]\] where \(\alpha \in (0, 1]\) is the step size (learning rate) and \(A'\) is the state reached after the agent’s chosen action.
Intuition: Why this update? If I thought \(V(A) = 0.5\) but my best follow-up has value \(0.3\), then my estimate of \(A\) was too optimistic—I should decrease it. Conversely, if my best follow-up has value \(0.6\), \(A\) is better than I thought, so I should increase its value. The difference \(V(A') - V(A)\) is the temporal difference, and we shift \(V(A)\) a fraction \(\alpha\) of the way toward \(V(A')\).
Numerical Walk-Through (Four Illustrative Cases):
Case \(V(S_t)\) \(V(S_{t+1})\) \(lpha\) Updated \(V(S_t)\) Interpretation
Later state looks better 0.50 0.70 0.10 \(0.50 + 0.10 imes(0.70 - 0.50) = 0.52\) The earlier state becomes slightly more promising—value nudged upward.
Later state looks worse 0.60 0.30 0.10 \(0.60 + 0.10 imes(0.30 - 0.60) = 0.57\) The earlier state’s value is reduced—we were too optimistic.
Larger learning step 0.40 0.80 0.25 \(0.40 + 0.25 imes(0.80 - 0.40) = 0.50\) A larger \(lpha\) moves the estimate faster but with less stability.
Close estimates 0.65 0.67 0.10 \(0.65 + 0.10 imes(0.67 - 0.65) = 0.652\) Only a small correction is made when successive estimates are similar.

Key insight: The update does not replace the old estimate fully. It moves it part of the way toward the later estimate. Small \(lpha\) gives slow but stable learning. Larger \(lpha\) gives faster but more sensitive (higher variance) learning. A decreasing step size can make the estimates settle for a fixed opponent; a step size that never vanishes lets the agent keep adapting if the opponent changes slowly.

Bootstrapping and Backing Up Values

Notice that we update \(V(A)\) using \(V(A')\), which is itself only an estimate. This is called bootstrapping: we learn an estimate from another estimate.

Initially every internal state has value \(0.5\), so updates do little. But the values of terminal states (\(1\) for a win, \(0\) for a loss) are correct from the start. As games are played, terminal values gradually propagate backward through the table: states adjacent to wins get value above \(0.5\), states adjacent to those get nudged up, and so on. Over many games, the entire table becomes informative.

Key Concept: This is the central trick that makes tabular TD learning work, and the same idea underlies all modern deep RL value-based methods (DQN, Double DQN, etc.).
Convergence Guarantee (Sutton & Barto): If the step-size parameter \(\alpha\) is reduced properly over time, this TD method converges, for any fixed opponent, to the true probabilities of winning from each state given optimal play by our player. Furthermore, the moves then taken (except on exploratory moves) are the optimal moves against that particular opponent. In other words, the method converges to an optimal policy.
Striking Feature — Planning Without a Model: The simple RL player can learn to set up multi-move traps for a shortsighted opponent. It is a striking feature of this solution that it achieves the effects of planning and lookahead without using a model of the opponent and without conducting an explicit search over possible sequences of future states and actions. The TD update implicitly propagates information backward through the state space — a form of learning that produces foresight without explicit search.

Exploration vs. Exploitation

The Dilemma

Definition (Exploitation): Pick the action that currently appears best according to your value estimates.
Definition (Exploration): Pick a different action—possibly one that looks worse—in order to gather information about it.
Intuition: Why is this a dilemma? Your value estimates are based on limited experience. They might be wrong. The only way to find out whether a seemingly bad action is actually good is to try it. But trying “bad-looking” actions costs you reward in the short run.

A driver who only follows the GPS will never discover a faster shortcut. A driver who always experiments with random side streets is reckless and never reaches a destination. The skill is in the balance.

Sutton & Barto emphasise that this issue has been intensively studied by mathematicians for many decades, yet remains unresolved—there is no universally optimal strategy for exploration. On a stochastic task, each action must be tried many times to gain a reliable estimate of its expected reward. If the agent only exploits, it may settle too early for a suboptimal action. If it only explores, it may fail to benefit from what it has already learned. Good reinforcement learning therefore requires a practical balance between both.

A Uniquely RL Problem: The entire issue of balancing exploration and exploitation does not even arise in supervised and unsupervised learning, at least in their purest forms. In supervised learning, the training set is fixed and independent of the learner's predictions. In RL, the agent chooses which data to collect via its actions — a chicken-and-egg problem that makes exploration central to the field.
Key Concept (Comparison with Evolutionary Methods): Evolutionary methods (genetic algorithms, genetic programming) evaluate entire policies by playing many complete games and using only the final outcome (win/loss). They do not evaluate individual states. Value-function methods, in contrast, allow individual states to be evaluated during play, making them far more sample-efficient—they take advantage of information available during the course of play, rather than only at the end. This is why we focus on value-function methods in this course.

When NOT to Update: Exploration Moves

In the tic-tac-toe scheme described above:

  • After an exploitation move, we apply the TD update—we are confident that the next state was chosen because of our value estimates, so it carries useful information about \(V(A)\).
  • After an exploration move, we do not update. The action was random, so the resulting next state tells us little about whether \(A\) is good or bad under our current policy.
Important Note: This is specific to the simple scheme presented in this lecture. More sophisticated algorithms (like Q-learning or Expected SARSA) update on exploration moves too, using clever weightings. But the lecture’s rule—"exploit \(\implies\) update, explore \(\implies\) don't update"—is enough to learn tic-tac-toe.

The Role of the Step Size \(\alpha\)

The learning rate \(\alpha\) controls how quickly we trust new information:

Value of \(\alpha\) Behaviour
\(\alpha = 0\) No update at all \(\implies\) no learning. Values are frozen forever.
\(\alpha = 1\) We completely replace the old estimate with the new one. Learning becomes wildly unstable.
Small constant (e.g., \(\alpha = 0.05\)) Slow, stable learning. The agent keeps adapting forever to new opponents/conditions.
Decaying \(\alpha_t\) Start large (learn quickly), decay over time (stabilize).
Key Concept (Continual Learning): Why keep \(\alpha > 0\) forever? If the environment changes (a new opponent appears), we want the agent to keep learning. A frozen agent (\(\alpha = 0\)) cannot adapt. RL is, fundamentally, continual learning.

A Common Exploration Strategy: \(\epsilon\)-Greedy

A practical algorithm for balancing exploration and exploitation is \(\epsilon\)-greedy:

\(\epsilon\)-Greedy Action Selection: \[A_t = \begin{cases} \text{random action} & \text{with probability } \epsilon, \\ \text{arg max}_a V(s') \text{ via action } a & \text{with probability } 1 - \epsilon. \end{cases}\]

Typically, \(\epsilon\) is large at the start of training (say \(\epsilon = 0.3\)) and decays toward a small value (say \(0.01\)) as the agent gains experience.

Putting It All Together

The General RL Recipe

  1. Initialize a value function \(V\) (or a Q-function \(Q\), or a policy \(\pi\)).
  2. Repeat for many episodes (games, trials, simulations):
    1. Observe the current state \(S_t\).
    2. Choose an action \(A_t\) (mostly greedy, occasionally exploratory).
    3. Receive reward \(R_{t+1}\) and next state \(S_{t+1}\).
    4. Update \(V\) (or \(Q\) or \(\pi\)) using a TD-style rule: \(V(S_t) \leftarrow V(S_t) + \alpha [ R_{t+1} + \gamma V(S_{t+1}) - V(S_t) ]\).
    5. Move on: \(S_t \leftarrow S_{t+1}\).
  3. Over time, the value function (and hence the implicit policy) converges to something good.

Sequential Decision Problems

The setup we have described is more formally called a Sequential Decision Problem (SDP). At every time step the agent must:

  1. Observe the state.
  2. Choose an action.
  3. Receive a reward and a new state.

This may continue forever (continuing tasks) or stop at a terminal state (episodic tasks). Both will be formalised in the next lecture as Markov Decision Processes (MDPs).

Common Pitfalls and Clarifications

Pitfall 1: Reward vs. Value

A reward of \(+10\) now does not necessarily mean a state is good—you might enter a low-value trap immediately afterwards. Always compare values (long-term expected return), not raw rewards, when deciding.

Pitfall 2: The Agent Cannot Choose Its Reward

A naive student might think, “Let me give myself \(+\infty\) for everything!” But that defeats the purpose. The reward function defines the problem, and only the environment may dispense rewards.

Pitfall 3: Values Depend on the Policy

There is no single “true value” of a state—only \(V^\pi(s)\) for a particular policy \(\pi\). Two different policies give two different value functions. When we write \(V(s)\) without a superscript, we are implicitly fixing a policy.

Pitfall 4: Updating Only One Step at a Time

In TD(0), each game updates only the immediately preceding state’s value. So values propagate slowly—many games are needed to push reliable information across the table. This is fine; in fact, simulating thousands of games against a software opponent is exactly the standard approach.

Lecture Takeaways

Key Points to Remember:
  1. RL is learning by interacting with an environment to maximize cumulative reward.
  2. The five basic elements: agent, environment, state, action, reward; together with the derived concepts of policy and value function.
  3. RL is distinguished by: reward-based feedback, sequential decisions, delayed consequences, and the exploration–exploitation trade-off.
  4. Reward = immediate feedback (scalar, from the environment).
  5. Value \(V^\pi(s)\) = expected long-term return from \(s\) under policy \(\pi\).
  6. Policy \(\pi(a \mid s)\) = the agent’s behaviour: probability of action \(a\) in state \(s\).
  7. Policy and value are dual: good values \(\implies\) greedy policy; consistent policy \(\implies\) well-defined values.
  8. The tic-tac-toe TD update: \(V(A) \leftarrow V(A) + \alpha [V(A') - V(A)]\).
  9. Tabular methods keep one value per state—great for small state spaces, infeasible for large ones (where deep RL takes over).
  10. Always balance exploration (try new things) and exploitation (use what you know). \(\epsilon\)-greedy is a standard recipe.
  11. Keep the learning rate \(\alpha > 0\) so the agent never stops adapting.

Historical Context

The field of reinforcement learning has deep roots. The term and modern framework trace back to the work of A. Harry Klopf in the late 1970s at Wright-Patterson Air Force Base. Klopf was dissatisfied with equilibrium-seeking models of intelligence and argued that maximizing systems—systems that actively try to maximize something—held the key to understanding natural intelligence. His ideas brought together Richard Sutton (then a Stanford undergraduate) and Andrew Barto (a newly-minted PhD at UMass Amherst) in 1979. Their collaboration, funded by AFOSR, produced the computational study of RL as we know it today.

However, the intellectual lineage goes back much further. In 1911, Edward Thorndike formulated the Law of Effect — arguably the first succinct expression of trial-and-error learning as a principle:

"Of several responses made to the same situation, those which are accompanied or closely followed by satisfaction to the animal will, other things being equal, be more firmly connected with the situation, so that, when it recurs, they will be more likely to recur; those which are accompanied or closely followed by discomfort to the animal will, other things being equal, have their connections with that situation weakened."
— Edward Thorndike, Animal Intelligence (1911)

In 1948, Alan Turing described what may be the earliest computational design for a learning system based on the Law of Effect — a "pleasure-pain system":

"When a configuration is reached for which the action is undetermined, a random choice for the missing data is made and the appropriate entry is made in the description, tentatively, and is applied. When a pain stimulus occurs all tentative entries are cancelled, and when a pleasure stimulus occurs they are all made permanent."
— Alan Turing, "Intelligent Machinery" (1948)

In the 1960s, Donald Michie built MENACE (Matchbox Educable Naughts and Crosses Engine) — a physical tic-tac-toe learner using matchboxes filled with coloured beads to represent state-action probabilities, with beads added or removed based on game outcomes. The BOXES system (Michie & Chambers, 1968) applied similar ideas to pole-balancing — one of the earliest reinforcement learning tasks under incomplete knowledge. Harry Klopf is the individual most responsible for reviving the trial-and-error research thread within AI in the 1970s, recognizing that the hedonic aspects of behaviour — the drive to achieve results from the environment — had been lost as researchers focused almost exclusively on supervised learning.

The field has since grown into one of the most active research areas in machine learning, with contributions from psychology, control theory, AI, and neuroscience. Key milestones include: TD-Gammon (Tesauro, 1992)—the first program to achieve world-champion level play using TD learning and neural networks; DQN (Mnih et al., 2015)—human-level Atari game play from raw pixels; AlphaGo (Silver et al., 2016)—defeating the world champion at Go; and AlphaGo Zero (2017)—learning superhuman Go without any human data.

Real-World Applications

Domain Examples
Game Playing Tic-tac-toe, chess, Go, Atari, StarCraft, backgammon
Robotics Balance, walking, navigation, grasping, manipulation
Autonomous Driving Lane decisions, speed control, planning under uncertainty
Industrial Control Refinery control, energy management, process optimisation
Operations Scheduling, inventory control, traffic signals, resource allocation
Recommendation Systems Personalisation, advertising, web services, content ranking
Healthcare & Education Adaptive interventions, tutoring systems, treatment planning
Finance Portfolio management, sequential bidding, risk-sensitive decisions
Common Thread: In each application, the central pattern is the same. The agent must act now, observe what happens, and improve future decisions. A single action cannot be judged only by its immediate effect—it must be judged by the later states and later rewards that it helps to produce. This is the unifying insight of reinforcement learning.

Test Your Knowledge

Q: What is the primary learning signal in reinforcement learning?

Explanation: RL agents learn from scalar reward feedback obtained by interacting with the environment. Unlike supervised learning, there are no correct action labels — only rewards that may arrive many steps after the causing action.

Q: In the tic-tac-toe TD(0) scheme from this lecture, how is V(A) updated after a greedy move?

Explanation: The TD(0) rule nudges the value of state A toward the estimated value of the best successor A′, using step size α. This bootstraps from another estimate rather than waiting for a final return.

Q: Why is a discount factor γ < 1 commonly used in continuing tasks?

Explanation: Without discounting, sums over infinite horizons may diverge. γ < 1 ensures finite returns and models a preference for immediate outcomes, analogous to the time value of money in finance.

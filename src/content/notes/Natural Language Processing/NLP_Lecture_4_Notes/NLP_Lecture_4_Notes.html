4.1 Recap: Skip-Gram with Negative Sampling (SGNS)

In the previous session, we introduced the Skip-Gram with Negative Sampling (SGNS) algorithm — one of the most influential static word embedding techniques. Here we provide a concise recap before moving to CBOW and GloVe.

4.1.1 Core Idea

Given a target word \(w_t\), the skip-gram model tries to predict the context words that appear within a fixed window (typically \(\pm 2\) to \(\pm 4\) words) around it. Negative sampling makes this computationally feasible by converting the problem into a binary classification task:

  • Positive samples: actual context words that co-occur with the target word in the corpus.
  • Negative samples: randomly sampled words that do not appear in the context window (usually \(k=5\)–\(20\) negative samples per positive sample).
Key Concept: SGNS treats learning as a discriminative task: for each (target, context) pair, the model predicts whether this pair came from the real data (\(P=1\)) or was a random noise pair (\(P=0\)). The objective is: \[ \mathcal{L} = \log\sigma(\mathbf{v}_{w_O}^\top \mathbf{v}_{w_I}) + \sum_{i=1}^{k} \mathbb{E}_{w_i \sim P_n(w)} \left[ \log\sigma(-\mathbf{v}_{w_i}^\top \mathbf{v}_{w_I}) \right] \] where \(\sigma\) is the sigmoid function, \(\mathbf{v}_{w_I}\) is the embedding of the input (target) word, \(\mathbf{v}_{w_O}\) is the embedding of the output (context) word, and \(P_n(w)\) is the noise distribution.

4.1.2 The Training Process

  1. Initialize: Start with random embeddings for every word in the vocabulary (both target and context embeddings).
  2. Forward pass: For a target word (e.g., "Ned"), take the dot product with each context word's embedding and apply the sigmoid function: \[ P(\text{context} \mid \text{target}) = \sigma(\mathbf{v}_{\text{context}}^\top \mathbf{v}_{\text{target}}) \]
  3. Compute error: For positive context words, the target probability is 1; for negative samples, it is 0. The error is: \[ \text{error} = \text{actual} - \text{predicted} \]
  4. Backward pass: Compute the partial derivative of the loss with respect to the target word embedding: \[ \frac{\partial \mathcal{L}}{\partial \mathbf{v}_{w_I}} = \sum_{\text{pos}} \text{error}_+ \cdot \mathbf{v}_{\text{pos}} \;+\; \sum_{\text{neg}} \text{error}_- \cdot \mathbf{v}_{\text{neg}} \]
  5. Update embeddings: Update the target word embedding using gradient descent: \[ \mathbf{v}_{w_I}^{\text{(new)}} = \mathbf{v}_{w_I}^{\text{(old)}} - \eta \cdot \frac{\partial \mathcal{L}}{\partial \mathbf{v}_{w_I}} \] where \(\eta\) is the learning rate (e.g., \(0.05\)).
  6. Update context embeddings: Similarly, update the embeddings of both positive and negative context words.
Note: After training, positive context word embeddings move closer to the target word embedding in vector space, while negative context word embeddings move away. This is the geometric intuition behind all static word embedding methods.

4.1.3 Context Window Size

The choice of context window is a crucial hyperparameter:

  • Smaller windows (\(\pm 2\)): Faster training, captures more syntactic relationships (e.g., verb tense, plural forms).
  • Larger windows (\(\pm 5\)–\(\pm 10\)): Captures more semantic or topical similarity (e.g., "doctor" and "hospital"), but slower.
  • Domain-specific corpora: May require larger windows to extract sufficient context from a limited vocabulary.

For most general-purpose corpora, \(\pm 2\) to \(\pm 4\) words is sufficient.

4.1.4 Why SGNS Remains Relevant

Despite the rise of contextual embeddings (BERT, GPT), SGNS remains widely used in production because:

  • It can be trained on CPUs with limited memory — no GPU required.
  • The resulting embeddings are lightweight and easy to deploy.
  • It performs well on domain-specific tasks with smaller corpora.
  • Libraries like Gensim provide production-ready implementations.
Example: Real-world applications of static word embeddings:
  • Search engines: Query expansion using semantically similar words.
  • Recommendation systems: Product embeddings for similar-item recommendations.
  • Chatbots: Intent classification using averaged word embeddings.
  • Information retrieval: Document ranking via cosine similarity of averaged embeddings.

4.1.5 Word Embeddings and Data Quality

Caution: Garbage In, Garbage Out. Since word embeddings are learned directly from the training corpus, any biases present in the data (cultural, gender, racial) will be encoded into the vector representations. For example, if a corpus consistently associates certain professions with a particular gender, the embeddings will reflect and potentially amplify that bias.

Mitigation strategies include:

  • Curating high-quality, balanced training corpora.
  • Applying debiasing techniques (e.g., removing the bias direction from the embedding space).
  • Using fairness-aware training objectives.
  • Auditing embeddings with tools like the Word Embedding Association Test (WEAT).

Key Concept: Word embeddings adapt to the context of the training data. The word "broadcast" originally meant scattering seeds in farming, but today it means transmitting media. Embeddings trained on different corpora will encode different dominant meanings. Similarly, new vocabulary (e.g., Gen Z slang) continually reshapes semantic spaces.

4.2 Continuous Bag of Words (CBOW)

4.2.1 Intuition

While Skip-Gram predicts context words from a target word, CBOW (Continuous Bag of Words) does the reverse: it predicts a target word from its surrounding context words. Think of it as a "fill in the blanks" problem.

Key Concept: Given the context words \(\{w_{t-2}, w_{t-1}, w_{t+1}, w_{t+2}\}\) (a window of surrounding words), CBOW tries to predict the center word \(w_t\). The model learns embeddings such that the target word's vector lies close to the average vector of its context words.
Example: Intuitive example: Given the context words \texttt{\{I, am, because, I\}}, the model predicts the target word happy. The full sentence is: "I am happy because I ...". The model learns that the embedding of "happy" should be similar to the average of embeddings of "I", "am", "because", and "I".

4.2.2 How CBOW Works

  1. Input: Embeddings of the context words within a fixed window (e.g., 4 words: 2 left + 2 right).
  2. Aggregation: The context word embeddings are averaged (or summed) to form a single context vector: \[ \mathbf{v}_{\text{context}} = \frac{1}{2m} \sum_{-m \leq j \leq m,\, j \neq 0} \mathbf{v}_{w_{t+j}} \]
  3. Prediction: This context vector is passed through a softmax layer to produce a probability distribution over the entire vocabulary: \[ P(w_t \mid w_{t-m}, \ldots, w_{t+m}) = \frac{\exp(\mathbf{u}_{w_t}^\top \mathbf{v}_{\text{context}})}{\sum_{w \in V} \exp(\mathbf{u}_w^\top \mathbf{v}_{\text{context}})} \] where \(\mathbf{u}_w\) are the output embeddings.
  4. Learning: The model maximizes the probability of the correct target word using cross-entropy loss. Weights are updated via backpropagation.

4.2.4 When to Use CBOW

  • When you have a large training corpus (millions+ of sentences).
  • When you care more about frequent words than rare ones.
  • When training speed is a priority (CBOW is roughly 2–3\(\times\) faster than Skip-Gram).
  • When your application domain has a relatively small, well-defined vocabulary.

4.3 Global Vectors (GloVe)

4.3.1 Motivation: Bridging Two Paradigms

Before GloVe, word embedding techniques broadly fell into two categories:

  1. Count-based / Frequency-based methods: Build a co-occurrence matrix by counting how often words appear together within a context window, then apply dimensionality reduction (e.g., LSA using SVD). These capture global corpus statistics but produce sub-optimal vector spaces.
  2. Prediction-based methods: Like CBOW and Skip-Gram, which learn embeddings by predicting words in local context windows. These capture local context patterns but may not fully exploit global co-occurrence statistics.
Key Concept: GloVe (Global Vectors for Word Representation), developed at Stanford, combines the strengths of both approaches: it uses global co-occurrence counts from the entire corpus while training via a prediction-based objective. The name itself — Global Vectors — emphasizes this dual nature.

4.3.2 The Co-occurrence Matrix

The foundation of GloVe is the word-word co-occurrence matrix \(X\).

Definition: Co-occurrence Matrix \(X\)
Let \(X_{ij}\) be the number of times word \(j\) appears in the context window of word \(i\), across the entire training corpus. For a window of size \(m\), we count occurrences of \(w_j\) within \(\pm m\) positions of \(w_i\).
Example: Toy example: Consider a corpus with three sentences:
I like NLP. I like deep learning. NLP is deep.

The unique vocabulary is: \(\{\texttt{I}, \texttt{like}, \texttt{NLP}, \texttt{deep}, \texttt{learning}, \texttt{is}\}\).

With a window of \(\pm 2\), the co-occurrence matrix \(X\) might look like:

\[ \begin{array}{c|cccccc} & \texttt{I} & \texttt{like} & \texttt{NLP} & \texttt{deep} & \texttt{learning} & \texttt{is} \\ \hline \texttt{I} & 0 & 2 & 1 & 1 & 1 & 0 \\ \texttt{like} & 2 & 0 & 1 & 1 & 1 & 0 \\ \texttt{NLP} & 1 & 1 & 0 & 1 & 0 & 1 \\ \texttt{deep} & 1 & 1 & 1 & 0 & 1 & 1 \\ \texttt{learning}& 1 & 1 & 0 & 1 & 0 & 0 \\ \texttt{is} & 0 & 0 & 1 & 1 & 0 & 0 \\ \end{array} \]

Interpretation: High co-occurrence values indicate strong semantic relationships. For instance, \(\texttt{like}\) co-occurs frequently with \(\texttt{I}\) (2 times) and with \(\texttt{deep}\) (1 time), reflecting typical syntactic patterns.

4.3.3 Co-occurrence Probabilities and Ratios

GloVe's key insight is that ratios of co-occurrence probabilities, rather than raw probabilities themselves, encode meaning.

For three words \(i\), \(j\), and \(k\), consider: \[ F(w_i, w_j, \tilde{w}_k) = \frac{P_{ik}}{P_{jk}} \] where \(P_{ik} = P(w_k \mid w_i) = X_{ik} / X_i\) (the conditional probability of word \(k\) given word \(i\)).

Table: Probability and ratio examples from a large corpus (illustrative values)
Probability / Ratio \(k = \texttt{solid}\) \(k = \texttt{gas}\) \(k = \texttt{water}\)
\(P(k \mid \texttt{ice})\) \(1.9 \times 10^{-4}\) \(6.6 \times 10^{-5}\) \(3.0 \times 10^{-3}\)
\(P(k \mid \texttt{steam})\) \(2.2 \times 10^{-5}\) \(7.8 \times 10^{-4}\) \(2.2 \times 10^{-3}\)
\(P(k \mid \texttt{ice}) / P(k \mid \texttt{steam})\) \(\mathbf{8.9}\) \(\mathbf{0.085}\) \(\mathbf{1.36}\)
What the ratios tell us:
  • \(\frac{P(\texttt{solid}\mid\texttt{ice})}{P(\texttt{solid}\mid\texttt{steam})} = 8.9 \gg 1\): "solid" is much more related to "ice" than to "steam".
  • \(\frac{P(\texttt{gas}\mid\texttt{ice})}{P(\texttt{gas}\mid\texttt{steam})} = 0.085 \ll 1\): "gas" is much more related to "steam" than to "ice".
  • \(\frac{P(\texttt{water}\mid\texttt{ice})}{P(\texttt{water}\mid\texttt{steam})} \approx 1.36\): "water" is roughly equally related to both, but slightly more to "ice".
Note: These ratios serve as a discriminative signal — they tell us which words should be semantically close (high ratio) and which should be far apart (low ratio). This is what GloVe's objective function encodes.

4.3.4 The GloVe Objective Function

GloVe learns word vectors \(\mathbf{w}_i\) and \(\tilde{\mathbf{w}}_k\) such that their dot product directly represents the log co-occurrence count: \[ \mathbf{w}_i^\top \tilde{\mathbf{w}}_k + b_i + \tilde{b}_k = \log X_{ik} \]

The full weighted least-squares objective is:

\[ \mathcal{J} = \sum_{i,j=1}^{|V|} f(X_{ij}) \left( \mathbf{w}_i^\top \tilde{\mathbf{w}}_j + b_i + \tilde{b}_j - \log X_{ij} \right)^2 \]

where:

  • \(\mathbf{w}_i\) and \(\tilde{\mathbf{w}}_j\) are the word vectors (the final embedding is \(\mathbf{w}_i + \tilde{\mathbf{w}}_i\)).
  • \(b_i\) and \(\tilde{b}_j\) are bias terms.
  • \(f(X_{ij})\) is a weighting function that prevents very frequent co-occurrences from dominating and ensures rare co-occurrences are not over-weighted: \[ f(x) = \begin{cases} (x/x_{\max})^\alpha & \text{if } x < x_{\max} \\ 1 & \text{otherwise} \end{cases} \] Typical values: \(x_{\max} = 100\), \(\alpha = 0.75\).

4.3.5 Vector Analogies

One of the most celebrated properties of word embeddings is their ability to solve analogies through simple vector arithmetic:

\[ \mathbf{v}_{\text{king}} - \mathbf{v}_{\text{man}} + \mathbf{v}_{\text{woman}} \approx \mathbf{v}_{\text{queen}} \]
Example: More analogy examples:
  • \(\mathbf{v}_{\text{Paris}} - \mathbf{v}_{\text{France}} + \mathbf{v}_{\text{Italy}} \approx \mathbf{v}_{\text{Rome}}\)
  • \(\mathbf{v}_{\text{walking}} - \mathbf{v}_{\text{walk}} + \mathbf{v}_{\text{swim}} \approx \mathbf{v}_{\text{swimming}}\)
  • \(\mathbf{v}_{\text{apple}} - \mathbf{v}_{\text{fruit}} + \mathbf{v}_{\text{grape}} \approx \mathbf{v}_{\text{wine}}\) (relationship inference)

This property emerges because the vector differences capture relational directions in the embedding space — a direct consequence of how context-based training distributes meaning across dimensions.

4.3.6 Visualization with t-SNE

High-dimensional word embeddings (typically 100–300 dimensions) are often visualized using t-SNE (t-distributed Stochastic Neighbor Embedding), which reduces them to 2D or 3D while preserving local structure.

Key Concept: A t-SNE plot immediately reveals:
  • Clusters: Semantically related words (e.g., countries, verbs, foods) group together.
  • Gradients: Continuous semantic shifts (e.g., good \(\to\) better \(\to\) best).
  • Analogies: Parallel relationships appear as parallel vectors in the reduced space.

Statistical Language Modeling

4.4 What is Language Modeling?

4.4.1 Definition

Key Concept: A language model assigns a probability to a sequence of words (a sentence, paragraph, or document). Formally, given a sequence of words \(w_1, w_2, \ldots, w_n\), the language model computes: \[ P(w_1, w_2, \ldots, w_n) \] This probability represents how "natural" or "likely" the sequence is in the given language, according to the training data.
Note: Even modern Large Language Models (LLMs) like GPT-4, Claude, and Gemini are, at their core, language models — they predict the probability of the next token given the previous tokens. The difference is in how they compute these probabilities (transformers and attention mechanisms vs. simple counting) and their scale (billions of parameters vs. simple lookup tables).
Key Concept: A language model acts as a "Fluency Judge." It internalizes the patterns, grammar, and idioms of a language by analyzing vast amounts of text. When presented with a sentence, it determines how "natural" or "likely" that sentence is:
  • \(P(\texttt{I saw a white swan})\) → High probability (sounds natural)
  • \(P(\texttt{Swan a white saw I})\) → Low probability (sounds strange)
We use language models every day — when your phone suggests the next word during typing, or when a search engine autocompletes your query, a language model is at work behind the scenes.

4.4.2 Why Language Modeling Matters

Language modeling is not just about generating text — it is the computational foundation of nearly all NLP applications:

  • Autocomplete / Predictive text: "I want to eat ..." \(\to\) food (not car).
  • Spell checking: "I ate an aple" \(\to\) Which has higher probability: "I ate an apple" vs. "I ate an ample"?
  • Grammar correction: "He go to school" \(\to\) "He goes to school" (based on probability of the corrected sequence).
  • Machine translation: "Tez hawaai jahaaz" \(\to\) Which translation is more probable: "Fast airplane" or "Rapid air machine"?
  • Speech recognition: The system hears "recognize speech" vs. "wreck a nice beach" — which word sequence has higher probability in the target language?
  • Information retrieval: Ranking documents by the likelihood that they are relevant to a query.
  • Text generation: Producing coherent paragraphs, articles, or code.

4.4.3 The Chain Rule of Probability

For any sequence of words, the joint probability can be decomposed using the chain rule:

\[ P(w_1, w_2, \ldots, w_n) = P(w_1) \cdot P(w_2 \mid w_1) \cdot P(w_3 \mid w_1, w_2) \cdots P(w_n \mid w_1, \ldots, w_{n-1}) \]

More compactly: \[ P(w_1^n) = \prod_{i=1}^{n} P(w_i \mid w_1^{i-1}) \]

where \(w_1^n\) denotes the sequence \((w_1, \ldots, w_n)\) and \(w_1^0\) is the empty context.

Example: Example: Probability of the phrase "its water is so transparent": \begin{align*} P(\texttt{its, water, is, so, transparent}) =\; &P(\texttt{its}) \\ &\times P(\texttt{water} \mid \texttt{its}) \\ &\times P(\texttt{is} \mid \texttt{its, water}) \\ &\times P(\texttt{so} \mid \texttt{its, water, is}) \\ &\times P(\texttt{transparent} \mid \texttt{its, water, is, so}) \end{align*}

Problem: As the sequence grows, finding training examples for long contexts becomes increasingly difficult. Many of these conditional probabilities will be zero simply because the exact sequence never appeared in the training corpus — even if the sentence is perfectly valid English.

Caution: The Sparsity Crisis. To estimate \(P(\texttt{transparent} \mid \texttt{Its water is so})\) using MLE counts, we would need: \[ P(\texttt{transparent} \mid \texttt{Its water is so}) = \frac{\text{Count}(\texttt{Its water is so transparent})}{\text{Count}(\texttt{Its water is so})} \] Language is creative — most specific long sequences of words have never occurred before, even across the entire web. The numerator might be 0 (giving probability 0), and the denominator might also be 0 (undefined). Even if we had infinite data, storing counts is impossible: with a vocabulary of 50,000 words, the number of possible 5-word sequences is \(50000^5\), an astronomical number. We need a way to approximate probability without relying on the full history.

4.5 Reliability vs. Discrimination: The Fundamental Tradeoff

Statistical inference over language data involves a fundamental tradeoff (Jurafsky & Martin, Ch. 6):

  • Discrimination: The more classifcatory features (context features) we use, the more finely we can distinguish different conditions that influence the probability of the target word. Using more history words gives us better discrimination.
  • Reliability: But more features means more bins — and each bin may end up with very few (or zero) training instances. Sparse bins produce unreliable probability estimates.
Key Concept: Finding equivalence classes that balance discrimination (enough context to be precise) and reliability (enough data in each bin) is the core challenge of statistical language modeling. N-gram models are one solution to this tradeoff: they limit context to a fixed window of \(k\) previous words.

4.6 The Markov Assumption and N-gram Models

4.6.1 The Markov Assumption

To make computation tractable, we make the Markov assumption: the probability of a word depends only on a fixed number of previous words (\(k\)), not on the entire history.

Key Concept: \(k\)-th order Markov assumption: \[ P(w_i \mid w_1, w_2, \ldots, w_{i-1}) \approx P(w_i \mid w_{i-k}, \ldots, w_{i-1}) \] The current word is conditioned only on the previous \(k\) words, not on the entire preceding sequence. This dramatically reduces the number of parameters to estimate.

Intuition: Think of it as the model having a deliberately limited "attention span." Instead of remembering the entire sentence history, it only looks at a small, fixed window of preceding words. This trade-off makes language modeling computationally feasible.

4.6.2 N-gram Definitions

An n-gram is a contiguous sequence of \(n\) items (words) from a given text. The parameter \(n\) determines how much context is used:

Table: N-gram Models
\(n\) Name Probability Model
1 Unigram \(P(w_i)\) — No context. Each word is independent.
2 Bigram \(P(w_i \mid w_{i-1})\) — Depends on the immediately previous word.
3 Trigram \(P(w_i \mid w_{i-2}, w_{i-1})\) — Depends on the previous two words.
4 4-gram \(P(w_i \mid w_{i-3}, w_{i-2}, w_{i-1})\) — Depends on the previous three words.
\(n\) \(n\)-gram \(P(w_i \mid w_{i-n+1}, \ldots, w_{i-1})\)
Note: In practice, bigrams (\(n=2\)) and trigrams (\(n=3\)) are most commonly used. Higher-order n-grams (4-gram, 5-gram) suffer from data sparsity — most n-gram sequences will never appear in the training data, even in very large corpora.
Caution: The Parameter Explosion. Estimating all possible n-gram probabilities quickly becomes infeasible as \(n\) grows. With a vocabulary of just 20,000 words:
ModelParameters to Estimate
Bigram (1st order)\(20{,}000 \times 19{,}999 \approx \mathbf{400\text{ million}}\)
Trigram (2nd order)\(20{,}000^2 \times 19{,}999 \approx \mathbf{8\text{ trillion}}\)
4-gram (3rd order)\(20{,}000^3 \times 19{,}999 \approx \mathbf{1.6 \times 10^{17}}\)

This is why 4-gram models require tens of millions of words of training data to become usable, and why bigrams/trigrams remain the practical standard. This is also why alternative equivalence classing strategies exist — such as stemming words, grouping words into semantic classes, or clustering — all of which reduce the effective vocabulary size.

4.6.3 Start and End Tokens

To handle sentence boundaries consistently, we introduce special tokens:

  • <s> (or <START>): Marks the beginning of a sentence.
  • </s> (or <END>): Marks the end of a sentence.
Example: For the sentence "I want to eat":
  • Bigram decomposition: \[ P(\texttt{I, want, to, eat}) \approx P(\texttt{I} \mid \texttt{<s>}) \cdot P(\texttt{want} \mid \texttt{I}) \cdot P(\texttt{to} \mid \texttt{want}) \cdot P(\texttt{eat} \mid \texttt{to}) \cdot P(\texttt{</s>} \mid \texttt{eat}) \]
  • Trigram decomposition: Requires two start tokens: \[ P(\texttt{I, want, to, eat}) \approx P(\texttt{I} \mid \texttt{<s>}, \texttt{<s>}) \cdot P(\texttt{want} \mid \texttt{<s>}, \texttt{I}) \cdot P(\texttt{to} \mid \texttt{I}, \texttt{want}) \cdot P(\texttt{eat} \mid \texttt{want}, \texttt{to}) \cdot P(\texttt{</s>} \mid \texttt{to}, \texttt{eat}) \]

4.7 Maximum Likelihood Estimation (MLE) for N-grams

4.7.1 Computing N-gram Probabilities

N-gram probabilities are estimated from a training corpus using Maximum Likelihood Estimation (MLE) — simply counting and normalizing:

Definition: Bigram MLE
\[ P_{\text{MLE}}(w_i \mid w_{i-1}) = \frac{C(w_{i-1}, w_i)}{C(w_{i-1})} \] where \(C(w_{i-1}, w_i)\) is the count of the bigram \((w_{i-1}, w_i)\) occurring together, and \(C(w_{i-1})\) is the total count of \(w_{i-1}\) in the corpus.
Definition: Trigram MLE
\[ P_{\text{MLE}}(w_i \mid w_{i-2}, w_{i-1}) = \frac{C(w_{i-2}, w_{i-1}, w_i)}{C(w_{i-2}, w_{i-1})} \]
Caution: Order matters! \(P(\texttt{am} \mid \texttt{I})\) and \(P(\texttt{I} \mid \texttt{am})\) are computed differently and can have very different values. In language modeling, the position and order of words is critical — swapping words changes the meaning entirely.

4.7.2 Worked Example: Bigram Counting

Example:

Toy training corpus (3 sentences):

  1. <s> I am Sam </s>
  2. <s> Sam I am </s>
  3. <s> I am Saurabh </s>

Bigram counts:

Table: Bigram counts \(C(w_{i-1}, w_i)\)
I am Sam Saurabh
<s> 2 0 1 0
I 0 2 0 0
am 0 0 2 1
Sam 0 0 0 0

Unigram counts (for denominators): \[ C(\texttt{<s>}) = 3,\; C(\texttt{I}) = 3,\; C(\texttt{am}) = 2,\; C(\texttt{Sam}) = 2,\; C(\texttt{Saurabh}) = 1 \]

Computed bigram probabilities:

\begin{align*} P(\texttt{I} \mid \texttt{<s>}) &= \frac{C(\texttt{<s>, I})}{C(\texttt{<s>})} = \frac{2}{3} \\[0.5ex] P(\texttt{am} \mid \texttt{I}) &= \frac{C(\texttt{I, am})}{C(\texttt{I})} = \frac{2}{3} \\[0.5ex] P(\texttt{Sam} \mid \texttt{am}) &= \frac{C(\texttt{am, Sam})}{C(\texttt{am})} = \frac{2}{2} = 1 \\[0.5ex] P(\texttt{</s>} \mid \texttt{Sam}) &= \frac{C(\texttt{Sam, </s>})}{C(\texttt{Sam})} = \frac{1}{2} \\[0.5ex] P(\texttt{am} \mid \texttt{Sam}) &= \frac{C(\texttt{Sam, am})}{C(\texttt{Sam})} = \frac{1}{2} \end{align*}
Note: Note the subtlety: \(P(\texttt{Sam} \mid \texttt{am}) = 1\) but \(P(\texttt{am} \mid \texttt{Sam}) = \frac{1}{2}\). The order of conditional probability makes a significant difference — this is what encodes the directional structure of language.

4.7.3 Sentence Probability from N-grams

To compute the probability of an entire sentence, multiply the individual n-gram probabilities:

Definition: Bigram Sentence Probability
\[ P(w_1, \ldots, w_n) \approx \prod_{i=1}^{n} P(w_i \mid w_{i-1}) \] using the independence assumption: each bigram is treated as independent of the others.

4.7.4 Underflow and the Log Trick

Since probabilities are numbers between 0 and 1, multiplying many of them leads to numerical underflow (values becoming too small for floating-point representation).

Key Concept: Solution: Use log probabilities. \[ \log P(w_1, \ldots, w_n) = \sum_{i=1}^{n} \log P(w_i \mid w_{i-1}) \] Logarithms convert multiplication into addition, which is:
  • Computationally cheaper (addition is faster than multiplication).
  • Numerically stable (no underflow — log probabilities stay in a reasonable range, typically \(-10\) to \(-1\)).
  • Monotonic: \(\log\) is monotonic, so maximizing log-probability is equivalent to maximizing probability.

Example: Instead of computing: \[ 0.67 \times 0.33 \times 1.0 \times 0.5 \times 1.0 = 0.11055 \] Compute: \[ \log(0.67) + \log(0.33) + \log(1.0) + \log(0.5) + \log(1.0) = -0.400 + (-1.109) + 0 + (-0.693) + 0 = -2.202 \] Then \(P = \exp(-2.202) \approx 0.11055\) if needed.

4.8 The Zero Probability Problem

4.8.1 Why Zeros Are Catastrophic

Consider a slightly larger training corpus with the following bigram probability table:

Example: Partial bigram probability table from a 9,222-sentence corpus:
\(w_i\) \(\rightarrow\) I want to eat
\(w_{i-1}\) \(\downarrow\)
I 0.002 0.33 0.0003 0.0036
want 0.0025 0.006 0.66 0.004
to 0.0005 0.001 0.002 0.28
eat 0.001 0.002 0.001 0.0005

Problem: If we want \(P(\texttt{I want to eat Chinese food})\): \[ P = P(\texttt{I}|\texttt{<s>}) \times P(\texttt{want}|\texttt{I}) \times P(\texttt{to}|\texttt{want}) \times P(\texttt{eat}|\texttt{to}) \times P(\texttt{Chinese}|\texttt{eat}) \times \ldots \]

If any single bigram has zero probability (e.g., \(P(\texttt{Chinese} \mid \texttt{eat})\) might be 0 because that pair never appeared in training), the entire sentence probability becomes 0 — even if the sentence is perfectly valid.

Caution: The multiplication property is a double-edged sword: one zero anywhere in the chain makes the whole product zero. In realistic corpora, most possible n-grams never appear, even in very large datasets. This is the data sparsity problem.
Note: The Black Swan Fallacy. Just because you haven't seen a black swan doesn't mean they don't exist. Similarly, just because a specific N-gram wasn't in the training data doesn't mean it's impossible in the real world. A model that assigns zero probability to unseen-but-valid sequences is overfitting to its training data. We must assign some small probability to unseen events — this process is called smoothing or discounting.
Caution: A Real-World Example. Bahl et al. (1983) reported that after training on 1.5 million words from the IBM Laser Patent Text corpus, 23% of trigram tokens found in further test data drawn from the same corpus were previously unseen. Even with modern web-scale corpora, the problem never disappears — language has a seemingly endless tail of rare events (Zipf's law). Bigger corpora reduce the magnitude of the problem but never eliminate it; there are always rare word combinations that haven't been observed yet.

4.9 Smoothing Techniques

Smoothing (also called discounting) adjusts probability estimates to account for unseen events — it "steals" probability mass from seen n-grams and redistributes it to unseen ones.

4.9.1 Laplace (Add-One) Smoothing

The simplest smoothing method: add 1 to every count. Think of it as giving every possible N-gram the "benefit of the doubt" — we pretend we've seen everything at least once.

Definition: Add-One / Laplace Smoothing
\[ P_{\text{Laplace}}(w_i \mid w_{i-1}) = \frac{C(w_{i-1}, w_i) + 1}{C(w_{i-1}) + |V|} \] where \(|V|\) is the vocabulary size (number of unique words in the corpus).
Key Concept: Why divide by \(|V|\) in the denominator? Two reasons:
  1. Normalization: Adding 1 to every numerator changes the total count. To keep probabilities summing to 1, we must adjust the denominator.
  2. Control magnitude: Dividing by \(|V|\) (typically thousands or millions) keeps the adjusted probability close to 0 for unseen bigrams, rather than giving them substantial probability mass. This reflects the intuition that most unseen pairs are indeed very unlikely.

Example: From the earlier example: \(C(\texttt{want}) = 608\), \(C(\texttt{want}, \texttt{to}) = 400\), \(|V| = 1{,}456\). \[ P_{\text{MLE}}(\texttt{to} \mid \texttt{want}) = \frac{400}{608} \approx 0.658 \] \[ P_{\text{Laplace}}(\texttt{to} \mid \texttt{want}) = \frac{400 + 1}{608 + 1456} = \frac{401}{2064} \approx 0.194 \]

For a zero-count bigram like \(C(\texttt{want}, \texttt{food}) = 0\): \[ P_{\text{MLE}}(\texttt{food} \mid \texttt{want}) = 0 \quad \text{(problem!)} \] \[ P_{\text{Laplace}}(\texttt{food} \mid \texttt{want}) = \frac{0 + 1}{608 + 1456} = \frac{1}{2064} \approx 0.00048 \quad \text{(small but non-zero!)} \]

Example: Laplace smoothing on the BeRP corpus (another illustration): Assume vocabulary size \(V = 1{,}446\).
  • Original MLE: \(P(\texttt{want} \mid \texttt{I}) = 827 / 2533 \approx 0.33\), \(P(\texttt{food} \mid \texttt{I}) = 0 / 2533 = 0\).
  • Laplace smoothed: New denominator for context "I" is \(C(\texttt{I}) + V = 2533 + 1446 = 3979\). \[ P_{\text{Laplace}}(\texttt{want} \mid \texttt{I}) = \frac{827 + 1}{3979} = \frac{828}{3979} \approx 0.21 \] \[ P_{\text{Laplace}}(\texttt{food} \mid \texttt{I}) = \frac{0 + 1}{3979} = \frac{1}{3979} \approx 0.00025 \]

The zero problem is solved — \(P(\texttt{food} \mid \texttt{I})\) is now a small but non-zero number. However, notice that \(P(\texttt{want} \mid \texttt{I})\) fell from 0.33 to 0.21: Laplace smoothing stole significant mass from the frequent event to distribute to unseen ones.

4.9.2 Problems with Laplace Smoothing

Caution: A Blunt Instrument. Laplace smoothing is a blunt instrument. Adding 1 to every count can drastically distort the probability distribution, especially when:
  • The vocabulary \(|V|\) is large, causing the denominator to grow significantly.
  • Many bigrams genuinely have zero probability (or very low probability) — the method redistributes too much mass.
  • The training corpus has many rare events — add-one treats all unseen events equally, which is often inappropriate.

Result: The "smoothed" counts, when back-calculated from the adjusted probabilities, can differ substantially from the original counts: \[ C_{\text{reconstructed}}(w_{i-1}, w_i) = P_{\text{Laplace}}(w_i \mid w_{i-1}) \times \big(C(w_{i-1}) + |V|\big) \] For frequent bigrams, the reconstructed count can be significantly lower than the original, indicating the smoothing has "stolen" too much probability mass.

Caution: How Bad Is Laplace? Church and Gale (1991) demonstrated the severity on a 44-million-word Associated Press newswire corpus with a vocabulary of 400,653 words. Using half the corpus (22 million words) for training:
  • 46.5% of the total probability mass was reassigned to unseen bigrams.
  • Empirically, only 9.2% of bigrams in the further text were previously unseen.
  • Laplace overestimates unseen events by a factor of 5× while drastically undercounting frequent events.

Despite these problems, Laplace's law is actually the Bayesian estimator that results from a uniform prior over events — every n-gram is assumed equally likely a priori. This theoretical basis explains its simplicity but also its weakness: with large vocabularies, a uniform prior is almost certainly wrong.

Note: Laplace smoothing is used successfully in text classification (e.g., Naive Bayes) where vocabulary sizes are modest, but it is generally not recommended for language modeling with large vocabularies. More sophisticated alternatives exist.

4.9.3 Add-\(k\) Smoothing

A generalization of Laplace: add \(k\) (where \(0 < k \leq 1\)) instead of 1. This is also known as Lidstone's law of succession (Hardy & Lidstone, 1920):

\[ P_{\text{Add-}k}(w_i \mid w_{i-1}) = \frac{C(w_{i-1}, w_i) + k}{C(w_{i-1}) + k|V|} \]

The most widely used value is \(k = 0.5\), which has a theoretical justification as Expected Likelihood Estimation (ELE) — also called the Jeffreys-Perks law. ELE corresponds to the expectation of the same quantity maximized by MLE, making it a principled middle ground between MLE and Laplace.

Key Concept: Add-\(k\) as Linear Interpolation. Lidstone's law can be re-expressed as a linear interpolation between the MLE estimate and a uniform prior. Setting \(\mu = \frac{C(w_{i-1})}{C(w_{i-1}) + k|V|}\): \[ P_{\text{Add-}k}(w_i \mid w_{i-1}) = \mu \cdot P_{\text{MLE}}(w_i \mid w_{i-1}) + (1-\mu) \cdot \frac{1}{|V|} \] This reveals add-\(k\) smoothing as a weighted average: the model trusts the MLE estimate proportionally to how much data it has for that context, and fills in with a uniform guess otherwise. As \(C(w_{i-1})\) grows large, \(\mu \to 1\) and the estimate approaches MLE. When counts are small, the uniform prior dominates.

In practice, the choice of \(k\) matters greatly. Smaller \(k\) means less probability mass is redistributed. Common choices: \(k = 0.5\) (expected likelihood), \(k = 0.1\), or \(k\) tuned on held-out data via cross-validation. However, add-\(k\) still shares Laplace's fundamental limitation: it discounts all counts by a linear function, which doesn't match the empirical distribution well at low frequencies.

4.9.4 Good-Turing Discounting

A more sophisticated approach that uses the frequency of frequencies to re-estimate counts. The key insight: use the count of things you've seen once (singletons) to estimate the count of things you've never seen.

Definition: Good-Turing Adjusted Count
Let \(N_c\) be the number of n-gram types that occur exactly \(c\) times in training. Then the adjusted count \(c^*\) is: \[ c^* = (c+1) \frac{N_{c+1}}{N_c} \] And the total probability mass reserved for unseen n-grams: \[ P_{\text{GT}}(\text{unseen}) = \frac{N_1}{N} \] where \(N\) is the total number of n-gram tokens in training.
Example: The Fishing Metaphor. Suppose you're fishing in a lake with 8 species and have caught 10 carp, 3 perch, 2 whitefish, 1 trout, 1 salmon, and 1 eel (18 fish total). Catfish and bass remain unseen.
  • Probability of a new species: \(P_{\text{GT}}(\text{new}) = N_1 / N = 3 / 18 \approx 0.17\)
  • Adjusted count for trout (originally \(c=1\)): \(c^* = 2 \cdot N_2 / N_1 = 2 \cdot 1 / 3 \approx 0.67\)
  • Smoothed probability of trout: \(P_{\text{GT}}(\text{trout}) = 0.67 / 18 \approx 0.037\)

The MLE would have said trout probability is \(1/18\) (too high) and catfish is 0 (too low). Good-Turing correctly reallocates probability mass from singletons to unseen items.

Note: Simple Good-Turing. In practice, raw \(N_c\) values are unreliable for high \(c\) (many bins are empty). Simple Good-Turing (Gale & Sampson, 1995) smooths the \(N_c\) curve by fitting a power law \(N_c = a \cdot c^b\) (via linear regression in log space) and uses the smoothed values for estimation. Also, discounting is typically only applied to low-frequency counts (\(c \leq k\), often \(k=5\)); high-frequency counts are reliable enough to use directly. Katz backoff, a widely-used framework, combines Good-Turing discounting with the backoff strategy described in the next section.

4.10 Interpolation and Backoff

These are more sophisticated techniques for handling unseen n-grams that avoid the bluntness of Laplace smoothing. Both approaches exploit the n-gram hierarchy: when a higher-order n-gram is unseen, we can fall back on lower-order n-grams that are more reliably estimated.

4.10.1 Linear Interpolation

Rather than relying on a single n-gram order, we combine all orders (e.g., trigram, bigram, and unigram) into a single estimate:

Definition: Linear Interpolation for Trigram
\[ P_{\text{interp}}(w_i \mid w_{i-2}, w_{i-1}) = \lambda_1 \, P(w_i \mid w_{i-2}, w_{i-1}) \;+\; \lambda_2 \, P(w_i \mid w_{i-1}) \;+\; \lambda_3 \, P(w_i) \] where: \[ \lambda_1 + \lambda_2 + \lambda_3 = 1, \quad \lambda_j \geq 0 \]
Key Concept: The \(\lambda\) weights represent the trust we place in each n-gram level:
  • \(\lambda_1\) (trigram weight) is usually largest (e.g., \(0.7\)–\(0.9\)) because trigrams capture the most context.
  • \(\lambda_2\) (bigram weight) is moderate (e.g., \(0.1\)–\(0.25\)) — useful when trigrams are sparse.
  • \(\lambda_3\) (unigram weight) is smallest (e.g., \(0.001\)–\(0.05\)) — used only as a last resort, since it has no context.

Intuition: Instead of picking just one expert, we ask all three — the Trigram, Bigram, and Unigram models — for their opinions, then take a weighted average. With \(\lambda_1 = 0.7, \lambda_2 = 0.2, \lambda_3 = 0.1\), we trust the trigram most but still incorporate weaker signals to prevent zero probabilities. In contrast, backoff asks experts one at a time, in a strict hierarchy — it starts with the strongest and only moves down when there's no answer.

Note: The \(\lambda\) values can be learned from a held-out development set using Expectation-Maximization (EM) or by simple grid search — similar to how hyperparameters are tuned in machine learning via cross-validation. Some implementations learn context-dependent lambdas that vary based on the specific \((w_{i-2}, w_{i-1})\) history.

4.10.2 Context-Conditioned Interpolation

A more powerful variant uses \(\lambda\) weights that depend on the specific history context:

\[ P_{\text{interp}}(w_i \mid w_{i-2}, w_{i-1}) = \lambda_1(w_{i-2}, w_{i-1})\, P(w_i \mid w_{i-2}, w_{i-1}) \;+\; \lambda_2(w_{i-2}, w_{i-1})\, P(w_i \mid w_{i-1}) \;+\; \lambda_3(w_{i-2}, w_{i-1})\, P(w_i) \]

For example, if we have very reliable counts for a particular bigram context, we can give more weight to the trigram component; if data is sparse, we lean more on bigrams/unigrams. Bahl et al. (1983) proposed bucketing: grouping histories by raw frequency and tying \(\lambda\) parameters within each bucket. Chen and Goodman (1996) later showed that grouping by the average number of counts per non-zero continuation works even better — this ratio reflects structural/grammatical constraints, not just data sparsity.

Example: Why interpolation works: Consider \(P(\texttt{food} \mid \texttt{want}, \texttt{to})\):
  • If \(C(\texttt{want, to, food}) = 0\) (trigram unseen), the trigram term contributes 0.
  • But \(C(\texttt{to, food})\) might be \(> 0\), so the bigram term contributes a meaningful probability.
  • If even that is 0, the unigram \(P(\texttt{food})\) still provides a small non-zero value.

Thus, interpolation ensures the final probability is never zero as long as the unigram probability is non-zero.

4.10.3 Backoff (Stupid Backoff)

Backoff takes a simpler approach: start with the highest-order n-gram and only "back off" to a lower order if the higher-order count is zero (or below some threshold).

Definition: Katz Backoff (with discounting)
The most widely-used form combines backoff with Good-Turing discounting (Katz, 1987). For a trigram model: \[ P_{\text{katz}}(w_i \mid w_{i-2}, w_{i-1}) = \begin{cases} P^*(w_i \mid w_{i-2}, w_{i-1}) & \text{if } C(w_{i-2}, w_{i-1}, w_i) > 0 \\ \alpha(w_{i-2}, w_{i-1}) \cdot P_{\text{katz}}(w_i \mid w_{i-1}) & \text{otherwise} \end{cases} \]

Here \(P^*\) is a discounted probability (using Good-Turing or another method) — this is crucial because without discounting, backing off would add probability mass, breaking the requirement that probabilities sum to 1. The \(\alpha\) factor is a normalization weight that distributes exactly the mass that was "saved" by discounting the higher-order estimates.

When the (n-1)-gram history itself is unseen (\(C(w_{i-2}, w_{i-1}) = 0\)), the backoff probability simply becomes the (n-1)-gram estimate, recursing down until reaching unigrams.

Key Concept: "Stupid Backoff" (Brants et al., 2007) simplifies this further by using a fixed discount factor:
  • If the trigram count exists: use it (with a small discount).
  • Otherwise, multiply the bigram probability by \(0.4\) (the "stupid" fixed factor).
  • If the bigram is also unseen, multiply the unigram probability by \(0.4^2 = 0.16\).

Think of backoff as consulting experts hierarchically:

  • First, ask the Trigram expert: \(P(w_3 \mid w_1, w_2)\).
  • If the Trigram expert hasn't seen it, "back off" to the Bigram expert: \(P(w_3 \mid w_2)\).
  • If the Bigram expert also hasn't seen it, fall back to the Unigram expert: \(P(w_3)\).

Despite its simplicity (and the fact that it does not produce true probabilities summing to 1), Stupid Backoff performs remarkably well in practice, especially for very large-scale language modeling.

Note: State of the Art. Chen and Goodman (1998) conducted the most comprehensive empirical comparison of smoothing techniques and found that a variant of Kneser-Ney smoothing — an extension of absolute discounting that provides a more accurate way of estimating the lower-order distribution — generally gives the best performance. Their key insight: when backing off to a lower-order n-gram, the distribution should account for how diverse a word's contexts are, not just how frequent it is. For instance, "Francisco" is frequent but almost exclusively follows "San"; "glasses" is less frequent but appears in many contexts. Kneser-Ney assigns higher unigram probability to "glasses" in backoff situations because it's more "versatile."

Other notable methods evaluated include Witten-Bell smoothing, which models the probability of seeing a new (previously unseen) event by counting how often new word types were observed after each history in training — effectively using the count of trigram types as an estimate of the probability of unseen events.

4.11 Pre-built N-gram Resources

Note: You don't always need to compute n-gram counts from scratch. Large-scale n-gram datasets are freely available for generic English:
  • Google N-grams Corpus: Contains n-grams (1-gram through 5-gram) with counts extracted from millions of books. Freely downloadable.
  • Web 1T 5-gram Corpus: Derived from approximately 1 trillion tokens of web text.
  • COCA (Corpus of Contemporary American English): N-gram frequency data with genre and year metadata.

For domain-specific applications (medical, legal, finance), you would still need to compute n-grams from your own corpus, as generic datasets won't capture domain-specific word relationships.

4.12 Applications of N-gram Language Models

N-gram language models, despite their simplicity, are still used in many production systems:

  • Speech Recognition: Acoustic models propose candidate word sequences; the language model ranks them by probability. For example, the famous "recognize speech" vs. "wreck a nice beach" disambiguation.
  • Spelling Correction: Given a misspelled word, candidate corrections are ranked by the probability of the surrounding n-gram context. For instance, detecting that "fifteen minuets" is less probable than "fifteen minutes."
  • Machine Translation: The decoder generates candidate translations; the target-language n-gram model ensures fluency. For example, "briefed reporters" is more likely than "briefed to reporters."
  • Input Method Editors (IME): Predictive text keyboards (like on smartphones) use bigram/trigram models to suggest next words.
  • Optical Character Recognition (OCR): Post-processes OCR output to fix errors based on language model probabilities.
  • Augmentative Communication: Systems that help people unable to use speech or sign language (e.g., Stephen Hawking) rely on word prediction to suggest likely words for selection menus.
  • Authorship Identification: N-gram profiles can distinguish between different authors based on their characteristic word sequence patterns.

4.13 Handling Unknown Words (OOV)

What happens if the test set contains a word that was never seen during training? This is the Out-Of-Vocabulary (OOV) problem.

  • Closed vocabulary: Assumes we know all possible words in advance (rarely true in practice).
  • Open vocabulary: Assumes new words can appear — we need a strategy to handle them.
Key Concept: The <UNK> token strategy:
  1. Define a fixed vocabulary \(V\) during training (often based on frequency — e.g., keep words appearing more than 3 times).
  2. Replace any word in the training data that is not in \(V\) with the special token <UNK> (Unknown).
  3. Train the N-gram probabilities for <UNK> just like any other word — the model learns where unknowns typically appear.
  4. At test time, any OOV word is replaced by <UNK>, and the model uses its learned probability for that token.

This way, the model gracefully handles new vocabulary without breaking — it remembers the statistical patterns of where unknown words tend to occur.

4.14 Perplexity: Evaluation of Language Models

Definition

Key Concept: Perplexity (PPL) is the standard intrinsic evaluation metric for language models. It measures how "surprised" or "confused" the model is when seeing new text.

For a test set \(W = w_1, w_2, \ldots, w_N\): \[ \text{PPL}(W) = P(w_1, w_2, \ldots, w_N)^{-\frac{1}{N}} = \sqrt[N]{\frac{1}{P(w_1, \ldots, w_N)}} \]

Equivalently, using the chain rule and bigram assumption: \[ \text{PPL}(W) = \exp\left( -\frac{1}{N} \sum_{i=1}^{N} \log_2 P(w_i \mid w_{i-1}) \right) \quad \text{(bits)} \]

4.14.1 Interpreting Perplexity

  • Lower perplexity = Better model. A model with PPL \(= 10\) is less "surprised" by the test data than a model with PPL \(= 100\).
  • Intuition: Perplexity can be thought of as the weighted average branching factor — if the model assigns equal probability to \(k\) possible next words at each step, perplexity \(\approx k\).
  • Baseline: A uniform unigram model over \(|V|\) words has PPL \(= |V|\). A perfect model (knowing exactly which word comes next) has PPL \(= 1\).
Note: The Branching Factor Analogy (The Dice Roll). Perplexity can be interpreted as the weighted average branching factor of the language model:

Imagine a model predicting digits (0–9), where each digit is equally likely (\(P = 1/10\)). The perplexity is 10. This means that at any point, the model is as confused when predicting the next item as if it were choosing randomly among 10 possibilities — like rolling a 10-sided die to predict the next word.

If a language model has a perplexity of 109 on the Wall Street Journal corpus, it means the model is as confused by the text as if it were choosing randomly among 109 words at each step.

Example: Perplexity in context:
  • GPT-4 on standard benchmarks: PPL \(\approx 10\)–\(25\) (depending on the dataset).
  • A well-trained trigram model on the same data: PPL \(\approx 100\)–\(200\).
  • A bigram model: PPL \(\approx 200\)–\(400\).
  • The improvement from bigram \(\to\) trigram \(\to\) neural \(\to\) transformer models directly reflects better language understanding through richer context modeling.

Example: Perplexity on the Wall Street Journal (WSJ) corpus:

Lower perplexity confirms that models incorporating more context (trigram > bigram > unigram) are significantly better predictors of the language than models with less or no context.

Note: Perplexity is still widely used today for evaluating transformer-based LLMs. It is the exponential of the cross-entropy loss: \[ \text{PPL} = \exp(\text{Cross-Entropy Loss}) \] This connection makes it a natural metric for any model trained with a cross-entropy objective — from simple n-gram models to GPT-4.

4.14.2 Training, Development, and Test Sets

Proper evaluation requires strict separation of data. A standard split is:

  • Training set (80%): Used to count n-gram frequencies and estimate MLE probabilities.
  • Held-out / Development set (10%): Used to tune hyperparameters (e.g., \(\lambda\) weights in interpolation, discounting factors). Never used for final evaluation.
  • Test set (10%): Used only once, at the end, to compute the final perplexity. Must be truly unseen throughout development.
Caution: Training on the Test Set. Testing on your training data is a cardinal sin in statistical NLP. If the test sentence also appears in training, the model will assign it artificially high probability, giving misleadingly low perplexity. In the worst case, a model that simply memorizes the training data would achieve perfect perplexity of 1 — a completely useless result. Standard practice is to use a development test set for iterative experimentation and reserve a final test set for the published result. Expect performance on the final test set to be slightly lower than on the dev set.

4.14.3 Comparing Language Models Statistically

When comparing two language models, a simple difference in average perplexity is not enough — the variance matters too. Even if Model A has lower perplexity than Model B, the difference may be due to random chance if variance is high. The standard approach is to divide the test set into 20+ smaller samples, compute perplexity on each, and apply a t-test to determine if the difference is statistically significant. Only if the t-test rejects the null hypothesis at a chosen significance level (e.g., \(\alpha = 0.05\)) can we claim one model is better. This is why published language modeling results include both mean perplexity and standard deviation or significance test results.

Bridging Static Embeddings and Language Modeling

4.15 From Static to Contextual

The transition from static word embeddings to contextual language models represents one of the most significant advances in NLP history:

Table: Evolution of Word Representations
Era Approach Embedding Key Limitation
Pre-2013 Count-based (TF-IDF, LSA) Sparse, high-dim Semantic gaps
2013–2017 Static (Word2Vec, GloVe) Dense, fixed per word One vector per word regardless of context
2018–present Contextual (BERT, GPT) Dynamic, context-dependent Computationally expensive
Key Concept: Why static embeddings are limited: A word like "bank" has the same vector whether it means "river bank" or "financial bank". Contextual embeddings solve this by generating different vectors for each occurrence based on surrounding words. However, the intuitions and mathematical foundations of static embeddings (dot products, cosine similarity, vector arithmetic, co-occurrence statistics) directly inform how contextual models are designed and trained.

4.16 N-grams \(\to\) Neural Language Models

N-gram models capture local dependencies but suffer from:

  • Data sparsity: Most n-gram sequences never appear in training.
  • No semantic generalization: "cat" and "feline" are treated as completely different tokens, even though they're synonyms.
  • Fixed context window: Cannot capture long-range dependencies (e.g., "The dog that chased the cat ... ran away" — the bigram model misses the connection between "dog" and "ran").
Note: Neural language models address all three issues by:
  1. Using dense word embeddings that generalize across similar words.
  2. Learning continuous representations of context (not just discrete n-gram patterns).
  3. Employing architectures (RNNs, then Transformers with attention) that can model arbitrarily long dependencies.

These will be covered in the next lecture on neural language modeling and the attention mechanism.

Caution: Iterative Development and Overtraining. In practice, researchers cycle through many model variants — train, test, revise, repeat. Even without explicitly memorizing the test set, repeatedly trying different variants and comparing on the same test data subtly "probes" its contents, leading to overtraining. The correct approach is to have two test sets: a development test set for iterative experimentation and a final test set used only once to produce published results. Performance on the final test set is typically slightly lower than on the dev set.

4.17 Summary: Key Takeaways

  1. CBOW predicts a target word from its surrounding context — faster but less powerful than Skip-Gram for rare words. Think of it as the "fill-in-the-blank" approach.
  2. GloVe combines global co-occurrence counting with local prediction-style training. The ratios of co-occurrence probabilities encode semantic relationships.
  3. Language models assign probabilities to word sequences. The chain rule decomposes joint probability into conditionals.
  4. The Markov assumption simplifies language modeling by limiting context to the previous \(k\) words — this is the foundation of n-gram models.
  5. Bigram and trigram models are practical implementations: each word depends on 1 or 2 previous words.
  6. Data sparsity is the central challenge: most possible n-grams are never seen. Smoothing, interpolation, and backoff are techniques to handle this.
  7. Log probabilities prevent numerical underflow and turn multiplication into addition.
  8. Perplexity is the standard evaluation metric — lower is better, measuring how "surprised" the model is by test data.
  9. All these concepts lay the groundwork for understanding neural language models and transformer architectures.

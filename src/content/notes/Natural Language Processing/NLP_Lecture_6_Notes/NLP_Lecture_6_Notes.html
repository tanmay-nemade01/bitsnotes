Large Language Models and Part-of-Speech Tagging

6.1 Foundations of Large Language Models (LLMs)

6.1.1 Concept Definition and Architectural Scope

A Large Language Model (LLM) is a general-purpose language representation model built on deep neural network architectures—specifically stacked transformer blocks—operating at massive computational scale. Mathematically, LLMs represent an evolutionary convergence across Machine Learning (ML), Deep Learning (DL), and Generative Artificial Intelligence (GenAI). Unlike traditional n-gram models or recurrent neural networks (RNNs) limited by local window sizes or vanishing gradients, LLMs utilize multi-head self-attention mechanisms and feedforward blocks to capture long-range contextual dependencies across thousands of tokens.

The term large refers explicitly to two distinct dimensions of scale:

  1. Parameter Scale: Trainable model weight matrices starting at tens of billions and scaling to 100 billion, 175 billion (e.g., GPT-3), or over a trillion parameters across mixture-of-experts (MoE) systems.
  2. Data and Compute Scale: Pre-training on web-scale text corpora comprising hundreds of gigabytes to tens of terabytes (trillions of tokens). Training requires massive parallel processing clusters (such as NVIDIA A100/H100 Tensor Core GPU clusters) because training on Central Processing Units (CPUs) is computationally intractable.
AI / ML / DL / GenAI Hierarchy:
Artificial Intelligence (AI)
  └─ Machine Learning (ML)
      └─ Deep Learning (DL)
          └─ Generative AI (GenAI)
              └─ Large Language Models (LLMs) — Transformer-based (e.g., 175B+ parameters)

Intuition & Mental Model: Think of an LLM as a high-dimensional, compressed knowledge graph built from vast web text. Pre-trained models (PTMs) act as foundational "base engines." Through fine-tuning (or instruction tuning), these base engines adapt to specialized domains like legal contract review, medical diagnosis assistance, or code generation. Enterprise organizations typically access massive models (175B+) via Cloud Application Programming Interfaces (APIs), while hosting smaller open-source models (such as Llama 3.1 8B) locally on enterprise edge servers.

Scope & Assumptions:

  • Pre-training Requirement: LLM representations assume data is Independent and Identically Distributed (I.I.D.) across large text corpora during self-supervised next-token prediction.
  • Compute Boundaries: Local hosting of 175B+ parameter models requires hundreds of gigabytes of VRAM (GPU memory). If hardware VRAM is exceeded, model inference fails due to Out-Of-Memory (OOM) errors.

6.1.2 Symbol Registry

  • \(N_{\text{params}}\) — Total trainable parameter count of the neural model — \(N_{\text{params}} \in \mathbb{Z}^+\) — integer parameter count
  • \(L\) — Number of stacked transformer layers — \(L \in \mathbb{Z}^+\) — layer index depth
  • \(d_{\text{model}}\) — Hidden embedding dimension — \(d_{\text{model}} \in \mathbb{Z}^+\) — dimension of representation space
  • \(H\) — Number of parallel attention heads per layer — \(H \in \mathbb{Z}^+\) — head count
  • \(d_k, d_v\) — Dimension of Query/Key and Value projection vectors — \(d_k = d_v = d_{\text{model}} / H\)
  • \(d_{\text{ff}}\) — Inner hidden dimension of the Feedforward Network — \(d_{\text{ff}} \in \mathbb{Z}^+\), typically \(d_{\text{ff}} = 4 \cdot d_{\text{model}}\)
  • \(W_Q, W_K, W_V, W_O\) — Weight projection matrices in Multi-Head Attention — \(W_Q, W_K, W_V \in \mathbb{R}^{d_{\text{model}} \times d_k}\), \(W_O \in \mathbb{R}^{d_{\text{model}} \times d_{\text{model}}}\)

6.1.3 Mathematical Formulation of LLM Model Parameters

The total parameter count \(N_{\text{params}}\) of a transformer architecture is determined by summing the trainable weight matrices and bias vectors across all \(L\) stacked transformer layers, alongside token embedding and output classification layers.

For a standard Transformer block consisting of Multi-Head Attention (MHA) and a Feedforward Network (FFN):

1. Multi-Head Attention (MHA) Layer:

  • Query, Key, and Value projections: 3 weight matrices of size \(d_{\text{model}} \times d_{\text{model}}\).
  • Output projection: 1 weight matrix of size \(d_{\text{model}} \times d_{\text{model}}\).
  • Total MHA parameters per layer:
\[ N_{\text{MHA}} = 4 \cdot d_{\text{model}}^2 \]

2. Feedforward Network (FFN) Layer:

  • First linear expansion: \(d_{\text{model}} \rightarrow d_{\text{ff}}\) weight matrix of size \(d_{\text{model}} \times d_{\text{ff}}\).
  • Second linear projection: \(d_{\text{ff}} \rightarrow d_{\text{model}}\) weight matrix of size \(d_{\text{ff}} \times d_{\text{model}}\).
  • Setting \(d_{\text{ff}} = 4 \cdot d_{\text{model}}\):
\[ N_{\text{FFN}} = 2 \cdot d_{\text{model}} \cdot d_{\text{ff}} = 2 \cdot d_{\text{model}} \cdot (4 \cdot d_{\text{model}}) = 8 \cdot d_{\text{model}}^2 \]

3. Total Parameters Per Transformer Layer:

\[ N_{\text{layer}} = N_{\text{MHA}} + N_{\text{FFN}} = 4 \cdot d_{\text{model}}^2 + 8 \cdot d_{\text{model}}^2 = 12 \cdot d_{\text{model}}^2 \]

4. Total Model Parameter Capacity Across \(L\) Layers:

\[ N_{\text{params}} \approx L \cdot N_{\text{layer}} = 12 \cdot L \cdot d_{\text{model}}^2 \]

Verbatim professor explanation: "When we say parameters in LLMs, like 175 billion parameters, these are model weights—not input tokens. They are the learned weight matrices inside the key, query, value matrices of multi-headed attention, feedforward layers, and output projection layers learned via backpropagation."

Worked Calculation — Estimating Transformer Parameter Count:

Problem: Calculate the parameter count for a standard 12-layer transformer model with hidden embedding dimension \(d_{\text{model}} = 768\) and feedforward inner dimension \(d_{\text{ff}} = 3072\) (ignoring biases and embedding layers for minimal layer estimation).

Step-by-Step Derivation:

1. Calculate Multi-Head Attention parameters per layer:

\[ N_{\text{MHA}} = 4 \cdot d_{\text{model}}^2 = 4 \cdot (768)^2 = 4 \cdot 589,824 = 2,359,296 \text{ parameters} \]

2. Calculate Feedforward Network parameters per layer:

\[ N_{\text{FFN}} = 2 \cdot d_{\text{model}} \cdot d_{\text{ff}} = 2 \cdot 768 \cdot 3072 = 4,718,592 \text{ parameters} \]

3. Sum layer parameters:

\[ N_{\text{layer}} = N_{\text{MHA}} + N_{\text{FFN}} = 2,359,296 + 4,718,592 = 7,077,888 \text{ parameters} \]

4. Multiply across \(L = 12\) layers:

\[ N_{\text{params}} = 12 \times 7,077,888 = 84,934,656 \approx 85 \text{ million parameters} \]

Sense Check: Adding vocabulary embedding layers (\(V \times d_{\text{model}} = 30,000 \times 768 \approx 23\text{M}\)) yields \(\approx 108\text{M}\) parameters, matching standard BERT-Base / GPT-1 architectural capacity.

Common Pitfall:

  • Confusing Parameters with Context Tokens: Students frequently mistake the parameter count (e.g., 175B) for the context window length (e.g., 4k or 128k tokens). Parameters are static, learned scalar weights stored in GPU memory; context tokens are dynamic sequence inputs processed at inference time.

6.2 Prompt Engineering and Context Management

6.2.1 Principles of Prompt Design and Context Windows

Prompt engineering is the empirical and technical discipline of constructing, formatting, and optimizing natural language inputs (prompts) to direct a pre-trained Large Language Model (LLM) toward deterministic, high-quality, and task-aligned outputs. Prompt engineering spans two distinct operational paradigms:

1. Hard Prompt Engineering: Textual prompt design where human users or front-end software explicitly compose discrete text tokens, system instructions, role assignments, and context constraints.

2. Soft Prompt Engineering: Optimization of continuous latent vector embeddings appended directly to the input representation in deep model space, learned via gradient descent while keeping base LLM weights frozen.

Intuition & Mental Model: Think of hard prompt engineering as writing clear, unambiguous instructions for an assistant. Every LLM operates within a fixed context window—the maximum buffer of tokens (input query + system context + generated output) that can be processed in a single forward pass. Because tokens incur computational latency, API billing costs, and carbon footprint, prompt design requires strict output length management (e.g., instructing the model to "summarize in exactly 3 bullet points").

Prompt Component Anatomy:
+--------------------+--------------------------------------------------------+
| Component          | Concrete Example                                       |
+--------------------+--------------------------------------------------------+
| Role Definition    | "You are an expert NLP professor."                     |
| Context Setting    | "We are reviewing Part-of-Speech tagging concepts."    |
| Task Instruction   | "Explain the difference between open and closed POS." |
| Constraints        | "Limit your answer to 3 bullet points. No code."       |
+--------------------+--------------------------------------------------------+

Scope & Assumptions — Context Window Constraints:

  • Fixed Memory Window: If the combined token length of the prompt and generated response exceeds the maximum context window (e.g., 4,096 tokens in early models or 128,000 in modern LLMs), the model truncates earlier tokens, leading to loss of context memory.
  • Attention Drift ("Lost in the Middle"): In extremely long context windows, transformer self-attention scores tend to decay for information placed in the middle of long inputs, prioritizing tokens at the very beginning and end.

6.2.2 Zero-Shot vs. Few-Shot Inference

During model inference (the deployment phase where model parameters \(\theta\) remain completely frozen), prompt context determines how the model generalizes to new tasks without updating weights:

  • Zero-Shot Inference: The model is presented purely with a task description and test input, without any prior input-output demonstrations. It relies entirely on representations learned during pre-training.
  • Few-Shot Inference (In-Context Learning): The model is provided with \(N\) concrete input-output demonstration pairs (\(N \ge 1\)) inside the prompt before the target query. This conditions the auto-regressive next-token distribution to adhere to the target format.

Comparative Example — Zero-Shot vs. Few-Shot Prompting:

Scenario: Sentiment classification of customer review text.

1. Zero-Shot Prompt:

   Task: Classify sentiment of the review: "The battery dies after two hours."
   Output: [Model may output unstructured conversational prose like "This sounds like a complaint about battery life..."]

2. Few-Shot Prompt (3-Shot In-Context Learning):

   Task: Classify customer review sentiment as POSITIVE, NEGATIVE, or NEUTRAL.

   Review: "Outstanding build quality and fast display." -> POSITIVE
   Review: "Average shipping speed, item arrived intact." -> NEUTRAL
   Review: "The battery dies after two hours." -> NEGATIVE
   Review: "The screen colors look vibrant and bright." -> POSITIVE

   Review: "The motor makes a loud grinding noise." ->

Model Output: NEGATIVE

Sense Check: The few-shot prompt enforces deterministic output formatting (NEGATIVE) directly aligning with downstream parsers.

Common Pitfall:

  • Confusing In-Context Learning with Fine-Tuning: Few-shot prompting does not modify or update model weights (\(\Delta \theta = 0\)). It alters only the active hidden state activations during a single inference step. Fine-tuning updates model weight matrices via backpropagation.

6.2.3 Symbol Registry

  • \(\theta\) — Pre-trained transformer model parameters — \(\theta \in \mathbb{R}^P\) — frozen weight vector
  • \(\Delta \theta\) — Weight update delta — \(\Delta \theta = 0\) — zero parameter update during in-context inference
  • \(N\) — Number of demonstration examples in a few-shot prompt — \(N \in \mathbb{Z}_{\ge 0}\) — integer count
  • \(P(y \mid x)\) — Auto-regressive conditional token probability — \(P \in [0, 1]\) — output probability scalar

6.3 Part-of-Speech (POS) Tagging Fundamentals

6.3.1 Definition, Motivation, and Disambiguation

Part-of-Speech (POS) tagging is the sequence labeling task of automatically assigning a syntactic lexical class marker (such as Noun, Verb, Adjective, or Preposition) to each word token in an input text sequence. A lexicon is the full dictionary repository of words in a language, while lexical class markers denote the syntactic categories assigned to those words.

Intuition & Pedagogical Motivation: Why is POS tagging hard? Because natural language exhibits extreme lexical ambiguity. A vast number of English words can act as different parts of speech depending entirely on their surrounding context words.

Consider the famous ambiguous sentence from the companion materials:

"I can can the can."

1. First "can" = Modal Verb (MD) — indicating ability

2. Second "can" = Base Main Verb (VB) — meaning to preserve/pack

3. Third "can" = Singular Noun (NN) — referring to a physical container

Contextual Disambiguation of the Word "back":
+--------------------------------------+------------------------+-------------+
| Sentence Context                     | Syntactic Role         | Tag (Penn)  |
+--------------------------------------+------------------------+-------------+
| "He opened the back door."           | Adjective (modifies)   | JJ          |
| "He carried the box on his back."    | Noun (direct object)   | NN          |
| "They promised to back the bill."    | Verb (infinitive)      | VB          |
| "The team won the voters back."      | Adverb (directional)   | RB          |
+--------------------------------------+------------------------+-------------+

Agentic AI Safety & Tool Calling Warning:

In modern agentic AI systems, POS tagging provides deterministic syntactic constraints during tool parsing.

Example: In the natural language command "set the timer for the oven to 10 minutes", a POS parser identifies "set" as the governing action verb, "timer" as the direct object noun phrase, and "for the oven" as a prepositional modifier phrase. Correct syntactic tagging ensures the agentic controller attaches the 10-minute duration parameter to the timer hardware interface rather than executing a dangerous operation directly on the oven heating element.

6.3.2 Real-World NLP Applications of POS Tagging

  • Voice Assistants & Command Parsing: Virtual assistants identify imperative action verbs (VB) to extract intent and target parameters from spoken commands.
  • Machine Translation & Named Entity Boundary Preservation: Machine Translation systems use proper noun tags (NNP) to preserve non-translatable proper nouns (such as "BITS Pilani" or "Chetana") without incorrectly translating them into literal dictionary meanings.
  • Sentiment Analysis & Opinion Mining: Pipelines extract descriptive adjectives (JJ, JJR, JJS) and adverbs (RB) to evaluate product review polarity.
  • Text-to-Speech (TTS) Synthesis: Pronunciation of words like "lead" (\(/liːd/\) as Verb vs. \(/lɛd/\) as Noun) depends directly on POS tag disambiguation.

6.3.3 Student Questions and Answers

Q: Why is POS tagging still relevant when modern LLMs and agentic systems exist?

A: POS tagging provides deterministic syntactic structure, syntactic disambiguation, and named entity boundaries. In agentic tool execution, POS tags disambiguate verb targets, ensuring that action execution attaches to the intended parameter and preventing destructive hardware or API operations.

6.4 Closed vs. Open Word Classes and POS Tagsets

6.4.1 Open and Closed Lexical Classes

Natural language vocabularies are partitioned into two fundamental lexical class categories based on how dynamic their vocabulary membership is over time:

1. Closed Class Words: Structural functional categories containing a fixed, small, and finite set of words that rarely change or admit new members. Examples include determiners/articles (a, an, the), prepositions (in, on, of, by), pronouns (he, she, it), and conjunctions (and, but). POS tagging for closed classes is simple and can be handled deterministically using static dictionary lookups.

2. Open Class Words: Content-bearing categories with dynamic, unbounded vocabularies that constantly grow and adapt through neologisms, technical terminology, and slang (e.g., words like selfie, prompting, finetuning). Examples include Nouns, Verbs, Adjectives, and Adverbs. Tagging open class words requires context-aware probabilistic modeling.

Intuition & Mental Model: Think of Closed Class words as the static structural mortar holding a sentence together—their dictionary definition and POS category are fixed and finite. Think of Open Class words as the dynamic bricks carrying semantic meaning—new words enter the language constantly, and existing content words adapt their syntactic function based on context.

Lexical Class Taxonomy:
+--------------------+-----------------------------+------------------------------------------+
| Lexical Class      | Members / Categories        | Vocabulary Nature & Tagging Approach     |
+--------------------+-----------------------------+------------------------------------------+
| Closed Class       | Articles, Prepositions,     | Fixed, finite set; handles via static    |
|                    | Pronouns, Conjunctions      | dictionary lookup matching.              |
+--------------------+-----------------------------+------------------------------------------+
| Open Class         | Nouns, Verbs, Adjectives,   | Dynamic, unbounded; constantly evolves;  |
|                    | Adverbs                     | requires context-aware sequence models.  |
+--------------------+-----------------------------+------------------------------------------+

6.4.2 Tagsets: Traditional vs. Penn Treebank

While traditional English school grammar defines 8 basic POS categories (Noun, Pronoun, Verb, Adverb, Adjective, Preposition, Conjunction, Interjection), computational NLP algorithms require fine-grained tagsets to distinguish morphological features such as tense, number, aspect, and degree.

The standard benchmark tagset in modern NLP (used across NLTK, spaCy, and Stanford NLP) is the Penn Treebank POS Tagset, which defines 45 fine-grained tags.

6.5 POS Tagging as a Sequence Learning Problem

6.5.1 Sequence Learning Formulation and Other Domain Examples

Sequence learning (or sequence labeling) is a structural supervised learning paradigm where both the input and the output consist of ordered, variable-length sequences of tokens exhibiting strong temporal or positional dependencies.

Formally, given an input word sequence \(W = (w_1, w_2, \dots, w_n)\) of length \(n\), the goal of sequence learning for POS tagging is to predict the joint optimal target sequence of tags \(\hat{T} = (\hat{t}_1, \hat{t}_2, \dots, \hat{t}_n)\) that maximizes the conditional probability \(P(T \mid W)\):

\[ \hat{T} = \arg\max_{T} P(T \mid W) \]

Why Independent Classifiers Fail: Standard non-sequential machine learning classifiers (such as binary Logistic Regression, Support Vector Machines, or Naive Bayes) process each input token independently without memory of neighboring predictions. They fail on POS tagging because the syntactic category of word \(w_i\) relies heavily on:

1. The preceding tag \(t_{i-1}\) (e.g., a Determiner DT is overwhelmingly followed by a Noun NN or Adjective JJ).

2. The surrounding word context \(w_{i-1}, w_{i+1}\).

Sequence Learning Input-Output Mapping:
Input Sequence W  :  (w_1="the",  w_2="smart",  w_3="dog",  w_4="barks")
                       |            |             |           |
Output Sequence T :  (t_1=DT,     t_2=JJ,       t_3=NN,     t_4=VBZ)

Cross-Domain Sequence Learning Parallels:

  • Bioinformatics & Gene Sequencing: DNA/RNA base pairs (\(A, C, G, T\)) form sequential strands analyzed to identify exons, introns, and mutation patterns in cancer research. Sequencers target faulty sequences while preserving healthy genomic structures.
  • Named Entity Recognition (NER): Tagging tokens with entity classes (B-PER, I-PER, B-ORG, O) to extract people, locations, and organizations.
  • Semantic Role Labeling (SRL): Assigning predicate-argument roles (Agent, Patient, Instrument) to parse who did what to whom.

6.5.2 Comparison of POS Tagging Approaches

Three major computational paradigms have evolved to solve POS sequence tagging:

Approach Paradigm Primary Mechanism Computational Speed Explainability Accuracy & Robustness
Rule-Based (e.g., Brill Tagger) Hand-crafted syntactic rules and morphological transform dictionaries Extremely fast 100% transparent & deterministic Low (fails on out-of-vocabulary edge cases)
Statistical (HMM / MEMM / CRF) Probabilistic Markov transition & emission sequence models Fast & lightweight High (mathematical audit trail & probability scores) High & robust
Neural / Transformer (BiLSTM-CRF / BERT) Deep contextual embeddings with bidirectional attention Slow (requires GPU acceleration) Low (black-box neural parameters) State-of-the-art (highest benchmark accuracy)

Scope & Trade-offs: While Transformer-based POS taggers achieve top accuracy, Statistical HMM models remain heavily tested in academic curricula and deployed in edge environments due to their minimal compute memory requirements and exact mathematical interpretability.

6.5.3 Symbol Registry

  • \(W\) — Input sentence sequence of words — \(W = (w_1, w_2, \dots, w_n)\) — ordered token vector
  • \(T\) — Target sequence of POS tags — \(T = (t_1, t_2, \dots, t_n)\) — ordered label vector
  • \(n\) — Length of the input sentence — \(n \in \mathbb{Z}^+\) — sequence token count
  • \(\hat{T}\) — Predicted optimal tag sequence — \(\hat{T} = \arg\max_T P(T \mid W)\) — argmax output sequence

6.6 Hidden Markov Models (HMM) for POS Tagging

6.6.1 Mathematical Formulation: Bayes Rule, Prior, and Likelihood

A Hidden Markov Model (HMM) is a generative probabilistic sequence model that assumes the system is governed by a sequence of hidden states (POS tags \(T = (t_1, t_2, \dots, t_n)\)) which generate visible observations (word tokens \(W = (w_1, w_2, \dots, w_n)\)).

The decoding objective is to identify the most probable hidden tag sequence \(\hat{T}\) given the observed sequence of words \(W\). Applying Bayes' Rule:

\[ \hat{T} = \arg\max_{T} P(T \mid W) = \arg\max_{T} \frac{P(W \mid T) \cdot P(T)}{P(W)} \]

Because the marginal likelihood (evidence) \(P(W)\) is constant across all candidate tag sequences \(T\), the denominator is dropped, reducing decoding to maximizing the joint probability:

\[ \hat{T} = \arg\max_{T} P(W \mid T) \cdot P(T) \]

where \(P(T)\) represents the prior probability of the tag sequence, and \(P(W \mid T)\) represents the likelihood of generating word sequence \(W\) given tags \(T\).

Intuition — The Climatologist & Ice Cream Analogy:

Imagine you are a climatologist in the year 3000 analyzing lost historical weather records from 2007:

  • Hidden States (Unobserved): The daily weather (\(H = \text{Hot}\), \(C = \text{Cold}\)). You cannot see past weather directly.
  • Observations (Visible): A preserved diary listing how many ice creams Jason ate each day (\(1\), \(2\), or \(3\)).

If Jason ate 3 ice creams, it was likely Hot; if he ate 1, it was likely Cold.

In NLP POS tagging:

  • Hidden States \(\rightarrow\) POS Tags (\(t_i \in \{\text{NN}, \text{VB}, \text{JJ}, \dots\}\))
  • Observations \(\rightarrow\) Words (\(w_i \in \{\text{"can"}, \text{"race"}, \text{"the"}\}\))

To make computing \(P(W \mid T) \cdot P(T)\) tractable for long sentences, HMMs make two core independence assumptions:

1. First-Order Markov Tag Transition Assumption (Prior):

The probability of tag \(t_i\) depends strictly on the immediately preceding tag \(t_{i-1}\), independent of earlier tags:

\[ P(T) = P(t_1, t_2, \dots, t_n) \approx \prod_{i=1}^{n} P(t_i \mid t_{i-1}) \]

2. Word Emission Independence Assumption (Likelihood):

The probability of emitting word \(w_i\) depends strictly on its own POS tag \(t_i\), independent of neighboring words or tags:

\[ P(W \mid T) = P(w_1, w_2, \dots, w_n \mid t_1, t_2, \dots, t_n) \approx \prod_{i=1}^{n} P(w_i \mid t_i) \]

Fundamental HMM Joint Probability Equation:

Combining both assumptions yields the full joint probability formulation:

\[ P(T, W) = P(T) \cdot P(W \mid T) = \prod_{i=1}^{n} P(t_i \mid t_{i-1}) \cdot P(w_i \mid t_i) \]

Verbatim professor explanation: "We split the posterior probability into two parts using Bayes rule: the likelihood of words given tags, and the prior probability of the tag sequence. Under the bigram assumption, the prior is just the product of tag transitions, and under the independence assumption, the likelihood is the product of word emissions."

Limitation of HMM Independence Assumptions:

The word emission assumption (\(P(w_i \mid t_i)\)) assumes word emissions are completely independent of context. In reality, whether "race" is a noun or verb depends on surrounding words ("to race" vs. "the race"). Maximum Entropy Markov Models (MEMMs) and Conditional Random Fields (CRFs) were invented to overcome this HMM limitation by allowing rich contextual features.

6.6.2 Symbol Registry

  • \(P(t_i \mid t_{i-1})\) — Tag transition probability — \(P(t_i \mid t_{i-1}) \in [0,1]\) — bigram transition scalar in matrix \(A\)
  • \(P(w_i \mid t_i)\) — Word emission probability — \(P(w_i \mid t_i) \in [0,1]\) — tag-to-word emission scalar in matrix \(B\)
  • \(\pi_i\) — Initial state probability — \(\pi_i = P(t_1 = t_i \mid \text{start})\) — start tag probability distribution vector
  • \(C(t_{i-1}, t_i)\) — Frequency count of tag bigram \(t_{i-1}, t_i\) in corpus — \(C \in \mathbb{Z}_{\ge 0}\)
  • \(C(t_i)\) — Total frequency count of tag \(t_i\) in corpus — \(C \in \mathbb{Z}_{\ge 0}\)
  • \(C(t_i, w_i)\) — Frequency count of tag \(t_i\) emitting word \(w_i\) — \(C \in \mathbb{Z}_{\ge 0}\)

6.6.3 Parameter Estimation from Labeled Corpora

HMM transition probabilities (Matrix \(A\)), emission probabilities (Matrix \(B\)), and initial probabilities (\(\boldsymbol{\pi}\)) are estimated from annotated training corpora (e.g., Penn Treebank) using Maximum Likelihood Estimation (MLE) count ratios:

1. Transition Matrix \(A\) Estimation:

\[ A_{j,k} = P(t_k \mid t_j) = \frac{C(t_j, t_k)}{C(t_j)} \]

Condition: Every row \(j\) in Matrix \(A\) sums to 1.0: \(\sum_k P(t_k \mid t_j) = 1.0\).

2. Emission Matrix \(B\) Estimation:

\[ B_{j,m} = P(w_m \mid t_j) = \frac{C(t_j, w_m)}{C(t_j)} \]

Condition: Every row \(j\) in Matrix \(B\) sums to 1.0: \(\sum_m P(w_m \mid t_j) = 1.0\).

3. Initial State Vector \(\boldsymbol{\pi}\) Estimation:

\[ \pi_j = P(t_1 = t_j \mid \text{start}) = \frac{C(\text{start}, t_j)}{C(\text{start})} \]

6.6.4 Student Questions and Answers

Q: How are row and column conditional probabilities structured in transition versus emission matrices?

A: In the transition matrix \(A\), rows represent the previous state \(t_{i-1}\) and columns represent the next state \(t_i\); each row sums to 1.0. In the emission matrix \(B\), rows represent POS tags \(t_i\) and columns represent emitted words \(w_i\); each tag row sums to 1.0.

6.7 Worked Computational Examples: Markov Chains and HMMs

6.7.1 Symbol Registry

  • \(S\) — Discrete state space — \(S = \{s_1, s_2, \dots, s_K\}\) — set of hidden states (e.g., weather or POS tags)
  • \(\boldsymbol{\pi}\) — Initial state distribution vector — \(\boldsymbol{\pi} \in \mathbb{R}^K, \sum \pi_i = 1\) — state start probabilities
  • \(A\) — State transition probability matrix — \(A \in \mathbb{R}^{K \times K}\) — where \(A_{i,j} = P(s_j \mid s_i)\)
  • \(B\) — Observation emission probability matrix — \(B \in \mathbb{R}^{K \times V}\) — where \(B_{i,k} = P(w_k \mid s_i)\)

6.7.2 Example 1: Markov Chain Weather Prediction

Worked Example 1 — 4-Day Warm Weather Markov Chain Probability:

Problem Description: Consider a 3-state weather Markov chain with discrete state space \(S = \{1: \text{Hot}, 2: \text{Cold}, 3: \text{Warm}\}\).

Given:

  • Initial state distribution vector \(\boldsymbol{\pi} = [0.2, 0.2, 0.2]\) (where initial warm probability \(\pi_{\text{Warm}} = 0.2\)).
  • Warm-to-warm transition probability \(P(\text{Warm} \mid \text{Warm}) = 0.6\).

Task: Compute the joint probability of observing 4 consecutive warm days: \(P(\text{Warm}_1, \text{Warm}_2, \text{Warm}_3, \text{Warm}_4)\).

Step-by-Step Derivation:

1. Write the Markov chain chain-rule factorization:

\[ P(\text{Warm}_1, \text{Warm}_2, \text{Warm}_3, \text{Warm}_4) = P(\text{Warm}_1) \cdot P(\text{Warm}_2 \mid \text{Warm}_1) \cdot P(\text{Warm}_3 \mid \text{Warm}_2) \cdot P(\text{Warm}_4 \mid \text{Warm}_3) \]

2. Substitute numerical parameters:

\[ P(\text{Warm}_1, \text{Warm}_2, \text{Warm}_3, \text{Warm}_4) = 0.2 \times 0.6 \times 0.6 \times 0.6 \]

3. Simplify exponential transition term:

\[ P(\text{Warm}_1, \text{Warm}_2, \text{Warm}_3, \text{Warm}_4) = 0.2 \times (0.6)^3 = 0.2 \times 0.216 = \mathbf{0.0432} \]

Final Answer: 0.0432 (or 4.32%).

Sense Check: Because \(0.6 < 1.0\), multiplying consecutive transition probabilities strictly decays joint probability over time, as expected for Markov chains.

Verbatim professor explanation: "To find the probability of four consecutive warm days, take the initial probability of warm on day one, which is 0.2, and multiply it by the warm-to-warm transition probability of 0.6 raised to the power of three, giving 0.0432."

6.7.3 Example 2: POS Disambiguation of Ambiguous Words

Worked Example 2 — Disambiguating "race" as Verb vs. Noun Using HMM Joint Probability:

Problem Description: Resolve the POS tag for the ambiguous word "race" in the target sentence phrase "expected to race tomorrow".

Candidate Tag Sequences:

  • Sequence A (Verb reading): \(T_A = (\text{TO}, \text{VB}, \text{NR})\)
  • Sequence B (Noun reading): \(T_B = (\text{TO}, \text{NN}, \text{NR})\)

Given HMM transition and emission parameters from training data:

  • \(P(\text{VB} \mid \text{TO}) = 0.80\), \(P(\text{NN} \mid \text{TO}) = 0.15\)
  • \(P(\text{"race"} \mid \text{VB}) = 0.10\), \(P(\text{"race"} \mid \text{NN}) = 0.02\)
  • \(P(\text{NR} \mid \text{VB}) = 0.25\), \(P(\text{NR} \mid \text{NN}) = 0.10\)

Step-by-Step Derivation:

1. Calculate joint HMM likelihood score for Sequence A (Verb):

\[ \text{Score}(T_A) = P(\text{VB} \mid \text{TO}) \cdot P(\text{"race"} \mid \text{VB}) \cdot P(\text{NR} \mid \text{VB}) \] \[ \text{Score}(T_A) = 0.80 \times 0.10 \times 0.25 = \mathbf{0.0200} \]

2. Calculate joint HMM likelihood score for Sequence B (Noun):

\[ \text{Score}(T_B) = P(\text{NN} \mid \text{TO}) \cdot P(\text{"race"} \mid \text{NN}) \cdot P(\text{NR} \mid \text{NN}) \] \[ \text{Score}(T_B) = 0.15 \times 0.02 \times 0.10 = \mathbf{0.0003} \]

3. Compare joint likelihood scores:

\[ \text{Score}(T_A) = 0.0200 \gg 0.0003 = \text{Score}(T_B) \]

Final Decision: The tagger assigns the Verb (VB) tag to "race".

Sense Check: The tag bigram transition \(P(\text{VB} \mid \text{TO}) = 0.80\) heavily favors infinitival verbs following "to", driving Sequence A's score nearly 67 times higher than Sequence B.

6.7.4 Example 3: Transition and Emission Matrix Calculation from Corpus

Worked Example 3 — MLE Parameter Matrix Estimation from Annotated Corpus:

Problem Description: Consider a tiny annotated training corpus containing three sentence fragments:

1. start / DT / NNS / stop (Words: "the employees")

2. start / DT / NN / stop (Words: "the employee")

3. start / NNS / stop (Words: "employees")

Task: Compute MLE transition probabilities \(P(\text{DT} \mid \text{start})\), \(P(\text{stop} \mid \text{NNS})\) and emission probabilities \(P(\text{"the"} \mid \text{DT})\), \(P(\text{"employee"} \mid \text{DT})\).

Step-by-Step Derivation:

1. Calculate transition probability \(P(\text{DT} \mid \text{start})\):

  • Total occurrences of start state \(C(\text{start}) = 3\).
  • Occurrences of DT immediately following start \(C(\text{start}, \text{DT}) = 2\).
\[ P(\text{DT} \mid \text{start}) = \frac{C(\text{start}, \text{DT})}{C(\text{start})} = \frac{2}{3} \approx \mathbf{0.667} \]

2. Calculate transition probability \(P(\text{stop} \mid \text{NNS})\):

  • Total occurrences of tag NNS across corpus \(C(\text{NNS}) = 2\).
  • Occurrences of stop immediately following NNS \(C(\text{NNS}, \text{stop}) = 2\).
\[ P(\text{stop} \mid \text{NNS}) = \frac{C(\text{NNS}, \text{stop})}{C(\text{NNS})} = \frac{2}{2} = \mathbf{1.000} \]

3. Calculate emission probability \(P(\text{"the"} \mid \text{DT})\):

  • Total occurrences of tag DT \(C(\text{DT}) = 2\).
  • Occurrences of word "the" emitted by tag DT \(C(\text{DT}, \text{"the"}) = 2\).
\[ P(\text{"the"} \mid \text{DT}) = \frac{C(\text{DT}, \text{"the"})}{C(\text{DT})} = \frac{2}{2} = \mathbf{1.000} \]

4. Calculate emission probability \(P(\text{"employee"} \mid \text{DT})\):

  • Word "employee" never appears under tag DT (\(C(\text{DT}, \text{"employee"}) = 0\)).
\[ P(\text{"employee"} \mid \text{DT}) = \frac{0}{2} = \mathbf{0.000} \]

Final Answers: \(P(\text{DT} \mid \text{start}) = \mathbf{0.667}\), \(P(\text{stop} \mid \text{NNS}) = \mathbf{1.000}\), \(P(\text{"the"} \mid \text{DT}) = \mathbf{1.000}\), \(P(\text{"employee"} \mid \text{DT}) = \mathbf{0.000}\).

Sense Check: In this tiny corpus, every NNS tag ends a sentence (so transition to stop is 1.0) and every DT tag emits "the" (so emission is 1.0).

6.7.5 Example 4: Ice Cream Diary Hidden Markov Model

Worked Example 4 — Ice Cream Diary HMM Evaluation:

Problem Description: In Jason's Ice Cream HMM (Jurafsky & Martin textbook formulation), hidden weather states are \(S = \{H: \text{Hot}, C: \text{Cold}\}\) and observed ice cream counts are \(V = \{1, 2, 3\}\).

Given HMM parameter matrices:

  • Initial probabilities \(\boldsymbol{\pi}\): \(\pi_H = 0.8\), \(\pi_C = 0.2\)
  • Transition matrix \(A\):
  • \(P(H \mid H) = 0.6\), \(P(C \mid H) = 0.4\)
  • \(P(H \mid C) = 0.5\), \(P(C \mid C) = 0.5\)
  • Emission matrix \(B\):
  • \(P(1 \mid H) = 0.2\), \(P(2 \mid H) = 0.4\), \(P(3 \mid H) = 0.4\)
  • \(P(1 \mid C) = 0.5\), \(P(2 \mid C) = 0.4\), \(P(3 \mid C) = 0.1\)

Task: Evaluate the joint HMM probability for observing ice cream sequence \(W = (1, 3, 1)\) along hidden weather path \(T = (C, H, C)\) (Cold on day 1, Hot on day 2, Cold on day 3).

Step-by-Step Derivation:

1. Formulate the joint probability product equation:

\[ P(T, W) = \pi_C \cdot P(w_1=1 \mid C) \cdot P(t_2=H \mid C) \cdot P(w_2=3 \mid H) \cdot P(t_3=C \mid H) \cdot P(w_3=1 \mid C) \]

2. Substitute numerical parameters:

\[ P(T, W) = 0.2 \times 0.5 \times 0.5 \times 0.4 \times 0.4 \times 0.5 \]

3. Compute step-by-step:

  • Day 1 (Initial \(\times\) Emission): \(0.2 \times 0.5 = 0.10\)
  • Day 2 (Transition \(\times\) Emission): \(0.10 \times 0.5 \times 0.4 = 0.020\)
  • Day 3 (Transition \(\times\) Emission): \(0.020 \times 0.4 \times 0.5 = \mathbf{0.0040}\)

Final Answer: 0.0040 (or \(4.0 \times 10^{-3}\)).

Sense Check: Alternate evaluation for sequence \(T = (H, H, C)\) yields \(0.8 \times 0.2 \times 0.6 \times 0.4 \times 0.4 \times 0.5 = 0.00768\), demonstrating how HMM scoring enables comparing path candidates.

6.8 The Combinatorial Search Problem and Viterbi Algorithm Motivation

6.8.1 Combinatorial Explosion in Exhaustive HMM Evaluation

To decode the globally optimal tag sequence \(\hat{T} = \arg\max_{T} P(T, W)\) in a Hidden Markov Model, a naive evaluation system would evaluate the joint HMM probability across every candidate path in the search space.

For a sequence of length \(T\) tokens over a tagset with \(N\) distinct POS tags (hidden states), the total number of candidate paths is:

\[ \text{Total Paths} = N^T \]

The computational time complexity of exhaustive brute-force evaluation is exponential: \(\mathcal{O}(N^T)\).

Intuition — Why Brute-Force Fails:

For a 10-word sentence using the standard Penn Treebank tagset (\(N = 45\)), exhaustive evaluation requires checking:

\[ 45^{10} \approx 3.405 \times 10^{16} \text{ paths} \]

Evaluating over 34 quadrillion paths for a single short sentence is computationally impossible in real-time NLP applications.

Combinatorial Scaling of Search Space (N = 45 Penn Treebank Tags):
+---------------------+-----------------+-------------------------------+-------------------------------+
| Sentence Length T    | Total Paths N^T | Brute-Force Ops O(N^T)        | Viterbi Ops O(T * N^2)        |
+---------------------+-----------------+-------------------------------+-------------------------------+
| T = 1 (1 word)      | 45^1 = 45       | 45 operations                 | 45 operations                 |
| T = 3 (3 words)     | 45^3 = 91,125   | 91,125 operations             | 6,075 operations              |
| T = 10 (10 words)   | 45^10           | approx 3.405 * 10^16 ops      | 20,250 operations             |
| T = 20 (20 words)   | 45^20           | approx 1.159 * 10^33 ops      | 40,500 operations             |
+---------------------+-----------------+-------------------------------+-------------------------------+

Scope & Limitations:

Because exhaustive search scale is exponential (\(\mathcal{O}(N^T)\)), brute-force evaluation is restricted strictly to toy demonstration problems (such as \(N=2, T=3\)). Practical POS sequence tagging requires dynamic programming.

6.8.2 Symbol Registry

  • \(N\) — Size of the hidden state space (number of POS tags) — \(N = |\mathcal{T}| \in \mathbb{Z}^+\) — state space size
  • \(T\) — Sequence length in word tokens — \(T \in \mathbb{Z}^+\) — time-step length
  • \(\mathcal{O}(N^T)\) — Computational time complexity of exhaustive brute-force path search
  • \(\mathcal{O}(T \cdot N^2)\) — Computational time complexity of Viterbi dynamic programming trellis decoding

6.8.3 Motivation for Dynamic Programming and Viterbi Decoding

To solve the combinatorial search problem, NLP uses the Viterbi Algorithm—a dynamic programming algorithm that computes the optimal state path using a trellis data structure.

Core Dynamic Programming Principle:

At each time step \(t\) and for each state \(s_j\), the Viterbi algorithm stores only the maximum probability score (\(v_t(j)\)) and the backpointer to the single best predecessor state that produced it. Because all sub-optimal paths entering state \(s_j\) at time \(t\) can never be part of a globally optimal path ending at time \(T\), they are discarded immediately (pruned).

This prunes the search space from exponential complexity \(\mathcal{O}(N^T)\) to polynomial complexity:

\[ \text{Complexity}_{\text{Viterbi}} = \mathcal{O}(T \cdot N^2) \]

Exam & Conceptual Takeaway: Viterbi dynamic programming reduces the time complexity of decoding a 10-word sentence from 34 quadrillion operations to just 20,250 operations, enabling real-time sequence tagging.

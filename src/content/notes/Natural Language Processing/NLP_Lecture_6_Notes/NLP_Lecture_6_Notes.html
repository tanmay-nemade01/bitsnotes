Large Language Models (LLMs)

6.1 What Are Large Language Models?

Large Language Models (LLMs) are general-purpose language models built using neural network approaches. They belong to the broader family of language models we have studied previously, but are distinguished by their enormous scale.

Key Concept: LLMs are language models that are extremely large in terms of (1) the number of trainable parameters, (2) the size of the training dataset, and (3) the computational resources required for training and inference.

6.1.1 Scale of LLMs

The "Large" in LLM refers to several dimensions of scale:

  • Parameters: Modern LLMs contain 100–175+ billion parameters (model weights). For reference, traditional \(n\)-gram models and feed-forward networks have orders of magnitude fewer parameters.
  • Data: LLMs are pre-trained on web-scale corpora — sometimes the entire crawlable web. This can amount to terabytes of text data.
  • Compute: Training requires specialized hardware such as NVIDIA A100 or H100 GPUs. Training on CPUs alone is infeasible at this scale. Even fine-tuning demands significant GPU resources.
Note: The parameters of an LLM are the model weights — learned through backpropagation (gradient descent). In transformer-based LLMs, these weights include:
  • Query (\(Q\)), Key (\(K\)), and Value (\(V\)) projection matrices for every attention head in every layer.
  • Feed-forward network weights in each transformer block.
  • Layer normalization parameters.
  • Embedding matrices for input tokens and output (pre-softmax) projections.

For a model like GPT-3 (175B parameters), with 96 transformer layers and 96 attention heads per layer, the parameter count accumulates rapidly.

6.1.2 General-Purpose Nature

LLMs are general-purpose — a single pre-trained LLM can be adapted to a wide variety of downstream NLP tasks without task-specific architectural changes:

  • Text summarization
  • Machine translation
  • Conversational AI / chatbots
  • Question answering
  • Sentiment analysis
  • Information retrieval and enterprise search
  • Code generation
  • Named entity recognition

This versatility is why LLMs have become the dominant paradigm in modern NLP.

6.1.4 Pre-training and Fine-tuning

LLM development follows a two-stage paradigm:

  1. Pre-training: The model is trained on a massive, general-domain corpus (e.g., Common Crawl, Wikipedia, books) using a self-supervised objective such as next-token prediction (causal language modeling) or masked language modeling.
  2. Fine-tuning: The pre-trained model is further trained on a smaller, domain-specific dataset (e.g., legal documents, medical texts) to adapt it to a particular application. Fine-tuning updates the pre-trained weights to accommodate the new data distribution.
Note: Fine-tuning is most effective when the new dataset is (1) reasonably large and (2) similar in nature to the original pre-training data. Parameter-efficient fine-tuning (PEFT) techniques like LoRA (Low-Rank Adaptation) allow fine-tuning with far fewer trainable parameters, reducing computational cost.
Caution: While LLMs are powerful, they come with significant challenges:
  • Explainability: It is difficult to understand why an LLM produced a particular output.
  • Responsible AI: Models can produce biased, harmful, or factually incorrect outputs (hallucinations).
  • Cost: Training and deploying LLMs is expensive in terms of compute, energy, and carbon footprint.
  • Data Privacy: Sending data to commercial APIs may expose sensitive organizational information.

Always evaluate whether a simpler, more explainable approach suffices before defaulting to LLMs.

6.1.5 Position of LLMs in the AI Landscape

LLMs sit at the intersection of several AI subfields:

  • Deep Learning: LLMs are built using deep neural networks (transformers).
  • Generative AI: LLMs generate new text, code, and (in multimodal variants) images, audio, and video.
  • Natural Language Processing: LLMs are fundamentally language models and serve as the backbone for most modern NLP tasks.

Prompt Engineering

6.2 What Is a Prompt?

A prompt is the natural language input that a user provides to an LLM to elicit a desired response. The quality of the prompt directly influences the quality, relevance, and accuracy of the model's output.

Key Concept: Prompt Engineering is the discipline of designing and optimizing prompts to maximize the quality of LLM outputs for a given task. It involves strategic choices about wording, structure, role assignment, examples, and output formatting.

6.2.1 Hard vs. Soft Prompts

  • Hard Prompt Engineering: The user manually crafts the textual prompt. This is the focus of this lecture and what most practitioners work with daily.
  • Soft Prompt Engineering: The system automatically learns continuous vector embeddings that serve as prompts. These learned "soft" tokens are prepended to the input and optimized via gradient descent while keeping the LLM weights frozen. This is an advanced technique used in parameter-efficient fine-tuning.

6.3 The Context Window

Every LLM has a context window — a maximum number of tokens it can process in a single request. This includes both the input prompt and the generated output.

Note: Token: In the simplest sense, a token is roughly a word or sub-word unit. Tokenization methods like Byte-Pair Encoding (BPE) split text into tokens. A context window of 4096 tokens means the combined input + output cannot exceed 4096 tokens.
  • Typical context windows range from 4K to 128K+ tokens (e.g., GPT-4 Turbo supports 128K, Claude 3 supports 200K).
  • Free-tier users often face stricter per-day token limits.
  • Best practice: Constrain the output length explicitly in your prompt (e.g., "Answer in 3–5 lines" or "Summarize in 50 words"). This saves cost, reduces latency, and lowers carbon footprint.

6.4 Elements of a Well-Designed Prompt

A well-crafted prompt typically includes several components:

  1. Role / Persona: Assign a role to the model.
    • "You are a mathematics professor designing problems for undergraduate students."
    • "Act as a legal expert reviewing a contract."

    The same question asked from different roles yields different outputs.

  2. Context / Background: Provide relevant context before the actual query.

    • "I am a researcher working on climate change. Summarize the following article..."
  3. Task Instruction: Clearly state what you want the model to do.
  4. Output Format Specification: Constrain the format of the response.
    • "Return the answer in JSON format."
    • "Provide your response in exactly 3 bullet points."
  5. Examples (Few-Shot): Provide input-output pairs to guide the model (discussed below).

6.5 Zero-Shot vs. Few-Shot Inference

6.5.1 Zero-Shot Inference

In zero-shot inference, no examples are provided. The model relies entirely on its pre-trained knowledge.

Example: Zero-Shot Prompt:
"Classify the sentiment of this review: 'The movie was okay, I guess.' Output the sentiment in one word."

The model may produce vague or incorrect outputs (e.g., "Nice book") because it lacks task-specific guidance.

6.5.2 Few-Shot Inference (In-Context Learning)

In few-shot inference, a small number of input-output examples are included in the prompt before the actual query. This is also called in-context learning or \(n\)-shot learning, where \(n\) is the number of examples provided.

Example: Few-Shot Prompt (3-shot):
"Classify the sentiment of each review as Positive, Negative, or Neutral.
Review: 'I loved this film!'   Sentiment: Positive
Review: 'Terrible waste of time.'   Sentiment: Negative
Review: 'It was decent, nothing special.'   Sentiment: Neutral
Review: 'The movie was okay, I guess.'   Sentiment:"

The model learns the pattern from the examples and produces a more accurate output: Neutral.

Key Concept: Why Few-Shot Works: The LLM is not being retrained during inference. Rather, the examples in the prompt guide the model's attention mechanism to focus on relevant patterns learned during pre-training. It is analogous to showing a human a few worked examples before asking them to solve a similar problem — the examples clarify the expected format and reasoning.
Note: Trade-offs:
  • More examples generally yield better outputs, but consume more of the context window.
  • During training-time fine-tuning (instruction tuning), you can provide hundreds or thousands of examples without context-window constraints. At inference time, you are limited by the context window.
  • Typical few-shot prompts use 1–5 examples (\(n = 1, 2, 3, 4, 5\)).

6.5.3 Modern Instruction-Tuned Models

Today, most LLMs (e.g., GPT-4, Claude, Llama 3 Instruct) are instruction-tuned — they have been fine-tuned during training to follow instructions and understand few-shot examples. Some models can even internally rewrite suboptimal prompts into better ones before generating a response, a technique sometimes called automatic prompt refinement.

Key Concept: Generative AI (GenAI) refers to AI systems that generate new content (text, images, audio, video, code, 3D models) based on patterns learned from training data. LLMs are the primary text-generation engine behind most GenAI applications.

6.6.2 Caveats and Responsible Use

Despite their power, LLM/GenAI systems should be adopted judiciously:

  • Data-hungry: Requires massive datasets and compute.
  • Explainability gap: Black-box nature makes debugging difficult.
  • Safety risks: Hallucinations, bias amplification, prompt injection attacks.
  • Regulatory compliance: Many industries (healthcare, finance, law) require auditable decision-making.
Caution: Golden Rule for Practitioners: Start with the simplest approach that solves the problem. If a rule-based system or a small statistical model works, use it. Only escalate to LLMs/transformers when you truly need their scale and generality, and you have the resources to manage their risks.

Part-of-Speech (POS) Tagging

6.7 What Is Part-of-Speech Tagging?

Part-of-Speech (POS) Tagging is the task of automatically assigning a grammatical category (a part-of-speech tag) to each word in a given text.

Key Concept: POS tagging is a sequence labeling problem: given a sequence of input words \(w_{1:n} = (w_1, w_2, \ldots, w_n)\), we must produce a sequence of output tags \(t_{1:n} = (t_1, t_2, \ldots, t_n)\), where each \(t_i\) is the correct POS tag for word \(w_i\).

6.7.1 Traditional English Parts of Speech

The eight traditional parts of speech in English grammar are:

Table: The Eight Traditional Parts of Speech
POS Function Examples
Noun (N) Names a person, place, thing, or idea dog, city, happiness
Pronoun (PRON) Replaces a noun he, she, it, they
Verb (V) Expresses action or state run, is, become
Adjective (ADJ) Describes/modifies a noun smart, blue, tall
Adverb (ADV) Modifies a verb, adjective, or adverb quickly, very, well
Preposition (PREP) Shows relation between words in, on, at, by, to
Conjunction (CONJ) Connects words, phrases, or clauses and, but, or
Interjection (INTJ) Expresses emotion oh!, wow!

Additionally, English has determiners/articles (a, an, the) and auxiliaries (is, are, have, do, will).

Key Distinction — Noun Subclasses: Traditional grammar distinguishes several important noun subtypes:
  • Proper Nouns (NNP) vs. Common Nouns (NN): Proper nouns name specific persons, places, or entities (Regina, Colorado, IBM). In written English, they are usually capitalized and generally aren't preceded by articles. Common nouns refer to general categories.
  • Count Nouns vs. Mass Nouns: Count nouns allow grammatical enumeration — they occur in singular and plural (goat/goats, relationship/relationships) and can be counted (one goat, two goats). Mass nouns conceptualize something as a homogeneous group (snow, salt, communism) — they are not counted (*two snows) and can appear without articles where singular count nouns cannot (Snow is white but not *Goat is white).
Adverb Subtypes: The adverb class is heterogeneous. Schachter (1985) notes that in a sentence like "Unfortunately, John walked home extremely slowly yesterday," all italicized words are adverbs. Key subtypes include:
  • Manner Adverbs: Describe how an action is performed (slowly, slinkily, delicately).
  • Degree Adverbs: Specify the extent of an action or property (extremely, very, somewhat).
  • Temporal Adverbs: Describe when an action took place (yesterday, Monday, now).
  • Directional/Locative Adverbs: Specify direction or location (home, here, downhill).
Because of this heterogeneity, some adverbs (e.g., temporal adverbs like Monday) are tagged as nouns in certain tagging schemes.

Beyond the Penn Treebank set, two historically significant larger tagsets are worth noting. The Brown Corpus tagset (Francis & Kučera, 1982) uses 87 tags and was developed for the pioneering 1-million-word Brown corpus — the first large-scale tagged corpus in English. It includes finer distinctions lost in the Treebank, such as separate tags for each inflection of be (BE/BED/BEDZ/BEG/BEM/BEN/BER/BEZ), do (DO/DOD/DOZ), and have (HV/HVD/HVG/HVN/HVZ); a dedicated tag NR for adverbial nouns (home, west, tomorrow); distinct tags for prepositions (IN) vs. subordinating conjunctions (CS); and separate tags for infinitive to (TO) vs. prepositional to (IN).

These larger tagsets preserve morphological and syntactic distinctions that the smaller Penn Treebank set collapses — useful for linguistic research but harder for automatic taggers due to increased ambiguity.

6.7.3 Open Class vs. Closed Class Words

Languages divide words into two broad categories:

  • Closed Class Words: A fixed, small set of words that rarely changes over time.
    • Articles/Determiners: a, an, the — only 3 in English.
    • Prepositions: in, on, at, by, to, of, for, with, ... — a finite set.
    • Pronouns (personal, possessive, reflexive), conjunctions (coordinating like and, but, or; subordinating like that, because, although), complementizers (subordinating conjunctions like that which link a verb to its clausal argument — e.g., I thought that you might like some milk), and auxiliaries.

    Closed-class words are easy to tag — a dictionary lookup suffices.

  • Open Class Words: An ever-evolving set of words. New words are constantly added, meanings shift, and some words fall out of use.

    • Nouns: new names, places, brands, technologies ("smartphone," "cryptocurrency").
    • Verbs: "google" (as a verb), "ghost" (as a verb), Gen-Z slang.
    • Adjectives: "cool" (meaning changed from "cold" to "excellent").
    • Adverbs: "literally" (now also used as an intensifier).

    Open-class words are hard to tag because they are constantly evolving and highly ambiguous.

One particularly subtle closed-class distinction is between prepositions and particles. A particle resembles a preposition or adverb but combines with a verb to form a phrasal verb — a single syntactic/semantic unit whose meaning is often not predictable from its parts (turn down = reject, rule out = eliminate, find out = discover).

Particle vs. Preposition — Diagnostic Test: Particles can often either precede or follow a noun phrase object:
  • She told off her friends. (particle before NP)
  • She told her friends off. (particle after NP — valid)
Prepositions cannot follow their noun phrase:
  • She stepped off the train. (preposition before NP)
  • *She stepped the train off. (ungrammatical — confirms preposition, not particle)
This distinction is so difficult that some tagsets (like CELEX) do not distinguish particles from prepositions, and even in corpora that do (like the Penn Treebank, using the RP tag for particles), automated taggers find the distinction extremely challenging. Only 61.5% of particles are correctly identified in typical taggers — most are mistakenly tagged as prepositions (IN) or adverbs (RB).
Example: Evolution of "cool":
  • Old meaning: "moderately cold" (adjective describing temperature).
  • Modern meaning: "fashionable, impressive, excellent" (adjective of approval).

A dictionary-based tagger trained on old data may misclassify "cool" when used in its modern sense.

6.8 Why Is POS Tagging Important?

POS tagging is a fundamental building block for virtually all NLP applications:

  1. Grammar Checking: Ensuring sentences are syntactically valid (e.g., subject-verb agreement).
  2. Machine Translation: Proper nouns should not be translated by meaning. "Chetana" (a name meaning "inspiration" in Sanskrit) should be transliterated, not translated as "inspiration." POS tags help distinguish proper nouns from common nouns.
  3. Named Entity Recognition (NER): Identifying proper nouns (person names, organizations, locations) is a precursor to information extraction.
  4. Conversational AI / Voice Assistants: Commands like "Set the timer for the oven to 10 minutes" require understanding that "set" is the action (verb), "timer" is the target (noun phrase), and "for the oven" is a prepositional modifier. Incorrect POS tagging could lead to dangerous misactions.
  5. Information Retrieval / Search Engines: Disambiguating queries. "play cricket" (verb + noun = sport) vs. "Cricket PlayStation" (proper noun = brand/game) vs. "cricket insect" (noun = animal).
  6. Sentiment Analysis: Adjectives ("amazing," "terrible") and adverbs ("very," "barely") carry sentiment.
  7. Text-to-Speech (TTS): Correct pronunciation and prosody depend on knowing whether a word is a noun or verb. English has many noun-verb pairs distinguished by stress placement: CONtent (noun) vs. conTENT (adjective), OBject (noun) vs. obJECT (verb), DIScount (noun) vs. disCOUNT (verb). Knowing the POS thus produces more natural pronunciations in speech synthesis and higher accuracy in speech recognition (Cutler, 1986).
  8. Stemming for Information Retrieval: Knowing a word's POS helps determine which morphological affixes it can take, improving stemming accuracy. POS can also help select out nouns and other important content words from a document for indexing.
  9. Relation Extraction: Understanding "who did what to whom" requires knowing which words are subjects (nouns), predicates (verbs), and objects (nouns).

6.9 Challenges in POS Tagging

6.9.1 Ambiguity

The same word can have different POS tags depending on context:

Table: Ambiguity of the Word "back"
Sentence POS of "back" Meaning
I opened the back door. Adjective (JJ) Rear, behind
I have pain on my back. Noun (NN) Body part
We need to win the voters back. Adverb (RB) Return to prior state
They promised to back the bill. Verb (VB) Support

This is a classic example: the word "back" appears as four different parts of speech across four different sentences. A tagger must use context to disambiguate.

Example: Another Ambiguous Word: "race"
  • "They expected the race to be close." — Here, "race" is a noun (NN), referring to a competition.
  • "They expected to race tomorrow." — Here, "race" is a verb (VB), meaning to compete in a race.

Determining the correct tag requires examining the surrounding words ("the" before suggests noun; "to" before suggests verb in infinitive form).

Example: Extreme Ambiguity: "can"

Consider the sentence: "I can can the can." Here, the word "can" appears three times but serves three different grammatical roles:

  • First "can" — Modal Verb (MD): auxiliary expressing ability
  • Second "can" — Main Verb (VB): meaning "to preserve in a can"
  • Third "can" — Noun (NN): a metal container

A POS tagger must examine the full syntactic context to disambiguate: after a pronoun subject ("I"), a modal verb is expected; after a modal, a base-form verb follows; after a determiner ("the"), a noun is expected. This illustrates why POS tagging is fundamentally a contextual, sequence-based task.

Two Fundamental Information Sources for Disambiguation: How does a tagger decide the correct POS for an ambiguous word? Manning & Schütze identify two complementary sources of information:
  1. Syntagmatic (Structural) Information: Look at the tags of neighboring words. Some tag sequences are common (e.g., DT JJ NN — a new play), while others are extremely unlikely or impossible (e.g., DT JJ VBP). This is the "horizontal" dimension of context.
  2. Lexical Information: Know the word itself and its prior distribution across POS tags. Although flour can be a verb (you flour the pan), it is much more likely to be a noun. The distribution of a word's usages across different POS is typically extremely uneven — this is why even a "dumb" tagger that simply assigns each word its most frequent tag achieves about 90% accuracy on benchmark corpora (Charniak et al., 1993).
All modern taggers combine both information sources. The 90% baseline is an important benchmark — it means the real challenge for taggers is resolving the remaining ~10% of ambiguous tokens (which, in running text, account for over 40% of all tokens; DeRose, 1988).

6.9.2 Sequence Learning Nature

POS tagging cannot be solved one word at a time in isolation. It is inherently a sequence learning problem because:

  • Order matters: "Cat sat on wall" is valid; "Wall cat on sat" is not.
  • Dependencies exist: The POS tag of one word depends on the tags of neighboring words (e.g., after a determiner "the," a noun or adjective is expected).
  • Variable-length input: Sentences can be short (3 words) or long (paragraphs).
Key Concept: A sequence learning problem is one where the input is a sequence of arbitrary length \(X = (x_1, x_2, \ldots, x_n)\) and the output is also a sequence \(Y = (y_1, y_2, \ldots, y_n)\), with dependencies across positions. POS tagging, machine translation, speech recognition, and named entity recognition are all sequence learning problems.

Standard classifiers like logistic regression or Naive Bayes are designed for single-label classification (\(X \to y\)), not sequence labeling. We need specialized models that can capture inter-token dependencies.

6.9.3 The Unknown Words Problem

A major practical challenge for any POS tagger is unknown words — words that appear in the test data but were never seen in the training corpus. Since lexical information is so powerful (the 90% baseline depends on knowing a word's most frequent tag), unknown words dramatically degrade performance — error rates can exceed 40% without special handling.

Fortunately, we can exploit morphological cues to guess the POS of unknown words. Weischedel et al. (1993) showed that combining several features can reduce the error rate on unknown words from over 40% to under 20%:

Morphological Cues for Guessing Unknown Word Tags:
  • Suffix -ed: Strongly suggests past tense verb (VBD) or past participle (VBN).
  • Suffix -s: Suggests plural noun (NNS) or 3rd-person singular verb (VBZ).
  • Suffix -ing: Strongly suggests gerund/present participle (VBG).
  • Suffix -tion (and -ment, -ness, -ity): Strongly suggests singular noun (NN).
  • Capitalization: If the unknown word is capitalized, it is very likely a proper noun (NNP). If not, common noun (NN) is more likely.
  • Hyphenation patterns: Can indicate compound adjectives or nouns.
Weischedel et al.'s model estimates: \(P(w \mid t) \propto P(\text{unknown word} \mid t) \times P(\text{capitalized} \mid t) \times P(\text{endings/hyphens} \mid t)\). This approach assumes independence between features — a limitation later addressed by loglinear models (Franz, 1996) that can model interactions (e.g., capitalized words are more likely to be unknown).

6.10 Approaches to POS Tagging

6.10.1 Rule-Based Tagging

  • How it works: Hand-crafted rules define tag assignments. E.g., "If the previous word is an article (DT), the current word is likely a noun (NN) or adjective (JJ)."
  • Pros: Fast, highly explainable (you know exactly why each tag was chosen).
  • Cons: Not scalable — languages have thousands of edge cases; writing rules for all of them is infeasible. Accuracy is limited.

6.10.2 Statistical Tagging (HMM, MEMM, CRF)

  • How it works: Probabilities are estimated from labeled training data. Models like Hidden Markov Models (HMMs) compute the most likely tag sequence given the word sequence.
  • Pros: More scalable than rule-based; reasonably accurate.
  • Cons: Requires labeled data; makes simplifying independence assumptions.
  • This lecture covers HMM-based tagging in depth.

6.10.3 Transformation-Based Tagging (Brill Tagging)

  • How it works: Start by assigning each word its most frequent tag. Then apply a learned, ordered list of transformation rules that correct errors. Each rule has the form "Change tag A to tag B if trigger environment C is satisfied." Example: "Change NN to VB if the previous tag is TO" (corrects to/NN school → to/TO school/NN but also to/TO go/VB). Later, more specific rules can reverse over-generalizations (e.g., "Change VB back to NN if the previous word is school").
  • Triggering environments can reference: preceding/following tags, preceding/following words, morphological properties of the current word.
  • Pros: Can condition on richer context than HMMs (individual words, not just tags); learned rules are human-interpretable; surprisingly resistant to overfitting; can be compiled into deterministic finite-state transducers for extremely fast runtime (10,000s of words per second).
  • Cons: Greedy learning may not find globally optimal rule sequence; does not naturally produce probability distributions over tags.

6.10.4 Neural Network Tagging (RNN, LSTM, BiLSTM)

  • How it works: Recurrent neural networks process the input sequence left-to-right (and right-to-left in bidirectional variants) and output a tag distribution at each position.
  • Pros: Excellent accuracy; automatically learns relevant features.
  • Cons: Less explainable; slower than rule-based or statistical methods.

6.10.5 Transformer-Based Tagging (BERT, etc.)

  • How it works: Pre-trained transformer models like BERT are fine-tuned on POS tagging data. Each token's contextualized embedding is fed through a classification head to predict its tag.
  • Pros: State-of-the-art accuracy; captures long-range dependencies.
  • Cons: Computationally expensive; poor explainability.
Note: Practical Guidance: Start with a simple approach (rule-based or HMM). Only escalate to neural/transformer methods if you need near-perfect accuracy, have sufficient labeled data, and can afford the compute. Explainability requirements in regulated industries often favor simpler models.
Accuracy Benchmarks: State-of-the-art taggers typically achieve 95–97% per-word accuracy on standard benchmarks (like the Penn Treebank/Wall Street Journal corpus). However, this should be interpreted cautiously:
  • Per-word vs. per-sentence accuracy: At 96% per-word accuracy, a 20-word sentence has only about a 44% chance of being entirely correct (\(0.96^{20} \approx 0.44\)). A tagger at 97% accuracy gives ~54% sentence-level accuracy; at 98%, ~67%. Small per-word improvements make a large difference in application quality.
  • Baseline reminder: The "dumb" most-frequent-tag baseline achieves ~90% accuracy, so the practical gain from sophisticated models is resolving the remaining ~10% of hard cases.
  • Accuracy varies dramatically with: amount of training data, tagset size (larger tagsets = more ambiguity), similarity between training and test corpora, and proportion of unknown words.
  • External factors (corpus similarity, dictionary coverage) often affect accuracy more than the choice of tagging algorithm — differences between methods are typically on the order of 0.5%.

Hidden Markov Models for POS Tagging

6.11 Intuition Behind HMMs

A Hidden Markov Model (HMM) is a probabilistic sequence model. In the context of POS tagging:

  • States (\(S\)): The POS tags themselves (NN, VB, JJ, DT, ...). These are hidden — we do not directly observe them.
  • Observations (\(O\)): The words in the sentence. These are what we see.
  • Goal: Given an observation sequence \(w_{1:n} = (w_1, \ldots, w_n)\), find the most probable hidden state sequence \(t_{1:n} = (t_1, \ldots, t_n)\).
Key Concept: Formally, we want to compute: \[ \hat{t_{1:n}} = \operatorname*{arg\,max}_{t_{1:n}}\; P\!\left(t_{1:n} \mid w_{1:n}\right) \] That is, the most likely sequence of POS tags given the sequence of words.

6.12 Components of an HMM

An HMM is defined by three probability distributions:

6.12.1 Initial Probability \(\pi\)

The probability that the first word's tag is a particular POS tag at the start of a sentence: \[ \pi(t_1) = P\!\left(t_1 \mid \text{start}\right) \]

Example: If in the training data, out of 100 sentences, 40 start with a noun (NN) and 30 start with a determiner (DT), then: \[ \pi(\text{NN}) = 0.4,\quad \pi(\text{DT}) = 0.3,\quad \ldots \]

6.12.2 Transition Probability \(A\) (Tag-to-Tag)

The probability of transitioning from one POS tag to the next: \[ a_{ij} = P\!\left(t_j \mid t_i\right) \] This is a matrix \(A\) of size \(|S| \times |S|\), where \(S\) is the set of POS tags.

Example: From training data: "DT \(\to\) NN" occurs 500 times, while "DT" appears in total 625 times as a preceding tag. Then: \[ P\!\left(\text{NN} \mid \text{DT}\right) = \frac{500}{625} = 0.8 \]

6.12.3 Emission Probability \(B\) (Tag-to-Word)

The probability of a particular word being generated from a particular state (POS tag): \[ b_j(w) = P\!\left(w \mid t_j\right) \] This is a matrix \(B\) of size \(|S| \times |V|\), where \(V\) is the vocabulary of words.

Example: In the training data, the word "dog" appears as a noun (NN) 120 times, and the NN tag appears 400 times total. Then: \[ P\!\left(\text{``dog''} \mid \text{NN}\right) = \frac{120}{400} = 0.3 \]

6.13 The Markov Assumptions

HMMs make two crucial simplifying assumptions:

6.13.1 First-Order Markov Assumption (for Tags)

The current POS tag depends only on the previous tag: \[ P\!\left(t_i \mid t_1, t_2, \ldots, t_{i-1}\right) \approx P\!\left(t_i \mid t_{i-1}\right) \]

This is a bigram assumption. If we looked at the previous two tags, it would be a trigram HMM. In practice, bigram HMMs work well for POS tagging.

Trigram Taggers and the Sparse Data Trade-off: We would intuitively expect more accurate predictions from conditioning on a longer history. For instance, the adverb tag RB can precede both a past tense verb (VBD) and a past participle (VBN). In the phrase clearly marked, a bigram tagger cannot distinguish these. A trigram tagger (two-tag memory) can: is clearly marked suggests VBN because the trigram "BEZ RB VBN" is more frequent, while he clearly marked suggests VBD because "PN RB VBD" is more frequent.

However, conditioning on longer histories is not always beneficial. There are usually no short-distance syntactic dependencies across commas, so knowing the tag before a comma doesn't help predict the tag after it. Worse, trigram transition probabilities are estimated from rarer events, so sparse data problems can make a trigram tagger perform worse than a bigram tagger.

Linear Interpolation addresses this by combining unigram, bigram, and trigram probabilities as a weighted sum:

\[ P(t_i \mid t_{i-2}, t_{i-1}) = \lambda_1 P_1(t_i) + \lambda_2 P_2(t_i \mid t_{i-1}) + \lambda_3 P_3(t_i \mid t_{i-2}, t_{i-1}) \]

where \(\lambda_1 + \lambda_2 + \lambda_3 = 1\). The \(\lambda\) weights are typically learned from held-out data using an EM algorithm. This allows the model to fall back on more robust bigram or unigram estimates when trigram counts are unreliable.

An alternative approach is the Variable Memory Markov Model (VMMM) (Schütze & Singer, 1994), where the length of context memory varies depending on the specific sequence — using more memory where data supports it and less where it would cause sparsity — rather than using a fixed weighted sum for all sequences.

6.13.2 Output Independence Assumption (for Words)

The current word depends only on its own POS tag (not on neighboring words or tags): \[ P\!\left(w_i \mid t_1, \ldots, t_i, \ldots, t_n, w_1, \ldots, w_{i-1}, w_{i+1}, \ldots, w_n\right) \approx P\!\left(w_i \mid t_i\right) \]

6.14 Computing the Joint Probability of a Tag Sequence

Using the Markov assumptions, the joint probability of a tag sequence \(t_{1:n}\) and word sequence \(w_{1:n}\) can be factorized as:

\begin{equation}\label{eq:hmm-joint} P\!\left(w_{1:n}, t_{1:n}\right) = \underbrace{P\!\left(t_1 \mid \text{start}\right)}_{\text{Initial}} \cdot \prod_{i=2}^{n} \underbrace{P\!\left(t_i \mid t_{i-1}\right)}_{\text{Transition}} \cdot \prod_{i=1}^{n} \underbrace{P\!\left(w_i \mid t_i\right)}_{\text{Emission}} \end{equation}
Example: Computing \(P\!\left(\text{``the smart dog''}, [\text{DT}, \text{JJ}, \text{NN}]\right)\)

Let's compute step by step:

  1. Initial: \(P\!\left(\text{DT} \mid \text{start}\right) = 0.3\)
  2. Transition DT \(\to\) JJ: \(P\!\left(\text{JJ} \mid \text{DT}\right) = 0.15\)
  3. Transition JJ \(\to\) NN: \(P\!\left(\text{NN} \mid \text{JJ}\right) = 0.55\)
  4. Emission "the" \(\mid\) DT: \(P\!\left(\text{``the''} \mid \text{DT}\right) = 0.75\)
  5. Emission "smart" \(\mid\) JJ: \(P\!\left(\text{``smart''} \mid \text{JJ}\right) = 0.02\)
  6. Emission "dog" \(\mid\) NN: \(P\!\left(\text{``dog''} \mid \text{NN}\right) = 0.10\)
\[ P\!\left(\text{``the smart dog''}, [\text{DT}, \text{JJ}, \text{NN}]\right) = 0.3 \times 0.15 \times 0.55 \times 0.75 \times 0.02 \times 0.10 \approx 3.71 \times 10^{-5} \]

This is the probability of one specific tag sequence. The HMM would compute this for all possible tag sequences and select the one with maximum probability.

Matrix Dimensions:
  • Transition Matrix \(A\): Size \(|S| \times |S|\) (number of tags × number of tags). Each entry \(a_{ij}\) is \(P(t_j \mid t_i)\).
  • Emission Matrix \(B\): Size \(|S| \times |V|\) (number of tags × vocabulary size). Each entry \(b_j(w)\) is \(P(w \mid t_j)\).
Transition Intuition: A noun (NN) is very likely to follow a determiner (DT) — e.g., "the cat". The transition probability \(P(\text{NN} \mid \text{DT})\) reflects this linguistic regularity.

Emission Intuition: If the tag is VBZ (verb, 3rd person singular), words like "is" and "eats" have high emission probabilities, while "race" is less likely under VBZ.

6.15 Estimating Probabilities from Training Data

All HMM probabilities are estimated from a labeled corpus (e.g., Penn Treebank) using Maximum Likelihood Estimation (MLE):

6.15.1 Transition Probability Estimation

\[ P\!\left(t_j \mid t_i\right) = \frac{\text{Count}(t_i \to t_j)}{\text{Count}(t_i)} \]

That is: how many times does tag \(t_j\) follow tag \(t_i\), divided by the total number of times tag \(t_i\) appears (in the position before another tag).

6.15.2 Emission Probability Estimation

\[ P\!\left(w \mid t\right) = \frac{\text{Count}(w \text{ is tagged as } t)}{\text{Count}(t)} \]

That is: how many times does word \(w\) appear with tag \(t\), divided by the total number of times tag \(t\) appears (regardless of word).

The Sparse Data Problem and Smoothing: MLE estimates assign zero probability to any event not seen in the training corpus. This is catastrophic for POS tagging because:
  • Unknown words: Any word not in the training data gets \(P(w \mid t) = 0\) for all tags, making the entire tag sequence probability zero.
  • Unseen transitions: Legitimate tag sequences that happen not to appear in the training data get zero probability.

Smoothing reserves some probability mass for unseen events. For HMM-based POS tagging, two common approaches are:

  1. Add-One (Laplace) Smoothing for Emissions (Church, 1988): Add 1 to the count of all POS tags listed in the dictionary for a particular word, guaranteeing non-zero probability for all tags \(t_j\) that are listed as possible for word \(w_l\). If a word has \(K_l\) possible tags: \(P(t_j \mid w_l) = \frac{C(t_j, w_l) + 1}{C(w_l) + K_l}\).
  2. Deleted Interpolation for Transitions (Charniak et al., 1993): Use a small constant \(\epsilon\) to reserve probability mass for unseen transitions: \(P(t_j \mid t_{j-1}) = (1-\epsilon)\frac{C(t_{j-1}, t_j)}{C(t_{j-1})} + \epsilon\).

Smoothing word generation probabilities is generally more important than smoothing transitions, since there are many rare words that won't appear in training.

Example: Computing Transition Probabilities from a Mini Corpus

Consider this tiny labeled corpus (3 sentences):

the/DT smart/JJ dog/NN
an/DT intelligent/JJ student/NNS
the/DT students/NNS run/VBP

Step 1 — Count transitions:

  • DT appears as a first tag from START: 3 times
  • NNS appears as a first tag from START: 0 times? Actually let's check. START \(\to\) DT: 3, START \(\to\) NNS: 0. But we also need to count STOP.

Let's compute \(P\!\left(\text{JJ} \mid \text{DT}\right)\):

  • Count(DT): 3 occurrences (in all three sentences)
  • Count(DT \(\to\) JJ): 2 times (sentence 1: DT\(\to\)JJ, sentence 2: DT\(\to\)JJ)
  • Count(DT \(\to\) NNS): 1 time (sentence 3: DT\(\to\)NNS)
\[ P\!\left(\text{JJ} \mid \text{DT}\right) = \frac{2}{3} \approx 0.667,\qquad P\!\left(\text{NNS} \mid \text{DT}\right) = \frac{1}{3} \approx 0.333 \]

Step 2 — Count emissions for DT:

  • Count(DT) = 3
  • "the" appears as DT: 2 times
  • "an" appears as DT: 1 time
\[ P\!\left(\text{``the''} \mid \text{DT}\right) = \frac{2}{3} \approx 0.667,\qquad P\!\left(\text{``an''} \mid \text{DT}\right) = \frac{1}{3} \approx 0.333 \]

6.16 The Complete POS Tagging Pipeline with HMM

Putting it all together for a given input sentence \(w_{1:n}\):

  1. For each possible tag sequence \(t_{1:n}\) (there are exponentially many), compute the joint probability using Equation \(\ref{eq:hmm-joint}\).
  2. Select the tag sequence with the maximum probability: \[ \hat{t_{1:n}} = \operatorname*{arg\,max}_{t_{1:n}}\; P\!\left(w_{1:n}, t_{1:n}\right) \]

6.16.1 Why Exhaustive Search Fails

If we have \(|S| = 45\) possible POS tags and a sentence of length \(n = 10\), the number of possible tag sequences is: \[ |S|^n = 45^{10} \approx 3.4 \times 10^{16} \]

Computing the probability for each sequence individually is computationally infeasible. This motivates the Viterbi algorithm, which efficiently finds the most probable sequence using dynamic programming.

Key Concept: The Viterbi algorithm is an optimization over the basic HMM. It uses dynamic programming to greedily select the maximum-probability path at each step, avoiding the need to enumerate all possible sequences. The time complexity reduces from \(O(|S|^n)\) to \(O(|S|^2 \cdot n)\).

The Viterbi Algorithm — Intuition

6.17 Motivation: The Jason and the Ice Cream Example

To understand why Viterbi is needed, consider this classic example (from Jurafsky & Martin):

Example: Scenario: Jason keeps a diary of how many ice creams he eats each day during summer. A climate scientist uses this data to infer the hidden weather sequence (Hot or Cold) that produced Jason's ice cream consumption.
  • Hidden States: Hot (H), Cold (C) — like POS tags.
  • Observations: 1, 2, or 3 ice creams eaten — like words.
  • Data: Jason ate (1, 3, 1) ice creams over three days.

Question: What was the most likely weather sequence — (H,H,H), (H,C,H), (C,C,C), etc.?

With only 2 states and 3 days, there are \(2^3 = 8\) possible weather sequences. For each, we must multiply: \[ \underbrace{\pi(\text{Day 1 weather})}_{\text{Initial}} \times \underbrace{P\!\left(\text{Day 2} \mid \text{Day 1}\right)}_{\text{Transition}} \times \underbrace{P\!\left(\text{Day 3} \mid \text{Day 2}\right)}_{\text{Transition}} \times \underbrace{P\!\left(1 \mid \text{Day 1}\right)}_{\text{Emission}} \times \underbrace{P\!\left(3 \mid \text{Day 2}\right)}_{\text{Emission}} \times \underbrace{P\!\left(1 \mid \text{Day 3}\right)}_{\text{Emission}} \]

For 8 sequences, this is manageable. But for 45 tags and 10-word sentences (\(45^{10}\) sequences), exhaustive computation is impossible. The Viterbi algorithm solves this by:

  • Building a trellis (a dynamic programming table) of size \(|S| \times n\).
  • At each position \(i\), keeping only the maximum probability path to each state, discarding all suboptimal paths.
  • Using recurrence: \(\text{Viterbi}[t, i] = \max_{t'} \big(\text{Viterbi}[t', i-1] \times P\!\left(t \mid t'\right) \times P\!\left(w_i \mid t\right)\big)\)

6.18 Viterbi Algorithm: Step-by-Step Walkthrough

Let's work through a concrete example with specific numbers to see how Viterbi efficiently finds the most probable hidden state sequence.

6.18.1 Scenario Setup: The Ice Cream Task (Slide 55)

Setup:
  • Observation Sequence: Jason ate 3 ice creams on Day 1, and 1 ice cream on Day 2 → Obs = (3, 1).
  • Hidden States: H (Hot), C (Cold).
  • Goal: Find the most likely weather sequence (e.g., H→H, or H→C, or C→H, or C→C).

Model Parameters:

  • Start Probabilities (\(\pi\)): \(P(H) = 0.8\), \(P(C) = 0.2\)
  • Transition Probabilities (\(A\)):
    • \(P(H \mid H) = 0.6\), \(P(C \mid H) = 0.4\)
    • \(P(H \mid C) = 0.5\), \(P(C \mid C) = 0.5\)
  • Emission Probabilities (\(B\)):
    • \(P(3 \mid H) = 0.4\), \(P(1 \mid H) = 0.2\)
    • \(P(3 \mid C) = 0.1\), \(P(1 \mid C) = 0.5\)

6.18.2 Step 1: Initialization (Day 1 → Observation = 3)

We compute the probability of starting in each hidden state given the first observation.

Formula: \(V[t, 1] = P(t \mid \text{Start}) \times P(\text{obs}_1 \mid t)\)
  • Path to Hot (\(V_1(H)\)): \(0.8 \times 0.4 = 0.32\)
  • Path to Cold (\(V_1(C)\)): \(0.2 \times 0.1 = 0.02\)

Winner for Day 1: Hot with score 0.32

6.18.3 Step 2: Recursion (Day 2 → Observation = 1)

Now we compute the best path to each state on Day 2, considering all possible predecessor states.

Formula: \(V[t, i] = \displaystyle\max_{\text{prev}} \big(V[\text{prev}, i-1] \times P(t \mid \text{prev})\big) \times P(\text{obs}_i \mid t)\)

Option A: Day 2 is HOT

  • From Hot(1): \(0.32 \times 0.6 \times 0.2 = 0.0384\)
  • From Cold(1): \(0.02 \times 0.5 \times 0.2 = 0.002\)

Best path to Hot(2): from Hot(1). Score: 0.0384

Option B: Day 2 is COLD

  • From Hot(1): \(0.32 \times 0.4 \times 0.5 = 0.064\)
  • From Cold(1): \(0.02 \times 0.5 \times 0.5 = 0.005\)

Best path to Cold(2): from Hot(1). Score: 0.064

6.18.4 Step 3: Termination & Backtrace

We compare the final scores for Day 2:

  • Score ending in Hot: 0.0384
  • Score ending in Cold: 0.064 (WINNER)

Now we backtrace from the winner:

  1. The winner is Cold(2).
  2. The best predecessor of Cold(2) was Hot(1).
  3. The best predecessor of Hot(1) was Start.
Result: The most likely weather sequence is HOT → COLD. Instead of checking all \(2^2 = 4\) possible sequences exhaustively, Viterbi computed it in \(O(N^2 \cdot T)\) time, where N = number of states and T = sequence length.

6.19 Maximum Entropy Markov Models (MEMM)

While HMMs are the classical approach to sequence labeling, they have a fundamental limitation: they are generative models that calculate \(P(w \mid t)\) — modelling how words are generated from tags. In practice, we want the reverse: given words, what are the most likely tags?

6.19.1 The Discriminative Alternative

Maximum Entropy Markov Models (MEMMs) are discriminative models that directly calculate \(P(t \mid w)\), the probability of a tag given the observed word and its context.

Key Concept: MEMMs replace the generative HMM formulation with a discriminative one based on logistic regression (maximum entropy classification), allowing rich feature extraction from the input context.

6.19.2 Why Switch to MEMM?

HMMs are limited — they only look at the current word and the previous tag to make predictions. MEMMs can incorporate arbitrary features of the input. When tagging "race", an MEMM can examine:

  • Is the previous word "the"? (Likely Noun)
  • Is the previous word "to"? (Likely Verb)
  • Does the word end in "-ing"?
  • Is the word capitalized?
  • What is the word's suffix or prefix?
  • What are the surrounding words?

6.19.3 The Mathematical Shift

HMM (Generative, via Bayes Rule):

\[ \hat{t} = \operatorname*{arg\,max}_{t} \prod_i P(w_i \mid t_i) \; P(t_i \mid t_{i-1}) \]

MEMM (Discriminative, via Logistic Regression):

\[ \hat{t} = \operatorname*{arg\,max}_{t} \prod_i P(t_i \mid w_i, t_{i-1}, \text{features}) \]
Why MEMMs Are More Powerful Than HMMs: HMMs are generative models — they model the joint distribution \(P(w, t)\) by computing \(P(w \mid t) \times P(t)\). This means they must model how words are "generated" from tags, which is computationally convenient but linguistically backwards (we observe words and want to infer tags).

MEMMs are discriminative models — they directly model the conditional distribution \(P(t \mid w)\) using maximum entropy classification (equivalent to multinomial logistic regression). For each position \(i\), an MEMM computes:

\[ P(t_i \mid w_{1:n}, t_{i-1}) = \frac{1}{Z(w, t_{i-1})} \exp\left(\sum_k \lambda_k \, f_k(w_{1:n}, i, t_{i-1}, t_i)\right) \]

where \(f_k\) are arbitrary feature functions, \(\lambda_k\) are learned weights, and \(Z\) is a normalization constant summing over all possible tags at position \(i\). This formulation lets MEMMs incorporate any observable feature of the input — word identity, prefixes/suffixes, capitalization, surrounding words, and the previous tag — without the independence assumptions that constrain HMMs.

This flexibility comes with a known weakness: the label bias problem. Because MEMMs normalize probabilities locally at each state, they can systematically favor states with fewer outgoing transitions, even when the global evidence points elsewhere. Consider a state with only one outgoing transition — that transition always gets probability 1.0 regardless of the observation, effectively ignoring the input. Conditional Random Fields (CRFs) were later developed to address this limitation by using global normalization over the entire sequence.

6.19.4 Summary: HMM vs. MEMM

  • POS tagging resolves ambiguity in language by using context.
  • HMMs use transition and emission probabilities to find the most likely tag sequence — they model the joint distribution \(P(w, t)\).
  • The Viterbi Algorithm efficiently finds the best path using dynamic programming (\(O(N^2 \cdot T)\) instead of exponential).
  • MEMMs improve on HMMs by allowing rich feature extraction (capitalization, suffixes, surrounding words) to directly discriminate between tags — they model the conditional distribution \(P(t \mid w)\).

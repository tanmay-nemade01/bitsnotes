13.2 What Object Detection Is and How It Differs from Segmentation

How precisely must the machine locate the object: every single pixel, or just a box around it? That one question splits segmentation from detection.

Segmentation is pixel-wise classification. Every pixel gets a class label, so the image splits into labeled regions with exact boundaries. Tumor detection, pneumonia analysis, and brain-tumor extraction all need that precision, because a surgeon cuts exactly along the marked boundary — a box that merely says "tumor somewhere in here" is useless in an operating room.

Object detection answers a coarser question. It draws a bounding box, a rectangle around each object of interest, and so marks the neighborhood where the object sits. A driver-assistance system does not need to know which pixels belong to a car. It needs to know where the car is in the frame — ahead-left, closing fast — and a box gives exactly that, at far lower cost than labeling all two million pixels of a frame.

The analogy that carries through this lecture: segmentation is tracing the exact outline of every animal in a coloring book, while detection is drawing one loose rectangle around each animal. Tracing wins art contests; rectangles win races, because they are cheaper and enough whenever position beats shape.

13.2.1 Detection Versus Segmentation

Segmentation labels each pixel with a class. Detection places one rectangle per object, defined by four corner values — usually \((x_{\min}, y_{\min})\) for one corner and \((x_{\max}, y_{\max})\) for the opposite corner. Every one of those four numbers must land close to the truth or the whole prediction fails, which is what makes detection one of the toughest problems in vision: classification asks one question per image, segmentation asks one easy question per pixel, but detection asks a class question plus four precise coordinate questions jointly.

Figure: A street frame with three cars — segmentation labels the car pixels (mirrors and wheels included); detection returns three rectangles, each four numbers plus a class.

Scope: choose segmentation when boundaries drive action (surgery, lane-line following, tumor volume). Choose detection when presence plus rough position drives action (counting cars, braking for pedestrians, tracking players). Pitfall: assuming detection is "easier segmentation." It is a harder joint problem because the four coordinates must all be right at once, as the one-in-ten-million argument in 13.4 shows.

13.3 The Sliding-Window Approach and Class Imbalance

What if object detection were just asking "is there a person in this little square" thousands of times? That is exactly where the field started.

The earliest detection idea is delightfully plain. Take a fixed-size window, say 40 by 20 pixels, and slide it across the whole image like a magnifying stamp. Each stop cuts out one sub-image. Then ask a plain yes-or-no question per stop. Does this slice hold a pedestrian. The answers come out as zeros everywhere except a few ones, so detection turns into classification over slices — no fancy geometry, just the same classifier applied at every position.

One size never fits all objects. A child nearby and an adult far away project to very different pixel heights, and a person with a dog is wider than a person alone. So the same image gets scanned again with a 20 by 10 window, a 5 by 5 window, and more shapes besides. Each shape and scale adds its own set of slices. Count them up in the worked example and the total reaches 330 sliding windows, of which only 6 hold a pedestrian. That ratio, 6 against 324, is the seed of everything painful about detection evaluation.

13.3.1 Mathematical Formulation

The professor's verbal rule for counting is "h cross b-h multiplied with w cross b-x". An image has height \(H\) and width \(W\). A template has height \(b_{h}\) and width \(b_{x}\). The number of sub-boxes is

\[N = \frac{H}{b_{h}} \times \frac{W}{b_{x}}\]

where \(N\) is the count of sub-boxes, \(H\) is the image height in pixels, \(W\) is the image width in pixels, \(b_{h}\) is the template height in pixels, and \(b_{x}\) is the template width in pixels. Read it as: the number of template heights that fit down the image, times the number of template widths that fit across it.

Check it with real numbers. A 512 by 512 image with a 2 by 2 window gives \(N = (512/2) \times (512/2) = 256 \times 256 = 65{,}536\) sub-boxes — over sixty-five thousand slices from one image at one scale. Now scale the window by 8 to 16 by 16: \(N = 32 \times 32 = 1{,}024\) slices. And new aspect ratios such as 2 by 4, 2 by 8, or 2 by 10 catch bodies that a square window would cut off: a tall thin pedestrian fits a 2 by 8 frame but gets sliced in half by a square. Every new scale and ratio multiplies the count again, before any occlusion handling even starts. This multiplicative explosion is why brute-force sliding windows died.

Figure: Sliding-window count as grids — one slice per template-sized cell; halving the template side doubles the grid in each direction and quadruples the count; each added aspect ratio adds another grid to the stack.

Scope: the formula assumes the window tiles the image with no overlap and no stride tricks; with stride \(s\) the count becomes roughly \((H/s) \times (W/s)\) per scale, even larger for dense strides. Assumption: windows are axis-aligned rectangles — rotated objects still get cut. Pitfall: adding scales feels like progress but each new scale adds hundreds of negatives per positive, deepening the imbalance below.

13.3.2 Worked Counting Example

Take the pedestrian image scanned at many shapes and scales. The slices stack up to 330 windows. Only 6 of them hold a pedestrian, so positives form

\[\frac{6}{330} \approx 0.018\]

about 1.8 percent of the data. From a classical learning view this is a lopsided minority-majority split: 6 positives against 324 negatives, odds of 54 to 1. A model can score \(324/330 \approx 98\) percent accuracy by answering "no person" every single time while learning nothing — a trap that returns later when accuracy itself goes on trial in 13.6. Sense-check: if a detector reports 95 percent accuracy on this scan, it is worse than the do-nothing baseline; the number proves nothing.

13.3.3 Student Questions and Answers

Q: How many of the drawn windows actually hold a pedestrian. A: Four of the highlighted ones do, and the full count across all scales is 6 positives out of 330 windows. The highlighted four are the visible teaching subset; the remaining two come from finer scales.

Q: Why try so many aspect ratios instead of one square. A: A body cut off in a 2 by 4 frame may fit fully in a 2 by 8 frame. Different ratios catch different framings of the same object, such as a person alone versus a person with a dog — the square sees half a torso where the tall frame sees the whole figure.

Sliding windows turn detection into classification over slices, but scales and ratios multiply the count to 330 with only 6 positives — a 54-to-1 imbalance that accuracy cannot judge. That imbalance motivates region proposals next.

13.4 Why Detection Is So Hard: the One-in-Ten-Million Argument

Guess the animal and draw its exact box by pure luck. What are the odds? Roughly one in ten million — and that number explains why detection dwarfs classification in difficulty.

A box needs four numbers to land right: left, top, right, bottom. Miss any one of them and the whole box fails, because a box with three perfect edges and one wild edge still misses the object. That strictness stacks on top of the class problem. ImageNet holds about 1000 classes, so blind guessing gets the class right with probability

\[P(\text{class}) = \frac{1}{1000}\]

where \(P(\text{class})\) is the chance of naming the right class out of 1000 options. The professor's verbal form is "one out of thousand."

Now grant a generous gift. Suppose each of the four box numbers lands within 10 percent of truth with chance 1 in 10 — generous, because real coordinates are continuous and far harder to hit. The verbal form is "10 percent chance that you predict this point correctly." All four must land together, and independent chances multiply, so

\[P(\text{box}) = \frac{1}{10} \times \frac{1}{10} \times \frac{1}{10} \times \frac{1}{10} = \frac{1}{10000}\]

where \(P(\text{box})\) is the chance that all four corner values land close to truth at once. Guessing both parts right multiplies the two chances:

\[P(\text{correct}) = \frac{1}{1000} \times \frac{1}{10000} = \frac{1}{10000000}\]

where \(P(\text{correct})\) is the chance of naming the class and placing the full box by luck. One in ten million. Pixel labeling never faces this, because each pixel gets its own plain class vote with no box attached — a thousand-way guess per pixel, and no joint coordinates. Detection asks what and where together, and the where part punishes every small shift.

Detection difficulty multiplies: a 1000-way class guess times four joint coordinate guesses gives a one-in-ten-million chance by luck. Concretely, a classifier that is 90 percent accurate per coordinate still lands all four only \(0.9^4 \approx 0.66\) of the time — and that is before the class guess.

A number line makes it vivid. Classification luck sits at one tick in a thousand. Box luck sits at one tick in ten thousand. Joint luck sits at one tick in ten million — a stadium of ten million people with exactly one winner. The takeaway: detection needs machinery (IoU scoring, then mAP) because naive guessing is hopeless and naive accuracy is meaningless.

Scope: the argument assumes independence between the four coordinates and a uniform 1-in-10 hit chance; real errors correlate (a shifted box moves all edges together), so the true figure differs, but the order of magnitude stands. Pitfall: reading "one in ten million" as a measured error rate. It is a teaching illustration of joint difficulty, not a benchmark number.

13.4.1 Student Questions and Answers

Q: Which data set has a thousand classes. A: ImageNet is the example. With that many classes, the class guess alone starts at one in a thousand before any box gets drawn — and the box then multiplies that rarity by ten thousand.

Class times four coordinates makes blind success one in ten million. Detection is hard because what and where must be won jointly — which is why the next section builds a scoring rule for where.

13.5 Intersection over Union: Scoring a Box

Two boxes overlap — but how much? One ratio between zero and one answers that for every detector ever built.

With sliding windows throwing out hundreds of boxes, most of them partly overlap the target: shifted by a few pixels, slightly too wide, slightly too short. The fix is a single score. Take the ground-truth box, the true rectangle. Take the predicted box, the guessed rectangle. Their intersection over union, called IoU and also known as the Jaccard score, is the shared area divided by the total area covered by either box. The professor's verbal form is "area of overlap divided by area of union":

\[\text{IoU} = \frac{\text{area of overlap}}{\text{area of union}} = \frac{|G \cap P|}{|G \cup P|}\]

where \(G\) is the ground-truth box, \(P\) is the predicted box, \(|G \cap P|\) is the area shared by both in square pixels, and \(|G \cup P|\) is the area covered by at least one of them. A value near 1 means a strong match — nearly the same rectangle. A value near 0 means a poor match — barely touching. The working cutoff used here is 0.5, the same spirit as a fair coin toss from binary classification: more overlap than not. Above 0.5 counts as holding the object. Below it gets thrown out.

The overlap intuition is a Venn diagram of two rectangles. The lens in the middle is the intersection; the full inked region is the union. IoU asks: what fraction of the ink is shared? A predicted whale box around a cow scores about 0.5 — half shared, half stray. A monkey box scores about 0.7. A tight box scores about 0.9, and the animal inside starts to look like a cow because the edges finally agree. Closer to one is better. Closer to zero is worse.

Scope: the 0.5 cutoff is a convention, not a law — COCO-style evaluation averages over 0.5 to 0.95 precisely because strictness changes verdicts. Pitfall: treating IoU 0.49 and 0.51 as qualitatively different; the boundary is arbitrary and a one-pixel shift can flip the call. Assumption: boxes are axis-aligned; rotated boxes need a generalized overlap.

13.5.1 Worked Numerical Example: IoU of 12 over 38

The ground-truth box runs from bottom-left \((1, 1)\) to top-right \((6, 5)\). The predicted box runs from bottom-left \((2, 2)\) to top-right \((8, 7)\). Here each pair \((x, y)\) holds an x pixel coordinate and a y pixel coordinate on the image grid.

Step one finds the shared rectangle. Its left edge is the later of the two lefts, \(\max(1, 2) = 2\); its right edge is the earlier of the two rights, \(\min(6, 8) = 6\); so width is \(6 - 2 = 4\). Its bottom is \(\max(1, 2) = 2\) and its top is \(\min(5, 7) = 5\); so height is \(5 - 2 = 3\). So

\[\text{intersection} = 4 \times 3 = 12\]

measured in square pixels.

Step two finds each box alone. The ground-truth area is

\[A_{G} = (6 - 1) \times (5 - 1) = 5 \times 4 = 20\]

and the predicted area is

\[A_{P} = (8 - 2) \times (7 - 2) = 6 \times 5 = 30\]

both in square pixels.

Step three joins them without double counting the shared part:

\[\text{union} = A_{G} + A_{P} - \text{intersection} = 20 + 30 - 12 = 38\]

The subtraction matters because adding both areas counts the shared patch twice. The final score is

\[\text{IoU} = \frac{12}{38} \approx 0.315\]

Since 0.315 sits below 0.5, this box gets rejected. Sense-check: the prediction is bigger (30 vs 20) and shifted up-right by a full pixel band, so less than a third shared is exactly what the picture suggests — two boxes can look close on screen and still fail, because every corner sits far from truth.

A second quick calibration: shrink the prediction to \((1, 1)\)–\((6, 5)\), identical to truth. Intersection becomes 20, union 20, IoU exactly 1. Shift it by half a pixel each way and the score drops into the 0.8–0.9 band — the tight-box regime from the lecture picture.

13.5.2 Student Questions and Answers

Q: Are the corner values the right way round, or should top-left and bottom-right swap. A: The labels needed a fix mid-sketch: one corner is the bottom-left \((x_{\min}, y_{\min})\) and the other is the top-right \((x_{\max}, y_{\max})\). After the swap the numbers above follow through cleanly. The lesson: always name corners as min and max per axis, never as visual "top" or "bottom," because image y-axes flip between conventions.

IoU is shared area over total area, with 0.5 as the working pass mark. The 12-over-38 example (0.315, rejected) is the template for the exam number problem.

13.6 Why Accuracy Lies and How Mean Average Precision Fixes It

A detector that finds nothing can score 98 percent. If that sentence bothers you, you already understand why detection needed a new metric.

Recall the pedestrian scan: 330 windows, only 6 positives. A model that predicts "no person" on every window, with no IoU and no real work, still scores \(324/330 \approx 98\) percent — above 90 percent while detecting nothing at all. Classical accuracy rewards that lazy answer because it counts the 324 easy negatives and ignores the 6 hard positives. So the field drops accuracy entirely for detection. The problem is a class-imbalance problem wearing a vision disguise: the same trap as fraud detection with 1 fraud in 1000 transactions, where "always innocent" looks brilliant.

The replacement comes in two layers. IoU decides whether one box is right (13.5). Mean average precision, called mAP, turns those box calls into one number per system. Its roots match the ROC area-under-curve idea from classical learning: plot precision against recall and measure the area beneath. Where ROC sweeps a threshold over scores, mAP sweeps down a ranked list of boxes.

13.6.1 Mathematical Formulation: Precision, Recall, and Their Curve

Rank every predicted box by its confidence score, the model's own trust in that box, from high to low. Compare each box with the ground truth at IoU 0.5. A box at or above 0.5 is a true positive (a hit). A box below 0.5 is a false positive (a false alarm). When two boxes hit the same object, only the higher-confidence one counts as true — the lower one becomes a false positive because its target is already used up, the duplicate rule.

At each row of the ranked list, with \(TP\) true positives so far and \(FP\) false positives so far,

\[\text{precision} = \frac{TP}{TP + FP}\]

where precision is the share of kept boxes that are right ("of everything I claimed, how much was correct"), and

\[\text{recall} = \frac{TP}{G}\]

where recall is the share of all ground-truth objects found so far and \(G\) is the total count of ground-truth objects ("of everything real, how much did I find"). The professor's verbal forms are "one divided by true positive plus false positive" for precision and "out of the ground truth, how many did I pick correctly" for recall. Precision starts high (early boxes are confident) and slides down as false alarms creep in. Recall starts low and climbs up as more objects get found.

The raw precision-recall line jumps up and down — every false positive dips it, every hit recovers it — so the area under it is hard to read. The fix is interpolated precision: at each recall level \(r\), replace the raw value with the highest precision found at that recall or any higher recall:

\[p_{\text{interp}}(r) = \max_{r' \geq r} p(r')\]

The curve turns into clean descending steps, and the area becomes easy to add up.

Figure: Precision–recall plot — raw precision zigzags (dashed) while interpolated precision forms the descending staircase; the area under the staircase is AP.

Scope: precision and recall here are ranked-list quantities, defined row by row — not single dataset-wide numbers. Assumption: confidence ranking is trustworthy, so the greedy match (highest confidence claims the object) is fair. Pitfall: forgetting the duplicate rule — the single most common exam error is marking two hits on one object both true.

13.6.2 Worked Example: Six Ranked Boxes Against Four Ground Truths

Four ground-truth objects wait to be found (\(G = 4\)). Six predicted boxes arrive ranked by confidence:

Rank Confidence IoU with truth Call
P1 0.90 0.91 true positive
P2 0.82 0.93 true positive
P3 0.65 0.40 false positive
P4 0.60 0.76 true positive
P5 lower 0.00 false positive
P6 lower still 0.69 true positive

Walk down the rows, keeping running \(TP\) and \(FP\). After P1: \(TP = 1, FP = 0\), precision \(1/1 = 1\), recall \(1/4 = 0.25\). After P2: \(TP = 2, FP = 0\), precision \(2/2 = 1\), recall \(2/4 = 0.5\). P3 misses (IoU 0.40 below 0.5), so \(TP = 2, FP = 1\): precision falls to \(2/3 \approx 0.67\) while recall stalls at \(2/4 = 0.5\). After P4: \(TP = 3, FP = 1\), precision \(3/4 = 0.75\), recall \(3/4 = 0.75\). After P5 (IoU 0.00): \(TP = 3, FP = 2\), precision \(3/5 = 0.6\), recall holds at \(3/4 = 0.75\). After P6: \(TP = 4, FP = 2\), precision \(4/6 \approx 0.67\), recall reaches \(4/4 = 1.0\).

Now the trap row. A seventh box P7 arrives with confidence 0.59 and IoU 0.7, above the cutoff — yet it still counts as a false positive. All four ground truths are already taken by higher-confidence boxes, and the method trusts the model's ranking: confidence order decides who claims an object, not overlap size. A bigger overlap cannot steal a match from a more confident box. Sense-check: recall is capped at 1.0 with all four found, and precision ends at 0.67 — good but visibly dragged down by the two false alarms, exactly what the metric should show.

13.6.3 Worked Example: Eleven-Point Interpolation and Averaging

Take recall marks 0.0 through 1.0 in steps of 0.1 (in the session's telling, the interior marks 0.1 to 0.9 carry the story). At each mark keep the best precision at that recall or higher. From the table above, the running values come out as 1 all the way through recall 0.5 (rows P1–P2 hold precision 1), then 0.75 at recall 0.6 and 0.7 (row P4's precision dominates everything at or above), then 0.67 at recall 0.8 and 0.9 (only row P6's 0.67 remains at that recall and above). The jagged line becomes a staircase, and the area is plain addition. The average precision, AP, for one class is the mean of those interpolated values:

\[\text{AP} = \frac{1}{11}\sum_{r \in \{0.0, 0.1, \ldots, 1.0\}} p_{\text{interp}}(r)\]

where \(p_{\text{interp}}(r)\) is the interpolated precision at recall level \(r\). With the session's numbers the nine interior marks sum to \(5 \times 1 + 2 \times 0.75 + 2 \times 0.67 = 5 + 1.50 + 1.34 = 7.84\), and dividing by 9 gives about 0.87 for the car class. Repeat per class: one AP for cars, one for people, one for computers. Then average across classes:

\[\text{mAP} = \frac{\text{AP}_{\text{car}} + \text{AP}_{\text{human}} + \text{AP}_{\text{computer}}}{3}\]

where mAP is the mean average precision over the three classes. That single number is the headline score of a detector — one number that punishes both false alarms (via precision) and misses (via recall), unlike accuracy which rewards doing nothing.

A second calibration: a perfect detector holds precision 1 at every recall mark, so AP is 1 and mAP is 1. The all-negative lazy detector has no ranked boxes at all, so recall never rises above 0 and AP is 0. The metric spans the full range exactly where accuracy collapsed everything near 98 percent.

13.6.4 Student Questions and Answers

Q: The 0.5 cutoff is just an assumption, so would 0.7 or 0.9 change everything. A: Yes, and that is fine. Raise the cutoff and some true positives turn false, precision and recall shift, and the whole curve moves — P4's 0.76 survives 0.7 but dies at 0.9, for instance. During tests, write down the assumed cutoff next to the answer and solve from there.

Q: Why does recall 0.8 read 0.67. A: At recall 0.8 every row at or below 0.75 recall is off the table, and 0.67 is the best precision left standing (row P6). Each slice keeps only rows at its recall or higher, then takes the max — that is interpolation.

Q: How do IoU, Jaccard, F1, and ROC fit together. A: IoU matches the Jaccard score — same ratio, different name. It also plays the role F1 plays, joining precision-like and recall-like views (overlap vs coverage) into one. mAP plays the role of the ROC area, since both read performance as area under a curve rather than a single threshold number.

13.7 Histogram of Oriented Gradients and Template Matching

Before networks learned their own features, engineers counted edge directions by hand — and that simple histogram carried pedestrian detection for a decade.

Before neural networks took over, the field leaned on hand-built features. The histogram of oriented gradients, called HOG, cuts an image into patches, often 128 by 64 pixels (a standing-person frame), then into 2 by 2 blocks, then into 8 by 8 cells. Inside each cell it counts edge directions weighted by edge strength: a strong vertical edge votes heavily for "vertical," a faint diagonal votes lightly for its angle. Each point on the result carries a magnitude, how strong the edge is, and a direction, which way the edge runs. Stack those counts across all cells and the whole image becomes a template of its edge patterns — a fingerprint of where edges point. The Eiffel Tower example shows why this works: towers share strong vertical and diagonal edges in the same places (legs rising, lattice crossing), so their templates line up even across different photos.

Pedestrian detection then runs as template matching. Collect many positive samples — people facing front, back, and side, shot from many angles. Collect many negative samples — patches with no person in them. Average the positives into one standard human template: upright posture, shoulders on top, head above, legs below, a blurry humanoid of edge counts. Slide that template across a new image, build HOG at each stop, and compare by distance. Where the distance between template and patch is smallest, the detector response peaks, and a box goes around that neighborhood.

HOG turns shape into numbers: per-cell histograms of edge direction weighted by gradient strength, stacked into a fixed template. Detection is then nearest-template search — the patch whose edge fingerprint best matches the average human gets the box.

13.7.1 Strengths and Limits of the HOG Era

The method was general for its day. Feed it examples, get back boxes with confidence scores, no hand-drawn rules per image — one pipeline served pedestrians, faces, and cars. Around 2005 this machinery ran on Pascal VOC, the first large-scale test bed with 20 classes covering people, animals, vehicles, and household objects. Teams tried every mix available: histogram equalization plus SIFT plus RANSAC, HOG variants, sliding mixes of all of them. The ceiling sat near 40 percent mAP, and nobody could break past it — year after year, the leaderboard barely moved.

Two limits explain the ceiling. First, size stays unknown: a template match says the pattern fits somewhere nearby, not how wide or tall the true region is — the box is a neighborhood, not a measurement. Second, HOG sees edges, not meaning. Two shop mannequins with legs and torsos match the human template well enough to fire the detector, though no pedestrian stands there: legs are legs to an edge counter. A side-profile face with one eye in view can fail the frontal template even when a person is right there, because one visible eye and a shifted nose bridge move the edge counts far from the frontal average. Low-level edges carry no sense of what a person is.

Driver-assistance teams of that era could get a rough neighborhood for an obstacle but not a trusted box — enough to warn, not enough to brake. That gap is why the field kept hunting for richer features.

Scope: HOG templates assume roughly aligned, upright objects at a fixed scale; rotation, articulation, and heavy occlusion break the average. Pitfall: confusing a high template score with a precise box — HOG localizes neighborhoods, and its boxes routinely need IoU forgiveness at 0.5 to count.

13.7.2 The CNN Breakthrough on Pascal VOC

Convolutional networks changed the feature itself. Instead of fixed edge counts designed by humans, the network learns its own templates from data, layer after layer, each richer than the last: edges in layer one, textures and parts in the middle, object-level patterns at the top. Near 2012 to 2013 the score on Pascal VOC jumped from the stuck 40 percent band to about 58 percent, an 18-point leap after years of inching forward — more progress in one year than the previous five combined. Crossing 50 percent carried weight: below half looks like guessing with a tilt, while above half reads as genuinely better than chance. Within about four years the number climbed toward 80 and 90 percent. The lesson is plain. Better features beat better scanning, and learned features beat hand-built ones.

Q: What goes wrong when the template fires on two mannequins. A: Edge histograms match because legs are legs to an edge counter. With no semantic sense of a living person, the detector reports a neighborhood that holds no pedestrian — a false positive no edge threshold can fix.

Q: Why does a side face break a frontal template. A: One visible eye and a changed nose bridge shift the edge counts away from the frontal average, so similarity falls short and the person gets missed — a false negative from pose alone.

13.8 Region Proposals and Selective Search

Six needles in a haystack of 330 straws. What if you could shrink the haystack to 30 straws before searching?

Step back to the core pain: 6 positives lost among 330 windows, or among thousands once scales and ratios pile on. Class-imbalance tools from classical learning point the way. Either copy the rare class over and over, called oversampling the minority, or throw away most of the dull majority, called undersampling the majority. Detection picks the second road. Instead of scoring every slice, first propose a small set of regions where an object might sit, then score only those. Six candidates among 30 proposed regions beats 6 among 330 blind windows every time: the positive rate jumps from 1.8 percent to 20 percent, and the classifier stops drowning in negatives. The gambling comparison sticks: hunting one question inside slide 13 beats hunting across the whole deck — though opening the right slide costs time, which is the price of the proposal stage.

Selective search builds those proposals from segmentation. Start with many tiny boxes (an oversegmentation of the image), then merge neighbors that look alike in color, texture, or shape. Merging runs bottom-up — small regions fusing into bigger ones — until a fixed budget of candidate boxes remains, about 2000 in the classic setup. The merge engine can be k-means style clustering, probabilistic grouping, or mean shift, all resting on one Gestalt idea: pixels that sit together and share a fate belong to one object. Television pixels share one fate because they form one television. Dress pixels stay together because one dress holds them. The result is a short list of object-like regions: not labeled, but shaped like things.

Region proposals are undersampling for detection: a segmentation-driven short list (about 2000 boxes) replaces the full sliding-window grid (tens of thousands), lifting the positive rate by an order of magnitude before any classifier runs.

Figure: The proposal funnel — tens of thousands of windows narrow to about 2000 object-like regions before the expensive classifier runs; anything the proposals miss never returns.

Scope: proposals are class-agnostic boxes, not detections — they say "something is here," never what it is. Assumption: objects form coherent color-texture-shape blobs; camouflaged or fragmented objects violate it and get missed. Pitfall: treating proposal count as accuracy — more proposals raise recall but cost compute linearly, and the missed ones never come back.

13.8.1 How Many Regions to Propose

Nobody hands down the count. Any number works: 10, 100, 1000, 2000, 5000. The floor sits near the class count, so a 20-class task wants at least 20 proposals (one per class at minimum), and headroom helps because misses never come back — a proposal stage with 90 percent recall still deletes 10 percent of objects permanently. Bigger budgets cost more compute, which is why the method runs slow: 5000 proposals mean 5000 classifier runs in R-CNN. The count is a knob, not a law — tune it against recall versus budget, like choosing how many slides to open before guessing.

13.8.2 Student Questions and Answers

Q: How is the number of classes or clusters picked for selective search. A: It is not picked from labels. The segmentation groups pixels by shared look and shared fate, and the budget knob sets how many regions survive. Give it 2000, or 100, or 10, and it returns that many candidate regions. Several students tripped on this: there is no k-means \(k\) tied to object classes here.

Q: Why study segmentation before detection at all. A: Because the proposal engine is segmentation. Grouping pixels into object-like regions is what narrows 330 blind windows down to a short list worth scoring — segmentation earns its place as detection's front end.

Proposals shrink the haystack by grouping pixels with a shared fate, trading guaranteed coverage for a far richer positive rate. R-CNN next spends its classifier budget only on that short list.

13.9 R-CNN: Two Thousand Boxes Through a CNN

Take the 2000 best guesses, run each through a full neural network, and keep the ones that look like objects. Simple — and 47 seconds per image.

R-CNN, short for regions with CNN features, wires selective search to a convolutional network in three stages: propose, describe, classify. One input image yields about 2000 proposed regions of all shapes and sizes: one 200 by 400, another 50 by 70, and so on. Neural networks demand fixed-size input, so each region gets warped — stretched or squeezed to one shape such as 128 by 128 (or 227 by 227 for AlexNet), whatever the backbone expects — regardless of its original aspect. Each warped patch then travels through the CNN alone, producing a feature vector, and a classifier on top (a hinge-loss SVM per class in the early design, a softmax in later retellings) names what sits inside. A person-and-horse test shows the loop: a patch with a person scores human and keeps its box, while a patch with no person gets rejected.

The backbone is swap-ready. AlexNet trained on ImageNet and tuned on Pascal's 21 classes (20 objects plus background) did the first duty, and VGG, ResNet, ResNet-150, Inception, or NASNet can slot in just as well — pretrain on ImageNet, fine-tune on Pascal, then train the end classifier. The last stage trains its own end classifier plus a box regressor, a small linear model that nudges each proposed box's edges toward truth (shifting x, y, width, height by learned deltas). On Pascal VOC 2010 the jump was real: about 53.7 percent mAP against 35.1 percent for pure segmentation proposals and the older deformable-parts HOG design — an 18-point gain from learned features on proposed regions. Reading advice: the R-CNN paper first, then the selective-search paper, since the two together show where the boxes come from and what the network does with them.

R-CNN's purpose: replace hand-built HOG templates with learned CNN features while keeping the proposal funnel. Inputs: one image plus about 2000 selective-search boxes. Steps: warp each box to fixed size, run the CNN per box, classify plus regress edges. Output: scored, nudged boxes. The design works — and its cost is the next section's target.

13.9.1 The Two Bottlenecks

Bottleneck one, compute: one image means 2000 separate CNN passes, so training drags to about 84 hours and one frame at test time eats about 47 seconds. A car system that needs 47 seconds to see a pedestrian is useless, because braking starts after the crash — real-time needs 30 frames per second, roughly a thousand times faster. Bottleneck two, proposal quality: the search itself scores only in the mid-30s mAP on its own, and its knobs need tuning. Errors stack across stages: a weak proposal poisons a strong classifier, and no later stage can recover a region that was never proposed. Scope: R-CNN suits offline analysis (photo archives, batch labeling) and never live video.

13.9.2 Student Questions and Answers

Q: Warping fixes sizes, and CNNs ignore rotation and scale, so is aspect ratio still a problem. A: Warping plus the network's built-in tolerance covers shape well enough — a squeezed pedestrian still reads as a pedestrian. The biting costs are elsewhere: 2000 passes per image and a proposal stage that misses too often. Do not optimize the solved problem; attack the bottlenecks.

Q: With an image of 256 by 256 slices, is 2000 proposals actually an improvement. A: Yes. Six positives among 2000 candidates (0.3 percent) beats 6 among 65,536 slices (0.009 percent) by a wide margin — thirty times richer. Better odds, but still far from the end of the road, which is why the next design attacks the 2000 passes directly.

R-CNN proves learned features on proposals beat HOG, jumping to 53.7 percent mAP — but 2000 CNN passes per image make it a batch tool, not a live one. Fast R-CNN next shares a single pass.

13.10 Fast R-CNN: One Pass and RoI Pooling

Two thousand network runs collapse into one. The trick: run the image once, then cut regions out of the features instead of the pixels.

Fast R-CNN keeps the proposals but kills the 2000 passes. The image travels through the convolutional stack exactly once — for example a VGG-style stack turning an 800 by 600 image into a 50 by 37 by 512 feature map. Depth 512 is the channel count (learned pattern detectors), not a proposal count. The spatial part shrinks 16 times: 800 down to 50 is a factor of 16 (four halving poolings: \(2^4 = 16\)). Every proposal then gets projected onto that one shared map instead of re-running the network: divide its image coordinates by 16 and read features at the landing spot.

RoI pooling is the projection tool. RoI means region of interest. Take a proposal on the original image, say x 160, y 80, width 320, height 160, where x and y mark the corner position and width and height mark the region size. Divide each by 16 to land on the feature map: x 10, y 5, width 20, height 10. Now force every region, whatever its shape, into one fixed grid — 7 by 7 by 512 in the classic paper, the size the classifier head expects. Divide width 20 by 7 to get about 2.86 and height 10 by 7 to get about 1.43, so each grid cell covers roughly a 3 by 2 patch of map values. Max-pool each patch, keep the strongest value, and drop it into the cell. All 2000 proposals end up as same-size descriptors on one shared map. One pass then predicts both the class and the refined box edges through sibling output heads. The 2000-pass bottleneck is gone: training drops from 84 hours toward single-digit hours, and test time from 47 seconds toward fractions of a second per image (plus proposal time).

Fast R-CNN's purpose: share one convolutional pass across all proposals. Inputs: image plus proposal boxes. Steps: run CNN once to a downsampled feature map, project each proposal by the stride (divide by 16), snap to a fixed 7-by-7 grid via max pooling. Output: uniform descriptors feeding joint class-plus-box heads. Cost: proposals still come from slow selective search — the one surviving bottleneck.

Picture a map of a city (the feature map) with 2000 address labels (proposals). R-CNN drove to each address separately; Fast R-CNN photographs the whole city once, then reads each address off the photo with a cookie cutter. The cookie cutter is RoI pooling: any shape in, same-size cookie out.

Scope: the stride (16 here) must match the backbone's actual downsampling — change the network and the divisor changes. Pitfall: confusing channel depth 512 with proposal count; 512 is how many pattern detectors fire per location, proposals stay near 2000. Assumption: features computed once serve all regions equally — true for translation but approximate for large scale gaps.

13.10.1 Worked Projection Example

Image 800 by 600 becomes feature map 50 by 37 by 512, a 16-times shrink in each spatial side (\(800/16 = 50\), \(600/16 = 37.5 \approx 37\)). A proposal at x 160, y 80 with width 320 and height 160 scales down to x \(160/16 = 10\), y \(80/16 = 5\), width \(320/16 = 20\), height \(160/16 = 10\). The 7 by 7 target grid cuts width 20 into bins of \(20/7 \approx 2.86\) and height 10 into bins of \(10/7 \approx 1.43\). Round to about 3 by 2 map values per cell. Suppose one such patch holds values \([3, 8, 1, 5, 2, 6]\). Max pooling writes 8 into that grid cell because the max keeps the strongest feature. Repeat for all 49 cells across all 512 channels and the proposal becomes a fixed 7 by 7 by 512 descriptor — \(7 \times 7 \times 512 = 25{,}088\) numbers — ready for the class and box heads in the same single pass. Sense-check: every proposal, from 200-by-400 giants to 50-by-70 scraps, exits as the identical shape the classifier was built for.

13.10.2 Student Questions and Answers

Q: Did the 2000 boxes shrink to fewer boxes now. A: No. The count stays near 2000. What shrank is the network work: one shared pass replaces 2000 separate passes, with every proposal projected onto the same feature map. Boxes unchanged; compute collapsed.

Q: What do x, y, width, and height each mean here. A: x and y pin the corner position of the region. Width stretches sideways from there and height stretches down. Position and size travel together through the divide-by-16 step — all four numbers scale, not just the corner.

Q: Why max pooling inside each grid cell. A: The max keeps the strongest feature in the patch and throws away the weaker ones, so the fixed-size descriptor holds on to what fired hardest — the dominant edge, texture, or part response in that cell.

One shared pass plus RoI projection ends the 2000-pass era. Proposals are still hand-built, though — Faster R-CNN next learns them too.

13.11 Faster R-CNN: Learning the Proposals and Fixing the Rounding

The last hand-built stage falls: the network learns to propose its own regions — and a half-pixel rounding bug gets fixed along the way.

One bottleneck survived Fast R-CNN: proposals still came from selective search, a separate hand-tuned stage scoring in the high 30s on its own and eating seconds per image. Faster R-CNN folds proposals into the network itself. A region proposal network, called RPN, slides over the same shared feature map and predicts candidate regions straight from learned features — objectness score plus box refinements at every map location. Fixed-shape anchor boxes with standard scales (such as 32, 64, 128, 256, 512 pixels) and ratios (such as 1:1, 1:2, 2:1, plus wide 4:9 or 16:9 variants) tile each map spot, typically 9 anchors per location, and two small heads read each anchor: a classification head scoring object versus background, and a regression head shaping the box edges as deltas relative to the anchor. No outside segmentation runs at all. Proposals, features, classes, and boxes all come from one trained stack — trained end to end, sharing convolutions between proposing and deciding.

Then comes the quiet bug fix. RoI pooling rounds every fractional value to the nearest grid point: a true x of 10.6 becomes 11, a y of 5.3 becomes 5, and widths and heights get the same treatment. Each rounding shifts the box by about 0.4 in x and 0.3 in y on the map. Multiply by the 16-times scale and the slip explodes:

\[\Delta x_{\text{image}} = 0.4 \times 16 = 6.4 \text{ pixels}, \qquad \Delta y_{\text{image}} = 0.3 \times 16 = 4.8 \text{ pixels}\]

and a 0.5 map slip means \(0.5 \times 16 = 8\) pixels on the real image, per corner, on every corner at once. IoU bleeds from all four sides at once. Since every small error stacks, a few tenths here cost real accuracy there — the professor's warning verbatim.

RoIAlign drops the rounding and keeps 10.6 at 10.6. Fractional positions sample the map by bilinear interpolation (a weighted blend of the four nearest grid values) instead of snapping to integers, so the true corner, width, and height survive untouched. The same single-network design from before now places boxes where they belong, and the scoreboard shows it: swapping selective search for a learned proposal network lifts Pascal-style mAP from the mid-60s near 66.9 upward, with COCO-style tests confirming the gain with pretraining, and anchor sizes, scales, and proposal counts all tuned by experiment rather than luck. Reading advice: the Fast R-CNN and Faster R-CNN papers next, most running VGG-style backbones, then try swapping in a home-built network and watch the mAP move — which is a small study on its own.

Faster R-CNN's purpose: learn proposals with an RPN on shared features, ending hand-built search. Inputs: image only — anchors tile the map automatically. Steps: shared CNN, RPN objectness plus anchor refinement, RoIAlign sampling without rounding, class plus box heads. RoIAlign's rule: never snap fractions; interpolate instead.

Scope: anchors must tile the expected object shapes — tiny or extreme-ratio objects need matching anchor scales, or recall collapses. Assumption: bilinear sampling approximates true sub-pixel features well; at very coarse maps the interpolation itself blurs. Pitfall: rounding looks harmless ("under a pixel") while costing 8 image pixels per corner — always multiply by the stride before judging.

13.11.1 Rounding Worked Example

A proposal corner sits at map position x 10.6, y 5.3. RoI pooling snaps it to x 11, y 5: an x shift of \(11 - 10.6 = 0.4\) and a y shift of \(5.3 - 5 = 0.3\). Scaled back by the stride 16, the image-level slip is \(0.4 \times 16 = 6.4\) pixels in x and \(0.3 \times 16 = 4.8\) pixels in y. A 0.5 slip anywhere means \(0.5 \times 16 = \mathbf{8}\) pixels on the image. All four corners slip at once — left edge 6 pixels off, right edge 6 the other way — so the shared area with truth shrinks on every side and IoU takes the hit from all directions. RoIAlign keeps 10.6 and 5.3 as they are, sampling between grid points, and the leak closes. Sense-check: on a 50-pixel-wide pedestrian, an 8-pixel edge error per side erases a third of the overlap — visible damage from invisible rounding.

13.11.2 Student Questions and Answers

Q: Does Faster R-CNN still run a segmentation model for proposals. A: No. The proposal network is a learned convolutional stage on the shared map. Hand-built segmentation leaves the pipeline entirely — one network proposes and decides.

Q: Rounding moves things by less than a pixel on the map, so why care. A: The map is 16 times smaller than the image, so a fraction on the map is many pixels on the street: 0.5 becomes 8. Sub-pixel slips become multi-pixel misses, and four slipping corners at once drag IoU down hard.

Q: Is 512 the new proposal count in the fast design. A: No. 512 is the channel depth of the feature map — the number of learned pattern detectors per location. Proposal counts stay near 2000 in the fast design and become a tuned knob, tested at many values, in the faster design.

13.12 Assignment Four: Contrastive Image-Text Pairs

No fixed data set, no labels to memorize — just your own photos, your own captions, and a loss function that pulls matches together and pushes strangers apart.

The fourth assignment ships with no fixed data set on purpose, since handing over full CLIP-scale data (hundreds of millions of pairs) would swamp the task and the grading. Each group of four or five collects about 20 scenes per person — roughly 80 to 100 pairs per group — writes a caption per scene, and trains a small multimodal model in the CLIP spirit: one image encoder and one text encoder projecting into a shared space where mates sit close. Nameplates and signboards with one word each are fine as source material; the point is the setup, not the scenery.

The graded core is the contrastive loss, often the InfoNCE form. Line up 100 images with their 100 captions in a batch. True pairs sit on the diagonal: image one with caption one, image two with caption two, and so on. Every off-diagonal pairing is a negative: image one against captions two through one hundred — 99 negatives per row. Only one match hides among 99 negatives, so the model must pull mates together (high similarity on the diagonal) and push strangers apart (low similarity off it). In symbols, for image \(i\) with its caption similarity \(s_{i,i}\) against all caption similarities \(s_{i,j}\):

\[\mathcal{L}_{i} = -\log \frac{\exp(s_{i,i} / \tau)}{\sum_{j=1}^{100} \exp(s_{i,j} / \tau)}\]

where \(\tau\) is a temperature controlling sharpness: low \(\tau\) punishes near-misses harder. What gets judged is the setup: how the loss is built (temperature, batch size, symmetric image-to-text plus text-to-image terms), how evaluation runs (recall at k: is the true mate in the top 1, 5, 10?), how the problem is framed, and the fine details around it such as learning-rate schedules, regularization, augmentation, preprocessing, and why the optimizer is SGD, SGD with momentum, or Adam. The video explanation, in its few minutes, carries more weight than the raw score, because open-ended framing is the industry skill being tested — the same push-past-baseline philosophy from 13.1.

Figure: The 100-by-100 similarity matrix — true pairs brighten the diagonal, off-diagonal negatives stay dark, and retrieval returns the closest images.

Scope: with only about 100 pairs, the model learns the contrastive mechanics, not web-scale semantics — expect overfitting and say so in the report. Pitfall: tiny batches (8 or 16) give too few negatives per row and the loss goes slack; use the largest batch memory allows. Pitfall: near-duplicate scenes leak: two photos of the same signboard with different captions punish the model for a "wrong" answer that is actually right — deduplicate scenes.

Q: What counts as the negative set for one image-caption pair. A: Every caption not written for that image. With 100 pairs, image one treats captions two through one hundred as negatives, and the same mirror rule holds on the caption side (caption one treats images two through one hundred as negatives) — the loss is symmetric.

Q: Is a nameplate data set with one word per image acceptable. A: Yes. Small self-collected sets are exactly the point, and the focus stays on the contrastive setup rather than data scale. One-word captions still train the diagonal-vs-rest distinction.

Key Industry Applications

Parameter-efficient tuning with LoRA and 4-bit QLoRA lets teams adapt giant models without full 32-bit retraining — the standard answer to rising token and hardware bills, where one GPU replaces a cluster. Driver-assistance stacks pick detection boxes over segmentation masks because a car's neighborhood is enough to brake on: position at 30 frames per second beats pixel-perfect boundaries that arrive too late. Hugging Face base, instruct, and adapter checkpoints set the start point for every such project, but adapters must be retrained per task since borrowed weights fit another data set. YOLO-line detectors serve live military and civilian systems where 47-second R-CNN frames could never keep up — the speed gap that motivated the entire Fast-to-Faster arc. CLIP-style contrastive training on self-collected image-caption pairs powers search across images by words, from product catalogs to surveillance archives. And mAP with IoU cutoffs remains the hiring-screen metric: any vision interview will ask what IoU 0.5 means and why accuracy is never reported for detectors.

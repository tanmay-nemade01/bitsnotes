Local Search and Optimization Algorithms

5.1 Fundamentals of Local Search and Optimization Problems

5.1.1 Concept Definition and Core Philosophy

Hook: What if the steps you take to reach a destination do not matter at all—only the final arrangement where you land? Traditional AI search meticulously records every turn along a path, but optimization problems demand a fundamentally different mindset.

Intuition & Analogy: Imagine tuning an old analog radio dial to find a crisp audio signal. You do not care about the sequence of minor left-and-right knob turns you made to get there; you only care about the clarity of the station playing right now. Similarly, arranging furniture in a living room is a local search task: you reconfigure the sofa and tables in place, evaluating whether the layout feels spacious, without preserving a step-by-step history of every inch the furniture slid across the floor.

Optimization is central to Artificial Intelligence, as many real-world AI problems require finding the best possible solution among a vast number of potential configurations. In traditional systematic search paradigms—such as uninformed search methods (Breadth-First Search, Depth-First Search) or informed search methods (\(A^*\) Search, Greedy Best-First Search)—the primary goal is to find an explicit path from an initial state to a goal state. In those path-based frameworks, the journey matters: the sequence of transitions, operator choices, and accumulated path costs directly constitute the solution.

Formal Definition — Local Search Paradigm: In local search, the path to the goal is completely irrelevant. A state \(s \in \mathcal{S}\) represents a complete configuration and candidate solution to the problem. The objective is not to construct a step-by-step path from a start node to a goal node, but rather to navigate the state space landscape \(\mathcal{S}\) to evaluate, refine, and optimize a single complete configuration until an optimal state \(s^*\) or satisfying configuration is reached.

Formally, given a state space \(\mathcal{S}\) and an objective function \(f: \mathcal{S} \to \mathbb{R}\) (or cost function \(g: \mathcal{S} \to \mathbb{R}\)), local search seeks:

\[ s^* = \arg\max_{s \in \mathcal{S}} f(s) \quad \text{or} \quad s^* = \arg\min_{s \in \mathcal{S}} g(s) \]

Operating on the current state \(s\), the algorithm moves exclusively to a neighboring state \(s' \in \text{Succ}(s)\) based on its objective value \(f(s')\), maintaining no memory of prior path transitions.

5.1.2 Comparison: Path-Based Search vs. Local Search

The fundamental distinction between traditional systematic path search and local state optimization search is summarized below:

Dimension Path-Based Search (e.g., \(A^*\), BFS, DFS) Local Search (e.g., Hill Climbing, Beam Search)
Solution Definition Sequence of actions/transitions from start to goal. The destination state configuration \(s\) itself.
Search Memory Footprint High: Stores frontiers, trees, or graphs (\(O(b^d)\) space). Ultra-low: Keeps only current state \(s\) and immediate neighbors (\(O(1)\) or \(O(b)\) space).
Path Cost Relevance Essential: Path cost \(g(n)\) directly determines optimality. Irrelevant: Path cost is completely ignored.
State Completeness States are often partial solutions (e.g., partial paths). Every state is a complete assignment of domain variables.
Primary Use Cases Navigation, routing, puzzle solving, action planning. Hyperparameter tuning, layout design, scheduling, VLSI placement.

When to pick which: Use path-based search when the sequence of actions matters (e.g., navigating a robot through a maze); use local search when only the final configuration quality matters and the search space is far too large to store in memory.

5.1.3 Symbol Registry — Local Search Fundamentals

  • \(s\) — Candidate state configuration — \(s \in \mathcal{S}\) — State vector
  • \(\mathcal{S}\) — State space landscape — Set of all valid variable assignments — Size \(|\mathcal{S}|\)
  • \(f(s)\) — Objective fitness function — \(f: \mathcal{S} \to \mathbb{R}\) — Real-valued score
  • \(g(s)\) — Cost function — \(g: \mathcal{S} \to \mathbb{R}\) — Real-valued score
  • \(s^*\) — Optimal goal state configuration — \(s^* = \arg\max_{s \in \mathcal{S}} f(s)\) — State vector
  • \(\text{Succ}(s)\) — Successor neighborhood of state \(s\) — Set of adjacent states

Assumptions & Scope:

  • Complete State Representation Required: Local search requires that every state \(s\) in the search space represents a fully specified, syntactically valid assignment of all problem variables.
  • No Path Recovery: Because local search discards path history, it cannot reconstruct how it arrived at a solution unless external logging is explicitly added.
  • Susceptibility to Local Optima: Local search relies on local evaluation metrics \(f(s)\), making it vulnerable to getting trapped on local peaks or plateaus in complex landscapes.

Pitfalls to Avoid:

  • Confusing "Candidate Solution" with "Goal Solution": Assuming a state is not a solution simply because it violates problem constraints. In local search, any complete variable assignment is called a candidate solution or feasible state.
  • Accounting for Transition Costs: Attempting to penalize local search moves based on how many steps were taken. Local search evaluates solely the objective function value \(f(s)\).

Q: Why is a state considered a solution when it doesn't satisfy all the goal conditions (for example, a chessboard configuration where queens are still attacking each other)? A: In local search terminology, any complete, syntactically valid assignment of variables is referred to as a "solution" or a "feasible state." This does not mean it is the optimal goal solution. It simply means it is a complete candidate solution whose quality must be evaluated. The algorithm's job is to start with such a state and iteratively optimize it until it satisfies all constraints or achieves maximum fitness.

Q: After receiving an initial state as a candidate solution, when improving upon it using neighboring states, is the transition cost considered? A: No, path cost is completely ignored in local search. The algorithm evaluates only the state's own objective or fitness score. It does not track, record, or penalize the number of steps or the cost of transitions taken to arrive at that state.

Key Takeaway: Path-based search focuses on the journey (finding the optimal path), whereas local search focuses on the destination (finding the optimal state configuration with minimal memory).

Local search algorithms are widely deployed in industrial applications where path history is unimportant, including hyperparameter tuning in machine learning, feature selection in high-dimensional datasets, robotic spatial positioning, chip layout design (VLSI), and complex airline crew scheduling problems.

5.2 Problem Formulation and State Representation: The 4-Queens Problem

5.2.1 Vector Representation Schema

Hook: How can a complex 2D chessboard grid containing 16 individual squares be represented in computer memory using just four simple numbers without losing any critical positional information?

Intuition & Analogy: Imagine managing a parking lot with 4 rows and 4 columns. Instead of saving a full 2D map of the entire lot, you simply keep a text list where line 1 tells you which row car 1 is parked in, line 2 for car 2, and so on. Because column positions are fixed in order (Column 1, Column 2, Column 3, Column 4), you only need to store the row number for each column.

To perform local search on a constraint satisfaction or optimization problem, we must formulate a compact mathematical representation of a state. Consider the classic 4-Queens problem, where four queens must be placed on a \(4 \times 4\) chessboard such that no two queens attack each other horizontally, vertically, or diagonally.

Instead of building a step-by-step placement tree (starting with an empty board and placing queens one by one), local search begins with all four queens already placed on the board—enforcing the structural constraint of placing exactly one queen per column.

Vector Formulation of Board States: By fixing the column index of queen \(i\) to column \(i\) (for \(i = 1, 2, \dots, N\)), a complete board state is uniquely defined by an \(N\)-dimensional integer vector \(V\):

\[ V = [V_1, V_2, \dots, V_N] \in \{1, 2, \dots, N\}^N \]

where \(V_i\) specifies the row position of the queen in column \(i\). The coordinate of the queen in column \(i\) is thus \((r_i, c_i) = (V_i, i)\).

This compact formulation reduces the unconstrained search space of placing 4 queens anywhere on 16 squares (which yields \(\binom{16}{4} = 1820\) states) down to a drastically smaller search space of \(N^N = 4^4 = 256\) complete state configurations.

5.2.2 Symbol Registry — State Representation

  • \(N\) — Board dimension and total number of queens — \(N \in \mathbb{Z}^+\) — \(N = 4\)
  • \(V\) — State configuration vector — \(V = [V_1, V_2, \dots, V_N]\) — Vector in \(\{1, \dots, N\}^N\)
  • \(V_i\) — Row index of the queen in column \(i\) — \(V_i \in \{1, \dots, N\}\) — Integer scalar
  • \(\mathcal{S}\) — Complete state space of all valid board vectors — \(\mathcal{S} = \{1, \dots, N\}^N\) — Size \(|\mathcal{S}| = N^N = 256\)

5.2.3 Vector Mapping Examples

Worked Example 5.2.1: Mapping Board Configurations to Vectors

Configuration 1: \(V = [2, 4, 2, 2]\)

  • Column 1: Queen \(Q_1\) is at Row 2 \(\to (r_1, c_1) = (2, 1)\)
  • Column 2: Queen \(Q_2\) is at Row 4 \(\to (r_2, c_2) = (4, 2)\)
  • Column 3: Queen \(Q_3\) is at Row 2 \(\to (r_3, c_3) = (2, 3)\)
  • Column 4: Queen \(Q_4\) is at Row 2 \(\to (r_4, c_4) = (2, 4)\)

  • Column 1: Queen \(Q_1\) is at Row 1 \(\to (r_1, c_1) = (1, 1)\)
  • Column 2: Queen \(Q_2\) is at Row 3 \(\to (r_2, c_2) = (3, 2)\)
  • Column 3: Queen \(Q_3\) is at Row 2 \(\to (r_3, c_3) = (2, 3)\)

Assumptions & Scope:

  • Fixed Column Ordering: Vector position \(i\) is implicitly linked to column \(i\). You cannot swap columns without re-indexing the vector.
  • Single Queen per Column: This representation structurally guarantees that no two queens share the same column. However, queens can still share rows or diagonals.

Pitfalls to Avoid:

  • Swapping Row and Column Roles: Writing \(V_r = c\) instead of \(V_c = r\). Remember: array index = column, array value = row.
  • Index Out of Bounds: Using 0-indexed values \(\{0, 1, 2, 3\}\) when the mathematical problem definition specifies 1-indexed rows \(\{1, 2, 3, 4\}\).

Exam note: Be prepared to convert back and forth between 2D grid coordinates \((r, c)\) and 1D vector representations \(V = [V_1, V_2, \dots, V_N]\) for arbitrary board configurations on exam questions.

Key Takeaway: The vector representation \(V = [V_1, V_2, \dots, V_N]\) embeds the 1-queen-per-column constraint directly into the data structure, shrinking the search space to \(N^N\).

Real-world domain connection: This index-as-variable, value-as-assignment state encoding is identical to how variables are mapped in Constraint Satisfaction Problems (CSPs), SAT solvers, and automated register allocation in compiler optimization.

5.3 Fitness Functions and Evaluation Metrics

5.3.1 Mathematical Formulation of Fitness

Hook: How does an artificial intelligence quantify the quality of a candidate solution in a single glance without knowing the path taken to reach it?

Intuition & Analogy: Think of a fitness score like a fault counter in a quality control inspection. If a factory produces a table with 4 legs, a score of zero means no wobbly legs (perfect product). In local search, a fitness function acts as an objective scorekeeper, evaluating how close a complete state configuration is to perfection.

To guide local search through the state space landscape, we evaluate each state using an objective function, commonly termed a fitness function \(F(n)\) (or objective evaluation metric \(H(n)\)). While heuristic functions in path search estimate the remaining distance to a goal node, a fitness function in local search directly measures the quality, utility, or constraint satisfaction of the current state configuration itself.

For the \(N\)-Queens problem, fitness can be defined either as a minimization metric (counting the number of attacking/conflicting queen pairs) or as a maximization metric (counting the number of non-conflicting queen pairs).

Formal Mathematical Formulation of Fitness Metrics:

Given an \(N\)-Queens vector \(V = [V_1, V_2, \dots, V_N]\), the total number of unique queen pairs is:

\[ N_{\text{pairs}} = \binom{N}{2} = \frac{N(N - 1)}{2} \]

For \(N = 4\), \(N_{\text{pairs}} = \frac{4 \times 3}{2} = 6\) pairs.

Two queens \(Q_i = (V_i, i)\) and \(Q_j = (V_j, j)\) with \(i < j\) are defined to be in conflict (\(C(Q_i, Q_j)=1\)) if:

\[ C(Q_i, Q_j) = \begin{cases} 1 & \text{if } V_i = V_j \text{ (same row) or } |V_i - V_j| = |i - j| \text{ (same diagonal)} \\ 0 & \text{otherwise (non-conflicting)} \end{cases} \]
  1. Minimization Fitness Metric \(h(s)\) (Conflict Count):
\[ h(s) = \sum_{1 \le i < j \le N} C(Q_i, Q_j) \]

Goal condition: \(h(s^*) = 0\) (zero attacking pairs).

  1. Maximization Fitness Metric \(f(s)\) (Non-Conflicting Count):
\[ f(s) = N_{\text{pairs}} - h(s) = \sum_{1 \le i < j \le N} (1 - C(Q_i, Q_j)) \]

Goal condition: \(f(s^*) = N_{\text{pairs}} = \frac{N(N-1)}{2}\) (for \(N=4\), \(f(s^*) = 6\)).

5.3.2 Symbol Registry — Fitness Computation

  • \(N_{\text{pairs}}\) — Total unique queen pairs — \(N_{\text{pairs}} = \binom{N}{2} = \frac{N(N-1)}{2}\) — Integer scalar (\(N_{\text{pairs}} = 6\) for \(N=4\))
  • \(Q_i\) — Coordinates of queen in column \(i\) — \(Q_i = (V_i, i)\) — Ordered pair \((r, c) \in \{1,\dots,N\}^2\)
  • \(\Delta r\) — Absolute row difference between queens \(i\) and \(j\) — \(\Delta r = |V_i - V_j|\) — Non-negative integer
  • \(\Delta c\) — Absolute column difference between queens \(i\) and \(j\) — \(\Delta c = |i - j|\) — Positive integer
  • \(C(Q_i, Q_j)\) — Indicator function for conflict between \(Q_i\) and \(Q_j\) — \(C(Q_i, Q_j) \in \{0, 1\}\) — Binary flag
  • \(h(s)\) — Minimization objective function (total conflicts) — \(h(s) \in \{0, \dots, N_{\text{pairs}}\}\) — Integer score
  • \(f(s)\) — Maximization objective function (non-conflicting pairs) — \(f(s) \in \{0, \dots, N_{\text{pairs}}\}\) — Integer score

5.3.3 Worked Example: Full Fitness Calculation

Worked Example 5.3.1: Complete Fitness Evaluation for State \(V = [2, 4, 2, 2]\)

Let us compute the exact fitness metrics for candidate state \(V = [2, 4, 2, 2]\) on a \(4 \times 4\) board.

The four queen positions are:

  • \(Q_1 = (V_1, 1) = (2, 1)\)
  • \(Q_2 = (V_2, 2) = (4, 2)\)
  • \(Q_3 = (V_3, 3) = (2, 3)\)
  • \(Q_4 = (V_4, 4) = (2, 4)\)

For \(N = 4\), there are \(\binom{4}{2} = 6\) unique pairs \((Q_i, Q_j)\) with \(i < j\):

  1. Pair \((Q_1, Q_2)\): \(Q_1 = (2, 1)\), \(Q_2 = (4, 2)\)
  • Row Check: \(V_1 = 2, V_2 = 4 \implies V_1 \neq V_2\) (Different rows)
  • Diagonal Check: \(\Delta r = |2 - 4| = 2\); \(\Delta c = |1 - 2| = 1\). Since \(\Delta r \neq \Delta c\) (\(2 \neq 1\)), not on same diagonal.
  • Status: Non-conflicting (\(C(Q_1, Q_2) = 0\)).
  1. Pair \((Q_1, Q_3)\): \(Q_1 = (2, 1)\), \(Q_3 = (2, 3)\)
  • Row Check: \(V_1 = 2, V_3 = 2 \implies V_1 = V_3 = 2\) (Same row 2).
  • Status: Conflicting (\(C(Q_1, Q_3) = 1\)).
  1. Pair \((Q_1, Q_4)\): \(Q_1 = (2, 1)\), \(Q_4 = (2, 4)\)
  • Row Check: \(V_1 = 2, V_4 = 2 \implies V_1 = V_4 = 2\) (Same row 2).
  • Status: Conflicting (\(C(Q_1, Q_4) = 1\)).
  1. Pair \((Q_2, Q_3)\): \(Q_2 = (4, 2)\), \(Q_3 = (2, 3)\)
  • Row Check: \(V_2 = 4, V_3 = 2 \implies V_2 \neq V_3\) (Different rows)
  • Diagonal Check: \(\Delta r = |4 - 2| = 2\); \(\Delta c = |2 - 3| = 1\). Since \(\Delta r \neq \Delta c\) (\(2 \neq 1\)), not on same diagonal.
  • Status: Non-conflicting (\(C(Q_2, Q_3) = 0\)).
  1. Pair \((Q_2, Q_4)\): \(Q_2 = (4, 2)\), \(Q_4 = (2, 4)\)
  • Row Check: \(V_2 = 4, V_4 = 2 \implies V_2 \neq V_4\) (Different rows)
  • Diagonal Check: \(\Delta r = |4 - 2| = 2\); \(\Delta c = |2 - 4| = 2\). Since \(\Delta r = \Delta c = 2\), they lie on the same diagonal.
  • Status: Conflicting (\(C(Q_2, Q_4) = 1\)).
  1. Pair \((Q_3, Q_4)\): \(Q_3 = (2, 3)\), \(Q_4 = (2, 4)\)
  • Row Check: \(V_3 = 2, V_4 = 2 \implies V_3 = V_4 = 2\) (Same row 2).
  • Status: Conflicting (\(C(Q_3, Q_4) = 1\)).

Final Score Summary:

  • Total Conflicts (Minimization score): \(h([2, 4, 2, 2]) = 1 + 1 + 1 + 1 = 4\)
  • Non-Conflicting Pairs (Maximization score): \(f([2, 4, 2, 2]) = 6 - 4 = 2\)

Sense-Check: \(h(s) + f(s) = 4 + 2 = 6 = N_{\text{pairs}}\), confirming full consistency.

Assumptions & Scope:

  • Combination, Not Permutation: We evaluate only ordered pairs \((i, j)\) with \(i < j\). Evaluating \((j, i)\) in addition to \((i, j)\) would double-count conflicts.
  • Diagonal Check Validity: The condition \(\Delta r = \Delta c\) captures both main diagonals (slope \(+1\)) and anti-diagonals (slope \(-1\)) in a single unified absolute value test.

Pitfalls to Avoid:

  • Double Counting Queen Conflicts: Counting pair \((Q_1, Q_3)\) twice (once as \(Q_1 \to Q_3\) and once as \(Q_3 \to Q_1\)), leading to an inflated score of 8 conflicts instead of 4.
  • Mixing Up Objective Directions: Forgetting whether your local search implementation is maximizing \(f(s)\) or minimizing \(h(s)\).

Q: How are \(Q_2\) and \(Q_4\) conflicting in the board configuration \([2, 4, 2, 2]\)? A: \(Q_2\) is located at column 2, row 4 (coordinates \((4, 2)\)) and \(Q_4\) is located at column 4, row 2 (coordinates \((2, 4)\)). The vertical distance is \(\Delta r = |4 - 2| = 2\) and the horizontal distance is \(\Delta c = |2 - 4| = 2\). Because \(\Delta r = \Delta c = 2\), both queens lie on the exact same diagonal and are in conflict.

Q: How do we decide when local search has reached the goal? A: We evaluate the state's fitness score \(F(n)\). When \(F(n)\) reaches the target optimal value defined for the problem (for instance, zero conflicting pairs \(h(s^*) = 0\), or max non-conflicting pairs \(f(s^*) = 6\) in 4-Queens), the global optimum has been found and the search terminates successfully.

Exam note: Expect numerical exam questions asking you to compute fitness scores \(h(s)\) and \(f(s)\), count conflicting queen pairs, and perform step-by-step row/diagonal checks for arbitrary state vectors.

Key Takeaway: The fitness function converts complex spatial constraint satisfaction into a single scalar score that guides local search transitions.

Real-world domain connection: Fitness functions mirror loss functions in machine learning (e.g., mean squared error, cross-entropy) and cost functions in financial portfolio optimization, where high-dimensional solutions are compressed into a single scalar value for gradient or search direction optimization.

5.4 Neighborhood Expansion Strategies (1-NN, 2-NN, and N-NN)

5.4.1 Definition of Neighborhood

Hook: How does a local search algorithm decide where it can move next without evaluating the entire universe of possible board configurations?

Intuition & Analogy: Imagine standing on a grid map at night with a small flashlight. You cannot see the entire landscape; you can only illuminate and step onto neighboring spots immediately adjacent to your feet. In local search, a "neighborhood" is the set of all candidate states reachable by applying one single, permitted modification operator to your current configuration.

In local search, a neighbor state \(s' \in \text{Succ}(s)\) is a complete configuration reachable from the current state \(s\) by applying an atomic modification operator. Local search algorithms do not explore a global search tree; they generate and examine states exclusively within the immediate neighborhood of the current state.

Formal Mathematical Formulation of Neighborhoods:

In variable assignment space \(\mathcal{S} = \{1, \dots, N\}^N\), the distance between two states \(V\) and \(V'\) is defined by the Hamming distance \(d_H(V, V')\), which counts the number of position entries where \(V_i \neq V'_i\).

  1. 1-NN Neighborhood (1-Nearest Neighbor / Single-Move): The set of all states at Hamming distance \(d_H(V, V') = 1\). Exactly one variable \(V_i\) is modified:
\[ N_{1NN} = N \times (N - 1) \]

For \(N = 4\): \(N_{1NN} = 4 \times (4 - 1) = 12\) neighbors.

  1. 2-NN Neighborhood (2-Nearest Neighbor / Double-Move): The set of all states at Hamming distance \(d_H(V, V') = 2\). Exactly two variables \((V_i, V_j)\) are modified simultaneously:
\[ N_{2NN} = \binom{N}{2} \times (N - 1)^2 = \frac{N(N - 1)}{2} (N - 1)^2 \]

For \(N = 4\): \(N_{2NN} = \binom{4}{2} \times (4 - 1)^2 = 6 \times 9 = 54\) neighbors.

  1. \(N\)-NN Neighborhood (Full Multi-Move Expansion): The set of all states where all \(N\) variables can change simultaneously (\(d_H(V, V') \le N\)), generating the entire state space of \(N^N\) states (256 for \(N=4\)).

5.4.2 Symbol Registry — Neighborhood Expansion

  • \(N\) — Board dimension and total number of queens — \(N \in \mathbb{Z}^+\) — \(N = 4\)
  • \(V\) — State configuration vector — \(V = [V_1, V_2, \dots, V_N]\) — Vector in \(\{1, \dots, N\}^N\)
  • \(d_H(V, V')\) — Hamming distance between states \(V\) and \(V'\) — \(d_H(V, V') \in \{0, \dots, N\}\) — Integer count of differing positions
  • \(N_{1NN}\) — Total number of 1-NN neighbor states — \(N_{1NN} = N(N-1)\) — Integer scalar (\(N_{1NN} = 12\) for \(N=4\))
  • \(N_{2NN}\) — Total number of 2-NN neighbor states — \(N_{2NN} = \binom{N}{2}(N-1)^2\) — Integer scalar (\(N_{2NN} = 54\) for \(N=4\))

5.4.3 1-NN Expansion Strategy (1-Nearest Neighbor / Single-Move)

Under 1-NN expansion, a neighbor state is generated by choosing one column index \(i \in \{1, \dots, N\}\) and reassigning queen \(Q_i\) to any of the other \(N-1\) available row positions in that column, while leaving all other \(N-1\) queens untouched.

5.4.4 Worked Examples: 1-NN and 2-NN Expansions

Worked Example 5.4.1: Complete 1-NN Expansion for State \(V = [2, 4, 2, 2]\)

Starting from state \(V = [2, 4, 2, 2]\), we systematically generate all 12 1-NN neighbor configurations by altering one column variable at a time:

  1. Altering Variable \(V_1\) (currently row 2; alternative rows: 1, 3, 4; \(V_2, V_3, V_4\) held constant at \(4, 2, 2\)):
  • Neighbor 1: \([1, 4, 2, 2]\)
  • Neighbor 2: \([3, 4, 2, 2]\)
  • Neighbor 3: \([4, 4, 2, 2]\)
  1. Altering Variable \(V_2\) (currently row 4; alternative rows: 1, 2, 3; \(V_1, V_3, V_4\) held constant at \(2, 2, 2\)):
  • Neighbor 4: \([2, 1, 2, 2]\)
  • Neighbor 5: \([2, 2, 2, 2]\)
  • Neighbor 6: \([2, 3, 2, 2]\)
  1. Altering Variable \(V_3\) (currently row 2; alternative rows: 1, 3, 4; \(V_1, V_2, V_4\) held constant at \(2, 4, 2\)):
  • Neighbor 7: \([2, 4, 1, 2]\)
  • Neighbor 8: \([2, 4, 3, 2]\)
  • Neighbor 9: \([2, 4, 4, 2]\)
  1. Altering Variable \(V_4\) (currently row 2; alternative rows: 1, 3, 4; \(V_1, V_2, V_3\) held constant at \(2, 4, 2\)):
  • Neighbor 10: \([2, 4, 2, 1]\)
  • Neighbor 11: \([2, 4, 2, 3]\)
  • Neighbor 12: \([2, 4, 2, 4]\)

Sense-Check: 4 columns \(\times\) 3 alternative rows per column = 12 total distinct 1-NN neighbors.

Worked Example 5.4.2: Calculating 2-NN Neighborhood Size for \(N=4\)

Compute the exact number of 2-NN neighbors generated from any state on a \(4 \times 4\) board:

  1. Choose 2 columns out of 4: \(\binom{4}{2} = \frac{4 \times 3}{2} = 6\) column pairs.
  2. Reassign rows for chosen pair: Each chosen column has \(N-1 = 3\) alternative row positions, giving \(3 \times 3 = 9\) joint row assignments.
  3. Total 2-NN Neighbors: \(N_{2NN} = 6 \times 9 = 54\) neighbors.

Sense-Check: \(N_{2NN} = 54\) is significantly larger than \(N_{1NN} = 12\), offering broader reach across the landscape at the expense of evaluating 4.5 times more states per iteration.

Assumptions & Scope:

  • Neighborhood Size vs. Computational Cost: 1-NN requires evaluating \(N(N-1)\) states per step (e.g., 12 for \(N=4\)). 2-NN requires evaluating \(\binom{N}{2}(N-1)^2\) states (e.g., 54 for \(N=4\)). As \(N\) grows, 2-NN expansion becomes computationally heavy.
  • Hamming Distance Barrier: A 1-NN local search step cannot jump out of a local minimum if escaping requires modifying two queens simultaneously.

Pitfalls to Avoid:

  • Confusing Row Distance with Step Count: Believing that moving a queen from row 1 to row 4 counts as 3 steps. In 1-NN, any single variable assignment change is 1 step, regardless of how many rows the queen slides.
  • Including the Current State: Counting the current state \(V\) as one of its own neighbors. Neighbors must differ from \(V\) in at least one variable position.

Q: In 1-NN expansion of \([2, 4, 2, 2]\), does moving a queen from row 2 to row 4 (e.g., generating \([2, 4, 4, 2]\)) count as a single step, even though the queen moved two rows down? A: Yes. In 1-NN expansion, "one step" refers strictly to changing the value of exactly one variable (one queen). Moving queen \(Q_3\) from row 2 directly to row 4 is a single atomic variable assignment change on \(V_3\), so \([2, 4, 4, 2]\) is a valid 1-NN neighbor generated in a single step.

Exam note: Remember that for an \(N \times N\) board, 1-NN expansion generates exactly \(N(N-1)\) neighbors, and 2-NN expansion generates \(\binom{N}{2}(N-1)^2\) neighbors. Be prepared to derive and compute these quantities for arbitrary \(N\) on exams.

Key Takeaway: 1-NN expansion evaluates \(N(N-1)\) single-move neighbors per iteration, balancing search exploration depth against computational memory and time.

Real-world domain connection: 1-NN and 2-NN expansions are identical to 1-flip and 2-flip move operators in k-OPT local search heuristics for the Traveling Salesperson Problem (TSP) and single-bit/two-bit mutations in evolutionary programming.

5.5 Hill Climbing Search and Its Core Variants

5.5.1 Symbol Registry — Hill Climbing and Stochastic Selection

  • \(K\) — Maximum allowed random restarts parameter — \(K \in \mathbb{Z}^+\) — Integer scalar
  • \(s\) — Current state configuration — \(s \in \mathcal{S}\) — State vector \(V\)
  • \(\text{Succ}(s)\) — Set of 1-NN successor states — \(|\text{Succ}(s)| = N_{1NN}\) — Set of \(N(N-1)\) states
  • \(F(s_i)\) — Objective/fitness score of successor state \(s_i\) — \(F(s_i) \in \mathbb{Z}_{\ge 0}\) — Integer scalar
  • \(freq(F)\) — Frequency of fitness score \(F\) among successors — \(freq(F) \in \mathbb{Z}_{\ge 0}\) — Integer scalar
  • \(P(F)\) — Selection probability of fitness score \(F\) — \(P(F) = \frac{freq(F)}{N_{1NN}}\) — Real probability in \([0, 1]\)

5.5.2 Basic Hill Climbing (Greedy Local Search)

Hook: Can a blindfolded hiker reach the highest peak in a mountain range simply by feeling which direction points uphill under their boots?

Intuition & Analogy: Basic hill climbing is like hiking up a steep mountain in pitch-black fog. At every step, you extend your foot in all immediate directions (your 1-NN neighbors) and take a step in whichever direction goes highest uphill. When every direction around you goes downhill or flat, you stop and declare that you have reached the peak.

Purpose & Algorithm — Basic Hill Climbing: Basic Hill Climbing is an iterative greedy local search algorithm that continually moves in the direction of increasing fitness value \(f(s)\) (or decreasing cost \(h(s)\)). It maintains only the current state \(s\), evaluates all 1-NN successors \(\text{Succ}(s)\), and transitions to the neighbor with the best score.

Inputs & Outputs:

  • Inputs: Initial state \(s_0 \in \mathcal{S}\), neighborhood operator \(\text{Succ}(\cdot)\), fitness function \(F(\cdot)\).
  • Outputs: State \(s^*\) representing a local or global maximum.
Algorithm: Basic Hill Climbing
1. current_state = Generate_Random_Initial_State()
2. loop:
3.     neighbors = Generate_1NN_Neighbors(current_state)
4.     best_neighbor = Select_State_With_Max_Fitness(neighbors)
5.     if Fitness(best_neighbor) <= Fitness(current_state):
6.         return current_state  // Local maximum or plateau reached
7.     current_state = best_neighbor

Landscape Limitations of Basic Hill Climbing:

  1. Local Maxima: A peak that is higher than all its immediate neighbors, but lower than the global maximum. The greedy algorithm gets trapped here because every neighbor looks worse.
  2. Plateaus: Flat regions of the landscape where all adjacent neighbors have identical fitness scores (\(F(s') = F(s)\)), leaving the search with zero directional gradient.
  3. Ridges: Narrow sloping chains of local peaks where 1-NN steps must move diagonally across axes, causing basic search to oscillate inefficiently or stall.

5.5.3 Hill Climbing with Random Restarts

To escape local maxima and navigate complex landscapes, Hill Climbing with Random Restarts introduces a series of independent search trials. If a basic hill climbing run gets stuck at a local maximum without reaching the target global optimum, the algorithm discards the stuck state and restarts from a brand-new, randomly generated initial state vector \(s_0 \sim U(\mathcal{S})\).

Restart Protocol & Parameter \(K\): The parameter \(K\) specifies the maximum number of independent random restart trials allowed:

  • The algorithm executes up to \(K\) independent hill climbing runs.
  • If any trial hits the global optimum (e.g., \(h(s) = 0\) conflicts), search halts immediately and returns the goal state.
  • If after \(K\) trials no global optimum has been found, the algorithm returns the overall best state encountered across all \(K\) trials.

Q: What happens when \(K = 1\) in Hill Climbing with Random Restarts? A: When \(K = 1\), the algorithm performs only a single run with no restarts allowed. Therefore, setting \(K = 1\) makes Hill Climbing with Random Restarts completely identical to basic Hill Climbing.

Exam note: In exam problems involving Hill Climbing with Random Restarts, always check the value of \(K\). If \(K = 1\), terminate search at the very first local peak. If \(K > 1\), perform up to \(K\) independent trials unless a global optimum is reached earlier.

5.5.4 Stochastic Hill Climbing

Stochastic Hill Climbing replaces deterministic greedy selection with probabilistic neighbor selection. Instead of always picking the single absolute best neighbor, stochastic hill climbing selects among valid 1-NN successors probabilistically based on their relative fitness values.

Step-by-Step Stochastic Probability Calculation Protocol:

  1. Generate all \(N_{1NN}\) successor states of the current state \(s\).
  2. Compute the fitness score \(F(s_i)\) for all \(N_{1NN}\) successors.
  3. Group the successors by their distinct fitness scores.
  4. Count the frequency \(freq(F)\) of each distinct fitness score among the \(N_{1NN}\) successors.
  5. Calculate the selection probability \(P(F)\) for each fitness score category:
\[ P(F) = \frac{freq(F)}{N_{1NN}} \]
  1. Sample a fitness category according to distribution \(P(F)\), then pick one state uniformly at random from among the candidate states in that category.

Worked Example 5.5.1: Stochastic Probability Table for State \([2, 4, 2, 2]\)

Suppose the 12 1-NN successors of state \([2, 4, 2, 2]\) yield the following distribution of fitness scores (where \(F\) represents non-conflicting pairs):

Fitness Score \(F\) Frequency \(freq(F)\) (out of 12) Selection Probability \(P(F) = \frac{freq(F)}{12}\) Percentage
\(F = 1\) 2 \(\frac{2}{12} = \frac{1}{6} \approx 0.1667\) 16.67%
\(F = 2\) 5 \(\frac{5}{12} \approx 0.4167\) 41.67%
\(F = 3\) 4 \(\frac{4}{12} = \frac{1}{3} \approx 0.3333\) 33.33%
\(F = 4\) 1 \(\frac{1}{12} \approx 0.0833\) 8.33%
Total 12 \(\frac{12}{12} = 1.0\) 100.0%
  • The category \(F = 2\) has the highest selection probability (\(P = 0.4167\)).
  • If category \(F = 2\) is sampled, the algorithm selects uniformly at random among the 5 states belonging to that category (each having an individual probability of \(\frac{1}{12} \approx 0.0833\)).

Pitfalls to Avoid:

  • Forgetting to Normalize Probabilities: Writing raw frequencies instead of dividing by total neighbors \(N_{1NN}\). Probabilities must sum to \(1.0\).
  • Infinite Plateau Looping: Not placing a step limit on plateau moves, causing basic hill climbing to loop infinitely between equal-scoring states.

Key Takeaway: Basic hill climbing is greedy and prone to local optima; random restarts tackle local peaks via \(K\) independent trials; stochastic hill climbing introduces probabilistic selection to smooth out search trajectories.

Real-world domain connection: Hill climbing variants underpin simulated annealing, stochastic gradient descent (SGD) in neural network optimization, and RAS (Random Access Search) in combinatorial operations research.

5.6 Local Beam Search and Stochastic Beam Search

5.6.1 Symbol Registry — Beam Search

  • \(K\) — Beam width / number of parallel state tracking threads — \(K \in \mathbb{Z}^+\) — Integer scalar
  • \(S_{\text{current}}\) — Pool of active beam states — \(|S_{\text{current}}| = K\) — Set of state vectors
  • \(S_{\text{successors}}\) — Combined pool of generated 1-NN successors — \(|S_{\text{successors}}| = K \times N_{1NN}\) — Set of state vectors
  • \(F(s)\) — Fitness evaluation metric for candidate state \(s\) — \(F(s) \in \mathbb{Z}_{\ge 0}\) — Integer scalar

5.6.2 Local Beam Search Mechanism

Hook: Why send a single scout up a single mountain trail when you can dispatch a team of \(K\) scouts simultaneously to explore multiple promising peaks at once?

Intuition & Analogy: Imagine sending \(K=4\) search parties into a forest looking for lost treasure. Instead of each search party wandering isolated in its own valley, at the end of each hour all four parties radio back their locations and surrounding findings. The team leader identifies the top 4 overall most promising locations found by anyone in the group, and dispatches the four parties to continue searching from those top 4 locations.

While Hill Climbing maintains only a single current state in memory, Local Beam Search maintains \(K\) states simultaneously. The parameter \(K\) is called the beam width.

Purpose & Algorithm — Local Beam Search (Beam Width \(K\)):

Local Beam Search tracks \(K\) complete candidate states in parallel. At each step, all \(K\) states generate their 1-NN neighbors, producing a combined candidate pool of \(K \times N_{1NN}\) successor states. The algorithm then selects the top \(K\) overall best states from this combined pool to form the next generation set.

Algorithm: Local Beam Search (Beam Width K)
1. current_states = Generate_K_Random_Initial_States()
2. loop:
3.     if any state in current_states is Global_Optimum():
4.         return state
5.     all_successors = []
6.     for state in current_states:
7.         all_successors.extend(Generate_1NN_Neighbors(state))
8.     if any successor in all_successors is Global_Optimum():
9.         return successor
10.    current_states = Select_Top_K_Best_States(all_successors)

Parallel Architecture and Thread Independence

Local Beam Search is designed for deployment across multi-core processors or distributed computing clusters (such as Hadoop or Spark). Each of the \(K\) parallel threads evaluates its state and generates its 12 successors independently.

Q: Are the \(K\) parallel search threads in Local Beam Search collaborating or sharing information with each other? A: No. In Local Beam Search, the \(K\) parallel search threads run completely independently without collaborating, exchanging state information, or performing genetic recombination. The only interaction occurs at the end of an iteration when all \(K \times N_{1NN}\) generated successors are aggregated into a single central pool to select the top \(K\) states for the next iteration. If any thread discovers a goal state, it broadcasts a global termination signal to halt search.

Q: Is Local Beam Search computationally slower than single-thread Hill Climbing? A: No. When deployed on multi-threaded or distributed hardware infrastructure, Local Beam Search runs in parallel, allowing it to explore \(K\) distinct regions of the state space concurrently without incurring sequential wall-clock time penalties.

Q: What does Local Beam Search reduce to when beam width \(K = 1\)? A: When beam width \(K = 1\), Local Beam Search tracks only a single state vector and selects its 1 best successor at each step, making it functionally identical to standard basic Hill Climbing.

5.6.3 Stochastic Beam Search

In deterministic Local Beam Search, strictly selecting the top \(K\) best successors from the combined pool of \(K \times N_{1NN}\) neighbors can lead to beam concentration: all \(K\) states quickly cluster around the slopes of a single local peak, destroying search diversity.

Stochastic Beam Search Mechanism: Stochastic Beam Search retains the parallel beam structure but selects \(K\) successors probabilistically from the combined candidate pool, weighting each successor's selection probability proportionally to its fitness score \(F(s_i)\):

\[ P(s_i) = \frac{F(s_i)}{\sum_{j=1}^{K \cdot N_{1NN}} F(s_j)} \]

This probabilistic selection ensures that weaker but diverse candidate states occasionally survive into the next generation, preventing all \(K\) beams from collapsing onto a single local optimum.

Assumptions & Scope:

  • Memory Cost: Memory footprint is \(O(K)\) states, and candidate evaluation cost per step is \(K \times N_{1NN}\) fitness calculations (e.g., \(4 \times 12 = 48\) evaluations per step for \(K=4\) on 4-Queens).
  • Distinction from Random Restarts: Random Restarts executes \(K\) sequential, unpooled searches one after another. Local Beam Search executes \(K\) parallel searches whose successors are pooled together at every step.

Pitfalls to Avoid:

  • Confusing Beam Search with Genetic Algorithms: Assuming Beam Search threads exchange genetic material or combine features (crossover). Beam Search only pools and filters states; it never combines state components.
  • Beam Concentration Risk: Setting \(K\) too low or using deterministic selection on steep landscapes, causing all \(K\) states to duplicate the exact same local peak.

Key Takeaway: Local Beam Search tracks \(K\) states in parallel, pooling \(K \times N_{1NN}\) successors to pick the top \(K\); Stochastic Beam Search introduces weighted sampling across the pool to preserve search diversity.

Real-world domain connection: Beam Search is heavily utilized as the decoding strategy in Natural Language Processing (NLP) models (such as sequence-to-sequence translation models, LLM text generation, and speech recognition), where the top \(K\) most probable word sequence candidate prefixes are tracked in parallel.

5.7 Introduction to Population-Based Evolutionary Algorithms (Genetic Algorithms Preview)

5.7.1 Paradigm Shift: Independent Threads vs. Collaborative Populations

Hook: What if parallel search threads did not search in isolation, but could actively share their best discoveries and breed superior new candidate solutions?

Intuition & Analogy: Think of selective breeding in agriculture. If one farmer breeds a wheat strain that resists drought (parent 1) and another breeds a strain with double grain yield (parent 2), crossing these two strains produces offspring that inherit both drought resistance and high yield. While Local Beam Search merely keeps the top \(K\) individuals alive, Genetic Algorithms combine useful traits from different individuals.

The local search paradigm evolves from single-state tracking (Hill Climbing) to multi-state parallel tracking (Beam Search), and ultimately to population-based collaborative evolution (Genetic Algorithms).

Comparison: Local Beam Search vs. Population-Based Evolutionary Search

Feature Dimension Local Beam Search Genetic Algorithms (GA)
Population Dynamics Maintains \(K\) states independently. Maintains a population of \(N_{\text{pop}}\) candidate solutions.
Information Sharing None: Search threads do not communicate or exchange state components. Active Collaboration: Crossover recombines sub-structures from two parent solutions.
Diversity Mechanism Stochastic selection over pooled 1-NN neighbors. Random mutation operators applied to offspring strings.
Natural Inspiration Parallel geographic exploration by isolated scouts. Biological evolution, natural selection, and genetics.

5.7.2 Symbol Registry — Genetic Algorithms

  • \(N_{\text{pop}}\) — Total population size — \(N_{\text{pop}} \in \mathbb{Z}^+\) — Integer count of candidate chromosomes
  • \(p_m\) — Mutation probability parameter — \(p_m \in [0, 1]\) — Real probability scalar

5.7.3 Genetic Algorithm Pipeline Preview

High-Level Genetic Algorithm Operational Loop:

  1. Chromosome Representation (Encoding): Encode candidate states as string vectors (analogous to board state vectors \(V = [V_1, V_2, \dots, V_N]\)).
  2. Initial Population Generation: Initialize a population of \(N_{\text{pop}}\) random chromosomes.
  3. Fitness Evaluation: Compute fitness score \(F(s)\) for every chromosome in the population.
  4. Parent Selection: Select pairs of high-fitness individuals as parents based on selection probabilities (e.g., roulette wheel or tournament selection).
  5. Crossover (Recombination): Swap segments between two parent chromosomes to construct child chromosomes inheriting traits from both.
  6. Mutation: Apply small, random alterations (e.g., changing one position value) to child chromosomes with low mutation probability \(p_m\) to inject fresh genetic diversity.
  7. Generational Replacement: Form the next generation population from the offspring and repeat until convergence to a global optimum.

Assumptions & Scope:

  • Conceptual Preview: This section provides a conceptual transition bridge. Detailed mathematical formulations of crossover operators (single-point, two-point, uniform) and selection schemes (roulette wheel, rank-based) are fully developed in subsequent lectures.
  • Representation Dependency: The effectiveness of GA crossover depends heavily on whether building blocks (schemata) in the chromosome encoding correspond to meaningful partial solutions.

Pitfalls to Avoid:

  • Equating Beam Search with Genetic Algorithms: Assuming Beam Search is a Genetic Algorithm. Beam Search lacks crossover; its \(K\) threads never exchange parts of their state vectors.
  • Over-mutating Offspring: Setting mutation probability \(p_m\) too high, which destroys beneficial genetic structures and degrades GA into blind random search.

Key Takeaway: Population-based evolutionary algorithms mark the transition from independent multi-thread local search to collaborative, recombination-driven optimization.

Real-world domain connection: Genetic Algorithms (GA) mimic biological natural selection and are widely used in Neural Architecture Search (NAS), antenna design, and financial trading strategy optimization, while Ant Colony Optimization (ACO) mimics the collective foraging behavior of ants depositing pheromone trails to solve routing and Traveling Salesperson problems.

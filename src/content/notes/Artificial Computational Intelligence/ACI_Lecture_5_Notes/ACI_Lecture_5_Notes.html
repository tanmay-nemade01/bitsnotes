Local Search and Introduction to Evolutionary Algorithms

📅 Published: June 2, 2026
🎓 Level: postgraduate
👥 Audience: Postgraduate students studying optimisation-style search where the goal state matters more than the path, including hill climbing and evolutionary methods.

Lecture Summary

This lecture shifts from path-finding search to local search and optimisation, where the solution is a state configuration rather than a sequence of actions. Only the final result matters — not how you got there.

Local search maintains a current state, generates neighbours, and moves to improving ones. Hill climbing (steepest ascent) picks the best neighbour each step — simple but prone to getting stuck at local optima. Stochastic hill climbing adds randomness to escape plateaus. Beam search runs k parallel hill-climbing threads that share fitness information to focus on promising regions, trading coverage for memory.

Fitness functions evaluate state quality (e.g., counting queen conflicts in N-Queens or timetabling penalties). The critical distinction between local and global optima is illustrated: standard hill climbing only guarantees local optimality. Mitigations include random-restart hill climbing (try from many starting points) and simulated annealing (accept worse moves with decreasing probability to escape peaks).

The lecture introduces genetic algorithms as a population-based search method using selection, crossover, and mutation for broader exploration. Real-world applications span VLSI layout, scheduling, and constraint satisfaction. This completes the classical search arc before the course moves to knowledge-based and probabilistic reasoning.

Key Learning Objectives

  • Contrast path-search and local-search formulations of problem solving.
  • Implement hill climbing, stochastic hill climbing, and beam search on state optimisation problems.
  • Define fitness functions and distinguish local from global optima.
  • Explain limitations of greedy local improvement and mitigations like random restart and simulated annealing.
  • Outline genetic algorithm components (population, selection, crossover, mutation) as evolutionary search.

At a Glance

  • In local search, the state itself is the solution; the path to the goal is irrelevant.
  • The fitness function evaluates how good a state is (analogous to heuristics, but computed after receiving a state).
  • Hill climbing generates neighbours (via 1NN) and moves to a better neighbour; it may settle at a local optimum.
  • Stochastic hill climbing uses probabilities derived from fitness values to select the next state.
  • Beam search runs K hill-climbing threads in parallel, stopping when any thread reaches the global optimum.
  • Local search algorithms do not guarantee a global optimum; they return a local optimum.

1. Course Recap: Search Foundations

Before introducing local search, we consolidate the concepts covered in the first quarter of this course.

5.1 The PEAS Framework and Problem Formulation

Every rational agent can be described by its PEAS specification:

  • Performance measure — how success is quantified.
  • Environment — the context in which the agent operates.
  • Actuators — what the agent uses to act upon the environment.
  • Sensors — what the agent uses to perceive the environment.

Environments can be classified along several axes: deterministic vs. stochastic, static vs. dynamic, discrete vs. continuous, and so on. Agent architectures range from simple-reflex to goal-based and utility-based.

5.2 Problem-Solving Agents (PSA)

A Problem-Solving Agent formulates a task as a search problem with five components:

  1. Initial state
  2. Goal state (or goal test)
  3. Transition model (successor function)
  4. Cost function (path cost)
  5. State space

Problems such as Tic-Tac-Toe and the 8-puzzle were modelled this way.

5.3 Uninformed and Informed Search

  • Uninformed (blind) search: BFS, DFS, uniform-cost search, iterative deepening, iterative lengthening. No domain knowledge beyond the problem definition.
  • Informed (heuristic) search: Uses a heuristic function h(n) that estimates the cost from node n to the goal. Heuristics traditionally came from subject-matter experts (SMEs) or were derived via pattern databases and learning. Key properties: admissibility (h(n) never overestimates the true cost) and consistency (the triangle inequality holds).

5.4 The Two Approaches: Path vs. State

In all the search techniques covered so far, the path to the goal is the solution. The journey — the sequence of states from initial to goal, along with its cost — is what we seek. Local search fundamentally changes this viewpoint.

2. Local Search and Optimization Problems

5.5 Philosophy: The State Itself Is the Solution

Core Distinction: In local search, a state itself is a solution to the problem. We are not interested in how we arrived at that state — the path is irrelevant. What matters is whether the configuration satisfies the constraints and, among many candidate configurations, which one is optimal.

Analogy. In path-based search, we are like an explorer charting a route from city A to city B: the itinerary is the answer. In local search, we are like a judge examining a completed chessboard: we care only about whether the queens are placed correctly, not about the order in which they were placed.

5.6 Why Use Local Search?

  • Very low memory: We keep track of only the current state (and perhaps a small set of neighbours), not an entire search tree.
  • Reasonable solutions in large/infinite spaces: Where systematic tree search is infeasible, local search can often find acceptable configurations quickly.
  • Pure optimization problems: Many problems are naturally framed as "find the best configuration" rather than "find a path to a configuration."

However, local search algorithms are not systematic — they might never explore a portion of the search space where a solution actually resides. They sample the neighbourhood rather than exhaustively searching the state space.

5.7 Local vs. Global Optimum

State-Space Landscape: Every state has an "elevation" defined by the objective function. If elevation = objective value, we seek the global maximum (hill climbing). If elevation = cost, we seek the global minimum (gradient descent). The shape of this landscape — the distribution of peaks, ridges, and plateaus — determines how difficult the search problem is.
Definition 1 (Global Optimum). The global optimum is the best solution across the entire state space — the maximum (or minimum) possible fitness value.
Definition 2 (Local Optimum). A local optimum is a solution that is better than all its immediate neighbours, but not necessarily the best in the whole space.

Local search algorithms do not guarantee reaching the global optimum. They typically converge to a local optimum and return it as their answer.

Exam Tip / Common Pitfall: Hill climbing and beam search do not guarantee the global optimum. In an exam, if asked whether these algorithms always find the best solution, the correct answer is no. They are local search methods that may settle at a local maximum/minimum.
Why Hill Climbing Gets Stuck — Three Landscape Features:
  • Local maxima: A peak higher than each neighbour but lower than the global maximum. The algorithm reaches the vicinity and cannot find any uphill move.
  • Ridges: A sequence of local maxima that are not directly connected. From each, all available actions point downhill, so greedy algorithms cannot navigate along the ridge.
  • Plateaus: A flat area where neighbours have equal fitness. This can be a flat local maximum (no uphill exit) or a shoulder (progress is still possible beyond the flat region). Hill climbing wanders aimlessly on a plateau.

For the 8-Queens problem, steepest-ascent hill climbing solves only about 14% of randomly generated instances. It works quickly when successful (average 4 steps) but gets stuck 86% of the time. A sideways move — allowing the algorithm to move to a neighbour with equal fitness — raises the success rate to 94%, though at the cost of more steps (average 21 for success, 64 for failure). Sideways moves must be limited (e.g., 100 consecutive) to prevent infinite wandering on flat local maxima.

5.8 Single-Instance vs. Population-Based Methods

Local search techniques fall into two categories:

  1. Single-instance based — operate on one current state at a time:
    • Hill climbing (and its variants)
    • Local beam search
  2. Population-based — maintain and evolve a set of states:
    • Genetic algorithms
    • Ant colony optimization (ACO)
[Added for clarity: In this course offering, the single-instance algorithms covered are hill climbing (with variants) and local beam search. Population-based algorithms covered are genetic algorithms and ACO. Simulated annealing and particle swarm optimization are not part of this syllabus.]

3. Fitness Functions and Problem Representation

5.9 Fitness Value vs. Heuristic Value

Fitness Function: The fitness function (denoted F(n) or H(n)) evaluates how good a given state is. Unlike a heuristic, which is supplied before solving the problem (by an SME or derived from pattern databases), the fitness function is computed on the fly once a state is presented.
  • The fitness function is chosen by the domain designer.
  • It can be framed as either a maximization problem (higher F(n) is better) or a minimization problem (lower F(n) is better), depending on the definition.
  • For the n-Queens problem, two common fitness definitions are:
    1. Number of non-conflicting pairs (goal: maximize to C(n,2)).
    2. Number of conflicting pairs (goal: minimize to 0).

5.10 Representing the n-Queens State

For an n × n board with one queen per column, we use a complete-state formulation: every state has all the components of a solution (all n queens placed), but they may not be in the right positions. A state can be represented as a vector of length n:

V = (v1, v2, v3, …, vn)

where vi ∈ {1, 2, …, n} denotes the row in which the queen of column i is placed.

Example 1 (4-Queens representation). The vector (2, 4, 2, 2) means:
  • Column 1: queen in row 2.
  • Column 2: queen in row 4.
  • Column 3: queen in row 2.
  • Column 4: queen in row 2.

5.11 The 1NN Neighbourhood Expansion

The term 1NN (one neighbouring region expansion) means: from the current state, we generate all states reachable by moving exactly one queen (one variable change). It is not related to the k-NN algorithm in machine learning.

1NN Expansion for n-Queens: For a state vector V = (v1, …, vn), each vi can be moved to any of the other (n − 1) rows while keeping all other queens fixed. Thus:

Number of neighbours = n × (n − 1)

For n = 4, this yields 4 × 3 = 12 neighbours.
Example 2 (Generating neighbours from (2, 4, 2, 2)). Fix v2, v3, v4 and vary only v1. The queen in column 1 is currently in row 2. It can move to rows 1, 3, or 4, yielding three configurations:

(1, 4, 2, 2), (3, 4, 2, 2), (4, 4, 2, 2)

Repeating for v2, v3, v4 gives a total of 3 × 4 = 12 neighbours.
[Added for clarity: Higher-order expansions exist (2NN, 3NN, …, nNN), where multiple queens can move simultaneously. 2NN for 4-Queens yields 54 neighbours. In this course, we always use 1NN.]

5.12 Calculating the Fitness for 4-Queens

Given a configuration, enumerate all C(4,2) = 6 queen pairs: (Q1, Q2), (Q1, Q3), (Q1, Q4), (Q2, Q3), (Q2, Q4), (Q3, Q4). Two queens conflict if they share the same row or the same diagonal. Otherwise they are non-conflicting.

Example 3 (Fitness of (2, 4, 2, 2)). Let the fitness F be the number of non-conflicting pairs.
  • Q1 (row 2) and Q2 (row 4): not same row, not same diagonal ⇒ non-conflicting.
  • Q1 and Q3 (both row 2): same row ⇒ conflicting.
  • Q1 and Q4 (both row 2): conflicting.
  • Q2 and Q3: non-conflicting.
  • Q2 and Q4: same diagonal ⇒ conflicting.
  • Q3 and Q4: same row ⇒ conflicting.
Hence F = 2 (only the first and fourth pairs are non-conflicting).
The global optimum for this fitness definition is F = 6 (no conflicts; all six pairs non-conflicting).

4. Hill Climbing

5.13 Basic Hill Climbing Algorithm

Hill climbing is the simplest local search algorithm. It repeatedly moves to the best neighbour until no neighbour is better than the current state. It is sometimes called greedy local search because it grabs a good neighbour state without thinking ahead about where to go next.

Hill Climbing — Step-by-Step:
  1. Select a random state as the initial current state.
  2. Evaluate its fitness F(current).
  3. Generate all successors (neighbours) via 1NN.
  4. Evaluate the fitness of every successor.
  5. If any successor has a better fitness than the current state, select it (or the best among them) as the new current state and go to step 3.
  6. If no successor is better, stop and return the current state as the solution (a local optimum).
Example 4 (Hill climbing that stalls). Start with (2, 4, 2, 2), whose fitness F = 2 (using non-conflicting pairs; correction: F = 2 not 4 as originally in slides). Generate all 12 neighbours. Suppose none of them has F > 2. The algorithm stops and returns this state with F = 2 as its answer — a local optimum, because the global optimum is F = 6.
Exam Tip / Common Pitfall: In path-based search, every intermediate node is a "partial solution"; we keep building until we reach the goal. In local search, every valid state is already a complete solution. The algorithm merely tries to improve it. This is a key conceptual shift.

5.14 Hill Climbing with Random Restart

If one run of hill climbing gets stuck at a local optimum, we can restart from a new random state and try again.

Hill Climbing with Random Restart:
  1. Run basic hill climbing from a random initial state.
  2. If the global optimum is found, stop.
  3. If stuck at a local optimum, pick a new random state (not a neighbour of the previous state) and repeat from step 1.
  4. Continue up to K restarts (a predefined limit). If K is exhausted without finding the global optimum, return the best solution found so far.
  • When K = 1, this reduces to basic hill climbing (one attempt only).
  • The choice of K is domain-dependent; it should not be too small (insufficient exploration) or too large (wasteful computation).
  • Completeness: Random-restart hill climbing is complete with probability 1 (it eventually generates a goal state as the initial state and trivially terminates). If each hill-climbing run has success probability p, the expected number of restarts needed is 1/p. For 8-Queens without sideways moves (p ≈ 0.14), roughly 7 iterations are needed on average.

5.15 Stochastic Hill Climbing

Instead of always picking the absolute best neighbour (or restarting randomly), stochastic hill climbing selects a neighbour probabilistically, favouring those with higher fitness.

Stochastic Hill Climbing — Probability Calculation:
  1. Generate all 12 neighbours and compute their fitness values.
  2. Identify the distinct fitness values present among the neighbours.
  3. Count the frequency of each distinct fitness value: how many neighbour configurations have that fitness.
  4. Compute the probability of selecting a successor with fitness f:

    P(f) = frequency of f / total number of neighbours

  5. Select the next state based on the highest probability. If multiple fitness values share the highest probability, pick one at random among them.
  6. Repeat from the newly selected state.
Example 5 (Probability table for stochastic hill climbing). Suppose the 12 neighbours of some state have fitness counts: F = 1 appears in 2 configurations, F = 2 in 5, F = 3 in 4, and F = 4 in 1. Then:

P(1) = 2/12 ≈ 0.17,   P(2) = 5/12 ≈ 0.42,   P(3) = 4/12 ≈ 0.33,   P(4) = 1/12 ≈ 0.08

The highest probability is 0.42 (for F = 2). The algorithm selects one of the five configurations with fitness 2.
Q&A. Why use probability instead of just picking the maximum fitness? In rugged search landscapes, the maximum may be a misleading local peak. A probabilistic approach gives lower-fitness neighbours a chance, potentially escaping plateaus or shallow local optima.

5.16 Termination Conditions (Summary)

A hill climbing run can terminate under any of these conditions:

  1. Global optimum reached: Fitness equals the known best possible value.
  2. No improving successor: All neighbours have fitness ≤ (or ≥, for minimization) the current state.
  3. Predefined restart limit K exhausted (random-restart variant).

5.17 First-Choice Hill Climbing

First-choice hill climbing is a practical variant for problems where each state has many successors (e.g., thousands). Instead of evaluating all neighbours, it generates successors randomly until one is found that is better than the current state. This is more efficient than generating and evaluating every neighbour when the branching factor is large.

5. Local Beam Search

5.18 Motivation: Parallelism

All hill climbing variants operate on a single current state. Beam search generalizes this by maintaining K states simultaneously, running hill climbing on each in parallel.

5.19 Algorithm

Local Beam Search:
  1. Select K random states as the initial beam.
  2. For each of the K states in parallel:
    1. Evaluate its fitness.
    2. Generate all neighbours (via 1NN).
    3. Evaluate fitness of all neighbours.
  3. If any state has reached the global optimum, stop all threads and return that state.
  4. If the goal is not found, select the next K states (one per thread) and repeat from step 2.
  5. If no improving successors exist for any thread, stop and return the best found.

5.20 Key Properties

  • Cooperation among threads: Unlike random-restart hill climbing (where K searches run independently), local beam search passes useful information among the parallel threads. The states that generate the best successors effectively direct the search — the algorithm abandons unfruitful searches and moves resources toward the most promising regions.
  • Lack of diversity: A potential problem is that the K states can become clustered in a small region of the state space, making the search little more than a K-times-slower version of hill climbing. Stochastic beam search (selecting successors with probability proportional to their value rather than always choosing the top K) helps alleviate this by increasing diversity.
  • K = 1 reduces to hill climbing: With a single thread, beam search is identical to basic (or stochastic) hill climbing.
  • Each thread can use a different variant: One thread may use basic hill climbing, another stochastic, another random restart. This flexibility increases the chance of finding the global optimum.
  • Stochastic beam search: When probability-based selection (as in stochastic hill climbing) is used within each thread, it is termed stochastic beam search. For K = 1, stochastic beam search reduces to stochastic hill climbing.
Exam Tip / Common Pitfall: Beam search does not guarantee the global optimum either. It only increases the likelihood by exploring multiple starting points in parallel. In an exam, do not claim that beam search is globally optimal.
Q&A. Is beam search slower than hill climbing? Not necessarily. Because the K threads run in parallel (e.g., on a multi-core system or distributed framework like Hadoop), the wall-clock time may be comparable to a single hill-climbing run while exploring K times more of the space.
Q&A. How is K chosen? K is selected based on domain expertise, empirical evidence, or problem constraints. It should not be 1 (degenerates to hill climbing) or excessively large (computationally prohibitive). In assignments and exams, K will typically be provided.

6. Introduction to Evolutionary Algorithms

The lecture concluded with a brief introduction to population-based methods, which will be covered in depth in the next session.

5.21 Genetic Algorithms (Preview)

Unlike beam search, where threads share information through a global selection pool, genetic algorithms involve collaboration via sexual reproduction among candidate solutions:

  1. Represent individuals: Encode candidate solutions as strings over a finite alphabet (often Boolean). For n-Queens, a digit string like 32752411 where c-th digit is the row of the queen in column c.
  2. Initial population: Generate a set of random states (analogous to the initial random state in hill climbing).
  3. Fitness evaluation: Compute fitness for every individual in the population. For 8-Queens with non-attacking pairs, the maximum is C(8,2) = 28.
  4. Selection: Choose "parent" individuals with probability proportional to their fitness. Alternatively, randomly select n individuals (n > ρ) and keep the ρ fittest as parents, where ρ is the mixing number (typically ρ = 2 for sexual reproduction).
  5. Crossover: Randomly choose a crossover point, split each parent string, and recombine the parts to form children. For example, parents 32752411 and 24748552 with crossover at position 3 produce 32748552 and 24752411.
  6. Mutation: With a small independent probability, flip each bit/position in the offspring. For n-Queens, this corresponds to moving a queen to a random row in its column.
  7. Replace the population and iterate until convergence. Elitism (retaining a few top-scoring individuals from the previous generation) guarantees that overall fitness never decreases over time.
Schema Theory: A schema is a substring with some positions left unspecified (e.g., 246***** describes all 8-Queens states where columns 1–3 are fixed to rows 2, 4, 6). If the average fitness of instances matching a schema is above the population mean, the number of instances of that schema grows over time. Genetic algorithms work best when schemas correspond to meaningful components of a solution — useful blocks that can be combined across individuals. This is why crossover (sexual reproduction) conveys an advantage over asexual reproduction (mutation-only).
[Added for clarity: Genetic algorithms are inspired by biological evolution (natural selection, crossover, mutation). Ant colony optimization (ACO), also to be covered, is inspired by how ants find shortest paths via pheromone trails.]

5.22 Contrast: Beam Search vs. Genetic Algorithms

Beam Search Genetic Algorithms
K threads share fitness information to direct search toward promising regions Population members collaborate via sexual reproduction (crossover)
No crossover; each thread generates successors from a single parent (asexual) Crossover combines parents' genetic material from two individuals
Selection: keep K best among all successors globally Selection: choose parents proportional to fitness; can use elitism
No mutation operator Mutation introduces diversity via random bit flips

7. Key Terms / Glossary

Local Search
A family of optimization algorithms where any valid state is treated as a complete solution; the algorithm attempts to improve it by examining neighbours.
Fitness Function (F(n) or H(n))
A function that evaluates the quality of a state. Defined by the domain designer and computed on a given state (unlike a heuristic, which is pre-supplied).
Global Optimum
The best possible solution in the entire state space.
Local Optimum
A solution that is better than all its immediate neighbours but not necessarily the global best.
1NN (One Neighbouring Region Expansion)
Generating all states reachable by changing exactly one variable (moving one queen, in the n-Queens problem).
Neighbour / Successor
A state reachable from the current state by a single move (one variable change in 1NN).
Hill Climbing
A local search that repeatedly moves to the best neighbour; stops when no neighbour is better.
Hill Climbing with Random Restart
Hill climbing that, upon getting stuck at a local optimum, restarts from a new random state (up to K attempts).
Stochastic Hill Climbing
Hill climbing that selects the next state probabilistically, based on fitness values of neighbours.
Beam Search
Parallel execution of K independent hill-climbing threads. If any thread finds the global optimum, all stop.
Stochastic Beam Search
Beam search where each thread uses stochastic (probability-based) selection.
Population-Based Search
Optimization methods that maintain and evolve a set of candidate solutions (e.g., genetic algorithms, ACO).
Genetic Algorithm
A population-based method using selection, crossover, and mutation, inspired by biological evolution.
Ant Colony Optimization (ACO)
A population-based method inspired by ant foraging behaviour using pheromone trails.

9. One-Page Summary / Cheat Sheet

5.23 Core Philosophy

  • Path-based search: The path (sequence of states) is the solution.
  • Local search: Every valid state is a solution; we improve it via neighbours.

5.24 Fitness Function

F(state) = quality measure (maximize or minimize)
For n-Queens with non-conflicting pairs: goal is F = C(n, 2).

5.25 Neighbourhood (1NN)

Number of neighbours = n(n − 1) (for n-Queens)

5.26 Hill Climbing Variants

Variant When stuck at local optimum
Basic Stops
Random restart Pick new random state; repeat up to K times
Stochastic Select neighbour probabilistically: P(f) = freq(f) / total

5.27 Beam Search

  • K parallel hill-climbing threads that share fitness information.
  • K = 1 ⇒ hill climbing.
  • Generates all successors of all K states, selects K best overall.

5.28 Termination Conditions

  1. Global optimum reached.
  2. No neighbour has better fitness.
  3. Restart limit K exhausted.
Key Fact: None of the local search algorithms (hill climbing, beam search) guarantee finding the global optimum. They return a local optimum.

Test Your Knowledge

Q: In local search, what is the primary object being optimised?

Explanation: Local search algorithms iterate over states, improving fitness (e.g., fewer queen conflicts). The path taken between states is irrelevant — only the quality of the current configuration matters.

Q: Why does standard hill climbing fail on some landscapes?

Explanation: Hill climbing moves only to strictly better neighbours. At a local optimum, every neighbour is worse or equal, so search halts even if better global states exist elsewhere.

Q: Beam search with k threads is best described as:

Explanation: Beam search tracks k active states, each performing local improvement, and typically keeps the k highest-fitness states globally — balancing exploration across regions of the state space.

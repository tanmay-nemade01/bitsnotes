9.2 Knowledge-Based Agents

Hook: Every agent you have built so far — the maze solver, the 8-puzzle player, the tic-tac-toe opponent — was born knowing exactly what it needed. But a real agent wakes up in a world it does not fully understand. It must *learn* facts from what it sees, *store* them somewhere, and *combine* them to figure out what it has never been told. That somewhere is the knowledge base.

9.2.1 Definition and Core Idea

A *knowledge-based agent* is an agent that maintains an internal store of facts about its world — a *knowledge base* (KB) — and uses logical reasoning to decide what to do. It does not just react. It does not just follow a pre-programmed plan. It *infers*.

Think of the agent taxonomy from earlier: reflex agents map percepts directly to actions. Model-based agents track internal state. Goal-based agents reason about desired outcomes. Utility-based agents maximize a happiness score. A knowledge-based agent is not a separate category in that list — it is the *engine underneath* all of them. Every non-trivial agent needs to store what it knows and derive new facts from old ones.

Intuition — The Detective Analogy: A detective arrives at a crime scene. She does not know who did it. She collects clues (percepts), writes them in her notebook (TELL), flips back through her notes to connect them (ASK), and when she infers a new suspect, she writes that down too (UPDATE). Her notebook is the KB. Her reasoning process — combining "the butler was in the kitchen" with "the kitchen door was locked from inside" to conclude "the butler could not have left" — is inference. The detective never saw the butler not leave. She *derived* it.

9.2.2 Knowledge Base (KB)

A *knowledge base* (KB) is a set of *sentences* expressed in a formal *knowledge representation language*. Each sentence is a statement about the world that can be evaluated as true or false. Sentences accepted without derivation are called *axioms*. Sentences derived from axioms are called *theorems*.

The KB is not a passive data dump. It is a living, growing collection. Every cycle of the agent's life involves exactly three operations:

OperationWhat it doesReal-world parallel
TELLAdd a new percept or fact to the KB"I see a breeze at [2,1]"
ASKQuery the KB: "What should I do?" or "Is [2,2] safe?""Given everything I know, is it safe to move up?"
UPDATERecord newly inferred knowledge into the KB"I have concluded there is a pit at [3,1]"

This TELL-ASK-UPDATE loop is the same pattern that powers every modern AI system. When ChatGPT answers your question, it is ASKing a KB built from its training data. When a RAG (Retrieval-Augmented Generation) system fetches documents before answering, it is TELLing the KB about those documents first. When a self-driving car updates its map after seeing a new road sign, it is running UPDATE. The vocabulary changes — "vector database," "context window," "fine-tuning" — but the three operations are identical.

An *axiom* is a sentence the agent accepts without proof. It may be a direct percept ("I feel a breeze") or a background rule of the world ("a breeze always means a pit is adjacent"). Axioms are the foundation; everything else is built on top of them by inference.

9.2.3 Prolog — A Logic Programming Language

Prolog (from "Programming in Logic") is a language purpose-built for knowledge-based agents. Unlike Python or Java — where you would need to write loops, data structures, and inference code from scratch — Prolog lets you declare facts and rules directly, then ASK questions. Prolog's engine handles the inference.

What Prolog does natively that a general-purpose language does not:

  • You state: pit_adjacent(X) :- breeze(X). ("X is pit-adjacent if there is breeze at X")
  • You query: ?- pit_adjacent([3,1]). ("Is [3,1] pit-adjacent?")
  • Prolog answers true. or false. by running logical inference automatically.

A webinar will introduce Prolog syntax, and assignments will use it. If you want to get ahead, install SWI-Prolog (free, open-source) and try encoding a few Wumpus World rules.

A knowledge-based agent is defined by its KB — a set of sentences it can TELL, ASK, and UPDATE. This three-operation loop is the universal pattern of intelligent systems, from 1970s expert systems to today's LLM-based agents. The rest of this lecture shows you how to build the reasoning engine that makes ASK actually *work*.

Real-World & Domain Connection: Expert systems — one of AI's first commercial successes — are pure knowledge-based agents. MYCIN (1976) diagnosed bacterial infections using a KB of ~600 rules. It outperformed junior doctors. Modern descendants include IBM Watson (which used a KB-derived approach for Jeopardy!) and the rule engines inside every credit card fraud detection system. The TELL/ASK/UPDATE loop you are learning here is not a toy — it runs production systems that approve your transactions and flag suspicious ones, every second of every day.

9.3 The Wumpus World

Hook: You are standing in a dark cave. You cannot see beyond the room you are in. Somewhere in the darkness, a monster waits. Somewhere else, pits open into nothing. And somewhere, gold glitters. You have no map. You have only your senses — a whiff of something foul, a draft of cold air, a faint sparkle. Can you find the gold without dying? Can you do it by *thinking* rather than by trial and (fatal) error?

9.3.1 Problem Description

The *Wumpus World* is a 4×4 grid-world designed to test whether an agent can reason logically under partial information. The agent starts knowing almost nothing. It must deduce the hidden layout — where the danger is, where the reward is — from indirect sensory clues.

The grid contains exactly four types of things:

ElementCountBehavior
Agent1Starts at cell [1,1], facing east
WumpusExactly 1A monster. Enter its cell → agent is eaten. Does not move.
PitMultiple (≥0)Bottomless holes. Enter a pit cell → agent falls and dies.
GoldExactly 1The prize. Grab it, return to [1,1], climb out → win.

All elements are static throughout the game. Only their initial placement varies across problem instances. The wumpus and gold never share a cell — otherwise the problem would be unsolvable.

Intuition — The Blindfolded Miner: Imagine you are blindfolded in a mine. You can feel a cold draft when you are near a shaft (pit → breeze). You can smell gas when you are near a leak (wumpus → stench). You cannot see the shaft or the leak directly. But by moving carefully and noting where you feel and smell things, you can *deduce* their exact locations. You do this without ever falling in or breathing the gas. That is exactly what the Wumpus agent does.

9.3.2 Percepts (Sensory Information)

The agent has five senses. Each is a single bit — present or absent:

PerceptTriggerRangeWhat it tells you
StenchWumpus in an adjacent cell4-neighborhood"The wumpus is next to me"
BreezePit in an adjacent cell4-neighborhood"A pit is next to me"
GlitterGold in the same cellSame cell only"The gold is right here"
BumpAgent walks into a wallOn contact"I hit a wall"
ScreamWumpus killed by arrowEntire cave"The wumpus just died"

Key properties of the sensor model:

  • No false positives. If you smell a stench, there is definitely a wumpus next to you.
  • No false negatives. If a wumpus is next to you, you will definitely smell it.
  • Percepts are *local* — you only sense your immediate neighbors (except Glitter and Scream).

A percept at any moment is a 5-tuple:

\[[\text{Stench?}, \text{Breeze?}, \text{Glitter?}, \text{Bump?}, \text{Scream?}]\]

At the start cell [1,1], the agent typically perceives [None, None, None, None, None] — the calm before the reasoning begins.

9.3.3 PEAS Specification

The PEAS framework (Performance, Environment, Actuators, Sensors) formalizes the Wumpus World as an AI task:

Performance measure (the score):

EventPoints
Grab the gold and climb out+1000
Die (pit or wumpus)−1000
Each action taken−1
Use the arrow (if applicable)−10

The −1 per action creates pressure to be efficient — wandering aimlessly costs points.

Environment:

  • 4×4 grid surrounded by walls. Coordinates: [1,1] is bottom-left, [4,4] is top-right.
  • Agent starts at [1,1], facing east (right).
  • Pit locations: each non-start square has probability 0.2 of being a pit (per the textbook; the professor's version may vary the configuration).
  • Wumpus and gold locations: chosen uniformly from the non-start squares.

Actuators (what the agent can do):

ActionEffect
Move ForwardStep one cell in the facing direction. If it is a wall → Bump, no movement.
Turn LeftRotate 90° counterclockwise.
Turn RightRotate 90° clockwise.
GrabPick up gold if present in the current cell.
ShootFire the single arrow in the facing direction (one use only).
ClimbExit the cave — only works at [1,1].

Sensors: Five binary detectors as described in §9.3.2.

9.3.4 Environment Characteristics

PropertyClassificationWhy
ObservabilityPartially observableThe agent only sees its current cell. It must infer the rest.
DeterminismDeterministicOutcomes are exact — no randomness in movement or perception.
Episodic vs SequentialSequentialEach move changes what the agent can perceive next. Actions are linked across time.
Static vs DynamicStaticNothing moves during the game.

Scope: The Wumpus World is partially observable but deterministic. This combination is rare in the real world — most partially observable environments are also stochastic. The Wumpus World isolates *logical* reasoning so you can learn it without also wrestling with probability. Probability enters in later modules (Bayesian networks, probabilistic reasoning over time).

9.3.5 The Arrow (Optional Variant)

The agent carries exactly one arrow. Shooting it into the wumpus's cell kills the wumpus (global Scream confirms it). Shooting anywhere else wastes it. This variant adds risk/reward tradeoffs but is not needed for the core logical reasoning examples — the agent can solve most configurations without the arrow.

9.3.6 Goal

The Wumpus World is not a pathfinding problem. It is a *discovery* problem. The agent's job is:

  1. Deduce where the wumpus, pits, and gold are — using only indirect percepts.
  2. Navigate a safe path to the gold and back to [1,1].

The "deduce" step is the whole point. A human solving the Wumpus World without logic would guess and die. An agent using logic can *prove* a cell is safe before ever stepping into it.

The Wumpus World is the canonical testbed for logical agents. Its rules are simple, but solving it requires exactly the skill this module teaches: deriving certain conclusions from indirect evidence. If you can build an agent that safely navigates the Wumpus World, you understand knowledge-based reasoning.

Real-World & Domain Connection: The Wumpus World is a simplified model of any exploration-under-uncertainty problem. Consider a Mars rover sensing terrain hazards, a submarine mapping obstacles with sonar, or a cybersecurity system inferring intrusions from network signals. All face the same core challenge: deduce hidden dangers from partial, local observations. The logical inference techniques you learn here are the foundation for all of them.

9.4 Logical Rules of the Wumpus World

Hook: You feel a cold draft in your cell. Somewhere next to you, a pit opens into blackness. But which direction? You cannot see it. You have to *think* your way to the answer. The rules that let you do that are just four lines of symbols — but they are the sharpest tool the agent has.

9.4.1 Symbol Definitions

These symbols are the alphabet of the Wumpus World. Every logical sentence the agent writes uses them:

SymbolMeaning
\(A\)Agent
\(B\)Breeze
\(G\)Glitter (or Gold)
\(OK\)Safe state (no danger in or adjacent to this cell)
\(P\)Pit
\(S\)Stench
\(V\)Visited
\(W\)Wumpus

Intuition — The Map Legend: Think of these symbols as the legend on a map. \(P\) is the "pit here" marker. \(B\) is the "wind here" marker. Once you know the legend, you can read any map — and once you know these symbols, you can encode any Wumpus World configuration as logical sentences.

9.4.2 Pit Rules

The relationship between pits and breeze is a two-way logical implication, but the direction matters. From cause to effect, you use AND. From effect to cause, you use OR.

Rule 1 — Cause → Effect (AND): If a pit exists at \((x,y)\), then breeze exists in every adjacent cell.

\[P(x,y) \rightarrow B(x+1,y) \land B(x-1,y) \land B(x,y+1) \land B(x,y-1)\]

Why AND? Because one pit *guarantees* breeze in *all four* neighbors. Not "some." Not "most." All of them. If even one neighbor lacks breeze, the pit cannot be at \((x,y)\).

Rule 2 — Effect → Cause (OR): If breeze exists at \((x,y)\), then a pit exists in at least one adjacent cell.

\[B(x,y) \rightarrow P(x+1,y) \lor P(x-1,y) \lor P(x,y+1) \lor P(x,y-1)\]

Why OR? Because feeling a breeze only tells you that *at least one* neighbor is a pit. It could be one. It could be two. It could be all four. You do not know which — only that the set of neighboring pits is non-empty.

Pitfall: Do not confuse the two directions. The most common mistake is using AND where OR belongs (or vice versa). Remember: when you *have* the pit → AND every neighbor gets breeze. When you *feel* the breeze → OR (at least one neighbor is a pit).

9.4.3 Wumpus Rules

The wumpus rules mirror the pit rules exactly, with \(W\) replacing \(P\) and \(S\) replacing \(B\):

Rule 3 — Cause → Effect (AND):

\[W(x,y) \rightarrow S(x+1,y) \land S(x-1,y) \land S(x,y+1) \land S(x,y-1)\]

Rule 4 — Effect → Cause (OR):

\[S(x,y) \rightarrow W(x+1,y) \lor W(x-1,y) \lor W(x,y+1) \lor W(x,y-1)\]

Because there is exactly one wumpus, the OR in Rule 4 becomes especially powerful: exactly one of those four disjuncts can be true. Combined with other observations, this uniqueness often pins down the wumpus's location.

9.4.4 Negation Rules (Equally Powerful)

The *absence* of a percept is just as informative as its presence — perhaps more so. When you feel nothing, you can *prove* the absence of danger.

Negated Stench Rule: If there is no stench at \((x,y)\), then the wumpus is in *none* of the adjacent cells.

\[\neg S(x,y) \rightarrow \neg W(x+1,y) \land \neg W(x-1,y) \land \neg W(x,y+1) \land \neg W(x,y-1)\]

This is the contrapositive of Rule 3 + Rule 4 combined, but more directly: negate the OR and you get a negated AND. Not smelling anything gives you *four certain negatives* — four cells you know are safe from the wumpus.

Negated Breeze Rule:

\[\neg B(x,y) \rightarrow \neg P(x+1,y) \land \neg P(x-1,y) \land \neg P(x,y+1) \land \neg P(x,y-1)\]

These negation rules are what make the Wumpus World solvable at all. The agent starts at [1,1] with no stench and no breeze. Applying the negation rules, it immediately proves that [2,1] and [1,2] are safe — without ever visiting them. Every subsequent deduction in the worked examples traces back to these negation rules. They are the engine of logical certainty in this world.

Visual Intuition: Picture the agent at the center of a plus sign (+). If the agent's cell is calm (no stench, no breeze), all four arms of the plus sign are certified safe. If there is a stench, exactly one arm points toward the wumpus — you just do not know which one yet. The negation rules draw green (safe) and red (danger) on the arms of the plus sign, and the agent navigates by steering toward green.

Four rules govern the entire Wumpus World: two for pits (AND forward, OR backward), two for wumpuses (same pattern). Their negations are equally powerful. Mastering when to use AND vs. OR — and when to use the negation — is the core skill of logical reasoning in this domain.

Real-World & Domain Connection: The pattern "cause guarantees effect in all directions; effect implies cause in some direction" appears everywhere in diagnostic reasoning. A disease (cause) produces symptoms in multiple body systems (AND). Observing a symptom (effect) means the disease could be one of several (OR). A router failure (cause) makes all downstream nodes unreachable (AND). Observing an unreachable node (effect) means the fault is somewhere upstream (OR). This AND/OR duality is the logical backbone of fault diagnosis in networks, medicine, and engineering.

9.5 Worked Example — Wumpus World Configuration 1

Hook: The agent has taken exactly two steps — one up, one back, one right — and from those two moves alone, it has located both the monster and a death trap. It has never seen either one. How? The answer is in the *intersection* of what it smelled and what it did not smell.

9.5.1 Initial State: Cell [1,1]

Step 1 — The agent wakes up at [1,1].

Percept: [None, None, None, None, None] — no stench, no breeze, no glitter.

Apply the negation rules:

From \(\neg S(1,1)\):

  • \(\neg W(2,1)\) — no wumpus above
  • \(\neg W(1,2)\) — no wumpus to the right

From \(\neg B(1,1)\):

  • \(\neg P(2,1)\) — no pit above
  • \(\neg P(1,2)\) — no pit to the right

Directly observed at [1,1]: \(\neg S(1,1)\), \(\neg B(1,1)\), \(\neg G(1,1)\), \(\neg W(1,1)\), \(\neg P(1,1)\).

Conclusion: Cells [2,1] and [1,2] are certified safe. The agent picks [2,1] and moves.

9.5.2 Move to [2,1]

Step 2 — The agent moves up to [2,1].

Percept: [None, Breeze, None, None, None] — breeze detected, no stench.

Apply the breeze → pit rule (OR direction):

\[B(2,1) \rightarrow P(3,1) \lor P(2,2) \lor P(1,1)\]

But \(P(1,1)\) was already proven false at Step 1 (\(\neg P(1,1)\) from the negation rule). So we eliminate it:

\[P(3,1) \lor P(2,2)\]

The agent now knows: *there is a pit in [3,1] or [2,2] (or both)*. Moving to either is risky. The agent backtracks to [1,1].

9.5.3 Backtrack and Move to [1,2]

Step 3 — The agent moves right to [1,2].

Percept: [Stench, None, None, None, None] — stench detected, no breeze.

Apply the stench → wumpus rule (OR direction):

\[S(1,2) \rightarrow W(1,3) \lor W(2,2) \lor W(1,1)\]

\(W(1,1)\) was already proven false (\(\neg W(1,1)\) from Step 1). Eliminate:

\[W(1,3) \lor W(2,2)\]

The agent now has two unknowns:

  • Pit: \(P(3,1) \lor P(2,2)\) (from Step 2)
  • Wumpus: \(W(1,3) \lor W(2,2)\) (from Step 3)

9.5.4 Cross-Elimination — The Key Inference

This is the heart of logical reasoning: combining knowledge gathered at *different times and places* to eliminate possibilities. Neither observation alone was enough. Together, they are decisive.

Wumpus elimination:

Hypothesis: \(W(2,2)\) is true.

If \(W(2,2)\) were true, then by the cause→effect rule (AND direction), stench would be present at [2,1] (because [2,2] is adjacent to [2,1]). But at Step 2, the agent was at [2,1] and perceived *only* breeze — no stench.

So: \(\neg W(2,2)\). (The hypothesis contradicts a recorded fact.)

Since \(W(1,3) \lor W(2,2)\) and we now know \(\neg W(2,2)\), we apply *disjunctive syllogism*:

\[\boxed{W(1,3)} \quad \text{— The wumpus is in [1,3].}\]

Pit elimination:

Hypothesis: \(P(2,2)\) is true.

If \(P(2,2)\) were true, then breeze would be present at [1,2] (because [2,2] is adjacent to [1,2]). But at Step 3, the agent was at [1,2] and perceived *only* stench — no breeze.

So: \(\neg P(2,2)\).

Since \(P(3,1) \lor P(2,2)\) and \(\neg P(2,2)\):

\[\boxed{P(3,1)} \quad \text{— The pit is in [3,1].}\]

9.5.5 Result

Cell [2,2] has been proven safe: no pit (\(\neg P(2,2)\)), no wumpus (\(\neg W(2,2)\)). The agent can now move diagonally to [2,2] and continue exploring toward the gold — having located both dangers without ever stepping into (or even seeing) either one.

With only the knowledge that [1,1] is OK — and two exploratory moves — the agent deduced the exact locations of both the wumpus and a pit. This is *certain* knowledge, not a guess. Logic turned two ambiguous percepts into two precise conclusions.

9.5.6 Student Question — Why Not Go to [1,2] First?

Q: Why did the agent go to [2,1] first instead of [1,2]?

A: Both choices were equally valid from the starting state. The agent had no reason to prefer one over the other. In this configuration, going to [2,1] first and then backtracking provided the necessary cross-elimination data. If the agent had gone to [1,2] first, it would have smelled stench, noted the wumpus disjunction, and backtracked. Then it would go to [2,1], feel breeze, and perform the same cross-elimination — just in the opposite order. The reasoning chain is symmetric; the order does not matter for correctness.

9.6 Worked Example — Wumpus World Configuration 2

Hook: Here is a different board. Same rules. Same agent. But the reasoning plays out a little differently — and that is the point. Logical inference is not a script. It is a skill. The pattern (move, perceive, eliminate, combine) is the same, but the moves adapt to what the agent finds.

9.6.1 Setup

A different Wumpus World configuration. The agent starts in an OK state — no stench, no breeze at [1,1]. The layout of pits, wumpus, and gold is different from Configuration 1, but the agent does not know how. It must discover the layout through the same logical rules.

9.6.2 Step-by-Step Reasoning

Step 1 — Start at OK cell. The agent applies the negation rules at [1,1]. Both adjacent cells (above and right) are certified safe.

Step 2 — Move up. Percept: Breeze detected, no stench.

The breeze tells us: pit is in the cell above, or to the right, or both. (The cell below — [1,1] — is ruled out because the agent came from there and it was OK.)

\[P(\text{above}) \lor P(\text{right})\]

Step 3 — Backtrack, then move right. Percept: Stench detected, no breeze in this cell.

No breeze here is key: it means the cell that was "right" from the upper position *cannot* have a pit. If it did, breeze would be felt here. So:

\[\boxed{P(\text{above})} \quad \text{— Pit location confirmed.}\]

Step 4 — Stench analysis. The stench at the right cell tells us:

\[W(\text{above}) \lor W(\text{right})\]

(The cell below — [1,1] — is already ruled out.)

Step 5 — Cross-check. If the wumpus were at the cell that was "right" from Step 2's upper position, the agent would have smelled stench during Step 2. But Step 2's percept was *only* breeze. So: \(\neg W(\text{that cell})\). The wumpus must be at the other position:

\[\boxed{W(\text{other position})} \quad \text{— Wumpus location confirmed.}\]

Step 6 — Both dangers located. The middle cell is now proven safe (no pit, no wumpus). The agent moves there.

Step 7 — Explore from the safe middle. The new cell is OK (no stench, no breeze). Its unexplored neighbors are certified safe by the negation rules. The agent continues outward.

Step 8 — Find the gold. At the gold cell, the agent may detect both stench and breeze simultaneously — the stench from the already-known wumpus, the breeze from an as-yet-unknown second pit. But the gold is here. The problem is solved. Grab it and return.

The same four rules, applied to a different board, produce a different sequence of deductions — but the underlying logic is identical. Practice with multiple configurations builds the intuition for *which rule to apply when*. The cross-elimination pattern (using the *absence* of a percept at location A to rule out a danger at location B) is the single most powerful move in Wumpus World reasoning.

9.7 What Is Logic?

Hook: The Wumpus World agent started with one fact — "I am at [1,1] and it is safe" — and ended with exact coordinates for a monster and a death pit. It never saw either one. That leap — from one known fact to two unknown facts — is what logic does. It is the machinery of *certainty*.

9.7.1 Definition

*Logic* is a formal language for representing facts about the world, together with rules for deriving new facts that must be true if the original facts are true. Logic does not guess. Logic does not estimate. Logic *proves*.

In the Wumpus World example, the agent's KB started with "I am at [1,1] and it is OK." From that single axiom, it inferred:

  • \(\neg W(1,1), \neg P(1,1), \neg G(1,1)\) — the start cell is empty
  • \(\neg W(2,1), \neg W(1,2)\) — no wumpus in the two reachable neighbors
  • \(\neg P(2,1), \neg P(1,2)\) — no pit in the two reachable neighbors
  • After two moves: \(W(1,3)\) and \(P(3,1)\) — the exact locations of both dangers

Every one of these conclusions is *forced* by the rules of the world and the agent's percepts. Given the premises, the conclusions cannot be false. That is the defining property of logical inference.

9.7.2 Syntax and Semantics

Every formal logic has two layers:

  • Syntax — the rules for what counts as a well-formed sentence. Like grammar in a natural language. x + 4 = 4 is syntactically valid in arithmetic; xy 4 = 2 is not.
  • Semantics — the rules for what a sentence *means*; specifically, whether it is true or false in a given world. x + 4 = 4 is true in a world where \(x=0\) and false in a world where \(x=1\).

In logic, every sentence must evaluate to either true or false. There is no "maybe," no "partially true," no "true in some sense." This two-valued property (called *bivalence*) is what gives logical reasoning its certainty. If the premises are true and the inference rules are sound, the conclusion is guaranteed true. Full stop.

Intuition — The Contract Language: Think of logic as the language of contracts. A contract says "If the buyer pays $500 (P), then the seller delivers the car (Q)." This sentence \(P \rightarrow Q\) has a precise, binary meaning. Either the contract was fulfilled or it was breached. There is no "mostly fulfilled." Logic is the contract language of reasoning — every sentence is a clause, and the inference rules are the legal code that determines what follows from what.

9.7.3 Model

A *model* is a complete assignment of truth values (true/false) to every proposition symbol in the language. Each model represents one possible way the world could be — one possible configuration of facts. The set of all models is the set of all possible worlds.

For a language with two proposition symbols \(P\) and \(Q\), there are exactly \(2^2 = 4\) models:

Model\(P\)\(Q\)
\(m_1\)TT
\(m_2\)TF
\(m_3\)FT
\(m_4\)FF

A sentence is true in some models and false in others. The sentence \(P \land Q\) is true only in \(m_1\). The sentence \(P \lor Q\) is true in \(m_1, m_2, m_3\). The sentence \(\neg P\) is true in \(m_3, m_4\).

Entailment is defined in terms of models: \(\alpha \models \beta\) ("\(\alpha\) entails \(\beta\)") means: in every model where \(\alpha\) is true, \(\beta\) is also true. The truth of \(\beta\) is forced by the truth of \(\alpha\); there is no model where \(\alpha\) holds but \(\beta\) fails.

9.7.4 This Is Not Probability

Pitfall: A common confusion: "Isn't the agent just making probabilistic guesses?" No. The Wumpus World inferences are *definitive*, not probabilistic.

When the agent is at [1,2] and feels no breeze, it does not say "there is probably no pit at [2,2]." It says "there is *definitely* no pit at [2,2]." Why? Because the rules of the world are absolute: if a pit were at [2,2], breeze *must* be felt at [1,2]. The absence of breeze *logically forces* the absence of a pit. There is no uncertainty and no probability involved.

Probability enters later in the course — in probabilistic reasoning, Bayesian networks, and reasoning over time — and it handles situations where the rules are not absolute. But this module is about *certain* inference: given the rules of the world and the observed percepts, some conclusions follow with 100% certainty. Logic is the tool for those conclusions.

Q: Are all these decisions predicted through probability?

A: No. This is not probability. It is seen evidence. If you are in a cell and feel no breeze, you can confirm with certainty that adjacent cells have no pit. This is a fact — logic, not probability. The professor emphasized this explicitly: the Wumpus World agent deals in certainties, not likelihoods.

Visual Intuition: Draw a Venn diagram. The large outer rectangle is the set of all possible models (all \(2^n\) truth assignments). Inside it, a smaller circle represents the models where the KB is true. An even smaller circle inside that represents the models where some query \(\alpha\) is also true. Entailment \(KB \models \alpha\) means the \(\alpha\)-circle completely contains the KB-circle — every KB-model is also an \(\alpha\)-model. If the \(\alpha\)-circle only partially overlaps the KB-circle, entailment fails.

Logic is the study of what *must* be true, given what you already know. Its two core concepts are syntax (well-formed sentences) and semantics (truth in models). Entailment captures the idea of one sentence *forcing* another to be true. This is the foundation everything else in this module builds on.

Real-World & Domain Connection: Formal logic underpins every verification system in computer science. When Intel designs a new processor, they use *model checking* (a direct application of the truth-table method you are about to learn) to verify that the chip's circuits correctly implement the intended Boolean functions. When a cryptography protocol is proven secure, the proof is a logical derivation from axioms about the computational model. The same \(\alpha \models \beta\) you write for the Wumpus World is, structurally, the same \(\alpha \models \beta\) that verifies a chip with a billion transistors does not have a design bug.

9.8 Propositional Logic

Hook: You now have a world (the Wumpus cave) and rules for it (stench ↔ nearby wumpus, breeze ↔ nearby pit). But "nearby wumpus" is not yet a formal sentence a computer can process. Propositional logic is the language that turns those English rules into symbols a machine can mechanically reason about.

9.8.1 What Is a Proposition?

A *proposition* is a declarative sentence that is either true or false — never both, never neither, never "maybe." The actual truth value can be unknown to you, but it *exists*. What matters is that the sentence *can* be evaluated.

Propositions (evaluable):

  • "The sun rises in the east." (True)
  • "1 + 2 = 5." (False — but still a proposition!)
  • "B is a vowel." (False — still evaluable)
  • \(W(1,3)\) — "The wumpus is in [1,3]." (True or false depending on the world)

NOT propositions (not evaluable as true/false):

  • "Will you go to office today?" (Question)
  • "You are beautiful!" (Exclamation)
  • "Read this carefully." (Command)
  • \(x - y = 6\) — without assigned values for \(x\) and \(y\), no truth value exists. Once \(x=10, y=4\), it becomes a true proposition.

Intuition — The Light Switch: A proposition is like a light switch — it has exactly two states: ON (true) or OFF (false). A question ("Is the light on?") is not a switch state. A command ("Turn on the light!") is not a switch state. Only a declaration ("The light is on") has a switch state. Propositional logic is the algebra of light switches.

9.8.2 Symbols

Propositional symbols are uppercase letters: \(P, Q, R, S, \ldots\) In the Wumpus World, we use subscripted symbols like \(W_{1,3}\) to mean "the wumpus is in cell [1,3]." Note: \(W_{1,3}\) is one atomic symbol — the 1, 3, and comma are not separate parts. The symbol \(W_{1,3}\) as a whole is either true or false.

Two special symbols exist: True (always true) and False (always false). These are constants, not variables.

9.8.3 Logical Connectives

Complex sentences are built from atomic propositions using five *logical connectives*. Each connective has a precise truth table — a complete specification of when the compound sentence is true, for every possible combination of its inputs.

ConnectiveSymbolReads asTrue when...
Negation\(\neg\)"not"The operand is false
Conjunction\(\land\)"and"Both operands are true
Disjunction\(\lor\)"or"At least one operand is true
Implication\(\rightarrow\)"if...then" / "implies"The premise is false OR the conclusion is true
Biconditional\(\leftrightarrow\)"if and only if"Both operands have the same truth value

\(\neg P\) flips the truth value of \(P\).

Example: \(W(1,3)\) = "wumpus in [1,3]." Then \(\neg W(1,3)\) = "wumpus NOT in [1,3]."

\(P \land Q\) is true only when *both* \(P\) and \(Q\) are true. Each part is a *conjunct*.

One false conjunct kills the whole conjunction. One false fact in an AND-chain makes the entire chain false.

Note: this is *inclusive* OR — both can be true. "Tea or coffee" in logic means you could have both. (Exclusive OR, XOR, is a separate connective: \(P \oplus Q\).)

9.8.7 Implication (IF-THEN / Conditional)

\(P \rightarrow Q\) ("if \(P\) then \(Q\)") is the most subtle connective. \(P\) is the *premise* (antecedent); \(Q\) is the *conclusion* (consequent). The only way \(P \rightarrow Q\) is false: \(P\) is true AND \(Q\) is false. In every other case, it is true.

\(P\)\(Q\)\(P \rightarrow Q\)

Pitfall: The two rows where \(P\) is false and the implication is true are the #1 source of confusion in propositional logic. Students ask: "How can 'if the moon is made of cheese then 2+2=4' be true?" The answer: an implication only makes a claim when the premise holds. When the premise is false, the implication is *vacuously true* — it promises nothing, so it cannot be broken.

Intuition — The Politician Analogy (from lecture): "If I am elected, then I will lower taxes."

Elected?Taxes lowered?Promise...

If the politician is not elected, you cannot accuse them of breaking their promise. The implication is only violated when the condition happens but the promised outcome does not.

9.8.8 Biconditional (IF AND ONLY IF)

\(P \leftrightarrow Q\) means \(P\) and \(Q\) always have the same truth value — both true or both false. It is equivalent to \((P \rightarrow Q) \land (Q \rightarrow P)\).

\(P\)\(Q\)\(P \leftrightarrow Q\)

TFF
FTF
FFT

In the Wumpus World, the KB rules use biconditionals: \(B_{1,1} \leftrightarrow (P_{1,2} \lor P_{2,1})\) says "breeze at [1,1] if and only if there is a pit in [1,2] or [2,1]." The biconditional captures the idea that breeze and pits are locked together — you cannot have one without the other.

9.8.9 Operator Precedence and Ambiguity

Without parentheses, \(\neg A \land B\) is ambiguous. Does it mean \((\neg A) \land B\) or \(\neg (A \land B)\)? These mean different things.

Operator precedence (from tightest to loosest): \(\neg\) → \(\land\) → \(\lor\) → \(\rightarrow\) → \(\leftrightarrow\)

So \(\neg A \land B\) defaults to \((\neg A) \land B\). But use explicit parentheses when there is any doubt. Clarity costs nothing; ambiguity costs marks on the exam.

Propositional logic is a language with exactly five connectives and precise truth tables for each. Master these truth tables cold — every inference method in the rest of this module (truth tables, theorem proving, resolution) is built on them. The implication truth table (false only in the T→F row) deserves special attention; it is the most frequently tested and most frequently misunderstood.

Real-World & Domain Connection: Propositional logic is the assembly language of reasoning. Every digital circuit in your computer — every AND gate, OR gate, NOT gate — directly implements a propositional connective. When you write if (x > 0 && y < 10) in code, the && is conjunction. When a SQL query has WHERE age > 18 AND city = 'Mumbai', it is filtering rows by a logical conjunction. The connectives you are learning are not abstract symbols — they are the primitives that every conditional, every filter, and every decision in software is built from.

9.9 Truth Tables for Inference

Hook: You are at [2,1]. You feel a breeze. Is [1,2] safe to enter? You could guess — and die. Or you could enumerate *every possible way the world could be*, eliminate the ones that contradict what you know, and check whether [1,2] is pit-free in *all* remaining worlds. If it is, the cell is provably safe. That is the truth-table method — brute force, but absolutely certain.

9.9.1 Entailment

*Entailment* (written \(\alpha \models \beta\)) means: in every possible world (model) where \(\alpha\) is true, \(\beta\) is also true. \(\beta\) is a *logical consequence* of \(\alpha\) — you cannot have \(\alpha\) without also having \(\beta\).

In the Wumpus World: the agent is at [2,1] and detects a breeze. Call this fact \(B_{2,1}\). The KB (which includes \(B_{2,1}\) plus the rules of the world) entails:

\[KB \models P_{1,1} \lor P_{2,2} \lor P_{3,1}\]

"There is a pit in [1,1], [2,2], or [3,1]." The KB forces at least one of those three to be true.

Intuition — The Elimination Game: Entailment is like playing "20 Questions" with possible worlds. You start with all \(2^n\) possible worlds. Each fact you learn eliminates some worlds. The worlds that survive are the ones where your KB is true. A sentence \(\beta\) is entailed if it is true in *every surviving world*. If even one survivor has \(\beta\) false, entailment fails.

9.9.2 Representing the Wumpus World KB in Propositional Logic

Consider a concrete Wumpus World configuration. The agent knows:

  • [1,1] has no pit (direct observation — it is alive there)
  • [1,1] has no breeze (percept)
  • [2,1] has breeze (percept after moving)

The KB encodes this as five propositional sentences:

RuleSentenceMeaning
R1\(\neg P_{1,1}\)No pit in [1,1]
R2\(B_{1,1} \leftrightarrow (P_{1,2} \lor P_{2,1})\)Breeze at [1,1] iff pit at [1,2] or [2,1]
R3\(B_{2,1} \leftrightarrow (P_{1,1} \lor P_{2,2} \lor P_{3,1})\)Breeze at [2,1] iff pit at [1,1], [2,2], or [3,1]
R4\(\neg B_{1,1}\)No breeze in [1,1]
R5\(B_{2,1}\)Breeze in [2,1]

A *literal* is an atomic proposition or its negation. The unique proposition symbols in this KB are:

\[P_{1,1},\; B_{1,1},\; P_{1,2},\; P_{2,1},\; P_{2,2},\; P_{3,1},\; B_{2,1}\]

That is \(n = 7\) literals, giving \(2^7 = 128\) possible models.

9.9.3 The Five-Step Truth Table Enumeration Method

The truth-table method (also called *model checking*) is a brute-force algorithm for determining entailment. It works for any propositional KB with a finite number of symbols.

Step 1 — Extract literals. List every distinct proposition symbol in the KB. Count them: that is \(n\).

Step 2 — Enumerate all \(2^n\) models. Create a truth table with one column per literal. Fill every row with a different true/false combination. For \(n=7\), there are 128 rows.

Step 3 — Evaluate each KB sentence per row. Using the truth tables for \(\neg, \land, \lor, \rightarrow, \leftrightarrow\), compute the truth value of R1, R2, R3, R4, R5 for every row. Add one column per rule.

Step 4 — Compute the KB column. \(KB = R1 \land R2 \land R3 \land R4 \land R5\). The KB is true only in rows where *all five rules* are true. Most rows will have KB = false because they contradict at least one rule. In this example, exactly 3 rows survive.

Step 5 — Check the query \(\alpha\) in KB-true rows. If \(\alpha\) is true in every row where KB is true, then \(KB \models \alpha\). If there is even one KB-true row where \(\alpha\) is false, entailment fails.

9.9.4 Worked Truth Table — Query \(\neg P_{1,2}\)

Query: \(\neg P_{1,2}\) — "Is there no pit in [1,2]? Is it safe?"

Step 1: \(n = 7\) literals.

Step 2: 128 rows (not shown in full — but we understand the structure).

Step 3: Compute each rule column:

  • R1 = \(\neg P_{1,1}\) — true when \(P_{1,1}\) is false.
  • R2 = \(B_{1,1} \leftrightarrow (P_{1,2} \lor P_{2,1})\) — true when both sides match.
  • R3 = \(B_{2,1} \leftrightarrow (P_{1,1} \lor P_{2,2} \lor P_{3,1})\) — true when both sides match.
  • R4 = \(\neg B_{1,1}\) — true when \(B_{1,1}\) is false.
  • R5 = \(B_{2,1}\) — use the \(B_{2,1}\) column directly.

Step 4: \(KB = R1 \land R2 \land R3 \land R4 \land R5\). After filtering, exactly 3 rows survive out of 128.

Step 5: In all 3 surviving rows, \(P_{1,2} = \text{false}\). So \(\neg P_{1,2} = \text{true}\) in all 3 rows.

Conclusion: \(KB \models \neg P_{1,2}\). The KB *proves* there is no pit in [1,2]. The agent can safely move there. This becomes new knowledge (R6).

9.9.5 Worked Truth Table — Query \(\neg P_{2,2}\)

Query: \(\neg P_{2,2}\) — "Is there no pit in [2,2]?"

Using the same 3 surviving rows:

In some rows, \(P_{2,2} = \text{true}\). In others, \(P_{2,2} = \text{false}\). So \(\neg P_{2,2}\) is true in some surviving rows and false in others.

Conclusion: \(KB \not\models \neg P_{2,2}\). The KB does *not* entail that [2,2] is safe. From the available percepts alone, the agent cannot prove [2,2] is pit-free.

The truth-table method gives a definitive yes/no answer to any entailment question in propositional logic. For this KB, \(\neg P_{1,2}\) is entailed (provably safe); \(\neg P_{2,2}\) is not entailed (unknown). The method is guaranteed correct — it directly implements the mathematical definition of entailment.

9.9.6 Scalability Problem

Scope: The truth-table method requires \(O(2^n)\) time and space. For \(n=7\), that is 128 rows — trivial. For \(n=30\), it is over a billion rows — impossible. Real-world knowledge bases can have thousands of propositions. Model checking by exhaustive enumeration does not scale.

This intractability motivates the second half of this module: *theorem proving*. Instead of enumerating all \(2^n\) worlds and checking each one, theorem proving uses inference rules to derive conclusions directly — often in a handful of steps. The next section introduces the logical equivalence laws that make theorem proving possible.

Visual Intuition: Imagine the \(2^n\) models as points on a circle. The KB-true models are a small cluster of points. Entailment asks: "Does the query-circle completely contain the KB-cluster?" The truth-table method draws both circles by hand — feasible for 128 points, impossible for billions. Theorem proving skips the drawing and reasons directly about the relationship between the circles.

Real-World & Domain Connection: Despite its scalability limits, model checking is not just a classroom exercise. *Bounded model checking* — a modern refinement that checks models up to a certain depth — is used to verify hardware designs at companies like Intel and NVIDIA. When the state space is small enough (e.g., a specific circuit module), exhaustive enumeration is feasible and provides ironclad guarantees. The same \(KB \models \alpha\) you compute by hand for the Wumpus World is computed by automated tools to verify that a chip's floating-point unit correctly implements the IEEE 754 standard.

9.10 Theorem Proving — Introduction

Hook: Truth tables work — but at \(2^n\) rows, they break quickly. A KB with just 30 propositions needs over a billion rows. No computer can do that. So how does real logical reasoning scale? The answer: *don't enumerate worlds — manipulate sentences*. Rewrite, simplify, substitute. Turn a big expression into a smaller, equivalent one. That is theorem proving.

9.10.1 Logical Equivalence

Two sentences \(\alpha\) and \(\beta\) are *logically equivalent* (written \(\alpha \equiv \beta\)) if they have identical truth values in every possible model. Equivalence means you can freely substitute one for the other — they assert exactly the same thing.

You can verify equivalence by truth table: compute the column for \(\alpha\), compute the column for \(\beta\), and check they are identical. If they match in all \(2^n\) rows, the sentences are equivalent.

9.10.2 Laws of Logical Equivalence

These laws are the "algebra" of logic — rewrite rules that preserve truth. Apply them strategically, and you can transform a complex KB into a form where entailment is obvious.

Core equivalence laws (memorize these):

LawFormWhat it lets you do
Commutativity\(\alpha \land \beta \equiv \beta \land \alpha\) ; \(\alpha \lor \beta \equiv \beta \lor \alpha\)Swap order of AND/OR
Associativity\((\alpha \land \beta) \land \gamma \equiv \alpha \land (\beta \land \gamma)\) ; same for \(\lor\)Drop parentheses in chains
Double Negation\(\neg(\neg \alpha) \equiv \alpha\)Cancel two NOTs
Contrapositive\(\alpha \rightarrow \beta \equiv \neg \beta \rightarrow \neg \alpha\)Flip and negate an implication
Biconditional Elimination\(\alpha \leftrightarrow \beta \equiv (\alpha \rightarrow \beta) \land (\beta \rightarrow \alpha)\)Break ↔ into two →
De Morgan's Laws\(\neg(\alpha \land \beta) \equiv \neg \alpha \lor \neg \beta\) ; \(\neg(\alpha \lor \beta) \equiv \neg \alpha \land \neg \beta\)Push NOT through AND/OR, flipping the connective
Idempotence\(\alpha \land \alpha \equiv \alpha\) ; \(\alpha \lor \alpha \equiv \alpha\)Eliminate duplicates

More useful laws:

LawForm
Domination\(\alpha \lor \text{True} \equiv \text{True}\) ; \(\alpha \land \text{False} \equiv \text{False}\)
Identity\(\alpha \land \text{True} \equiv \alpha\) ; \(\alpha \lor \text{False} \equiv \alpha\)

Intuition — Algebraic Manipulation: You already use equivalence laws in ordinary algebra: \(a + b = b + a\) (commutativity), \((a+b)+c = a+(b+c)\) (associativity), \(-(-a) = a\) (double negation). Logical equivalence laws are the same idea — algebraic rules for simplifying expressions — but applied to AND, OR, NOT, and implication instead of addition and multiplication.

9.10.3 Verifying Equivalence with Truth Tables

Any equivalence law can be proven by truth table. For commutativity of AND:

\(\alpha\)\(\beta\)\(\alpha \land \beta\)\(\beta \land \alpha\)
TTTT
TFFF
FTFF
FFFF

The last two columns are identical → \(\alpha \land \beta \equiv \beta \land \alpha\). Every equivalence law can be verified this way.

9.10.4 What Comes Next

The next session builds on these equivalence laws to introduce specific *inference rules*:

  • Modus Ponens: From \(\alpha \rightarrow \beta\) and \(\alpha\), derive \(\beta\).
  • Modus Tollens: From \(\alpha \rightarrow \beta\) and \(\neg \beta\), derive \(\neg \alpha\).
  • AND-Elimination: From \(\alpha \land \beta\), derive \(\alpha\) (or \(\beta\)).
  • Conjunctive Normal Form (CNF): A standardized format (AND of ORs) that enables automated resolution.
  • Resolution: A single inference rule that is both sound and complete for propositional logic.
  • Predicate Logic (First-Order Logic): Extends propositional logic with quantifiers (\(\forall\), \(\exists\)) and predicates, enabling much richer knowledge representation.

Q: Are these theorem-proving steps ordered? Do we always apply biconditional elimination first, then contraposition, then modus ponens?

A: No, the steps are not strictly ordered. Theorem proving is not a fixed recipe — it is a skill. Different people may reach the same conclusion in different numbers of steps, applying different laws in different sequences. Some paths are shorter than others. Mastery comes from practice: knowing which law to apply where. Later techniques like conjunctive normal form and resolution provide more *systematic* approaches — they reduce the "art" of theorem proving to a mechanical procedure.

Logical equivalence laws are the rewrite rules of logic. They let you transform a sentence into an equivalent but simpler form — without enumerating \(2^n\) worlds. Paired with inference rules (modus ponens, resolution), they form the engine of theorem proving: derive conclusions in polynomial steps that truth tables would need exponential time to verify.

Real-World & Domain Connection: De Morgan's laws — the ones you just learned — are used every time you write if (!(a && b)) in code and a compiler optimizes it to if (!a || !b). Modern SAT solvers (Boolean satisfiability engines) use equivalence rewriting as a preprocessing step, applying hundreds of rewrite rules to simplify the input formula before the main search begins. What takes you 5 minutes by hand, a SAT solver does in microseconds — but it uses exactly the same laws.

9.11 Student Questions and Answers

Q: Can gold be near the wumpus or a pit?

A: Yes, gold can be in a cell adjacent to a pit or the wumpus, but it can never be in the *same* cell. If gold were in the same cell as the wumpus, the problem would be unsolvable — reaching the gold would always mean getting eaten. The problem instances are generated so that a safe path to the gold always exists (in solvable configurations).

Q: What if the agent starts in a breeze state?

A: If the starting cell [1,1] itself has breeze, the agent cannot deduce much. Breeze at [1,1] means a pit is in [1,2] or [2,1], but the agent does not know which one. It must take a risk and move to gain more information. In some configurations, the problem may be unsolvable. For example, if [2,1] has a pit and [1,2] has the wumpus, the agent cannot safely move in any direction. But the Wumpus World is not always about winning. The point is whether the agent can reason about its situation from available percepts, even when safe options are limited.

Q: How does the agent store and accumulate knowledge across moves? (Several students asked variations of this.)

A: The agent maintains a percept vector for each visited cell: [Stench?, Breeze?, Glitter?, Bump?, Scream?]. At [1,1] it records OK. At [2,1] it records breeze. At [1,2] it records stench. These percepts are TELLed to the KB and persist. Every move, the agent can ASK the KB using all accumulated percepts. The KB grows with each new percept and each new inference — the agent's knowledge compounds over time. The cross-elimination in the worked example (combining breeze-at-[2,1] with no-stench-at-[2,1] to rule out \(W(2,2)\)) is possible only because the agent *remembered* both percepts.

Q: Does the agent need to see the next cell to decide if it is safe?

A: No — and that is the whole point. The agent does not need to visit a cell to know it is dangerous. Stench in the current cell tells the agent the wumpus is next door. The percept alone is enough to infer danger (or safety) in adjacent cells. The negation rules are especially powerful here: no stench and no breeze mean *all* adjacent cells are provably safe, without visiting any of them.

Q: Is the truth-table method scalable?

A: For 7 literals (128 rows), a computer handles it instantly. But for \(n\) literals, it is \(O(2^n)\) in both time and space — exponential growth makes it infeasible beyond roughly 30-40 propositions. This is why theorem proving, SAT solvers, and resolution methods exist: they derive the same conclusions in far fewer steps, often in polynomial rather than exponential time for the cases that matter.

Q: Is this really intelligence if it is just programmed rules? (Several students raised variations of the "is this AI or just programming?" question.)

A: This is the foundational debate in AI, going back to the very first class. Fifty years ago, automatic doors were considered intelligent — they opened when someone approached. Later, people realized it was just sensors and motors doing their programmed job. The Wumpus agent exhibits intelligent-seeming behavior (deducing danger locations without visiting them), but internally it is applying logical rules mechanically. The philosophical question "is this intelligence?" has no settled answer. The practical answer: the system exhibits *rationality* — it does the right thing given its knowledge. Whether we label that "intelligent" or "just programmed" does not change whether it works. (The follow-up question about whether humans themselves are "programmed" by environment and experience moves into philosophy of mind and is outside the scope of this computational course.)

9.12 Key Industry and Real-World Connections

  • Prolog and Logic Programming: Prolog (Programming in Logic) is a declarative language where you state facts and rules, then query the system. The Wumpus World agent can be directly implemented in Prolog — you encode the KB sentences (R1–R5, the pit/stench rules) as Prolog clauses, then query ?- safe([2,2]). and Prolog runs resolution automatically. Prolog powers expert systems, natural language parsers, and automated theorem provers to this day. SWI-Prolog is free and open-source.
  • Knowledge Bases in Modern AI: Modern LLM-based agents do not use explicit propositional KBs, but the architecture is the same pattern evolved: storing facts, querying them, and inferring new ones. Vector databases (Pinecone, Weaviate) are contemporary TELL mechanisms. Retrieval-Augmented Generation (RAG) is a modern ASK pipeline — retrieve relevant documents, then reason over them. Agent memory systems (LangChain's memory modules, OpenAI's Assistant API) are the UPDATE loop — persisting inferred facts for future use.
  • Expert Systems: One of AI's first commercial successes. MYCIN (1976, Stanford) diagnosed bacterial infections using a KB of roughly 600 if-then rules and outperformed junior doctors in clinical trials. DENDRAL (1960s) inferred molecular structures from mass spectrometry data using rule-based reasoning. Modern expert systems run in insurance underwriting, loan approval, and medical diagnosis support — all using the TELL/ASK/UPDATE pattern from this lecture.
  • SAT Solvers and Formal Verification: Modern Boolean satisfiability solvers (MiniSAT, Z3, CaDiCaL) use the DPLL and CDCL algorithms — direct descendants of the truth-table and resolution methods. SAT solvers verify that hardware designs (CPU circuits, GPU cores) correctly implement their specifications. They prove that software has no null-pointer dereferences or buffer overflows. When Intel verifies a new chip design, SAT solvers check billions of logical constraints — all using the same \(KB \models \alpha\) framework.
  • Automated Planning: AI planning systems (used in robotics, logistics, spacecraft operations) encode the world state, action preconditions, and goal states as logical sentences. The planner then uses theorem-proving techniques to find a sequence of actions whose execution entails the goal. Knowledge-Based Agents

Must-know: A knowledge-based agent maintains a KB (set of logical sentences) and uses TELL, ASK, and UPDATE operations to perceive, reason, and act. The KB is the engine underneath every non-trivial agent architecture.

\[\text{Agent loop: } \text{TELL}(\text{percept}) \rightarrow \text{ASK}(\text{action}) \rightarrow \text{UPDATE}(\text{inference})\]

Top pitfall: Confusing the KB with a passive database. The KB is active — it grows with every new percept and every new inference, compounding knowledge over time.

Self-check: What are the three operations every knowledge-based agent performs, and what does each one do?

Connects to: The Wumpus World, Propositional Logic, Logic

The Wumpus World

Must-know: The Wumpus World is a 4x4 grid-world with one wumpus, multiple pits, and one gold. The agent senses stench (wumpus-adjacent), breeze (pit-adjacent), glitter (gold-same-cell), bump (wall), and scream (wumpus death). It is partially observable but deterministic — designed to isolate logical reasoning from probabilistic uncertainty.

\[\text{Percept: } [\text{Stench?},\, \text{Breeze?},\, \text{Glitter?},\, \text{Bump?},\, \text{Scream?}]\]

Top pitfall: Thinking the Wumpus World involves probability. All inferences are definitive — the agent proves safety or danger with 100% certainty, not likelihood.

Self-check: List the five percepts in the Wumpus World and what each one signals to the agent.

Connects to: PEAS Specification, Environment Characteristics, Logical Rules of the Wumpus World

Logical Rules of the Wumpus World

Must-know: Four rules govern the entire world: Cause→Effect uses AND (one pit guarantees breeze in ALL four neighbors). Effect→Cause uses OR (breeze means at least ONE neighbor is a pit). Same pattern for wumpus/stench. The negation rules (absence of percept → absence of danger in ALL neighbors) are the engine of certainty.

\[\text{Cause}\rightarrow\text{Effect: } P(x,y) \rightarrow B(x+1,y) \land B(x-1,y) \land B(x,y+1) \land B(x,y-1) \\ \text{Effect}\rightarrow\text{Cause: } B(x,y) \rightarrow P(x+1,y) \lor P(x-1,y) \lor P(x,y+1) \lor P(x,y-1) \\ \text{Negation: } \neg B(x,y) \rightarrow \neg P(x+1,y) \land \neg P(x-1,y) \land \neg P(x,y+1) \land \neg P(x,y-1)\]

Top pitfall: Using AND where OR belongs (or vice versa). When you HAVE the pit → AND every neighbor gets breeze. When you FEEL the breeze → OR (at least one neighbor is a pit).

Self-check: If an agent feels a breeze at [2,2], write the logical sentence that captures what this tells the agent about pits in adjacent cells.

Connects to: The Wumpus World, Propositional Logic, Worked Example — Configuration 1

Propositional Logic

Must-know: Propositional logic uses five connectives: negation (NOT), conjunction (AND), disjunction (OR), implication (IF-THEN), and biconditional (IFF). The implication P→Q is false ONLY when P is true and Q is false. In all other cases (including when P is false), it is vacuously true.

\[P \rightarrow Q \text{ is false only in row } (P=\text{T},\, Q=\text{F})\]

Top pitfall: Confusion about vacuous truth: when the premise P is false, the implication P→Q is ALWAYS true regardless of Q. The implication only makes a claim when the premise holds.

Self-check: Complete the truth table for P→Q. In which single row is it false?

Connects to: Truth Tables for Inference, Theorem Proving, Logical Equivalence Laws

Truth Tables for Inference (Model Checking)

Must-know: The truth-table method enumerates all 2^n possible models, keeps only those where the KB (conjunction of all rules) is true, and checks if the query is true in every surviving model. If yes, KB entails the query. The method is guaranteed correct but requires O(2^n) time — infeasible beyond ~30 propositions.

\[KB \models \alpha \text{ iff } \forall m: (m \text{ satisfies } KB) \implies (m \text{ satisfies } \alpha)\]

Top pitfall: Confusing 'not entailed' with 'false.' If KB does not entail α, it means the query could be true or false — it is unknown, not disproven.

Self-check: Given a KB with 5 propositional symbols, how many rows does the truth table have? If the KB is true in exactly 2 rows and the query is true in both, is the query entailed?

Connects to: Propositional Logic, Theorem Proving, Entailment and Models

Theorem Proving and Logical Equivalence

Must-know: Theorem proving avoids enumerating all models by using equivalence laws (commutativity, associativity, double negation, contrapositive, De Morgan's, biconditional elimination, idempotence) to rewrite sentences into simpler, equivalent forms. Paired with inference rules like Modus Ponens and Resolution, it derives conclusions in far fewer steps than truth tables.

\[\text{De Morgan: } \neg(\alpha \land \beta) \equiv \neg\alpha \lor \neg\beta; \quad \neg(\alpha \lor \beta) \equiv \neg\alpha \land \neg\beta\]

Top pitfall: Thinking theorem proving is a fixed recipe with a mandatory order of steps. It is a skill — different sequences of law applications can reach the same conclusion.

Self-check: Apply De Morgan's law to transform ¬(P ∧ Q) into an equivalent expression using OR.

Connects to: Propositional Logic, Truth Tables for Inference, Logical Rules of the Wumpus World

Genetic Algorithms, Ant Colony Optimization, and Neural Architecture Search

6.1 Genetic Algorithms for Optimization

6.1.1 Overview and Biological Principles

Hook & Motivation: How can an optimization algorithm discover creative, high-performing solutions to ultra-complex combinatorial problems without getting trapped in local optima? By mimicking natural selection, survival of the fittest, and genetic recombination across a population of candidate solutions.

Genetic algorithms (GAs) belong to a broader family of metaheuristic optimization techniques known as bio-inspired or nature-inspired algorithms. These algorithms draw direct computational inspiration from biological evolution and natural selection, establishing multi-instance collaborative search across a population. In classical local search strategies such as hill climbing or local beam search, search threads operate either on a single state instance or as parallel independent state vectors. When multiple search instances are used in local beam search, they evaluate independently in parallel without sharing structural information or exchanging sub-components of candidate solutions.

Intuition & Analogy: Think of traditional search methods like isolated mountain climbers who never talk to each other—if one gets stuck on a low peak, their progress cannot help another climber. A Genetic Algorithm is like a collaborative breeding program: two high-performing individuals pool their best traits together through collaboration to spawn offspring that might climb even higher than either parent.

Core Definition — Population-Based Recombination:
Genetic algorithms introduce a fundamentally distinct search paradigm: collaborative recombination among a population of candidate solutions. Instead of maintaining independent parallel states, a genetic algorithm maintains a collection of candidate states termed a population. Individual candidate states undergo stochastic parent selection, genetic crossover (recombination), and random mutation across successive iterations (generations). This mechanism enables high-performing structural building blocks (schemata) from two different parent solutions to combine into offspring solutions, exploring the state space through collaboration in ways non-collaborative search cannot replicate.

6.1.2 Seven-Step Process and Termination Criteria

The 7-Step Evolutionary Algorithm Pipeline (Seven Distinct Phases):
The seven-step execution process (seven distinct phases) of a genetic algorithm proceeds as follows:

  1. Problem Representation (Encoding): Formulate candidate states as discrete data structures (bit strings, integer vectors, or permutation arrays) representing individual chromosomes.
  2. Initial Population Generation: Randomly generate or initialize a population of \(K\) candidate individual state vectors across the state space.
  3. Fitness Evaluation: Quantitative score evaluation using a domain-specific fitness function \(f(B_i)\) measuring solution quality or health.
  4. Parent Selection: Select pairs of candidate states (parents) from the current population based on relative fitness scores using stochastic methods like Roulette Wheel Selection or Tournament Selection.
  5. Crossover (Recombination): Recombine structural segments of selected parent pairs to create offspring (children) inheriting traits from both parents.
  6. Mutation: Apply random alterations to individual genes (vector elements or bits) within offspring with probability \(p_m\) to introduce novel traits not present in either parent.
  7. Population Update and Iteration: Replace the previous population with the newly generated offspring and re-evaluate population fitness.

Assumptions & Scope (Three Termination Criteria):
A genetic algorithm is a stochastic metaheuristic search; it does not guarantee finding a global optimum within a fixed runtime. Iterative evolution proceeds continuously until at least one of three explicit termination criteria is met:

  1. Target Fitness Threshold Reached: A candidate solution achieves the global optimum or satisfies a target fitness value (e.g., zero attacking queen pairs in an \(N\)-queens board).
  2. Computational Generation Limit Exceeded: The total number of executed iterations reaches a predefined maximum limit (e.g., completing exactly \(G_{\text{max}}\) generations).
  3. Population Convergence / Stagnation: The average or max fitness value across iteration \(N+1\) shows negligible change compared to iteration \(N\), indicating search stagnation in a local optimum.

6.1.3 Symbol Registry

Symbol registry — Genetic Algorithms for N-Queens Optimization:

  • \(K\) — Population size (number of candidate configurations per generation) — \(K \in \mathbb{Z}^+\) — integer scalar
  • \(B_i\) — Candidate state vector representing board configuration \(i\) — \(B_i = [r_1, r_2, \dots, r_N]\) — \(N\)-dimensional integer vector
  • \(r_j\) — Row position of the queen in column \(j\) — \(r_j \in \{1, 2, \dots, N\}\) — integer scalar
  • \(f(B_i)\) — Fitness function value evaluating non-attacking queen pairs for configuration \(B_i\) — \(f(B_i) \in [0, \binom{N}{2}]\) — non-negative integer
  • \(f_{\text{total}}\) — Total cumulative fitness across the entire population — \(f_{\text{total}} = \sum_{i=1}^K f(B_i)\) — positive integer
  • \(p_i\) — Selection probability for candidate state \(B_i\) on the roulette wheel — \(p_i = \frac{f(B_i)}{f_{\text{total}}}\) — scalar in \((0, 1]\)
  • \(C_m\) — Offspring candidate state vector generated after crossover and mutation — \(C_m \in \{1, 2, \dots, N\}^N\) — \(N\)-dimensional integer vector

6.1.4 Worked Example: 4-Queens Problem Step-by-Step

Comprehensive Worked Example — 4-Queens Genetic Algorithm Walkthrough:

Consider the 4-Queens problem solved using a genetic algorithm with population size \(K = 4\). The objective is to place 4 queens on a \(4 \times 4\) chessboard such that no two queens attack each other horizontally, vertically, or diagonally.

Step 1: Initial Population Representation
Each board state is encoded as a 4-dimensional vector where index \(j \in \{1,2,3,4\}\) represents column \(j\), and element value \(r_j \in \{1,2,3,4\}\) represents the row position of the queen in column \(j\).

  • \(B_1 = [1, 4, 2, 2]\) (Queen 1 at row 1, Queen 2 at row 4, Queen 3 at row 2, Queen 4 at row 2)
  • \(B_2 = [2, 1, 4, 1]\) (Queen 1 at row 2, Queen 2 at row 1, Queen 3 at row 4, Queen 4 at row 1)
  • \(B_3 = [1, 4, 3, 2]\) (Queen 1 at row 1, Queen 2 at row 4, Queen 3 at row 3, Queen 4 at row 2)
  • \(B_4 = [2, 1, 4, 1]\) (Queen 1 at row 2, Queen 2 at row 1, Queen 3 at row 4, Queen 4 at row 1)

Step 2: Fitness Calculation
The maximum possible number of non-attacking queen pairs on an \(N\)-queens board is given by the combination formula:

\[ \binom{N}{2} = \binom{4}{2} = \frac{4 \times 3}{2} = 6 \]

Fitness \(f(B_i)\) counts non-attacking pairs out of 6 possible pairs:

  • \(f(B_1) = 4\) non-attacking pairs
  • \(f(B_2) = 4\) non-attacking pairs
  • \(f(B_3) = 2\) non-attacking pairs
  • \(f(B_4) = 3\) non-attacking pairs

Total population fitness \(f_{\text{total}}\):

\[ f_{\text{total}} = f(B_1) + f(B_2) + f(B_3) + f(B_4) = 4 + 4 + 2 + 3 = 13 \]

Step 3: Selection Probabilities & Roulette Wheel Selection
Selection probability for candidate state \(B_i\):

\[ p(B_i) = \frac{f(B_i)}{f_{\text{total}}} \]
  • \(p(B_1) = \frac{4}{13} \approx 0.3077\) (30.77% of roulette wheel)
  • \(p(B_2) = \frac{4}{13} \approx 0.3077\) (30.77% of roulette wheel)
  • \(p(B_3) = \frac{2}{13} \approx 0.1538\) (15.38% of roulette wheel)
  • \(p(B_4) = \frac{3}{13} \approx 0.2308\) (23.08% of roulette wheel)

Four stochastic wheel spins choose the parent pool sequence:

  • Spin 1 selects \(B_4\)
  • Spin 2 selects \(B_1\)
  • Spin 3 selects \(B_1\)
  • Spin 4 selects \(B_3\)

Parent couples formed:

  • Couple 1: \((B_4, B_1) = ([2, 1, 4, 1], [1, 4, 2, 2])\)
  • Couple 2: \((B_1, B_3) = ([1, 4, 2, 2], [1, 4, 3, 2])\)

Step 4: Crossover (Recombination)

  1. Single-Point Crossover on Couple 1 (Split after index 1):
    • Parent 1 (\(B_4\)): \([2 \mid 1, 4, 1]\)
    • Parent 2 (\(B_1\)): \([1 \mid 4, 2, 2]\)
    • Offspring \(C_1 = [2, 4, 2, 2]\)
    • Offspring \(C_2 = [1, 1, 4, 1]\)
  2. Two-Point Crossover on Couple 2 (Splits after index 1 and index 3):
    • Parent 1 (\(B_1\)): \([1 \mid 4, 2 \mid 2]\)
    • Parent 2 (\(B_3\)): \([1 \mid 4, 3 \mid 2]\)
    • Offspring \(C_3 = [1, 4, 3, 2]\)
    • Offspring \(C_4 = [1, 4, 2, 2]\)

Step 5: Mutation
Mutate one random element per offspring:

  • \(C_1 = [2, 4, 2, 2] \xrightarrow{\text{mutate index 1 to 1}} C_1' = [1, 4, 2, 2]\)
  • \(C_2 = [1, 1, 4, 1] \xrightarrow{\text{mutate index 2 to 3}} C_2' = [1, 3, 4, 1]\)
  • \(C_3 = [1, 4, 3, 2] \xrightarrow{\text{mutate index 3 to 2}} C_3' = [1, 4, 2, 2]\)
  • \(C_4 = [1, 4, 2, 2] \xrightarrow{\text{mutate index 4 to 3}} C_4' = [1, 4, 2, 3]\)

Step 6: Offspring Generation Evaluation & Sense Check
Re-evaluate fitness for \(\{C_1', C_2', C_3', C_4'\}\). If max fitness 6 is achieved, terminate; otherwise proceed to generation 2.
Sense check: Fitness total and selection probabilities sum exactly to 1.0 (100%), confirming probability mass conservation across roulette wheel selection.

6.1.5 Student Questions and Answers

Q: Should we eliminate a parent from the roulette wheel once it has been selected for one couple?

A: No, candidate states are not eliminated after being selected. A single candidate solution with high fitness can be selected multiple times to participate in different parent couples across different spins of the roulette wheel. In biological evolution, an individual can have offspring across different partnerships over time. However, within any single couple, the two parent instances should ideally represent distinct states to perform meaningful genetic recombination.

Q: Why don't we simply select the two highest-probability candidate states deterministically as parents instead of spinning a roulette wheel?

A: Deterministically picking the top two candidates introduces strong selection bias and rapidly eliminates population diversity, causing early premature convergence to sub-optimal local peaks. Less fit candidate states may still contain valuable sub-structures or schema components that could recombine with another state into a globally optimal solution. The roulette wheel gives every candidate a probability proportional to its fitness, balancing exploitation of good solutions with stochastic exploration of the search space.

Q: If crossover only recombines existing parent numbers, how do children acquire completely new properties or values?

A: Crossover alone only mixes existing parent attributes across positions. Unique individual traits and novel attribute values arise specifically through the mutation step. By altering one or two vector elements to values not present in that position in either parent, mutation introduces fresh search directions into the population.

Q: How do single-point and multi-point crossover strategies differ when generating offspring?

A: In single-point crossover, a single split line is drawn across the state vector, swapping all elements after that line between parents. In two-point or multi-point crossover, multiple boundary lines are drawn, swapping internal segment blocks between parents while keeping outer segments fixed.

6.1.6 Industry Applications and Mathematical Formulations

Genetic algorithms excel in complex optimization tasks including system trajectory planning, automated circuit layout design, combinatorial scheduling, and symbolic regression.

Mathematical Formulation for Linear Equation Solving:
Genetic algorithms can solve systems of linear equations or non-linear Diophantine equations of the form:

\[ A x + B y + C z = D \]

Candidate states are encoded as integer or floating-point vectors \([x, y, z]\). The fitness function evaluates the inverse magnitude error:

\[ f(x, y, z) = \frac{1}{1 + |A x + B y + C z - D|} \]

As the linear combination approaches the constant target \(D\), the absolute error \(|A x + B y + C z - D|\) approaches 0 and the fitness value \(f(x, y, z)\) approaches its maximum value of 1. Parent selection, crossover, and vector element mutation iteratively refine candidate numeric vectors toward valid equation roots.

6.2 Ant Colony Optimization (ACO)

6.2.1 Biological Intuition and Foraging Mechanics

Hook & Motivation: How do blind biological ants, with no central leader or global map, consistently discover the shortest path between their nest and a food source around obstacles? Through decentralized collective intelligence powered by chemical scent trails called pheromones.

Ant Colony Optimization (ACO) is a probabilistic metaheuristic for solving hard combinatorial optimization problems, inspired by the collective foraging behavior of real ant colonies. When ants explore the environment surrounding their nest in search of food sources, individual ants walk randomly while depositing a chemical marker called pheromone along their path.

Intuition & Analogy: Imagine two pathways between a nest and a food source: one short and one long. Ants walking on the shorter path return to the nest faster, making more round trips per hour. More round trips mean more scent trails deposited per minute. Because the scent trails evaporate over time, the longer, slower path loses its scent, while the shorter, faster path gets stronger and stronger until every ant follows it!

Core Definition — Stigmergic Communication & Positive Feedback:
ACO relies on stigmergy—indirect communication between autonomous agents mediated by environmental modifications (pheromone trails). The collective optimization process operates through positive feedback:

  1. Ants choose paths probabilistically based on pheromone density \(\tau_{ij}\) and heuristic visibility \(\eta_{ij}\).
  2. Ants traversing shorter paths complete tours faster, laying fresh pheromone at a higher frequency.
  3. Concurrent evaporation \((1 - \rho)\) steadily clears unused or sub-optimal paths.
  4. Over successive iterations, the colony converges stochastically on the optimal or near-optimal path.

6.2.2 Mathematical Formulation for Traveling Salesman Problem

Ant Colony Optimization is applied to the Traveling Salesman Problem (TSP), defined on a complete graph \(G = (V, E)\) with \(N\) cities (vertices). The goal is to find a Hamiltonian cycle of minimum total distance visiting every city exactly once and returning to the origin city.

1. Next State Transition Probability Rule:
An ant located at city \(i\) selects the next unvisited city \(j\) probabilistically according to the transition formula:

\[ P_{ij} = \frac{(\tau_{ij})^\alpha \cdot (\eta_{ij})^\beta}{\sum_{h \in \text{Unvisited}} (\tau_{ih})^\alpha \cdot (\eta_{ih})^\beta} \]

where:

  • \(\tau_{ij}\) is the pheromone concentration level on edge \((i, j)\).
  • \(\eta_{ij}\) is the heuristic visibility of edge \((i, j)\).
  • \(\alpha \ge 0\) controls the relative influence of pheromone trail memory.
  • \(\beta \ge 0\) controls the relative influence of local heuristic distance desirability.

2. Heuristic Visibility:
The heuristic visibility \(\eta_{ij}\) represents the local greedy desirability of edge \((i, j)\), defined as the reciprocal of spatial distance or traversal cost \(d_{ij}\):

\[ \eta_{ij} = \frac{1}{d_{ij}} \]

3. Global Pheromone Evaporation and Update Rule:
After ants complete their path traversals, pheromone levels on all graph edges undergo global evaporation and local deposition updates:

\[ \tau_{ij}^{\text{new}} = (1 - \rho) \cdot \tau_{ij}^{\text{old}} + \Delta \tau_{ij} \]

where \(\rho \in (0, 1]\) is the pheromone evaporation rate parameter.

The incremental pheromone deposit \(\Delta \tau_{ij}\) accumulated across all traversing ants is defined as:

\[ \Delta \tau_{ij} = \sum_{k=1}^K \Delta \tau_{ij}^k, \quad \Delta \tau_{ij}^k = \begin{cases} \frac{Q}{L_k} & \text{if ant } k \text{ traversed edge } (i, j) \text{ in its tour} \\ 0 & \text{otherwise} \end{cases} \]

where \(Q\) is a constant pheromone deposit parameter, and \(L_k\) is the total tour length completed by ant \(k\).

Assumptions & Scope:

  • Local Search Metaheuristic: ACO does not guarantee finding the global minimum path in every single run; it is a stochastic metaheuristic.
  • Dynamic Pheromone Updates: Intermediate city transition steps MUST evaluate updated pheromone values from preceding transitions, not static initial matrix values.
  • Parameter Sensitivity: Setting \(\alpha = 0\) reduces ACO to purely greedy local search; setting \(\beta = 0\) leads to rapid stagnation on early random trails without distance guidance.

6.2.3 Symbol Registry

Symbol registry — Ant Colony Optimization:

  • \(N\) — Total number of cities and exploring ants — \(N \in \mathbb{Z}^+\) — integer scalar
  • \(d_{ij}\) — Spatial distance or traversal cost between city \(i\) and city \(j\) — \(d_{ij} > 0\) — positive real scalar
  • \(\tau_{ij}\) — Pheromone concentration level on edge \((i, j)\) — \(\tau_{ij} \ge 0\) — real scalar
  • \(\eta_{ij}\) — Heuristic visibility of edge \((i, j)\), defined as \(\frac{1}{d_{ij}}\) — \(\eta_{ij} > 0\) — positive real scalar
  • \(\alpha\) — Pheromone importance weighting parameter — \(\alpha \ge 0\) — real scalar parameter (e.g., 0.5)
  • \(\beta\) — Heuristic distance importance weighting parameter — \(\beta \ge 0\) — real scalar parameter (e.g., 0.75)
  • \(\rho\) — Pheromone evaporation rate parameter — \(\rho \in (0, 1]\) — real scalar parameter (e.g., 0.1)
  • \(Q\) — Total pheromone deposit constant parameter — \(Q > 0\) — positive real constant (e.g., 100)
  • \(L_k\) — Total path distance of the complete tour completed by ant \(k\) — \(L_k > 0\) — positive real scalar
  • \(P_{ij}\) — Transition probability for an ant at city \(i\) to move to city \(j\) — \(P_{ij} \in [0, 1]\) — probability scalar

6.2.4 Comprehensive Worked Example: 5-City Traveling Salesman Problem

Comprehensive Worked Example — 5-City TSP Ant Colony Optimization:

Consider a 5-city Traveling Salesman Problem with cities \(\{1, 2, 3, 4, 5\}\) and an exploring ant starting at origin City 4.

Given Parameters:

  • \(\alpha = 0.5\)
  • \(\beta = 0.75\)
  • \(\rho = 0.1\)
  • \(Q = 100\)

Distance Matrix \(d_{ij}\):

\[ \begin{bmatrix} 0 & 65 & 52 & 69 & 45 \\ 65 & 0 & 39 & 28 & 55 \\ 52 & 39 & 0 & 72 & 30 \\ 69 & 28 & 72 & 0 & 40 \\ 45 & 55 & 30 & 40 & 0 \end{bmatrix} \]

Initial Pheromone Matrix \(\tau_{ij}\):

\[ \begin{bmatrix} 0 & 0.54 & 0.48 & 0.35 & 0.50 \\ 0.54 & 0 & 0.45 & 0.39 & 0.42 \\ 0.48 & 0.45 & 0 & 0.32 & 0.68 \\ 0.35 & 0.39 & 0.32 & 0 & 0.68 \\ 0.50 & 0.42 & 0.68 & 0.68 & 0 \end{bmatrix} \]

Step 1: Transition from Start City 4
Unvisited cities from City 4 are \(\{1, 2, 3, 5\}\). Probability formula:

\[ P_{4j} = \frac{(\tau_{4j})^{0.5} \cdot \left(\frac{1}{d_{4j}}\right)^{0.75}}{\sum_{h \in \{1,2,3,5\}} (\tau_{4h})^{0.5} \cdot \left(\frac{1}{d_{4h}}\right)^{0.75}} \]

Evaluating terms for candidate edges from City 4:

  • Edge (4, 1): \(\tau_{41} = 0.35\), \(d_{41} = 69\). \[ \text{Term}_{41} = (0.35)^{0.5} \cdot \left(\frac{1}{69}\right)^{0.75} \approx 0.5916 \cdot 0.0418 = 0.0247 \]
  • Edge (4, 2): \(\tau_{42} = 0.39\), \(d_{42} = 28\). \[ \text{Term}_{42} = (0.39)^{0.5} \cdot \left(\frac{1}{28}\right)^{0.75} \approx 0.6245 \cdot 0.0821 = 0.0513 \]
  • Edge (4, 3): \(\tau_{43} = 0.32\), \(d_{43} = 72\). \[ \text{Term}_{43} = (0.32)^{0.5} \cdot \left(\frac{1}{72}\right)^{0.75} \approx 0.5657 \cdot 0.0405 = 0.0229 \]
  • Edge (4, 5): \(\tau_{45} = 0.68\), \(d_{45} = 40\). \[ \text{Term}_{45} = (0.68)^{0.5} \cdot \left(\frac{1}{40}\right)^{0.75} \approx 0.8246 \cdot 0.0629 = 0.0519 \]

Denominator Sum: \(\text{Sum}_4 = 0.0247 + 0.0513 + 0.0229 + 0.0519 = 0.1508\)

Normalized Probabilities:

  • \(P_{41} = \frac{0.0247}{0.1508} \approx 0.16\)
  • \(P_{42} = \frac{0.0513}{0.1508} \approx 0.34\)
  • \(P_{43} = \frac{0.0229}{0.1508} \approx 0.15\)
  • \(P_{45} = \frac{0.0519}{0.1508} \approx 0.34\)

The maximum probability selects transition City 4 to City 2 (\(P_{42} = 0.34\)).

Step 2: Pheromone Matrix Update After Traversal (4, 2)
Evaporation multiplier: \((1 - \rho) = 1 - 0.1 = 0.9\).
Pheromone deposit on traversed edge (4, 2):

\[ \Delta \tau_{42} = \frac{Q}{d_{42}} = \frac{100}{28} \approx 3.5714 \]

Updating edge (4, 2):

\[ \tau_{42}^{\text{new}} = (0.9 \times 0.39) + 3.5714 = 0.351 + 3.5714 = 3.9224 \]

All non-traversed edges undergo pure evaporation (e.g., \(\tau_{41}^{\text{new}} = 0.9 \times 0.35 = 0.3150\), \(\tau_{12}^{\text{new}} = 0.9 \times 0.54 = 0.4860\), \(\tau_{23}^{\text{new}} = 0.9 \times 0.45 = 0.4050\), \(\tau_{25}^{\text{new}} = 0.9 \times 0.42 = 0.3780\)).

Step 3: Transition from City 2
Unvisited cities from City 2: \(\{1, 3, 5\}\).
Using updated pheromone values:

  • Edge (2, 1): \(\tau_{21} = 0.4860\), \(d_{21} = 65 \implies \text{Term}_{21} = (0.4860)^{0.5} \cdot \left(\frac{1}{65}\right)^{0.75} \approx 0.6971 \cdot 0.0437 = 0.0305\)
  • Edge (2, 3): \(\tau_{23} = 0.4050\), \(d_{23} = 39 \implies \text{Term}_{23} = (0.4050)^{0.5} \cdot \left(\frac{1}{39}\right)^{0.75} \approx 0.6364 \cdot 0.0641 = 0.0408\)
  • Edge (2, 5): \(\tau_{25} = 0.3780\), \(d_{25} = 55 \implies \text{Term}_{25} = (0.3780)^{0.5} \cdot \left(\frac{1}{55}\right)^{0.75} \approx 0.6148 \cdot 0.0495 = 0.0304\)

Denominator Sum: \(\text{Sum}_2 = 0.0305 + 0.0408 + 0.0304 = 0.1017\)
Probabilities: \(P_{21} \approx 0.30\), \(P_{23} \approx 0.40\), \(P_{25} \approx 0.30\).

Transition selected: City 2 to City 3 (\(P_{23} = 0.40\)).
Update edge (2, 3): \(\Delta \tau_{23} = \frac{100}{39} \approx 2.5641 \implies \tau_{23}^{\text{new}} = (0.9 \times 0.4050) + 2.5641 = 2.9286\).

Step 4: Transition from City 3
Unvisited cities from City 3: \(\{1, 5\}\).

  • Edge (3, 1): \(\tau_{31} = 0.4320\), \(d_{31} = 52 \implies \text{Term}_{31} \approx 0.0339\)
  • Edge (3, 5): \(\tau_{35} = 0.5508\), \(d_{35} = 30 \implies \text{Term}_{35} \approx 0.0579\)

Denominator Sum: \(0.0339 + 0.0579 = 0.0918\)
Probabilities: \(P_{31} \approx 0.37\), \(P_{35} \approx 0.63\).

Transition selected: City 3 to City 5 (\(P_{35} = 0.63\)).
Update edge (3, 5): \(\Delta \tau_{35} = \frac{100}{30} \approx 3.3333 \implies \tau_{35}^{\text{new}} = (0.9 \times 0.5508) + 3.3333 = 3.8290\).

Step 5: Deterministic Return and Total Tour Distance

  • From City 5, remaining unvisited city is City 1 (transition \(5 \to 1\)). Deposit: \(\Delta \tau_{51} = \frac{100}{45} \approx 2.2222\).
  • From City 1, return to origin City 4 (transition \(1 \to 4\)). Deposit: \(\Delta \tau_{14} = \frac{100}{69} \approx 1.4493\).

Final Hamiltonian Cycle:

\[ 4 \to 2 \to 3 \to 5 \to 1 \to 4 \]

Total Tour Distance \(L\):

\[ L = d_{42} + d_{23} + d_{35} + d_{51} + d_{14} = 28 + 39 + 30 + 45 + 69 = 211 \]

Sense Check: Every city \(\{1,2,3,4,5\}\) is visited exactly once before returning to origin City 4, confirming a valid Hamiltonian cycle.

6.2.5 Student Questions and Answers

Q: Why do we apply pheromone evaporation to edges that were not traversed by the ant during an iteration?

A: Evaporation is critical to prevent the algorithm from converging prematurely to sub-optimal early paths. By scaling non-traversed edges by \((1 - \rho)\), unvisited or infrequently visited paths gradually lose pheromone intensity. This ensures that paths that are no longer reinforced by current ant tours evaporate over time, directing future ants toward shorter paths.

Q: Does Ant Colony Optimization guarantee finding the global minimum path in every run?

A: No, ACO is a stochastic local search metaheuristic and does not guarantee finding the global optimum in a finite number of steps. A fast-moving ant or early random choice may deposit high initial pheromones along a sub-optimal route, attracting subsequent ants before optimal routes are fully explored. However, across multiple iterations, ACO consistently finds near-optimal solutions efficiently.

Q: In step-by-step hand calculations, do we use the original initial pheromone matrix for all steps or the updated values from previous transitions?

A: You must use the updated pheromone values calculated from the immediately preceding transition step. Using initial table values for subsequent city transitions is a common calculation error. Pheromones evolve dynamically after every transition.

6.3 Neural Architecture Search (NAS) and CoDeepNet

6.3.1 Motivation and Self-Designing AI

Hook & Motivation: Why rely solely on human intuition and manual trial-and-error to design complex deep neural network architectures, when evolutionary algorithms can automatically discover optimal network topologies from scratch?

Deep neural network design traditionally relies heavily on human domain experts who manually select network topologies, layer depths, kernel dimensions, skip connections, and optimization hyperparameters through trial-and-error. This manual engineering process is computationally expensive, slow, and restricted by human design biases.

Intuition & Analogy: Designing a neural network by hand is like trying to build a complex Lego castle by guessing where every single brick should go. Neural Architecture Search (NAS) acts like an automated robot builder that experiments with thousands of different Lego combinations, keeping the structural patterns that hold the most weight.

Core Definition — Self-Designing Artificial Intelligence:
Neural Architecture Search (NAS) shifts machine learning from hand-crafted architecture engineering to automated, self-designing artificial intelligence systems. By framing neural network topology selection as a search problem over a discrete space of network architectures \(\Omega\), NAS algorithms automatically discover novel deep neural network configurations optimized for specific target tasks.

6.3.2 Neuroevolution and Topology Evolution

Neuroevolution & NEAT:
Neuroevolution refers to the application of genetic algorithms and evolutionary computation to evolve neural network structures, layer parameters, and synaptic connection weights.

  • NEAT (NeuroEvolution of Augmenting Topologies): A seminal framework that incrementally evolves both edge weights and structural topologies (adding nodes and connections) from minimal initial networks using historical gene tracking to align crossover.

CoDeepNet (Co-Evolving Deep Neural Networks):
CoDeepNet extends neuroevolution to modern deep neural networks by combining genetic algorithm topology evolution with gradient descent weight optimization across two hierarchical levels:

  • Module Level: Evolves individual structural sub-graphs (e.g., convolutional blocks, dense blocks, and residual attention modules).
  • Blueprint Level: Evolves high-level macro-architectures that assemble module components into complete end-to-end deep networks.

6.3.3 Symbol Registry

Symbol registry — Neural Architecture Search and CoDeepNet:

  • \(\mathcal{A}\) — Candidate neural network architecture configuration — \(\mathcal{A} \in \Omega\) — discrete architecture space
  • \(\mathcal{F}(\mathcal{A})\) — Fitness score evaluating validation accuracy of architecture \(\mathcal{A}\) — \(\mathcal{F} \in [0, 1]\) — real scalar
  • \(w\) — Synaptic weight tensor parameters of candidate network — \(w \in \mathbb{R}^D\) — multi-dimensional tensor
  • \(\mathcal{P}_g\) — Population of candidate neural network architectures in generation \(g\) — \(\mathcal{P}_g = \{\mathcal{A}_1, \dots, \mathcal{A}_K\}\) — set of network models
  • \(\eta_{\text{learn}}\) — Learning rate hyperparameter evolved during architecture optimization — \(\eta_{\text{learn}} > 0\) — real scalar parameter

6.3.4 Five-Step Evolutionary Pipeline for NAS

Procedural Spine — The 5-Step NAS Evolutionary Pipeline:

  1. Architecture Population Initialization: Randomly generate a population of candidate network architectures \(\mathcal{P}_0 = \{\mathcal{A}_1, \mathcal{A}_2, \dots, \mathcal{A}_K\}\) with varying layer types (convolutional, pooling, fully connected), kernel sizes, and activation functions.
  2. Short-Epoch Weight Training & Proxy Fitness Evaluation: Train each candidate network architecture \(\mathcal{A}_i\) on the dataset training split for a minimal fixed number of epochs (1 to 5 epochs) using gradient descent backpropagation. Compute validation accuracy as the fitness score: \[ \mathcal{F}(\mathcal{A}_i) = \text{Accuracy}_{\text{val}}(\mathcal{A}_i; w_{\text{proxy}}) \]
  3. Parent Architecture Selection: Select top-performing candidate network architectures using roulette wheel or tournament selection based on validation fitness scores \(\mathcal{F}(\mathcal{A}_i)\).
  4. Architectural Crossover and Mutation:
    • Crossover: Swap structural blocks or layer sub-sequences between two parent network architectures to construct offspring network blueprints.
    • Mutation: Randomly modify architectural genes in offspring, such as inserting a new convolutional layer, altering filter channel counts (e.g. changing 64 filters to 128 filters), adding residual skip connections, or mutating learning rate hyperparameters \(\eta_{\text{learn}}\).
  5. Generative Evolution Loop: Replace the older architecture population with new mutated offspring architectures and repeat until target accuracy is achieved or generation budget is exhausted.

Assumptions & Scope (Computational Complexity):

  • Proxy Fitness Trade-off: Evaluating candidates over 1-2 epochs provides a relative ranking proxy. While fast, short-epoch evaluation can occasionally misrank networks that require longer training to excel.
  • Hardware Budget: NAS searches demand substantial GPU compute clusters; proxy evaluation is necessary to render architecture search computationally feasible.

6.3.5 Student Questions and Answers

Q: Why do we train candidate neural network architectures for only 1 or 2 epochs during fitness evaluation instead of full convergence?

A: Fully training every candidate deep network to convergence across hundreds of epochs for every individual in every generation would require prohibitive computational resources (thousands of GPU-hours). Short-epoch training provides a fast proxy signal that correlates well with final fully-trained model performance, allowing the genetic algorithm to evaluate hundreds of candidate architectures efficiently.

Q: How does CoDeepNet handle both network topology evolution and weight optimization simultaneously?

A: CoDeepNet decouples structural topology search from parameter weight training. The genetic algorithm handles macro-architectural evolution (adding layers, block connections, and hyperparameter selection), while standard gradient descent backpropagation optimizes connection weights within each candidate network during the fitness evaluation phase.

Genetic Algorithms for Optimization

Must-know: Genetic algorithms optimize by recombining structural building blocks (crossover) and randomly perturbing traits (mutation) across a population evaluated via a fitness-proportionate roulette wheel.

\[ p_i = \frac{f(B_i)}{\sum_{j=1}^K f(B_j)} \]

Top pitfall: Confusing roulette wheel parent selection with elimination—parents remain in the wheel and can be selected for multiple couples across runs.

Self-check: Calculate the selection probability of a candidate state with fitness 4 in a population of total fitness 13.

Connects to: 6.2 Ant Colony Optimization, 6.3 Neural Architecture Search

Ant Colony Optimization (ACO)

Must-know: ACO selects graph edges probabilistically using P_ij proportional to (tau_ij)^alpha * (eta_ij)^beta, updating pheromones via tau_new = (1-rho)*tau_old + delta_tau with eta_ij = 1/d_ij.

\[ P_{ij} = \frac{(\tau_{ij})^\alpha \cdot (\eta_{ij})^\beta}{\sum_{h \in \text{Unvisited}} (\tau_{ih})^\alpha \cdot (\eta_{ih})^\beta} \]

Top pitfall: Using initial static pheromone values for step 2/3 transitions instead of carrying forward the updated pheromone matrix values from the immediately preceding transition.

Self-check: Calculate the heuristic visibility eta_ij for an edge of distance d_ij = 28.

Connects to: 6.1 Genetic Algorithms, 6.3 Neural Architecture Search

Neural Architecture Search (NAS) and CoDeepNet

Must-know: NAS evolves neural network topologies via genetic operators (crossover of layer blocks, mutation of layer types/channels), using short-epoch validation accuracy as a fast proxy fitness evaluation.

\[ \mathcal{F}(\mathcal{A}_i) = \text{Accuracy}_{val}(\mathcal{A}_i; w_{proxy}) \]

Propositional Logic Inference Techniques

Imagine you are trapped in a dark cave. You feel a breeze from one direction but not another. There might be bottomless pits nearby. You cannot see them. But you can reason. From a few facts about breezes and pits, you can work out which squares are safe. This is exactly what a logical agent does. And this lecture is about the four ways it can do it.

A knowledge-based agent uses a knowledge base (KB) — a set of sentences about the world. From these sentences, it infers new facts. The process of drawing these conclusions is called inference. This lecture covers four inference techniques for propositional logic. These are truth tables, theorem proving, proof by contradiction with PL resolution, and the DPLL algorithm. Each one answers the same question: "does my knowledge base entail this query?" But each does it differently.

The techniques build on each other. We start with the brute-force truth table. Then we learn theorem proving, which is faster but needs intuition. Then PL resolution, which is mechanical and complete — no intuition needed. Then DPLL, which was invented in the 1950s and is the ancestor of every modern SAT solver. Along the way, we see how CNF conversion works and why contradiction is such a useful trick. By the end, you will be able to take an English problem and encode it in logic. You will know how to convert it to CNF. From there, you can prove or disprove any query using resolution.

10.1 Review — Truth Table Inferencing

10.1.1 Knowledge-Based Agents and Inferencing

Hook. How many truths can you squeeze out of a handful of facts? If I tell you "no breeze at the entrance" and "a breeze two steps east," what can you conclude? Can you work out where the pits are? This is the central puzzle of logical inference — and it is what every knowledge-based agent does.

A knowledge-based agent starts with a set of facts and rules called its knowledge base (KB). The agent's goal is to infer new knowledge — to answer queries by reasoning from what it already knows. Once the answer to a query is known, that answer becomes new knowledge. It can then be added back into the KB. The agent builds its understanding incrementally.

The art of this topic is this. Given a bunch of statements, how can we infer new rules or facts from them? This is fundamental to AI. Modern AI does it in different ways. But it all boils down to inferencing techniques. Based on rules, we deduce new information.

Intuition + Analogy. Think of a logic puzzle like a seating arrangement. You know Alice sits left of Bob. Bob does not sit next to Carol. Dave sits at the end. From just these rules, you can figure out the entire order. That is inference. Propositional logic does the same thing with formal rules. The KB is your set of given clues. Each inference step is like filling in one more seat.

But here is where the analogy breaks: in a seating puzzle, you deal with 4 or 5 people. In logic, you might deal with 7, 20, or 1000 variables. At some point, you cannot do it in your head. You need a method. The truth table is the simplest method.

Symbol Registry — Truth Table Inferencing

  • \(P_{i,j}\) — proposition: there is a pit at location \((i,j)\)
  • \(B_{i,j}\) — proposition: there is a breeze at location \((i,j)\)
  • \(KB\) — knowledge base (a set of logical sentences)
  • \(\models\) — entailment: \(KB \models \alpha\) means \(\alpha\) is true in all models where KB is true
  • \(M(\alpha)\) — set of all models in which \(\alpha\) is true
  • \(2^n\) — number of rows in a truth table for \(n\) symbols

10.1.2 Truth Table Technique with the Wumpus World

Formalize — Truth Table Inference.

Model checking is a direct implementation of the definition of entailment. A sentence \(\alpha\) entails a sentence \(\beta\), written \(\alpha \models \beta\). This means: in every model where \(\alpha\) is true, \(\beta\) is also true. In other words, \(M(\alpha) \subseteq M(\beta)\), where \(M(\alpha)\) is the set of all models that make \(\alpha\) true.

For propositional logic, a model is simply an assignment of true or false to every proposition symbol. If the KB and query together use \(n\) symbols, there are exactly \(2^n\) possible models. The truth table method enumerates all of them and checks each one. In every model where the KB is true, is the query also true?

In the Wumpus world problem, we are given a KB containing statements about pits and breezes:

  • \(R1: \neg P_{1,1}\) — there is no pit at location (1,1)
  • \(R2: B_{1,1} \leftrightarrow (P_{1,2} \lor P_{2,1})\) — a breeze at (1,1) if and only if there is a pit at (1,2) or (2,1)
  • \(R3: B_{2,1} \leftrightarrow (P_{1,1} \lor P_{2,2} \lor P_{3,1})\)
  • \(R4: \neg B_{1,1}\) — there is no breeze at (1,1)
  • \(R5: B_{2,1}\) — there is a breeze at (2,1)

The query asks: is \(\neg P_{1,2}\) (no pit at 1,2) true?

Worked Example — Truth Table on Wumpus World.

The truth table approach has 5 steps:

  1. Identify all literals. There are 7 relevant symbols: \(P_{1,1}, B_{1,1}, P_{1,2}, P_{2,1}, B_{2,1}, P_{2,2}, P_{3,1}\).
  2. Draw the full truth table. With 7 symbols, the table has \(2^7 = 128\) rows.
  3. Evaluate all rules. For each row, compute whether each rule R1 through R5 is true. Then compute the AND of all five — this is the truth of the complete KB for that row.
  4. Find rows where the KB is true. Out of 128 rows, only 3 rows have all five rules true. These are the only rows that matter. They represent the possible worlds — the states of the wumpus cave consistent with everything the agent knows.
  5. Check the query in those rows. In all 3 rows, \(P_{1,2}\) is false. So \(\neg P_{1,2}\) is true in every model of the KB. We write \(KB \models \neg P_{1,2}\).

Sense-check: The agent started knowing it was at (1,1) with no breeze. After moving to (2,1) and feeling a breeze, it can only explain this if the pits are in certain places. None of those configurations involve a pit at (1,2). So (1,2) is safe.

Visual intuition. Picture a grid of squares, each with two columns: "is pit?" and "is breeze?" The truth table is a 128-row spreadsheet. Each row is one possible arrangement of pits and breezes. You delete all rows that break any rule. Only 3 rows survive. In every surviving row, the column for \(P_{1,2}\) reads "false." The table gave you a guarantee. No matter which of the 3 possible worlds is the real one, square (1,2) is safe.

10.1.3 Limitations of Truth Table Inferencing

Scope — When truth tables work and when they break.

The truth table method is sound (every conclusion is guaranteed correct) and complete (every entailed sentence can be proved). Both properties hold because the method is a direct implementation of the mathematical definition of entailment.

Assumptions:

  • The space of models must be finite. For propositional logic with a fixed set of symbols, this is always true. For first-order logic or arithmetic (with infinite domains), model checking fails because you cannot enumerate infinitely many models.
  • The method requires that you can list all symbols. In the wumpus world, we only listed 7. But the full world has symbols for every square, orientation, and time step. For a 100×100 board over 1000 time steps, the number of symbols becomes enormous.

The truth table approach has exponential time complexity. For just 7 symbols we had 128 rows. For \(n\) symbols, there are \(2^n\) rows. In real-world problems with hundreds or thousands of variables, the truth table explodes. Propositional entailment is co-NP-complete — every known algorithm has exponential worst-case complexity.

Pitfalls:

  • Wrong symbol count. If you miss a symbol, your table is incomplete. You must include every symbol that appears in either the KB or the query.
  • Confusing rows. It is easy to miscount satisfying rows or misread the query column. Always double-check the 3 key rows.
  • Thinking "million rows is fine." \(2^{100}\) is about \(1.27 \times 10^{30}\) — far more than the number of atoms in the universe. Exponential growth is brutal.

Recap. A truth table enumerates every possible world. It keeps only the worlds where the KB is true. If the query is true in all those worlds, the KB entails the query. Simple, guaranteed correct — but exponential in cost. For more than about 30 symbols, it becomes impractical. The next three techniques all try to beat this exponential wall.

Real-world & domain connection. Truth tables are rarely used directly in practice, but they define the gold standard of what "entailment" means. Every inference algorithm is judged by whether it agrees with the truth table answer. The concept appears in digital circuit design. Engineers verify that a circuit's output matches its specification for every possible input. This is called model checking. For small circuits (few inputs), a truth table is the simplest verification tool.

10.2 Theorem Proving with Logical Equivalences

10.2.1 Logical Equivalence Rules

Hook. The truth table took 128 rows to answer one question. What if instead of listing every possible world, you could just rewrite the sentences you already have? Keep rewriting until the answer pops out. That is theorem proving — algebraic manipulation for logic.

Intuition + Analogy. Think of logical equivalences like the rules of algebra. You know that \(x + y = y + x\) and that \(-(x + y) = -x - y\). You do not draw a graph of every possible value of \(x\) to solve \(2x + 3 = 7\). You rearrange: subtract 3, divide by 2, done. Logical equivalences do the same for logic sentences. Commutativity swaps the order of AND/OR. De Morgan pushes negations inside. Double negation cancels two NOTs. Each rule is a legal rewrite. Chain enough rewrites together and you turn "I know P implies Q, and I know P" into "I know Q."

Where the analogy breaks: in algebra you usually follow a fixed order (isolate the variable). In theorem proving, you have many choices at each step. Picking the shortest path needs intuition.

10.2.2 Logical Equivalence Rules and Inference Rules

Formalize — The Equivalence Toolkit.

A set of proven logical equivalences lets us rewrite statements without changing their meaning. Two sentences \(\alpha\) and \(\beta\) are logically equivalent, written \(\alpha \equiv \beta\). This means they are true in exactly the same set of models. Equivalently, \(\alpha \equiv \beta\) if and only if \(\alpha \models \beta\) and \(\beta \models \alpha\).

The key equivalences (from Figure 7.11 of AIMA):

  • Commutativity: \(\alpha \land \beta \equiv \beta \land \alpha\); \(\alpha \lor \beta \equiv \beta \lor \alpha\)
  • Associativity: \((\alpha \land \beta) \land \gamma \equiv \alpha \land (\beta \land \gamma)\); same for \(\lor\)
  • Double negation: \(\neg(\neg\alpha) \equiv \alpha\)
  • De Morgan's laws: \(\neg(\alpha \land \beta) \equiv \neg\alpha \lor \neg\beta\); \(\neg(\alpha \lor \beta) \equiv \neg\alpha \land \neg\beta\)
  • Contraposition: \(\alpha \implies \beta \equiv \neg\beta \implies \neg\alpha\)
  • Implication elimination: \(\alpha \implies \beta \equiv \neg\alpha \lor \beta\)
  • Biconditional elimination: \(\alpha \leftrightarrow \beta \equiv (\alpha \implies \beta) \land (\beta \implies \alpha)\)
  • Distributivity of \(\lor\) over \(\land\): \(\alpha \lor (\beta \land \gamma) \equiv (\alpha \lor \beta) \land (\alpha \lor \gamma)\)

These equivalences can be used as inference rules that work in both directions (unlike Modus Ponens, which only goes forward). An inference rule is a pattern. If you have sentences matching the top half, you can add the sentence in the bottom half. A proof is a chain of such rule applications leading from the KB to the query.

Beyond equivalences, there are two one-directional inference rules that are workhorses of theorem proving:

Modus Ponens: If \(\alpha \implies \beta\) is given, and \(\alpha\) alone is also given, then you can infer \(\beta\). Written as a rule pattern:

\[ \frac{\alpha \implies \beta, \quad \alpha}{\beta} \]

Think of it like this: "If I am tired, then I need to rest" is given. "I am tired" is also given. From these two, you can conclude "I need to rest."

AND Elimination: If \(\alpha \land \beta\) is given as true, then \(\alpha\) is true and \(\beta\) is true individually. Written as:

\[ \frac{\alpha \land \beta}{\alpha} \]

When does \(\alpha \land \beta\) become true? Only when both \(\alpha\) and \(\beta\) are true. So if we are told the conjunction is true, we can infer each conjunct separately. If "tired and sleepy" is given, then "I am tired" is true and "I am sleepy" is true.

10.2.3 Worked Example — Proving \(\neg P_{1,2}\) via Theorem Proving

Symbol Registry — Wumpus World Theorem Proving

  • \(P_{i,j}\) — there is a pit at location \((i,j)\) — boolean literal
  • \(B_{i,j}\) — there is a breeze at location \((i,j)\) — boolean literal
  • \(R1\) through \(R5\) — the five rules in the knowledge base
  • \(R6\) through \(R11\) — newly generated rules during proof

Given KB:

  • \(R1: \neg P_{1,1}\)
  • \(R2: B_{1,1} \leftrightarrow (P_{1,2} \lor P_{2,1})\)
  • \(R3: B_{2,1} \leftrightarrow (P_{1,1} \lor P_{2,2} \lor P_{3,1})\)
  • \(R4: \neg B_{1,1}\)
  • \(R5: B_{2,1}\)

Query: Is \(\neg P_{1,2}\) entailed by the KB?

Proof (6 steps):

Step 1 — Biconditional elimination on R2: R2 is of the form \(\alpha \leftrightarrow \beta\) where \(\alpha = B_{1,1}\) and \(\beta = (P_{1,2} \lor P_{2,1})\). Applying biconditional elimination:

\[ R6: (B_{1,1} \implies (P_{1,2} \lor P_{2,1})) \land ((P_{1,2} \lor P_{2,1}) \implies B_{1,1}) \]

We picked R2 first and not R3 because R2 is simpler. It has \(P_{1,2}\) in it — the query variable. And it has fewer literals: 3 vs 4 in R3. Always start with the rule that brings you closer to your query.

Step 2 — AND elimination on R6: R6 is of the form \(\alpha \land \beta\). We can pick either conjunct. We pick the second one because it has \(B_{1,1}\) as the consequent. And \(R4\) already tells us \(\neg B_{1,1}\). This hints we can use contraposition and modus ponens later.

\[ R7: (P_{1,2} \lor P_{2,1}) \implies B_{1,1} \]

Step 3 — Contraposition on R7: R7 is of the form \(\alpha \implies \beta\). Contraposition says \(\alpha \implies \beta \equiv \neg\beta \implies \neg\alpha\). Here \(\alpha = (P_{1,2} \lor P_{2,1})\) and \(\beta = B_{1,1}\).

\[ R8: \neg B_{1,1} \implies \neg(P_{1,2} \lor P_{2,1}) \]

We chose contraposition because R4 gives us \(\neg B_{1,1}\) — making the antecedent of R8 true. This sets up modus ponens perfectly.

Step 4 — Modus ponens on R8 and R4: We have \(\neg B_{1,1} \implies \neg(P_{1,2} \lor P_{2,1})\) and we have \(\neg B_{1,1}\). Modus ponens lets us infer the consequent:

\[ R9: \neg(P_{1,2} \lor P_{2,1}) \]

Step 5 — De Morgan's law on R9: R9 has a negation outside an OR: \(\neg(P_{1,2} \lor P_{2,1})\). De Morgan's law says \(\neg(\alpha \lor \beta) \equiv \neg\alpha \land \neg\beta\):

\[ R10: \neg P_{1,2} \land \neg P_{2,1} \]

Step 6 — AND elimination on R10: R10 is a conjunction. AND elimination gives us each conjunct separately:

\[ R11: \neg P_{1,2} \]

R11 is exactly the query. So, the KB entails \(\neg P_{1,2}\). Done in 6 steps.

Sense-check: R11 says "no pit at (1,2)." We also learned as a byproduct that there is no pit at (2,1). This matches the truth table result — in all 3 satisfying rows, \(P_{1,2}\) was false.

The professor's intuition while solving: At every step, ask "am I going towards \(P_{1,2}\)?" Start with the query's rule. Pick the branch that sets up the next useful rule. Choose rules that bring you closer. Biconditional elimination comes first — it is the only rule for \(\leftrightarrow\). Then break apart ANDs. Then use contraposition to flip things around for modus ponens.

Visual intuition. The proof is like a chain of dominoes. R2 falls first (biconditional elimination), splitting into two connected pieces. One piece (R7) tips into contraposition (R8). R8 touches R4, and together they trigger modus ponens (R9). R9 falls into De Morgan (R10), which breaks apart into the final piece (R11). Each step is a single rule application. The chain is only as strong as your choice of which rule to apply next.

10.2.4 Intuition and Drawbacks of Theorem Proving

The theorem proving approach is much faster than truth tables — 6 steps instead of 128 rows. But it has a major drawback: it requires intuition about which rule to apply at each step.

At many points, you have multiple choices. For example:

  • After R6, you could have picked either conjunct. Picking the wrong one might still lead to the answer, but through a longer path.
  • After R7, you could have applied implication elimination instead of contraposition. You would still eventually reach the same answer, but with more steps.
  • You could have started with R3 instead of R2. R3 has more terms and does not even contain \(P_{1,2}\) directly, so the proof would be much longer.

Scope — When theorem proving works and when it breaks.

Theorem proving is sound because every inference rule has been proven to preserve truth. If premises are true, the conclusion must be true. It can be complete if the set of inference rules is enough to derive every entailed sentence. The resolution rule (Section 10.4) provides this completeness.

Assumptions and limitations:

  • The proof is only as short as your cleverness. Without a good choice of rules, you may generate hundreds of intermediate sentences before finding the answer.
  • You can exhaust all possible rules and never reach the conclusion. In that case, you can declare the query is not entailed (assuming your rule set is complete). But this takes time — you might generate R20, R30, and so on before realizing you need to backtrack.
  • There is no single guaranteed shortest path. Theorem proving is a search problem. The initial state is the KB, actions are rule applications, and the goal is a state containing the query. Any search algorithm (BFS, DFS, iterative deepening) can drive the proof — but search is not free.

Pitfalls:

  • Picking the wrong rule first. Many students try to apply modus ponens before eliminating biconditionals. Modus ponens needs an implication; it cannot work on \(\leftrightarrow\).
  • Forgetting to name the rule. The professor requires rule names at each step in exams. Writing just the new sentence without naming the rule loses marks.
  • Getting lost in derivations. If a step takes you further from the query, backtrack immediately. The query is your compass.
  • Applying rules to the wrong sentence. When you have the choice between R2 and R3 for biconditional elimination, always pick the simpler one that contains the query literal.

Key insight: The approach is not blind exploration. You know the query you want to prove: \(\neg P_{1,2}\). At every step, choose the rule that takes you closer. With practice, you develop intuition about which rules to apply when.

10.2.5 Student Q&A on Theorem Proving

Q: If we take a different approach in theorem proving, do we still reach the same answer?

A: Yes, you will get the same answer, but the number of steps will vary. If you pick the right rules, you land the answer quickly. If you pick others, you go roundabout. If at some point you get stuck, you backtrack and try a different rule. You are free to use any rule any number of times.

Q: What if I keep going roundabout and do not reach the negation — when do I conclude the query is false?

A: Suppose you exhaust all rules. No new rules can be generated. And you still cannot reach the conclusion. Then the query is false. It is not entailed.

Q: Could we have taken the other branch after AND elimination instead of the one chosen?

A: Yes. If you took the first part of R6 (\(B_{1,1} \implies (P_{1,2} \lor P_{2,1})\)), you could apply contraposition to get \(\neg(P_{1,2} \lor P_{2,1}) \implies \neg B_{1,1}\). That does not help directly because you do not have \(\neg(P_{1,2} \lor P_{2,1})\) yet. But with other steps, you would reach the same answer in a different way. There are many paths. The key is going towards what you want.

Q: When we are doing theorem proving, are we required to write the names of the rules we apply?

A: Yes, you should name the rules you apply at each step. Otherwise, nobody knows what you are inferring. This applies to exams too — rule names are required.

Recap. Theorem proving rewrites logical sentences using equivalence and inference rules. It cuts a 128-row truth table down to a 6-step proof. But its weakness is that you must pick the right rule at each step. The next technique, PL Resolution, removes the guesswork — it is a mechanical procedure with only one inference rule.

Real-world & domain connection. Automated theorem provers are used in formal verification. They prove that a chip design or a software module correctly implements its specification. Companies like Intel and AMD use theorem proving to verify processor arithmetic units. They check that a new unit will never produce a wrong result, no matter what inputs it receives. The proofs can be thousands of steps long. But each step is a simple rule application checked by a computer, not a human. In mathematics, the famous "four color theorem" was proved with the help of a computer theorem prover. It checked thousands of cases.

10.3 Proof by Contradiction

Hook. What if instead of trying to prove something is true, you prove that its opposite is impossible? That is proof by contradiction — a trick mathematicians have used for over two thousand years. And it turns out to be the secret ingredient that makes PL Resolution work.

10.3.1 Concept and Motivation

Proof by contradiction is a mathematical technique. To prove something, you assume its negation. Then you try to show that this assumption leads to a contradiction. If the negation leads to a contradiction, then the original statement must be true.

Intuition + Analogy. Imagine you are accused of breaking a window. You want to prove your innocence. You do not find a witness who saw you elsewhere. Instead, you assume you did break the window. Then you check: the window broke at 3 PM. But you were in a meeting at 3 PM, and 20 people saw you there. You cannot be in two places at once. Contradiction. So the assumption — that you broke the window — must be false. You are innocent.

In logic, the same trick works: assume the query is false. Add it to your knowledge base. If the knowledge base now contradicts itself (like containing both \(A\) and \(\neg A\)), then the assumption cannot be right. So the query must be true.

Symbol Registry — Proof by Contradiction

  • \(\square\) — empty clause, denotes a contradiction (equivalent to False)
  • \(\alpha \models \beta\) — \(\alpha\) entails \(\beta\)
  • \(\neg Q\) — negation of the query (the assumption added to KB)
  • unsatisfiable — a sentence with no model (always false)

10.3.2 How Contradiction Works in Inference

Formalize — Proof by Refutation.

Proof by contradiction is also called proof by refutation or reductio ad absurdum (Latin for "reduction to an absurdity"). The formal justification comes from a key equivalence:

\[ \alpha \models \beta \quad \text{if and only if} \quad (\alpha \land \neg\beta) \text{ is unsatisfiable} \]

In words: \(\alpha\) entails \(\beta\) exactly when the sentence "\(\alpha\) is true and \(\beta\) is false" has no model — it is impossible. This is the foundation of resolution-based inference.

For our logic problems, the contradiction technique works like this:

  1. Take the query \(Q\) you want to prove (e.g., \(\neg P_{1,2}\)).
  2. Negate it: \(\neg Q\) (which is \(P_{1,2}\) in this case — double negation cancels out).
  3. Add this negated query to your KB as an assumption — you temporarily pretend it is true.
  4. Apply inference rules as usual.
  5. If the inference leads to a contradiction (an empty clause \(\square\), or something like \(A \land \neg A\)), then:
    • The inference is false → your assumption (\(\neg Q\)) is false → the original query (\(Q\)) is true.

Worked Example — Contradiction on the Wumpus World.

We want to prove \(Q = \neg P_{1,2}\) (no pit at (1,2)). Instead of proving it directly, we use contradiction:

  1. Negate the query. \(\neg Q = P_{1,2}\). Assume there is a pit at (1,2).
  2. Add the negated query to the KB as R13: \(P_{1,2}\).
  3. Apply inference rules. From Section 10.4, the CNF clauses include R7: \(B_{1,1} \lor \neg P_{1,2}\) and R4: \(\neg B_{1,1}\). Resolving R4 with R7 gives R14: \(\neg P_{1,2}\).
  4. Now we have R13 (\(P_{1,2}\)) and R14 (\(\neg P_{1,2}\)). These are complementary — both cannot be true. This is a direct contradiction.
  5. The assumption led to a contradiction. So the assumption \(P_{1,2}\) must be false. So, \(\neg P_{1,2}\) is true.

Sense-check: We assumed a pit at (1,2). But the KB (knowing there is no breeze at (1,1)) forces that there cannot be a pit at (1,2). The two clash. So the assumption was wrong — (1,2) is safe.

Why use contradiction? For many logic-based systems, proving the negation is shorter than going directly to the true value. A simple case: if the KB already contains \(\neg P_{1,2}\) somewhere, adding \(P_{1,2}\) creates \(P_{1,2} \land \neg P_{1,2}\). This is an immediate contradiction. The assumption is instantly proved false, and the query is proved true in just one step.

Visual intuition. Imagine all possible worlds as dots on a page. The KB carves out a region of dots consistent with the facts. The query carves out another region. Proving \(KB \models Q\) means the KB region is entirely inside the Q region. Proof by contradiction works differently. It takes the region outside Q (the negated query) and adds it to the KB. Then it tries to show the combined region is empty. If KB + not-Q has no dots, then KB must be entirely inside Q.

10.3.3 Relationship to Resolution

Scope — Where proof by contradiction helps and where it does not.

The contradiction technique is useful when:

  • The inference system has a mechanical way to detect contradictions (like the empty clause in resolution).
  • The negated query is a single literal (a unit clause), which gives the resolution procedure a clean starting point.
  • The KB is already in a form where complementary literals are easy to spot.

It is less useful when:

  • You are doing pure theorem proving by hand, where a direct forward proof is often clearer.
  • The query is a complex sentence whose negation would introduce many new literals and clauses.

Pitfalls:

  • Forgetting to negate. The most common mistake is adding the query directly instead of its negation. Adding \(Q\) to prove \(Q\) is circular reasoning.
  • Double negation confusion. If the query is \(\neg P_{1,2}\), its negation is \(P_{1,2}\) (not \(\neg\neg P_{1,2}\), though that is equivalent). Cancel double negations immediately.
  • Thinking contradiction proves the query false. A contradiction means your assumption was wrong. If you assumed \(\neg Q\) and got a contradiction, then \(Q\) is true — not false.

Recap. Proof by contradiction flips the problem: instead of proving \(Q\), prove that \(\neg Q\) is impossible. Add \(\neg Q\) to your KB. If you can derive a contradiction (like \(A \land \neg A\) or the empty clause), then \(Q\) must be true. This is the engine under the hood of PL Resolution, which we cover next.

Real-world & domain connection. Proof by contradiction is a standard technique across mathematics and computer science. Euclid used it to prove there are infinitely many primes. He assumed a largest prime, then constructed a bigger one — contradiction. In computer science, it is used in complexity theory. Assume a problem is easy, then show a contradiction — so it must be hard. It is also used in program verification. Assume the program has a bug and derive a contradiction with the specification — so the program is correct. The resolution algorithm in the next section automates exactly this process.

10.4 PL Resolution Using CNF

10.4.1 What is Conjunctive Normal Form

Hook. Theorem proving needs intuition. You have to pick the right rule at every step. What if there was just ONE rule — a single mechanical operation you repeat until the answer falls out? That is resolution. And to use it, every sentence in your KB must be in one standard shape: CNF.

Symbol Registry — PL Resolution

  • CNF — Conjunctive Normal Form: conjunction of clauses, each clause is a disjunction of literals
  • \(\square\) — empty clause (contradiction)
  • unit clause — a clause with exactly one literal
  • complementary literals — a literal and its negation (e.g., \(A\) and \(\neg A\))
  • resolvent — the clause produced by cancelling complementary literals from two clauses

CNF (Conjunctive Normal Form) is a specific way of writing logical statements. A statement in CNF is a conjunction of clauses, where each clause is a disjunction of literals.

Visually:

\[ (\text{literal}_1 \lor \text{literal}_2 \lor \dots) \land (\text{literal}_3 \lor \text{literal}_4 \lor \dots) \land \dots \]

Key properties:

  • Inside every clause (every pair of parentheses), only OR gates can appear.
  • Between clauses, only AND gates connect them.
  • A single literal with no operator is also a valid clause (a "unit clause").

Formalize — CNF Grammar.

A literal is either a proposition symbol or the negation of a proposition symbol. A bare proposition symbol is a positive literal, e.g., \(A\). The negation of a proposition symbol is a negative literal, e.g., \(\neg A\). A clause is a disjunction of literals: \(\ell_1 \lor \ell_2 \lor \dots \lor \ell_k\). A sentence in CNF is a conjunction of clauses: \(C_1 \land C_2 \land \dots \land C_m\).

Example of a statement in CNF:

\[ (A \lor \neg B) \land (B \lor \neg C \lor D) \land (\neg A) \]

Here the first clause is \((A \lor \neg B)\), second is \((B \lor \neg C \lor D)\), third is the unit clause \((\neg A)\). All joined by AND.

In our Wumpus world KB, R1 (\(\neg P_{1,1}\)), R4 (\(\neg B_{1,1}\)), and R5 (\(B_{2,1}\)) are unit clauses — already in CNF. But R2 and R3 are not in CNF — they contain \(\leftrightarrow\) (double implication). Before applying PL Resolution, we must convert everything to CNF. Section 10.5 covers the conversion procedure in detail.

10.4.2 Unit Resolution Rule

The resolution rule says: take two clauses where one has a literal \(L\) and the other has its negation \(\neg L\). These are complementary literals. You can cancel them and keep whatever remains.

\[ \frac{A \lor B \quad \neg B \lor C}{A \lor C} \]

Here \(B\) and \(\neg B\) are complementary — they cancel out. What remains is \(A \lor C\).

Formalize — Full Resolution Rule.

The general resolution rule for propositional logic:

\[ \frac{\ell_1 \lor \dots \lor \ell_k, \quad m_1 \lor \dots \lor m_n}{\ell_1 \lor \dots \lor \ell_{i-1} \lor \ell_{i+1} \lor \dots \lor \ell_k \lor m_1 \lor \dots \lor m_{j-1} \lor m_{j+1} \lor \dots \lor m_n} \]

where \(\ell_i\) and \(m_j\) are complementary literals (one is the negation of the other). The resolvent contains all literals from both original clauses except the complementary pair. Each duplicate literal is removed — this is called factoring. For example, resolving \((A \lor B)\) with \((A \lor \neg B)\) yields \((A \lor A)\), which factors to just \(A\).

Why does this work? The literal \(\ell_i\) must be either true or false. If \(\ell_i\) is true, then \(m_j\) is false. Then the remaining literals of the second clause (\(m_1 \lor \dots \lor m_{j-1} \lor m_{j+1} \lor \dots \lor m_n\)) must contain at least one true literal. If \(\ell_i\) is false, then the remaining literals of the first clause must contain at least one true literal. Either way, the resolvent holds.

In PL Resolution as taught in this course, we specifically use unit resolution. In unit resolution, one side must be a unit clause (a single literal). You resolve a unit clause against another clause, cancelling exactly one pair of complementary literals.

10.4.3 The PL Resolution Technique (Three Components)

PL Resolution combines three things:

  1. CNF Format: All rules in the KB must be in CNF. If they are not, convert them first using the 4-step flowchart from Section 10.5.
  2. Contradiction: Negate the query, add it to the KB as an assumption. This is the proof-by-contradiction setup from Section 10.3.
  3. Unit Resolution: Repeatedly cancel complementary literals between a unit clause and another clause until either:
    • You reach an empty clause (denoted \(\square\)). Contradiction achieved. The inference is false → the assumption is false → the original query is true.
    • You cannot proceed further. No more complementary pairs with a unit clause exist. The resolution process fails to find a contradiction → the original query is false (not entailed).

10.4.4 Worked Example — Simple CNF Resolution Problem

Given KB in CNF:

\[ (A \lor \neg B) \land (B \lor \neg C) \land (\neg A) \]

After AND elimination, we write these as separate clauses:

\[ R1: A \lor \neg B \] \[ R2: B \lor \neg C \] \[ R3: \neg A \]

Query: \(\neg C\) — is this entailed?

Step 1 — Negate the query and add to KB: Negation of \(\neg C\) is \(C\). Add as:

\[ R4: C \]

Step 2 — Apply unit resolution:

Take R4 (\(C\), a unit) and R2 (\(B \lor \neg C\)). Complementary literals: \(C\) and \(\neg C\). Cancel them. Result:

\[ R5: B \]

Take R5 (\(B\), a unit) and R1 (\(A \lor \neg B\)). Complementary: \(B\) and \(\neg B\). Cancel. Result:

\[ R6: A \]

Take R6 (\(A\), a unit) and R3 (\(\neg A\)). Complementary: \(A\) and \(\neg A\). Cancel. Result: empty clause \(\square\).

Interpretation: We reached empty. The inference is false → our assumption (R4: \(C\)) is false → the original query (\(\neg C\)) is true. The KB does entail \(\neg C\).

Sense-check: If \(C\) were true, then from R2 we get \(B\). From R1 we get \(A\). But R3 says \(\neg A\). You cannot have both \(A\) and \(\neg A\). So \(C\) cannot be true — meaning \(\neg C\) must be true. The resolution chain mirrors exactly this line of reasoning.

Visual intuition. Imagine the clauses as a stack of cards. Each card carries a disjunction of literals. You are holding one card — a unit clause. You scan the stack for a card that contains the negation of your literal. When found, you cancel the pair and set the remaining literals from that card as your new hand. Repeat. If you ever hold an empty hand (no literals left), you have won — contradiction proved. The resolution algorithm in AIMA Figure 7.13 formalizes exactly this process. It systematically generates all possible resolvents. This continues until either the empty clause appears or no new clauses can be generated.

10.4.5 Student Q&A on PL Resolution

Q: Why can't we take R2 and R3 and cancel B directly without a unit clause?

A: Because neither R2 (\(B \lor \neg C\)) nor R3 (\(\neg A\)) is a unit clause — both have more than one literal. In unit resolution, one side must be a unit clause (a single literal standing alone). You always cancel between a unit and a larger clause. The full resolution rule does allow resolving two non-unit clauses, but the course focuses on unit resolution.

Q: If the empty set is not reached in PL Resolution, what does that mean?

A: If you cannot reach empty, you have not proved a contradiction. This happens when you cannot find any more complementary pairs with a unit clause. The resolution process did not succeed. In a complete resolution system, failure to derive the empty clause means the sentence \((KB \land \neg Q)\) is satisfiable. There exists at least one model where the KB is true and the query is false. So, the original query is not entailed by the KB.

Q: What is the meaning of reaching an empty clause?

A: The empty clause \(\square\) means a contradiction has been attained. It is equivalent to False — a disjunction of zero disjuncts, which can never be true. You negated the query and added it to your KB. If you arrive at an empty clause, your assumption led to a contradiction. So the assumption was false, making the original query true.

Q: What if we reach the empty clause without using the assumed (negated) query?

A: That is fine. Any resolution, with or without the assumed rule, can be used. If you can reach empty through other resolutions, that also shows the KB is inconsistent. In practice, the assumed rule is a unit clause (a single negated literal), so it almost always plays a role. But using it is not strictly required.

Q: Is resolution the same as elimination?

A: No. Use the term "resolution" — that is the actual rule. "Elimination" can cause confusion because there are other types (biconditional elimination, AND elimination, implication elimination). Resolution specifically means cancelling complementary literals from two clauses to produce a new clause.

Q: Does the query need to be part of the KB's literal set?

A: Yes. The query should involve literals that appear in the KB. If the query asks about a literal \(D\) that never appears in any KB clause, the KB has no information about \(D\). Resolution would not be able to derive anything about it. The query is meaningless for that KB.

Pitfalls:

  • Resolving without CNF. The most common mistake: trying to apply resolution directly to sentences that still contain \(\implies\) or \(\leftrightarrow\). Convert to CNF first — always.
  • Resolving two non-unit clauses. The course uses unit resolution. You must always resolve a unit clause against another clause. Do not resolve two multi-literal clauses against each other.
  • Forgetting to negate. Adding the query directly instead of its negation is a critical error. If you want to prove \(\neg C\), you must add \(C\), not \(\neg C\).
  • Misinterpreting the empty clause. Empty means the query IS entailed (true). No empty means it is NOT entailed (false). Students often flip this.

Recap. PL Resolution is a mechanical inference procedure. Put the KB in CNF. Negate the query and add it. Repeatedly cancel complementary literals between unit clauses and other clauses. If you reach the empty clause, the query is proved true. No intuition needed — just follow the algorithm. Section 10.5 shows how to convert any sentence to CNF. Section 10.6 presents DPLL, which builds on CNF to do satisfiability checking efficiently.

Real-world & domain connection. Resolution is the foundation of automated theorem proving. The programming language Prolog uses a restricted form of resolution (SLD resolution) as its execution mechanism. Every time you run a Prolog program, the interpreter is performing resolution behind the scenes. SAT solvers — used by companies like Intel and Microsoft for chip verification — take CNF as input. They use resolution (among other techniques) to find satisfying assignments or prove unsatisfiability. The annual SAT competition benchmarks solvers on industrial problems with millions of variables and clauses.

10.5 CNF Conversion

Hook. You have a sentence like "breeze if and only if pit at left or pit at right." It has a double arrow. PL Resolution cannot handle it. The resolution rule eats only one format: CNF — clauses of ORs joined by ANDs. How do you turn any logic sentence into that shape? There is a four-step recipe. Follow it exactly, in order, every time.

Symbol Registry — CNF Conversion

  • CNF — Conjunctive Normal Form
  • \(\leftrightarrow\) — biconditional (if and only if)
  • \(\implies\) — implication (if-then)
  • \(\lor\) — disjunction (OR)
  • \(\land\) — conjunction (AND)
  • \(\neg\) — negation (NOT)

10.5.1 The Four-Step Conversion Flowchart

Purpose. CNF conversion transforms any propositional logic sentence into Conjunctive Normal Form. CNF is a conjunction of clauses. Each clause is a disjunction of literals. This is the required input format for the PL Resolution algorithm and for SAT solvers like DPLL.

Inputs & Outputs.

  • Input: Any well-formed sentence of propositional logic, possibly containing \(\neg\), \(\land\), \(\lor\), \(\implies\), and \(\leftrightarrow\).
  • Output: A logically equivalent sentence in CNF — a conjunction of one or more clauses, each clause being a disjunction of literals. The output may be longer (more clauses) than the input.

Steps — The Four-Step Flowchart.

The order matters. Do not skip steps. Do not reorder them.

Step 1 — Eliminate biconditionals (\(\leftrightarrow\)). Replace every occurrence of \(\alpha \leftrightarrow \beta\) with \((\alpha \implies \beta) \land (\beta \implies \alpha)\).

Why this step first? Because \(\leftrightarrow\) is the outermost connective that must be removed. No other rule directly eliminates it. This step may double the number of sub-formulas but it must come first.

Step 2 — Eliminate implications (\(\implies\)). Replace every occurrence of \(\alpha \implies \beta\) with \(\neg\alpha \lor \beta\).

Why second? Because after Step 1, the only remaining non-CNF connectives are \(\implies\). Convert them all to \(\lor\) and \(\neg\). After this step, your sentence uses only \(\neg\), \(\land\), and \(\lor\).

Step 3 — Push negations inward (De Morgan + double negation). Move every \(\neg\) symbol inward until it applies only to individual proposition symbols (literals). Apply these transformations repeatedly, wherever they match:

  • \(\neg(\neg\alpha) \equiv \alpha\) (double negation elimination)
  • \(\neg(\alpha \land \beta) \equiv \neg\alpha \lor \neg\beta\) (De Morgan)
  • \(\neg(\alpha \lor \beta) \equiv \neg\alpha \land \neg\beta\) (De Morgan)

After this step, no negation operator sits outside a parenthesis. Every \(\neg\) is directly attached to a proposition symbol.

Step 4 — Distribute \(\lor\) over \(\land\). Wherever you find a pattern \(\alpha \lor (\beta \land \gamma)\), apply distributivity:

\[ \alpha \lor (\beta \land \gamma) \equiv (\alpha \lor \beta) \land (\alpha \lor \gamma) \]

This is only needed when an OR sits outside an AND. If a clause already has only ORs inside its parentheses, it is already in CNF — leave it alone.

After these four steps, the result is guaranteed to be in CNF.

10.5.2 Worked Example — Converting R2 to CNF

R2 is: \(B_{1,1} \leftrightarrow (P_{1,2} \lor P_{2,1})\)

Trace — Full conversion of R2 to CNF.

Step 1 — Biconditional elimination: Replace \(\alpha \leftrightarrow \beta\) with \((\alpha \implies \beta) \land (\beta \implies \alpha)\), where \(\alpha = B_{1,1}\) and \(\beta = (P_{1,2} \lor P_{2,1})\):

\[ (B_{1,1} \implies (P_{1,2} \lor P_{2,1})) \land ((P_{1,2} \lor P_{2,1}) \implies B_{1,1}) \]

Step 2 — Implication elimination: Apply \(\alpha \implies \beta \equiv \neg\alpha \lor \beta\) to both implications:

\[ (\neg B_{1,1} \lor P_{1,2} \lor P_{2,1}) \land (\neg(P_{1,2} \lor P_{2,1}) \lor B_{1,1}) \]

Step 3 — De Morgan on the second part: The second clause has \(\neg(P_{1,2} \lor P_{2,1})\). Apply De Morgan:

\[ \neg(P_{1,2} \lor P_{2,1}) \equiv \neg P_{1,2} \land \neg P_{2,1} \]

Substituting back, the second clause becomes \((\neg P_{1,2} \land \neg P_{2,1}) \lor B_{1,1}\).

The full expression after Step 3:

\[ (\neg B_{1,1} \lor P_{1,2} \lor P_{2,1}) \land ((\neg P_{1,2} \land \neg P_{2,1}) \lor B_{1,1}) \]

The first clause \((\neg B_{1,1} \lor P_{1,2} \lor P_{2,1})\) is already in CNF — it has only ORs inside. The second clause is not yet in CNF because it has an AND inside an OR.

Step 4 — Distributivity on the second clause: The second clause matches the pattern \(\alpha \lor (\beta \land \gamma)\) with \(\alpha = B_{1,1}\), \(\beta = \neg P_{1,2}\), \(\gamma = \neg P_{2,1}\). Distribute:

\[ (B_{1,1} \lor \neg P_{1,2}) \land (B_{1,1} \lor \neg P_{2,1}) \]

Final CNF for R2:

\[ (\neg B_{1,1} \lor P_{1,2} \lor P_{2,1}) \land (B_{1,1} \lor \neg P_{1,2}) \land (B_{1,1} \lor \neg P_{2,1}) \]

Sense-check: The original R2 had one sentence with a \(\leftrightarrow\) and 3 literals. The CNF version has three clauses with 8 total literal occurrences. It is uglier but mechanically usable. Verify by checking one case. Suppose \(B_{1,1}\) is false, \(P_{1,2}\) is false, and \(P_{2,1}\) is false. The original R2 says "false \(\leftrightarrow\) (false \(\lor\) false)" = "false \(\leftrightarrow\) false" = true. In CNF: clause 1 = \((\text{true} \lor \text{false} \lor \text{false})\) = true. Clause 2 = \((\text{false} \lor \text{true})\) = true. Clause 3 = \((\text{false} \lor \text{true})\) = true. All true. Matches.

Distributivity check (when to apply): The rule \(\alpha \lor (\beta \land \gamma) \equiv (\alpha \lor \beta) \land (\alpha \lor \gamma)\) only applies when there is a mix — outside is OR, inside is AND. If outside is OR and inside is also OR, the clause is already CNF — leave it alone. If outside is AND and inside is OR, it is also already CNF. The only problem pattern is OR-outside-AND-inside.

10.5.3 Full Set of CNF Clauses for the Wumpus World

After converting both R2 and R3 (R3 follows the same 4-step process), the complete KB in CNF becomes:

  • \(R1: \neg P_{1,1}\)
  • \(R4: \neg B_{1,1}\)
  • \(R5: B_{2,1}\)
  • \(R6: \neg B_{1,1} \lor P_{1,2} \lor P_{2,1}\) (from R2)
  • \(R7: B_{1,1} \lor \neg P_{1,2}\) (from R2)
  • \(R8: B_{1,1} \lor \neg P_{2,1}\) (from R2)
  • (More clauses from R3 conversion)

Every rule is now in CNF. No implications, no double implications — just ORs inside clauses joined by ANDs. We can now apply PL Resolution.

10.5.4 Full PL Resolution on Wumpus World \(\neg P_{1,2}\)

Query: \(\neg P_{1,2}\) — is there no pit at (1,2)?

Trace — PL Resolution on Wumpus CNF.

Step 1 — Negate the query and add to KB: Negation of \(\neg P_{1,2}\) is \(P_{1,2}\). Add:

\[ R13: P_{1,2} \]

Step 2 — Apply unit resolution:

Take R4 (\(\neg B_{1,1}\), a unit) and R7 (\(B_{1,1} \lor \neg P_{1,2}\)). Complementary literals: \(B_{1,1}\) and \(\neg B_{1,1}\). Cancel them:

\[ R14: \neg P_{1,2} \]

Take R13 (\(P_{1,2}\), a unit) and R14 (\(\neg P_{1,2}\)). Complementary literals: \(P_{1,2}\) and \(\neg P_{1,2}\). Cancel. Result:

\[ \square \quad \text{(empty clause)} \]

Conclusion: We reached empty. Contradiction achieved. The inference is false → the assumption (R13) is false → the original query (\(\neg P_{1,2}\)) is true. There is no pit at (1,2).

Sense-check: This matches the result from all three previous techniques — truth table, theorem proving, and now PL Resolution. All four methods agree.

Why choose R7 over R8? We picked R7 because cancelling \(B_{1,1}\) with R4 leaves \(\neg P_{1,2}\), which is directly related to our query. Had we picked R8, we would have been left with \(\neg P_{2,1}\) — not what we are looking for. Always resolve in the direction of your query.

10.5.5 Complexity and Practical Considerations

Complexity & Cost. Converting a sentence to CNF can cause exponential blowup in the worst case. For example, converting \((A_1 \land B_1) \lor (A_2 \land B_2) \lor \dots \lor (A_n \land B_n)\) to CNF produces \(2^n\) clauses. In practice, a trick called Tseitin transformation avoids this by introducing auxiliary variables. The resulting CNF is not logically equivalent but is equisatisfiable (has the same satisfiability). For this course, use the 4-step flowchart on the sentences given; they are designed not to explode.

When to use: CNF conversion is a prerequisite step whenever you plan to use resolution or a SAT solver. If you are doing truth tables or pure theorem proving, you do not need CNF.

Alternatives: For Horn clause knowledge bases, each clause has at most one positive literal. You can use forward chaining or backward chaining directly — no CNF conversion needed. These are covered in the next lecture on predicate logic.

Pitfalls:

  • Wrong step order. Doing De Morgan before eliminating implications creates extra work and may lead to errors. Follow the sequence exactly.
  • Missing distributivity. Students often stop after Step 3, producing a formula that still has AND-inside-OR. It is not CNF yet. Always check for distributivity.
  • Applying distributivity to OR-inside-OR. The formula \((A \lor B \lor C)\) is already a single CNF clause. Do not distribute it.

Recap. CNF conversion is a 4-step pipeline: eliminate \(\leftrightarrow\), eliminate \(\implies\), push negations inward with De Morgan, distribute \(\lor\) over \(\land\). Follow the order. The output is a conjunction of OR-clauses, ready for resolution. This conversion underlies every SAT solver and every application of PL Resolution.

Real-world & domain connection. CNF is the standard input format for the DIMACS CNF file format used by virtually every SAT solver. These include the ones that verify microprocessors at Intel. They also prove security properties of network protocols and solve Sudoku puzzles. A software verification tool like CBMC (C Bounded Model Checker) checks your C program for bugs. It converts the program into a CNF formula and feeds it to a SAT solver like MiniSAT or Glucose. The 4-step conversion you learn here is the same process, applied at industrial scale.

10.6 The DPLL Algorithm

Hook. The truth table drew 128 rows to find 3 that mattered. What a waste. What if you could skip the 125 useless rows and walk straight to the satisfying ones? That is exactly what DPLL does. It builds a tree, prunes dead branches early, and finds solutions without enumerating the world.

10.6.1 Motivation — Avoiding Full Truth Table Enumeration

Recall the truth table approach. With 7 literals, we drew all 128 rows. But only 3 rows had the KB as true. The other 125 rows were useless. The DPLL algorithm (Davis–Putnam–Logemann–Loveland) asks: why draw all 128 rows? Can we directly find those 3 rows without enumerating everything?

Symbol Registry — DPLL Algorithm

  • DPLL — Davis–Putnam–Logemann–Loveland algorithm
  • SAT — Boolean satisfiability problem
  • pure symbol — a literal that appears with the same polarity in all clauses
  • unit clause — a clause with only one unassigned literal
  • unit propagation — cascade of forced assignments from unit clauses

Purpose. DPLL is a backtracking-based search algorithm for determining the satisfiability of propositional logic formulas in CNF. It answers the question: "Is there any assignment of true/false to the symbols that makes every clause true?" If yes, the formula is satisfiable. If no, it is unsatisfiable. To check entailment (\(KB \models \alpha\)), DPLL tests whether \(KB \land \neg\alpha\) is unsatisfiable — the standard refutation approach.

DPLL was developed in the 1950s (Davis & Putnam, 1960; Davis, Logemann & Loveland, 1962) for mathematical logic. This was long before modern AI. It is connected to the Boolean satisfiability problem (SAT), the classic NP-complete problem in computer science. Modern SAT solvers are direct descendants of DPLL.

Inputs & Outputs.

  • Input: A set of clauses in CNF, and a list of proposition symbols.
  • Output: Either a satisfying model (an assignment of true/false to every symbol that makes all clauses true) or "unsatisfiable."

10.6.2 Pure Symbolic Literals

A pure symbolic literal is a literal that maintains the same polarity across all clauses in which it appears. It is either always positive (never negated) or always negative (never appearing without negation). If it does not appear in some clauses, that is fine — "not available" is not a polarity flip.

Steps — Identifying Pure Symbols (The Matrix Method).

Create a table with rules as rows and literals as columns. For each cell, mark:

  • T if the literal appears positively (without negation) in that clause
  • F if the literal appears negatively (with negation) in that clause
  • — if the literal does not appear in that clause

Example with three clauses:

  • \(C1: A \lor B \lor \neg C\)
  • \(C2: \neg B \lor A\)
  • \(C3: C \lor D\)
ClauseABCD
C1TTF—
C2TF——
C3——TT
  • A: T, T, — → never flips → pure symbol (always positive)
  • B: T, F, — → flips between T and F → not pure
  • C: F, —, T → flips between F and T → not pure
  • D: —, —, T → never flips → pure symbol (always positive)

Pure symbols are important because you start the DPLL search tree with a pure symbol. A pure symbol can be assigned the value that makes all its occurrences true without ever making a clause false. For a positive pure symbol (always T in the matrix), set it to true. For a negative pure symbol (always F in the matrix), set it to false. This is the pure symbol heuristic.

10.6.3 Tree-Based Search for Satisfying Assignments

DPLL builds a tree where each node is a literal with two branches. The branches are: assign it true, or assign it false. Then it propagates the consequences through the clauses to find which assignments make every clause true.

Steps — The DPLL Algorithm.

The algorithm uses three heuristics to prune the search:

  1. Early termination. If every clause is already true under the current partial assignment, return "satisfiable" immediately. There is no need to assign remaining variables. If any clause is false (all its literals are false), backtrack immediately — this branch is dead.
  2. Pure symbol heuristic. Find a symbol that appears with only one polarity in all remaining (not-yet-satisfied) clauses. Assign it the value that makes all its literals true. This is always safe — it never makes a clause false.
  3. Unit clause heuristic. A unit clause is a clause with only one unassigned literal. All other literals in it are already false under the current partial assignment. The remaining literal must be true for the clause to hold. Assign it immediately. This can cascade — assigning one unit clause may create another (called unit propagation).

The algorithm in pseudocode (from AIMA Figure 7.17):

function DPLL(clauses, symbols, model):
    if every clause is true in model: return true
    if some clause is false in model: return false
    P, value = FIND-PURE-SYMBOL(symbols, clauses, model)
    if P is not null: return DPLL(clauses, symbols - P, model ∪ {P=value})
    P, value = FIND-UNIT-CLAUSE(clauses, model)
    if P is not null: return DPLL(clauses, symbols - P, model ∪ {P=value})
    P = FIRST(symbols)
    rest = REST(symbols)
    return DPLL(clauses, rest, model ∪ {P=true})
           or DPLL(clauses, rest, model ∪ {P=false})

DPLL is essentially a depth-first search with smart pruning. It is sound (only returns true for satisfiable formulas) and complete (always finds a model if one exists) for propositional logic.

10.6.4 Worked Example with Wumpus World Rules

Consider two clauses from our CNF:

  • \(C1: \neg P_{1,2} \lor B_{1,1}\)
  • \(C2: \neg P_{2,1} \lor B_{1,1}\)

Literals involved: \(P_{1,2}, B_{1,1}, P_{2,1}\) — three literals.

Trace — DPLL on a tiny Wumpus CNF.

Step 1 — Build the purity matrix:

Clause\(P_{1,2}\)\(B_{1,1}\)\(P_{2,1}\)
C1FT—
C2—TF

  • \(B_{1,1}\): T, T → never flips → pure symbol (always positive)
  • \(P_{2,1}\): —, F → never flips → pure symbol (always negative)

All three are pure symbols. Start with \(P_{1,2}\):

Step 2 — Branch on \(P_{1,2} = \text{true}\): Substitute into C1: \(\neg(\text{true}) \lor B_{1,1}\) → \(\text{false} \lor B_{1,1}\). For C1 to be true, \(B_{1,1}\) must be true (since the other disjunct is false). So \(B_{1,1} = \text{true}\) is forced.

Now check C2 with \(B_{1,1} = \text{true}\): \(\neg P_{2,1} \lor \text{true}\) → true regardless of \(P_{2,1}\). So \(P_{2,1}\) is don't care.

Satisfying assignment: \(P_{1,2} = T, B_{1,1} = T, P_{2,1} = \text{don't care}\).

Step 3 — Branch on \(P_{1,2} = \text{false}\): Substitute into C1: \(\neg(\text{false}) \lor B_{1,1}\) → \(\text{true} \lor B_{1,1}\) → true regardless of \(B_{1,1}\). So \(B_{1,1}\) is don't care for this branch.

Now branch on \(B_{1,1}\):

  • Sub-branch: \(B_{1,1} = \text{true}\): C2: \(\neg P_{2,1} \lor \text{true}\) → true. \(P_{2,1}\) don't care.
  • Sub-branch: \(B_{1,1} = \text{false}\): C2: \(\neg P_{2,1} \lor \text{false}\) → for C2 to be true, \(\neg P_{2,1}\) must be true → \(P_{2,1}\) must be false. Satisfaction: \(P_{1,2} = F, B_{1,1} = F, P_{2,1} = F\).

Summary: Instead of drawing \(2^3 = 8\) truth table rows and filtering, DPLL gave us the satisfying assignments directly. The assignments are: (T, T, —) and (F, F, F), plus the don't-care extensions. In the original Wumpus world with 128 rows, DPLL would find just the 3 satisfying rows directly — no enumeration needed.

Sense-check: The DPLL tree pruned branches as soon as clauses were satisfied. The \(P_{1,2} = T\) branch forced a single assignment. The \(P_{1,2} = F\) branch required one more decision. This is exactly the efficiency gain: explore only the decisions that matter.

Key idea: DPLL is the reverse logic of the truth table. The truth table enumerates everything and then filters. DPLL starts with the problem and takes pure symbols. It assigns true/false values and reverse-engineers which assignments make the KB true.

10.6.5 Student Q&A on DPLL

Q: In the don't-care case, do we need to write both true and false values?

A: No, you can just put a dash. Don't-care means the clause is satisfied regardless of that variable's value. You do not need to enumerate both possibilities.

Q: If a literal is not available in some rules, do we assume it follows the trend from other rules?

A: No. "Not available" simply means the literal does not appear in that clause. It does not affect purity — only actual appearances matter. A literal is pure if it never flips polarity across the clauses where it does appear. Absence is neutral.

Q: How do we decide which literal to start the DPLL tree with?

A: You can start with any pure symbolic literal. If there are multiple pure symbols, pick any one. Do not start with a non-pure symbol. Pure symbols are safe choices — they never force a clause to become false.

Q: How do Karnaugh maps compare to DPLL?

A: They are entirely different. DPLL is a general algorithm for checking satisfiability: given rules, find an assignment that makes them all true. K-maps (Karnaugh maps) are a diagrammatic method for simplifying Boolean expressions in digital circuit design. Different purpose, different domain. DPLL is about finding any satisfying assignment; K-maps are about finding the simplest equivalent expression.

10.6.6 Complexity and Modern Extensions

Complexity & Cost. DPLL has worst-case exponential time complexity. SAT is NP-complete, so no algorithm can guarantee polynomial time for all instances (unless P = NP). In practice, DPLL with modern enhancements solves problems with millions of variables. The key innovations that made this possible:

  • Component analysis: If clauses split into disjoint sets with no shared variables, solve each component independently.
  • Variable ordering (degree heuristic): Branch on the variable that appears most often in remaining clauses.
  • Conflict clause learning: When backtracking, record the reason for the conflict as a new clause. This prevents the same dead end from being explored again.
  • Random restarts: If progress stalls, restart with a different random seed, keeping learned clauses.
  • Watched literals: An indexing trick that makes unit propagation extremely fast.

When to use DPLL vs alternatives:

  • DPLL (or modern SAT solvers) is the right tool for checking satisfiability of general propositional formulas in CNF.
  • For Horn clauses only (at most one positive literal per clause), forward/backward chaining runs in linear time — much faster.
  • For small formulas (< 20 variables), a truth table may be faster and simpler.
  • WALKSAT (a local search algorithm) is faster for some satisfiable problems but cannot prove unsatisfiability.

Pitfalls:

  • Starting with a non-pure symbol. This defeats the pruning advantage. Always identify pure symbols first.
  • Confusing polarity. In the matrix, T means the literal appears positive (e.g., \(A\)), F means it appears negative (e.g., \(\neg A\)). Do not confuse the polarity of the literal with the truth value you assign.
  • Forgetting unit propagation cascades. When one unit clause assignment forces another, you must follow the chain. This is the most powerful pruning mechanism in DPLL.

Recap. DPLL searches for a satisfying assignment by building a decision tree. It uses pure symbols and unit clauses to prune branches early. It avoids the exponential enumeration of truth tables. Instead of asking "what could be true," it asks "what must be true." Modern SAT solvers are DPLL descendants that handle millions of variables. The last section previews predicate logic, where we will see inference techniques for a richer language.

Real-world & domain connection. DPLL-based SAT solvers are used throughout the tech industry. Intel and AMD verify processor designs by encoding them as CNF. They check that no input produces a wrong output. Microsoft uses SAT solvers for Windows driver verification. Google's OR-Tools library includes a SAT solver for constraint optimization. The annual SAT competition (since 2002) drives solver improvements. Winning solvers like Glucose, Lingeling, and MapleSAT are all DPLL descendants. When you run pip install python-sat, the solver under the hood is a modern DPLL.

10.7 Predicate Logic Preview

10.7.1 Why Propositional Logic is Not Enough

Hook. Propositional logic can say "pit at (1,2)" and "breeze at (1,1)." But can it say "every square adjacent to a pit has a breeze"? No. It would need a separate sentence for each of the 16 squares, each of the 4 directions, each of the time steps. That is why we need a richer language.

Symbol Registry — Predicate Logic Preview

  • \(\forall\) — universal quantifier ("for all", "every")
  • \(\exists\) — existential quantifier ("there exists", "some")
  • forward chaining — data-driven inference from known facts to new facts
  • backward chaining — goal-directed inference from query back to known facts

Formalize — The Limits of Propositional Logic.

Propositional logic has a fundamental limitation: it cannot express quantified statements. It deals only with individual, named propositions — each \(P_{i,j}\) is a separate symbol. There is no way to say "there exists" or "for all."

Consider these examples:

  • "Some students are brilliant" — the word "some" (\(\exists\)) cannot be represented. You would need to list every student and say "student-1 is brilliant OR student-2 is brilliant OR ..." This is impossible if you do not know how many students there are.
  • "All women are beautiful" — the word "all" (\(\forall\)) is equally impossible. You would need to write "woman-1 is beautiful AND woman-2 is beautiful AND ..." — again, impossible without a fixed list.

This is why we need predicate logic (first-order logic), which introduces quantifiers:

  • \(\exists\) (exists) — for "some", "there exists", "at least one"
  • \(\forall\) (for all) — for "all", "every", "each"

With quantifiers, you can write: \(\forall x\ \text{Student}(x) \implies \text{Brilliant}(x)\) — a single sentence covering every student. This is the expressive power propositional logic lacks.

10.7.2 What is Coming — Predicate Logic

Intuition. Think of propositional logic as dealing with fixed objects — "this specific pit," "that specific breeze." Predicate logic adds variables and quantifiers, letting you talk about patterns. For any square, if it has a breeze, then one of its neighbors has a pit. It is the difference between listing every employee's salary by name and writing a formula: "salary = base + experience × rate".

Everything else stays the same. You can still do truth tables, theorem proving, and resolution with predicate logic. But predicate logic introduces two main inference techniques:

  • Forward chaining: Starting from known facts and applying rules to derive new facts. This is data-driven — new percepts trigger new inferences automatically. Example: if the agent smells a stench at (1,2), forward chaining adds "wumpus is at (1,1), (1,3), or (2,2)."
  • Backward chaining: Starting from a query and working backwards to see if known facts support it. This is goal-directed — you only do work relevant to answering the specific question. Example: the agent asks "is (2,2) safe?" and backward chaining traces through the rules to check whether a pit or wumpus could be there.

Forward chaining and backward chaining are the two main inference techniques for predicate logic. Both run in linear time for Horn clause knowledge bases.

Pitfalls:

  • Confusing propositional and predicate. Propositional logic symbols are indivisible atoms (\(P_{1,2}\) is one symbol, not a function of 1 and 2). Predicate logic uses predicates with arguments: \(Pit(x, y)\) or \(Breeze(1, 1)\). Do not treat the subscripts in \(P_{1,2}\) as predicate arguments — they are part of the symbol name.
  • Thinking you are done. This lecture covers propositional logic. Predicate logic is the next lecture. But the four techniques you learned (truth table, theorem proving, PL resolution, DPLL) carry forward. The resolution rule, in particular, generalizes to first-order logic with the addition of unification — matching variables to terms.

Recap. Propositional logic cannot say "all" or "some." Predicate logic adds quantifiers (\(\forall\), \(\exists\)) and predicates to express patterns over domains. The next lecture covers forward chaining and backward chaining for predicate logic inference. Together, propositional and predicate logic form the complete logic and inference module.

Real-world & domain connection. Predicate logic (first-order logic) is the foundation of the Prolog programming language. It is used in expert systems and natural language processing. Prolog programs are essentially Horn clause knowledge bases, and Prolog's execution is backward chaining with unification. IBM's Watson used first-order logic representations for parts of its Jeopardy-playing system. The Semantic Web's OWL (Web Ontology Language) is based on description logics. These are decidable fragments of first-order logic. They are used by organizations for knowledge representation. These include the BBC, the New York Times, and the US National Cancer Institute.

Truth Table Inferencing

Must-know: A truth table enumerates all \(2^n\) models and keeps only rows where the KB is true. If the query holds in every surviving row, then \(KB \models \text{query}\). It is sound and complete but exponential — impractical beyond ~30 symbols.

\[ M(\alpha) \subseteq M(\beta) \quad \text{means} \quad \alpha \models \beta \]

⚠️ Top pitfall: Missing a symbol in the table. You must list every literal that appears in the KB or the query, or your rows are incomplete.

Self-check: With 7 literals, how many rows does the table have, and what does it mean if only 3 rows satisfy the KB?

Connects to: Theorem proving, PL Resolution, DPLL — all answer the same entailment question without full enumeration.

Theorem Proving with Equivalences

Must-know: Rewrite sentences using equivalence rules (De Morgan, contraposition, biconditional/implication elimination) and one-way rules (Modus Ponens, AND Elimination). Always name the rule at each step. Pick rules that move you toward the query.

\[ \frac{\alpha \implies \beta, \quad \alpha}{\beta} \quad \text{(Modus Ponens)} \qquad \alpha \leftrightarrow \beta \equiv (\alpha \implies \beta) \land (\beta \implies \alpha) \]

⚠️ Top pitfall: Applying Modus Ponens before eliminating a biconditional. Modus Ponens needs an implication; it cannot fire on \(\leftrightarrow\).

Self-check: Why is theorem proving faster than a truth table here, and what is its main weakness?

Connects to: CNF conversion (uses the same equivalence rules), PL Resolution.

Proof by Contradiction

Must-know: To prove \(Q\), assume \(\neg Q\), add it to the KB, and derive a contradiction. If \(KB \land \neg Q\) is unsatisfiable, then \(KB \models Q\). This is the engine behind resolution.

\[ \alpha \models \beta \quad \text{iff} \quad (\alpha \land \neg\beta) \text{ is unsatisfiable} \]

⚠️ Top pitfall: Forgetting to negate the query. Adding \(Q\) to prove \(Q\) is circular. If the query is \(\neg P_{1,2}\), the assumption is \(P_{1,2}\).

Self-check: If assuming \(\neg Q\) leads to a contradiction, is \(Q\) true or false?

Connects to: PL Resolution (the contradiction is the empty clause), CNF conversion.

PL Resolution and CNF

Must-know: Put the KB in CNF, negate the query and add it, then repeatedly cancel complementary literals between a unit clause and another clause. Reaching the empty clause \(\square\) proves the query true. No intuition needed — it is mechanical.

\[ \frac{A \lor B \quad \neg B \lor C}{A \lor C} \qquad \text{empty clause } \square \text{ means contradiction} \]

⚠️ Top pitfall: Resolving two non-unit clauses, or resolving before converting to CNF. The course uses unit resolution only, and only on CNF clauses.

Self-check: What does reaching the empty clause tell you about the query, and what if you cannot reach it?

Connects to: CNF conversion (4-step flowchart), proof by contradiction, DPLL.

CNF Conversion (Four Steps)

Must-know: Convert any sentence to CNF in this fixed order: (1) eliminate \(\leftrightarrow\), (2) eliminate \(\implies\), (3) push negations inward with De Morgan, (4) distribute \(\lor\) over \(\land\). CNF = AND of OR-clauses.

\[ \alpha \lor (\beta \land \gamma) \equiv (\alpha \lor \beta) \land (\alpha \lor \gamma) \]

⚠️ Top pitfall: Stopping after Step 3. If an OR sits outside an AND, you still need Step 4 — otherwise the formula is not CNF.

Self-check: After eliminating \(\leftrightarrow\) and \(\implies\), what two transformations remain before the formula is in CNF?

Connects to: PL Resolution (needs CNF input), DPLL (operates on CNF).

DPLL Algorithm

Must-know: DPLL finds a satisfying assignment by building a decision tree, pruning with three heuristics: early termination, pure symbols (assign the only polarity they ever show), and unit propagation. It avoids enumerating all \(2^n\) rows.

\[ \text{SAT check: } KB \models \alpha \iff KB \land \neg\alpha \text{ is unsatisfiable} \]

⚠️ Top pitfall: Starting the tree with a non-pure symbol. A pure symbol never flips polarity across clauses, so assigning it is always safe.

Self-check: In the matrix method, what makes a literal "pure", and why do we start the search tree with one?

Connects to: Truth tables (DPLL skips the wasted rows), CNF (its input format), SAT solvers.

Predicate Logic Preview

Must-know: Propositional logic cannot say "all" or "some". Predicate logic adds quantifiers \(\forall\) (for all) and \(\exists\) (there exists) plus predicates with arguments, so one sentence covers a whole domain. The four inference techniques carry forward.

\[ \forall x\ \text{Student}(x) \implies \text{Brilliant}(x) \]

⚠️ Top pitfall: Treating \(P_{1,2}\) as a predicate with arguments. In propositional logic it is one indivisible symbol; predicates look like \(Pit(x,y)\).

Self-check: Why can propositional logic not express "some students are brilliant" without listing every student?

Connects to: Forward and backward chaining (next lecture), resolution with unification.

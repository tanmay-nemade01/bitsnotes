Heuristic Evaluation and Design for Informed Search

📅 Published: June 2, 2026
🎓 Level: postgraduate
👥 Audience: Postgraduate students designing admissible and consistent heuristics for A* and informed search in puzzle and planning domains.

Lecture Summary

This lecture focuses on heuristic functions — the domain knowledge that makes informed search practical. While uninformed methods explore blindly, informed search uses h(n), an estimate of the cost from node n to a goal, to prioritise promising branches.

Greedy best-first search orders nodes by h(n) alone: it can be fast but is neither optimal nor complete in general. A* combines path cost g(n) with heuristic h(n) via f(n) = g(n) + h(n), yielding optimal solutions when h is admissible (never overestimates true remaining cost). Consistency (monotonicity) is a stronger property requiring h(n) ≤ c(n, a, n′) + h(n′) for every edge — it ensures f is non-decreasing along paths and simplifies implementations.

Good heuristics balance informativeness with computational cost. Sources include relaxed problems (drop constraints), pattern databases, landmarks, domain expert estimates, and learned features. The 8-puzzle section compares misplaced tiles vs Manhattan distance as heuristics, while N-Queens examples explore conflict-counting approaches.

The lecture explicitly stops before local search algorithms (hill climbing, genetic algorithms), which are reserved for Lecture 5. A key exam skill practised here is proving admissibility or consistency on small graphs and designing stronger heuristics via problem relaxation.

Key Learning Objectives

  • Explain why informed search needs heuristics and how f(n) = g(n) + h(n) guides A*.
  • Define admissible and consistent heuristics and verify them on graphs and puzzles.
  • Construct heuristics from relaxed problems, pattern databases, and domain-specific insight.
  • Compare greedy best-first and A* on optimality, completeness, and efficiency.
  • Evaluate heuristic quality using dominance, effective branching factor, and computational cost.

1. Recap: Informed Search

1.1 Why Informed Search Is Needed

Uninformed search methods such as BFS and DFS explore without guidance about which branch is promising. They know the state space and goal test, but they do not use an estimate of how close a node is to the goal. In large practical problems, this becomes expensive because the search may expand many irrelevant branches.

Informed search adds a practical rule of thumb, educated guess, or intuition called a heuristic. A heuristic lets the search prioritize paths that appear promising instead of wandering through all possibilities.

Heuristic — A heuristic function \(h(n)\) estimates the cost or distance from a node \(n\) to a goal. It is used to guide search toward likely solutions.

The lecture used the maze analogy: using a heuristic is like using a compass and map instead of wandering aimlessly.

1.2 Greedy Best-First Search and A*

Two informed strategies were contrasted:

  • Greedy Best-First Search (GBFS) uses evaluation function \(f(n) = h(n)\). It is fast because it does not compute actual accumulated cost, but it is not guaranteed to be optimal.
  • A* search uses \(f(n) = g(n) + h(n)\), where \(g(n)\) is the actual cost from the start node to \(n\), and \(h(n)\) is the estimated remaining cost from \(n\) to a goal.

A* is more cautious than GBFS because it balances what has already been paid with what is estimated to remain.

Romania Route-Finding Example (GBFS). Using straight-line distance to Bucharest (\(h_{\text{SLD}}\)) as the heuristic: Arad (\(h = 366\)) \(\to\) Sibiu (\(h = 253\)) \(\to\) Fagaras (\(h = 176\)) \(\to\) Bucharest (\(h = 0\)). GBFS finds this solution without expanding any node off the solution path, but the route (Arad–Sibiu–Fagaras–Bucharest, cost 450) is 32 miles longer than the optimal path via Rimnicu Vilcea and Pitesti (cost 418). This illustrates why the algorithm is called “greedy”—it tries to get as close to the goal as it can at each step, but greediness can lead to suboptimal results.

Romania Route-Finding Example (A*). Using the same \(h_{\text{SLD}}\) heuristic, A* computes \(f = g + h\) at each step: Arad (\(f = 0 + 366 = 366\)) \(\to\) Sibiu (\(f = 140 + 253 = 393\)) \(\to\) Rimnicu Vilcea (\(f = 220 + 193 = 413\)) \(\to\) Pitesti (\(f = 317 + 100 = 417\)) \(\to\) Bucharest (\(f = 418 + 0 = 418\)). Notice that Bucharest first appears on the frontier via Fagaras with \(f = 450\), but it is not selected for expansion because the node at Pitesti has \(f = 417 < 450\). A* waits until the cheaper path through Pitesti (cost 418) is fully explored before selecting it as the optimal solution. This demonstrates how A* balances \(g\) and \(h\) to avoid the greediness trap.

1.3 Where Heuristics Come From

In the classical setting discussed in the lecture, heuristics are often supplied by domain experts or SMEs. However, experts can be wrong. Therefore, heuristics are not deployed blindly. They are first evaluated on sample problems where actual path costs are known.

Key Point 1. A heuristic is better when its estimates are closer to true costs, provided it still satisfies the required correctness properties.

The instructor emphasized that heuristic design is an iterative process: propose a heuristic, test it on sample cases, check admissibility and consistency, deploy in a test environment, observe performance, and revise if necessary.

2. Admissibility

2.1 Definition

Admissibility — For every node \(n\), a heuristic is admissible if \(h(n) \le h^*(n)\), where \(h^*(n)\) is the true minimum cost from \(n\) to a goal.

An admissible heuristic is optimistic: it may underestimate the remaining cost, but it must never overestimate. If optimality is required, even a small overestimate violates admissibility.

Why Admissibility Guarantees Optimality in A*. The proof is by contradiction. Suppose the optimal path costs \(C^*\), but A* returns a suboptimal path costing \(C > C^*\). Then there must exist some node \(n\) on the optimal path that is unexpanded (otherwise the optimal solution would have been returned). Since \(n\) is on the optimal path, \(g(n) = g^*(n)\). By admissibility, \(h(n) \le h^*(n)\). Therefore:

\[f(n) = g^*(n) + h(n) \le g^*(n) + h^*(n) = C^*\]

So \(f(n) \le C^*\), meaning \(n\) would have been expanded before any node with \(f > C^*\). The suboptimal goal with cost \(C > C^*\) would only be considered after \(n\) is expanded, so A* cannot return a suboptimal path. This proof requires that all action costs are positive, and that \(h(\text{goal}) = 0\).

2.2 How to Check Admissibility

For each node \(n\) in the sample graph:

  1. List the valid directed paths from \(n\) to the goal.
  2. Compute the cost of each path.
  3. Take the minimum path cost as \(h^*(n)\).
  4. Check whether \(h(n) \le h^*(n)\).

Admissibility is checked node by node; it is not a single whole-graph calculation. If the goal is unreachable from a node, then \(h^*(n) = \infty\), so any finite heuristic estimate is less than infinity.

Exam Tip / Common Pitfall — Do not include paths that keep looping or revisit the goal unnecessarily. For admissibility, use a clean directed path from the node to the goal and take the minimum actual path cost.

The lecture used a directed graph with goal node 3 and heuristic values:

Example 1. Checking admissibility in the five-node graph.

  • Node 1: Paths to goal 3 include 1 \(\to\) 3 with cost 125 and 1 \(\to\) 2 \(\to\) 3 with cost 70 + 50 = 120. Thus \(h^*(1) = 120\). Since \(80 \le 120\), node 1 is admissible.
  • Node 2: The path 2 \(\to\) 3 costs 50. Thus \(h^*(2) = 50\). Since \(60 \le 50\) is false, node 2 is not admissible.
  • Node 3: This is the goal, so \(h(3) = 0\).
  • Node 4: Paths include 4 \(\to\) 5 \(\to\) 1 \(\to\) 3 and 4 \(\to\) 5 \(\to\) 1 \(\to\) 2 \(\to\) 3. Enumerate valid directed paths, compute costs, and compare the smallest cost with \(h(4) = 200\).
  • Node 5: Paths include 5 \(\to\) 1 \(\to\) 3 with cost 75 + 125 = 200 and 5 \(\to\) 1 \(\to\) 2 \(\to\) 3 with cost 75 + 70 + 50 = 195. Thus \(h^*(5) = 195\). Since \(190 \le 195\), node 5 is admissible.

If any node fails the check, the heuristic table must be corrected before relying on A* for optimality.

Q&A. Q: Must admissibility be enforced when the overestimate is very small?
A: Yes, if optimality is required. Any overestimate means the heuristic is not admissible.

Q&A. Q: What happens if a goal is not reachable from a node?
A: The true cost is treated as \(\infty\), so a finite heuristic estimate remains less than the actual cost.

3. Consistency

3.1 Definition

Consistency — For every directed edge \((i, j)\) with actual edge cost \(c(i, j)\), a heuristic is consistent if \(h(i) \le c(i, j) + h(j)\).

This is the triangular inequality for heuristic search. The estimate from i directly to the goal must not be larger than taking one actual step from i to j and then using the heuristic estimate from j.

Why Consistency Matters: f-costs are Non-decreasing. When extending a path from \(n\) to \(n'\) via action \(a\):

\[f(n') = g(n) + c(n, a, n') + h(n')\]

Compare with \(f(n) = g(n) + h(n)\). Cancelling \(g(n)\), we see \(f(n') \ge f(n)\) if and only if \(h(n) \le c(n, a, n') + h(n')\)—the very definition of consistency. This means consistent heuristics guarantee that \(f\) is strictly non-decreasing along any path, ensuring that the first time A* reaches any state, it has reached it via an optimal path, and no state ever needs to be re-expanded or re-added to the frontier.

3.2 Equivalent Intuition

For an edge from \(i\) to \(j\), consistency can be understood as:

\[h(i) - h(j) \le c(i, j)\]

The instructor derived this from the idea that the heuristic drop across an edge should not exceed the actual edge cost. If \(h(i) > c(i, j) + h(j)\), then the heuristic at \(i\) is misleading: the route through \(j\) is already cheaper according to actual one-step cost plus the next estimate.

3.3 How to Check Consistency

For each directed edge \((i, j)\):

  1. Identify the starting node \(i\) and ending node \(j\).
  2. Write \(h(i) \le c(i, j) + h(j)\).
  3. Substitute the edge cost and heuristic values.
  4. Mark the edge consistent if the inequality is true.

Consistency is checked edge by edge. Edges that start at the goal node often trivially satisfy the inequality because \(h(\text{goal}) = 0\) and edge costs are positive.

3.4 Worked Example: Same Five-Node Graph

Example 2. Checking consistency on selected edges.

  • Edge 1 \(\to\) 2 with cost 70: \(h(1) = 80 \le 70 + h(2) = 70 + 60 = 130\). Consistent.
  • Edge 5 \(\to\) 1 with cost 75: \(h(5) = 190 \le 75 + h(1) = 75 + 80 = 155\). Inconsistent.
  • Edge 1 \(\to\) 4 with cost 100: \(h(1) = 80 \le 100 + h(4) = 100 + 200 = 300\). Consistent.
  • Edge 2 \(\to\) 4 with cost 75: \(h(2) = 60 \le 75 + h(4) = 75 + 200 = 275\). Consistent.
  • Edge 2 \(\to\) 5 with cost 125: \(h(2) = 60 \le 125 + h(5) = 125 + 190 = 315\). Consistent.
  • Edge 4 \(\to\) 5 with cost 50: \(h(4) = 200 \le 50 + h(5) = 50 + 190 = 240\). Consistent.

3.5 Why Admissibility and Consistency Matter

Key Point 2. If the heuristic used by A* is admissible and consistent, A* is guaranteed to return an optimal solution. Every consistent heuristic is admissible, but the converse does not hold—an admissible heuristic can still be inconsistent. With an inconsistent heuristic, A* may reach the same state via multiple paths, requiring multiple frontier entries or child-pointer updates when a better path is discovered. This is why consistency is preferred in practice: it guarantees the first time a state is reached, it is reached on an optimal path.

The reason is intuitive: admissibility prevents global overestimation, while consistency prevents local edge-level contradictions. Together, they keep the search from being misled away from an optimal path.

Optimal Efficiency of A*. With a consistent heuristic, A* is optimally efficient: no algorithm that extends search paths from the initial state using the same heuristic information can expand fewer nodes than A*. Specifically, A* expands:

  • Surely expanded: all nodes reachable on a path where every node has \(f(n) < C^*\) (these are strictly necessary—any one could be on the optimal path).
  • Possibly expanded: some nodes on the “goal contour” where \(f(n) = C^*\) before selecting a goal.
  • Never expanded: no nodes with \(f(n) > C^*\).

This pruning behaviour explains why nodes like Timisoara (\(f = 447\)) and Zerind (\(f = 449\)) are never expanded in the Romania A* example: they exceed the optimal solution cost \(C^* = 418\).

Exam Tip / Common Pitfall — Admissibility is checked for nodes using true minimum cost to the goal. Consistency is checked for directed edges using \(h(i) \le c(i, j) + h(j)\). Do not mix the two tests.

4. Properties of a Good Heuristic

A good heuristic has several properties:

  1. Admissible: it never overestimates true remaining cost.
  2. Consistent: it satisfies triangular inequality across neighboring nodes.
  3. Informative: it is close to the true cost, so it avoids unnecessary exploration.
  4. Fast to compute: it should not cost so much that it defeats the purpose of search guidance.
  5. Low effective branching: it should reduce the number of nodes explored.

4.1 Comparing Multiple Heuristics

A problem can have multiple heuristics. The lecture described several ways to compare them.

Choosing Among Heuristics

  • If two heuristics are admissible and one is closer to the true cost without overestimating, the closer one is usually better.
  • If one heuristic contains all information from another plus extra information, prefer the more informative superset.
  • If two admissible and consistent heuristics both solve the problem, prefer the one with lower effective branching.
  • If two heuristics provide complementary information, a weighted combination may be used.

A weighted combination can be written as \(h(n) = \alpha h_1(n) + \beta h_2(n)\), where \(\alpha\) and \(\beta\) are weights reflecting confidence in each heuristic source.

When combining heuristics, admissibility is not automatically preserved. The combined heuristic must be checked again before using it for optimal A*.

4.2 Zero Heuristic Values

If the problem has a single goal, only the goal should normally have \(h(n) = 0\). If multiple nodes have \(h(n) = 0\), that usually indicates multiple goal states or a poorly designed heuristic.

5. Problem Formulation Before Heuristic Design

Before asking an SME or designing a heuristic, the problem must be clearly formulated. The instructor emphasized that AI practitioners must describe the problem in the language of agent design.

5.1 Information to Give an Expert

  1. PEAS: performance measure, environment, actuators, and sensors.
  2. Environment type: for example, fully or partially observable, deterministic or stochastic, static or dynamic.
  3. Agent architecture: such as goal-based, utility-based, or another architecture relevant to the problem.
  4. Problem-Solving Agent formulation: initial state, goal state, actions, transition model, and path cost.

The transition model is especially important because seeing one or two levels of children helps reveal what the state changes look like. This can guide heuristic design without fully solving the problem.

Exam Tip / Common Pitfall — In exams and assignments, the prompt may give only a real-world scenario or a goal state. You may need to define the state representation, initial state, goal test, transition model, constraints, and heuristics yourself.

6. Heuristic Design for the 8-Puzzle

6.1 Problem Description

The 8-puzzle contains numbered tiles and one blank space on a 3 × 3 board. A move slides a neighboring tile into the blank. Allowed moves are up, down, left, and right; diagonal moves are not allowed.

A goal state might arrange the tiles as 1, 2, 3, 4, 5, 6, 7, 8 with the blank in a specified location. The goal test can be defined by numbering cells and checking whether each tile appears in its target cell.

Formal 8-puzzle Formulation. States: a description specifying the location of each tile on the \(3\times3\) grid. Initial state: any designated configuration, but note that a parity property partitions the state space—each goal is reachable from exactly half of all possible initial states. Actions: the simplest way to model movement is to think of the blank space sliding Left, Right, Up, or Down (rather than the tiles moving) because the blank is unique. Transition model: maps a state and action to the resulting state after swapping the blank with the adjacent tile. Goal test: checks whether each tile occupies its target cell. Action cost: each action costs 1.

Note how the formulation involves abstraction: the intermediate sliding positions of a tile are ignored, and real-world complications like shaking the board or physically prying out tiles are abstracted away. This is the essence of effective search problem formulation—retain enough detail for valid solutions but remove extraneous complexity.

6.2 Heuristic 1: Number of Misplaced Tiles

Definition 1. The misplaced-tile heuristic counts how many tiles are not currently in their goal positions.

If the count is 0, the puzzle is in the goal state. A higher value means more tiles are misplaced. Depending on convention, the blank may or may not be counted, but the convention should be stated and used consistently.

Key Point 3. The misplaced-tile heuristic is easy to compute and gives useful guidance, but it is less informative than Manhattan distance.

6.3 Heuristic 2: Manhattan Distance of Tiles

Definition 2. The Manhattan distance between two grid positions is the number of horizontal and vertical steps required to move from one to the other, with no diagonal movement.

For a tile \(t\) at current row-column position \((r_t, c_t)\) and goal position \((r^*_t, c^*_t)\), its Manhattan distance is:

\[|r_t - r^*_t| + |c_t - c^*_t|\]

The total Manhattan heuristic is:

\[h(n) = \sum_{t \in T} (|r_t - r^*_t| + |c_t - c^*_t|)\]

where \(T\) is the set of numbered tiles being counted.

Example 3. Manhattan distance in the tile puzzle. If tile 1 is three grid steps away from its goal position, its contribution is 3. If tile 2 is one step away, its contribution is 1. The total heuristic is the sum of such contributions over all counted tiles.

Manhattan distance is more informative because it measures how far each tile is, not merely whether it is wrong.

6.4 Heuristic 3: Manhattan Distance of the Blank Only

Another possible heuristic is the Manhattan distance of the blank tile from its goal location. This is fast but weak. A state can have the blank in the correct place while all numbered tiles are still wrong.

Exam Tip / Common Pitfall — The blank-only heuristic can falsely make a bad configuration look good. For 8-puzzle design, prefer total Manhattan distance of all numbered tiles when accuracy matters; use misplaced tiles when a simpler heuristic is acceptable.

6.5 Comparing 8-Puzzle Heuristics

HeuristicMeaningTrade-off
H1: Manhattan distance of the blank onlyFast but weak; can misleadLeast computation
H2: Sum of Manhattan distances of all numbered tilesMost informativeMore computationally expensive
H3: Number of misplaced tilesEasiest to computeLess informative than H2

For all three 8-puzzle heuristics above, lower values are better because the goal value is 0.

6.6 Why Heuristics Matter for Tile Problems

The 15-puzzle has roughly 1.3 trillion possible states. Uninformed BFS or DFS would require enormous computation. Heuristics reduce search by pruning unpromising branches.

7. Relaxed Problems

7.1 Definition

Definition 3. A relaxed problem is a simplified version of the original problem obtained by removing one or more constraints.

The cost of solving the relaxed problem can be used as a heuristic for the original harder problem.

7.2 8-Puzzle Relaxations

In the original 8-puzzle, tiles move only by sliding into the blank, and diagonal motion is not allowed. Possible relaxations include:

  • Allow tiles to move diagonally.
  • Allow tiles to move through each other.
  • Allow tiles to move freely to target positions.

Removing constraints makes the problem easier to solve, and the solution cost of the easier version can guide the original problem.

7.3 State Space Effect

When a constraint is removed, more configurations become legal. Therefore, the state space of the relaxed problem is a supergraph of the original state space.

Key Point 4. Relaxation makes the rules easier, but it can increase the number of states because configurations previously forbidden now become allowed.

8. Other Ways to Construct Heuristics

8.1 Pattern Databases

A pattern database precomputes solutions or costs for smaller subproblems, stores them, and later reuses them during search. For example, a tile puzzle can precompute costs for selected groups of tiles.

The instructor connected this idea to dynamic programming: solve smaller instances once, store the result, and refer to it repeatedly instead of recomputing.

8.2 Landmarks

A landmark is a useful intermediate state whose distance relationships are already known. The GPS analogy was used: instead of computing every street-to-street route, guide someone to a known mall, signal, or landmark first, then route from there.

Rubik's Cube solving was used as an example. Solvers often move any configuration to a known landmark pattern, after which a memorized sequence solves the remaining steps.

8.3 Learning from Experience

The lecture introduced several ways an AI system can learn better heuristics:

  • Meta-level learning: the AI studies its own past search paths and learns to avoid dead ends or unhelpful states.
  • Feature learning: the AI solves many random instances and identifies features that predict final cost, such as the number of tiles out of order.
  • Pattern databases: stored experience from smaller solved subproblems becomes future guidance.
  • Neural network heuristics: a neural network predicts heuristic value from a state representation.

8.4 Neural Networks as Heuristics

In classical A*, \(h(n)\) is a number supplied by a human-designed heuristic. In learned heuristic search, the heuristic may be produced by a neural network:

\[h(n) = \text{NN}(s, \theta)\]

where \(s\) is the state representation and \(\theta\) represents learned parameters.

For A*, this becomes \(f(n) = g(n) + h_{\text{NN}}(n)\). For GBFS, the search may use \(h_{\text{NN}}(n)\) alone.

The reference paper mentioned in class used A* and GBFS to evaluate learned heuristics on grid-style domains such as Sokoban, mazes with teleports, and sliding puzzles.

9. \(N\)-Queens Problem

9.1 Problem Statement

In the \(N\)-Queens problem, an \(N \times N\) chessboard and \(N\) queens are given. The goal is to place the queens so that no two queens attack each other. Two queens attack each other if they are in the same row, same column, or same diagonal.

N-Queens Goal — A board is a goal state when every queen is safe: no pair of queens shares a row, column, or diagonal.

9.2 Problem-Solving Agent Formulation

For the 4-Queens example:

  • State representation: coordinates, row variables such as \(V_1, V_2, V_3, V_4\), or numbered board cells.
  • Initial state: a current placement of queens.
  • Actions: place or move a queen to a non-occupied square, subject to the chosen representation.
  • Transition model: the new board configuration after a legal move.
  • Goal test: no queen attacks another queen.
  • Path cost: cost of transitions, often based on valid placements or moves.
  • State space size: in a common one-queen-per-row formulation, possible arrangements are on the order of \(N!\).

The instructor recommended constructing the search tree one row at a time for clarity and efficiency.

9.3 Relaxed \(N\)-Queens

If a constraint is removed, such as allowing two queens in the same column, the relaxed problem permits configurations that the original problem rejects. This increases the state space because more placements become legal.

9.4 Heuristic 1: Non-Conflicting Pairs

For 4 queens, the unique queen pairs are \((Q_1, Q_2), (Q_1, Q_3), (Q_1, Q_4), (Q_2, Q_3), (Q_2, Q_4), (Q_3, Q_4)\). There are 6 possible pairs.

The non-conflicting-pairs heuristic counts how many of these pairs are not attacking each other. For 4-Queens, the best value is 6, which means all pairs are safe and the state is a goal.

9.5 Heuristic 2: Conflicting Pairs

The conflicting-pairs heuristic counts how many queen pairs do attack each other. The best value is 0. For this heuristic, lower is better. A high value means many queens are attacking each other, so the state is less promising.

9.6 Heuristic 3: Safe Queens

The safe-queens heuristic counts how many individual queens are not being attacked by any other queen. A state with more safe queens is more promising.

Example 4. Comparing N-Queens configurations. Suppose a configuration has \(Q_1\) and \(Q_3\) attacking each other, while the other relevant pairs are safe. Then the number of conflicting pairs is 1. The non-conflicting-pairs score is lower than the maximum of 6, and the safe-queens count depends on which queens are attacked. Such a configuration is worse than one with no conflicts, but better than one where many queens attack each other.

9.7 How Heuristics Prune Search

Key Point 5. For N-Queens, some heuristics are maximization-style and some are minimization-style. Maximize non-conflicting pairs or safe queens; minimize conflicting pairs.

Without a heuristic, the search expands children from every configuration. With a heuristic, states with many conflicts or few safe queens can be ignored earlier. This reduces unnecessary exploration and focuses on more promising configurations.

10. Applications and Variants Mentioned

10.1 Applications of Informed Search

The lecture mentioned several applications:

  • Pathfinding in maps and GPS systems;
  • Game AI, including chess systems such as Deep Blue;
  • Robotics and motion planning;
  • Logistics and shipping route optimization;
  • Puzzle solving, including sliding puzzles, Sudoku-like problems, and Rubik's Cube-style state spaces.

10.2 A* Variants

The lecture briefly mentioned variants such as iterative deepening A* and simplified memory-bounded A*. These were treated as add-on concepts from the webinar rather than the main exam focus of this session.

Iterative Deepening A* (IDA*). IDA* applies iterative deepening using \(f\)-cost (\(g + h\)) as the cutoff rather than depth. Each iteration exhaustively searches one \(f\)-contour, finds a node just beyond it, and uses that node’s \(f\)-cost as the next contour. For integer-valued \(f\)-costs (like the 8-puzzle), at most \(C^*\) iterations are needed (e.g., \(\le 31\) iterations for the hardest 8-puzzle instances). Memory usage is \(O(bd)\) rather than exponential, at the cost of re-visiting some states across iterations. When \(f\)-costs are continuous rather than integer, IDA* degrades—each new contour may contain only one new node, making the number of iterations equal to the number of states.

Recursive Best-First Search (RBFS). RBFS mimics best-first search using only linear space. It performs a recursive depth-first search but uses an \(f\)-limit to track the best alternative path available from any ancestor. When the current node exceeds this limit, recursion unwinds back to the alternative. As it unwinds, each node’s \(f\)-value is replaced with a backed-up value—the best \(f\)-value among its children—so RBFS remembers the best leaf in a forgotten subtree and can later decide whether re-expanding it is worthwhile.

Weighted A*. In weighted A*, the heuristic is multiplied by a weight \(W > 1\): \(f(n) = g(n) + W \times h(n)\). This can be seen as a generalization: \(W = 0\) gives uniform-cost search, \(W = 1\) gives standard A*, \(W \to \infty\) gives greedy best-first. Weighted A* focuses the search more narrowly towards the goal, exploring fewer nodes but potentially missing the optimal path. The resulting solution costs between \(C^*\) and \(W \times C^*\), though in practice it is often much closer to \(C^*\). This approach is called satisficing search—accepting “good enough” suboptimal solutions for significant speedups. For example, on a grid problem, \(W = 2\) explored 7 times fewer states while increasing path cost by only 5%.

Beam Search. Beam search limits the frontier size to \(k\) best nodes by \(f\)-score, discarding the rest. An alternative version keeps all nodes whose \(f\)-score is within \(\delta\) of the best \(f\)-score. This is incomplete and suboptimal but executes fast with controlled memory use—appropriate when the state space is too large for full A*.

11. Key Terms / Glossary

Admissibility
A property of \(h(n)\) such that \(h(n) \le h^*(n)\) for every node \(n\).
A*
Informed search using \(f(n) = g(n) + h(n)\).
Branch factor
The number of successor nodes generated from a node; lower branching usually means less search effort.
Consistency
Edge-level property \(h(i) \le c(i, j) + h(j)\).
Conflicting pair
In N-Queens, a pair of queens that attack each other by row, column, or diagonal.
Domain dominance
A heuristic is preferred when it contains stronger or more complete guidance than another comparable heuristic.
Effective branch factor
Practical measure of how much a heuristic reduces exploration.
GBFS
Greedy Best-First Search; expands using h(n) only.
Heuristic
An estimate or rule of thumb used to guide search.
Informative heuristic
A heuristic close to true cost and therefore useful for pruning.
Landmark
A known intermediate state used to estimate or guide distance to a goal.
Manhattan distance
Grid distance using only horizontal and vertical moves.
Meta-level learning
Learning from the AI system's own search behavior.
Misplaced tile
A tile not currently in its goal position.
N-Queens
Puzzle of placing N queens on an N × N board with no attacks.
Pattern database
Precomputed table of subproblem costs used during search.
PEAS
Performance measure, Environment, Actuators, Sensors.
Problem-Solving Agent
Formulation with initial state, actions, transition model, goal test, and path cost.
Pruning
Avoiding expansion of branches considered unpromising.
Relaxed problem
Easier problem formed by removing constraints from the original.
Safe queen
A queen not attacked by any other queen.
SME
Subject-matter expert who may propose heuristic values or design ideas.
Triangular inequality
The consistency condition linking \(h(i)\), \(c(i, j)\), and \(h(j)\).

13. One-Page Summary / Cheat Sheet

Core Formulas

\[f(n) = g(n) + h(n)\] \[h(n) \le h^*(n) \qquad \text{(admissibility)}\] \[h(i) \le c(i, j) + h(j) \qquad \text{(consistency)}\]

Admissibility Checklist — For each node \(n\), find the true minimum path cost \(h^*(n)\) to the goal. If \(h(n) \le h^*(n)\), the node passes. If any node overestimates, the heuristic is not admissible for that sample.

Consistency Checklist — For every directed edge \((i, j)\), substitute values into \(h(i) \le c(i, j) + h(j)\). If any edge fails, the heuristic is inconsistent.

Good Heuristic — A good heuristic is admissible, consistent, informative, accurate, fast to compute, and reduces effective branching.

8-Puzzle

Misplaced tiles is simple. Total Manhattan distance is stronger but more expensive. Blank-only Manhattan is weak because the blank can be correct while the puzzle remains unsolved.

N-Queens

Goal: no shared row, column, or diagonal. Maximize non-conflicting pairs or safe queens; minimize conflicting pairs. For 4-Queens there are \(\binom{4}{2} = 6\) unique queen pairs.

When Heuristics Are Insufficient

Use better SMEs, relaxed problems, pattern databases, landmarks, feature learning, meta-level learning, or neural networks to create stronger heuristic guidance.

Test Your Knowledge

Q: If h is consistent, which property holds for A* along any solution path?

Explanation: Consistency implies h(n) ≤ c(n,n′) + h(n′), which with f = g + h yields f(n′) ≥ f(n) along edges. Non-decreasing f prevents the need to reopen closed nodes.

Q: Manhattan distance of all tiles in the 8-puzzle (sum of horizontal and vertical distances to goal positions) is:

Explanation: Each tile must travel at least its individual Manhattan distance; summing these lower bounds cannot overestimate total moves, making this heuristic admissible and typically more informed than misplaced-tile counting.

Q: Greedy best-first search using f(n) = h(n) differs from A* because:

Explanation: Without g(n), greedy search can follow paths that look close to the goal but accumulate high cost. A* balances accumulated cost and estimate, enabling optimality guarantees with admissible h.

Heuristic Evaluation and Design for Informed Search

4.1 Recap: Informed Search

4.1.1 Why Informed Search Is Needed

Uninformed search strategies—such as Breadth-First Search (BFS), Depth-First Search (DFS), and Uniform Cost Search (UCS)—operate blindly. They explore the state space using only the general problem definition and path costs accumulated so far, possessing no domain knowledge about where the goal state actually lies relative to the current search frontier. For simple problems with small state spaces, blind search is adequate. However, for real-world artificial intelligence applications characterized by massive or infinite state spaces, blind search fails due to exponential time and space complexity.

Analogy — Compass vs. Blind Wandering: Imagine searching for a destination inside a dense, foggy forest. Uninformed search is like walking in an expanding circle or picking random paths, trying every single path until you stumble across the destination. Informed search is like having a compass that points continuously in the general direction of the destination. Even if obstacles force minor detours, the compass prevents you from walking away from the goal.

State Space Explosion

Consider the classic tile-sliding puzzle:

  • 8-Puzzle: Possesses \(9! / 2 = 181,440\) reachable states.
  • 15-Puzzle: Possesses \(16! / 2 \approx 1.3 \times 10^{12}\) (1.3 trillion) reachable states.
  • Rubik's Cube (3x3x3): Possesses over \(4.3 \times 10^{19}\) reachable states.

Attempting to locate a goal state in a 15-puzzle or Rubik's cube using uninformed search produces a combinatorial explosion, exhausting system memory and computational time. Informed search solves this by incorporating domain-specific guidance—known as heuristics—to prioritize expanding nodes that appear closest to the goal.

4.1.2 Greedy Best-First Search and A*

Informed search algorithms rank nodes on the search frontier using an evaluation function \(f(n)\). The node with the lowest evaluation score is selected for expansion at each step.

Symbol Registry

  • \(n\) — Current state or node in the search graph (\(n \in S\)).
  • \(f(n)\) — Total evaluation score of node \(n\); scalar priority metric used to order the frontier queue.
  • \(g(g(n))\) — Exact path cost accumulated from the initial start node \(S_0\) to node \(n\) along the current path (\(g(n) \ge 0\)).
  • \(h(n)\) — Estimated remaining path cost from node \(n\) to the nearest goal state (\(h(n) \ge 0\)).
  • \(h^*(n)\) — True, actual minimal cost of an optimal path from node \(n\) to the nearest goal state (\(h^*(n) \ge 0\)).

Greedy Best-First Search (GBFS): Greedy Best-First Search evaluates nodes strictly by their estimated remaining heuristic distance to the goal:

\[ f(n) = h(n) \]

Because GBFS completely ignores the historical accumulated path cost \(g(n)\), it drives aggressively toward whichever node appears closest to the goal. While computationally fast and lightweight, GBFS can be easily trapped in dead ends or led down highly suboptimal paths if the heuristic is inaccurate.

A* Search: A* Search combines the historical cost so far \(g(n)\) with the estimated remaining cost to the goal \(h(n)\):

\[ f(n) = g(n) + h(n) \]

By evaluating \(f(n) = g(n) + h(n)\), A* estimates the total cost of the complete path passing from the start node \(S_0\), through node \(n\), to the goal state. This balances past expenditure against future estimates, preventing the search from pursuing expensive paths even if they temporarily appear close to the goal.

Walkthrough — GBFS vs. A* on a 3-Node Choice: Suppose start node \(S\) has two successors, \(A\) and \(B\):

  • Path to \(A\): Edge cost \(c(S, A) = 10\). Heuristic estimate \(h(A) = 3\).
  • Path to \(B\): Edge cost \(c(S, B) = 1\). Heuristic estimate \(h(B) = 5\).
  • True goal costs: \(h^*(A) = 3\), \(h^*(B) = 5\).

Greedy Best-First Search Evaluation:

  • \(f(A) = h(A) = 3\)
  • \(f(B) = h(B) = 5\)
  • GBFS chooses node \(A\) because \(3 \lt 5\). Total path cost via \(A\) becomes \(10 + 3 = 13\).

A* Search Evaluation:

  • \(f(A) = g(A) + h(A) = 10 + 3 = 13\)
  • \(f(B) = g(B) + h(B) = 1 + 5 = 6\)
  • A* chooses node \(B\) because \(6 \lt 13\). Total path cost via \(B\) is \(1 + 5 = 6\).

Sense check: GBFS picked node \(A\) based solely on low heuristic cost, ignoring the high initial step cost of 10. A* correctly identified that path \(B\) offers a lower total path cost of 6.

4.1.3 Where Heuristics Come From

A heuristic function \(h(n)\) is a problem-specific estimate of remaining search effort. Traditionally, heuristics were designed by human Subject Matter Experts (SMEs) relying on field intuition and domain rules of thumb.

Warning — Domain Expert Heuristic Flaws: Domain experts are not infallible. An expert might propose a heuristic rule that overestimates actual travel time or distance due to hidden assumptions. If a human expert supplies an inaccurate or over-optimistic heuristic function, the search algorithm can be misled into expanding suboptimal paths or skipping the optimal path entirely, forfeiting solution optimality.

The core principle governing heuristic quality is:

\[ \text{The closer } h(n) \text{ is to } h^*(n), \text{ the fewer redundant nodes A* expands.} \]
  • If \(h(n) = 0\) for all nodes, A* degrades to Uniform Cost Search (Dijkstra's algorithm), expanding nodes in concentric contours of equal \(g(n)\).
  • If \(h(n) = h^*(n)\) (the perfect heuristic), A* expands only nodes on the exact optimal path directly to the goal without any wasted search effort.

To evaluate whether a proposed heuristic function is mathematically reliable and guarantees optimal search results, we evaluate two theoretical properties: Admissibility and Consistency.

Informed search relies on evaluation functions to navigate state spaces efficiently. A* balances accumulated cost \(g(n)\) and heuristic estimate \(h(n)\). To guarantee optimal paths, heuristics must satisfy mathematical properties, starting with Admissibility.

4.2 Admissibility

4.2.1 Definition

A heuristic function \(h(n)\) is defined as admissible if it never overestimates the actual minimal cost required to reach a goal state from node \(n\). In plain terms, an admissible heuristic is strictly optimistic—it may underestimate the true cost or hit it exactly, but it must never exaggerate.

Admissibility Condition: For every node \(n\) in the state space \(S\):

\[ h(n) \le h^*(n) \]

where:

  • \(h(n)\) is the estimated remaining cost from node \(n\) to the goal.
  • \(h^*(n)\) is the true, optimal cost of the shortest path from node \(n\) to the nearest goal state.

Additionally, for any goal state \(G\), the heuristic value must evaluate exactly to zero:

\[ h(G) = 0 \]

Intuition — The Optimistic Budget Estimator: Think of an admissible heuristic as a travel budget estimate. If a trip will actually cost \$120, an optimistic estimate of \$80 keeps you interested in exploring that option. But if your estimator claims the trip costs \$200, you might dismiss that option immediately without ever discovering that it was actually the cheapest route. Optimism prevents premature pruning of optimal paths.

Scope & Assumptions:

  • Optimality Guarantee: Admissibility is a non-negotiable requirement for A* tree search to guarantee returning an optimal (lowest-cost) solution.
  • Consequence of Violation: If even a single node overestimates the cost (\(h(n) > h^*(n)\)), A* loses its optimality guarantee and may terminate early with a sub-optimal solution.

4.2.2 How to Check Admissibility

Admissibility is not a single global number for an entire graph; it must be evaluated individually for every node in the problem space.

Misconception Correction: Admissibility is evaluated node-by-node against the true minimal path cost \(h^*(n)\). You cannot declare a heuristic "admissible" by inspecting average values or a subset of nodes—every reachable state must satisfy \(h(n) \le h^*(n)\).

The verification protocol for a node \(n\) proceeds in four steps:

  1. Path Enumeration: Identify all simple, non-cyclic paths leading from node \(n\) to the target goal node \(G\).
  2. Actual Cost Calculation: Compute the actual path cost \(g(\text{path})\) for each enumerated path by summing its edge costs.
  3. Identify Optimal Cost \(h^*(n)\): Select the minimal path cost:
\[ h^*(n) = \min_{\text{paths}} g(\text{path}) \]
  1. Inequality Check: Compare \(h(n)\) against \(h^*(n)\). If \(h(n) \le h^*(n)\), the node passes. If \(h(n) > h^*(n)\), the heuristic is inadmissible at node \(n\).

4.2.3 Worked Example: Five-Node Graph

Symbol Registry

  • \(n\) — Current graph node (\(n \in \{1, 2, 3, 4, 5\}\)).
  • \(G\) — Goal node; target state (Node 3).
  • \(h(n)\) — Proposed heuristic value of node \(n\).
  • \(h^*(n)\) — True minimal path cost from node \(n\) to Node 3.
  • \(c(i, j)\) — Directed edge cost from node \(i\) to node \(j\).

Consider a directed graph with 5 nodes \(\{1, 2, 3, 4, 5\}\), where Node 3 is the designated goal state.

Proposed Heuristic Table:

\[ h(1) = 80, \quad h(2) = 60, \quad h(3) = 0, \quad h(4) = 200, \quad h(5) = 190 \]

Directed Graph Edges and Edge Costs:

\[ \begin{aligned} c(1, 3) &= 125, & c(1, 2) &= 70, & c(2, 3) &= 50, & c(5, 1) &= 75 \\ c(4, 5) &= 50, & c(1, 4) &= 100, & c(2, 4) &= 75, & c(2, 5) &= 125 \end{aligned} \]

Full Node-by-Node Admissibility Audit:

1. Node 1 Evaluation:

  • Paths to Goal (Node 3):
  • Path 1a: \(1 \to 3\), cost \(= c(1,3) = 125\).
  • Path 1b: \(1 \to 2 \to 3\), cost \(= c(1,2) + c(2,3) = 70 + 50 = 120\).
  • True Minimal Cost: \(h^*(1) = \min(125, 120) = 120\).
  • Check: \(h(1) = 80 \le 120\) \(\Rightarrow\) PASS (Admissible).

2. Node 2 Evaluation:

  • Path to Goal (Node 3):
  • Path 2a: \(2 \to 3\), cost \(= c(2,3) = 50\).
  • True Minimal Cost: \(h^*(2) = 50\).
  • Check: \(h(2) = 60 \le 50\) \(\Rightarrow\) FAIL (Inadmissible!) because \(60 > 50\).

3. Node 3 Evaluation (Goal Node):

  • Path to Goal: Already at goal, cost \(= 0\).
  • True Minimal Cost: \(h^*(3) = 0\).
  • Check: \(h(3) = 0 \le 0\) \(\Rightarrow\) PASS (Admissible).

4. Node 4 Evaluation:

  • Paths to Goal (Node 3):
  • Path 4a: \(4 \to 5 \to 1 \to 3\), cost \(= 50 + 75 + 125 = 250\).
  • Path 4b: \(4 \to 5 \to 1 \to 2 \to 3\), cost \(= 50 + 75 + 70 + 50 = 245\).
  • True Minimal Cost: \(h^*(4) = \min(250, 245) = 245\).
  • Check: \(h(4) = 200 \le 245\) \(\Rightarrow\) PASS (Admissible).

5. Node 5 Evaluation:

  • Paths to Goal (Node 3):
  • Path 5a: \(5 \to 1 \to 3\), cost \(= 75 + 125 = 200\).
  • Path 5b: \(5 \to 1 \to 2 \to 3\), cost \(= 75 + 70 + 50 = 195\).
  • True Minimal Cost: \(h^*(5) = \min(200, 195) = 195\).
  • Check: \(h(5) = 190 \le 195\) \(\Rightarrow\) PASS (Admissible).

Audit Conclusion: Because Node 2 violates the condition (\(60 > 50\)), the heuristic function overall is inadmissible. To fix this, \(h(2)\) must be reduced to a value \(\le 50\).

Common Pitfalls in Admissibility Verification:

  1. Confusing Path Costs with Heuristics: Comparing \(h(n)\) to an arbitrary path cost rather than the true optimal minimal path cost \(h^*(n)\).
  2. Ignoring Multi-Hop Paths: Checking only direct edges to the goal (e.g. evaluating Node 1 as \(c(1,3) = 125\) while missing the cheaper two-hop path \(1 \to 2 \to 3\) costing \(120\)).
  3. Assuming Partial Admissibility is Enough: A heuristic is either fully admissible across the entire state space or inadmissible overall. One violating node breaks the guarantee.

Q: How do we know the true actual cost \(h^*(n)\) when designing heuristics for complex new problems? A: During the design and validation phase, engineers build small benchmark instances where exact shortest path costs \(h^*(n)\) can be computed via exhaustive search. These benchmarks serve as ground-truth test suites to confirm that candidate heuristic formulas never overestimate costs.

Q: Is admissibility strictly required even if the overestimate is tiny (e.g., \(h(2) = 60\) vs. actual cost \(50\))? A: Yes. Admissibility is a strict mathematical precondition for A* optimality. Even a minor overestimation of 10 units destroys the optimistic lower-bound property, allowing A* to prune the optimal path.

Q: Should path enumeration include cyclic paths or repeated node traversals? A: No. Path enumeration considers only simple non-cyclic paths from node \(n\) to goal \(G\). Adding cycles only increases path cost and cannot produce the minimal cost \(h^*(n)\).

Exam note: Be prepared to evaluate admissibility on a node-by-node basis, compute all simple paths to the goal, identify \(h^*(n)\), and write explicit failing inequalities (e.g., \(h(2) = 60 > 50 = h^*(2)\)) to prove inadmissibility.

4.3 Consistency

4.3.1 Definition

A heuristic function \(h(n)\) is defined as consistent (or monotonic) if its estimated cost to the goal never decreases along any edge by more than the actual step cost of that edge.

Symbol Registry

  • \(n\) — Current node (starting state of directed edge).
  • \(n'\) — Successor node reached from \(n\) via action \(a\).
  • \(a\) — Action performed at node \(n\).
  • \(c(n, a, n')\) — Actual non-negative step cost of the edge from \(n\) to \(n'\).
  • \(h(n)\) — Heuristic estimate of remaining cost from node \(n\) to goal.
  • \(h(n')\) — Heuristic estimate of remaining cost from successor node \(n'\) to goal.

Consistency Condition (Triangle Inequality): For every node \(n\) and every successor \(n'\) generated by action \(a\):

\[ h(n) \le c(n, a, n') + h(n') \]

Rearranging terms yields an equivalent formulation in terms of heuristic cost reduction:

\[ h(n) - h(n') \le c(n, a, n') \]

The estimated remaining cost reduction \(h(n) - h(n')\) cannot exceed the actual physical cost \(c(n, a, n')\) incurred along that transition.

Intuition — The Triangle Inequality on Graphs: Consistency is a form of the triangle inequality applied to heuristic state space graphs. It dictates that the estimated distance to your destination \(h(n)\) cannot be greater than taking a detour to an intermediate landmark \(n'\) (costing \(c(n, a, n')\)) plus the remaining estimated distance from that landmark to the destination \(h(n')\). If a detour plus remaining distance were shorter than your direct estimate, your direct estimate was unrealistically pessimistic!

4.3.2 Monotonicity of Evaluation Score \(f(n)\)

If a heuristic function is consistent, the total evaluation score \(f(n) = g(n) + h(n)\) along any search path is strictly monotonically non-decreasing.

Proof of Monotonic \(f\)-values: Let \(n'\) be a successor of node \(n\) reached via action \(a\) with step cost \(c(n, a, n')\). The accumulated path cost to \(n'\) is \(g(n') = g(n) + c(n, a, n')\). Evaluating \(f(n')\):

\[ \begin{aligned} f(n') &= g(n') + h(n') \\ &= g(n) + c(n, a, n') + h(n') \\ &\ge g(n) + h(n) \quad \text{(applying consistency condition } c(n, a, n') + h(n') \ge h(n)\text{)} \\ &= f(n) \end{aligned} \]

Thus:

\[ f(n') \ge f(n) \]

Why Consistency Matters for Graph Search: When A* uses a consistent heuristic on a graph:

  1. Contour Expansion: A* expands nodes in non-decreasing order of \(f(n)\).
  2. First-Expansion Optimality: The first time A* expands any node \(n\), the path found to \(n\) is guaranteed to be optimal.
  3. No Re-opening: The algorithm never needs to re-open or re-expand previously closed nodes. This dramatically reduces memory and running time.

4.3.3 How to Check Consistency

Unlike admissibility (which checks nodes against the goal), consistency is evaluated on an edge-by-edge basis for every directed transition \((i \to j)\) in the state space graph.

The verification protocol for an edge \((i \to j)\) proceeds in four steps:

  1. Identify directed edge \((i \to j)\) and retrieve its step cost \(c(i, j)\).
  2. Retrieve heuristic values \(h(i)\) and \(h(j)\).
  3. Compute the upper bound: \(\text{RHS} = c(i, j) + h(j)\).
  4. Verify the inequality: \(h(i) \le \text{RHS}\).
  • If \(h(i) \le c(i, j) + h(j)\), the edge is consistent.
  • If \(h(i) > c(i, j) + h(j)\), the edge violates consistency.

4.3.4 Worked Example: Same Five-Node Graph

Consider the same 5-node directed graph from Section 4.2 with goal node Node 3.

Heuristic Table:

\[ h(1) = 80, \quad h(2) = 60, \quad h(3) = 0, \quad h(4) = 200, \quad h(5) = 190 \]

Graph Edges and Step Costs:

\[ \begin{aligned} c(1, 3) &= 125, & c(1, 2) &= 70, & c(2, 3) &= 50, & c(5, 1) &= 75 \\ c(4, 5) &= 50, & c(1, 4) &= 100, & c(2, 4) &= 75, & c(2, 5) &= 125 \end{aligned} \]

Full Edge-by-Edge Consistency Audit:

  1. Edge \(1 \to 2\) (\(c(1, 2) = 70\)):
\[ h(1) \le c(1, 2) + h(2) \implies 80 \le 70 + 60 = 130 \quad (\text{True } \Rightarrow \mathbf{PASS}) \]
  1. Edge \(5 \to 1\) (\(c(5, 1) = 75\)):
\[ h(5) \le c(5, 1) + h(1) \implies 190 \le 75 + 80 = 155 \quad (\text{False } \Rightarrow \mathbf{FAIL!}) \]

Analysis: Edge \(5 \to 1\) violates consistency because \(190 > 155\). Moving from node 5 to node 1 costs 75 units, but drops the estimated remaining cost from 190 down to 80 (a drop of 110 units). The heuristic drop (110) exceeds the step cost (75).

  1. Edge \(1 \to 4\) (\(c(1, 4) = 100\)):
\[ h(1) \le c(1, 4) + h(4) \implies 80 \le 100 + 200 = 300 \quad (\text{True } \Rightarrow \mathbf{PASS}) \]
  1. Edge \(2 \to 4\) (\(c(2, 4) = 75\)):
\[ h(2) \le c(2, 4) + h(4) \implies 60 \le 75 + 200 = 275 \quad (\text{True } \Rightarrow \mathbf{PASS}) \]
  1. Edge \(2 \to 5\) (\(c(2, 5) = 125\)):
\[ h(2) \le c(2, 5) + h(5) \implies 60 \le 125 + 190 = 315 \quad (\text{True } \Rightarrow \mathbf{PASS}) \]
  1. Edge \(4 \to 5\) (\(c(4, 5) = 50\)):
\[ h(4) \le c(4, 5) + h(5) \implies 200 \le 50 + 190 = 240 \quad (\text{True } \Rightarrow \mathbf{PASS}) \]
  1. Edge \(1 \to 3\) (\(c(1, 3) = 125\)):
\[ h(1) \le c(1, 3) + h(3) \implies 80 \le 125 + 0 = 125 \quad (\text{True } \Rightarrow \mathbf{PASS}) \]
  1. Edge \(2 \to 3\) (\(c(2, 3) = 50\)):
\[ h(2) \le c(2, 3) + h(3) \implies 60 \le 50 + 0 = 50 \quad (\text{False } \Rightarrow \mathbf{FAIL!}) \]

Analysis: Edge \(2 \to 3\) fails because \(60 > 50\). Node 2's inadmissible overestimate carries over into a consistency violation on the edge connected to the goal.

Audit Summary: Edges \(5 \to 1\) and \(2 \to 3\) fail consistency. Overall, the heuristic is inconsistent.

Relationship Between Admissibility and Consistency:

  • Consistency implies Admissibility: Every consistent heuristic with \(h(G) = 0\) is automatically admissible. (Proof: By induction along the optimal path to the goal).
  • Admissibility does NOT imply Consistency: A heuristic can be admissible at every node yet inconsistent along certain edges.
  • Consequence of Inconsistency: If an admissible heuristic is inconsistent, A* tree search remains optimal, but A* graph search requires re-opening closed nodes when shorter paths are discovered later.

Exam note: Check consistency edge-by-edge using the triangle inequality \(h(i) \le c(i, j) + h(j)\). Remember that consistency guarantees monotonic \(f(n)\) values and prevents node re-opening in A* graph search.

4.4 Properties of a Good Heuristic

4.4.1 Comparing Multiple Heuristics

When solving complex search problems, engineers often design multiple candidate admissible heuristics \(h_1(n), h_2(n), \dots\). To determine which heuristic is superior, we use the formal property of Dominance.

Symbol Registry

  • \(h_1(n)\) — First candidate admissible heuristic function.
  • \(h_2(n)\) — Second candidate admissible heuristic function.
  • \(h^*(n)\) — True optimal minimal path cost from node \(n\) to the goal.
  • \(b^*\) — Effective branching factor; metric measuring search tree pruning efficiency.
  • \(N\) — Total number of nodes expanded by A* search.
  • \(d\) — Solution depth (number of steps in the optimal path).

Dominance Definition: Given two admissible heuristics \(h_1\) and \(h_2\), if for every node \(n\) in the state space:

\[ h_2(n) \ge h_1(n) \]

then \(h_2\) dominates \(h_1\).

Intuition — Tighter Bounds Prune More Nodes: Because both heuristics are admissible (\(h_1(n) \le h^*(n)\) and \(h_2(n) \le h^*(n)\)), \(h_2(n) \ge h_1(n)\) means that \(h_2(n)\) is always closer to the true optimal cost \(h^*(n)\). The closer a heuristic estimate is to \(h^*(n)\), the higher its \(f\)-value for suboptimal nodes, allowing A* to prune suboptimal subtrees much earlier.

Effective Branching Factor \(b^*\)

The quality of a heuristic is quantitatively measured by its effective branching factor \(b^*\). If A* expands a total of \(N\) nodes while finding a solution at depth \(d\), then \(b^*\) is the branching factor of a uniform tree containing \(N+1\) nodes:

\[ N + 1 = 1 + b^* + (b^*)^2 + \dots + (b^*)^d = \frac{(b^*)^{d+1} - 1}{b^* - 1} \]

A well-designed heuristic reduces \(b^*\) toward 1 (where \(b^* = 1\) represents ideal search that explores only the exact optimal path to the goal). A dominating heuristic \(h_2\) is guaranteed to yield a smaller or equal effective branching factor \(b^*\) compared to \(h_1\).

4.4.2 Zero Heuristic Values

If a heuristic function yields \(h(n) = 0\) for every node \(n\), it is automatically admissible and consistent:

\[ h(n) = 0 \le h^*(n) \quad \text{and} \quad 0 \le c(n, a, n') + 0 \]

Under \(h(n) = 0\), the A* evaluation function simplifies to:

\[ f(n) = g(n) + h(n) = g(n) + 0 = g(n) \]

Degeneration to Uniform Cost Search: Setting \(h(n) = 0\) transforms A* into Uniform Cost Search (Dijkstra's Algorithm). While guaranteed to find optimal paths, it forfeits all directional guidance, causing A* to expand nodes blindly in concentric contours of equal path cost \(g(n)\).

4.4.3 Problem Formulation Before Heuristic Design

Before crafting a heuristic function, an AI engineer must formally specify the environment using a Problem-Solving Agent (PSA) formulation:

The 5-Component Problem-Solving Agent (PSA) Specification:

  1. Initial State \(S_0\): The starting configuration of the agent and environment.
  2. Actions \(\text{Actions}(s)\): The set of executable moves available from state \(s\).
  3. Transition Model \(\text{Result}(s, a)\): Deterministic or stochastic function returning the successor state \(s'\) resulting from action \(a\) applied to state \(s\).
  4. Goal Test \(\text{IsGoal}(s)\): Boolean predicate determining whether state \(s\) is a valid goal state.
  5. Path Cost Function \(c(s, a, s')\): Non-negative step cost associated with transitioning from state \(s\) to \(s'\) via action \(a\).

4.4.4 Information to Give an Expert

When consulting a human Subject Matter Expert (SME) to extract heuristic intuition, the engineer must provide a detailed domain briefing comprising:

  1. PEAS Specification:
  • Performance Measure: Target optimization metric (e.g. minimize travel time, minimize fuel consumption, maximize precision).
  • Environment: Description of the state space context (e.g. road network, grid maze, game board).
  • Actuators: Operational controls (e.g. steering angle, tile movement, robotic arm joint controls).
  • Sensors: Input devices (e.g. GPS, camera feed, sonar rangefinder).
  1. Environment Classification: Clarifying whether the problem is fully vs. partially observable, deterministic vs. stochastic, static vs. dynamic, discrete vs. continuous, single-agent vs. multi-agent.
  2. Formal PSA Representation: Explaining the exact state representation, valid actions, and goal criteria to ensure the expert's rules map cleanly onto \(h(n)\).

Dominance determines which admissible heuristic is superior: higher admissible estimates yield smaller effective branching factors \(b^*\). To design effective heuristics like those for the 8-puzzle, we start with formal PSA definitions.

4.5 Heuristic Design for the 8-Puzzle

4.5.1 Problem Description

The 8-puzzle consists of a \(3 \times 3\) grid board containing 8 sliding square tiles numbered 1 through 8, along with a single empty slot (the blank space). An adjacent tile can slide horizontally or vertically into the blank space. Diagonal moves are strictly prohibited.

Initial State Example:           Goal State:
+---+---+---+                    +---+---+---+
| 7 | 2 | 4 |                    | 1 | 2 | 3 |
+---+---+---+                    +---+---+---+
| 5 |   | 6 |                    | 8 |   | 4 |
+---+---+---+                    +---+---+---+
| 8 | 3 | 1 |                    | 7 | 6 | 5 |
+---+---+---+                    +---+---+---+

The objective is to find a minimal sequence of tile slides that transforms the initial state into the goal state configuration.

4.5.2 Heuristic 1: Number of Misplaced Tiles

Misplaced Tiles Heuristic \(h_1(n)\): The misplaced tiles heuristic counts how many numbered tiles are currently not in their designated goal grid positions.

\[ h_1(n) = \sum_{i=1}^{8} \mathbb{I}(\text{Tile } i \text{ is not in its goal position}) \]

where \(\mathbb{I}(\cdot)\) is the indicator function returning 1 if true and 0 if false. The blank space is excluded from the count.

Evaluation on Initial State: Comparing the initial state above against the goal state:

  • Tile 1: At position (3,3), goal is (1,1) \(\to\) Misplaced (1)
  • Tile 2: At position (1,2), goal is (1,2) \(\to\) Correct (0)
  • Tile 3: At position (3,2), goal is (1,3) \(\to\) Misplaced (1)
  • Tile 4: At position (1,3), goal is (2,3) \(\to\) Misplaced (1)
  • Tile 5: At position (2,1), goal is (3,3) \(\to\) Misplaced (1)
  • Tile 6: At position (2,3), goal is (3,2) \(\to\) Misplaced (1)
  • Tile 7: At position (1,1), goal is (3,1) \(\to\) Misplaced (1)
  • Tile 8: At position (3,1), goal is (2,1) \(\to\) Misplaced (1)

Total misplaced count: \(h_1(n) = 7\).

Admissibility of \(h_1(n)\): \(h_1(n)\) is strictly admissible because every misplaced tile must be moved at least once to reach its goal position. Since moving one tile takes at least 1 step, \(h_1(n) \le h^*(n)\).

4.5.3 Heuristic 2: Manhattan Distance of Tiles

Symbol Registry

  • \((x_i, y_i)\) — Current row and column coordinates of numbered tile \(i\) (\(i \in \{1, \dots, 8\}\)).
  • \((x_i^{\text{goal}}, y_i^{\text{goal}})\) — Target row and column goal coordinates of tile \(i\).
  • \(h_2(n)\) — Total Manhattan distance heuristic value for state \(n\).

Manhattan Distance Heuristic \(h_2(n)\): The Manhattan distance heuristic sums the horizontal and vertical grid distances required for each numbered tile to reach its target goal position:

\[ h_2(n) = \sum_{i=1}^{8} \left( |x_i - x_i^{\text{goal}}| + |y_i - y_i^{\text{goal}}| \right) \]

This measures the number of grid moves each tile would need if there were no other tiles blocking its path.

Worked Walkthrough — Tile-by-Tile Manhattan Distance Calculation:

Let us compute \(h_2(n)\) for the sample initial state configuration against the goal state:

Tracing the lecture's explicit worked calculation for this state yields individual tile distances summing to:

\[ h_2(n) = 3 + 1 + 2 + 1 + 0 + 4 + 5 + 2 = 18 \]

Sense check: Since every single step moves a tile by at most 1 grid unit along one axis, a tile requires at least its Manhattan distance in moves to reach its destination. Therefore, \(h_2(n) \le h^*(n)\) is strictly admissible.

4.5.4 Heuristic 3: Manhattan Distance of the Blank Only

Q: Can we use the Manhattan distance of the empty blank space alone as a heuristic? A: No. Trigger: Students proposal of blank space distance alone (h3). Resolution: Rejected because h3=0 when the blank reaches its goal position while all 8 numbered tiles remain completely scrambled. This zero estimate misleads the search algorithm into expanding unpromising subtrees.

4.5.5 Comparing 8-Puzzle Heuristics

Dominance in 8-Puzzle Heuristics: For any valid 8-puzzle state \(n\):

\[ h_2(n) \ge h_1(n) \]

Because both \(h_1\) and \(h_2\) are admissible, \(h_2\) (Manhattan Distance) dominates \(h_1\) (Misplaced Tiles).

For the sample initial state:

  • \(h_1(n) = 7\)
  • \(h_2(n) = 18\)
  • True minimal cost \(h^*(n) \ge 18\)

Because \(h_2(n)\) gives a much tighter lower bound, A* search using \(h_2\) prunes far more suboptimal paths than \(h_1\).

4.6 Relaxed Problems

4.6.1 Definition

A relaxed problem is created by removing one or more operational constraints from the original problem definition, making it easier to transition between states.

Symbol Registry

  • \(P\) — Original problem state space graph.
  • \(P_{\text{relaxed}}\) — Relaxed problem supergraph state space.
  • \(h(n)\) — Heuristic estimate for node \(n\).
  • \(h^*(n)\) — True optimal minimal path cost in original problem graph \(P\).
  • \(h_{\text{relaxed}}^*(n)\) — True optimal minimal path cost in relaxed supergraph \(P_{\text{relaxed}}\).

Fundamental Theorem of Relaxed Problems: The exact optimal solution cost to a relaxed problem is guaranteed to be an admissible and consistent heuristic for the original problem.

\[ h(n) = h_{\text{relaxed}}^*(n) \le h^*(n) \]

Intuition — The Supergraph Property: Removing constraints adds new edges to the state space graph. The relaxed problem's state space is therefore a supergraph containing all original nodes and edges plus additional shortcut edges. Because every valid path in the original graph remains valid in the supergraph (alongside new shortcuts), the shortest path cost in the supergraph can never exceed the shortest path cost in the original graph.

4.6.2 8-Puzzle Relaxations

The standard 8-puzzle heuristic functions (\(h_1\) and \(h_2\)) are not arbitrary inventions; they are derived systematically by relaxing constraints of the original puzzle rules:

1. Original 8-Puzzle Rules

Rule Constraint: Tile \(T\) can move from Square A to Square B if and only if Square A is adjacent to Square B AND Square B is currently empty (the blank space).

2. Relaxation A (Yields Manhattan Distance Heuristic \(h_2\))

Relaxed Constraint: Tile \(T\) can move from Square A to Square B if Square A is adjacent to Square B (ignoring whether Square B is occupied or blank).

  • Derivation: Under Relaxation A, tiles can slide over or pass through each other. The minimal number of steps required to move a single tile to its goal grid square is simply its horizontal distance plus vertical distance.
  • Result: Summing these independent unblocked tile steps yields the Manhattan Distance Heuristic \(h_2(n)\).

3. Relaxation B (Yields Misplaced Tiles Heuristic \(h_1\))

Relaxed Constraint: Tile \(T\) can move from Square A to Square B in a single step (ignoring adjacency AND ignoring whether Square B is blank).

  • Derivation: Under Relaxation B, any tile out of position can teleport directly to its goal position in exactly 1 move. A tile already in its goal position requires 0 moves.
  • Result: The total minimal cost equals the number of tiles not in their goal position, yielding the Misplaced Tiles Heuristic \(h_1(n)\).

4.6.3 Why Relaxed Heuristics Are Always Admissible and Consistent

Formal Proof of Admissibility and Consistency for Relaxed Heuristics:

  1. Admissibility: Let \(P\) be the original problem graph and \(P_{\text{relaxed}}\) be the supergraph with relaxed rules. Any valid path in \(P\) is a valid path in \(P_{\text{relaxed}}\). Since \(h(n) = h_{\text{relaxed}}^*(n)\) is the minimal path cost in \(P_{\text{relaxed}}\), it must be \(\le\) the minimal path cost in \(P\), which is \(h^*(n)\). Hence, \(h(n) \le h^*(n)\) (Admissible).
  2. Consistency: Because \(h(n) = h_{\text{relaxed}}^*(n)\) is an exact shortest-path distance function on the graph \(P_{\text{relaxed}}\), it obeys the triangle inequality across every edge:
\[ h_{\text{relaxed}}^*(n) \le c(n, a, n') + h_{\text{relaxed}}^*(n') \]

Hence, \(h(n) \le c(n, a, n') + h(n')\) (Consistent).

Trade-off in Relaxation Design:

  • Over-relaxation: Removing too many constraints makes the relaxed problem trivial, but yields weak, uninformative heuristics (e.g. relaxing all rules until \(h(n) = 0\)).
  • Under-relaxation: Removing too few constraints leaves the relaxed problem almost as hard to solve as the original problem, consuming excessive computation to evaluate \(h(n)\).
  • Ideal Balance: A good relaxation creates a problem that can be solved in closed-form or polynomial time while retaining tight bounds on \(h^*(n)\).

Exam note: Be prepared to explain how relaxing rules creates supergraphs and why exact optimal solution costs to relaxed problems are guaranteed to be both admissible and consistent heuristics for the original problem.

4.7 Other Ways to Construct Heuristics

4.7.1 Pattern Databases

When manual relaxation is difficult, heuristics can be constructed systematically using Pattern Databases. A pattern database stores exact solution costs for sub-problems of a complex search domain in a pre-computed lookup table.

Symbol Registry

  • \(P_{\text{sub}}\) — Sub-problem configuration pattern (e.g. tiles 1, 2, 3, 4 of a 15-puzzle).
  • \(L\) — Landmark node in a spatial state graph.
  • \(n\) — Current graph state node.
  • \(G\) — Target goal node.
  • \(c(a, b)\) — Pre-computed shortest path distance between nodes \(a\) and \(b\).
  • \(h_{\theta}(n)\) — Neural network estimated cost with parameter weights \(\theta\).

Pattern Database Construction & Evaluation:

  1. Define Sub-problem: Select a specific subset of state components (for example, abstracting a 15-puzzle by tracking only tiles 1, 2, 3, 4 while treating all other tiles as indistinguishable blank spaces).
  2. Exhaustive Pre-computation: Run backward breadth-first search from the goal state to compute the exact minimal number of moves required to solve the sub-problem from every possible sub-configuration.
  3. Lookup Table: Store these exact costs in a high-speed memory table.
  4. Live Evaluation: During live A* search on the full problem, extract the current sub-configuration, look up its exact cost in the database, and use it as \(h(n)\).

Admissibility of Pattern Databases: Pattern database lookup values are strictly admissible because the exact cost to solve a sub-problem is a lower bound on the cost to solve the full problem (since solving the full problem requires solving the sub-problem as a necessary sub-step).

4.7.2 Landmarks

In large-scale spatial road networks (such as GPS navigation engines mapping millions of intersections), computing exact point-to-point shortest paths on demand or storing an \(O(N^2)\) distance matrix is computationally intractable.

Landmark Heuristic (ALT Algorithm — A*, Landmarks, Triangle Inequality):

  1. Select a small set of prominent reference nodes \(\mathcal{L} = \{L_1, L_2, \dots, L_k\}\) across the map (e.g. major highway interchanges or airports).
  2. Pre-compute and store exact shortest path distances \(c(n, L)\) and \(c(L, n)\) between all nodes \(n\) and all landmarks \(L \in \mathcal{L}\).
  3. Using the reverse triangle inequality, the distance between node \(n\) and goal \(G\) via landmark \(L\) satisfies:
\[ |c(n, L) - c(G, L)| \le c(n, G) = h^*(n) \]
  1. The Landmark Heuristic takes the maximum lower bound over all available landmarks:
\[ h_{\text{landmarks}}(n) = \max_{L \in \mathcal{L}} |c(n, L) - c(G, L)| \]

Derivation of Landmark Inequality: By the standard triangle inequality on directed graphs:

\[ c(n, L) \le c(n, G) + c(G, L) \implies c(n, G) \ge c(n, L) - c(G, L) \]

Similarly:

\[ c(G, L) \le c(G, n) + c(n, L) \implies c(n, G) \ge c(G, L) - c(n, L) \]

Combining both yields:

\[ h^*(n) = c(n, G) \ge |c(n, L) - c(G, L)| \]

This proves that \(h_{\text{landmarks}}(n)\) is strictly admissible and consistent.

4.7.3 Learning from Experience

Instead of relying on human expert intuition or manual problem relaxation, modern AI systems learn heuristic functions automatically from execution history and data:

  1. Inductive Feature Learning: The agent generates thousands of random state configurations, solves them using blind search or pattern databases, records the exact solution cost \(h^*(n)\), and fits a statistical regression model (e.g. linear model or decision tree) mapping state features (such as misplaced tiles, blank position, or row/column parity) to predicted cost.
  2. Meta-Level Learning: The agent analyzes its own past search trees to identify recurring dead-end state patterns, dynamically synthesizing heuristic penalty rules that prevent future searches from entering unpromising subtrees.

4.7.4 Neural Networks as Heuristics

Recent advancements in deep learning utilize neural network value functions \(h_{\theta}(n)\) to guide state-space search:

Deep Learning Heuristic Integration: A deep neural network (such as a Convolutional Neural Network or ResNet) takes a state vector or grid tensor representation of node \(n\) and outputs a continuous scalar cost prediction \(h_{\theta}(n)\).

  • A* Integration: Evaluates frontier priority as \(f(n) = g(n) + h_{\theta}(n)\).
  • Greedy Best-First Integration: Evaluates frontier priority as \(f(n) = h_{\theta}(n)\).

Domain Applications: Deep neural network heuristics are widely used in complex grid pathfinding, Sokoban puzzle solvers, automated circuit routing, and high-dimensional search domains (such as DeepCubeA for solving the Rubik's Cube). For further reading, see Russell & Norvig AIMA §3.6 Heuristic Functions and literature on Neural Networks for Grid Domain Heuristics in A and GBFS*.

Beyond manual relaxation, heuristics can be generated automatically via Pattern Databases, Landmark reverse triangle inequalities, inductive machine learning, or Deep Neural Network value approximators.

4.8 N-Queens Problem

4.8.1 Problem Statement

The \(N\)-Queens problem requires placing \(N\) queen chess pieces on an \(N \times N\) chessboard such that no two queens attack each other. Under standard chess rules, two queens attack each other if they share the same row, the same column, or the same diagonal.

Sample 4-Queens Goal State (N = 4):
+---+---+---+---+
| . | Q | . | . |  (Row 1, Col 2: v_2 = 1)
+---+---+---+---+
| . | . | . | Q |  (Row 2, Col 4: v_4 = 2)
+---+---+---+---+
| Q | . | . | . |  (Row 3, Col 1: v_1 = 3)
+---+---+---+---+
| . | . | Q | . |  (Row 4, Col 3: v_3 = 4)
+---+---+---+---+

Symbol Registry

  • \(N\) — Grid dimension and total number of queens to place (\(N \ge 4\)).
  • \(V\) — State vector \([v_1, v_2, \dots, v_N]\) where \(v_i\) stores the row position of the queen in column \(i\).
  • \(v_i\) — Integer row index of queen in column \(i\) (\(v_i \in \{1, \dots, N\}\)).
  • \(\binom{N}{2}\) — Total number of distinct pairs of queens on the board.
  • \(h_1(n)\) — Count of non-conflicting queen pairs (maximize).
  • \(h_2(n)\) — Count of conflicting queen pairs (minimize).
  • \(h_3(n)\) — Count of unattacked safe queens (maximize).

4.8.2 Problem-Solving Agent Formulation

Complete-State PSA Formulation for \(N\)-Queens:

  • State Representation: A 1D vector \(V = [v_1, v_2, \dots, v_N]\), where each index \(i\) corresponds to column \(i\), and value \(v_i\) is the row index of queen \(i\). This implicitly enforces that no two queens ever occupy the same column.
  • Initial State: All \(N\) queens placed in initial rows (e.g. \(V = [1, 1, \dots, 1]\) or a random placement).
  • Actions: Select column \(i\) and change queen row \(v_i\) to a different row \(r \in \{1, \dots, N\}\).
  • Goal Test: No two queens attack each other along any row or diagonal.

4.8.3 Total Pair Combinations

Total Queen Pairs Formula: For \(N\) queens placed on an \(N \times N\) board, the total number of unique pairs of queens is given by the combination formula:

\[ \text{Total Pairs} = \binom{N}{2} = \frac{N(N-1)}{2} \]
  • For 4-Queens (\(N=4\)):
\[ \binom{4}{2} = \frac{4 \times 3}{2} = 6 \text{ total pairs} \]

The 6 pairs are \((Q_1, Q_2), (Q_1, Q_3), (Q_1, Q_4), (Q_2, Q_3), (Q_2, Q_4), (Q_3, Q_4)\).

  • For 8-Queens (\(N=8\)):
\[ \binom{8}{2} = \frac{8 \times 7}{2} = 28 \text{ total pairs} \]

4.8.4 Heuristic Functions for N-Queens

  1. Heuristic 1 — Non-Conflicting Pairs \(h_1(n)\):
  • Counts the number of queen pairs that do not attack each other.
  • Target: Maximize \(h_1(n)\). A goal state achieves \(h_1(n) = \binom{N}{2}\) (for 4-Queens, \(h_1 = 6\)).
  1. Heuristic 2 — Conflicting Pairs \(h_2(n)\):
  • Counts the number of queen pairs that do attack each other (sharing a row or diagonal).
  • Target: Minimize \(h_2(n)\). A goal state achieves \(h_2(n) = 0\).
  • Relationship: \(h_1(n) + h_2(n) = \binom{N}{2}\).
  1. Heuristic 3 — Safe Queens \(h_3(n)\):
  • Counts the number of individual queens that are completely unattacked by any other queen on the board.
  • Target: Maximize \(h_3(n)\). A goal state achieves \(h_3(n) = N\) (for 4-Queens, \(h_3 = 4\)).

4.8.5 Worked Example: Evaluating 4-Queen Configurations

Trace of 4-Queen State Evaluations:

Consider four candidate 4-Queen board configurations generated during search:

1. Configuration 1: Vector \(V = [1, 3, 1, 4]\)

  • Queens placed at: \(Q_1=(1,1)\), \(Q_2=(3,2)\), \(Q_3=(1,3)\), \(Q_4=(4,4)\).
  • Conflict Analysis:
  • \(Q_1\) and \(Q_3\) share Row 1 \(\to\) Conflict!
  • \(Q_2(3,2)\) and \(Q_4(4,4)\) share diagonal (\(|3-4| = |2-4| = 2\)) \(\to\) Conflict!
  • Metrics:
  • Conflicting Pairs \(h_2 = 2\)
  • Non-Conflicting Pairs \(h_1 = 6 - 2 = 4\)
  • Safe Queens \(h_3 = 0\) (all queens involved in at least one conflict)
  • Verdict: Evaluated as unpromising; search algorithm prunes this state.

2. Configuration 2: Vector \(V = [3, 1, 4, 2]\) (Goal State)

  • Queens placed at: \(Q_1=(3,1)\), \(Q_2=(1,2)\), \(Q_3=(4,3)\), \(Q_4=(2,4)\).
  • Conflict Analysis: Zero row or diagonal collisions among all 6 pairs.
  • Metrics:
  • Conflicting Pairs \(h_2 = \mathbf{0}\)
  • Non-Conflicting Pairs \(h_1 = \mathbf{6}\)
  • Safe Queens \(h_3 = \mathbf{4}\)
  • Verdict: Valid Goal State reached! Search terminates with optimal path.

3. Configurations 3 & 4 (Partial/Promising Configurations):

  • States with \(h_2 = 1\) conflicting pair and \(h_3 = 2\) safe queens.
  • Verdict: Higher priority score than Configuration 1; selected for immediate expansion.

Why Heuristic Evaluation Prunes the Search Space: Without heuristic guidance, an uninformed search for 8-Queens evaluates \(8^8 = 16,777,216\) board states. By using conflict-counting heuristics (\(h_2\)), local search (such as Hill-Climbing or Min-Conflicts) or A* prunes unpromising branches, reaching a goal state in under 50 state expansions.

Exam note: Calculate non-conflicting pairs \(h_1\), conflicting pairs \(h_2\), and safe queens \(h_3\) step-by-step using \(\binom{N}{2}\). Remember that goal states achieve \(h_2 = 0\), \(h_1 = \binom{N}{2}\), and \(h_3 = N\).

4.9 Applications and Variants Mentioned

4.9.1 Applications of Informed Search

Informed heuristic search is a foundational technology deployed across modern industry:

Key Industrial Application Domains:

  1. GPS & Navigation Systems: Routing engines (e.g. Google Maps, Waze) use A* with contraction hierarchies and landmark heuristics to compute optimal driving directions across highway networks in milliseconds.
  2. Robotics & Autonomous Motion Planning: Autonomous vehicles and industrial manipulators use A* variants (such as Hybrid A*) to plan collision-free trajectories through continuous configuration spaces.
  3. Game AI & Strategy Engines: Chess, checkers, and real-time strategy (RTS) games use heuristic static evaluation functions within search trees to evaluate unit moves and position strength.
  4. Logistics & Fleet Optimization: Supply chain and delivery management platforms use heuristic search to solve complex Vehicle Routing Problems (VRP) under time-window constraints.

4.9.2 A* Variants

While standard A* search is optimal and complete, its memory requirements can become prohibitive for massive state spaces because it stores all frontier and explored nodes in RAM. Several variants address these practical limitations:

Symbol Registry

  • \(w\) — Heuristic weight parameter (\(w \ge 1.0\)).
  • \(C^*\) — Optimal path cost to goal.
  • \(f_{\text{limit}}\) — Cutoff threshold for Iterative Deepening A*.

1. Iterative Deepening A* (IDA*): IDA* replaces A*'s open list priority queue with a series of depth-first search passes.

  • Threshold: Each iteration sets an \(f\)-cost limit \(f_{\text{limit}}\), initialized to \(h(S_0)\).
  • Pruning: Any node whose evaluation \(f(n) = g(n) + h(n) > f_{\text{limit}}\) is pruned.
  • Next Threshold: If no goal is found, the threshold for the next pass is updated to the minimum \(f\)-cost that exceeded the previous limit.
  • Memory Advantage: Reduces memory complexity from exponential \(O(b^d)\) to linear \(O(bd)\), where \(b\) is branching factor and \(d\) is solution depth.

2. Simplified Memory-Bounded A* (SMA*): SMA* operates within a fixed, user-specified memory limit.

  • When memory is full, SMA* expands the best leaf node and forgets the leaf node with the worst (highest) \(f\)-value.
  • SMA* maintains a back-pointer in parent nodes recording the forgotten child's \(f\)-value, allowing the search to re-generate dropped subtrees only if all alternative paths prove worse.

3. Weighted A* Search: Weighted A* modifies the evaluation function to weight the heuristic estimate heavier than accumulated path cost:

\[ f(n) = g(n) + w \cdot h(n) \quad (w > 1) \]

Setting \(w > 1\) trades strict solution optimality for dramatic speed gains. The solution cost returned by Weighted A* is guaranteed to be bounded by at most \(w \times C^*\).

Informed search powers real-world GPS, robotics, and logistics. Variants like IDA*, SMA*, and Weighted A* overcome A*'s exponential memory bottleneck or trade minor solution quality for speed.

Must-know: Total queen pairs on an N x N board is C(N, 2) = N(N-1)/2. A goal state has 0 conflicting pairs, C(N,2) non-conflicting pairs, and N safe queens.

\[\text{Total Pairs} = \binom{N}{2} = \frac{N(N-1)}{2}\]

⚠️ Top pitfall: Counting directed pairs instead of unique undirected pairs C(N,2).

Self-check: How many total queen pairs exist on an 8-Queens board?

Applications and Variants Mentioned

Must-know: IDA* reduces memory to linear O(bd) using depth-first search iterations with f-cost cutoffs. Weighted A* f(n) = g(n) + w*h(n) guarantees solution quality within w * C*.

\[f(n) = g(n) + w \cdot h(n), \quad w > 1\]

⚠️ Top pitfall: Confusing IDA* with standard DFS without f-cost thresholding.

17.1 Linear SVM — Problem Recap

Hook: What if a classifier could ignore 95% of your training data and still make perfect decisions? SVM does exactly that — it builds the boundary using only the hardest few points, discarding the easy ones.

17.1.1 Definition and Core Concepts

Intuition + Analogy: Imagine two groups of people standing on opposite sides of a wide hallway. You want to draw a line on the floor that separates them with maximum clearance on both sides. The people standing closest to the middle — the ones you're most worried about accidentally crossing — are the only ones that matter for placing the line. Everyone else standing far back is irrelevant. In SVM, those closest people are the support vectors, and the empty corridor you create is the margin. The analogy breaks if the groups are intermingled — that's where soft-margin SVM (§17.2) comes in.

Support vector machine (SVM) is a classification method. It uses only the support vectors — the data points that are hardest to classify from both classes — to build a decision boundary.

Support vectors are the points that lie very close to the margin. The margin is a region around the decision boundary. The goal in SVM is to maximize the margin — to maximize the width of the separation between the two classes. This makes SVM an optimization problem: maximize the width between two classes by finding the best decision boundary.

The weight vector \(\mathbf{w}\) (also called the normal vector) is perpendicular to the decision boundary. The decision boundary is the line that separates both classes. Since the weight vector is perpendicular to the decision boundary, it naturally points in the direction of the data points.

In Python's sklearn.svm.SVC, the library identifies support vectors automatically via the dual solution. But when support vectors are already given in a hand-solved problem, the task is to find the decision boundary.

17.1.3 Mathematical Formulation — The Dual Problem

The margin formula is \(\frac{2}{\|\mathbf{w}\|}\) — two divided by the norm of the weight vector.

Maximizing the margin \(\frac{2}{\|\mathbf{w}\|}\) is equivalent to minimizing \(\|\mathbf{w}\|^2\). For mathematical convenience, the objective is written as minimizing \(\frac{1}{2}\|\mathbf{w}\|^2\). This is the primal problem:

\[ \min_{\mathbf{w}, b} \frac{1}{2}\|\mathbf{w}\|^2 \quad \text{subject to} \quad y_i(\mathbf{w} \cdot \mathbf{x}_i + b) \geq 1 \; \forall i \]

The constraint on one side of the margin: \(y_i(\mathbf{w} \cdot \mathbf{x}_i + b) = +1\). The constraint on the other side: \(y_i(\mathbf{w} \cdot \mathbf{x}_i + b) = -1\). Combining both gives: \(y_i(\mathbf{w} \cdot \mathbf{x}_i + b) \geq 1\).

This is a constrained optimization problem. The direct solution (the primal) is complex. So we convert it into a dual problem using Lagrange multipliers \(\alpha_i \geq 0\), one per constraint.

Dual formation converts the problem from \((\mathbf{w}, b)\) coordinates into Lagrange multipliers \((\alpha_i)\). The dual formulation reduces computation because only support vectors have \(\alpha_i > 0\); for all other points \(\alpha_i = 0\).

From the Lagrangian \(L(\mathbf{w}, b, \boldsymbol{\alpha}) = \frac{1}{2}\|\mathbf{w}\|^2 - \sum_i \alpha_i [y_i(\mathbf{w} \cdot \mathbf{x}_i + b) - 1]\), setting derivatives to zero yields the dual and the three key formulas:

Notation note: The enrichment reference (Bishop, §7.1) uses \(t_n \in \{-1, +1\}\) for labels and \(a_n\) for multipliers; this lecture uses \(y_i\) for labels and \(\alpha_i\) for multipliers. The forms are equivalent.

Weight vector: \[ \mathbf{w} = \sum_i \alpha_i y_i \mathbf{x}_i \]

Bias (only for support vectors): \[ b = y_s - \mathbf{w} \cdot \mathbf{x}_s \] where \(s\) indexes a support vector.

Decision function (prediction): \[ f(\mathbf{x}) = \text{sign}\left(\sum_i \alpha_i y_i (\mathbf{x}_i \cdot \mathbf{x}) + b\right) \]

Even without understanding the derivations, these three formulas are what matter for solving SVM problems.

The weight vector formula says: \(\mathbf{w}\) is the sum over all data points of (Lagrange multiplier \(\times\) class label \(\times\) the data point itself). Since \(\alpha_i = 0\) for non-support-vectors, only support vectors contribute.

When the bias term is augmented into the data vector (same as done in linear regression), the third component of \(\mathbf{w}\) becomes the bias. You don't need to use the separate bias formula — just read the last component of the augmented weight vector.

Why the dual? The primal involves \(\mathbf{w}\) (dimension = number of features); the dual involves \(\boldsymbol{\alpha}\) (dimension = number of data points). When features outnumber data points, the dual is actually more efficient. Also, the dual exposes the kernel trick — data only appear as dot products \(\mathbf{x}_i \cdot \mathbf{x}_j\), which we can replace with \(K(\mathbf{x}_i, \mathbf{x}_j)\) in §17.5.

17.1.5 Visual Intuition

Picture a 2D scatter plot with two classes (say, red circles and blue squares). The decision boundary is a straight line running through the gap between them. On either side of this line, parallel to it, are two dashed lines — these are the margin boundaries. The perpendicular distance from the decision boundary to either margin line is exactly \(1/\|\mathbf{w}\|\). The support vectors are the few points that sit exactly on these dashed margin lines. All other points are farther away and don't affect the boundary at all. If you removed a non-support-vector point, the boundary wouldn't move. If you moved a support vector even slightly, the boundary would shift to maintain the maximum margin.

17.1.6 Key Pedagogical Points

Pitfalls: 1. Sign confusion (\(-b\) vs \(+b\)): The notation \(-b\) vs \(+b\) is just different conventions. Some literature uses minus, some uses plus. It is simply the equation of a line \(mx + b\). Do not get confused by the sign. 2. Norm-squared forms: \(\frac{1}{2}\|\mathbf{w}\|^2\) is same as \(\frac{1}{2}\mathbf{w}^\top\mathbf{w}\) — these are the same expression. 3. Threshold values: If the prediction is exactly \(+1\) or \(-1\), the point lies exactly on the margin (it is a support vector). If prediction is greater than \(+1\) or less than \(-1\), the point is outside the margin and correctly classified with confidence. The threshold for the margin is \(\pm 1\), not \(0\). 4. "Only support vectors matter" trap: While only support vectors determine the boundary, you can't identify them until you solve the full optimization. All training data must be included in the dual formulation; the zeros \((\alpha_i = 0)\) fall out naturally from the KKT conditions. 5. Feature scaling: SVM is sensitive to feature scales because the margin is measured in Euclidean distance. Always standardize features before training.

17.1.7 Assumptions & Scope

Scope / Assumptions: - Linear separability: Hard-margin SVM assumes the data is linearly separable in the feature space. If it is not, the optimization has no feasible solution. Use soft-margin SVM (§17.2) instead. - Binary classification: The basic SVM handles exactly two classes. For multi-class, use one-vs-one or one-vs-rest strategies. - Convexity guarantee: The SVM dual is a convex quadratic program — any local optimum is global. This is a key advantage over neural networks. - No probability output: Standard SVM gives a hard decision (\(\pm 1\)), not calibrated probabilities. Use Platt scaling or the relevance vector machine (Bishop §7.2) if probabilities are needed.

Recap: SVM finds the widest possible empty street (margin) between two classes, using only the points at the street edge (support vectors). The three formulas to memorize: \(\mathbf{w} = \sum \alpha_i y_i \mathbf{x}_i\), \(b = y_s - \mathbf{w}\cdot\mathbf{x}_s\), and \(f(\mathbf{x}) = \text{sign}(\sum \alpha_i y_i (\mathbf{x}_i\cdot\mathbf{x}) + b)\).

Bridge: The hard-margin SVM assumes perfectly clean, separable data — but real-world data is never that tidy. In §17.2, we introduce the slack variable to handle noise and overlapping classes.

17.1.8 Real-World & Domain Connection

Linear SVMs are widely used for text classification (spam detection, sentiment analysis) because text data in bag-of-words representation is often high-dimensional and roughly linearly separable. They are also used in bioinformatics for gene expression classification, where the number of features (genes) far exceeds the number of samples — the max-margin property is especially valuable for controlling overfitting in this regime. The sparse solution (only support vectors matter) means prediction is fast, which is critical for real-time applications like email filtering.

17.2 Soft Margin SVM — Handling Noisy Data

Hook: A hard-margin SVM is like a bouncer who throws out anyone standing an inch past the velvet rope — even if they belong inside. Real data doesn't cooperate: students with perfect scores get rejected, and students with low scores get admitted. How do we build a classifier that tolerates a few rebels without losing the boundary entirely?

17.2.1 Motivation — When Hard Margins Fail

Intuition + Analogy: Think of a hard-margin SVM as drawing a line through a perfectly sorted pile of red and blue marbles — every red on one side, every blue on the other. Now imagine someone tosses a handful of marbles randomly across the pile. If you insist on a single clean line, you'll either misclassify the tossed marbles or twist the line into a crazy shape that overfits. A soft margin says: "I'll draw a reasonable line, and if a few marbles end up on the wrong side, I'll note the mistake but not upend the whole boundary for them." The penalty for being on the wrong side is the slack variable.

With a hard margin SVM, a single line separates the classes. Everything above the line is positive; everything below is negative. There is no tolerance.

Real-world datasets are never clean. Consider the GPA and entrance exam score example: even with high scores, some students may not get admission. Even with low scores, some may get admission to their top choice. Data points from one class can appear on the other side of an ideal boundary.

If a hard margin decision boundary is drawn through noisy data, many points will be misclassified, and accuracy will be very low.

Even when data is linearly separable, choosing a perfect decision boundary can lead to overfitting. A non-linear decision boundary that perfectly separates training data will not generalize well.

17.2.2 The Slack Variable

The solution is to make the margin soft — to accommodate noise by allowing some misclassification. This is done by introducing a slack variable, denoted \(\xi_i\) (the professor also used \(\epsilon_i\) verbally; \(\xi_i\) is the standard notation in Bishop §7.1.1).

Definition: The slack variable \(\xi_i\) represents the distance of a data point from the correct side of its margin.

Visual intuition: Two classes — filled circles vs. unfilled circles. A decision boundary with margins on each side. Now consider: - A filled-circle point that appears on the unfilled-circle side. It should be on the left/top side but ended up on the wrong side. \(\xi_i\) for that point = the distance from the correct-side margin. - Another filled-circle point near the margin but on the correct side — it is close but safe. It gets a small positive \(\xi_i\) between 0 and 1.

Values of the slack variable:

ConditionValue of \(\xi_i\)
Point is correctly classified AND well outside the margin\(\xi_i = 0\)
Point is correctly classified but inside the margin (close to boundary)\(0 < \xi_i < 1\)
Point is completely misclassified (on the wrong side)\(\xi_i > 1\)

The slack variable cannot be negative. You cannot give "extra credit" for a point that is very far away on the correct side.

The slack variable can be regarded as a measure of confidence in the classification: - \(\xi_i = 0\) → high confidence - \(0 < \xi_i < 1\) → some confidence, but the point is close enough to cause concern - \(\xi_i > 1\) → misclassified, low confidence

Data points located far away from the margin on the incorrect side receive a high penalty.

From the enrichment reference (Bishop §7.1.1): The slack variables are formally defined as \(\xi_n = 0\) for points on or inside the correct margin boundary, and \(\xi_n = |t_n - y(\mathbf{x}_n)|\) for other points. A data point on the decision boundary \(y(\mathbf{x}_n) = 0\) has \(\xi_n = 1\). This matches the professor's classification: \(\xi = 0\) for correctly classified outside margin; \(0 < \xi \leq 1\) for inside margin but correct side; \(\xi > 1\) for misclassified.

17.2.3 The Soft Margin Objective Function

The primal SVM formula becomes:

\[ \min_{\mathbf{w}, b, \xi} \quad \frac{1}{2}\|\mathbf{w}\|^2 + C \sum_{i=1}^{n} \xi_i \]

subject to: \[ y_i(\mathbf{w}^\top \mathbf{x}_i + b) \geq 1 - \xi_i, \quad \xi_i \geq 0 \]

The first term \(\frac{1}{2}\|\mathbf{w}\|^2\) maximizes the margin (minimizing this is equivalent to maximizing the margin).

The second term \(C \sum \xi_i\) is the penalty term (regularization). It penalizes points that violate the margin.

\(\mathbf{w}^\top \mathbf{x}_i\) is just the vector way of writing the dot product \(\mathbf{w} \cdot \mathbf{x}_i\). Both mean the same thing.

Derivation note (Bishop §7.1.1): The Lagrangian for the soft-margin problem introduces two sets of multipliers: \(a_n \geq 0\) for the margin constraints and \(\mu_n \geq 0\) for the \(\xi_n \geq 0\) constraints. Optimizing out \(\mathbf{w}, b, \{\xi_n\}\) yields the same dual form as the hard-margin case, but with box constraints \(0 \leq a_n \leq C\). Support vectors with \(a_n < C\) lie exactly on the margin (\(\xi_n = 0\)); those with \(a_n = C\) are inside the margin or misclassified.

17.2.4 The Hyperparameter C — The Football Coach Analogy

\(C\) is a hyperparameter that controls the trade-off between margin width and misclassification.

The football coach analogy:

Imagine a football court. A decision boundary is the center line. On each side of that line are two more lines — these are the margins. Two teams stand on each side. The coach wants to keep players on their own side.

- High C (strict coach): The coach is very strict. He will not allow any player to cross to the other side. He makes the margin very narrow (thin). Even if a player takes a few steps toward the other side, he is still safely on his own side. The margin is narrow, so training data is correctly classified. But this can lead to overfitting.

- Low C (liberal coach): The coach is relaxed. He makes the margin wider. Some players may cross to the other side — this is allowed. The margin is wider, so some misclassification is tolerated. There may be more training errors, but the model generalizes better.

Summary:

C valueCoachMarginMisclassificationRisk
HighStrictNarrowMinimalOverfitting
LowLiberalWideSome allowedBetter generalization

In Python, C is automatically set or can be tuned. In practice for noisy real-world data, a liberal coach (lower C, wider margin) is preferred because data points can be "naughty" — some data points have features similar to points on the other side and are confusing to classify.

17.2.5 Visual Intuition

Imagine the same 2D scatter plot from §17.1.5, but now some points of each class have crossed into the other class's territory. The decision boundary is still a straight line, but the margin boundaries (dashed lines) are now violated by some points. Each violating point has a little arrow drawn from it to its correct margin boundary — the length of that arrow is \(\xi_i\). Points with long arrows (misclassified) push hard on the boundary; points with short arrows (inside margin but correct) nudge gently. The total "push" is weighted by \(C\): high \(C\) means the boundary fights every violation; low \(C\) means it tolerates small pushes.

17.2.6 Pitfalls

Pitfalls: 1. Confusing \(\xi\) with hinge loss: The slack variable \(\xi_i\) is a concept — its mathematical realization is the hinge loss (covered in §17.3). Don't treat them as interchangeable in formulas. 2. C too high → overfitting: A very large \(C\) forces near-zero training error, making the model memorize noise. The margin becomes so narrow that the model loses generalization. 3. C too low → underfitting: A very small \(C\) allows too many misclassifications, and the margin becomes so wide that the boundary barely separates the classes. 4. \(\xi\) cannot be negative: You can't give bonus points for being far on the correct side. Slack only penalizes, never rewards. 5. Not just for non-separable data: Even when data is linearly separable, soft margin can help by preventing a boundary that overfits to borderline points.

17.2.7 Student Q&A

Q: If C is higher, does the total penalty value become more? A: Yes. A higher C means a larger penalty term overall, which forces the margin to be narrow so fewer points incur the penalty.

17.2.8 Assumptions & Scope

Scope / Assumptions: - Slack is linear: The penalty increases linearly with \(\xi\). This makes the SVM sensitive to outliers — one far-misclassified point can dominate the objective. The hinge loss (next section) formalizes this. - C must be tuned: There is no automatic "best" C. Cross-validation is standard practice. - Box constraints in the dual: The soft-margin dual differs from the hard-margin dual only by the constraint \(0 \leq \alpha_i \leq C\) (instead of just \(\alpha_i \geq 0\)). This is the only change — the dual objective is identical.

Recap: Soft-margin SVM introduces slack variables \(\xi_i\) that measure how far a point is from its correct margin. The hyperparameter \(C\) trades off margin width against misclassification penalty. Think of C as the strictness of the coach: high C = narrow margin, low C = wide margin.

Bridge: The slack variable is a conceptual tool. Its mathematical implementation in the loss function is the hinge loss, covered next in §17.3.

17.2.9 Real-World & Domain Connection

Soft-margin SVM is the default in virtually all real-world SVM applications because cleanly separable data is extremely rare. In medical diagnosis (e.g., classifying tumors as benign or malignant based on biomarkers), some patients defy the pattern — a patient with "benign" biomarker ranges may still have a malignant tumor. A hard margin would either misclassify that patient or contort the boundary in a medically unreasonable way. The soft margin allows the model to say: "This patient looks like the benign group, but I'm flagging them as an edge case." Similarly, in credit scoring, some high-income applicants default and some low-income applicants repay — soft margins accommodate these exceptions gracefully.

17.3 Hinge Loss — Mathematical Realization of the Slack Variable

Hook: The slack variable \(\xi_i\) is an intuitive idea — "how far is this point from where it should be?" But you can't plug a concept into an optimizer. You need a loss function. The hinge loss is that function: it takes the same intuition and turns it into a computable number that gradient-based solvers can minimize.

17.3.1 Definition

Intuition + Analogy: Think of a door hinge. When the door is pushed past its frame (correct side), nothing happens — zero loss. When it's pushed the wrong way past the frame, the hinge resists more and more the further you push. The hinge loss works the same way: correctly classified points produce zero loss (no resistance). Misclassified points produce loss proportional to how far they are on the wrong side. The "hinge" is at the margin boundary \(\pm 1\) — that's where loss starts accumulating.

The slack variable is a concept. Its mathematical realization in calculations is called the hinge loss. The hinge loss formula:

\[ L_{\text{hinge}} = \max(0, 1 - y_i (\mathbf{w} \cdot \mathbf{x}_i + b)) \]

Equivalently: \[ L_{\text{hinge}} = \max(0, 1 - y_i (\boldsymbol{\theta}^\top \mathbf{x}_i)) \]

Where \(\boldsymbol{\theta}^\top \mathbf{x}\) is the vector representation of the line equation \(mx + b\). The notations \(\boldsymbol{\theta}\) and \(\mathbf{w}\) are used interchangeably across different literature. \(\boldsymbol{\theta}^\top \mathbf{x}\) is the same as \(\mathbf{w} \cdot \mathbf{x} + b\).

From the enrichment reference (Bishop §7.1): The standard SVM error function can be written as \(E_{\infty}(y(\mathbf{x}_n)t_n - 1)\) where \(E_{\infty}(z) = 0\) if \(z \geq 0\) and \(\infty\) otherwise — this is the hard-margin error. The soft-margin relaxes this to a linear penalty, giving the hinge-loss form \(\max(0, 1 - y_i(\mathbf{w}^\top\mathbf{x}_i + b))\).

17.3.3 Hinge Loss Values by Classification Outcome

Case 1 — Correctly classified, positive class (\(y_i = +1\)):

The point is on the positive side. The prediction \(\mathbf{w} \cdot \mathbf{x}_i + b\) is greater than \(+1\).

\[ L = \max(0, 1 - 1 \times (\text{value} > 1)) = \max(0, 1 - (\text{something} > 1)) = \max(0, \text{negative}) = 0 \]

Case 2 — Correctly classified, negative class (\(y_i = -1\)):

The point is on the negative side. The prediction \(\mathbf{w} \cdot \mathbf{x}_i + b\) is less than \(-1\).

\[ L = \max(0, 1 - (-1) \times (\text{value} < -1)) = \max(0, 1 + (\text{value} < -1)) \]

Since the value is much less than \(-1\), \(1 + (\text{very negative})\) is still negative. So: \(\max(0, \text{negative}) = 0\).

Conclusion for correct classification: Hinge loss = 0, whether positive or negative class. This matches the slack variable concept — no penalty when correctly classified and outside the margin.

Why comparisons are against +1 and -1: If the prediction is exactly \(+1\) or \(-1\), the point lies exactly on the margin — these are the support vectors. For a non-support-vector correctly classified point, the prediction magnitude is greater than 1: on the positive side it is \(> +1\), on the negative side it is \(< -1\).

Case 3 — Incorrectly classified (\(y_i = +1\) but prediction is negative):

The point is on the wrong side. \(y_i = +1\) but \(\mathbf{w} \cdot \mathbf{x}_i + b < -1\).

\[ L = \max(0, 1 - 1 \times (\text{value} < -1)) = \max(0, 1 - (\text{very negative})) = \max(0, 1 + \text{something}) > 1 \]

The result is greater than 1.

Case 4 — Within the margin but correctly classified:

The point is on the correct side but inside the margin. The prediction is between 0 and 1 (for positive class) or between -1 and 0 (for negative class).

The hinge loss will be \(0 < L < 1\).

Summary of hinge loss values:

Classification statusHinge loss
Correctly classified, outside margin\(L = 0\)
Correctly classified, inside margin\(0 < L < 1\)
Incorrectly classified\(L > 1\)

17.3.4 The Complete Soft Margin Formulation with Hinge Loss

\[ \min_{\mathbf{w}, b} \quad \frac{1}{2}\|\mathbf{w}\|^2 + C \sum_{i=1}^{n} \max(0, 1 - y_i(\mathbf{w}^\top \mathbf{x}_i + b)) \]

Note: \(\frac{1}{2}\|\mathbf{w}\|^2\) is the same as \(\frac{1}{2}\mathbf{w}^\top\mathbf{w}\).

Subject to: \(\xi_i \geq 0\) (slack variable cannot be negative).

17.3.5 Visual Intuition — The Hinge Loss Shape

Plot the hinge loss as a function of \(z = y_i(\mathbf{w}^\top\mathbf{x}_i + b)\), the "signed distance from the boundary scaled by the margin." The x-axis is \(z\) and the y-axis is \(L\). For \(z \geq 1\) (correctly classified, outside margin), \(L = 0\) — a flat line at zero. For \(z < 1\), \(L = 1 - z\) — a straight line sloping down-left at 45 degrees. The "hinge" is at \(z = 1\), where the flat zero line meets the sloping penalty line. This shape is why it's called hinge loss: it looks like a door hinge opening at \(z = 1\).

17.3.6 Pitfalls

Pitfalls: 1. Threshold confusion: The threshold for zero loss is \(z \geq 1\), not \(z \geq 0\). A point exactly on the decision boundary (\(z = 0\)) has hinge loss = 1, not 0. 2. "Less than -1" arithmetic: When \(y_i = -1\) and prediction \(< -1\), the product \(y_i \times (\mathbf{w}^\top\mathbf{x}_i + b)\) is positive (negative × negative). Don't get the sign wrong. 3. Hinge loss vs. slack: \(\xi_i\) is the value of hinge loss for point \(i\), but in the optimization they serve different roles. Hinge loss is plugged into the objective directly; \(\xi_i\) appears in the constrained form. They represent the same quantity but aren't notationally interchangeable. 4. Non-differentiability at z=1: The hinge loss has a kink at \(z = 1\). Standard gradient descent needs subgradient methods at that point. In practice, solvers handle this.

17.3.7 Student Q&A

Q: For a negative-class point correctly classified, why is the hinge loss still 0? A: \(y_i = -1\), and the prediction is less than -1. So \(1 - (-1) \times (\text{less than }-1) = 1 + (\text{value less than }-1)\). Since the value is much less than -1, this sum is negative, and max(0, negative) = 0.

Q: Why is the threshold at +1 and -1, not at 0? A: Points exactly at +1 or -1 lie on the margin itself — those are the support vectors. Correctly classified points are beyond the margin, so their prediction magnitude exceeds 1.

Q: For a point within the margin on the correct side, what is the hinge loss? A: Between 0 and 1. The point is correctly classified but close to the boundary, so it gets a small penalty.

Recap: Hinge loss is the mathematical realization of the slack variable: \(L = \max(0, 1 - y_i(\mathbf{w}^\top\mathbf{x}_i + b))\). It is zero for correctly classified points outside the margin, between 0 and 1 for points inside the margin, and >1 for misclassified points.

Bridge: With hinge loss, the soft-margin SVM objective is fully specified as an unconstrained optimization. Next, we confront the core limitation: what if no straight line can separate the classes at all? That's where non-linear SVM (§17.4) comes in.

17.3.8 Real-World & Domain Connection

Hinge loss is not just an SVM peculiarity — it appears across machine learning wherever "margin-based" classification is used. In natural language processing, linear SVMs with hinge loss were the dominant text classifier before deep learning (e.g., for spam filters, topic categorization). The hinge loss's insensitivity to correctly classified points (zero gradient when \(z > 1\)) means the optimizer focuses exclusively on hard cases — which is exactly why SVMs produce sparse solutions. This sparsity is exploited in large-scale document ranking systems where only a tiny fraction of training documents (the support vectors) need to be stored for prediction.

17.4 Non-Linear SVM — The Need for Higher Dimensions

Hook: Can you separate the blue marbles from the red marbles when the blues are huddled in the center and the reds are on both sides? No single straight line on the floor can do it. But what if you could lift the reds off the floor into the air? Suddenly a tilted sheet of glass slides right between them. That's non-linear SVM — lifting data into a higher dimension where it becomes separable.

17.4.1 When Data is Not Linearly Separable

Intuition + Analogy: Consider a medicine dosage problem. Low dosage → no cure. High dosage → no cure. Only the perfect middle dosage cures. You plot "cured" (blue) in the middle and "not cured" (red) on both ends of a 1D line. No single point on that line can split blue from red. But if you add a second axis — dosage² — the reds on both ends shoot upward (squaring a number far from zero makes it large), while the blues near zero stay low. Now a diagonal line cleanly separates them. The trick is always the same: add dimensions that stretch the space so that what was tangled becomes untangled.

Linear SVM works when a single line (or hyperplane) can separate the classes. But some datasets are linearly inseparable — no single straight line can separate the two classes.

Example: Blue dots clustered near the origin (around zero) and red dots on both sides. Drawing a line anywhere leaves red dots on both sides. A single decision boundary cannot separate them.

Real-world example: Medicine dosage. A very low dosage does not cure the disease. A very high dosage also does not cure the disease. Only the right dosage in the middle cures the disease. So the "cured" class (blue dots) sits in the middle, surrounded by "not cured" (red dots) on both ends. This is a non-linear separation problem.

17.4.2 The Core Idea — Mapping to a Higher Dimension

The trick: map the data to a higher dimension. In the original one-dimensional space (only dosage \(x\)), the classes are not separable. Add a new dimension \(x^2\). Now:

- Points near 0 stay near 0 (squaring a small number keeps it small) - Points far from 0 (red dots on both sides) shoot upward when squared

In the higher-dimensional space, a straight diagonal line can separate the red dots from the blue dots perfectly.

Many things that are complex in lower dimensions become much simpler in higher dimensions. This is the key insight behind non-linear SVM.

Why this works mathematically: Cover's theorem states that a complex pattern-classification problem cast in a high-dimensional space nonlinearly is more likely to be linearly separable than in a low-dimensional space. The higher the dimension, the more "room" there is to place a hyperplane between classes.

17.4.3 The Mapping Function \(\phi\)

A function \(\phi(\mathbf{x})\) maps the original data point \(\mathbf{x}\) to a higher-dimensional coordinate system called the feature space.

In the higher-dimensional feature space, a hyperplane can be applied. Terminology: - In 2D: use a line - In 3D: use a plane - In 4D+: use a hyperplane - In SVM, everything is generally called a hyperplane regardless of dimension.

Example: Original 2D data \((x_1, x_2)\) that is not linearly separable (circles clustered in the middle, squares surrounding them). Transform to a 5D vector: \((x_1^2, x_2^2, \sqrt{2}x_1, \sqrt{2}x_2, 1)\). In 5D, the data becomes linearly separable. Then write the linear equation:

\[ w_0 + w_1(x_1^2) + w_2(x_2^2) + w_3(\sqrt{2}x_1) + w_4(\sqrt{2}x_2) = 0 \]

Mapping note: This 5-dimensional mapping \((x_1^2, x_2^2, \sqrt{2}x_1, \sqrt{2}x_2, 1)\) is a simplified illustrative example. The full polynomial kernel \((1 + \mathbf{x}_i^\top\mathbf{x}_j)^2\) for 2D data actually corresponds to a 6-dimensional mapping that also includes the cross-term \(\sqrt{2}x_1x_2\) — this is derived in §17.6. The 5D version shown here omits the cross term for simplicity and still illustrates the core concept.

If 2D → 3D is still not enough, the dimension can be increased further — up to thousands or even infinitely many dimensions.

17.4.4 Non-Linear SVM — The Two-Step Process

Step 1: Transform the original input data into a higher-dimensional space using a non-linear mapping \(\phi\).

Step 2: Search for a linear separating hyperplane in that new space. This becomes a quadratic optimization problem that can be solved using linear SVM.

So only one extra step is added: transforming the input data into a higher dimension. After transformation, solve it exactly like linear SVM.

17.4.5 The Non-Linear SVM Equation

Linear SVM decision boundary: \(\mathbf{w} \cdot \mathbf{x} + b = 0\)

Non-linear SVM decision boundary: \(\mathbf{w} \cdot \phi(\mathbf{x}) + b = 0\)

The constrained optimization remains the same structure — only \(\mathbf{x}\) is replaced by \(\phi(\mathbf{x})\).

In the dual formulation, instead of the dot product \(\mathbf{x}_i \cdot \mathbf{x}_j\), use \(\phi(\mathbf{x}_i) \cdot \phi(\mathbf{x}_j)\). Nothing else changes.

The formulas for \(\mathbf{w}\) and \(b\) also change only by replacing \(\mathbf{x}_i\) with \(\phi(\mathbf{x}_i)\).

For test records (denoted as \(\mathbf{z}\)), convert the test tuple into the higher dimension using the same mapping function \(\phi\) used for training.

17.4.6 Visual Intuition

Picture a 1D number line with blue dots at \(x = 0\) and red dots at \(x = -3\) and \(x = +3\). No single cut point separates them. Now add a vertical axis for \(x^2\). The blue dot at \(x=0\) stays at height 0. The red dots at \(x = \pm 3\) jump to height 9. In this 2D space \((x, x^2)\), the blues are at \((0, 0)\) and the reds are at \((-3, 9)\) and \((3, 9)\). A line with negative slope can now slice between them. The non-linear boundary in 1D ("the middle region is blue") has become a linear boundary in 2D.

17.4.7 Key Pedagogical Points

Pitfalls: 1. "I can just keep adding dimensions": While Cover's theorem says higher dimensions help, blindly adding dimensions causes the curse of dimensionality — data becomes sparse and distances become meaningless. The kernel trick (§17.5) solves this by working implicitly. 2. Confusing \(\phi\) with the kernel: \(\phi(\mathbf{x})\) is the explicit mapping function. The kernel \(K(\mathbf{x}_i, \mathbf{x}_j) = \phi(\mathbf{x}_i)^\top\phi(\mathbf{x}_j)\) bypasses computing \(\phi\) altogether. They are related but not the same thing. 3. "Any mapping works": The mapping must correspond to a valid kernel satisfying Mercer's conditions (§17.7). You can't arbitrarily define \(\phi\) and expect the SVM dual to be well-behaved. 4. Overfitting in high dimensions: Just because data can be separated in a million-dimensional space doesn't mean the boundary will generalize. The margin (controlled by C) still matters.

- The complex non-linear boundary found in the lower-dimensional space and the linear hyperplane in the higher-dimensional space are the same thing. Finding a complicated circle in 2D is equivalent to finding a simple hyperplane in a higher dimension. - These concepts are difficult on first exposure. It takes practice and multiple passes. Everyone is on the same page learning this material.

Recap: Non-linear SVM maps data to a higher-dimensional feature space via \(\phi(\mathbf{x})\) where a linear hyperplane can separate the classes. The non-linear boundary in the original space corresponds to a linear boundary in the feature space.

Bridge: Explicitly computing \(\phi(\mathbf{x})\) for every data point and then taking dot products is computationally infeasible. The kernel trick (§17.5) lets us skip the explicit mapping entirely.

17.4.8 Real-World & Domain Connection

Non-linear SVM with RBF kernels was the state-of-the-art for handwritten digit recognition (e.g., USPS dataset, MNIST) before deep convolutional networks took over. The insight — that a non-linear boundary in pixel space corresponds to a linear boundary in some learned feature space — is the same principle that underlies the kernel methods used today in computational biology for protein structure prediction. When the number of features is moderate but the decision boundary is known to be non-linear (e.g., in spectroscopy-based material classification), non-linear SVMs remain competitive and interpretable.

17.5 The Kernel Trick

17.5.1 The Computational Problem

Real-world datasets can have millions of records. Moving every single data point from a lower dimension to a higher dimension is computationally very expensive and not feasible. It requires enormous memory and processing power. A computer may crash trying to explicitly map 10 million records to a million-dimensional space.

17.5.2 What the Kernel Trick Does

The kernel trick calculates the relationship (similarity) between points as if they were in a higher dimension, without actually transforming the data into that higher dimension.

It computes the dot product in the high-dimensional space without ever performing the mathematical transformation \(\phi\). This avoids the explicit mapping, which drastically reduces computations.

17.5.3 The Kernel Function

A kernel function \(K\) calculates the inner product of the projected points:

\[ K(\mathbf{x}_i, \mathbf{x}_j) = \phi(\mathbf{x}_i)^\top \phi(\mathbf{x}_j) \]

- \(\mathbf{x}_i, \mathbf{x}_j\) — original data points in low-dimensional space - \(\phi\) — mapping function that would theoretically move data to higher dimension - \(K\) — kernel function that gives the dot product in high-dimensional space directly

The SVM hypothesis function changes from: \[ \sum_i \alpha_i y_i (\mathbf{x}_i^\top \mathbf{x}) \] to: \[ \sum_i \alpha_i y_i K(\mathbf{x}_i, \mathbf{x}) \]

17.5.4 Common Kernel Functions

Kernel typeFormula
Linear kernel\(K(\mathbf{x}_i, \mathbf{x}_j) = \mathbf{x}_i^\top \mathbf{x}_j\) (simple dot product)
Polynomial kernel\(K(\mathbf{x}_i, \mathbf{x}_j) = (1 + \mathbf{x}_i^\top \mathbf{x}_j)^d\) for degree \(d = 2, 3, 4, \ldots\)
Gaussian (RBF) kernel\(K(\mathbf{x}_i, \mathbf{x}_j) = \exp(-\gamma \|\mathbf{x}_i - \mathbf{x}_j\|^2)\)
Sigmoid kernel\(K(\mathbf{x}_i, \mathbf{x}_j) = \tanh(\kappa \mathbf{x}_i^\top \mathbf{x}_j + c)\)

The linear kernel is what has been used so far in hard-margin SVM — just the dot product of the data points.

17.5.5 Worked Kernel Trick Demonstration — 2D to 3D

Given: Two 2D vectors \(\mathbf{a} = (a_1, a_2)\) and \(\mathbf{b} = (b_1, b_2)\).

Step 1 — Define a mapping \(\phi\) that takes 2D to 3D:

\[ \phi(\mathbf{a}) = (a_1^2,\; \sqrt{2}a_1a_2,\; a_2^2) \] \[ \phi(\mathbf{b}) = (b_1^2,\; \sqrt{2}b_1b_2,\; b_2^2) \]

The \(\sqrt{2}\) terms are for mathematical convenience — they make the algebra work out cleanly.

The mapping works by taking the product of every pair of components: \(a_1 \times a_1 = a_1^2\), \(a_1 \times a_2\) (with \(\sqrt{2}\)), \(a_2 \times a_2 = a_2^2\).

Step 2 — Dot product of the transformed vectors:

\[ \phi(\mathbf{a})^\top \phi(\mathbf{b}) = a_1^2 b_1^2 + 2a_1a_2b_1b_2 + a_2^2 b_2^2 \]

(Since \(\sqrt{2} \times \sqrt{2} = 2\), the middle term has coefficient 2.)

Step 3 — Recognize the simplification:

This expression equals \((a_1b_1 + a_2b_2)^2\), which is \((\mathbf{a}^\top \mathbf{b})^2\).

So: \(\phi(\mathbf{a})^\top \phi(\mathbf{b}) = (\mathbf{a}^\top \mathbf{b})^2\).

The trick: Instead of converting \(\mathbf{a}\) and \(\mathbf{b}\) to 3D explicitly (computing \(\phi\) for every point), just take the dot product in the original 2D space and square it. The result is identical to what the 3D dot product would give.

17.5.6 Worked Kernel Trick Demonstration — 3D to 9D

Given: Two 3D vectors \(\mathbf{x} = (x_1, x_2, x_3)\) and \(\mathbf{y} = (y_1, y_2, y_3)\).

Step 1 — Define \(\phi\) for 3D:

Take the product of every pair of components: \[ \phi(\mathbf{x}) = (x_1^2,\; x_1x_2,\; x_1x_3,\; x_2x_1,\; x_2^2,\; x_2x_3,\; x_3x_1,\; x_3x_2,\; x_3^2) \]

This is a 9-dimensional vector. Same for \(\phi(\mathbf{y})\).

Step 2 — Dot product of the 9D vectors:

Taking \(\phi(\mathbf{x})^\top \phi(\mathbf{y})\) and simplifying yields \((x_1y_1 + x_2y_2 + x_3y_3)^2 = (\mathbf{x}^\top \mathbf{y})^2\).

The trick again: The result of the 9D dot product is exactly the square of the simple 3D dot product.

In practice, Python's SVM implementation uses this reverse-engineering approach — it knows from the mathematical derivation that \((\mathbf{x}^\top \mathbf{y})^2\) equals the high-dimensional dot product, so it never explicitly computes \(\phi\).

17.5.7 Student Q&A

Q: How do we get the five terms for the 2D-to-5D mapping? A: The mapping functions are derived through reverse engineering. In practice, starting from the known result \((\mathbf{x}^\top \mathbf{y})^2\), one works backward to find what \(\phi\) must be. The specific \(\phi\) is chosen so that \(\phi(\mathbf{x})^\top \phi(\mathbf{y}) = (\mathbf{x}^\top \mathbf{y})^2\). This is not a blind assumption — the mapping is derived from the desired kernel.

Q: Do we actually compute \(\phi\)? A: No. The explicit mapping is only shown for understanding. In actual implementation, only the dot product of the original data points is computed and squared. Both approaches give the same answer, but the kernel trick avoids the expensive explicit transformation.

17.5.8 Visual Intuition

The kernel trick is easiest to see with the polynomial kernel \(K(\mathbf{a},\mathbf{b}) = (\mathbf{a}^\top\mathbf{b})^2\). In 2D, the explicit mapping \(\phi\) takes a point \((a_1, a_2)\) and produces a 3D point \((a_1^2, \sqrt{2}a_1a_2, a_2^2)\). Computing \(\phi(\mathbf{a})^\top\phi(\mathbf{b})\) requires 3 multiplications and 2 additions. But \((\mathbf{a}^\top\mathbf{b})^2 = (a_1b_1 + a_2b_2)^2\) requires only 2 multiplications, 1 addition, and 1 square — and gives the exact same number. For an RBF kernel mapping to infinite dimensions, the savings are infinite.

17.5.9 Pitfalls

Pitfalls: 1. Kernel ≠ \(\phi\): The kernel \(K(\mathbf{x}_i, \mathbf{x}_j)\) is a function of two arguments. The mapping \(\phi(\mathbf{x})\) is a function of one argument. The kernel is the inner product of two mapped points, but it's not the mapping itself. 2. Not all kernels are equal: The RBF (Gaussian) kernel can model arbitrarily complex boundaries but requires tuning \(\gamma\). The polynomial kernel is simpler but limited to polynomial decision boundaries. 3. Kernel matrix size: The kernel matrix \(\mathbf{K}\) is \(N \times N\) (where \(N\) is the number of training points). For \(N = 100{,}000\), storing this matrix takes ~40 GB. Scalability is the main practical limitation of kernel SVMs. 4. Normalization matters: Kernels based on distances (like RBF) are sensitive to feature scales. Always standardize before applying.

Starting from the known result \((\mathbf{x}^\top\mathbf{y})^2\), one works backward to find what \(\phi\) must be. The specific \(\phi\) is chosen so that \(\phi(\mathbf{x})^\top\phi(\mathbf{y}) = (\mathbf{x}^\top\mathbf{y})^2\).

Q: Do we actually compute \(\phi\)? A: No. The explicit mapping is only shown for understanding. In actual implementation, only the dot product of the original data points is computed and squared. Both approaches give the same answer, but the kernel trick avoids the expensive explicit transformation.

Recap: The kernel trick replaces \(\phi(\mathbf{x}_i)^\top\phi(\mathbf{x}_j)\) with \(K(\mathbf{x}_i, \mathbf{x}_j)\), computing high-dimensional inner products without ever leaving the original space.

17.5.11 Real-World & Domain Connection

The kernel trick is not unique to SVM — it underpins all kernel methods including kernel PCA, kernel ridge regression, and Gaussian processes. In computational biology, string kernels compute similarity between DNA sequences without explicitly enumerating all subsequences. In computer vision, histogram intersection kernels enable fast image comparisons. The general principle — "compute in the dual using only inner products" — is one of the most powerful ideas in machine learning.

17.6 Proving a Function is a Kernel

Hook: You're handed a formula like \(K(\mathbf{x}_i, \mathbf{x}_j) = (1 + \mathbf{x}_i^\top \mathbf{x}_j)^2\) and asked: "Is this a kernel?" The answer is yes — but you must prove it by reverse-engineering the hidden mapping \(\phi\). This is a standard exam question.

17.6.1 How to Verify a Kernel Function

Intuition + Analogy: Proving a function is a kernel is like reverse-engineering a recipe. Someone hands you a cake and says "this was made from flour, eggs, and sugar." Your job: figure out the exact proportions and mixing method. The kernel is the cake; \(\phi\) is the recipe. You expand algebraically, spot patterns (coefficients of 2 that hint at \(\sqrt{2}\) terms), and reconstruct what \(\phi\) must have been.

Exam-style question: Given \(K(\mathbf{x}_i, \mathbf{x}_j) = (1 + \mathbf{x}_i^\top \mathbf{x}_j)^2\), show that it is a valid kernel function.

Method: To prove \(K\) is a kernel, find a mapping \(\phi\) such that \(K(\mathbf{x}_i, \mathbf{x}_j) = \phi(\mathbf{x}_i)^\top \phi(\mathbf{x}_j)\).

Step-by-step derivation:

1. Write the dot product explicitly: \(\mathbf{x}_i^\top \mathbf{x}_j = x_{i1}x_{j1} + x_{i2}x_{j2}\) (for 2D vectors).

2. Substitute: \(K = (1 + x_{i1}x_{j1} + x_{i2}x_{j2})^2\).

3. This is \((a + b + c)^2\) where \(a = 1\), \(b = x_{i1}x_{j1}\), \(c = x_{i2}x_{j2}\).

4. Expand using \((a + b + c)^2 = a^2 + b^2 + c^2 + 2ab + 2ac + 2bc\): \[ \begin{aligned} K &= 1^2 + (x_{i1}x_{j1})^2 + (x_{i2}x_{j2})^2 \\ &\quad + 2(1)(x_{i1}x_{j1}) + 2(1)(x_{i2}x_{j2}) + 2(x_{i1}x_{j1})(x_{i2}x_{j2}) \\[4pt] &= 1 + x_{i1}^2 x_{j1}^2 + x_{i2}^2 x_{j2}^2 \\ &\quad + 2x_{i1}x_{j1} + 2x_{i2}x_{j2} + 2x_{i1}x_{i2}x_{j1}x_{j2} \end{aligned} \]

Expansion verified. ✓ The algebra is exact.

5. The coefficient 2 in three terms signals \(\sqrt{2}\) factors. Rewrite as a dot product of two 6D vectors:

\[ \phi(\mathbf{x}_i) = \begin{pmatrix} 1, & x_{i1}^2, & x_{i2}^2, & \sqrt{2}\,x_{i1}, & \sqrt{2}\,x_{i2}, & \sqrt{2}\,x_{i1}x_{i2} \end{pmatrix} \]

\[ \phi(\mathbf{x}_j) = \begin{pmatrix} 1, & x_{j1}^2, & x_{j2}^2, & \sqrt{2}\,x_{j1}, & \sqrt{2}\,x_{j2}, & \sqrt{2}\,x_{j1}x_{j2} \end{pmatrix} \]

Then: \[ \begin{aligned} \phi(\mathbf{x}_i)^\top \phi(\mathbf{x}_j) &= 1\cdot 1 + x_{i1}^2 x_{j1}^2 + x_{i2}^2 x_{j2}^2 \\ &\quad + (\sqrt{2}x_{i1})(\sqrt{2}x_{j1}) + (\sqrt{2}x_{i2})(\sqrt{2}x_{j2}) + (\sqrt{2}x_{i1}x_{i2})(\sqrt{2}x_{j1}x_{j2}) \\[4pt] &= 1 + x_{i1}^2 x_{j1}^2 + x_{i2}^2 x_{j2}^2 + 2x_{i1}x_{j1} + 2x_{i2}x_{j2} + 2x_{i1}x_{i2}x_{j1}x_{j2} \end{aligned} \]

This matches the expansion of \((1 + \mathbf{x}_i^\top \mathbf{x}_j)^2\) exactly. ✓

6. So \(K(\mathbf{x}_i, \mathbf{x}_j) = \phi(\mathbf{x}_i)^\top \phi(\mathbf{x}_j)\) is satisfied — it is a valid kernel function. The original 2D data is implicitly mapped to 6 dimensions.

General pattern: The polynomial kernel \((1 + \mathbf{x}^\top\mathbf{y})^d\) maps \(D\)-dimensional data to \(\binom{D+d}{d}\) dimensions. For \(D=2, d=2\): \(\binom{4}{2} = 6\) dimensions.

Exam note: This type of question — "show that a given function is a kernel function" — may appear on the exam. The mapping function \(\phi\) will be given, or the kernel will need to be expanded and \(\phi\) reconstructed as shown above.

17.6.2 Pitfalls

Pitfalls: 1. Forgetting the constant term: The "1" in \((1 + \mathbf{x}_i^\top \mathbf{x}_j)^d\) adds a bias dimension to \(\phi\). Omitting it gives \((\mathbf{x}_i^\top\mathbf{x}_j)^d\), which is also valid but maps to fewer dimensions (no bias). 2. Missing cross-terms: For degree \(d > 1\), the expansion includes interaction terms like \(x_{i1}x_{i2}x_{j1}x_{j2}\). These correspond to \(\sqrt{2}x_1x_2\) in \(\phi\). 3. Forgetting \(\sqrt{2}\): If you write \(\phi\) without \(\sqrt{2}\) factors, the dot product won't match. The \(\sqrt{2}\) comes from \((\sqrt{2}a)(\sqrt{2}b) = 2ab\). 4. Confusing kernel proof with Mercer's theorem: Proving a specific function is a kernel (by finding \(\phi\)) is different from checking arbitrary functions against Mercer's conditions (§17.7). The \(\phi\)-finding method is exam-relevant.

Recap: To prove \(K\) is a kernel: expand algebraically, identify \(\sqrt{2}\) hints from coefficient-2 terms, reconstruct \(\phi\) such that \(\phi(\mathbf{x}_i)^\top\phi(\mathbf{x}_j)\) matches the expansion.

Bridge: Not every function can be a kernel. Mercer's theorem (§17.7) gives the necessary conditions.

17.7 Mercer's Theorem — Conditions for Valid Kernels

Hook: You can't just invent a function and call it a kernel. If you do, the SVM optimization might not even have a solution — the dual could be unbounded. Mercer's theorem is the gatekeeper: it tells you which functions are legitimate kernels and which are impostors.

17.7.1 Why Not Every Function is a Kernel

Intuition + Analogy: A kernel computes a dot product in some feature space. A dot product must behave like one: it must be symmetric (\(\mathbf{a}\cdot\mathbf{b} = \mathbf{b}\cdot\mathbf{a}\)) and it must produce a positive length for any non-zero vector (\(\mathbf{v}\cdot\mathbf{v} > 0\)). If a function violates these properties, there is no feature space where it could be a valid inner product. Mercer's theorem formalizes exactly these requirements — it's like a building code that every kernel must pass.

Not every function can serve as a kernel. A function \(K\) must satisfy certain conditions to behave like a true dot product in some feature space.

17.7.2 Mercer's Conditions

To guarantee that \(K\) behaves like a true dot product in some feature space, it must satisfy Mercer's theorem. The two key conditions introduced in the lecture:

1. Continuity: \(K\) must be continuous — no breaks or jumps in the function. 2. Symmetry: \(K(\mathbf{x}_i, \mathbf{x}_j) = K(\mathbf{x}_j, \mathbf{x}_i)\). The order of the two arguments does not matter. This follows from \(\phi(\mathbf{x}_i)^\top \phi(\mathbf{x}_j) = \phi(\mathbf{x}_j)^\top \phi(\mathbf{x}_i)\).

Kernels satisfying Mercer's theorem are called Mercer kernels.

Full statement (from Bishop §7.1): Mercer's theorem requires that the kernel matrix (Gram matrix) \(\mathbf{K}\) with entries \(K_{nm} = K(\mathbf{x}_n, \mathbf{x}_m)\) be positive semidefinite for any set of points \(\{\mathbf{x}_n\}\). That is, for any vector \(\mathbf{v}\), \(\mathbf{v}^\top\mathbf{K}\mathbf{v} \geq 0\). Continuity and symmetry are necessary but not enough — positive semidefiniteness is the complete condition. The professor's focus on continuity and symmetry gives the practical essence.

17.7.3 Constructing Kernels

From existing kernels (if \(K_1, K_2\) are valid kernels): - \(K = \alpha K_1\) where \(\alpha > 0\) — multiply by a positive constant - \(K = K_1 + \alpha\) where \(\alpha > 0\) — add a positive constant - \(K = K_1 + K_2\) — sum of two kernels - \(K = K_1 \times K_2\) — product of two kernels

From distance metrics:

A valid distance function \(d(\mathbf{x}, \mathbf{x}')\) must satisfy four properties: 1. Non-negativity: \(d(\mathbf{x}, \mathbf{x}') \geq 0\) — distance cannot be negative 2. Identity: \(d(\mathbf{x}, \mathbf{x}) = 0\) — distance from a point to itself is zero 3. Symmetry: \(d(\mathbf{x}, \mathbf{x}') = d(\mathbf{x}', \mathbf{x})\) 4. Triangle inequality: \(d(\mathbf{x}, \mathbf{z}) \leq d(\mathbf{x}, \mathbf{x}') + d(\mathbf{x}', \mathbf{z})\) — the direct distance is always less than or equal to an indirect path through a third point

Common distance functions (Euclidean, Manhattan) satisfy these implicitly. Any valid distance metric can be turned into a kernel:

\[ K(\mathbf{x}, \mathbf{x}') = e^{-d(\mathbf{x}, \mathbf{x}')} \]

17.7.4 Student Q&A

Q: How did we know the mapping function \(\phi\) for a given kernel? A: It comes from reverse engineering. The kernel formula like \((1 + \mathbf{x}_i^\top \mathbf{x}_j)^2\) is expanded algebraically. When the expansion shows a coefficient of 2, that is the hint to use \(\sqrt{2}\) terms in \(\phi\). The expansion is rewritten as a dot product of two vectors, and those vectors become \(\phi(\mathbf{x}_i)\) and \(\phi(\mathbf{x}_j)\).

Recap: Mercer's theorem is the quality check for kernels: a valid kernel must be continuous, symmetric, and produce a positive semidefinite Gram matrix. The Gaussian (RBF), polynomial, and sigmoid kernels all satisfy these conditions.

17.8 Non-Linear SVM — Worked Numerical Example

Hook: You've learned the theory — mapping functions, kernels, dual formulations. Now let's see it all work together. Given 8 data points that are linearly inseparable, a custom mapping function \(\phi\), and the same linear SVM method from §17.1, you can solve a complete non-linear SVM problem from start to finish.

Intuition: This is a two-stage process. Stage 1: apply \(\phi\) to "untangle" the data. Stage 2: solve a standard linear SVM on the transformed data. Stage 2 is identical to the §17.1 worked example — you already know how to do it. The only new part is Stage 1, and the mapping function \(\phi\) will always be provided in exam problems.

17.8.1 Problem Setup

Given data:

Blue class vectors (4 points): \((1, 1)\), \((1, -1)\), \((-1, 1)\), \((-1, -1)\) — clustered near the origin.

Red class vectors (4 points): \((2, 0)\), \((0, 2)\), \((-2, 0)\), \((0, -2)\) — surrounding the blue points.

There is no single straight line that can separate these blue and red points. The blue points are at the center, surrounded by red points — linearly inseparable.

Given mapping function \(\phi\):

If the Euclidean distance \(\sqrt{x_1^2 + x_2^2} \geq 2\): \[ \phi(x_1, x_2) = (6 - |x_1 + x_2|,\; (x_1 - x_2)^2,\; 6 - |x_2|) \]

Otherwise, the point remains unchanged: \(\phi(x_1, x_2) = (x_1, x_2)\).

17.8.2 Apply the Mapping

Blue points: For each of the four blue points \((1,1), (1,-1), (-1,1), (-1,-1)\), the Euclidean distance is \(\sqrt{1^2 + (\pm 1)^2} = \sqrt{2} \approx 1.414 < 2\). So all four blue points remain unchanged: \(\phi(\mathbf{x}) = \mathbf{x}\). ✓

Red points: For \((2, 0)\), Euclidean distance = \(\sqrt{4 + 0} = 2 \geq 2\). Apply the transformation: \[ \phi(2, 0) = (6 - |2 + 0|,\; (2 - 0)^2,\; 6 - |0|) = (6 - 2,\; 4,\; 6) = (4,\; 4,\; 6) \] The computation follows directly from the given \(\phi\) formula. ✓ The lecture also mentions an alternative numerical example with different \(\phi\); both are correct within their respective problem statements.

Similarly for \((0, 2)\), \((-2, 0)\), and \((0, -2)\) — all satisfy the distance condition and get transformed.

After transformation, the red dots move to a different region of the space. The data becomes linearly separable.

17.8.3 Finding Support Vectors and Solving

After the mapping, identify the support vectors. In this example, three support vectors are found: \(s_1, s_2, s_3\).

Add the bias: Augment each support vector with a bias term (value 1), just as in the linear SVM numerical.

Write equations for \(\alpha_1, \alpha_2, \alpha_3\): Three linear equations in terms of the Lagrange multipliers, using the same method as the linear SVM problem at the start.

Solve: Solve the system of three equations to get \(\alpha_1, \alpha_2, \alpha_3\).

Compute \(\mathbf{w}\): \[ \mathbf{w} = \sum_{k=1}^{3} \alpha_k y_k \mathbf{s}_k \] The augmented vector has three features. The third component is the bias.

Result: \(\mathbf{w} = (1, 1, -10.057)\).

Weight vector: \((1, 1)\). Bias: \(-10.057\).

17.8.4 Drawing the Decision Boundary

Decision boundary equation: \(\mathbf{w} \cdot \mathbf{x} + b = 0\).

Substituting: \(1 \cdot x_1 + 1 \cdot x_2 - 10.057 = 0\).

So: \(x_2 = 10.057 - x_1\).

To draw the line, substitute different values of \(x_1\) and compute the corresponding \(x_2\).

17.9 FACT ML — Fairness, Accountability, and Transparency

Hook: An algorithm doesn't have morals — it learns whatever patterns exist in the data you feed it, including society's worst biases. When Amazon's hiring AI penalized resumes containing "women," or when facial recognition failed on darker skin tones, it wasn't malice — it was training data that encoded historical discrimination. FACT ML is the framework for preventing, detecting, and fixing these failures.

17.9.1 Definitions

FACT ML (also written FACCT): Fairness, Accountability, and Transparency in Machine Learning.

Fairness is the absence of bias — no favoring of a group or a set of people, knowingly or unknowingly.

Bias is knowingly or unknowingly favoring a group or a set of data. It can arise from multiple reasons in the dataset.

Accountability is determining responsibility when models fail. The question of who takes accountability when AI models fail is still an active debate. This must be defined before starting any AI project.

Transparency means ensuring models comply with regulations and are understandable. It addresses questions like how to make ML models transparent and compliant.

17.9.2 Real-World Examples of Algorithmic Bias

1. Amazon's AI hiring tool (circa 2018): Reportedly penalized resumes containing the word "women." The model learned gender bias from historical hiring data.

2. Webcam facial recognition (circa 2022-2023): Reports claimed webcams struggled to recognize people of color. There was not enough training data of people with darker skin tones.

3. Online passport application system: Incorrectly identified a person's eyes as closed. This shows the impact of algorithmic bias and poor performance across different demographics — not enough data of certain groups to categorize them properly.

4. COMPAS (Correctional Offender Management Profiling for Alternative Sanctions): A risk assessment algorithm used in the US criminal justice system. Introduced to predict a defendant's likelihood of recidivism (re-offending), violent recidivism, or failure to appear in court.

The COMPAS controversy (circa 2016): People of color were consistently labeled as high risk, while white people were labeled as low risk. The prediction was majorly considering race, which was incorrect.

This controversy sparked major discussions on algorithmic fairness, bias, and eventually the FACT ML framework itself. Before COMPAS, the term "FACT" was not widely used — the controversy drove the importance of these concepts.

5. Occupation gender bias: Research shows correlation between the gender demographic of a profession and the "woman bias" score assigned by models. Occupations with higher percentage of women (nurse, librarian) get higher woman bias scores. Traditional male-dominated jobs (engineer, carpenter) show lower or negative scores. This reinforces stereotypes.

17.9.3 How ML Models Learn and Amplify Bias

ML models approximate patterns present in training data. In the process of learning these patterns, models can simultaneously learn — and even amplify — the biases present in the data, whether introduced knowingly or unknowingly.

Models can still discriminate despite being programmed to follow instructions, because they absorb the biases embedded in their training data.

Key insight (from the professor): Even when you program a model to be neutral, it learns from data that is not neutral. The model doesn't "decide" to be biased — it faithfully reproduces the bias it found in the training distribution. This is why data auditing is not optional; it's essential.

17.9.4 Addressing Bias — Removing Sensitive Features

A common approach: remove sensitive features (race, ethnicity, gender) from the dataset during data preprocessing.

But removing sensitive features alone is not enough. Other features can serve as proxies that indirectly reveal the sensitive attribute. Example: even after removing race and ethnicity, a column like "often goes to Mexican markets" can still allow the model to infer race.

Best practice: At the data collection stage itself, consider which features might encode sensitive information. During preprocessing, remove not only the directly sensitive columns but also columns from which sensitivity can be inferred. Address bias at the source.

All standard data preprocessing steps apply: discretization, normalization, removing noise, handling outliers, handling missing data — and additionally, auditing for sensitive features.

17.10 Model Interpretability

Hook: A self-driving car slams the brakes on a clear highway. Why? If you can't answer that question, you can't fix the bug, you can't defend the car in court, and you can't trust it with human lives. Interpretability is the "why" behind every ML decision — and in high-stakes domains, it's not optional, it's a legal requirement.

17.10.1 Why Interpretability Matters

Interpretability is the ability to explain why a model made a particular decision. It is critical in several domains:

1. Autonomous vehicles: If a self-driving car stops, accelerates, or causes an accident, the decision must be explainable to a court.

2. Security and surveillance: AI systems used in facial recognition or surveillance must be transparent. Without transparency, there is no way to know if the system is discriminating against certain groups or using faulty criteria.

3. Finance: Algorithms used for creditworthiness and loan approval must be able to explain why an application was denied for one person and approved for another. This is a legal compliance requirement.

Legal compliance is required in all these applications: autonomous vehicles, security, and finance.

17.10.2 The Accuracy-Interpretability Trade-off

There is an inverse relationship between model accuracy and model interpretability.

- Models with high accuracy (deep learning, ensemble models with 500 estimators) have lower interpretability. It is very difficult to explain the result of 500 sequential models. - Models that are inherently more interpretable (linear/logistic regression, decision trees) often provide lower predictive accuracy.

17.10.3 Highly Interpretable Models

Decision trees are among the most interpretable models:

- Structure resembles a flow chart — a tree where each branch represents the outcome of a decision. - This mirrors how humans make decisions in real life. - It is essentially a series of if-then-else rules. You can trace the exact path back and see why the tree made a decision. - The root node feature is selected based on feature importance — there is a clear, quantifiable reason why a particular feature sits at the top of the tree. - Decision trees can be used to examine a model's bias in its decision-making process because the logic is traceable.

State space representation of decision trees (KD-tree / K-dimensional tree):

Example: \(x_2 < 0.3\) splits the space. On one side, \(x_1\) further splits. On the other side, another split. Each region of the feature space corresponds to a path through the tree. This geometric interpretation makes decisions highly interpretable.

Linear regression is highly interpretable:

- Each feature is assigned a weight. The weight determines how much influence that feature has on the prediction. - By examining the weights, one can explain which features drive the prediction and by how much.

K-Nearest Neighbors (k-NN) is interpretable:

- After classification, one can explain: "This point was classified as green because its five nearest neighbors closely resemble the green class." This mirrors how people make judgments by similarity.

17.10.4 L1 vs L2 Regularization for Interpretability

L1 regularization (Lasso):

The penalty term is the sum of the absolute values of the weights: \(\sum |w_i|\).

Due to the geometry of the L1 constraint (diamond-shaped in 2D), the optimization drives many coefficients exactly to zero. This produces a sparse model — not all features are used.

L2 regularization (Ridge):

The penalty term is the sum of the squares of the weights: \(\sum w_i^2\).

L2 reduces coefficient values but does not shrink any coefficient all the way to zero. All features remain in the model.

Recap: Interpretability is the "why" behind model decisions. Decision trees (if-then-else rules), linear regression (feature weights), and k-NN (nearest-neighbor reasoning) are inherently interpretable. For black-box models, LIME and SHAP provide local explanations. L1 regularization promotes sparsity, which further aids interpretability by reducing the number of features that need explaining.

17.10.5 LIME and SHAP — Explaining Black-Box Models

LIME — Local Interpretable Model-agnostic Explanations:

LIME does not explain the model. It explains individual predictions. It is model-agnostic — it does not care how the original model was built; it can be applied to any ML model.

How LIME works (illustrative example with image classification):

1. A model predicts an animal as a "dog." 2. LIME hides (perturbs) one part of the image — for example, the ear — and asks the model to predict again. The model may still predict "dog" but with lower confidence. 3. LIME hides a different part (e.g., the nose) and asks again. 4. By creating multiple versions of the input and observing how predictions change, LIME builds an understanding of which parts of the input matter most. 5. Based on these local perturbations and their effect on predictions, LIME explains: "This is how the model is working for this particular prediction."

LIME focuses on every local area of the data point, not on the model's global logic.

SHAP (SHapley Additive exPlanations): Another tool used alongside LIME for explaining model predictions and addressing bias.

High-performance models (deep learning, ensemble methods) are too complex to understand directly. LIME and SHAP bridge the gap between accuracy and interpretability.

Linear SVM (Hard Margin)

Must-know: SVM maximizes the margin by minimizing ||w||^2. Only support vectors (points on the margin boundaries) determine the decision boundary. The three key formulas are: w = sum a_i y_i x_i, b = y_s - w.x_s, and f(x) = sign(sum a_i y_i (x_i.x) + b).

\[\min_{\mathbf{w}, b} \frac{1}{2}\|\mathbf{w}\|^2 \quad \text{s.t.} \quad y_i(\mathbf{w} \cdot \mathbf{x}_i + b) \geq 1\]

⚠️ Top pitfall: Confusing the margin threshold: the margin boundaries are at +-1, not at 0. A point with prediction exactly +1 or -1 is a support vector.

Self-check: If you remove a non-support-vector point from the training set, does the decision boundary change?

Connects to: Soft Margin SVM, Dual formulation, KKT conditions

Soft Margin SVM

Must-know: Slack variable xi_i measures how far a point is from its correct margin. Hyperparameter C controls the trade-off: high C = strict (narrow margin, risk overfitting), low C = liberal (wide margin, risk underfitting).

\[\min_{\mathbf{w}, b, \xi} \frac{1}{2}\|\mathbf{w}\|^2 + C \sum \xi_i \quad \text{s.t.} \quad y_i(\mathbf{w}^\top \mathbf{x}_i + b) \geq 1 - \xi_i, \; \xi_i \geq 0\]

⚠️ Top pitfall: xi_i cannot be negative. You cannot give bonus credit for a point far on the correct side. C too high = overfitting, C too low = underfitting.

Self-check: What is the slack value for a correctly classified point well outside the margin?

Connects to: Hinge Loss, Regularization, Bias-Variance Tradeoff

Hinge Loss

Must-know: Hinge loss is the mathematical realization of the slack variable: L = max(0, 1 - y_i(w.x_i + b)). Zero for correctly classified outside margin, 0-1 for inside margin, >1 for misclassified.

\[L_{\text{hinge}} = \max(0, 1 - y_i (\mathbf{w} \cdot \mathbf{x}_i + b))\]

⚠️ Top pitfall: The threshold for zero loss is at prediction >= 1, not >= 0. A point exactly on the decision boundary has hinge loss = 1.

Self-check: What is the hinge loss for a negative-class point (y=-1) with prediction -2?

Connects to: Slack Variable, Soft Margin Objective, Subgradient methods

Non-Linear SVM and Mapping

Must-know: Non-linear SVM maps data to a higher-dimensional feature space via a function phi where a linear hyperplane can separate the classes. Cover's theorem guarantees better separability in higher dimensions.

\[\text{Non-linear SVM: } \mathbf{w} \cdot \phi(\mathbf{x}) + b = 0\]

⚠️ Top pitfall: Confusing phi with the kernel. phi is the explicit mapping; the kernel K(x_i, x_j) = phi(x_i)^T phi(x_j) bypasses computing phi entirely.

Self-check: Why can't we just keep adding dimensions indefinitely?

Connects to: Kernel Trick, Curse of Dimensionality, Cover's Theorem

The Kernel Trick

Must-know: The kernel trick computes high-dimensional dot products without ever explicitly transforming data. Common kernels: linear, polynomial (1 + x_i^T x_j)^d, RBF exp(-gamma ||x_i - x_j||^2).

\[K(\mathbf{x}_i, \mathbf{x}_j) = \phi(\mathbf{x}_i)^\top \phi(\mathbf{x}_j)\]

⚠️ Top pitfall: The kernel matrix K is N x N - for N = 100,000 it takes ~40 GB. Scalability is a major practical limitation.

Self-check: For the polynomial kernel (a^T b)^2 in 2D, what is the implied phi mapping?

Connects to: Mercer's Theorem, Feature Mapping, Computational efficiency

Proving a Kernel / Mercer’s Theorem

Must-know: To prove a function is a kernel: expand algebraically, identify coefficient-2 terms hinting at sqrt(2) factors, reconstruct phi. Mercer's theorem requires continuity, symmetry, and positive semidefinite Gram matrix.

\[(1 + \mathbf{x}_i^\top\mathbf{x}_j)^2 = 1 + x_{i1}^2 x_{j1}^2 + x_{i2}^2 x_{j2}^2 + 2x_{i1}x_{j1} + 2x_{i2}x_{j2} + 2x_{i1}x_{i2}x_{j1}x_{j2}\]

⚠️ Top pitfall: Forgetting the constant term, missing cross-terms, and forgetting sqrt(2) factors in phi.

Self-check: How many dimensions does (1 + x^T y)^d map 2D data to for d=2?

Connects to: Kernel Trick, Mercer's Theorem, Polynomial kernel construction

\[\text{Fairness} = \text{absence of bias across demographic groups}\]

⚠️ Top pitfall: Believing that removing race/gender columns eliminates bias. Other features can act as proxies (neighborhood, shopping habits).

Model Interpretability

Must-know: Interpretability explains why a model made a decision. Accuracy-interpretability trade-off. Interpretable models: decision trees, linear regression, k-NN. L1 regularization (Lasso) drives coefficients to zero. LIME and SHAP explain black-box predictions locally.

\[\text{LIME: } \xi(x) = \arg\min_{g \in G} L(f, g, \pi_x) + \Omega(g)\]

⚠️ Top pitfall: Confusing L1 and L2: L1 drives coefficients to zero (feature selection); L2 shrinks but never to zero. LIME explains individual predictions, not the global model.

Feature Construction and Deep Q-Networks (DQN)

12.1 Revision of Function Approximation and Semi-Gradient TD Methods

Hook: How can an AI learn to master games like Chess or Go with \(10^{170}\) possible positions when a computer hard drive cannot store even a tiny fraction of a lookup table for all states?

Intuition & Analogy: Imagine evaluating property values across an entire country. A tabular approach is like keeping a massive ledger with a physical entry for every single house address in existence. If you have never visited a house at 742 Evergreen Terrace, its ledger entry is blank, and knowing the price of 740 Evergreen Terrace gives you zero information about 742.

In contrast, parameterized function approximation is like fitting a dynamic real-estate pricing model based on general features—such as square footage, number of bedrooms, and neighborhood crime rate. Adjusting the weight (importance) attached to "square footage" instantly updates the estimated value of millions of houses simultaneously, including houses the model has never explicitly seen.

Where the analogy breaks: Physical real estate features usually have stable, monotonic relationships with price. In reinforcement learning, non-linear function approximators (like deep neural networks) must approximate complex value topologies where small state changes can lead to vastly different long-term rewards, leading to catastrophic interference if weights are updated too aggressively.

12.1.1 Tabular Representation vs. Parameterized Function Approximation

In classical reinforcement learning, value functions are represented using tabular methods. A tabular representation maintains an explicit lookup table where every discrete state \(s \in \mathcal{S}\) or state-action pair \((s,a) \in \mathcal{S} \times \mathcal{A}\) corresponds to a unique scalar entry storing its estimated value \(V(s)\) or \(Q(s,a)\). For example, a state value table might explicitly store \(V(S_1) = 71\), \(V(S_2) = 70\), and \(V(S_3) = -10\). In a state-action tabular lookup, rows represent unique pairs such as \((S_1, a_1), (S_1, a_2), (S_2, a_1)\).

The primary characteristic of tabular representations is independent learning: updating the value of a specific state row leaves all other table entries entirely unchanged. If a state has never been visited during environmental interaction episodes, its corresponding table entry remains unupdated at its initial default value. When the state space or state-action space is large or continuous, visiting every state becomes impossible. However, unvisited states often lie in close physical or semantic proximity to frequently visited states. Tabular methods fail to generalize across nearby states because they lack any spatial or functional coupling between entries.

Parameterized function approximation resolves this scaling bottleneck by replacing the explicit lookup table with a functional mapping parameterized by a weight vector \(\mathbf{w} \in \mathbb{R}^d\). Instead of storing distinct values per state, the estimated value function is written as a parameterized function \(\hat{V}(s, \mathbf{w})\) or \(\hat{Q}(s, a, \mathbf{w})\). Inputting a state vector \(s\) (or state-action pair) into this function computes a scalar value estimate. Adjusting the weight vector \(\mathbf{w}\) updates the predicted values for all states simultaneously, enabling generalization: learning about one visited state updates the estimated values of unvisited nearby states.

In non-linear function approximation, finding a weight vector \(\mathbf{w}\) that yields exact optimal values across all continuous state-action pairs is an impossible task. Modifying \(\mathbf{w}\) to improve the value prediction for state \(S_3\) inevitably shifts the function surface for other states, potentially increasing their approximation errors. Therefore, function approximation does not seek global optimality; instead, it optimizes for a useful approximation that allows an agent to make effective control decisions within its environment.

12.1.2 Symbol Registry — Function Approximation

Symbol Registry — Function Approximation:

  • \(s\) — Environment state — \(s \in \mathcal{S}\) — State vector or discrete identifier.
  • \(a\) — Agent action — \(a \in \mathcal{A}\) — Discrete or continuous action.
  • \(\mathbf{w}\) — Parameter weight vector — \(\mathbf{w} \in \mathbb{R}^d\) — \(d\)-dimensional trainable weight parameters.
  • \(\hat{V}(s, \mathbf{w})\) — Estimated state-value function — Mapping from state \(s\) and weights \(\mathbf{w}\) to a scalar value prediction.
  • \(\hat{Q}(s, a, \mathbf{w})\) — Estimated action-value function — Mapping from state \(s\), action \(a\), and weights \(\mathbf{w}\) to a scalar action-value prediction.
  • \(V^\pi(s)\) — True state-value function under policy \(\pi\) — Expected return starting from state \(s\) following policy \(\pi\).

12.1.3 Limitations of Tabular Methods and Motivation for Function Approximation

Tabular methods break down when applied to real-world environments with high-dimensional or continuous state spaces. For instance, in visual control tasks where states consist of raw screen pixels (e.g., \(84 \times 84\) pixel images with 256 grayscale levels per pixel), the number of distinct environmental states exceeds \(256^{84 \times 84} \approx 10^{17000}\), which far exceeds the total number of atoms in the observable universe (\(\sim 10^{80}\)). Storing a table of this magnitude requires infinite memory, and searching or populating such a table via sample experience is computationally impossible.

Function approximation provides three fundamental advantages:

  1. Memory Efficiency: Replaces memory requirements proportional to state space size \(|\mathcal{S}|\) with fixed memory proportional to weight dimension \(d\), where \(d \ll |\mathcal{S}|\).
  2. Generalization: Transfers learned value estimates from visited regions of the state space to unvisited regions sharing similar feature representations.
  3. Continuous Domain Support: Computes value predictions for continuous state inputs without requiring ad-hoc state discretization.

12.1.4 Gradient Monte Carlo vs. Semi-Gradient TD(0) Update Rules

Mathematical Formalization of Value Function Weight Updates:

Value function approximation algorithms update weight vectors using gradient descent principles. We define the mean squared value error (MSVE) objective over the state distribution \(d(s)\) as:

\[ \text{MSVE}(\mathbf{w}) = \sum_{s \in \mathcal{S}} d(s) \left[ V^\pi(s) - \hat{V}(s, \mathbf{w}) \right]^2 \]

To minimize the squared error for a single state transition at time \(t\) with update target \(U_t\), we define the instantaneous squared loss:

\[ \mathcal{L}_t(\mathbf{w}) = \frac{1}{2} \left[ U_t - \hat{V}(S_t, \mathbf{w}) \right]^2 \]

Taking the gradient of \(\mathcal{L}_t(\mathbf{w})\) with respect to the weight vector \(\mathbf{w}\) using the chain rule yields:

\[ \begin{aligned} \nabla_{\mathbf{w}} \mathcal{L}_t(\mathbf{w}) &= \frac{1}{2} \cdot 2 \left[ U_t - \hat{V}(S_t, \mathbf{w}) \right] \cdot \nabla_{\mathbf{w}} \left[ U_t - \hat{V}(S_t, \mathbf{w}) \right] \\ &= -\left[ U_t - \hat{V}(S_t, \mathbf{w}) \right] \nabla_{\mathbf{w}} \hat{V}(S_t, \mathbf{w}) \quad \text{(assuming } U_t \text{ is independent of } \mathbf{w} \text{)} \end{aligned} \]

Applying stochastic gradient descent (SGD) to adjust weights in the direction opposite to the gradient (\(\mathbf{w}_{t+1} = \mathbf{w}_t - \alpha \nabla_{\mathbf{w}} \mathcal{L}_t(\mathbf{w}_t)\)) yields the general weight update rule:

\[ \mathbf{w}_{t+1} = \mathbf{w}_t + \alpha \left[ U_t - \hat{V}(S_t, \mathbf{w}_t) \right] \nabla_{\mathbf{w}} \hat{V}(S_t, \mathbf{w}_t) \]

where \(\alpha > 0\) is the positive learning rate step size, \(U_t\) is the target estimate of the return, and \(\nabla_{\mathbf{w}} \hat{V}(S_t, \mathbf{w}_t)\) represents the gradient vector of the value function with respect to the parameter vector \(\mathbf{w}_t\).

In Gradient Monte Carlo methods, the target \(U_t\) is the actual complete discounted return \(G_t = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}\) accumulated from time step \(t\) until the end of the episode. Because \(G_t\) is an unbiased sample of the true value \(V^\pi(S_t)\) and does not depend on the weight vector \(\mathbf{w}\), Gradient Monte Carlo performs true stochastic gradient descent, guaranteeing convergence to a local optimum under standard step-size conditions. However, Monte Carlo updates require complete episode rollouts, making them offline and ineffective for continuing or long-horizon tasks.

In One-Step Temporal-Difference (Semi-Gradient TD(0)) learning, the full Monte Carlo return \(G_t\) is replaced with a one-step bootstrapped target \(U_t = R_{t+1} + \gamma \hat{V}(S_{t+1}, \mathbf{w}_t)\). The weight update equation becomes:

\[ \mathbf{w}_{t+1} = \mathbf{w}_t + \alpha \left[ R_{t+1} + \gamma \hat{V}(S_{t+1}, \mathbf{w}_t) - \hat{V}(S_t, \mathbf{w}_t) \right] \nabla_{\mathbf{w}} \hat{V}(S_t, \mathbf{w}_t) \]

Exam note: Students must explicitly distinguish Gradient Monte Carlo from Semi-Gradient TD updates on examinations; Monte Carlo targets use complete episode returns \(G_t\) (unbiased, true SGD), while TD targets bootstrap using the current value function estimate at the next state \(R_{t+1} + \gamma \hat{V}(S_{t+1}, \mathbf{w}_t)\) (biased, semi-gradient).

12.1.5 Symbol Registry — Semi-Gradient TD Update

Symbol Registry — Semi-Gradient TD Update:

  • \(\alpha\) — Learning rate step size — \(\alpha \in (0, 1]\) — Positive scalar step size.
  • \(\gamma\) — Discount factor — \(\gamma \in [0, 1]\) — Scalar temporal discount factor.
  • \(R_{t+1}\) — Immediate reward — \(R_{t+1} \in \mathbb{R}\) — Scalar reward received after action at time step \(t\).
  • \(S_t\) — Current state at time \(t\) — \(S_t \in \mathcal{S}\) — State vector at time step \(t\).
  • \(S_{t+1}\) — Next state at time \(t+1\) — \(S_{t+1} \in \mathcal{S}\) — State vector at time step \(t+1\).
  • \(U_t\) — Update target — \(U_t \in \mathbb{R}\) — Scalar target for parameter update.
  • \(\delta_t\) — Temporal-difference error — \(\delta_t = U_t - \hat{V}(S_t, \mathbf{w}_t)\) — Scalar prediction error.
  • \(\nabla_{\mathbf{w}} \hat{V}(S_t, \mathbf{w}_t)\) — Gradient vector — \(\nabla_{\mathbf{w}} \hat{V}(S_t, \mathbf{w}_t) \in \mathbb{R}^d\) — Vector of partial derivatives of the estimated value function with respect to weights.

12.1.6 The Semi-Gradient Nature and Moving Target Problem

The standard derivation of stochastic gradient descent assumes that the target \(U_t\) is independent of the parameter vector \(\mathbf{w}\). In Monte Carlo methods, this assumption holds because \(G_t\) is calculated entirely from actual environmental rewards.

However, in TD(0), the target \(U_t = R_{t+1} + \gamma \hat{V}(S_{t+1}, \mathbf{w}_t)\) explicitly depends on the current parameter vector \(\mathbf{w}_t\). Taking the full gradient of the squared error loss with respect to \(\mathbf{w}_t\) would require differentiating both the estimated value \(\hat{V}(S_t, \mathbf{w}_t)\) and the target value \(\hat{V}(S_{t+1}, \mathbf{w}_t)\):

\[ \nabla_{\mathbf{w}} \left( \frac{1}{2} \left[ R_{t+1} + \gamma \hat{V}(S_{t+1}, \mathbf{w}) - \hat{V}(S_t, \mathbf{w}) \right]^2 \right) = -\left[ R_{t+1} + \gamma \hat{V}(S_{t+1}, \mathbf{w}) - \hat{V}(S_t, \mathbf{w}) \right] \left( \nabla_{\mathbf{w}} \hat{V}(S_t, \mathbf{w}) - \gamma \nabla_{\mathbf{w}} \hat{V}(S_{t+1}, \mathbf{w}) \right) \]

Semi-gradient methods deliberately ignore the second term \(-\gamma \nabla_{\mathbf{w}} \hat{V}(S_{t+1}, \mathbf{w})\), treating \(U_t\) as a constant during gradient step evaluation.

This operational choice introduces the moving target problem. Whenever \(\mathbf{w}_t\) is updated to bring \(\hat{V}(S_t, \mathbf{w}_t)\) closer to \(U_t\), the target value \(U_t\) itself shifts because it relies on the same modified parameters \(\mathbf{w}\). Differentiating only the prediction term while holding the target term fixed converts true gradient descent into a semi-gradient update. While semi-gradient updates lose the strict convergence guarantees of true gradient descent on non-linear functions, they enable online, step-by-step bootstrapping updates that learn significantly faster than Monte Carlo methods in practice.

Q: In semi-gradient TD(0), since we already generated an episode, do we not have the next state's value already available?

A: Online temporal-difference learning does not wait to generate a full episode before making parameter updates. Instead, the agent steps through the environment step-by-step. At every single state transition, the agent observes the immediate reward and next state, updates the parameter vector \(\mathbf{w}\) immediately, and then proceeds to take the next step using the updated parameters. This step-by-step parameter update is why TD learning is an online approach and why it exhibits a moving target problem.

12.1.7 Multi-Step (n-Step) Semi-Gradient TD Methods and Tail-End Handling

\(n\)-step semi-gradient temporal-difference methods bridge the gap between single-step TD(0) and full-horizon Monte Carlo methods. Instead of bootstrapping after a single transition or waiting until episode termination, \(n\)-step methods accumulate rewards over \(n\) environment steps before bootstrapping using the value estimate at state \(S_{t+n}\).

The formal \(n\)-step return target \(G_{t:t+n}\) is defined as:

\[ G_{t:t+n} = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots + \gamma^{n-1} R_{t+n} + \gamma^n \hat{V}(S_{t+n}, \mathbf{w}_{t+n-1}) \]

The corresponding semi-gradient parameter update equation at time \(\tau = t - n + 1\) is:

\[ \mathbf{w}_{\tau+n} = \mathbf{w}_{\tau+n-1} + \alpha \left[ G_{\tau:\tau+n} - \hat{V}(S_\tau, \mathbf{w}_{\tau+n-1}) \right] \nabla_{\mathbf{w}} \hat{V}(S_\tau, \mathbf{w}_{\tau+n-1}) \]

A critical algorithmic requirement in \(n\)-step methods is handling tail-end transitions near episode termination. When the time step \(t+n\) exceeds the terminal time step \(T\) of an episode, the target calculation truncates all unavailable future reward terms and sets the bootstrapped terminal state value to zero:

\[ G_{t:t+n} = \sum_{k=t+1}^{\min(t+n, T)} \gamma^{k-t-1} R_k + \begin{cases} \gamma^n \hat{V}(S_{t+n}, \mathbf{w}), & \text{if } t+n < T \\ 0, & \text{if } t+n \ge T \end{cases} \]

If an episode terminates at step \(T=3\) and the algorithm uses a 3-step target, updating state \(S_2\) when only one step remains requires truncating the target to \(G_{2:5} = R_3\), because \(S_3\) is terminal and has a value of zero.

12.1.8 Symbol Registry — n-Step Semi-Gradient TD

Symbol Registry — n-Step Semi-Gradient TD:

  • \(n\) — Step horizon — \(n \in \mathbb{Z}^+\) — Positive integer step horizon.
  • \(\tau\) — Update time index — \(\tau = t - n + 1\) — Time index of the state being updated.
  • \(T\) — Terminal time step — \(T \in \mathbb{Z}^+\) — Time step when the episode terminates.
  • \(G_{t:t+n}\) — \(n\)-step target return — \(G_{t:t+n} \in \mathbb{R}\) — \(n\)-step truncated return with bootstrapped value function estimate.
  • \(\mathbf{w}_\tau\) — Parameter vector at time \(\tau\) — \(\mathbf{w}_\tau \in \mathbb{R}^d\) — Weight parameters at time step \(\tau\).

12.1.9 Worked Computation: 2-Step Semi-Gradient TD Update on a Linear Function

Worked Walkthrough: 2-Step Semi-Gradient TD Update on a Linear Function

Consider an environment episode with the following state transition sequence:

\[ S_0 \xrightarrow{A, R_1 = 2} S_1 \xrightarrow{B, R_2 = 3} S_2 \xrightarrow{C, R_3 = 5} \text{Terminal} \]

Each state is represented by a single scalar feature distance: \(x(S_0) = 5\), \(x(S_1) = 7\), and \(x(S_2) = 3\). The agent uses a linear function approximator model:

\[ \hat{V}(x, \mathbf{w}) = w_1 x + w_0 \]

Initial parameters are given as \(w_1 = 0.8\) and \(w_0 = 0.7\). The discount factor is \(\gamma = 1.0\), and the learning rate step size is \(\alpha = 0.1\).

Step 1: Compute the value estimate for the state two steps ahead, \(S_2\).

\[ \hat{V}(S_2, \mathbf{w}) = \hat{V}(3, \mathbf{w}) = w_1 \cdot x(S_2) + w_0 = (0.8 \times 3) + 0.7 = 2.4 + 0.7 = \mathbf{3.1} \]

Step 2: Compute the 2-step TD target return \(G_{0:2}\) for state \(S_0\).

\[ G_{0:2} = R_1 + \gamma R_2 + \gamma^2 \hat{V}(S_2, \mathbf{w}) = 2 + (1.0 \times 3) + (1.0^2 \times 3.1) = 2 + 3 + 3.1 = \mathbf{8.1} \]

Step 3: Compute the current value estimate \(\hat{V}(S_0, \mathbf{w})\) for state \(S_0\).

\[ \hat{V}(S_0, \mathbf{w}) = \hat{V}(5, \mathbf{w}) = (0.8 \times 5) + 0.7 = 4.0 + 0.7 = \mathbf{4.7} \]

Step 4: Calculate the temporal-difference error \(\delta_0\).

\[ \delta_0 = G_{0:2} - \hat{V}(S_0, \mathbf{w}) = 8.1 - 4.7 = \mathbf{3.4} \]

Step 5: Compute the gradient vector of \(\hat{V}(S_0, \mathbf{w})\) with respect to parameters \(w_1\) and \(w_0\).

\[ \nabla_{w_1} \hat{V}(S_0, \mathbf{w}) = x(S_0) = \mathbf{5}, \quad \nabla_{w_0} \hat{V}(S_0, \mathbf{w}) = \mathbf{1} \]

Step 6: Update the weight parameters \(w_1\) and \(w_0\).

\[ w_1 \leftarrow w_1 + \alpha \cdot \delta_0 \cdot \nabla_{w_1} \hat{V}(S_0, \mathbf{w}) = 0.8 + (0.1 \times 3.4 \times 5) = 0.8 + 1.7 = \mathbf{2.5} \] \[ w_0 \leftarrow w_0 + \alpha \cdot \delta_0 \cdot \nabla_{w_0} \hat{V}(S_0, \mathbf{w}) = 0.7 + (0.1 \times 3.4 \times 1) = 0.7 + 0.34 = \mathbf{1.04} \]

The updated parameter vector is \(\mathbf{w}_{\text{new}} = \begin{bmatrix} \mathbf{2.5} \\ \mathbf{1.04} \end{bmatrix}\).

Sense Check: State \(S_0\) initially had a low estimated value (\(4.7\)), but the observed 2-step return plus future estimate totaled \(8.1\). The positive error \(\delta_0 = +3.4\) correctly pushed both weights upward so that future predictions for state \(S_0\) (and similar states with positive feature values) will be higher.

Assumptions & Scope:

  • Linearity / Function Class: Gradient update formulas depend explicitly on the choice of function approximator \(\hat{V}(s, \mathbf{w})\). For linear approximators (\(\mathbf{w}^\top \mathbf{x}(s)\)), convergence to a unique local optimum (the TD fixed point) is guaranteed under linear semi-gradient TD(0).
  • Off-policy Instability: Semi-gradient TD methods combined with off-policy learning and function approximation form the "Deadly Triad", which can cause parameter divergence if unmitigated.

Visual Intuition: Imagine plotting state value estimates along a continuous 1D axis. A tabular value function appears as discrete, disconnected bar charts where changing one bar leaves all others unchanged. A linear function approximator appears as a single straight line across the state space; adjusting the slope (\(w_1\)) and intercept (\(w_0\)) tilts and shifts the entire line, updating predictions for all states at once.

Common Pitfalls:

  1. Differentiating the Target: Attempting to take a full gradient of the target \(\gamma \hat{V}(S_{t+1}, \mathbf{w})\) with respect to \(\mathbf{w}\). Semi-gradient TD explicitly treats the target term as a fixed constant during differentiation.
  2. Missing Off-Boundary Tail Truncation: Forgetting to set \(\hat{V}(S_T, \mathbf{w}) = 0\) when an \(n\)-step rollout reaches a terminal state \(S_T\), which incorrectly propagates future non-existent rewards.
  3. Confusing Monte Carlo and TD Gradients: Assuming semi-gradient TD follows true stochastic gradient descent on MSVE; TD converges to the TD fixed point, which differs slightly from the minimum MSVE state value.

Recap & Bridge: Tabular RL scales poorly due to memory limits and lack of generalization. Parameterized function approximation resolves this by fitting a global function \(\hat{V}(s, \mathbf{w})\), updated via semi-gradient TD updates that bootstrap across time steps. Next, we examine how features \(\mathbf{x}(s)\) were constructed manually in classical RL versus extracted automatically by deep neural networks.

Real-World & Domain Connection: Function approximation is essential in industrial control systems such as heating, ventilation, and air conditioning (HVAC) optimization or autonomous driving, where environmental state spaces (temperatures, air flows, continuous vehicle velocities, and positions) are continuous. Tabular methods cannot represent these domains, whereas function approximators map high-dimensional sensor streams directly to control decisions.

12.2 Classical Feature Construction vs. Deep Learning Feature Extraction

Hook: Why did AI researchers spend decades hand-crafting complex mathematical grid templates (like tile coding and Fourier bases) to help agents perceive environments, only to replace them all with end-to-end convolutional neural networks?

Intuition & Analogy: Imagine trying to teach a computer to recognize handwritten digits.

Classical Feature Construction is like hiring a human expert to write manual rules and extract geometric features: counting the number of closed loops, measuring stroke curvature, and detecting horizontal lines. If the expert forgets to write a rule for a slanted line, the model fails.

Deep Feature Extraction is like providing raw pixel photos to a multi-layer neural network. The initial layers automatically discover edge detectors, middle layers group edges into shapes (loops, strokes), and final layers combine shapes into digit classifications—learning the optimal feature representations directly from data without human manual feature engineering.

Where the analogy breaks: In supervised visual recognition, features are learned from static labeled images. In Deep RL, the neural network extracts features from a non-stationary sequence of images generated by an agent's evolving policy, meaning the feature representation itself must adapt to changing state distributions.

12.2.1 Manual Feature Engineering in Classical RL

Before deep learning was integrated into reinforcement learning, linear function approximation relied heavily on manual feature construction. A linear value function maps a state \(s\) to a scalar value using a manually designed feature extraction vector \(\mathbf{x}(s) = [x_1(s), x_2(s), \dots, x_d(s)]^\top\):

\[ \hat{V}(s, \mathbf{w}) = \mathbf{w}^\top \mathbf{x}(s) = \sum_{i=1}^d w_i x_i(s) \]

Classical feature engineering techniques include:

  • Polynomial Features: Constructing joint cross-product terms between raw state variables (e.g., \(x_1, x_2, x_1 x_2, x_1^2\)).
  • Fourier Basis: Expanding state representations into periodic sine and cosine basis functions of varying frequencies: \(\phi_i(s) = \cos(\pi \mathbf{c}_i^\top s)\).
  • Coarse Coding & Tile Coding: Partitioning continuous state spaces into overlapping multi-dimensional binary receptive fields (tiles) grouped into tilings, creating sparse binary feature vectors.
  • Radial Basis Functions (RBFs): Mapping continuous states using continuous Gaussian distance kernels centered at fixed prototype points \(\mu_i\): \(\phi_i(s) = \exp\left(-\frac{\|s - \mu_i\|^2}{2\sigma_i^2}\right)\).

While linear methods with constructed features enjoy stable convergence properties, manual feature engineering suffers from major limitations. Designing effective feature representations requires extensive domain expertise, fails to scale to high-dimensional raw pixel inputs (the curse of dimensionality), and cannot adapt feature representations when environmental dynamics shift.

12.2.2 Symbol Registry — Feature Construction

Symbol Registry — Feature Construction:

  • \(\mathbf{x}(s)\) — Feature vector for state \(s\) — \(\mathbf{x}(s) \in \mathbb{R}^d\) — \(d\)-dimensional constructed feature representation.
  • \(\phi(s; \theta_{\text{conv}})\) — Deep neural feature mapping — \(\phi(s; \theta_{\text{conv}}) \in \mathbb{R}^k\) — Non-linear latent feature representation learned by neural network layers.
  • \(w_i\) — Linear weight component — \(w_i \in \mathbb{R}\) — Weight scalar corresponding to feature \(i\).
  • \(d\) — Feature dimension — \(d \in \mathbb{Z}^+\) — Number of manually engineered features.

12.2.3 Transition to Automatic Feature Extraction in Deep RL

Deep reinforcement learning replaces manual feature engineering with automatic end-to-end feature extraction. Deep neural networks (such as Convolutional Neural Networks, CNNs) process raw high-dimensional sensory inputs (e.g., RGB screen images) directly.

In a Deep Q-Network, early convolutional and pooling layers act as a non-linear feature mapping \(\phi(s; \theta_{\text{conv}})\), transforming raw high-dimensional spatial pixels into abstract low-dimensional latent representations. The final fully connected output layers compute action-values as linear functions of these automatically learned latent features:

\[ \hat{Q}(s, a; \mathbf{w}, \theta_{\text{conv}}) = \mathbf{w}_a^\top \phi(s; \theta_{\text{conv}}) \]

By backpropagating temporal-difference loss signals end-to-end through the network, the visual feature representations and the decision-making value parameters are optimized simultaneously. This eliminates human bias in feature design and allows agents to automatically discover task-relevant visual representations (such as detecting ball position, paddle location, or wall obstacles in video games).

Dimension Classical Feature Construction Deep Learning Feature Extraction
Feature Origin Manually engineered by human domain experts Automatically learned end-to-end from raw data
Input Domain Low-dimensional continuous state vectors (\(d \le 10\)) High-dimensional raw sensory inputs (pixels, point clouds)
Model Structure Linear model over fixed non-linear features \(\mathbf{w}^\top \mathbf{x}(s)\) Non-linear deep architecture \(\mathbf{w}_a^\top \phi(s; \theta_{\text{conv}})\)
Convergence Guaranteed convergence under linear semi-gradient TD No global guarantee; susceptible to divergence (Deadly Triad)
Scalability Suffers from curse of dimensionality as state dimension grows Highly scalable to millions of raw sensory dimensions

Assumptions & Scope:

  • Fixed vs. Adaptive Representation: Linear models assume that the manually designed feature space \(\mathbf{x}(s)\) spans the true value function space. If essential state combinations are omitted from \(\mathbf{x}(s)\), a linear model can never represent the true value function.
  • Differentiability Requirement: Deep feature extraction assumes the feature mapping \(\phi(s; \theta)\) is end-to-end differentiable so gradient updates can propagate from the value output back to raw input layers.

Visual Intuition: Picture a pipeline. Classical RL feeds raw sensor data through a fixed, hand-crafted "Feature Filter Box" (tile coding/RBFs), creating a sparse binary vector that is multiplied by trainable weights. Deep RL replaces the fixed filter box with a stack of adjustable convolutional filter sheets whose internal weights tilt and warp automatically in response to backpropagated value error signals.

Common Pitfalls:

  1. Curse of Dimensionality in Tile Coding: Exponential explosion of tiles when extending tile coding to state spaces with more than 5-10 continuous variables.
  2. Brittle Manual Features: Hand-crafted features failing when environmental lighting, camera angles, or minor visual details change.
  3. Catastrophic Interference in Deep Features: Updating neural weights on a new batch of experience destroying feature representations needed for previously mastered state regions.

Recap & Bridge: Classical RL relied on human expertise to design fixed linear features (\(\mathbf{w}^\top \mathbf{x}(s)\)), which failed to scale to visual state spaces. Deep RL replaces hand-crafted features with convolutional neural networks (\(\phi(s; \theta_{\text{conv}})\)) that learn representations end-to-end. Next, we examine Deep Q-Networks (DQN) and the fundamental challenges encountered when combining deep learning with temporal-difference RL.

Real-World & Domain Connection: In robotics, classical controllers relied on hand-calibrated joint angle kinematic features, which broke down when robot limbs encountered unmodeled friction or wear. Modern deep RL end-to-end policies process raw camera feeds and tactile sensor arrays directly, automatically learning robust spatial features for robotic manipulation and locomotion.

12.3 Deep Q-Networks (DQN): Architecture and Challenges

Hook: Why did researchers for decades believe it was impossible to plug raw video pixels into a deep neural network to learn optimal control policies, and what breakthrough allowed a single algorithm to master 47 Atari games directly from vision?

Intuition & Analogy: Imagine taking a single photographic snapshot of a highway. Can you tell if a car is moving forward at 60 mph, reversing, or parked? No—a single static image lacks time derivative information.

Now imagine looking at 4 consecutive photo frames stacked together like a short flipbook. By comparing the position of the car across frames 1, 2, 3, and 4, your brain instantly infers direction, speed, and acceleration.

Frame stacking in Deep Q-Networks functions like this 4-frame flipbook: it transforms static 2D image inputs into a dynamic state representation that restores the Markov property without requiring complex recurrent memory units.

Where the analogy breaks: Frame stacking only captures short-term motion dynamics over 4 steps. If a game requires remembering events that occurred 500 steps ago (such as finding a key in a maze), 4-frame stacking is insufficient and full recurrent memory (like LSTM/GRU) is required.

12.3.1 Historical Context and Breakthrough of DQN

The Deep Q-Network (DQN) algorithm, introduced by Mnih et al. (NIPS 2013) - Playing Atari with Deep Reinforcement Learning and refined in Mnih et al. (Nature 2015) - Human-level control through deep reinforcement learning, represents the landmark breakthrough of deep reinforcement learning. Operating within the Arcade Learning Environment (ALE), DQN demonstrated that a single, end-to-end neural network architecture could learn to play a diverse suite of Atari 2600 games directly from raw screen pixels, achieving human-level or superhuman performance across multiple games without game-specific engineering, hyperparameter tuning per game, or manual visual pre-processing.

Prior to DQN, combining non-linear deep neural network approximators with reinforcement learning algorithms (like Q-learning) was widely considered unstable or divergent due to the "Deadly Triad": the combination of function approximation, bootstrapping, and off-policy training. DQN proved that deep learning and reinforcement learning could be combined stably at scale by introducing key algorithmic innovations: experience replay and target networks.

12.3.2 The Four Key Challenges in Combining Deep Learning with Reinforcement Learning

Combining deep neural networks with temporal-difference reinforcement learning introduces four fundamental technical challenges:

  1. Sparse, Noisy, and Delayed Rewards: Supervised deep learning relies on immediate, dense, hand-annotated ground-truth labels for every training sample. In RL, environmental rewards are scalar, often sparse (zero for thousands of steps), noisy, and delayed. An agent taking actions in a chess or video game receives a non-zero reward signal only after hundreds or thousands of decisions, making credit assignment difficult.
  2. Long Credit Assignment Delays: The temporal gap between executing a decisive action (e.g., dodging an enemy bullet) and receiving its resulting environmental reward (e.g., clearing the stage minutes later) can span thousands of time steps, making it difficult for gradient updates to assign proper credit to early causal actions.
  3. Non-Stationary Data Distribution: Supervised learning algorithms assume a fixed, stationary data distribution \(p(x, y)\). In RL, as the agent updates its policy \(\pi\), it selects different actions, causing the observed sequence of states and rewards to drift continuously. The data distribution generated by the agent changes dynamically as learning progresses (\(p_\pi(s)\) drifts with \(\pi\)).
  4. Highly Correlated Non-i.i.d. Samples: Standard deep learning optimizers (SGD, Adam) assume that training mini-batches consist of independent and identically distributed (i.i.d.) samples. In RL, consecutive video frames in an episode trajectory are highly correlated (e.g., frame \(t\) and frame \(t+1\) are virtually identical), violating the i.i.d. assumption and causing neural network gradients to diverge or overfit to local state trajectories.

12.3.3 Input Preprocessing, Frame Stacking, and Hardware Artifact Mitigation

A single raw Atari 2600 video screen frame consists of a \(210 \times 160\) pixel image with a 128-color palette (\(210 \times 160 \times 3 = 100,800\) values per step), which contains significant visual redundancy and lacks temporal motion context.

To construct a fully Markovian state representation \(\phi(s)\), DQN executes a standardized visual preprocessing pipeline:

  1. Hardware Sprite Flickering Mitigation: Due to memory limitations in the Atari 2600 console, games display certain sprites only on even frames and other sprites only on odd frames. To eliminate visual flickering, DQN takes the element-wise maximum over the current frame \(x_t\) and previous frame \(x_{t-1}\): \[ \tilde{x}_t = \max(x_t, x_{t-1}) \]
  2. Luminance Grayscale Conversion & Resampling: Converts the flickering-corrected RGB frame \(\tilde{x}_t\) to a 1D luminance Y-channel image (\(Y = 0.299R + 0.587G + 0.114B\)) and rescales it down to an \(84 \times 84\) pixel square resolution.
  3. Cropping & Normalization: Crops non-essential visual margins (e.g., game score displays) to produce a clean \(84 \times 84\) visual array.
  4. Frame Stacking: Stacks the \(m=4\) most recent preprocessed consecutive frames along the channel dimension. The resulting input state tensor \(\phi_t = \phi(s_t)\) has shape \(84 \times 84 \times 4\): \[ \phi_t = \begin{bmatrix} \text{Frame}_{t-3} \\ \text{Frame}_{t-2} \\ \text{Frame}_{t-1} \\ \text{Frame}_t \end{bmatrix} \in \mathbb{R}^{84 \times 84 \times 4} \]
  5. Frame Skipping: Following standard Atari benchmarks, the agent selects an action on every \(k\)-th frame (\(k=4\)), repeating the selected action across intervening skipped frames. This increases environment execution speed by \(4\times\) without increasing deep neural network forward-pass computation.

12.3.4 Detailed Deep Convolutional Network Architecture Specifications

Deep Q-Network Layer Specifications (Nature 2015):

The Nature 2015 DQN architecture processes the \(84 \times 84 \times 4\) input tensor through three spatial convolutional layers followed by two fully connected dense layers:

  1. Input Layer: Tensor of shape \(84 \times 84 \times 4\) representing 4 stacked preprocessed grayscale frames.
  2. Convolutional Layer 1: Convolves 32 filters of size \(8 \times 8\) with a stride of 4 pixels, applying Rectified Linear Unit (ReLU) activation: \[ \text{Output Shape:} \quad 20 \times 20 \times 32 \]
  3. Convolutional Layer 2: Convolves 64 filters of size \(4 \times 4\) with a stride of 2 pixels, applying ReLU activation: \[ \text{Output Shape:} \quad 9 \times 9 \times 64 \]
  4. Convolutional Layer 3: Convolves 64 filters of size \(3 \times 3\) with a stride of 1 pixel, applying ReLU activation: \[ \text{Output Shape:} \quad 7 \times 7 \times 64 \]
  5. Fully Connected Hidden Layer: Flattens the \(7 \times 7 \times 64 = 3136\) spatial feature map into a dense linear vector connected to 512 rectifier (ReLU) units.
  6. Output Layer: Fully connected linear layer with \(|\mathcal{A}|\) output units (one output node per valid discrete action, where \(|\mathcal{A}|\) ranges between 4 and 18 across Atari games). Each node outputs \(\hat{Q}(\phi(s), a_i; \theta)\).

Symbol Registry — Deep Q-Network Architecture:

  • \(\phi_t\) — Stacked preprocessed state tensor — \(\phi_t = \phi(s_t) \in \mathbb{R}^{84 \times 84 \times 4}\) — 4-frame stacked state tensor.
  • \(a_t\) — Selected action — \(a_t \in \mathcal{A} = \{1, 2, \dots, |\mathcal{A}|\}\) — Discrete action index.

  • \(k\) — Frame skip factor — \(k = 4\) — Number of emulator frames per action decision step.

Assumptions & Scope:

  • Markov Property: Frame stacking assumes that stacking \(m=4\) frames is sufficient to make the state space fully observable and Markovian.
  • Discrete Action Spaces: Standard DQN assumes discrete, finite action spaces \(\mathcal{A}\), evaluating \(\max_{a'} Q(s', a')\) over all discrete actions simultaneously.

Visual Intuition: Picture a conveyor belt of incoming Atari screen frames. A preprocessing block converts each raw image into an \(84 \times 84\) grayscale tile. A sliding window of size 4 collects the 4 most recent tiles and stacks them into an \(84 \times 84 \times 4\) tensor, which is fed directly into the first convolutional layer of the Q-network.

Common Pitfalls:

  1. Feeding Single Frames: Passing a single \(84 \times 84 \times 1\) frame into Q-learning breaks the Markov property because velocity cannot be determined, leading to severe policy oscillation.
  2. Ignoring Sample Correlation: Training deep Q-networks on consecutive raw sequential transitions without experience replay leads to catastrophic gradient drift and failure to converge.

Recap & Bridge: Deep Q-Networks combined deep CNN feature extraction with Q-learning to achieve human-level play from pixels, overcoming state complexity via \(84 \times 84 \times 4\) frame stacking. However, stabilizing deep neural network optimization against non-i.i.d. correlations and moving targets requires specialized algorithmic components: Experience Replay and Target Networks, detailed in Section 12.4.

Real-World & Domain Connection: Visual frame stacking and preprocessing techniques established by DQN are widely used in video-based autonomous driving, video anomaly detection, and automated user interface testing, where temporal state context must be extracted from multi-frame visual feeds.

12.4 Core Algorithmic Components of DQN: Experience Replay and Target Network

Hook: How do you stop a deep learning model from crashing into severe instability when its training targets keep moving after every single weight update, and its input data comes from a non-i.i.d. stream of video frames?

Intuition & Analogy: Imagine trying to hit a target while practicing archery.

Experience Replay Buffer is like recording your past 10,000 arrow shots into a video logbook. Instead of analyzing only the single shot you just fired (which looks almost identical to the shot right before it), you draw 32 random video clips from your logbook—some from last week, some from yesterday, some from today. This breaks sequential correlation and ensures your technique does not overfit to your most recent mistake.

Decoupled Target Network is like freezing the target bullseye on the wall for 10 minutes. If someone moved the target 2 inches to the left every single time you released an arrow, you would constantly overcorrect and oscillate in confusion. Freezing the target gives you a fixed destination to optimize toward, and once your technique stabilizes, the target position is updated.

Where the analogy breaks: In archery, target positions are fixed physical objects. In deep Q-learning, the target \(y_j\) is a mathematical function of future value estimates, meaning freezing \(\theta^-\) stabilizes function updates, but periodic updates to \(\theta^-\) still create step-discontinuities in the loss surface every \(C\) steps.

12.4.1 Purpose, Inputs, and Outputs of the DQN Architecture

A naive deep Q-network architecture might take both the state tensor \(\phi(s)\) and a candidate action \(a\) as joint inputs, outputting a single scalar value \(\hat{Q}(\phi(s), a; \theta)\). However, evaluating the Q-learning target requires computing \(\max_{a'} \hat{Q}(\phi(s'), a'; \theta)\). If the action space contains \(|\mathcal{A}|\) discrete choices, this naive architecture requires running \(|\mathcal{A}|\) separate forward passes through the deep convolutional network for every single state transition step, creating an immense computational bottleneck.

DQN resolves this structural bottleneck through an efficient multi-output network design. The deep network receives only the state tensor \(\phi(s)\) (shape \(84 \times 84 \times 4\)) at its input layer. The network processes this visual input through three convolutional layers followed by two fully connected layers. The final output layer consists of \(|\mathcal{A}|\) distinct output nodes, where each node directly outputs the predicted Q-value \(\hat{Q}(\phi(s), a_i; \theta)\) for action \(a_i \in \mathcal{A}\).

This architectural design allows a single forward pass through the network to evaluate predicted action-values for all candidate actions simultaneously, enabling instant \(\max_{a'}\) computation and efficient \(\epsilon\)-greedy action selection.

12.4.2 Deep-Dive 1: Experience Replay Buffer (\(\mathcal{D}\))

To address the challenges of highly correlated sequential data and non-stationary data distributions, DQN introduces Experience Replay (Lin, 1992; Mnih et al., 2013, 2015).

During environmental interaction, at each time step \(t\), the agent stores its observed transition tuple \(e_t = (\phi_t, a_t, r_t, \phi_{t+1})\) into a sliding-window replay memory buffer \(\mathcal{D} = \{e_1, e_2, \dots, e_N\}\) of fixed capacity \(N\) (typically \(N = 1,000,000\) transitions). When the buffer reaches full capacity, newly added transitions overwrite the oldest stored transitions.

During network optimization, instead of performing gradient descent on the most recent transition step, DQN samples a uniform random mini-batch of transitions \(B = \{(\phi_j, a_j, r_j, \phi_{j+1})\}_{j=1}^K\) from \(\mathcal{D}\) (typically mini-batch size \(K = 32\)).

Experience Replay provides three critical benefits:

  1. Breaks Sample Correlations: Randomly sampling transitions from across a million historical steps decorrelates the training samples, restoring the i.i.d. assumption required for stable gradient descent.
  2. Increases Data Efficiency: Each experienced transition tuple is reused in multiple mini-batch gradient updates rather than discarded immediately after one step.
  3. Smoothes Data Distribution: Mini-batches average experience over past policies, preventing the network parameters from diverging due to localized, self-reinforcing behavioral feedback loops.

12.4.3 Deep-Dive 2: Decoupled Target Q-Network (\(\theta^-\))

To eliminate the moving target problem inherent in semi-gradient Q-learning, DQN maintains two distinct neural network weight vectors with identical structural architectures:

  1. Primary Q-Network (\(\theta\)): The active network parameters updated at every optimization step using mini-batch gradient descent.
  2. Target Q-Network (\(\theta^-\)): A separate, frozen parameter vector used exclusively to compute the target values \(y_j\) during loss evaluation.

The Q-learning target for a sampled mini-batch transition \(j\) is computed using the target network weights \(\theta^-\):

\[ y_j = \begin{cases} r_j, & \text{if } \phi_{j+1} \text{ is terminal} \\ r_j + \gamma \max_{a' \in \mathcal{A}} \hat{Q}(\phi_{j+1}, a'; \theta^-), & \text{if } \phi_{j+1} \text{ is non-terminal} \end{cases} \]

The target network parameters \(\theta^-\) remain completely frozen for \(C\) time steps (e.g., \(C = 10,000\) steps). Every \(C\) steps, the primary network weights are copied directly to the target network: \(\theta^- \leftarrow \theta\).

Decoupling the target network fixes the target values \(y_j\) for \(C\) steps, eliminating harmful feedback oscillations where parameter updates to \(\theta\) instantly destabilize the target values they are trying to match.

12.4.4 Loss Formulation, Huber Error Clipping, and Optimization

Mathematical Formalization of DQN Loss Function, Error Clipping, and RMSprop Updates:

DQN optimizes its primary network parameters \(\theta\) by minimizing an expected loss \(L_i(\theta_i)\) over mini-batches sampled uniformly from the replay buffer \(\mathcal{D}\):

\[ L_i(\theta_i) = \mathbb{E}_{(\phi, a, r, \phi') \sim U(\mathcal{D})} \left[ \mathcal{L}_{\text{Huber}} \left( y_j - \hat{Q}(\phi, a; \theta_i) \right) \right] \]

Reward Clipping: During training, all positive rewards are clipped to \(+1\) and all negative rewards to \(-1\) (\(r \in \{-1, 0, +1\}\)). This limits the scale of error derivatives across games with vastly different scoring systems.

Huber Loss (Error Clipping): To prevent exploding gradients caused by large temporal-difference errors \(\delta_j = y_j - \hat{Q}(\phi_j, a_j; \theta_i)\), DQN applies Huber loss (Smooth L1 Loss) with threshold \(\delta_{\text{clip}} = 1\):

\[ \mathcal{L}_{\text{Huber}}(\delta_j) = \begin{cases} \frac{1}{2} \delta_j^2, & \text{if } |\delta_j| \le 1 \\ |\delta_j| - \frac{1}{2}, & \text{if } |\delta_j| > 1 \end{cases} \]

Differentiating Huber loss with respect to primary parameters \(\theta_i\) clips the effective gradient magnitude to 1 when \(|\delta_j| > 1\):

\[ \nabla_{\theta_i} L_i(\theta_i) = -\mathbb{E}_{(\phi, a, r, \phi') \sim U(\mathcal{D})} \left[ \text{clip}(\delta_j, -1, 1) \cdot \nabla_{\theta_i} \hat{Q}(\phi, a; \theta_i) \right] \]

Optimizer: The primary weights \(\theta\) are updated using mini-batch RMSprop with mini-batch size \(K=32\), learning rate \(\alpha = 0.00025\), momentum factor \(0.95\), squared gradient decay factor \(0.95\), and numerical stability epsilon \(\epsilon_{\text{RMS}} = 0.01\).

12.4.5 Theoretical Analysis of Overestimation Bias in Q-Learning

Mathematical Foundation & Proof of Overestimation Bias (Thrun & Schwartz 1993, van Hasselt 2010, 2016):

The max operator in standard Q-learning target calculation (\(\max_a Q(s', a; \theta^-)\)) uses the same parameter values to both select and evaluate an action. Because the maximum over estimated values is higher than or equal to the maximum over true values:

\[ \mathbb{E} \left[ \max_{a} Q(s, a) \right] \ge \max_{a} \mathbb{E} \left[ Q(s, a) \right] \]

standard Q-learning systematically overestimates action values.

Thrun & Schwartz (1993) Upper Bound: If target estimation errors are uniformly distributed in an interval \([-\epsilon, \epsilon]\) across \(m\) available actions, each target value is overestimated up to:

\[ \text{Bias} \le \gamma \epsilon \frac{m - 1}{m + 1} \]

van Hasselt et al. (AAAI 2016) Theorem 1 Lower Bound: Consider a state \(s\) where all true optimal action values are equal to \(V^*(s)\) (i.e., \(Q^*(s, a) = V^*(s)\) for all \(a\)). Let \(Q_t(s, a)\) be arbitrary value estimates that are unbiased on average (\(\sum_{a=1}^m (Q_t(s, a) - V^*(s)) = 0\)), but have non-zero variance \(C > 0\), where \(C = \frac{1}{m} \sum_{a=1}^m (Q_t(s, a) - V^*(s))^2\). Then:

\[ \max_{a} Q_t(s, a) \ge V^*(s) + \sqrt{\frac{C(m-1)}{m}} \]

Proof Rationale: Since not all estimates are identical, at least one action estimate must exceed the average \(V^*(s)\). Taking the maximum selects that positive deviation, guaranteeing a strictly positive upward bias \(\sqrt{C(m-1)/m} > 0\).

Double Q-Learning Lower Bound: Under the exact same conditions, the lower bound on the absolute error of the Double Q-learning estimate is zero.

12.4.6 Evolution of Deep Q-Learning: NIPS 2013 vs. Nature 2015 vs. Double DQN

The deep Q-learning algorithmic paradigm evolved across three key milestones:

  1. NIPS 2013 DQN (DQN1): Introduced by Mnih et al. (NIPS 2013) - Playing Atari with Deep Reinforcement Learning, combining the Experience Replay buffer \(\mathcal{D}\) with a deep CNN approximator, but using a single network for both target computation and value prediction. While successful on 7 games, it suffered from instability on complex games due to the moving target problem.
  2. Nature 2015 DQN (DQN2): Introduced by Mnih et al. (Nature 2015) - Human-level control through deep reinforcement learning, introducing the Decoupled Target Network (\(\theta^-\)) updated every \(C\) steps alongside Experience Replay. This dual-network stabilization allowed a single agent architecture to play 49 Atari games stably, matching or exceeding human performance on a majority of games.
  3. Double DQN (DDQN): Introduced by van Hasselt et al. (AAAI 2016) - Deep Reinforcement Learning with Double Q-learning, addressing the inherent overestimation bias of standard Q-learning. Standard Q-learning uses the same network parameters \(\theta^-\) to both select and evaluate the maximum action in the target: \(\max_{a'} \hat{Q}(\phi', a'; \theta^-)\). Double DQN decouples action selection from action evaluation by selecting the greedy action using primary weights \(\theta\) and evaluating its Q-value using target weights \(\theta^-\):
\[ y_j^{\text{DoubleDQN}} = r_j + \gamma \hat{Q}\left(\phi_{j+1}, \arg\max_{a'} \hat{Q}(\phi_{j+1}, a'; \theta); \theta^-\right) \]

12.4.8 Complete Pseudocode Walkthrough of Nature DQN (DQN2)

Algorithm: Deep Q-Learning with Experience Replay and Target Network (Nature 2015)

1:  Initialize replay memory D to capacity N
2:  Initialize primary action-value function Q with random weights theta
3:  Initialize target action-value function Q_hat with weights theta_minus = theta
4:  For episode = 1 to M do:
5:      Initialize sequence s_1 = {x_1} and preprocessed sequence phi_1 = phi(s_1)
6:      For t = 1 to T do:
7:          With probability epsilon select a random action a_t from A
8:          Otherwise select action a_t = argmax_a Q(phi(s_t), a; theta)
9:          Execute action a_t in emulator and observe reward r_t and image x_{t+1}
10:         Set s_{t+1} = s_t, a_t, x_{t+1} and preprocessed phi_{t+1} = phi(s_{t+1})
11:         Store transition tuple (phi_t, a_t, r_t, phi_{t+1}) in replay memory D
12:         
13:         # Mini-batch optimization step
14:         Sample random mini-batch of K transitions (phi_j, a_j, r_j, phi_{j+1}) from D
15:         Set y_j = r_j if phi_{j+1} is terminal
16:         Set y_j = r_j + gamma * max_{a'} Q_hat(phi_{j+1}, a'; theta_minus) if non-terminal
17:         Perform gradient descent step on loss (y_j - Q(phi_j, a_j; theta))^2 wrt theta
18:         
19:         # Periodic target network update
20:         Every C steps reset target network theta_minus = theta
21:     End For
22: End For

Assumptions & Scope:

  • Off-Policy Data Storage: Experience replay requires off-policy RL algorithms (like Q-learning) because transitions stored in \(\mathcal{D}\) were generated by older policies \(\pi_{\text{old}}\). On-policy algorithms (like SARSA) cannot use standard experience replay without importance sampling correction.
  • Memory Requirements: Storing \(1,000,000\) raw preprocessed frame tuples requires significant RAM (\(\sim 8\)-\(16\) GB), requiring efficient frame storage indices in software.

Visual Intuition: Imagine two parallel neural networks side-by-side. On the left is the active Primary Network (\(\theta\)), taking mini-batch transitions from a large circular Replay Buffer (\(\mathcal{D}\)) and taking SGD gradient steps continuously. On the right is the frozen Target Network (\(\theta^-\)), standing still like a statue and generating stable target predictions \(y_j\). Every \(C=10,000\) steps, a bridge opens between the two networks and copies the primary weights across to overwrite the target network (\(\theta^- \leftarrow \theta\)).

Common Pitfalls:

  1. Updating Target Network Every Step (\(C=1\)): Setting \(C=1\) collapses the target network back to standard single-network Q-learning, reintroducing severe moving target instability.
  2. On-Policy Replay Sampling: Sampling transitions only from the most recent trajectory defeats the decorrelation purpose of experience replay.
  3. Overestimating Target Values in Standard DQN: Forgetting that \(\max_{a'} Q(s', a'; \theta^-)\) causes overestimation bias because max operations inflate noisy value estimates.

SGD assumption) and Target Network (freezing \(\theta^-\) for \(C\) steps to solve moving target instability), and contrast standard DQN target \(y_j\) with Double DQN target \(y_j^{\text{DoubleDQN}}\).

Recap & Bridge: Experience Replay (\(\mathcal{D}\)) decorrelates sample batches, and the Decoupled Target Network (\(\theta^-\)) eliminates moving target oscillations, turning deep Q-learning into a stable, scalable algorithm. Double DQN further refined target calculation by decoupling action selection from evaluation. Real-World & Domain Connection: Decoupled target networks and replay buffers are foundational to modern deep RL algorithms across domains, including continuous control (DDPG, SAC, TD3) in robotic manipulation, industrial process control, and algorithmic trading.

12.5.1 Numerical Hand Calculations vs. High-Level Systems Abstraction

Common Pitfalls:

  1. Getting Lost in Paper Notation: Abandoning paper reading because authors use different symbols (\(\mathbf{\theta}\) vs \(\mathbf{w}\), \(\mathbf{s}\) vs \(x\)) for standard concepts.

Exam Guidance Summary

Key Examinable Topics and Problem Types:

  1. Tabular vs. Function Approximation: Expect conceptual exam questions comparing lookup tables against parameterized function approximators. Key points: tabular methods lack spatial generalization and scale exponentially (\(|\mathcal{S}|\)), whereas function approximation generalizes across nearby states and fixes parameter memory footprint (\(d\)).
  2. Gradient MC vs. Semi-Gradient TD Updates: On numerical exam problems, carefully distinguish Monte Carlo targets (using complete episode return \(G_t\)) from TD targets (using immediate reward plus bootstrapped next-state value \(R_{t+1} + \gamma \hat{V}(S_{t+1}, \mathbf{w})\)).
  3. Semi-Gradient Property: Exam questions frequently ask why TD updates are termed semi-gradient. The key answer is that the update equation differentiates only the current state prediction \(\hat{V}(S_t, \mathbf{w})\) while treating the bootstrapped target \(R_{t+1} + \gamma \hat{V}(S_{t+1}, \mathbf{w})\) as a constant, ignoring the target's dependency on \(\mathbf{w}\).
  4. \(n\)-Step Target Calculation & Tail Handling: Practice calculating \(n\)-step truncated returns \(G_{t:t+n}\). Pay special attention to episode termination boundaries where target formulas omit future unreceived rewards and collapse terminal state values to zero.
  5. Four Deep RL Challenges: Be prepared to list and explain the 4 core challenges of combining deep neural networks with RL: sparse/delayed rewards, long credit assignment delays, non-stationary data distributions, and highly correlated non-i.i.d. samples.
  6. DQN Components & Purpose: Memorize the dual purpose of Experience Replay \(\mathcal{D}\) (decorrelating samples, restoring i.i.d. assumption, data efficiency) and the Decoupled Target Network \(\theta^-\) (eliminating moving target instability by freezing target values for \(C\) steps).
  7. DQN Output Architecture: Explain why DQN outputs a vector of Q-values for all actions from a state input rather than taking \((s,a)\) as a joint input (avoids calling the CNN \(|\mathcal{A}|\) times per step).

Key Industry Applications

Key Industry Applications of Deep Q-Networks and Function Approximation:

  • End-to-End Visual Perception in Autonomous Systems: DQN proved that deep neural networks can learn control policies directly from high-dimensional visual inputs without human-engineered features, establishing the foundational architecture for modern autonomous driving and robotic perception.
  • Experience Replay in Industrial Control: Experience Replay buffers are universally deployed across industrial deep RL frameworks (including SAC, TD3, and PPO off-policy variants) to maximize sample efficiency in high-cost environments like physical robotics, HVAC optimization, and datacenter cooling management.
  • Low-Latency Multi-Output Action Evaluation: The multi-output Q-network design (predicting all action values simultaneously from a state input) is widely utilized in high-speed real-time control systems (e.g., automated high-frequency trading and autonomous vehicle path selection) to minimize inference latency during action selection.

Function Approximation and Semi-Gradient TD Methods

Must-know: Parameterized function approximation replaces tabular lookup with a weight-parameterized function, enabling generalization across states. Semi-gradient TD updates treat the bootstrapped target as a constant during differentiation, ignoring the target's dependency on weights.

\[\mathbf{w}_{t+1} = \mathbf{w}_t + \alpha \left[ R_{t+1} + \gamma \hat{V}(S_{t+1}, \mathbf{w}_t) - \hat{V}(S_t, \mathbf{w}_t) \right] \nabla_{\mathbf{w}} \hat{V}(S_t, \mathbf{w}_t)\]

Top pitfall: Confusing Gradient Monte Carlo targets (complete episode return \(G_t\), true SGD) with Semi-Gradient TD targets (bootstrapped \(R_{t+1} + \gamma \hat{V}(S_{t+1}, \mathbf{w}_t)\), semi-gradient). Also, forgetting to truncate the target at episode termination when computing \(n\)-step returns.

Self-check: Why is TD(0) called semi-gradient rather than true gradient descent?

Connects to: 12.2 Feature Construction, 12.3 DQN Architecture

Classical Feature Construction vs. Deep Learning Feature Extraction

Must-know: Classical RL used hand-engineered features (polynomial, Fourier, tile coding, RBFs) with linear models, limited by curse of dimensionality. Deep RL replaces these with CNN feature mappings that learn representations end-to-end from raw pixels.

\[\hat{V}(s, \mathbf{w}) = \mathbf{w}^\top \mathbf{x}(s) \quad \text{vs.} \quad \hat{Q}(s, a; \mathbf{w}, \theta_{\text{conv}}) = \mathbf{w}_a^\top \phi(s; \theta_{\text{conv}})\]

Top pitfall: Assuming deep feature extraction converges as reliably as linear function approximation. Deep RL has no global convergence guarantee and is susceptible to the Deadly Triad.

Self-check: Why can't tile coding scale to raw pixel inputs with hundreds of dimensions?

Connects to: 12.1 Function Approximation, 12.3 DQN Architecture

Deep Q-Networks (DQN): Architecture and Challenges

Must-know: DQN faces four core challenges: sparse/delayed rewards, long credit assignment delays, non-stationary data distributions, and highly correlated non-i.i.d. samples. Frame stacking (84x84x4) restores the Markov property by encoding temporal dynamics into the state representation.

\[\phi_t = \begin{bmatrix} \text{Frame}_{t-3} \\ \text{Frame}_{t-2} \\ \text{Frame}_{t-1} \\ \text{Frame}_t \end{bmatrix} \in \mathbb{R}^{84 \times 84 \times 4}\]

Top pitfall: Feeding a single frame into Q-learning breaks the Markov property because velocity and direction cannot be determined from one static image, causing severe policy oscillation.

Self-check: Why does DQN output Q-values for all actions from a state input rather than taking (s,a) as a joint input?

Connects to: 12.2 Feature Construction, 12.4 Core DQN Components

Core Algorithmic Components of DQN: Experience Replay and Target Network

Must-know: Experience Replay decorrelates sequential samples by storing transitions in a buffer and sampling random mini-batches, restoring the i.i.d. assumption for stable SGD. The Decoupled Target Network freezes target weights for C steps to eliminate moving target instability. Double DQN decouples action selection from evaluation to reduce overestimation bias.

\[y_j = r_j + \gamma \hat{Q}\left(\phi_{j+1}, \arg\max_{a'} \hat{Q}(\phi_{j+1}, a'; \theta); \theta^-\right)\]

Top pitfall: Setting the target network update frequency C=1 collapses back to standard single-network Q-learning, reintroducing severe moving target instability. Also, using standard DQN's max operator causes systematic overestimation of Q-values.

Self-check: Why does Experience Replay require off-policy algorithms like Q-learning rather than on-policy algorithms like SARSA?

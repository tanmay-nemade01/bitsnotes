3.1 Recap: Where We Stand

Key Idea: The Story So Far
  1. Model: A \(K\)-armed bandit — \(K\) actions, no state, reward drawn from a hidden distribution per arm.
  2. Estimate values: \(Q_t(a)\) is the sample average of rewards observed for arm \(a\).
  3. Select actions: Greedy (\(\arg\max_a Q(a)\)) or \(\epsilon\)-greedy (random with prob. \(\epsilon\), greedy otherwise).
  4. Open issues: How does reward variance affect things? What if the environment is non-stationary? Are there better ways to explore than \(\epsilon\)-greedy?

In this lecture we close out these open issues and step beyond the vanilla MAB toward problems that involve context.

3.2 Reverse Engineering ε-Greedy Choices

A common exam-style question is to look at a sequence of observed actions and rewards and identify which steps must have been a random (ε) exploration step, which steps may have been random, and which were definitely greedy. This forces you to internalize how the ε-greedy decision rule actually works.

3.2.1 The Two-Phase Decision Rule

Key Idea: Entry Point of ε-Greedy

The \(\epsilon\)-greedy algorithm does not look at the \(Q\)-values first. Its entry point is a coin flip:

  • Draw \(u \sim \text{Uniform}(0, 1)\).
  • If \(u \le \epsilon \Rightarrow\) pick a random arm (explore).
  • If \(u > \epsilon \Rightarrow\) pick the greedy arm \(\arg\max_a Q(a)\) (exploit).

This matters for the reverse-engineering exercise because a chosen action could have been produced by either branch:

  • In the greedy branch, only the highest-\(Q\) arm can be picked (ties are broken arbitrarily).
  • In the random branch, any arm can be picked with probability \(1/K\).

3.2.2 Worked Problem: A 4-Armed Bandit Trace

Consider a \(K = 4\) bandit with \(\epsilon\)-greedy and sample-average estimates. All initial estimates are \(Q_1(a) = 0\) for all \(a\). We observe the following trace:

Step \(t\) Action \(A_t\) Reward \(R_t\) Status before step
1 \(A_1\) 1 all \(Q = 0\)
2 \(A_2\) 1 \(Q(A_1) = 1\), others 0
3 \(A_2\) 2 \(Q(A_1) = 1\), \(Q(A_2) = 1\), others 0
4 \(A_2\) 2 \(Q(A_1) = 1\), \(Q(A_2) = 1.5\), others 0
5 \(A_3\) — \(Q(A_1) = 1\), \(Q(A_2) \approx 1.67\), others 0

Question: On which steps did the ε (random) branch definitely occur, and on which did it only possibly occur?

3.2.3 Step-by-step Analysis

  • Step 1: All \(Q\)-values are tied at 0. In the greedy branch ties are broken randomly — so picking \(A_1\) is consistent with greedy. In the random branch, \(A_1\) also has probability \(1/4\).
    Conclusion: maybe-\(\epsilon\), cannot tell either way.
  • Step 2: Now \(Q(A_1) = 1\) and \(Q(A_2) = Q(A_3) = Q(A_4) = 0\). The greedy choice is unambiguously \(A_1\). But the agent picked \(A_2\). The greedy branch cannot have produced \(A_2\). Therefore the random branch must have been triggered.
    Conclusion: certainly-\(\epsilon\).
  • Step 3: After step 2 we have \(Q(A_1) = 1\) and \(Q(A_2) = 1\) (tied highest). Picking \(A_2\) is consistent with the greedy branch (with a random tie-break) and with the random branch.
    Conclusion: maybe-\(\epsilon\).
  • Step 4: After step 3, \(Q(A_2) = 1.5\) is the unique highest. Picking \(A_2\) is the greedy choice — but it could also have come from the random branch. The random branch can produce any arm, including the greedy one.
    Conclusion: maybe-\(\epsilon\).
  • Step 5: After step 4, \(Q(A_2) \approx 1.67\) is strictly highest. The agent picked \(A_3\) instead. The greedy branch cannot have produced \(A_3\).
    Conclusion: certainly-\(\epsilon\).
Key Idea: Master Rule

You can say “certainly \(\epsilon\)” only when the agent selected an action that is not the highest-valued one. If the agent picked an action that is (or is tied for) the highest, either branch could have produced it — so you can only say “maybe \(\epsilon\)”. You can never say “certainly greedy”, because the random branch can always coincidentally pick the greedy arm.

Intuition: Classroom Analogy There is a clear topper in the class. The teacher selects a student for a competition. • If the teacher picks the topper, you do not know whether she chose deliberately (greedy) or by accident (random). • If the teacher picks anyone else, you know for sure the choice was not based on rank — it must have been random.

3.3 The Effect of Reward Variance

So far we have not paid attention to how noisy the rewards from each arm are. The standard 10-armed testbed used unit variance — \(R_t \sim \mathcal{N}(q^*(a), 1)\). But what happens if that variance changes? This question has practical implications for how aggressively you should explore.

3.3.1 Three Variance Regimes

Regime Reward behavior What it means for learning
Zero variance Reward = true value, deterministic Pull each arm once; you know everything.
Low (unit) variance Mild noise around true value A handful of pulls per arm gives a reliable estimate.
High variance Large fluctuations around the mean Need many pulls before estimates settle; cannot stop exploring too early.

3.3.2 Zero Variance: A Tempting Trap

Intuition: Zero-Variance MAB

If every pull of arm \(a\) returns exactly \(q^*(a)\) with no noise, the optimal strategy looks deceptively simple:

  1. Pull each of the \(K\) arms once.
  2. From step \(K + 1\) onward, always pull the arm with the largest observed reward.

You have effectively reduced the bandit problem to a finite enumeration.

Caution: Why Textbooks Still Discourage Pure Greedy

On paper zero-variance solves to a clean answer. In practice however:

  • Real environments almost never have truly zero variance — some hidden noise always leaks in (measurement error, time effects, etc.).
  • Even if the underlying reward is deterministic, the model of the environment may be wrong.

So Sutton & Barto recommend keeping a small \(\epsilon > 0\) as insurance even when theory suggests greedy is optimal.

3.3.3 High Variance: Stay Curious Longer

When the variance is large, a single positive reward might be a fluke. To distinguish a truly good arm from a lucky bad arm, you need many samples per arm.

Key Idea: Variance vs. \(\epsilon\)

The higher the reward variance, the longer you should keep \(\epsilon\) large. Do not decay your exploration too fast — you cannot yet trust the running averages.

Empirical Evidence: 10-Armed Testbed with Different Reward Variances

Sutton & Barto's 10-armed testbed averaged over 2000 randomly generated bandit tasks. With unit-variance rewards (\(R_t \sim \mathcal{N}(q^*(a), 1)\)), the greedy method achieved only ~1.0 average reward per step compared to the best possible ~1.55, because it often got stuck on suboptimal arms — it found the optimal arm in only about one-third of the 2000 tasks. The \(\epsilon = 0.1\) method explored more and usually found the optimal arm earlier, but never selected it more than 91% of the time. The \(\epsilon = 0.01\) method improved more slowly but eventually outperformed \(\epsilon = 0.1\) on both average reward and optimal-action rate.

Suppose the reward variance were larger — say 10 instead of 1. With noisier rewards it takes more exploration to identify the optimal action, and \(\epsilon\)-greedy methods fare even better relative to greedy. On the other hand, with zero variance the greedy method would know the true value of each action after trying it once and might perform best. But even in the deterministic case, exploration is valuable if the problem is nonstationary or if initial estimates are misleading — the learner faces bandit-like decisions that change over time due to the learning process itself.

3.4 Non-Stationary Bandit Problems

So far we have implicitly assumed that each arm’s reward distribution is fixed over time — a stationary problem. We now lift that assumption.

3.4.1 Definition

Definition: Non-Stationary Reward Distribution

A bandit problem is non-stationary if the reward distribution of at least one action changes over time:

\[ p(r \mid A_t = a) \neq p(r \mid A_{t'} = a) \quad \text{for some } t \neq t' \]

Notice the important distinction:

  • The variance can be high or low — this only controls how noisy each draw is.
  • Non-stationarity changes the mean (and possibly the entire distribution) over time.

3.4.2 Stationary vs. Non-Stationary - A Side-by-Side View

Before diving into examples, it helps to compare the same domain under both assumptions:

Setting Stationary Version Non-Stationary Version
Slot-Machine Style Bandit Each arm has a fixed payout distribution throughout the experiment. A long sequence of plays gives better estimates of fixed action values. The payout pattern changes after maintenance, a rule change, or a change in operating conditions. Older observations may no longer represent the present arm values.
Online Advertisement During a short A/B experiment, the click probability for each advertisement is assumed nearly fixed. Each ad can be treated as having a stable average reward. User attention changes with season, festival period, repeated exposure, competitor campaigns, or current news. An ad that worked well earlier may later become less effective.
Treatment Choice A controlled study compares a few treatment protocols for a clearly defined patient group over a short period. If patient characteristics and clinical conditions are stable, each treatment may be viewed as having an approximately fixed outcome distribution. The mix of patients, disease variants, co-medications, adherence, and hospital practice can change. The observed outcome distribution of a treatment may drift, so older evidence should not dominate forever.
Cloud Configuration A service is tested under a stable workload and fixed infrastructure. Each configuration has a roughly stable distribution of throughput or latency. Workload, traffic mix, background jobs, network congestion, and hardware contention vary across time. A configuration that was best in the morning may not be best during peak load.
Intuition: In real deployments, it is safer to expect some degree of non-stationarity. User populations change, systems are upgraded, demand fluctuates, and external conditions shift. Therefore, practical bandit methods need to track action values rather than merely converge once and stop adapting.
Key Insight from Sutton & Barto: Effective Nonstationarity

Even if the underlying environment is strictly stationary and deterministic, the agent often faces effectively nonstationary decision tasks. Why? Because as the agent learns, its own estimates change — the "problem" as seen by the agent evolves. As the book puts it: "Even if the underlying task is stationary and deterministic, the learner faces a set of banditlike decision tasks each of which changes over time due to the learning process itself." This is why reinforcement learning requires a permanent balance between exploration and exploitation — not just an initial exploration phase.

3.4.3 Real-World Examples

Example: Online Advertising You decide which ad to show a user. The user’s mood, interests, and life stage drift constantly. An ad that converted last month may bore the same user today. If you froze your estimates, you would slowly become useless.
Example: Managing a Boss with Mood Swings A manager approves your proposals on some days and rejects identical ones on others. The reward of the action “submit proposal” drifts with the manager’s mood, workload, and recent events. To get your goodies, you must keep re-learning the current reward.
Example: Industry Skill Demand The career value of a particular technical skill is non-stationary. Five years ago, deep learning was the hot skill; ten years ago, big data; now it might be LLM and agentic systems. An engineer’s lifetime “reward” for any skill choice depends on continual updates to estimates — never lock in.

3.4.4 The Naive Fix: Keep \(\epsilon\) Permanently Positive

The simplest reaction to non-stationarity is to refuse to decay \(\epsilon\):

  • Set \(\epsilon\) to a moderate constant (say 0.05 or 0.1).
  • Never let it drop to zero.

This ensures the agent is always sampling sub-optimal-looking arms, so it can notice when their value rises.

Key Idea: The Real Issue

Even with \(\epsilon > 0\), the sample-average estimator gives too much weight to the distant past. Recent observations get diluted in the average.

Why? Suppose you are at step \(t = 10{,}000\) and the current estimate is \(Q(a) = 30\). A new reward \(R = 5\) arrives. The updated average is:

\[ Q_{\text{new}}(a) = Q(a) + \frac{1}{10{,}001} (5 - 30) = 30 + \left(-\frac{25}{10{,}001}\right) \approx 29.9975 \]

The estimate barely budged! But if the environment just shifted so that the true mean is now 5, this slow reaction is disastrous. We need an estimator that puts more weight on recent rewards. This is the motivation for the incremental update with a constant step size, which we develop next.

3.5 Incremental Update of the Sample Average

Before solving the non-stationary problem, we rewrite the sample average in a form that exposes the right “handle” to modify.

3.5.1 Derivation

The sample average after \(n\) rewards is:

\[ Q_{n+1} = \frac{1}{n} \sum_{i=1}^{n} R_i \]

Split off the most recent reward:

\[ Q_{n+1} = \frac{1}{n} \left[ R_n + \sum_{i=1}^{n-1} R_i \right] = \frac{1}{n} \left[ R_n + (n-1) Q_n \right] \]

where we used the fact that \(\sum_{i=1}^{n-1} R_i = (n-1) Q_n\). Expanding:

\[ Q_{n+1} = \frac{R_n + n Q_n - Q_n}{n} = Q_n + \frac{1}{n} [ R_n - Q_n ] \]
Key Idea: Incremental Sample Average \[ Q_{n+1} = Q_n + \frac{1}{n} [ R_n - Q_n ] \]

This is exactly the sample average — but expressed as an online update that needs only \(O(1)\) memory. The naive implementation (storing all past rewards for each action) would have memory and computation that grow without bound. This incremental form requires only \(Q_n\) and \(n\), and constant computation per new reward. Sutton & Barto note that this holds even for \(n = 1\), obtaining \(Q_2 = R_1\) for arbitrary \(Q_1\).

3.5.2 The General Update Form

Stare at the rewritten expression. It has the very general structure:

\[ \text{NewEstimate} = \text{OldEstimate} + \text{StepSize} \times [ \text{Target} - \text{OldEstimate} ] \]

This template will appear over and over in RL: Q-learning, SARSA, TD(0), policy gradient — everything ultimately resembles this update.

  • Step size \(\alpha_n\): How much we move toward the target. For the exact sample average, \(\alpha_n = 1/n\).
  • Target \(R_n\): Where we’d like the estimate to be in the light of the new evidence.
  • Old estimate \(Q_n\): Our prior belief.

Sutton & Barto call the expression \(\left[\text{Target} - \text{OldEstimate}\right]\) an error in the estimate. The error is reduced by taking a step toward the target — though the target itself may be noisy. This notion of error as a directed quantity (not an absolute loss) is a recurring motif throughout the book.

3.5.3 A Tiny Numerical Walk-Through

Let \(Q_n = 10\), and suppose at step \(n = 5\) we observe \(R = 5\). Then \(Q_{n+1} = 10 + \frac{1}{5}(5 - 10) = 10 - 1 = 9\). The estimate moved toward the new reward.

Intuition: Interpreting \(\text{Target} - \text{Estimate}\) The term \(R_n - Q_n\) is the gap between what we just saw and what we believed. It is not an error in the supervised-learning sense, because the target \(R_n\) itself is noisy and possibly time-varying. A reward of 5 today does not mean future rewards will be 5. We are not trying to “reduce the error to zero”; we are trying to track a moving (and noisy) target.

3.5.4 Why Is This Useful?

The rewrite seems trivial. The payoff is that we can now change the step size:

  • Keep \(\alpha_n = 1/n \Rightarrow\) exact sample average (good for stationary).
  • Use a constant \(\alpha_n = \alpha \Rightarrow\) exponentially-weighted average that forgets the past (good for non-stationary).

The next section explores the constant-step-size case.

3.6 Constant Step Size for Non-Stationary Problems

Set the step size to a small constant \(\alpha \in (0, 1]\): \(Q_{n+1} = Q_n + \alpha [ R_n - Q_n ]\)

3.6.1 Why It Adapts to Change

When \(\alpha = 1/n\), the influence of a fresh reward shrinks as \(n\) grows — the agent becomes increasingly stubborn. When \(\alpha\) is a fixed constant (say 0.1), every reward, regardless of when it arrives, carries the same weight.

Key Idea: Constant Step Size Effect

A constant \(\alpha\) implements an exponential recency weighting: recent rewards strongly influence the estimate, while old rewards exponentially decay in their contribution. The agent keeps learning forever.

3.6.2 Mathematical View: Exponential Recency-Weighted Average

Unrolling the recursion (you should verify this on paper at home):

\[ Q_{n+1} = (1-\alpha)^n Q_1 + \sum_{i=1}^{n} \alpha (1-\alpha)^{n-i} R_i \]

The weights on past rewards \(R_i\) decay geometrically with age. The initial value \(Q_1\) also fades exponentially. Contrast this with the sample-average estimator, where every \(R_i\) gets weight \(1/n\) regardless of age.

Sutton & Barto note a key verification: the sum of all weights is exactly 1 — \((1-\alpha)^n + \sum_{i=1}^{n} \alpha(1-\alpha)^{n-i} = 1\) — confirming this is a true weighted average. In the extreme, if \(1-\alpha = 0\) (i.e., \(\alpha = 1\)), all weight goes to the very last reward \(R_n\) alone (using the convention \(0^0 = 1\)), making the estimate equal to that single reward.

3.6.3 Intuitive Example: A Simple Tracking Illustration

Intuition: A Simple Tracking Illustration

Case 1 — Reward level increases: Suppose \(Q = 10\) and \(\alpha = 0.2\). If the next rewards are \(14\) and \(16\):

\[ Q \leftarrow 10 + 0.2(14 - 10) = 10.8 \] \[ Q \leftarrow 10.8 + 0.2(16 - 10.8) = 11.84 \]

The estimate begins moving upward, which is appropriate if the action's reward distribution has improved.

Case 2 — Reward level decreases: Suppose \(Q = 12\) and \(\alpha = 0.2\). If the next rewards are \(8\) and \(7\):

\[ Q \leftarrow 12 + 0.2(8 - 12) = 11.2 \] \[ Q \leftarrow 11.2 + 0.2(7 - 11.2) = 10.36 \]

The estimate moves downward, which is useful when older high rewards no longer represent current performance. The constant \(\alpha\) keeps the estimate responsive in both directions — the step size never shrinks with time.

3.6.4 Intuitive Example: The 50-Year-Old Engineer

Intuition: Two Engineers, Same Age

Engineer A: “I’m 50 years old, my learning days are behind me.” This is the \(1/n\) step size — each new input gets vanishingly small weight relative to a lifetime of past experience. Behavior calcifies.

Engineer B: “Age is just a number, I keep learning.” This is the constant-\(\alpha\) step size — every new input gets the same attention, so the engineer adapts continually to a changing world.

3.6.5 Trade-Off: Bias-vs-Variance with \(\alpha\)

A constant \(\alpha\) is not without cost:

Step size Pros Cons
\(\alpha_n = 1/n\) Converges exactly to true mean in stationary case (provable). Stops adapting once \(n\) is large; useless if true value drifts.
Constant \(\alpha\) Always responsive to fresh rewards; tracks drift. Never fully converges; estimates jitter around the true value.

3.6.6 Choosing \(\alpha\): Student Question

A common student question: "If \(\alpha\) is constant, doesn't the very first reward get undue weight?" Answer: Yes, in some sense. With \(Q_1 = 0\) and a first reward of \(R_1 = 10\) and \(\alpha = 0.2\), the very first update gives \(Q_2 = 0 + 0.2 \cdot (10 - 0) = 2\). The estimate is heavily biased by that single data point until many more come in. In practice you can: • Use a higher \(\alpha\) early and decay it (similar to decaying \(\epsilon\)). • Or simply accept that early estimates are imprecise — the constant \(\alpha\) guarantees later evidence will dominate.

3.6.7 Theoretical Note: Robbins-Monro Conditions

When does a stochastic averaging procedure converge? A general result from stochastic approximation theory says \(Q_n \to q^*(a)\) almost surely if the step size sequence satisfies:

\[ \sum_{n=1}^{\infty} \alpha_n = \infty \quad \text{and} \quad \sum_{n=1}^{\infty} \alpha_n^2 < \infty \]
  • \(\alpha_n = 1/n\) satisfies both \(\Rightarrow\) guaranteed convergence (stationary).
  • Constant \(\alpha_n = \alpha\) violates the second condition \(\Rightarrow\) does not converge but does track.

This is exactly the reason we deliberately violate convergence in non-stationary problems.

Practical Note from Sutton & Barto: Although step-size sequences that meet the Robbins–Monro conditions are often used in theoretical work, they are seldom used in applications and empirical research. Sequences satisfying the conditions often converge very slowly or need considerable tuning to obtain a satisfactory convergence rate. In nonstationary environments — which are the norm in reinforcement learning — permanent tracking at the cost of full convergence is exactly what we want.

3.6.8 The \(\epsilon\)-Greedy Algorithm with Constant \(\alpha\)

Algorithm 1: \(\epsilon\)-Greedy with Constant Step Size 
1: Initialize: Q(a) ← 0 for all a; choose ε ∈ (0, 1) and α ∈ (0, 1]
2: for each time step t = 1, 2, ... do
3:     Draw u ~ Uniform(0, 1)
4:     if u > ε then
5:         At ← arg maxa Q(a)    ▷ exploit
6:     else
7:         At ← random arm         ▷ explore
8:     end if
9:     Pull arm At and observe reward Rt
10:    Q(At) ← Q(At) + α [ Rt − Q(At) ]    ▷ constant step
11: end for
Key Idea: Two Knobs for Non-Stationary MAB
  • Keep \(\epsilon > 0\) always so the agent continues to discover changes.
  • Use a constant \(\alpha\) so the agent continues to learn from those discoveries.

\(\epsilon\) feeds the agent fresh experience; \(\alpha\) ensures that experience actually moves the estimate. Either alone is insufficient.

3.7 Optimistic Initial Values

We now look at the first of two alternative ways to encourage exploration without \(\epsilon\).

3.7.1 The Trick

Set the initial \(Q\)-values to a number that is much higher than any reward the environment can plausibly return.

Example: Optimistic Init in the 10-Armed Testbed The true rewards are roughly in the range \([-3, +3]\). Instead of initializing \(Q(a) = 0\) for all \(a\), set \(Q(a) = +5\).

3.7.2 Why It Drives Exploration

Suppose we run pure greedy (\(\epsilon = 0\)) starting from \(Q(a) = 5\) everywhere.

  1. Step 1: All \(Q\) tied. Ties broken arbitrarily \(\Rightarrow\) pick some arm, say \(A_1\). The reward arrives, e.g. \(+0.4\), which is much lower than the optimistic prior. So \(Q(A_1)\) drops (to \(\approx 4.6\) with \(\alpha = 0.1\)).
  2. Step 2: Now \(Q(A_2), Q(A_3), \dots = 5\) are all above \(Q(A_1) = 4.6\). Greedy picks among them \(\Rightarrow\) tries a new arm.
  3. This continues. Every time greedy picks an arm, the reward disappoints relative to the optimistic prior, and the next greedy step naturally rotates to a different arm.

Net effect: Without any explicit randomness, the agent thoroughly samples every arm in the early steps. Exploration is essentially baked into the initial conditions.

3.7.3 Why It Eventually Stops Working

Once all the \(Q\)-values have come down close to their true means, the agent has settled into pure exploitation. There is no longer any built-in pressure to revisit arms.

Caution: Optimistic Init is a One-Shot Trick

Optimistic initialization drives exploration only transiently. After the values converge, exploration ceases.

  • Fine if the problem is stationary and you only need to find the best arm once.
  • Fails miserably if the problem is non-stationary — you cannot detect later changes.
Why It's Not a General Solution: The "Beginning of Time" Critique

Sutton & Barto note two deeper limitations. First, with a constant step size \(\alpha\), the bias from optimistic initial values is permanent — it decays over time (as shown in the unrolled form, \((1-\alpha)^n Q_1\)) but never vanishes entirely, unlike in the sample-average case where the bias disappears after each action has been selected at least once. This is usually not a problem in practice, and can sometimes even be helpful as a way of encoding prior knowledge about reward levels.

More fundamentally, the method treats the beginning of time as a special event. As the book argues: "If the task changes, creating a renewed need for exploration, this method cannot help. Indeed, any method that focuses on the initial state in any special way is unlikely to help with the general nonstationary case." The beginning of time occurs only once — relying on it as the sole source of exploration pressure is a fragile strategy.

3.7.4 Empirical Comparison

In the 10-armed testbed, comparing Realistic (\(Q_1=0, \epsilon=0.1\)) vs Optimistic (\(Q_1=5, \epsilon=0\)):

  • Optimistic + greedy (\(\epsilon=0\)): climbs faster early and reaches a high optimal-action rate.
  • Realistic + \(\epsilon\)-greedy (\(\epsilon=0.1\)): starts more slowly but keeps a permanent exploration cushion — safer in case the environment changes.
Key Idea: When To Use Optimistic Init

A clever idea, but narrow. Use it when:

  • The problem is firmly stationary.
  • You know an upper bound on plausible rewards.
  • You want a parameter-free way to encourage early exploration.

Otherwise, prefer \(\epsilon\)-greedy or UCB (next section).

3.8 Upper Confidence Bound (UCB) Action Selection

UCB is one of the most influential exploration strategies in RL. It replaces the parameter \(\epsilon\) with a principled, automatic exploration bonus based on uncertainty.

3.8.1 Worked UCB Numerics from the Lecture

Example 1: Two Actions

At time \(t = 20\), suppose \(Q_t(a_1) = 1.0\) with \(N_t(a_1) = 10\), \(Q_t(a_2) = 0.8\) with \(N_t(a_2) = 2\), and \(c = 2\):

\[ \text{score}(a_1) = 1.0 + 2 \times \sqrt{\frac{\ln 20}{10}} \approx 1.0 + 1.095 = 2.095 \] \[ \text{score}(a_2) = 0.8 + 2 \times \sqrt{\frac{\ln 20}{2}} \approx 0.8 + 2.448 = 3.248 \]

UCB selects \(a_2\) even though its current estimate is lower, because it has been tried much less often. If the observed reward is \(R = 1.4\), the sample-average update after its third selection is:

\[ Q(a_2) \leftarrow 0.8 + \frac{1}{3}(1.4 - 0.8) = 1.0 \]

Example 2: Four Actions

At time \(t = 50\), let \(c = 1\) and:

Action\(Q_t(a)\)\(N_t(a)\)
\(a_1\)1.1025
\(a_2\)1.2020
\(a_3\)0.704
\(a_4\)0.901

The UCB scores are:

Action\(Q_t(a) + \sqrt{\frac{\ln 50}{N_t(a)}}\)
\(a_1\)\(\approx 1.50\)
\(a_2\)\(\approx 1.64\)
\(a_3\)\(\approx 1.69\)
\(a_4\)\(\approx 2.88\)

UCB selects \(a_4\). Although \(a_4\) is far from greedy by \(Q_t(a)\) alone, it has been selected only once, so its uncertainty term dominates. The algorithm gives a nearly-untried arm a chance before writing it off.

Empirical Performance: 10-Armed Testbed (Figure 2.3)

On the 10-armed testbed, UCB with \(c = 2\) generally outperforms \(\epsilon\)-greedy with \(\epsilon = 0.1\), except in the very first steps when it selects randomly among the as-yet-unplayed actions. A notable feature: UCB shows a prominent spike in performance on the 11th play. Here's why: after each of the 10 arms has been tried once, \(N_t(a) = 1\) for all arms, and the uncertainty term is \(\sqrt{\ln 11 / 1} \approx 1.55\). The arm with the highest single-sample reward gets both a high \(Q_t(a)\) and a high uncertainty bonus, producing a temporary "super-optimistic" peak before estimates stabilize.

3.8.2 UCB Intuition: Why the Exploration Bonus Matters

Consider the following snapshot:

Arm \(Q(a)\) \(N(a)\) (# pulls)
\(A_1\) 7 10
\(A_2\) 9 30
\(A_3\) 1 5
\(A_4\) 20 15

Pure greedy would always pick \(A_4\). But notice that \(A_3\) has been pulled only 5 times — our estimate of \(Q(A_3) = 1\) is based on very little data. Maybe its true value is much higher and we just got unlucky. Fairness, in a statistical sense, says \(A_3\) deserves more chances before we write it off.

Key Idea: UCB’s Insight

Choose actions based on a combination of:

  1. Their current estimated value \(Q_t(a)\), and
  2. How uncertain we are about that estimate.

Arms that have been sampled rarely have high uncertainty \(\Rightarrow\) they deserve a bonus.

\[ A_t = \arg\max_a \left[ Q_t(a) + c \sqrt{\frac{\ln t}{N_t(a)}} \right] \]
Key Idea: Summary of All Action-Selection Methods
MethodRule and ParametersExploration Behaviour
Greedy\(A_t = \arg\max_a Q_t(a)\); no exploration parameter.Pure exploitation. Useful as a baseline, but can settle on suboptimal action after misleading early rewards.
\(\epsilon\)-greedySelect greedy with prob. \(1-\epsilon\); random from all \(K\) actions with prob. \(\epsilon\).Simple continuing exploration. Larger \(\epsilon\) explores more; smaller \(\epsilon\) exploits more.
Optimistic InitSet \(Q_1(a)\) high for all actions, then act greedily.Encourages early exploration because untried arms remain attractive. Most suitable when an initial burst of exploration is enough.

Choosing between methods: There is no single best rule independent of the task. Greedy is mainly a baseline. \(\epsilon\)-greedy is simple and robust when continuing exploration is desired. Optimistic initialization is useful when early exploration is valuable and reasonable optimistic estimates can be chosen. UCB is more directed because it prefers actions with high estimates or high uncertainty, but relies on meaningful action counts and is most natural in bandit settings.

Sutton & Barto's parameter study (Figure 2.5): Averaging over 1000 steps on the 10-armed testbed, all algorithms show a characteristic inverted-U shape — they perform best at an intermediate parameter value. UCB generally performs best, but \(\epsilon\)-greedy and gradient bandits are also strong. All methods are fairly insensitive to their parameter choice, performing well over about an order of magnitude range.

Limitations: UCB is more difficult than \(\epsilon\)-greedy to extend beyond bandits to the full RL setting. Two key challenges: (1) nonstationary problems — the simple UCB method presented here does not track drifting values well without modifications more complex than Section 2.4's approach; (2) large state spaces with function approximation — in the more advanced settings of Part III of the book, there is currently no known practical way of utilizing the UCB idea.

3.9 A Brief Look at Policy-Based / Gradient Bandits

So far, every method we have studied has the same structure: 1. Estimate values \(Q(a)\) from rewards. 2. Choose actions based on those values (greedy, \(\epsilon\)-greedy, UCB, . . . ). These are called value-based methods.

3.9.1 An Alternative: Learn the Action Directly

What if we skipped the value-estimation step entirely?

Definition: Policy-Based Approach

Instead of learning \(Q(a)\) and deriving a policy, we directly learn a parameterized policy \(\pi_{\theta}(a)\) – a probability distribution over actions – and update its parameters \(\theta\) to maximize expected reward.

In the bandit setting this is called a gradient bandit algorithm: maintain a numerical preference \(H_t(a)\) for each arm, convert preferences to probabilities via a softmax:

\[ \pi_t(a) = \frac{e^{H_t(a)}}{\sum_{b} e^{H_t(b)}} \]

and update preferences using a stochastic gradient ascent on the expected reward.

3.9.2 Worked Examples

Reward Above Baseline

Suppose there are three actions, \(H_t(a_1) = H_t(a_2) = H_t(a_3) = 0\), so \(\pi_t(a_i) = 1/3\). Let \(\alpha = 0.1\), selected action \(A_t = a_2\), reward \(R_t = 2.0\), and baseline \(\bar{R}_t = 1.0\). Then \(R_t - \bar{R}_t = 1.0\):

  • \(\Delta H(a_2) = 0.1 \times 1.0 \times (1 - 1/3) = 0.0667\)
  • \(\Delta H(a_1) = \Delta H(a_3) = -0.1 \times 1.0 \times (1/3) = -0.0333\)

The selected action becomes more likely because it performed better than the baseline. The unselected actions become slightly less likely.

Reward Below Baseline

Suppose \(\pi_t(a_1) = 0.5\), \(\pi_t(a_2) = 0.3\), \(\pi_t(a_3) = 0.2\), selected \(A_t = a_1\), \(R_t = 0.4\), \(\bar{R}_t = 1.0\), \(\alpha = 0.1\). Then \(R_t - \bar{R}_t = -0.6\):

  • \(\Delta H(a_1) = 0.1 \times (-0.6) \times (1 - 0.5) = -0.03\)
  • \(\Delta H(a_2) = -0.1 \times (-0.6) \times 0.3 = 0.018\)
  • \(\Delta H(a_3) = -0.1 \times (-0.6) \times 0.2 = 0.012\)

The selected action becomes less likely because it performed worse than the baseline. The unselected actions gain preference — a form of indirect exploration that compensates for the poor outcome.

3.9.3 Why We Skip the Details Here

Policy-gradient methods require a careful mathematical setup (gradient of expectations, log-derivative trick, baselines, etc.). The instructor’s plan is to develop them properly later, in the context of policy gradient and actor-critic methods for full RL. For now, simply remember the taxonomy: • Value-based: Estimate \(Q \Rightarrow\) derive action. • Policy-based: Directly parameterize and optimize the policy. • Actor-Critic: Both — a value network (critic) helps a policy network (actor).

Key Insight from Sutton & Barto: The Baseline's Role

The expected update of the gradient-bandit algorithm is equal to the gradient of expected reward, making it an instance of stochastic gradient ascent — this guarantees robust convergence properties. Critically, nothing is required of the reward baseline \(\bar{R}_t\) other than that it not depend on the selected action. The choice of baseline does not affect the expected update of the algorithm, but it dramatically affects the variance of the update and thus the rate of convergence. Sutton & Barto's Figure 2.4 shows that with a baseline, the \(\alpha = 0.4\) variant performs well; without a baseline, performance degrades significantly. Using the average reward as the baseline is simple and works well in practice, though it may not be the very best choice.

3.10 Contextual Bandits: Bridging MAB and Full RL

We are now ready to relax the most restrictive assumption of MAB: that there is no notion of state or context.

3.10.1 Three Layers of Decision-Making

Setting Inputs to action selection Does action affect future situation?
Vanilla MAB Nothing (stateless) No
Contextual Bandit A context \(x_t\) observed before acting No (context evolves on its own)
Full RL A state \(s_t\) that the agent’s actions influence Yes — actions move you to new states

3.10.2 Associative vs. Non-Associative Search

Definition: Associative Search The action depends on (is associated with) some observation about the current situation. Both contextual bandits and full RL are associative. Sutton & Barto note that the term "associative search" was introduced by Barto, Sutton, and Brouwer (1981), and the modern literature uses the term contextual bandits for this problem. Thorndike's Law of Effect (quoted in Chapter 1 of the book) describes associative search by referring to the formation of associative links between situations (states) and actions.
Definition: Non-Associative Search The action does not depend on any observed situation — the agent uses the same decision rule every step. Vanilla MAB is non-associative.

3.10.3 What is a Contextual Bandit?

Definition: Contextual Bandit

At each step \(t\):

  1. Observe a context \(x_t\) from the environment.
  2. Select an action \(A_t\) based on \(x_t\).
  3. Receive a reward \(R_t\) from the environment.

Critical property: The action \(A_t\) does not change \(x_{t+1}\). The context evolves exogenously. The agent must learn a separate “mini-bandit” for each possible context — or, more practically, a function \(\pi(a \mid x)\) that generalizes across contexts.

3.10.4 Examples of Contextual Bandits

The table below formalizes how key applications map to the contextual bandit framework — identifying what constitutes the context, the action set, and the reward signal:

ApplicationContextActionsReward & Why Contextual
Online Advertising User profile, device, query, page type, time of day. Candidate advertisements. Click, purchase, or revenue. The best advertisement depends on the observed user and page context.
News / Content Recommendation User interests, recent browsing, location, and current session features. Articles, videos, or posts. Click, dwell time, or completion. Different users should receive different recommendations.
Clinical Decision Support Patient record, symptoms, history, age, and risk indicators. Candidate treatments or interventions. Recovery indicator or improvement score. Treatment choice depends on patient-specific context.
Information Retrieval Search query, intent features, and previous interaction signals. Ranking policy or selected result group. Click satisfaction or relevance signal. The useful action depends on the query and user intent.
Adaptive Tutoring Learner profile, recent answers, and estimated mastery level. Next exercise, hint, or explanation type. Correctness or learning gain. The best instructional action depends on the learner's current context.
Key Idea: These examples are contextual bandits because the learner receives side information before acting, but receives reward only for the chosen action. They are intermediate between ordinary bandits and full reinforcement learning: more expressive than a single-situation bandit, but still simpler than a multi-state sequential decision process.

3.10.5 When MAB / Contextual Bandit / Full RL?

Key Idea: A Three-Question Decision Tree

When asked to model a problem, ask:

  1. Does the optimal action depend on observable situational information?
    • No ⇒ Vanilla MAB.
    • Yes ⇒ go to Question 2.
  2. Does my action affect what information I’ll see next?
    • No ⇒ Contextual Bandit.
    • Yes ⇒ Full RL.
Example: Why Driving Is Full RL Driving a car requires looking at the current state (speed, road, surrounding traffic) before acting. Moreover, your action (accelerate, brake, turn) changes the next state you will see. Both conditions for full RL are met. You cannot model this as a bandit.
Example: Why Chess Is Full RL Chess has a clear state (the board). Each move you make changes the board for the next decision. The opponent also responds based on your move. Full RL.

3.11 Summary & Key Takeaways

Key Idea: Concepts From This Lecture
  1. Reverse-engineering \(\epsilon\)-greedy: You can say “certainly \(\epsilon\)” only when a non-greedy action is observed.
  2. Reward variance: The higher the variance, the longer you must explore.
  3. Non-stationary problems: Reward distributions drift. Keep \(\epsilon > 0\) and use a constant step size.
  4. Incremental update: The sample average rewrites as \(Q_{n+1} = Q_n + \frac{1}{n} [ R_n - Q_n ]\).
  5. General update form: \(\text{New} = \text{Old} + \alpha [ \text{Target} - \text{Old} ]\) — a template used everywhere in RL.
  6. Constant step size \(\alpha\): Yields exponential recency weighting; tracks change in non-stationary problems.
  7. Optimistic initial values: Cheap, parameter-free, but only transient exploration; only works for stationary problems.
  8. UCB: Adds an uncertainty bonus \(c \sqrt{\frac{\ln t}{N(a)}}\) to each value. Empirically strong; no \(\epsilon\) needed.
  9. Value-based vs. policy-based: Two big families of RL algorithms. Gradient bandits are the policy-based MAB.
  10. Contextual bandit: Action depends on observed context, but action does not affect future context.
  11. Full RL: Action depends on state and affects future state.

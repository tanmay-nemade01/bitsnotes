🎓 Level: postgraduate
👥 Audience: Postgraduate students studying bandit algorithms and value-based decision making before full MDP-based reinforcement learning.

Lecture Summary

This lecture deepens the RL vocabulary and introduces the multi-armed bandit (MAB) problem as the simplest setting for studying action-value estimation and exploration. The five RL elements — agent, environment, reward signal, value function, and optional model — are explained, with emphasis on why values (long-term return expectations) matter more than immediate rewards.

The state-value function V(s) answers 'how good is it to be in this state?', while the action-value function Q(s,a) answers 'how good is it to take this action here?' Q is often preferred when action outcomes are stochastic, since it avoids averaging over all possible next states at decision time. The environment model p(s′, r | s, a) enables planning when known, but even in games like chess, the state space is so large that model-free approaches become necessary.

The MAB formulation removes states entirely: K arms, each pull yields a reward from an unknown distribution, and the goal is to maximise cumulative reward. True values q*(a) are estimated with sample averages using efficient incremental updates. Greedy selection (always pick the best-looking arm) risks locking onto a suboptimal choice due to noisy early samples. ε-greedy fixes this by exploring randomly with probability ε.

The classic 10-armed testbed shows that moderate ε (like 0.1) outperforms pure greedy early on. Real applications include online advertising, A/B testing, and clinical trials — demonstrating that bandits are far from just a casino analogy.

Key Learning Objectives

  • Compare state-value V(s) and action-value Q(s,a) and explain when Q is preferable under stochastic transitions.
  • Define the environment model p(s′, r | s, a) and contrast model-based with model-free reinforcement learning.
  • Formulate the K-armed bandit problem and estimate q*(a) using sample-average and incremental update rules.
  • Implement and analyse greedy versus ε-greedy action selection, including selection probabilities.
  • Interpret the 10-armed testbed results and relate bandit applications to recommendation, testing, and clinical trials.

1. Recap: What is Reinforcement Learning?

Reinforcement Learning (RL) is a learning paradigm in which an agent learns by interacting with an environment so as to maximize a notion of cumulative reward. It mirrors the way humans naturally learn — through trial, error, and feedback.

Definition: Reinforcement Learning
A computational approach to learning whereby an agent tries to maximize the total amount of reward it receives while interacting with a complex, uncertain environment.

2.1 How RL Differs From Other Paradigms

ParadigmTraining SignalGoal
SupervisedLabeled (input, output) pairs given by a teacherLearn input → output mapping
UnsupervisedNo labels — only raw dataFind patterns / structure
ReinforcementScalar rewards from environment (often delayed, sparse)Learn behavior (policy) that maximizes long-term reward
Evaluative vs. Instructive Feedback
In supervised learning, the feedback is instructive — it tells you the correct output directly. In RL, the feedback is evaluative — it only tells you how good or bad your chosen action was, not which action would have been better. The agent does not know that a different action should have been chosen; it only knows the outcome was poor. This creates the fundamental need for exploration and credit assignment.
Three Distinguishing Features of RL (Sutton & Barto, §1.1)
Reinforcement learning problems are set apart by three characteristics that do not arise in pure supervised or unsupervised learning:
  1. Closed-loop interaction: The agent's actions influence its subsequent inputs. The learning system is not a passive observer — the data it learns from depends on the actions it has previously chosen.
  2. No instructive supervision: The agent is not told which actions to take. It must discover which actions yield the most reward by trying them out. There are no labeled training examples of correct behavior.
  3. Extended temporal consequences: Actions may affect not only the immediate reward but also the next situation and, through that, all subsequent rewards. Delayed effects and long-term credit assignment are central — a good move now may set up a win many steps later.

2. Elements of Reinforcement Learning

At the heart of any RL system are several key building blocks. Understanding these is essential before moving to algorithms.

2.2 The Agent-Environment Interface

The cycle of interaction at every discrete time step t is:

  1. The agent observes the current state St of the environment.
  2. The agent chooses an action At.
  3. The environment transitions to a new state St+1 and returns a reward Rt+1.
  4. The cycle repeats.

2.3 Core Elements

Definition: The Five Elements of RL
  1. Agent — the learner / decision maker.
  2. Environment — everything outside the agent that it interacts with.
  3. Reward Signal — a scalar feedback indicating how good or bad an action was at a particular moment. It defines the immediate goal of the RL problem. The agent's sole objective is to maximize the total reward it receives over the long run. The reward signal depends on the agent's current action and the current state of the environment; crucially, the agent cannot alter the process that generates rewards — it can only influence rewards through its actions. If an action is selected by the policy and followed by low reward, then the policy may be changed to select some other action in that situation in the future. In general, reward signals may be stochastic functions of the state and the actions taken.
  4. Value Function — captures the long-term desirability of a state (or of taking an action in a state). Reward tells what is immediately good, while value tells what is good in the long run. A state may give low immediate reward but still have high value if it commonly leads to better future states.
  5. Model of the Environment (optional) — an internal representation that predicts how the environment will respond to actions. A model mimics the behaviour of the environment: given a state and action, it may predict the resultant next state and reward. Models support planning, where the agent considers possible future situations before actually experiencing them.
Key Distinction: Policy vs. Value Function
A policy π defines the agent's behaviour at a given time. It maps states to actions (deterministic) or to probabilities over actions (stochastic, written as π(a|s)). The policy is central because it alone is sufficient to determine behaviour — once the current state and policy are known, the agent's action-selection rule is specified. The policy corresponds to what in psychology would be called a set of stimulus–response rules or associations.

The value function does not directly specify behaviour. Instead, it estimates long-term desirability. RL decisions are usually based on value judgments, not only on immediate rewards — because once you have accurate values, choosing the best action becomes easy: pick the action that leads to the highest-value future. Rewards are primary (given directly by the environment), whereas values, as predictions of rewards, are secondary. Yet it is values with which we are most concerned when making decisions — we seek actions that bring about states of highest value, not highest immediate reward.

3. Value Functions: The Heart of RL

Key Idea: Why values matter
Reward tells you the immediate consequence of an action. Value tells you the long-term consequence. Most RL algorithms are about estimating good values, because once you have accurate values, choosing the best action becomes easy — pick the action that leads to the highest-value future.

There are two fundamental kinds of value functions you must distinguish very clearly.

2.4 State Value Function V(s)

Definition: State Value Function
V(s) is the expected long-term return when the agent is in state s (and follows some policy thereafter).

V(s) = 𝔼 [ ∑k=0∞ γk Rt+k+1 | St = s ]

Intuitively: "How good is it just to BE in this state?"

2.5 Action Value Function Q(s, a)

Definition: Action Value Function
Q(s, a) is the expected long-term return when the agent takes action a in state s and follows some policy afterwards.

Q(s, a) = 𝔼 [ ∑k=0∞ γk Rt+k+1 | St = s, At = a ]

Intuitively: "How good is it to TAKE action a in this state?"

Notation convention: Letter V ⇒ State Value Function (V(s)). Letter Q ⇒ Action Value Function (Q(s, a)).

2.6 Worked Example: 4×4 Grid World

Consider a 4 × 4 grid where each cell is a state. The agent starts at the bottom-left "Start" cell and must reach the top-right "Goal" cell. Each cell has a (learned) value attached to it.

Decision-making with V: From the Start state, the agent inspects the values of all neighbors (Up gives V = 7, Right gives V = 9) and moves toward the higher-valued cell. With V, you must look one step ahead to evaluate every possible successor before deciding.

Decision-making with Q: If we instead had Q(Start, Up) = 10 and Q(Start, Right) = 11, we could directly compare actions without a look-ahead. Just pick the action with the highest Q.

2.7 Why Q is Often Preferred: The Stochastic Outcome Problem

Intuition: Car Braking Example
You are driving and apply the action brake. The outcome is not deterministic:
  • With probability 0.90: the car stops (good outcome).
  • With probability 0.07: the car skids (bad).
  • With probability 0.03: the brake fails (very bad).

A single action can lead to multiple possible next states. Looking one step ahead with V(s) becomes complicated — you'd need to compute a weighted average over all possible outcomes every time you decide. The Q-function Q(s, brake) pre-summarizes this weighted average. You just look up the Q-value and act.

Key Idea: V vs. Q
  • Use V when outcomes of actions are simple / deterministic and the look-ahead is cheap (e.g., chess — a move clearly leads to a known board position).
  • Use Q when outcomes are stochastic or look-ahead is expensive. Q "bakes in" the uncertainty of the outcome into a single number per (state, action) pair.

2.8 Initial Values, Exploration, and Loops - A Student's Doubt

Question: If we always follow the greedy move based on initial values, won't we get stuck in a cycle in the grid?

Answer: The values shown in the grid above are merely initial (often random) values. The whole point of RL is to update these values through experience until the values reflect true desirability. To do this updating, the agent must occasionally make exploratory (non-greedy) moves. This is the exploration vs. exploitation trade-off, which we discuss in detail later.

4. Model of the Environment

Definition: Model of the Environment
A model is an abstract mathematical description of how the environment behaves in response to actions. Formally, the model is the joint probability distribution:

p(s′, r | s, a) = Pr{St+1 = s′, Rt+1 = r | St = s, At = a}

That is: given current state s and action a, what is the probability of landing in state s′ with reward r?

2.9 Why Models Matter

  • If you have a perfect model, you can plan on paper without ever interacting with the real environment.
  • You can compute theoretically optimal values using algorithmic approaches like dynamic programming.
  • Models are also used for simulation — generate synthetic experience cheaply.

2.10 Model-Based vs. Model-Free RL

CategoryDescription
Model-Based The algorithm uses (or first learns) a model of the environment. Two sub-flavors:
• Model is given (e.g., the rules of chess).
• Model is learned from experience and then used for planning.
Model-Free No explicit model is constructed. The agent directly learns values or policies from raw experience. Examples: Q-learning, policy-gradient methods.
Key Taxonomy: Model-Based vs. Model-Free
  • Model-based methods use a model for planning — choosing actions by considering possible future situations before they are experienced. The model predicts the next state and reward given a state and action, enabling the agent to simulate and reason about consequences.
  • Model-free methods learn directly from experience without an explicit environment model. They rely on trial-and-error interaction to estimate values or improve policies. These are more widely deployed in practice for large-scale problems.
Practical reality: In theory, the environment of tic-tac-toe (and even chess) can be modeled exactly — we know all rules and outcomes. But for chess, the state space is so enormous that exact computation is infeasible. So practitioners typically use model-free approaches even when a theoretical model exists.

5. From RL to Deep RL: A Quick Glimpse

So far, value functions have been stored in a table — one entry per state (or per state–action pair). This is fine for tic-tac-toe but impossible for problems like Go, robotics, or video games where the state space is astronomical.

Definition: Deep Reinforcement Learning
We replace the value table with a neural network parameterized by weights θ:

V(s; θ)   or   Q(s, a; θ)

The neural network takes a state (or state–action pair) as input and outputs the value. The objective of learning is to find weights θ such that the network's output is as close as possible to the true value.
Example: For tic-tac-toe, instead of a giant lookup table over all board configurations, we feed the 3 × 3 board into a neural network whose output is a single number — the value of that state. As we play games, we update θ via gradient descent.

In a full Deep RL system, you may have multiple neural networks: one for value, one for policy, one for the model, etc.

6. The Multi-Armed Bandit (MAB) Problem

The MAB problem is the simplest possible RL setup. It strips away the notion of state so we can focus purely on the exploration–exploitation trade-off and on the mechanics of learning action values. Crucially, the bandit setting isolates evaluative feedback in its purest form: the agent receives only a reward that evaluates the action taken, not any instruction about which action would have been correct. Purely evaluative feedback depends entirely on the action taken (the reward reveals how good the chosen action was), whereas instructive feedback indicates the correct action independently of the one taken. All the complexity of the exploration–exploitation dilemma flows from this single property — the agent must actively try actions just to discover whether they are good or bad.

2.11 The Casino Analogy

Imagine walking into a casino with a stack of coins. In front of you are K slot machines (one-armed bandits), each with its own lever. Each pull of a lever costs one coin and gives back some reward (often zero, sometimes positive, perhaps even negative on average) drawn from that machine's hidden reward distribution.

2.12 Formal Setup

Definition: K-Armed Bandit
  • There are K actions ("arms"): a1, a2, …, aK.
  • At each time step t, the agent selects one action At and receives a reward Rt drawn from the (unknown) reward distribution of that arm.
  • There is no state. The same set of actions is available at every step.
  • Goal: maximize the total (expected) reward accumulated over time.

2.13 Why MAB is "Stateless"

In the casino, the machines don't remember anything about you, and you have no varying context. The reward distribution is fixed and the agent's choice depends only on what it has learned about each arm — not on any external state. This is the key simplification.

Notation in MAB: Because there is no state, we write Q(a) instead of Q(s, a). This is an exception only for MAB; in the full RL setting, Q is always a function of both state and action.

2.14 The True Value of an Action

Definition: True Value q*(a)
The true value of action a is the expected reward when a is selected:

q*(a) = 𝔼[Rt | At = a]

If we knew q*(a) for every action, the problem would be trivial: always pick the arm with the highest q*.

The catch: The agent does not know q*(a). It must estimate it through experience.

2.15 Sample-Average Estimation

A natural way to estimate q*(a) is to average all rewards observed so far when action a was chosen:

Qt(a) = ∑i=1t−1 Ri · 𝟙Ai=a
∑i=1t−1 𝟙Ai=a

where 𝟙Ai=a is the indicator function (1 if Ai = a, else 0). This is just the sample mean of rewards for action a.

Example: Numerical Walk-Through
Suppose after 10 pulls, the history is:
ArmRewards observedEstimated Q
1−1, −1, 5(−1−1+5)/3 = 1.0
2−1, 0(−1+0)/2 = −0.5
30, −1, −0.5(0−1−0.5)/3 ≈ −0.5
4−2, −2(−2−2)/2 = −2
At t = 11, the highest Q is for Arm 1. A greedy agent would pull Arm 1 again.

Important nuance: The sample average is computed per arm, using only the rewards observed for that arm — not a global average across all arms.

7. Action Selection: Greedy vs. ε-Greedy

How does the agent choose which arm to pull at each step? This is the action-selection problem and it embodies the exploration–exploitation trade-off.

2.16 Greedy Action Selection

Definition: Greedy Selection
Always pick the arm with the highest current estimate:

At = arg maxa Qt(a)

Problem with pure greedy: You may get unlucky early and stick to a sub-optimal arm forever.
Example: Why Pure Greedy Can Fail
Suppose Arm 1's true value is −0.5 (bad), but the first few rewards you happen to observe are +1 each. The estimate Q(1) shoots up. Meanwhile, Arm 2's true value is +1 (good), but the first few pulls happen to give −2. The estimate Q(2) becomes very low. A pure greedy agent will now keep pulling Arm 1 forever, never giving Arm 2 a chance to reveal its true (better) value. This is called premature convergence.

2.17 ε-Greedy Action Selection

To avoid getting trapped, we mix in a small fraction of random exploration:

Definition: ε-Greedy
With probability 1 − ε: pick the greedy action (exploit).
With probability ε: pick an arm uniformly at random (explore).

At = { arg maxa Qt(a)   with probability 1 − ε
random arm      with probability ε

The parameter ε is a small hyperparameter (e.g., 0.01 or 0.1) that controls how often the agent explores.

2.18 Pseudocode

Algorithm 1: ε-Greedy Action Selection 
 1: Initialize: Q(a) ← 0 for all a; N(a) ← 0 for all a; ε ← 0.05
 2: for each time step t = 1, 2, ... do
 3:     u ← random.uniform(0, 1)    ▷ sample uniform in [0, 1]
 4:     if u > ε then
 5:         At ← arg maxa Q(a)    ▷ exploit
 6:     else
 7:         At ← random arm         ▷ explore
 8:     end if
 9:     Pull arm At and observe reward Rt
10:     N(At) ← N(At) + 1
11:     Q(At) ← Q(At) + 1/N(At) × (Rt − Q(At))    ▷ incremental average
12: end for

Incremental update trick: Instead of storing all past rewards, we update the running average online:

Qn+1 = Qn + (1/n)(Rn − Qn)

This is mathematically equivalent to the sample average but requires O(1) memory per arm.

8. Computing Action-Selection Probabilities

A frequently-tested concept: what is the probability that a specific arm is selected by an ε-greedy policy?

2.19 Worked Example 1: Two Actions, ε = 0.5

Suppose A1 is the greedy (highest-Q) action and A2 is the non-greedy one.

Method — Decompose by selection mode:

Pr(A1) = Pr(A1 | greedy mode) · Pr(greedy mode) + Pr(A1 | random mode) · Pr(random mode)

= 1 · (1 − ε) + (1/K) · ε

= 1 · 0.5 + (1/2) · 0.5 = 0.75

Pr(A2) = 0 · (1 − ε) + (1/2) · 0.5 = 0.25

2.20 Worked Example 2: Four Actions, ε = 0.4

Greedy action A1: Pr(A1) = 1 · (1 − 0.4) + (1/4) · 0.4 = 0.6 + 0.1 = 0.7

Each non-greedy action: Pr(Ai) = 0 · (1 − 0.4) + (1/4) · 0.4 = 0.1   (i = 2, 3, 4)

Sanity check: 0.7 + 0.1 + 0.1 + 0.1 = 1.0 ✓

Key Idea: General Formula
For K arms with ε-greedy:

Pr(greedy arm) = (1 − ε) + ε/K,   Pr(non-greedy arm) = ε/K

The greedy arm gets the lion's share plus an equal slice of the exploration budget.

8B. Incremental Updates and Step-Size Choices

The sample-average method requires storing all past rewards. An incremental update avoids this by updating online using only the current estimate and the latest reward.

2.21 Derivation of the Incremental Update

Incremental Sample-Average Update Rule

Qn+1 = Qn + (1/n)(Rn − Qn)

General Form: NewEstimate ← OldEstimate + StepSize × [Target − OldEstimate]

This form appears repeatedly in RL. The term [Target − OldEstimate] is the estimation error — how far the old estimate is from the target. The step-size determines how strongly the newest reward affects the estimate.
Derivation Walk-Through 
Qn+1 = (1/n) Σi=1n Ri
      = (1/n)[Rn + Σi=1n-1 Ri]
      = (1/n)[Rn + (n-1)(1/(n-1))Σi=1n-1 Ri]
      = (1/n)[Rn + (n-1)Qn]
      = (1/n)[Rn + nQn − Qn]
      = Qn + (1/n)(Rn − Qn)
The learner does not need to store all earlier rewards — just the current estimate Qn and the count n.

2.22 Sample-Average vs. Constant Step-Size

ChoiceUpdate RuleInterpretation
Sample-average step-sizeQn+1 = Qn + (1/n)[Rn − Qn]Each reward contributes equally. As n grows, the step-size shrinks and the estimate becomes progressively more stable. Natural when the reward distribution is stationary.
Constant step-sizeQn+1 = Qn + α[Rn − Qn]Recent rewards keep receiving noticeable influence. The estimate always adapts. Natural when the reward distribution is non-stationary and may drift over time.
Exponential Recency-Weighted Average
With a constant step-size α, the estimate Qk+1 is a weighted average of all past rewards and the initial estimate Q1:

Qk+1 = (1 − α)kQ1 + ∑i=1k α(1 − α)k−iRi

The weight α(1 − α)k−i given to reward Ri decays exponentially as the age of the reward (k − i) increases. Recent rewards contribute far more to the estimate than distant ones. This is why a constant step-size is suitable for tracking a changing environment — old data fades away automatically.
Convergence Conditions for Step-Size Sequences
From stochastic approximation theory, a sequence {αk} guarantees convergence with probability 1 to the true action values if:

∑k=1∞ αk = ∞   and   ∑k=1∞ αk2 < ∞

First condition: The sum of steps diverges — steps must remain large enough to eventually overcome any initial estimation error or random fluctuation.
Second condition: The sum of squared steps converges — eventually steps must become small enough to assure the estimate settles.

Note that αk = 1/k (sample-average) satisfies both conditions. Constant αk = α satisfies the first (diverges) but violates the second (sum of squares does not converge) — meaning the estimates never fully converge and continue to fluctuate in response to recent rewards. This continual fluctuation is desirable in non-stationary environments. In practice, sequences that meet these conditions often converge too slowly and are seldom used in applications.
Numerical Tracking Illustration
Case 1: Reward level increases. Q = 10, α = 0.2. Rewards: 14, 16.
Q ← 10 + 0.2(14 − 10) = 10.8
Q ← 10.8 + 0.2(16 − 10.8) = 11.84 — estimate moves upward appropriately.

Case 2: Reward level decreases. Q = 12, α = 0.2. Rewards: 8, 7.
Q ← 12 + 0.2(8 − 12) = 11.2
Q ← 11.2 + 0.2(7 − 11.2) = 10.36 — estimate moves downward, reflecting current performance.
Practical Rule: For stationary problems, use sample-average (1/n) because you want equal weight on all data. For non-stationary problems, use a constant step-size α so the estimate stays responsive to recent changes. In real deployments, some degree of non-stationarity is almost always present (user populations change, systems are upgraded, demand fluctuates), so constant or slowly-decaying step-sizes are safer.

9. Exploration vs. Exploitation Trade-off

Definition: The Dilemma
Exploit: Use what you currently know to maximize immediate reward.
Explore: Try less-tested actions to potentially discover something better.

These two are inherently in conflict: every step you spend exploring is a step you didn't spend exploiting, and vice versa.

2.23 Why You Must Explore

  • Early estimates of Q(a) are based on very few samples and may be wildly off.
  • Pure exploitation can lock you into a sub-optimal arm forever.
  • Even after long learning, the world may change (non-stationary problems).

2.24 Why You Must Exploit

  • Always exploring is wasteful — you never reap the benefits of what you learn.
  • In real applications (e.g., medical trials, ad serving), every exploration step has a real cost.
Intuition: Restaurant Choice
Imagine your favorite Italian restaurant near home. You know it's great. But there's a new Thai place that opened last week — maybe it's even better, maybe much worse. Do you go to the safe favorite (exploit), or take a chance on the new one (explore)? This everyday choice is the exploration–exploitation trade-off.

10. The 10-Armed Testbed Experiment

To compare action-selection strategies empirically, researchers use a standard 10-armed testbed.

2.25 Setup

  • Generate a problem with K = 10 arms.
  • For each arm a, the true value q*(a) is drawn from N(0, 1).
  • When arm a is pulled, the reward is drawn from N(q*(a), 1).
  • Run the agent for 1000 steps. Track the average reward per step.
  • Repeat the entire experiment for 2000 independent problems and average the curves to smooth out randomness.

2.26 Empirical Results

The classic comparison plots average reward over 1000 steps for three settings: ε = 0 (pure greedy), ε = 0.1, and ε = 0.01.

Average reward over 1000 steps

ε = 0.1 — highest throughout

ε = 0.01 — slow but steady improvement

ε = 0 (greedy) — plateaus early

2.27 Interpretation

  • ε = 0 (Greedy): Rises quickly but plateaus early at a sub-optimal level. With no exploration, the agent commits to whatever first looked good — even if it was misleading.
  • ε = 0.1: Keeps improving for a long time and ends up the clear winner in the short term. 10% exploration is aggressive enough to keep discovering better arms.
  • ε = 0.01: Improves slowly (only 1% exploration), but if you ran for many more steps it would eventually surpass ε = 0.1. Why? Because once you know the best arm, you want to exploit it almost all the time — 10% wasted exploration becomes a constant drag on performance.
Key Idea: Practical Lesson
A common strategy: start with a large ε and decay it over time. Explore a lot early when you know nothing, and exploit more aggressively once your estimates are reliable.

2.28 Stationary vs. Non-Stationary Rewards

TypeDescription
StationaryThe true reward distributions q*(a) do not change over time.
Non-stationaryThe distributions drift (e.g., user preferences change).
  • For stationary problems, you could eventually decay ε → 0. But in practice, since you can never be 100% sure you've found the truth, keep a small positive ε forever.
  • For non-stationary problems, never set ε = 0. You must keep exploring to detect changes.
Note: Advanced exploration strategies (Optimistic Initial Values, UCB, and Gradient Bandits) are covered in detail in Lecture 3: Non-Stationary Bandits, UCB and Contextual Bandits.

11. Real-World Applications of MAB

Although the casino setup is a toy example, MAB models a huge number of real problems where decisions are stateless and feedback is the reward.

2.29 Application 1: Online Advertising / Recommendation

Example: Naïve Amazon Banner
An e-commerce site shows 10 product banners. Each banner = an arm. Reward = 1 if user clicks (or buys), 0 otherwise. The system doesn't know which products users will love — it must learn through interaction.
  • Start with Q(a) = 0 for all banners.
  • Each visitor click updates the estimate.
  • Banners with low estimated CTR get phased out; new banners are introduced (exploration).
The reward distribution is hidden in users' minds — no engineer can tell you in advance which banner converts best.

2.30 Application 2: A/B Testing / Web Layout Optimization

Arms: Alternative page layouts, button positions, or message variants.
Reward: Conversion, sign-up, or successful task completion.

Traditional A/B testing splits traffic evenly between variants. A bandit approach adaptively allocates more traffic to better-performing variants while still exploring others, achieving higher cumulative reward during the test itself.

2.31 Application 3: Detecting a Biased Coin

A single coin can be thought of as a 1-armed bandit. "Pulling" = flipping. Reward = 1 if heads, 0 if tails.

  • Average ≈ 0.5: fair coin.
  • Average > 0.5: biased toward heads.
  • Average < 0.5: biased toward tails.

This trivially illustrates the sample-average estimation.

2.32 Application 4: Clinical Trials

Suppose you have K candidate drugs and want to find the most effective one. Each patient is a single trial; reward = treatment success. You must balance:

  • Exploiting the drug that currently looks best (so patients get the best known treatment).
  • Exploring other drugs (so you don't miss a better cure).

2.33 Application 5: Simple Portfolio Management

A toy model: 3 actions = {Buy, Sell, Hold} a single asset. Reward = realized return. The MAB model is a simplification; the full problem is properly modeled as a full RL problem because the optimal action depends on the current market state.

2.34 When MAB is Not Enough: Contextual Bandits

If the best action depends on contextual information (user identity, location, time of day, etc.), the vanilla MAB no longer suffices. We then move to Contextual Bandits — the next step toward full RL.

Textbook Motivating Example: Colored Slot Machine (Sutton & Barto, §2.8)
Imagine a slot machine that changes the color of its display when it changes its hidden action values. Without the color signal, you'd face a nonstationary bandit where the true values jump randomly — methods that rely on slow tracking of a single estimate would fail. With the color signal, you can learn an associative policy: "if red, play arm 1; if green, play arm 2." Each color (context) tells you which situation you're in, and the policy associates each situation with its best action. This shift from "find one best action" to "learn which action is best in which situation" is the key leap toward full reinforcement learning — the very idea Thorndike's Law of Effect described as forming associative links between situations and actions.
Definition: Contextual Bandit (Associative Search)
At each time step, the learner observes a context xt (side information about the situation), selects an action At, and receives a reward for that selected action. The objective is to learn which actions work well in which contexts — associating different situations with different useful actions.
Contextual Bandit vs. Full RL: A contextual bandit is not yet full RL because the action affects only the immediate reward — it is not treated as changing the next context in a controlled sequential process. In full RL, actions can affect future states and future rewards, so delayed consequences and long-term credit assignment become central.

Intuition: Life Stage Changes
Amazon's recommendations for a single user shift over time — college days, marriage, kids, retirement. Even if the user is "the same person", the underlying reward distribution changes with context. Pure MAB cannot capture this; contextual bandits and full RL can.

12. Summary & Key Takeaways

Key Concepts of This Lecture
  1. Elements of RL: Agent, Environment, Reward, Value Function, Model.
  2. State value V(s) vs. Action value Q(s, a): Q pre-summarizes future rewards and is preferred when outcomes are stochastic.
  3. Model of the environment: The distribution p(s′, r | s, a). If known, you can plan optimally; usually unknown.
  4. Deep RL: Replace value tables with neural networks.
  5. Multi-Armed Bandit: A stateless simplification of RL — pure focus on action-value estimation and exploration.
  6. Sample-average estimation: Qt(a) is the running average of rewards from arm a.
  7. Greedy is myopic and risks premature convergence.
  8. ε-greedy balances exploration (ε) and exploitation (1 − ε).
  9. For stationary problems, ε may decay over time. For non-stationary problems, keep ε > 0 always.
  10. Real-world bandit applications: ad serving, recommendation, A/B testing, clinical trials.

Test Your Knowledge

Q: In a 5-armed bandit with ε = 0.2 where arm 1 is the current greedy arm, what is Pr(selecting arm 1)?

Explanation: Under ε-greedy, Pr(greedy arm) = (1−ε) + ε/K = 0.8 + 0.2/5 = 0.84. Non-greedy arms each get probability ε/K = 0.04.

Q: Why can pure greedy (ε = 0) perform poorly on the 10-armed testbed?

Explanation: With ε=0 the agent commits to whichever arm looked best after a few pulls. Unlucky early draws cause permanent suboptimal exploitation without any further exploration.

Q: When is Q(s,a) typically preferred over V(s) for action selection?

Explanation: Q(s,a) stores the expected return for taking action a directly. With stochastic transitions, using V(s) would require evaluating all possible next states at each decision — Q avoids that overhead.

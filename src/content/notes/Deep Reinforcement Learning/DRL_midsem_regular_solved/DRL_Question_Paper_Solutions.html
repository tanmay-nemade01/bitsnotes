Midsem Solved.3 Question 1 - Bandit Algorithms for Restaurant Recommendation [6 Marks]

Midsem Solved.3.1 Concept Primer: What is a Multi-Armed Bandit (MAB)?

Imagine you walk into a casino with slot machines (one-armed bandits). Each machine pays out at a different unknown rate. Your goal is to figure out which machine pays the most and keep pulling it — but you face a dilemma: explore (try different machines to learn their payoffs) or exploit (keep pulling the machine that has paid the most so far). This is the classic exploration vs. exploitation trade-off.

In this problem, the three restaurants are like three slot machine arms. Each time the user orders from a restaurant, we get a reward of +1 (order placed); if they don't order, we get 0. Our goal is to estimate the "quality" (expected reward) of each restaurant and recommend the best one.

Key terms: - Q(a): The estimated value (average reward) of choosing action (restaurant) a. We update it incrementally as we collect more data. - Incremental averaging: A formula that lets us update Q(a) one step at a time without storing all past rewards. - UCB (Upper Confidence Bound): A strategy that picks the action with the highest Q-value plus an exploration bonus for actions we haven't tried much. - ε-Greedy: A strategy that mostly picks the best-known action (exploitation) but sometimes (with probability ε) picks a random action (exploration).

Midsem Solved.3.2 (a) Incremental Averaging - Q(R1), Q(R2), Q(R3) after 7 sessions [2 Marks]

What are we doing here?

We want to estimate the "quality" of each restaurant — how likely a user is to order when recommended that restaurant. We do this by keeping a running average of the rewards. Every time we recommend a restaurant, we observe whether the user ordered (reward = 1) or didn't (reward = 0), and we update our estimate.

Why incremental averaging? Instead of storing all past rewards and recomputing the average each time (which is slow and memory-intensive), we use a formula that updates the old estimate with just one new piece of data.

Formula (incremental update):

$$Q_n(A) = Q_{n-1}(A) + \frac{1}{n} \cdot (R_n - Q_{n-1}(A))$$

In plain English: "New estimate = Old estimate + (1/n) × (New reward − Old estimate)"

  • n = how many times this restaurant has been recommended so far
  • R_n = the reward from the latest recommendation (1 or 0)
  • The term (R_n − Q_{n-1}(A)) is the prediction error — the difference between what actually happened and what we expected
  • (1/n) is the step size — as n grows, each new observation has less impact (the average becomes more stable)

Why this works: When n = 1, the step size is 1, so we fully trust the first observation. When n = 100, the step size is 0.01, so each new observation barely moves the estimate — reflecting that we already have a reliable average.

Step-by-step:

Session Action R Q(R1) Q(R2) Q(R3) Update
Init — — 0 0 0 All initialised to 0
1 R1 1 1.000 0 0 n_R1=1, Q=0+(1/1)(1-0)=1
2 R2 0 1 0.000 0 n_R2=1, Q=0+(1/1)(0-0)=0
3 R3 1 1 0 1.000 n_R3=1, Q=0+(1/1)(1-0)=1
4 R1 1 1.000 0 1 n_R1=2, Q=1+(1/2)(1-1)=1

Final Q-values after 7 sessions:

Restaurant Q-value
R1 1.000
R2 0.667
R3 0.500

Sample calculation (Session 7 — R2): - n_R2 before update = 2 (sessions 2 and 5) - n_R2 = 3 after including session 7 - Q(R2) = 0.5 + (1/3)(1 − 0.5) = 0.5 + 0.5/3 = 0.5 + 0.1667 = 0.6667

Reading the result: R1 has Q = 1.000 (it was recommended twice and the user ordered both times), R2 has Q = 0.667 (ordered 2 out of 3 times), and R3 has Q = 0.500 (ordered 1 out of 2 times). So R1 looks best so far.

Midsem Solved.3.3 (b) UCB with c = 2 - Action at Session 8 [2 Marks]

What are we doing here?

The problem with incremental averaging alone is that it only tells us what happened — it doesn't account for how confident we are. R1 has a perfect Q-value of 1.000, but it was only tried twice. R2 has a lower Q-value but was tried three times. Should we keep recommending R1 blindly?

UCB (Upper Confidence Bound) solves this by adding an exploration bonus to each restaurant's Q-value. The bonus is larger for restaurants we've tried fewer times, effectively saying: "This restaurant might be great — we just haven't tried it enough to know." The parameter c controls how aggressive the exploration is (higher c = more exploration).

UCB formula:

$$A_t = \arg\max_a \left[ Q_t(a) + c \cdot \sqrt{\frac{\ln(t)}{N_t(a)}} \right]$$

In plain English: "Pick the restaurant with the highest (estimated quality + exploration bonus)."

  • t = total number of sessions so far (= 7)
  • N_t(a) = how many times restaurant a has been recommended
  • ln(t) / N(a) = the "uncertainty" — bigger when N(a) is small (we haven't tried this restaurant much)
  • c = 2 = the exploration coefficient — multiplying by 2 gives a generous bonus for under-explored restaurants
  • √ ensures the bonus grows slowly (logarithmically) over time — we explore more early on, less later

where: - t = total sessions so far = 7 - N(R1) = 2, N(R2) = 3, N(R3) = 2 - ln(7) = 1.9459 - c = 2

Step 1 — Compute exploration bonus for each restaurant:

Restaurant N(a) ln(t)/N(a) √(ln(t)/N(a)) c × √(ln(t)/N(a))
R1 2 1.9459/2 = 0.97295 0.9864 2 × 0.9864 = 1.9728
R2 3 1.9459/3 = 0.64863 0.8054 2 × 0.8054 = 1.6108
R3 2 1.9459/2 = 0.97295 0.9864 2 × 0.9864 = 1.9728

Why R1 and R3 have the same bonus: Both have been tried only 2 times, so both have the same uncertainty. R2 has been tried 3 times, so its bonus is smaller — it's less uncertain.

Step 2 — Compute UCB values:

Restaurant Q(a) Exploration Bonus UCB = Q(a) + Bonus
R1 1.000 1.9728 2.9728
R2 0.667 1.6108 2.2775
R3 0.500 1.9728 2.4728

Step 3 — Select action with highest UCB:

UCB(R1) = 2.9728 > UCB(R3) = 2.4728 > UCB(R2) = 2.2775

Action at session 8: R1 — R1 wins because it has both the highest Q-value and a large exploration bonus (it hasn't been tried as often as R2). UCB naturally balances exploitation (high Q) with exploration (large bonus for rarely-tried actions).

Midsem Solved.3.4 (c) ε-Greedy with ε = 0.3 - Selection Probabilities [2 Marks]

What are we doing here?

The ε-Greedy strategy is the simplest way to balance exploration and exploitation. With probability (1 − ε), we exploit — pick the restaurant with the highest Q-value. With probability ε, we explore — pick a random restaurant uniformly (each restaurant has equal chance).

Think of it as: "Most of the time (70%), I'll recommend my best guess. But 30% of the time, I'll try something random — maybe I'll discover something better."

ε-greedy rule: - With probability 1 − ε = 0.7: select the greedy action (highest Q-value) - With probability ε = 0.3: explore uniformly among all 3 actions

Step 1 — Identify greedy action:

Q(R1) = 1.000, Q(R2) = 0.667, Q(R3) = 0.500

Greedy action: R1 (highest Q-value)

Step 2 — Compute probabilities:

Restaurant Greedy Component (p = 0.7) Exploration Component (p = 0.3) Total Probability
R1 0.7 × 1 = 0.7 0.3 × (1/3) = 0.1 0.8
R2 0.7 × 0 = 0.0 0.3 × (1/3) = 0.1 0.1
R3 0.7 × 0 = 0.0 0.3 × (1/3) = 0.1 0.1

Selection probabilities at session 8: - P(R1) = 0.8 (greedy pick + exploration) - P(R2) = 0.1 (exploration only) - P(R3) = 0.1 (exploration only)

The tie between R2 and R3 during exploration is broken arbitrarily (uniform random).

Key insight: Even though R1 is the "best" restaurant, it only gets 80% of the probability, not 100%. The remaining 20% is spread equally among all restaurants. This ensures we keep gathering information about R2 and R3 in case our estimates are wrong. If ε were 0, we'd never explore again — a bad strategy if the true qualities are different from our current estimates.

Midsem Solved.4 Question 2 - Hospital Triage MDP [6 Marks]

Midsem Solved.4.1 Concept Primer: What is an MDP?

A Markov Decision Process (MDP) is a mathematical framework for modelling sequential decision-making under uncertainty. It consists of:

  • States: The different situations the system can be in (e.g., "patient at triage" vs "patient admitted")
  • Actions: What the decision-maker can do in each state (e.g., "Admit" or "Observe")
  • Transition probabilities: The chance of ending up in each possible next state after taking an action. These are stochastic — you don't know for sure what will happen.
  • Rewards: A numerical signal (positive or negative) received after each transition, telling you how good the outcome was.
  • Discount factor (γ): A number between 0 and 1 that determines how much you care about future rewards vs immediate rewards. γ = 0 means "only care about now"; γ = 1 means "future rewards matter as much as present ones."

The "Markov" property means the future depends only on the current state, not on how we got there — making the problem tractable.

Midsem Solved.4.3 (b) Bellman Optimality Equations with γ = 0.9 [2 Marks]

What are we doing here?

The Bellman equation is the core equation of dynamic programming in MDPs. It answers: "What is the value (long-term expected reward) of being in a given state?"

The idea is: the value of a state equals the best expected reward you can get from that state, considering all future rewards discounted by γ. "Discounted" means a reward of +10 two steps from now is worth only 10 × γ² to you today (because of uncertainty about the future).

The Bellman Optimality Equation says: V(s) = max over all actions of [expected immediate reward + γ × expected value of next state]. We start from terminal states (where V = 0) and work backwards.

Why start from T? Because terminal states have no future — their value is 0. This gives us a base case to calculate backwards.

For terminal state: V*(T) = 0

For S2 (no action — only stochastic outcome):

S2 represents a patient who was observed but still needs admission. There's no decision to make here — the system just transitions to Terminal with some probability.

V(S2) = Σ_{s'} P(s' | S2) · [ R(S2 → s') + γ · V(s') ]

This says: "The value of being in S2 is the weighted average of all possible outcomes: probability × (reward + discounted future value)."

V(S2) = 0.8 × [10 + 0.9 × 0] + 0.2 × [−5 + 0.9 × 0] = 0.8 × 10 + 0.2 × (−5) = 8 − 1 = 7*

For S1 (two actions to choose from):

Here we must decide: Admit or Observe? We compute the value of each action (Q-value) and pick the better one.

V*(S1) = max { Q(S1, Admit), Q(S1, Observe) }

Q(S1, Admit) = Σ P(s' | S1, Admit) · [ R + γ · V(s') ] = 0.8 × [10 + 0.9 × 0] + 0.2 × [−5 + 0.9 × 0] = 8 − 1 = 7*

Q(S1, Observe) = Σ P(s' | S1, Observe) · [ R + γ · V(s') ] = 0.6 × [3 + 0.9 × 0] + 0.4 × [2 + 0.9 × V(S2)] = 0.6 × 3 + 0.4 × [2 + 0.9 × 7] = 1.8 + 0.4 × [2 + 6.3] = 1.8 + 0.4 × 8.3 = 1.8 + 3.32 = 5.12

V*(S1) = max{7, 5.12} = 7

Optimal action at S1: Admit (since 7 > 5.12)

Bellman equation for S1 (compact form):

V(S1) = max { 0.8(10 + 0.9·0) + 0.2(−5 + 0.9·0), ← Admit 0.6(3 + 0.9·0) + 0.4(2 + 0.9·V(S2)) ← Observe }

where V*(S2) = 0.8(10) + 0.2(−5) = 7

Midsem Solved.4.4 (c) Impact of Changing Deterioration Reward from −5 to 0 [2 Marks]

If the deterioration reward changes from −5 to 0:

Recalculated values:

V(S2) = 0.8 × 10 + 0.2 × 0 = 8*

Q(S1, Admit) = 0.8 × 10 + 0.2 × 0 = 8

Q(S1, Observe) = 1.8 + 0.4 × [2 + 0.9 × 8] = 1.8 + 0.4 × 9.2 = 1.8 + 3.68 = 5.48

The agent becomes less risk-averse toward deterioration since the negative penalty is removed, making Admit an even more attractive choice relative to Observe (gap widens from 1.88 to 2.52). Midsem Solved.5 Question 3 - Recycling Robot: Value Iteration [6 Marks]

Midsem Solved.5.1 Concept Primer: What is Value Iteration?

Value Iteration is an algorithm that finds the optimal policy (best action for each state) by iteratively improving value estimates for every state. Starting from V₀(s) = 0 for all states, at each iteration, we update every state's value using the Bellman Optimality backup:

$$V_{k+1}(s) = \max_a \sum_{s'} P(s'|s,a) \cdot [R(s,a,s') + \gamma \cdot V_k(s')]$$

In plain English: "For each state, try every possible action, compute the expected total reward for each (immediate reward + discounted value of where you end up), and keep the best one as the new value."

After enough iterations, the values converge to V*(s), and the optimal action at each state is simply the action that achieved the maximum in the last iteration.

Why iterate? Because we don't know the true values upfront. Each iteration propagates information one step further into the future — after k iterations, each state's value accounts for the best possible outcomes up to k steps ahead.

Midsem Solved.6 Question 4 - Monte Carlo Methods for Self-Driving Car [6 Marks]

Midsem Solved.6.1 Concept Primer: What are Monte Carlo Methods?

Monte Carlo (MC) methods learn the value of states by averaging the actual returns (total discounted rewards) observed from many complete episodes of experience. Unlike Dynamic Programming, MC methods don't need a model of the environment — they just observe what happens.

Key terms: - Episode: A complete sequence of states, actions, and rewards from start to finish (like one complete drive). - Return (G_t): The total discounted reward from time step t onwards: $G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \ldots$ - First-Visit MC: Only the first time we visit a state in an episode counts toward the average. This avoids bias from revisiting the same state. - Every-Visit MC: Every visit to a state in an episode counts. This uses more data but can be slightly biased in some settings. - Why average returns? By the law of large averages, if we visit a state many times and average the returns, we converge to the true expected return (i.e., V(s)).

States: S1 (straight road), S2 (approaching intersection) γ = 0.8

Midsem Solved.6.3 (a) First-Visit MC - V(s) Estimates [2 Marks]

What are we doing here?

In First-Visit Monte Carlo, we look at each episode and collect the return G_t only for the first time we enter each state. Then we average those returns across all episodes to estimate V(s). If a state appears multiple times in one episode, we only count the first occurrence — this ensures each sample is independent.

Midsem Solved.6.5 (c) Why Dynamic Programming is Unsuitable [2 Marks]

Dynamic Programming requires a complete model of the MDP — specifically, known transition probabilities P(s' | s, a) and reward function R(s, a, s'). In this self-driving car scenario, the vehicle navigates a real-world environment where the exact probabilities of transitioning between road states under different driving actions are unknown and cannot be pre-specified. Unlike controlled grid-worlds or board games, real driving involves stochastic road conditions, unpredictable traffic, and continuous sensor noise, making it impossible to enumerate exact transition dynamics — hence DP cannot be applied and model-free methods like Monte Carlo are necessary.

Midsem Solved.7.1 (a) Return Calculation G₀ through G₅ [2 Marks]

What are we doing here?

The return G_t is the total discounted reward from time step t to the end of the episode. It answers: "If I'm at time t, how much total reward (accounting for the discount factor) will I accumulate from now until the episode ends?"

Why discount? Because rewards further in the future are less certain and less valuable than immediate rewards. The discount factor γ (0 < γ ≤ 1) controls how much we care about the future vs. now.

Midsem Solved.7.2 (b) Autonomous Drone Landing - MAB vs RL Framework [2 Marks]

(i) Can this be modelled as a Multi-Armed Bandit?

No. A Multi-Armed Bandit assumes that actions do not affect future states or future reward distributions — each pull of an arm is independent of previous pulls. Landing a drone on a moving ship is fundamentally non-stationary and state-dependent: the drone's current position, velocity, altitude, and the ship's motion all change as a result of the drone's actions. Taking an incorrect action (e.g., descending too early) moves the drone into a different state where the set of available options and their outcomes are completely different.

(ii) More appropriate RL framework

A full MDP (Markov Decision Process) formulation is appropriate, solved using model-free reinforcement learning (e.g., Q-learning, Deep Q-Networks, or Policy Gradients). This framework captures: - State transitions: The drone's position and velocity evolve based on actions taken - Stochastic dynamics: Unknown ship motion introduces randomness in outcomes - Sequential decision-making: The value of a current action depends on future states - Delayed rewards: A safe landing reward is only obtained after a sequence of correct actions

An alternative framework is Model-Based RL, where the drone learns an approximate model of ship motion dynamics from experience and uses it for planning — this can be more sample-efficient when interacting with a real physical system.

Midsem Solved.7.3 (c) Policy Iteration vs Value Iteration [2 Marks]

One-sentence justification for each: - Convergence speed: Policy iteration typically converges in O(|S|) iterations because each policy evaluation step fully propagates value information, while value iteration's convergence rate depends on γ and requires many iterations when γ ≈ 1. - Cost per iteration: Value iteration costs O(|S|²|A|) per sweep (one Bellman backup per state), whereas policy iteration costs O(|S|³) per policy evaluation if solving linear systems exactly, or O(k|S|²) for k iterative evaluation sweeps.

Intuitive analogy: Think of Value Iteration as taking small steps towards the answer at each iteration (updating values one step at a time), while Policy Iteration takes a big leap by fully solving for the current policy's values, then switching to a better policy. The big leap often gets to the answer in fewer total steps, but each step costs more.

Practical note: For small to medium MDPs (|S| < 10⁶), policy iteration often converges faster in total wall-clock time despite the higher per-iteration cost, whereas value iteration is simpler to implement and preferred when |S| is very large.

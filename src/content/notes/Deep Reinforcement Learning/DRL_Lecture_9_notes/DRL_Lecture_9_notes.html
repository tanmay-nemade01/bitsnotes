9.1 The Role of Reinforcement Learning in Modern AI

Hook: Can you name a modern AI system that does not use some form of trial-and-error learning? From ChatGPT to self-driving cars, the answer is increasingly "none." Reinforcement Learning is the engine behind this shift — and it is no longer confined to niche control problems.

9.1.1 RL as the Foundation for Iterative Refinement

Intuition: Think of RL as the process of learning to cook. You try a recipe, taste the result, adjust the salt, try again. Each iteration makes you a better cook. RL does the same for AI: it takes an action, observes the outcome (reward), and adjusts its strategy to do better next time. The cycle — act, observe, improve — is what drives every RL system.
Formalize: Reinforcement Learning is a computational approach to learning from interaction. An agent takes actions in an environment, receives rewards (scalar feedback signals), and updates its policy (the mapping from situations to actions) to maximize cumulative reward over time. Key terms: - Agent: the learner/decision-maker - Environment: everything the agent interacts with - State \(s\): the situation the agent is in - Action \(a\): what the agent can do - Reward \(R_t\): scalar feedback at time \(t\) - Return \(G_t\): cumulative (possibly discounted) sum of future rewards: \(G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \ldots\) - Policy \(\pi(a|s)\): probability of taking action \(a\) in state \(s\)

Reinforcement Learning has become the foundation for almost all modern AI tasks. A few years ago, RL use cases were limited to domains like thermal power plant control — using sensors to measure physical parameters and using RL to keep them in control. Today, RL applications are far more prevalent.

Consider an information retrieval pipeline: you submit a query, the system tries to understand the query, decomposes it, fetches relevant documents, and ranks them so the most relevant appears at the top. With LLMs and RAG (Retrieval-Augmented Generation), there is a need to iteratively refine results. Iterative refinement — keep improving performance — is where RL comes in.

Analogy — the student preparing for an exam: A student solves a practice paper (action), checks the answer key (reward), learns what went wrong (update), and solves the next paper better. The cycle of "attempt → feedback → improve" is RL in human form. The student does not need a mathematical model of the exam — they learn purely from experience. This is the essence of model-free RL.

Even LLM training pipelines now use RL. There are algorithms like DPO (Direct Preference Optimization), but without understanding the basics of RL, it is impossible to adapt such algorithms to specific requirements. Unlike classic algorithms like quicksort — which are done, tested, and simply called — modern RL algorithms are recent and often need to be adapted to particular scenarios. This is why foundations are critical.

Concrete example — LLM alignment with RLHF: 1. A language model generates a response (action). 2. A human rates the response as helpful or unhelpful (reward). 3. A reward model is trained to predict human preferences. 4. The LLM's policy is updated using RL (specifically PPO) to maximize the predicted reward. 5. The cycle repeats, and the LLM becomes increasingly aligned with human preferences. This is RL in production — and it depends on the same concepts (policy, reward, value, return) covered in this lecture.
Scope: The RL methods in this course apply to problems where: - The agent interacts with an environment sequentially - Feedback comes as scalar rewards (not full labels) - The goal is to maximize long-term cumulative reward - The environment may be unknown (model-free setting) RL is not the right tool when you have a fixed labeled dataset and need one-shot predictions — that is supervised learning's domain.

Visual Intuition: Picture the RL loop as a circle: Agent → Action → Environment → Reward + New State → Agent (update) → ... This agent-environment interaction loop is the central diagram of RL. The agent sits on one side, the environment on the other. The only communication channels are actions (agent → environment) and observations + rewards (environment → agent). Every RL algorithm, from the simplest bandit to the most complex LLM trainer, fits this loop.

Pitfalls: 1. Confusing RL with supervised learning: RL has no "correct answer" labels. The agent discovers what works through trial and error. 2. Assuming a model is always needed: Modern RL (Monte Carlo, TD) can learn without knowing the environment's transition probabilities — this is the model-free setting. 3. Expecting immediate results: RL needs many episodes of interaction. The first policy is random; improvement is gradual.
Recap: RL is learning what to do (policy) by trying things (actions) and seeing what works (rewards). It powers everything from game-playing AI to LLM alignment. Bridge: Before building optimal policies, we need to evaluate a given policy — which is exactly what Monte Carlo methods do.

Real-World & Domain Connection: RL is used in LLM training pipelines (DPO, RLHF), information retrieval with RAG, thermal power plant control, robotics, game playing (AlphaGo, OpenAI Five), inventory management, and drug discovery. The common thread: any sequential decision problem where you can measure success but don't have a labeled dataset of "correct" decisions.

    9.3 Recap: On-Policy Monte Carlo Methods

    9.3.1 What Are Monte Carlo Methods?

    Hook: Imagine learning to play chess without ever being told the rules. You just play thousands of games, and after each game, you know whether you won or lost. Over time, you figure out which moves lead to wins. That is Monte Carlo RL — learning solely from the outcomes of complete experiences.
    Definition: Monte Carlo (MC) methods are model-free RL techniques that learn value functions and optimal policies by averaging sample returns from complete episodes. They do not require a model of the environment's dynamics — only experience in the form of state-action-reward sequences. The name "Monte Carlo" comes from the famous casino city — a nod to the random sampling at the heart of these methods. In RL, MC methods specifically refer to methods that average complete returns (unlike TD methods, which learn from partial returns).
    Intuition — the roulette analogy: A Monte Carlo method is like estimating the average payout of a roulette wheel by spinning it thousands of times and averaging the results. You don't need to know the wheel's physics (the model). You just need to spin and record. Each spin is an episode; the payout is the return.

    The core idea: generate many episodes from a given policy, and use those episodes as a basis to improve the policy.

    9.3.2 Policy Evaluation with MC

    Policy Evaluation (Prediction): Given a fixed policy \(\pi\), estimate the value function \(V^\pi(s)\) or action-value function \(Q^\pi(s,a)\) — the expected return starting from state \(s\) (and taking action \(a\)) and following \(\pi\) thereafter. The MC approach: run many episodes following \(\pi\). For each state \(s\) visited, record the return \(G\) that followed. The estimate \(V(s)\) is the average of all returns observed after visiting \(s\). \[ V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s] \approx \frac{1}{N} \sum_{i=1}^{N} G_i(s) \] Where \(G_i(s)\) is the return following the \(i\)-th visit to state \(s\), and \(N\) is the number of visits.

    Two variants:

  • First-visit MC: Average returns only from the first visit to \(s\) in each episode. Unbiased; most widely studied.
  • Every-visit MC: Average returns from all visits to \(s\). Slightly biased but extends naturally to function approximation.

    • Both converge to the true \(V^\pi(s)\) as the number of visits goes to infinity.

    9.3.3 MC Control — The Full Algorithm

    MC Control (Policy Improvement): MC control uses Generalized Policy Iteration (GPI) — alternating between policy evaluation (estimating Q-values from episodes) and policy improvement (making the policy greedy with respect to Q). The broad steps: - Start with an arbitrary policy \(\pi\) (epsilon-soft — all actions have at least \(\varepsilon/|A|\) probability) - Generate episodes, compute returns, update \(Q(s,a)\) - Improve \(\pi\) to be \(\varepsilon\)-greedy with respect to the latest \(Q\) - Repeat — the policy improves with each cycle - The starting random policy is \(\varepsilon\)-soft; the optimal policy converges to \(\varepsilon\)-greedy

    MC methods are value-based: you compute values of state-action pairs and use those values to direct the policy. Unlike DP, no model is needed because Q-values directly tell you which action is best.

    9.3.5 Initialization Details

    The algorithm initializes three things:

  • Policy \(\pi\): \(\varepsilon\)-soft — every action in every state has probability at least \(\varepsilon / |A(s)|\). This ensures all actions are explored.
  • \(Q(s, a)\) values: initialized arbitrarily (randomly) for all state-action pairs. Unlike DP's state values, MC control uses action values because — without a model — state values alone cannot tell you which action to take.
  • Returns list: an empty list attached to each \((s, a)\) pair. New returns are appended to this list. At any point, \(Q(s, a)\) is the average of everything in the returns list.
    • Example with four actions (A1, A2, A3, A4) from state S: You compute \(Q(S, A_1)\), \(Q(S, A_2)\), \(Q(S, A_3)\), \(Q(S, A_4)\). For \(Q(S, A_3)\), maintain a returns list: - Episode 1 return: 3 → list: \([3]\), \(Q = 3\) - Episode 2 return: 4 → list: \([3, 4]\), \(Q = (3+4)/2 = 3.5\) - Episode 3 return: 5 → list: \([3, 4, 5]\), \(Q = (3+4+5)/3 = 4\) - Episode 4 return: 5 → list: \([3, 4, 5, 5]\), \(Q = (3+4+5+5)/4 = 4.25\) Each return can be a simple cumulative sum (\(\gamma=1\)) or a discounted return — whichever is decided for the problem.

    9.3.7 On-Policy Analogy — The Self-Made Person

    The professor's analogy: On-policy learning is like a self-made person — you enter the world, try things, experience outcomes, improve yourself, all on your own. There is no mentor, no teacher. You interact with the world, improve yourself, and cycle.

    The policy \(\pi\) plays two roles simultaneously:

  • Explorer: generating experience by interacting with the environment
  • Optimizer: converging toward optimal behavior
    • The fundamental tension: A policy generating experience must allow exploration (cannot always pick the greedy action), but the goal is to become optimal (mostly picking the greedy action). One policy is forced to serve two masters — explore enough to find good actions, but exploit enough to be useful. This is the exploration-exploitation dilemma.
    Pitfalls of on-policy MC: 1. Exploration vs exploitation trade-off: Too much exploration → slow convergence. Too little → may miss optimal actions entirely. 2. Only learns about actions it takes: If \(\pi\) never tries action \(a\) in state \(s\), \(Q(s,a)\) never improves. This is why \(\varepsilon\)-soft policies are required. 3. Episodic only: MC methods require episodes to terminate. For continuing (non-episodic) tasks, TD methods are needed. 4. High variance: A single episode's return can be far from the true expected value. Many episodes are needed for convergence.
    Recap: On-policy MC learns by doing — one policy both generates experience and improves from it. It is simple and converges under mild conditions, but the single-policy bottleneck limits its flexibility. Bridge: What if we could separate exploration from learning? One policy explores (the teacher), another learns (the student). This is off-policy learning.

    Real-World & Domain Connection: On-policy methods are used when you control the data collection process — robots exploring a warehouse, game AI playing against itself, recommendation systems doing A/B testing. The agent's own actions generate the training data, and the same policy that collects data is the one being improved.

    9.4 Motivation for Off-Policy Learning

    9.4.1 The Two-Role Tension

    Hook: What if you could learn to drive by watching thousands of other drivers — good ones, bad ones, and everything in between — without ever sitting behind the wheel yourself? And what if, after learning, you could drive better than any of them? That is the promise of off-policy learning.
    The problem with on-policy: The policy \(\pi\) in on-policy methods must simultaneously: 1. Explore enough to discover good actions (requires randomness) 2. Exploit what it has learned to be optimal (requires greediness) This is like asking one person to be both the curious student who tries everything and the disciplined expert who always does the right thing. The tension is unavoidable.

    Additionally, in real environments, there are often:

  • Safety constraints: certain actions are disallowed. "You can do anything, but this door must never be opened."
  • Prior experience: a teacher can provide teaching examples from past experience. The learner should not be constrained by what the teacher knows — the learner can experiment and do better.

    • 9.4.2 Decoupling the Roles

    Off-policy learning separates exploration from optimization by using two different policies: | Policy | Role | Description | |--------|------|-------------| | Behavior policy \(b\) | Teacher / Explorer | Generates experience. Can bring prior knowledge, safety norms, constraints. | | Target policy \(\pi\) | Learner / Optimizer | The policy being learned. Starts arbitrary, improves over time. | The behavior policy generates the episodes. The target policy learns from them — but through a correction factor (importance sampling) that accounts for the fact that the experience came from a different policy.
    The professor's analogy (Dr. Kalam): The teachers who taught Dr. A.P.J. Abdul Kalam did not become president or rocket scientists. The learner went beyond. The teacher allowed the learner to explore, learn, and improve. The behavior policy is the teacher — it provides the raw material. The target policy is the student — it can surpass the teacher.

    The behavior policy can:

  • Disallow certain actions (set probability to 0 for unsafe actions) — enforcing safety constraints
  • Bring a wealth of prior knowledge — from all doctors in a medical domain, all traffic data in transportation, all financial history in finance
  • Be a fixed, pre-existing dataset (batch off-policy learning)

    • The target policy learns from this experience but is not constrained by it. The learner can surpass the teacher — this is the key advantage over on-policy methods.

    9.4.3 The Core Challenge — Different Distributions

    The distribution mismatch problem: The behavior policy \(b\) and target policy \(\pi\) are different probability distributions over actions. Experience is generated from \(b\), but the learner wants expectations according to \(\pi\). If you simply average all returns, you are computing: \[ \mathbb{E}_b[G_t \mid S_t = s] = v_b(s) \] But what you actually want is: \[ \mathbb{E}_\pi[G_t \mid S_t = s] = v_\pi(s) \] These are not the same because \(b \neq \pi\). The returns are "biased" — they reflect the behavior policy's preferences, not the target policy's.
    Intuition — learning from a different teacher: A cautious driving instructor (behavior policy) always takes the safe route and gets home in 30 minutes. You (target policy) want to take the highway and get home in 20 minutes. If you simply average the instructor's times, you estimate 30 minutes. But you drive differently — you need to correct the instructor's returns to reflect your driving style. This correction is called importance sampling.

    Where this is heading: Importance sampling provides a principled way to reweight returns from \(b\) so that their average converges to the value under \(\pi\). The correction factor is the ratio of trajectory probabilities under the two policies.

    Recap: Off-policy learning decouples exploration (behavior policy \(b\)) from optimization (target policy \(\pi\)). The cost is a distribution mismatch that must be corrected. Bridge: Importance sampling is the correction mechanism — it reweights returns so we can estimate \(\pi\)'s values using \(b\)'s experience.

    Real-World & Domain Connection: Off-policy learning works well with historical data like user click logs, medical records, and financial transactions. You can learn a policy better than the one that generated the data. It is also key in safety-sensitive domains such as autonomous driving and healthcare. In these cases, exploring freely is too dangerous — you learn from safe demonstrations instead.

    9.5 Importance Sampling

    9.5.1 The Intuition

    Hook: You and your friend both flip coins, but your coin is biased toward heads (70% heads) while your friend's is fair (50% heads). Your friend records their results: heads, tails, heads. How would you estimate what your expected winnings would be if you had been flipping? You would give more weight to heads (which you get more often) and less to tails. Importance sampling is exactly this idea, applied to entire action sequences.
    The professor's intuition: The teacher says: do step A, then step C, then step C again, then step D. The teacher says this sequence yields a return of 100. But the learner's behavior is different: do more of A, much less of C, more of D. The return according to the teacher is 100, but the learner needs to adjust this — the learner's importance for A is higher, for C is lower, for D is higher. A correction factor is needed.

    9.5.2 Trajectory Probability

    Trajectory probability: Consider a trajectory \(\tau\): \[ S_0 \xrightarrow{A_1} S_1 \xrightarrow{A_2} S_0 \xrightarrow{A_1} \text{Terminal} \] The probability of this trajectory under policy \(\pi\) is the product of alternating policy decisions and environment transitions: \[ P_\pi(\tau) = \pi(A_1|S_0) \cdot p(S_1|S_0,A_1) \cdot \pi(A_2|S_1) \cdot p(S_0|S_1,A_2) \cdot \pi(A_1|S_0) \cdot p(T|S_0,A_1) \] Breaking this down: - \(\pi(A_1|S_0)\) — probability the policy chooses \(A_1\) from \(S_0\) (policy decision) - \(p(S_1|S_0,A_1)\) — probability the environment transitions to \(S_1\) given \((S_0, A_1)\) (environment model) - ...and so on, alternating policy and environment for each step. The general form: for a trajectory of length \(T\), \[ P_\pi(\tau) = \prod_{t=0}^{T-1} \pi(A_t|S_t) \cdot p(S_{t+1}|S_t, A_t) \]

    The apparent contradiction: Computing \(P_\pi(\tau)\) requires the environment model \(p\) — but Monte Carlo methods are model-free. This seems like a dead end.

    9.5.3 The Ratio Eliminates the Model

    The critical insight: We do not need \(P_\pi(\tau)\) or \(P_b(\tau)\) individually. We only need their ratio: \[ \frac{P_\pi(\tau)}{P_b(\tau)} = \frac{\prod_{t} \pi(A_t|S_t) \cdot p(S_{t+1}|S_t,A_t)}{\prod_{t} b(A_t|S_t) \cdot p(S_{t+1}|S_t,A_t)} \] Every \(p(S_{t+1}|S_t, A_t)\) term appears identically in both numerator and denominator. They cancel out, leaving: \[ \frac{P_\pi(\tau)}{P_b(\tau)} = \prod_{t=0}^{T-1} \frac{\pi(A_t | S_t)}{b(A_t | S_t)} \] This product is called the importance sampling ratio, denoted \(\rho\) (rho). \[ \boxed{\rho_{0:T-1} = \prod_{t=0}^{T-1} \frac{\pi(A_t | S_t)}{b(A_t | S_t)}} \] The standard textbook form (Sutton & Barto, Eq. 5.3) writes this as: \[ \rho_{t:T-1} = \prod_{k=t}^{T-1} \frac{\pi(A_k|S_k)}{b(A_k|S_k)} \] where the subscript \(t:T-1\) indicates the ratio covers steps \(t\) through \(T-1\).
    Why this matters: You do NOT need the environment model to compute the importance sampling ratio. The model probabilities cancel out. Only the policy probabilities — which you define — matter. This is what makes importance sampling compatible with model-free RL.

    9.5.5 The Coverage Condition

    Coverage condition: For off-policy learning to be valid, the behavior policy \(b\) must satisfy: \[ \pi(a|s) > 0 \implies b(a|s) > 0 \quad \text{for all } s, a \] What this means: If the target policy allows taking action \(a\) from state \(s\) (probability > 0), the behavior policy must also allow it with non-zero probability. If the teacher says a particular action is disallowed (\(b(a|s) = 0\)), that action will never be taken during experience generation — and the learner can never learn about it. The professor's analogy (Chandramukhi film reference): If the teacher says "you must never open that door" (probability = 0), then during experience generation, that door will never be opened. The learner cannot evaluate that action. Coverage is the mathematical guarantee that the learner can eventually learn about every action the target policy might take.

    9.5.6 Worked Example — Computing \(\rho\) for a Simple Trajectory

    Setup: - State \(S\) has two actions: \(A\) and \(B\) - Target policy \(\pi\): \(\pi(A|S) = 0.7\), \(\pi(B|S) = 0.3\) - Behavior policy \(b\): \(b(A|S) = 0.5\), \(b(B|S) = 0.5\) Trajectory (Version 1 — mixed actions): \(S \xrightarrow{A} S \xrightarrow{B} S \xrightarrow{A} \text{Terminal}\) Rewards: After first \(A\): 0, after \(B\): 2, after second \(A\): 10. (\(\gamma = 1\), so return from start \(G = 0 + 2 + 10 = 12\)) Step-by-step \(\rho\) computation: \[ \begin{aligned} \rho &= \frac{\pi(A|S)}{b(A|S)} \cdot \frac{\pi(B|S)}{b(B|S)} \cdot \frac{\pi(A|S)}{b(A|S)} \\ &= \frac{0.7}{0.5} \cdot \frac{0.3}{0.5} \cdot \frac{0.7}{0.5} \\ &= 1.4 \times 0.6 \times 1.4 \\ &= \mathbf{1.176} \end{aligned} \] --- Trajectory (Version 2 — all A, the version the professor computed in class): \(S \xrightarrow{A} S \xrightarrow{A} S \xrightarrow{A} \text{Terminal}\) \[ \begin{aligned} \rho &= \left(\frac{\pi(A|S)}{b(A|S)}\right)^3 = \left(\frac{0.7}{0.5}\right)^3 = (1.4)^3 = \mathbf{2.744} \end{aligned} \] Note: The professor's spoken calculation yielded \(\rho \approx 2.74\), which corresponds to version 2 (all A actions). The lecture notes originally showed both versions mixed. Both are correct for their respective trajectories. The key point: \(\rho\) is the product of per-step probability ratios — compute it one step at a time.

    Interpreting \(\rho\):

  • \(\rho > 1\): the trajectory is more likely under the target policy than under the behavior policy. The learner gives this trajectory more importance than the teacher.
  • \(\rho < 1\): the trajectory is less likely under the target policy. The learner gives it less importance.
  • \(\rho \approx 1\): the learner is aligned with the teacher for this trajectory — no correction needed.
    • Pitfalls: 1. \(\rho\) can grow/shrink exponentially: A product of \(T\) ratios — for long episodes, \(\rho\) can become extremely large (if \(\pi\) strongly favors the taken actions) or extremely small (if \(\pi\) strongly disfavors them). This causes the high variance of ordinary importance sampling. 2. \(\rho = 0\) when \(\pi\) is deterministic and disagrees: If \(\pi\) is deterministic and the behavior policy takes an action \(\pi\) would not, \(\rho\) becomes 0 for the entire trajectory from that point backward. 3. Coverage violation produces 0/0: If \(b(a|s) = 0\) for some action \(\pi\) might take, the ratio is undefined and learning is impossible for that action.
    Recap: The importance sampling ratio \(\rho = \prod_t \frac{\pi(A_t|S_t)}{b(A_t|S_t)}\) reweights a trajectory generated by \(b\) so that, on average, it reflects what would have happened under \(\pi\). The model dynamics cancel out — only policy probabilities matter. Bridge: With \(\rho\) in hand, we can now compute value estimates from off-policy data — which brings us to ordinary vs. weighted importance sampling.

    Real-World & Domain Connection: Importance sampling is used far beyond RL. In survey statistics, it reweights biased samples to match population demographics. In Monte Carlo integration, it samples from an easy distribution to estimate integrals under a hard one. In A/B testing, it estimates a new policy's effect from data collected under the old one. Off-policy RL inherits this machinery to learn optimal behavior from suboptimal data.

    Importance-weighted return for (S, A): The raw return is 12. The corrected return = 12 × ρ.

    The return for (S, B) and the final (S, A) are computed similarly, each with their own ρ computed from that step onward.

    9.6 Worked Grid-World Example

    9.6.1 Environment Setup

    Consider a grid with states \(W\) (West), \(X\), \(Y\), and an absorbing terminal state. From each state, two actions are possible: Right and Left.     9.7 Ordinary vs Weighted Importance Sampling

    9.7.1 Ordinary Importance Sampling

    Ordinary importance sampling estimates \(V^\pi(s)\) as the simple (unweighted) average of all importance-weighted returns: \[ V^\pi(s) = \frac{\sum_{i=1}^{N} \rho_i \cdot G_i}{N} \] Where: - \(N\) is the number of episodes (returns observed for state \(s\)) - \(\rho_i\) is the importance sampling ratio for episode \(i\) - \(G_i\) is the raw return from episode \(i\)
    Applying to the two episodes from section 9.6: | Episode | \(\rho\) | \(G\) | \(\rho \cdot G\) | |---------|----------|-------|------------------| | \(\tau_1\) (Right) | 3.9204 | 10 | 39.204 | | \(\tau_2\) (Left) | 0.02 | 1 | 0.02 | Ordinary IS estimate for \(V^\pi(W)\): \[ V^\pi(W) = \frac{39.204 + 0.02}{2} = \frac{39.224}{2} = \mathbf{19.612} \] (Using the professor's rounded numbers: \(\frac{39.6 + 0.02}{2} = \frac{39.62}{2} = 19.81\))

    9.7.2 Weighted Importance Sampling

    Weighted importance sampling estimates \(V^\pi(s)\) as a weighted average — the numerator is the sum of importance-weighted returns, and the denominator is the sum of the importance weights themselves (not the count \(N\)): \[ V^\pi(s) = \frac{\sum_{i=1}^{N} \rho_i \cdot G_i}{\sum_{i=1}^{N} \rho_i} \] This normalizes by the total weight, preventing any single episode from dominating the estimate.
    Applying to the two episodes: \[ V^\pi(W) = \frac{39.204 + 0.02}{3.9204 + 0.02} = \frac{39.224}{3.9404} \approx \mathbf{9.954} \] (Using the professor's rounded numbers: \(\frac{39.6 + 0.02}{3.96 + 0.02} = \frac{39.62}{3.98} \approx 9.95\)) Sense-check: The true \(V^\pi(W)\) should be close to 10 (since the target policy almost always goes Right, and Right leads to a terminal reward of 10). The weighted IS estimate of ~9.95 is much closer to this than the ordinary IS estimate of ~19.61. Weighted IS correctly downweights the Left episode.

    9.7.3 Why Weighted Importance Sampling Is Preferred

    The professor's motivating example — extreme variance: Consider two episodes for estimating \(V^\pi(W)\): - Episode 1: Take the Right action 1000 times, then get reward 10. - \(\rho\) per step = \(0.99/0.5 \approx 1.98 \approx 2\) - Total \(\rho = 2^{1000}\) (astronomically large) - Importance-weighted return = \(2^{1000} \times 10\) - Episode 2: Take Right action 2 times, then get reward 10. - Total \(\rho = 2^2 = 4\) - Importance-weighted return = \(4 \times 10 = 40\)
    Ordinary IS estimate: \[ V(W) = \frac{2^{1000} \times 10 + 40}{2} \approx \frac{2^{1000} \times 10}{2} \] The estimate is completely dominated by the first episode — and oscillates wildly between runs depending on whether a long episode appears. The variance is effectively infinite. Weighted IS estimate: \[ V(W) = \frac{2^{1000} \times 10 + 40}{2^{1000} + 4} \approx 10 \] The denominator normalizes by the sum of weights. The huge weight \(2^{1000}\) appears in both numerator and denominator, canceling its influence. The estimate is stable and close to 10 — the true value.
    Comparison table: | Property | Ordinary IS | Weighted IS | |----------|-------------|-------------| | Formula | \(\frac{\sum \rho_i G_i}{N}\) | \(\frac{\sum \rho_i G_i}{\sum \rho_i}\) | | Variance | High (unbounded in theory) | Low (stable) | | Bias | Unbiased | Slightly biased initially, bias → 0 asymptotically | | Single-episode behavior | Estimate = \(\rho \cdot G\) (can be extreme) | Estimate = \(G\) (reasonable, since \(\rho\) cancels) | | Numerical stability | Can overflow (\(2^{1000}\) is huge) | Stable (weights normalized) | | Practical use | Rarely used directly | Preferred in practice |
    Pitfalls: 1. Ordinary IS can diverge: As shown in Sutton & Barto Example 5.5, ordinary IS can have infinite variance even in simple MDPs with loops. The estimate may never converge within any practical number of episodes. 2. Weighted IS bias is negligible: The initial bias of weighted IS is usually far outweighed by its variance reduction. For any reasonable number of episodes, weighted IS is the better choice. 3. Both require coverage: Neither method works if \(b\) does not cover \(\pi\). If some action has \(b(a|s) = 0\) but \(\pi(a|s) > 0\), learning is impossible for that \((s,a)\).

    9.7.4 Incremental Average Refresher

    To compute averages efficiently without storing all returns, use incremental updates. Simple (unweighted) average — after \(N\) steps, adding new return \(R\): \[ \text{NewAverage} = \text{OldAverage} + \frac{1}{N}(R - \text{OldAverage}) \] The term \(\frac{1}{N}\) is the step size — each step has equal weight in a true average. Weighted average — with cumulative weight \(C_{\text{new}} = C_{\text{old}} + W_{\text{new}}\): \[ \text{NewAverage} = \text{OldAverage} + \frac{W_{\text{new}}}{C_{\text{new}}}(G_{\text{new}} - \text{OldAverage}) \] This is the same pattern: replace \(1\) with \(W_{\text{new}}\) and \(N\) with \(C_{\text{new}}\) (the cumulative sum of all weights so far). This incremental form is exactly what appears in the off-policy MC control algorithm — the update: \[ Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \frac{W}{C(S_t, A_t)}\big(G - Q(S_t, A_t)\big) \] is a weighted incremental average with weight \(W\) and cumulative sum \(C\).
    Recap: Weighted importance sampling is the practical choice for off-policy MC — it trades a tiny amount of bias for dramatically lower variance and numerical stability. The incremental weighted average form appears in the off-policy algorithm's Q-update. Bridge: With importance sampling and weighted averaging in hand, we can now write the complete off-policy MC control algorithm.

    Real-World & Domain Connection: The ordinary vs. weighted IS trade-off appears throughout statistics. Survey samplers use weighted estimates (Horvitz-Thompson estimator) to avoid results being dominated by a few heavily-weighted respondents. In RL, this same principle keeps off-policy learning stable when the behavior and target policies diverge significantly.

    9.8 The Off-Policy MC Control Algorithm (Weighted Importance Sampling)

    9.8.1 Assumption

    The target policy \(\pi\) is assumed to be deterministic. This means: - For the action chosen by \(\pi\): probability = 1 - For all other actions: probability = 0 So in the importance sampling ratio \(\pi(a|s) / b(a|s)\), the numerator is either 1 (if \(a\) is the action \(\pi\) takes) or 0 (otherwise). This simplifies the algorithm: when \(\pi\) disagrees with the action taken, the importance weight becomes 0, and we can stop processing earlier steps of that episode.

    9.8.2 Symbol Registry — Algorithm Variables

    SymbolMeaningType
    \(Q(s, a)\)Action-value estimate — expected return from \((s,a)\) under \(\pi\)Scalar
    \(C(s, a)\)Cumulative sum of importance weights for \((s, a)\) so farScalar
    \(\pi(s)\)Deterministic target policy — picks \(\arg\max_a Q(s, a)\)Function
    \(b\)Behavior policy (given, fixed, soft)Function
    \(W\)Running importance weight (accumulated right-to-left)Scalar
    \(G\)Running return (accumulated right-to-left)Scalar

    9.8.3 Initialization

  • Initialize \(Q(s, a)\) arbitrarily (random) for all state-action pairs
  • Initialize \(C(s, a) = 0\) for all \((s, a)\) — cumulative sum of weights, starts at 0
  • Set \(\pi(s) = \arg\max_a Q(s, a)\) (ties broken consistently, making it deterministic)

    • Since \(Q\) is initialized randomly, \(\pi\) starts as an essentially random deterministic policy. It improves as \(Q\) is updated.

    Example initialization for state \(S\) with actions {up, down, left, right}: | Action | \(Q(S, a)\) | |--------|-------------| | up | 3 | | down | 4 | | left | 5 | | right | 10 | Then \(\pi(S) = \text{right}\) (deterministic — probability 1 for right, 0 for others).

    9.8.4 The Algorithm

    Purpose: Learn an optimal deterministic policy \(\pi^*\) from episodes generated by a (possibly different) soft behavior policy \(b\), using weighted importance sampling to correct for the distribution mismatch. Inputs: A soft behavior policy \(b\) (any policy with \(b(a|s) > 0\) for all \(a, s\)); discount factor \(\gamma\). Outputs: Optimal deterministic policy \(\pi^*\) and action-value estimates \(Q(s,a)\). 
    
Initialize Q(s,a) arbitrarily for all s, a

Initialize C(s,a) ← 0 for all s, a

π(s) ← argmax_a Q(s,a)    (ties broken consistently)



Repeat forever:

    Generate an episode S₀, A₀, R₁, S₁, A₁, R₂, ..., S_T using b

    G ← 0

    W ← 1

    For t = T-1 down to 0:

        G ← γ·G + R_{t+1}

        C(S_t, A_t) ← C(S_t, A_t) + W

        Q(S_t, A_t) ← Q(S_t, A_t) + (W / C(S_t, A_t)) · (G − Q(S_t, A_t))

        π(S_t) ← argmax_a Q(S_t, a)

        If A_t ≠ π(S_t):

            break    (exit inner loop — go to next episode)

        W ← W × (1 / b(A_t | S_t))
    Pseudocode (Sutton & Barto §5.7):
    Why \(W \leftarrow W \times (1 / b(A_t | S_t))\) and not \(W \leftarrow W \times \pi(A_t|S_t) / b(A_t|S_t)\)? Because \(\pi\) is deterministic, \(\pi(A_t|S_t)\) is either 1 (when \(A_t = \pi(S_t)\)) or 0 (when \(A_t \neq \pi(S_t)\)). The "if \(A_t \neq \pi(S_t)\) then break" handles the 0 case — we stop processing. When we continue, \(\pi(A_t|S_t) = 1\), so multiplying by \(1 / b(A_t|S_t)\) is equivalent to multiplying by \(\pi(A_t|S_t) / b(A_t|S_t) = 1 / b(A_t|S_t)\). The factor of 1 from the numerator is implicit. This is the standard form in Sutton & Barto (Exercise 5.11).

    9.8.5 Understanding the Break Condition

    The break: If the action taken (\(A_t\)) is not the action the current target policy would have taken, stop processing earlier steps of this episode. Why? Because if \(A_t \neq \pi(S_t)\), then \(\pi(A_t | S_t) = 0\) (since \(\pi\) is deterministic). The importance weight for all earlier steps would become 0 (multiplying by 0 for this step), so updates to earlier \((s, a)\) pairs would have zero weight — making them meaningless. This means the algorithm only learns from the tail of each episode where every action taken matches what \(\pi\) would have chosen. If non-greedy actions are common early in episodes, learning for early states is slow — a known limitation of off-policy MC.

    9.8.6 Worked Algorithm Walkthrough — Full Numeric Example

    Setup: - State \(S\) has two actions: Right (\(R\)) and Left (\(L\)) - Behavior policy \(b\): \(b(R|S) = 0.5\), \(b(L|S) = 0.5\) - Target policy \(\pi\): deterministic, say initially \(\pi(S) = R\) - Initial values: \(Q(S,R) = 0\), \(Q(S,L) = 0\), \(C(S,R) = 0\), \(C(S,L) = 0\) - \(\gamma = 1\) (undiscounted) Episode generated by \(b\): \(S \xrightarrow{R, R_1=0} S \xrightarrow{R, R_2=1} S \xrightarrow{R, R_3=2} S \xrightarrow{R, R_4=10} T\) All four actions are Right, so the episode is 4 steps long. Processing from right to left (\(t = 3, 2, 1, 0\)): --- Step t = 3 (last transition: reward 10): \[ \begin{aligned} G &= \gamma \cdot 0 + R_4 = 0 + 10 = \mathbf{10} \\ W &= 1 \\ C(S,R) &= 0 + 1 = \mathbf{1} \\ Q(S,R) &= 0 + \frac{1}{1}(10 - 0) = \mathbf{10} \\ \pi(S) &= R \quad (\text{since } Q(S,R)=10 > Q(S,L)=0) \\ A_3 &= R = \pi(S) \quad \checkmark \text{ (continue)} \\ W &\leftarrow 1 \times \frac{1}{0.5} = \mathbf{2} \end{aligned} \] --- Step t = 2 (reward 2): \[ \begin{aligned} G &= 1 \cdot 10 + R_3 = 10 + 2 = \mathbf{12} \\ W &= 2 \\ C(S,R) &= 1 + 2 = \mathbf{3} \\ Q(S,R) &= 10 + \frac{2}{3}(12 - 10) = 10 + \frac{4}{3} = \mathbf{11.333} \\ \pi(S) &= R \quad (\text{still } Q(S,R) > Q(S,L)) \\ A_2 &= R = \pi(S) \quad \checkmark \\ W &\leftarrow 2 \times \frac{1}{0.5} = \mathbf{4} \end{aligned} \] --- Step t = 1 (reward 1): \[ \begin{aligned} G &= 1 \cdot 12 + R_2 = 12 + 1 = \mathbf{13} \\ W &= 4 \\ C(S,R) &= 3 + 4 = \mathbf{7} \\ Q(S,R) &= 11.333 + \frac{4}{7}(13 - 11.333) = 11.333 + \frac{4}{7}(1.667) \approx 11.333 + 0.952 = \mathbf{12.286} \\ \pi(S) &= R \quad \checkmark \\ W &\leftarrow 4 \times \frac{1}{0.5} = \mathbf{8} \end{aligned} \] --- Step t = 0 (reward 0): \[ \begin{aligned} G &= 1 \cdot 13 + R_1 = 13 + 0 = \mathbf{13} \\ W &= 8 \\ C(S,R) &= 7 + 8 = \mathbf{15} \\ Q(S,R) &= 12.286 + \frac{8}{15}(13 - 12.286) \approx 12.286 + 0.381 = \mathbf{12.667} \\ \pi(S) &= R \quad \checkmark \\ W &\leftarrow 8 \times \frac{1}{0.5} = \mathbf{16} \end{aligned} \] Episode complete. Final \(Q(S,R) \approx 12.667\), \(C(S,R) = 15\).

    9.8.7 Manual Shortcut for One Episode

    For a single episode where every action agrees with the deterministic \(\pi\): 1. Compute the return \(G\) from the start: \(G = 0 + 1 + 2 + 10 = 13\) 2. Compute \(\rho = \prod_t (1 / b(A_t|S_t))\): \(\rho = (1/0.5)^4 = 2^4 = 16\) 3. Importance-weighted return = \(\rho \times G = 16 \times 13 = 208\) Now, if we had a prior \(Q(S,R)\) with cumulative weight \(C_{\text{old}}\) and value \(Q_{\text{old}}\): \[ Q_{\text{new}} = Q_{\text{old}} + \frac{W_{\text{new}}}{C_{\text{old}} + W_{\text{new}}}(G - Q_{\text{old}}) \] For example, if \(Q_{\text{old}} = 10\) with \(C_{\text{old}} = 10\): \[ Q_{\text{new}} = 10 + \frac{16}{10 + 16}(13 - 10) = 10 + \frac{16}{26}(3) = 10 + \frac{48}{26} \approx 10 + 1.846 = \mathbf{11.846} \] This matches the incremental form applied to the entire episode as a single weighted update.
    Pitfalls: 1. Learning only from tails: If early actions frequently disagree with \(\pi\), the algorithm breaks early and learns nothing for early states. This slows learning significantly for states at the start of long episodes. 2. \(C(s,a)\) must accumulate correctly: Forgetting to add \(W\) to \(C\) before the Q-update corrupts the weighted average. 3. \(\pi\) must be updated immediately: After updating \(Q(S_t, A_t)\), \(\pi(S_t)\) must be recomputed before checking the break condition. If \(\pi\) changes, the next iteration's break check uses the new \(\pi\). 4. \(b\) must be soft: If any action has \(b(a|s) = 0\), the algorithm may divide by zero (\(1/b(A_t|S_t)\)) or fail coverage.
    Recap: The off-policy MC control algorithm uses weighted importance sampling to learn a deterministic optimal policy from episodes generated by a soft behavior policy. It processes episodes right-to-left, accumulating G and W, updating Q via weighted incremental average, and breaking when an action disagrees with \(\pi\). Bridge: With MC methods complete (both on-policy and off-policy), we turn to TD learning — which updates after every single step instead of waiting for episode completion.

    Real-World & Domain Connection: Off-policy MC control is the basis for learning from demonstration data. In robotics, a robot watches human demonstrations (behavior policy). Then it improves beyond them using the same algorithmic pattern: Q-update, policy improvement, and break on disagreement.

    9.9 Student Questions and Answers

    Q: Why multiply the return by the importance sampling ratio? What is the intuition? A: (Professor's answer) Think of three entities in the learning environment: the teacher (behavior policy \(b\)), the learner (target policy \(\pi\)), and the exam authority (the environment that gives rewards). The teacher acts a certain way and gets a return. The exam authority awards marks based on outcomes. As the learner, you reason: "The teacher took these actions and earned this return. But I would act differently — taking some actions more often and others less often." So you correct the return by a factor that reflects your different style. - If you would take this action more often than the teacher → multiply by factor \(> 1\) (you deserve more credit for this experience) - If you would take it less often → multiply by factor \(< 1\) (this experience is less relevant to you) That correction factor is the importance sampling ratio \(\rho\).
    Q: How are we learning \(\pi\)? We are only getting sequences from the behavior policy \(b\), not from \(\pi\). A: (Professor's answer) Initially, \(\pi\) is random — it is based on randomly initialized \(Q\) values (\(\pi(s) = \arg\max_a Q(s,a)\)). The behavior policy \(b\) is given and fixed — it generates the episodes. After each episode: 1. You update \(Q(s,a)\) using the importance-weighted returns from \(b\)'s episode 2. You update \(\pi\) to be greedy with respect to the new \(Q\) So \(\pi\) improves with each episode even though all experience comes from \(b\). The key insight: you are estimating values according to \(\pi\), not according to \(b\). The importance sampling ratio corrects for the fact that the experience came from \(b\), not \(\pi\). Over time, \(\pi\) converges to optimal — it surpasses the teacher.

    9.10 Introduction to Temporal Difference (TD) Learning

    9.10.1 What Comes After MC

    Hook: Monte Carlo methods are patient — they wait until the end of an episode to learn anything. But what if episodes are long? What if they never end? TD methods answer: "Don't wait. Learn after every single step."
    TD learning combines two ideas: - From Monte Carlo: learn directly from raw experience without a model of the environment - From Dynamic Programming: bootstrap — use current estimates of later states to update estimates of earlier states, without waiting for the final outcome The key difference from MC: MC methods wait until the end of an episode to compute returns and update values. TD methods update values after every single step — they do not need to wait for the episode to finish.
    Intuition — predicting commute time: Every day you drive home. A Monte Carlo method waits until you arrive, notes the total time (say 35 minutes), and updates its estimate. A TD method updates its prediction at every traffic light. For example: "I predicted 30 minutes. This light took 5 minutes. Now I predict 28 minutes more. My original estimate was off by 3 minutes." The TD method learns continuously, adapting to traffic as it happens.

    The TD(0) update rule (the simplest TD method):

    \[ V(S_t) \leftarrow V(S_t) + \alpha \big[ R_{t+1} + \gamma V(S_{t+1}) - V(S_t) \big] \]

    Breaking this down:

  • \(R_{t+1} + \gamma V(S_{t+1})\) is the TD target — a better estimate of \(V^\pi(S_t)\) based on the immediate reward plus the estimated value of the next state
  • \(R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\) is the TD error \(\delta_t\) — how wrong the current estimate was
  • \(\alpha\) is the step-size parameter
    • Comparison — three ways to estimate \(V^\pi(S_t)\): | Method | Target | Waits for | Bootstraps? | |--------|--------|-----------|-------------| | DP (model-based) | \(\sum_{s',r} p(s',r|s,a)[r + \gamma V(s')]\) | Nothing (one-step lookahead) | Yes | | MC (model-free) | \(G_t\) (full return) | End of episode | No | | TD(0) (model-free) | \(R_{t+1} + \gamma V(S_{t+1})\) | One step | Yes | TD sits between DP and MC: model-free like MC, bootstrapping like DP.

    9.10.2 Preview of TD

    TD methods will be covered in detail in the next class. Understanding MC methods deeply (both on-policy and off-policy) is essential before moving to TD, because:

  • The right-to-left return accumulation pattern in MC reappears in n-step TD
  • Importance sampling extends to off-policy TD methods like Q-learning
  • The GPI framework (evaluate → improve → repeat) is the same for TD control methods (SARSA, Q-learning)
  • The weighted importance sampling technique prepares you for the off-policy corrections in TD
    • Recap: TD methods update after every step using \(R_{t+1} + \gamma V(S_{t+1})\) as a target, combining MC's model-free learning with DP's bootstrapping. They are the foundation of modern RL algorithms like DQN, A2C, and PPO. Bridge: Next lecture will fully develop TD(0), SARSA, Q-learning, and the crucial on-policy vs. off-policy distinction in TD control.

    Real-World & Domain Connection: TD learning is the algorithmic core of DeepMind's DQN (which plays Atari games from pixels), AlphaGo's value networks, and most modern deep RL systems. Every time ChatGPT's RLHF pipeline updates the policy after seeing a single preference comparison, it is using a form of TD learning.

  • Importance-weighted return — multiply raw return \(G\) by \(\rho\)
  • Ordinary vs. weighted importance sampling estimate — know both formulas and when to use each
  • One iteration of the off-policy MC update — the weighted incremental average: \[ Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \frac{W}{C(S_t, A_t)}(G - Q(S_t, A_t)) \]
    • Exam note: The algorithm may be provided in a closed-book exam, but you must understand what each variable means: - \(W\): running importance weight (accumulated right-to-left, multiplied by \(1/b(A_t|S_t)\) at each step) - \(C(s,a)\): cumulative sum of all weights for \((s,a)\) — the denominator of the weighted average - \(G\): running return (accumulated right-to-left as \(\gamma G + R_{t+1}\)) - The break condition: stops processing when \(A_t \neq \pi(S_t)\) because \(\pi\) is deterministic Conceptual clarity matters far more than memorization for this topic.
    Common exam traps: 1. Forgetting that \(\rho\) for a single \((s,a)\) pair is computed from that step onward — not from the episode start 2. Using ordinary IS formula \(\sum \rho_i G_i / N\) when the problem calls for weighted IS 3. Confusing the on-policy and off-policy algorithms — the key difference is the presence of \(W\) and \(C\) in off-policy 4. Not checking the break condition before updating \(W\) — if \(A_t \neq \pi(S_t)\), exit immediately; do NOT update \(W\)

    9.12 Key Takeaways

    1. On-policy MC: One policy \(\pi\) both generates experience and learns from it. Simple but constrained by the exploration-exploitation tension. The self-made learner — no teacher needed, but no teacher to guide either. 2. Off-policy MC: Two policies — behavior \(b\) (teacher, generates experience) and target \(\pi\) (learner, being optimized). Decouples exploration from optimization. Allows incorporating prior knowledge, safety constraints, and learning from existing datasets. 3. Importance sampling ratio \(\rho = \prod_t \frac{\pi(A_t|S_t)}{b(A_t|S_t)}\) corrects for the distribution mismatch. Model dynamics cancel out — only policy probabilities matter. This is why importance sampling works in model-free RL. 4. Weighted importance sampling is preferred over ordinary IS: lower variance, numerically stable. The denominator is \(\sum \rho_i\) (sum of weights), not \(N\) (count of episodes). Trade-off: tiny bias for dramatically lower variance. 5. The off-policy algorithm processes episodes right-to-left, accumulating return \(G\) and weight \(W\), updating \(Q(s,a)\) via weighted incremental averaging, and updating \(\pi\) to be greedy. Breaks when \(A_t \neq \pi(S_t)\) because the importance weight would become 0. 6. TD methods are the next step — they update after every step rather than waiting for episode completion. \(V(S_t) \leftarrow V(S_t) + \alpha[R_{t+1} + \gamma V(S_{t+1}) - V(S_t)]\). Combine MC's model-free nature with DP's bootstrapping.

    9.13 Key Industry Applications

  • LLM Training: RL is used in training pipelines like RLHF (Reinforcement Learning from Human Feedback) and DPO (Direct Preference Optimization). The policy update in RLHF is off-policy: the reward model provides signals, but the LLM's generations come from its own changing policy.
  • Information Retrieval: RAG (Retrieval-Augmented Generation) systems use iterative refinement powered by RL. The retriever and generator are jointly optimized through trial and error — each query-document-relevance triple is a mini episode.
  • Thermal Power Plants: RL controls physical parameters (temperature, pressure, flow rate) using sensor measurements. Off-policy methods allow learning from historical operational data while improving beyond the original control strategy.
  • Medical Domain: Off-policy learning allows incorporating knowledge from all doctors, patients, and researchers. A treatment policy can learn from diverse clinical records (behavior policy) and improve to a more optimal strategy — without running risky exploratory trials.
  • Traffic Systems: Prior experience from existing traffic data serves as the behavior policy. A new signal control policy can learn from this data and improve beyond the current system.
  • Finance: Historical financial data serves as the behavior policy for learning trading strategies. Importance sampling corrects for the fact that the historical trader's style differs from the target strategy.
  • Safety-Critical Systems: Off-policy methods allow embedding safety guardrails — actions with \(b(a|s) = 0\) are never explored. This is essential in autonomous driving, aircraft control, and nuclear plant operation.
  • Game Playing: On-policy MC and TD methods power self-play training (AlphaGo, AlphaZero), where the agent generates and learns from its own experience. Off-policy methods enable learning from human game records — the human is the behavior policy, and the AI improves beyond human-level play.

    On-Policy Monte Carlo Methods

    Must-know: On-policy MC evaluates a policy by averaging complete returns from sampled episodes. The same policy \(\pi\) both generates experience and learns from it. First-visit MC is unbiased and most widely used.

    \[ V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s] \approx \frac{1}{N} \sum_{i=1}^{N} G_i(s) \]

    Top pitfall: Confusing on-policy and off-policy — the presence of importance weights \(W\) and cumulative sum \(C\) signals off-policy; their absence signals on-policy.

    Self-check: Why must the behavior policy in on-policy MC be \(\varepsilon\)-soft, and what would happen if it were purely greedy?

    Connects to: Off-policy MC (Section 9.4), MC algorithm trace (Section 9.8)

    Off-Policy Learning and Importance Sampling

    Must-know: Off-policy learning separates the behavior policy \(b\) (generates experience) from the target policy \(\pi\) (being optimized). The importance sampling ratio \(\rho = \prod_t \frac{\pi(A_t|S_t)}{b(A_t|S_t)}\) corrects for the distribution mismatch — environment model terms cancel out.

    \[ \rho_{t:T-1} = \prod_{k=t}^{T-1} \frac{\pi(A_k \mid S_k)}{b(A_k \mid S_k)} \]

    Top pitfall: Computing \(\rho\) from the episode start instead of from the relevant step onward. Each state-action pair's \(\rho\) is the product of ratios from that step to the end only.

    Self-check: If \(\pi(R|S) = 0.99\), \(b(R|S) = 0.5\), and the trajectory is \(S \to R \to S \to R \to T\) with return 10, what is the importance-weighted return?

    Connects to: Ordinary vs. weighted IS (Section 9.7), Coverage condition (Section 9.5.5)

    Ordinary vs. Weighted Importance Sampling

    Must-know: Weighted importance sampling is preferred in practice — denominator is \(\sum \rho_i\) not \(N\). It yields dramatically lower variance (stable estimates) with negligible initial bias. Ordinary IS can diverge even in simple MDPs.

    \[ V^\pi(s)_{\text{weighted}} = \frac{\sum_{i=1}^{N} \rho_i \cdot G_i}{\sum_{i=1}^{N} \rho_i} \quad\text{vs.}\quad V^\pi(s)_{\text{ordinary}} = \frac{\sum_{i=1}^{N} \rho_i \cdot G_i}{N} \]

    Top pitfall: Using the ordinary IS formula in an exam when the problem requires weighted IS, or forgetting that the weighted denominator is the sum of weights, not the count of episodes.

    Self-check: Two episodes give \(\rho_1=4, G_1=10\) and \(\rho_2=0.02, G_2=1\). Compute both ordinary and weighted IS estimates for \(V(s)\).

    Connects to: Incremental average updates (Section 9.7.4), Off-policy MC algorithm (Section 9.8)

    Off-Policy MC Control Algorithm

    Must-know: The algorithm processes episodes right-to-left, accumulating \(G\) (return) and \(W\) (running importance weight). Updates \(Q(s,a)\) via weighted incremental average: \(Q \leftarrow Q + \frac{W}{C}(G - Q)\). Breaks when \(A_t \neq \pi(S_t)\) because the target policy is deterministic.

    \[ Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \frac{W}{C(S_t, A_t)}\big(G - Q(S_t, A_t)\big) \quad\text{with}\quad W \leftarrow W \times \frac{1}{b(A_t \mid S_t)} \]

    Top pitfall: Forgetting to add \(W\) to \(C\) before updating \(Q\), or updating \(W\) after hitting the break condition (if \(A_t \neq \pi(S_t)\), exit immediately — do not update \(W\)).

    Self-check: In the algorithm, why is \(W\) multiplied by \(1/b(A_t|S_t)\) instead of \(\pi(A_t|S_t)/b(A_t|S_t)\)?

    Connects to: Weighted importance sampling (Section 9.7), Deterministic target policy (Section 9.8.1)

    Temporal Difference (TD) Learning

    Must-know: TD methods update after every single step rather than waiting for episode completion. The TD target is \(R_{t+1} + \gamma V(S_{t+1})\) — bootstrapping from the next state's estimate. Combines MC's model-free learning with DP's bootstrapping.

    \[ V(S_t) \leftarrow V(S_t) + \alpha\big[R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\big] \]

    Top pitfall: Confusing the TD target with the full MC return — TD uses one-step reward plus bootstrapped value, while MC uses the complete episode return.

    Self-check: In what situations would you prefer TD over MC, and vice versa?

    Connects to: On-policy MC recap (Section 9.3), Dynamic programming bootstrapping, n-step TD and SARSA (next lecture)

    Importance Sampling Ratio — Numerical Computation

    Must-know: Given \(\pi(a|s)\) and \(b(a|s)\) for each step in a trajectory, compute \(\rho\) as the product of per-step ratios. For deterministic \(\pi\), the numerator is 1 (agreeing actions) or 0 (disagreeing, causing a break). Exam questions will expect manual computation for 1-2 episode examples.

    \[ \rho = \frac{0.99}{0.5} \cdot \frac{0.99}{0.5} \cdot \frac{1}{1} = 1.98 \times 1.98 = 3.9204 \quad\text{(example: 3-step trajectory)} \]

    Top pitfall: Computing \(\rho\) with per-step ratios that include environment transition probabilities — these cancel out, so only policy probability ratios are needed.

    Self-check: If \(\pi(R|S)=0.7, b(R|S)=0.5\) and the trajectory has 3 steps all taking action R, compute \(\rho\) and the weighted return if raw \(G=12\).

    Connects to: Trajectory probability (Section 9.5.2), Coverage condition (Section 9.5.5)

Video Understanding with CNNs, RNNs and Spatiotemporal Networks

Published: 2026-09-15
Level: postgraduate
Audience: Postgraduate students in Video Analysis

This lecture turns still-image vision into video understanding. It starts with per-frame CNN codes, adds ordered time models and attention, then fuses space and time by pooling, recurrence, segments, and joint 3D kernels. Labs make each path concrete with pre-trained backbones in PyTorch.

7.1 CNN Features from Edges to Meaning

7.1.1 Low-Level Filters and High-Level Meaning

A single photo can tell swimming from jogging before any motion is seen. How does a stack of small filters learn that kind of meaning from raw pixels?

A CNN, a convolutional neural network that slides small weight grids over an image, works to extract features. Each stage applies filters, also called convolutions, which are small grids of weights that react to local patterns. Early stages react to simple structure. A first layer may react to horizontal edges and vertical edges. A next layer may join edges into contours, corners and shapes. As we go deeper and deeper, the network builds more abstract structure. Deep layers respond to object parts and full objects, for instance a wheel, a face, or a swimming pool ladder. At that depth we stop talking about pixels and start talking about meaning. The deep vector is a semantic representation, a numeric summary of what is present in the image rather than where each edge sits. In short, CNN depth builds semantic representation.

The lecture opened with that exact point. CNN depth builds semantic representation. Early maps stay close to pixels. Late vectors stay close to object identity. That shift from pixels to meaning drives the whole video design.

Think of a sieve stack. The top sieve keeps only tiny stones. The middle sieve groups stones into piles. The bottom sieve labels each pile by type. In this analogy, depth builds meaning. Shallow sieves pass texture. Deep sieves pass object labels. The analogy breaks at one point. Real sieves only sort by size. A CNN sorts by learned shape, texture, and part layout. Still, the sieve stack analogy explains why depth builds meaning. Small change in depth gives a large change in meaning. That is why depth matters.

In words, the input image passes through a chain of convolution steps. Each step trades spatial detail for meaning. Early maps stay close to the image. Late maps stay close to the task. One example is telling a birthday scene from a wedding scene. Another is telling swimming from jogging. Both need object and scene cues more than edge cues.

A concrete pass helps. Take an RGB frame of size 224 by 224 with 3 channels. Layer 1 learns about 64 edge filters. Each filter looks at a 7 by 7 patch. Its output marks where that edge sits. Layer 2 pools nearby replies and joins them into textures and corners. The spatial size falls to about 56 by 56. Layer 3 and layer 4 repeat the same pattern. Size falls to 28 by 28, then 14 by 14, then 7 by 7. Channel count grows from 64 to 256 to 512 to 1024 to 2048. By the end, each of the 2048 numbers pools over the whole frame. No number marks a single edge now. Each number marks how strongly some learned part was present.

Picture the change as a curve. The horizontal axis lists layer depth from input to output. The vertical axis lists meaning level from pixels to objects. The curve starts flat near edges and textures. It rises steeply near parts and objects. The landmark sits near the last pooling step. There the curve bends from where to what. The takeaway is direct. Depth moves the code from where edges sit to what objects are present.

A filter response, how strongly a small weight grid matches its patch, written \(r\), might be \(r = 4.2\) on a sharp edge and \(r = 0.1\) on flat sky. A feature map, the full image of such replies, written \(F\), might be \(F \in \mathbb{R}^{56 \times 56 \times 64}\) after an early block. A semantic representation, the late pooled vector that names content, written \(S_t\), might be \(S_t \in \mathbb{R}^{2048}\) for ResNet50. Early \(F\) keeps location. Late \(S_t\) keeps identity.

A short contrast helps. Small spread means darts cluster tightly. Large spread means darts scatter. In the same way, early CNN maps cluster around local texture, while late CNN maps scatter across object meaning. Use this picture when reading histograms later. Tight spread hints at texture focus. Wide spread hints at mixed object cues.

Scope: This depth story holds for photo-style frames with common objects, pets, people, cars, pools, and rooms. It holds when the backbone was trained on a large photo set such as ImageNet.

Assumption: Input has 3 color channels with normal photo range. Filters learned edges and textures that match this input. When input shifts to thermal, depth, or multi-band scans, early filters misfire. Then depth alone does not give meaning. A custom first stage is needed.

Visual check for this idea is simple. Plot mean activation per layer for two frames, one pool and one track. The horizontal axis is layer index. The vertical axis is mean reply. Early layers give close curves for both frames. Late layers split apart. Pool frames push water-part channels high. Track frames push ground-texture channels high. The split point marks where meaning starts.

Do not mix depth with channels. Depth means layer count. Channels such as RGB sit at the input. RGB does not grow with depth. Another trap is reading late vectors as locations. A 2048-number vector has no rows or columns left. It cannot say where the pool ladder sits. It can only say how strongly pool cues fired. A third trap is trusting every channel. Many channels stay near zero on a given frame. Only a subset drives the choice.

Real-world work starts here because reuse is cheap. Traffic cameras and self-driving stacks start from such per-frame CNN vectors. Cars, lanes and people are common objects that ImageNet-style training already covers. A team can pull \(S_t\) per frame and test a simple head before training anything new.

Recap: shallow filters mark edges, deep filters mark object meaning, and the pooled vector carries that meaning forward. Next, that per-frame meaning needs a time model that links frames in order.

7.1.2 Mathematical Formulation

The per-frame spatial feature from CNN backbone is the ground rule for this lecture. In words, the spoken description in class was: for each frame, the spatial feature for that frame is got by applying a CNN to the frame. We keep that verbal form next to the math so the source of the math stays visible.

Let \(I_t\) be frame \(t\), an RGB image with height \(H\) and width \(W\), so \(I_t\) lives in real space of size \(H\) by \(W\) by 3. Let \(\text{CNN}\) be the backbone up to pooling, with no classification head. Then the per-frame spatial feature is:

\[ S_t = \text{CNN}(I_t) \]

Here \(S_t\) is the spatial feature vector or tensor for frame \(t\). The symbol \(t\) is the frame index, from 1 to \(T\). The symbol \(T\) is the total frame count in the clip or video. The symbol \(S\) marks spatial-only content, with no time correlation yet. When the backbone is ResNet50 cut at pooling, \(S_t\) has 2048 numbers. When the backbone is MobileNet cut at pooling, \(S_t\) has 1280 numbers. Both are one-dimensional vectors per frame for the downstream step.

What sits inside \(\text{CNN}\) matters for later shape bugs. A backbone is a chain. Convolution pulls local sums. A nonlinear step such as ReLU keeps positive replies and drops negative ones. Pooling shrinks rows and columns. Normalization steadies the range. Written as stages for one block:

\[ F_{l+1} = \text{Pool}(\text{ReLU}(W_l * F_l + b_l)) \]

Here \(F_l\) is the input map to block \(l\). The symbol \(W_l\) is the filter bank for that block. The symbol \(b_l\) is the bias vector. The symbol \(*\) is convolution, a sliding sum of products. The symbol \(F_{l+1}\) is the output map. After the last block, GAP, global average pooling that averages each last map to one number per channel, turns maps into a vector. That vector is \(S_t\).

Worked check with real shapes. Input \(I_t\) is \(224 \times 224 \times 3\). ResNet50 body ends with maps of size \(7 \times 7 \times 2048\). GAP averages each \(7 \times 7\) sheet to one number. Count the outputs: 2048 sheets give 2048 numbers. So \(S_t \in \mathbb{R}^{2048}\). Swap to MobileNet. Its last sheets number 1280. GAP gives 1280 numbers. So \(S_t \in \mathbb{R}^{1280}\). Sense-check: channel count at the cut sets vector length. No time mixing has happened yet. Each \(S_t\) still belongs to one frame.

A tiny numeric trace shows what convolution does. Take a 3 by 3 patch with values 64, 65, 69 in the top row. Take a filter that keeps the two diagonal corners. Multiply paired slots and add. Kept products 64 plus 69 plus 63 give 196. That 196 is one slot in the reply map. Slide the filter by one step and repeat. The full sweep turns texture into reply strength.

Picture GAP as a final squeeze. The horizontal axis lists channel index from 1 to 2048. The vertical axis lists mean reply. Bars vary in height. Tall bars mark parts present in this frame. Short bars mark parts absent. The takeaway is that location is gone but presence remains.

Scope: This form fits fixed-size RGB frames fed one by one. It fits ResNet50, ResNet101, MobileNet, and EfficientNet cut at GAP. It also fits gray frames copied to 3 channels in the demo path.

Assumption: Frames share the same size and range as training photos. Pre-processing with resize, center crop, and mean-std shift is applied. Without that step, \(S_t\) drifts even when content matches.

Do not feed class scores downstream. Scores have only 1000 numbers tied to old labels. They throw away detail that action heads need. Always cut at GAP. Do not mix \(S_t\) with clip vector \(G\). \(S_t\) is per frame. \(G\) is per clip. Do not read \(t\) as training round. Here \(t\) is frame order.

Real-world teams treat this line as a contract. The vision group delivers \(S_t\) per frame with fixed length. The video group consumes that list. When widths clash, the fault is often a silent backbone swap. ResNet gives 2048. MobileNet gives 1280. Code must state the width.

Recap: \(S_t = \text{CNN}(I_t)\) turns each frame into a fixed meaning vector, with length set by the backbone cut. Next, ordered models link the list \(S_1\) to \(S_T\) over time.

7.1.3 Student Questions and Answers

Several students asked the same core doubt in different words, so we join them into one canonical entry.

Q: CNN applies filters for feature extraction, and early layers give edges. Does it stop there, or does depth add more beyond edges and RGB channels? As we go deeper, what does a CNN learn on the higher end?

A: It goes deeper. Early layers give edges, shapes and contours. Deeper layers give high-level structure tied to object identity. Depth here means network depth, not image channels. Channels such as RGB sit at the input, while meaning builds with layers. So we can call the late output a semantic representation. On the higher end the net learns which object or scene parts are present and how they differ across classes. That late vector supports classification because items from different classes sit apart in that space.

Why did the doubt seem fair? Edges are easy to see in first-layer plots. RGB channels are also easy to name. It is natural to think depth just adds more of the same. The fix is to separate two axes. Input axis holds RGB. Depth axis holds meaning. RGB stays at 3. Meaning grows with blocks. Once that split is clear, the late vector reads as object code, not edge map.

Exam note: Be ready to state what early and late layers code, and why the GAP vector is called semantic. Name the cut point and the vector length for the backbone you used.

7.2 Sequence Models and Attention for Ordered Data

7.2.1 RNN Steps with Two Inputs and Two Outputs

A list of frame vectors looks like a bag of photos. How does a model know that frame 3 comes after frame 2 and builds on it?

An RNN, a recurrent neural network that reuses the same weights at each time step, fits ordered data. Time order is the key, not training rounds. Rounds over the full dataset are called epochs, and epochs are a different idea. An RNN reads step 1, then step 2, then step 3, keeping a trace of what it read. The core claim for this part is simple. RNN reuses weights across time steps. The same cell runs at each \(t\). Only the inputs and the memory change.

At each time \(t\), the cell takes two inputs and makes two outputs. Input one is the current sample \(x_t\), for instance the spatial vector \(S_t\) of frame \(t\). Input two is the prior state \(h_{t-1}\), which is the memory carried from the prior step. Output one is the new state \(h_t\), which passes to the next step. Output two is the step output \(y_t\), which can feed a later task.

Think of a relay runner carrying a note. Each runner reads a new clue plus the note from the last runner. Each runner then rewrites the note and passes it on. Here the clue is \(x_t\). The note is \(h_{t-1}\) turning into \(h_t\). The analogy breaks at one point. Runners get tired. An RNN cell never tires. It applies the same math each time. Still, the relay picture shows why order matters and why memory must pass forward.

In words, the spoken form was: at each timeframe there are two inputs, the time series input and the prior state, and two outputs, the updated state and a task output. The math keeps that shape. The RNN state update with current input and prior state is:

A state vector, the memory carried across steps, written \(h_t\), might be \(h_t \in \mathbb{R}^{512}\) in the demo. An input vector, the fresh sample at this step, written \(x_t\), might be \(x_t \in \mathbb{R}^{2048}\) from ResNet. A step output, the per-step task reply, written \(y_t\), might be a class score or a tag.

Compact cell form:

\[ h_t, y_t = \text{RNN}(x_t, h_{t-1}) \]

Here \(x_t\) is the input vector at time \(t\). The symbol \(h_{t-1}\) is the state vector from time \(t-1\). The symbol \(h_t\) is the updated state at time \(t\). The symbol \(y_t\) is the per-step output at time \(t\). The function \(\text{RNN}\) uses the same weights at each \(t\), which is why we say the same network runs many times along time. One common plain form with matrices is:

\[ h_t = \tanh(W_{xh} x_t + W_{hh} h_{t-1} + b_h) \]

\[ y_t = W_{hy} h_t + b_y \]

Here \(W_{xh}\) maps input to state. The symbol \(W_{hh}\) maps old state to new state. The symbol \(b_h\) is the state bias. The symbol \(W_{hy}\) maps state to output. The symbol \(b_y\) is the output bias. The symbol \(\tanh\) is a squash that keeps values in \([-1, 1]\). Shapes must line up. When \(x_t \in \mathbb{R}^{2048}\) and \(h_t \in \mathbb{R}^{512}\), then \(W_{xh} \in \mathbb{R}^{512 \times 2048}\) and \(W_{hh} \in \mathbb{R}^{512 \times 512}\).

Unroll three steps to see reuse. Start with \(h_0 = 0\). Step 1 reads \(x_1\) and \(h_0\) to make \(h_1\). Step 2 reads \(x_2\) and \(h_1\) to make \(h_2\). Step 3 reads \(x_3\) and \(h_2\) to make \(h_3\). Weights \(W_{xh}\), \(W_{hh}\), \(W_{hy}\) stay fixed. Only \(x\), \(h\), and \(y\) change with \(t\).

Tiny trace with real numbers. Keep size 2 for hand math. Let \(W_{xh} = [[1, 0], [0, 1]]\), \(W_{hh} = [[0.5, 0], [0, 0.5]]\), \(b_h = [0, 0]\). Let \(x_1 = [1, 0]\), \(h_0 = [0, 0]\). Then \(W_{xh}x_1 = [1, 0]\). Add \(W_{hh}h_0 = [0, 0]\). Sum is \([1, 0]\). Apply \(\tanh\): \(h_1 = [0.762, 0]\). Next let \(x_2 = [0, 1]\). Then \(W_{xh}x_2 = [0, 1]\). Add \(W_{hh}h_1 = [0.381, 0]\). Sum is \([0.381, 1]\). Apply \(\tanh\): \(h_2 = [0.364, 0.762]\). Final states are \(h_1 = [0.762, 0]\) and \(h_2 = [0.364, 0.762]\). Sense-check: step 2 still carries a trace of step 1 through the 0.364 term. That carry is the memory.

A CNN treats inputs as separate items with weak links. An RNN treats inputs as linked items with strong links. That split drives the whole video design: CNN for what is in each frame, RNN for how frames link over time.

Picture training as two loops. The horizontal axis is time \(t\) from 1 to \(T\). The vertical axis is state strength. The RNN curve moves forward step by step inside one clip. Epochs form a separate outer loop that repeats whole clips. The landmark is \(t = 1\), where \(h_0\) is zero and the net has no past. The takeaway is that time loop and epoch loop live on different levels.

Scope: This cell fits short ordered lists with fixed vector width, such as 16 frame vectors of 2048 numbers. It fits whole-clip tags and per-frame tags.

Assumption: Steps arrive in true order with no shuffle. State size is fixed. Long gaps need gated cells such as LSTM or GRU, or attention, because plain states fade.

Do not call time steps epochs. Steps index order inside one clip. Epochs count passes over the full set. Do not feed shuffled frames and expect order learning. Shuffle kills the signal the cell is built to use. Do not grow \(h_t\) without need. A 512-number state already holds much clip context.

LSTM and GRU keep the same two-in two-out shape. They add gates that guard the memory. Gates decide what to keep, what to drop, and what to write. That guard helps far links, such as frame 142 leaning on frame 3. Plain RNN links fade fast. Gated cells hold them longer.

Recap: the RNN cell links ordered inputs by passing a learned state forward with shared weights. Next, attention adds a direct lookup that lets a late step pull from any early step.

7.2.2 Attention and Transformers

A late word often points back to an early word. How can a model jump straight back without walking through every step in between?

Attention, a weighting step that gives more weight to relevant parts and less weight to the rest, answers a simple need. Not all words, and not all image parts, matter equally for the current choice. A transformer, a network built around such weighting with encoder blocks, uses that idea to process sequences and images. The core claim here is compact. Attention scores relevant prior words. Each new choice leans on the most telling past items.

Take pronoun choice. In the sentence about students asking a question where we must fill the next pronoun, the word students matters more than the words are or asking for picking the form them. The model should attend to students when it picks them rather than they or he or she. The pronoun students example shows attention relevance in one line. Students drives them. Nearby verbs matter less.

Take image focus. When talk turns to one corner of a screen view, the eye moves to that corner and the rest drops away. That shift of focus is attention in daily form. Take word order. Dog bites man differs from man bites dog. Weights must track that shift. The same scoring helps generation, because each new word leans on the most relevant prior words. The dog and man example shows why order and links matter.

In words, the spoken form was: some parts are more relevant than others, and attention finds which part to stress so processing can go faster. The attention weight from query and key vectors makes that stress exact.

A query vector, what the current position is looking for, written \(q\), might be \(q \in \mathbb{R}^{64}\). A key vector, what each past position offers, written \(k_i\), might be \(k_i \in \mathbb{R}^{64}\) for candidate \(i\). A value vector, what each past position will pass if picked, written \(v_i\), might share the same width.

Raw score form for one query:

\[ a_i = \text{weight}(q, k_i) \]

Here \(q\) is the query vector for the current position, for instance the current word or image patch. The symbol \(k_i\) is the key vector for candidate position \(i\). The symbol \(a_i\) is the scalar attention weight for position \(i\), with weights across \(i\) adding to 1. Large \(a_i\) means position \(i\) drives the current choice.

Scaled dot-product form used in practice:

\[ s_i = \frac{q^\top k_i}{\sqrt{d}} \]

\[ a_i = \frac{\exp(s_i)}{\sum_{j} \exp(s_j)} \]

\[ z = \sum_{i} a_i v_i \]

Here \(d\) is the key width. The symbol \(s_i\) is the raw match score. Division by \(\sqrt{d}\) keeps scores in a safe range. The symbol \(z\) is the weighted mix passed onward. Weights add to 1 by build of the softmax step.

Worked pronoun scores. Query \(q\) asks for the plural subject. Keys: \(k_{\text{students}}\), \(k_{\text{are}}\), \(k_{\text{asking}}\). Raw scores are \(s = [3.0, 0.2, 0.5]\). Exponentiate: \([\exp(3.0), \exp(0.2), \exp(0.5)] = [20.09, 1.22, 1.65]\). Sum is \(22.96\). Divide: weights are \(a = [0.875, 0.053, 0.072]\). Sense-check: students takes about 88 percent of the mass. The model picks them because students dominates the mix.

Picture the weights as bars. The horizontal axis lists past positions. The vertical axis lists weight from 0 to 1. One tall bar marks the key match. Short bars mark the rest. The landmark is the tall bar at students. The takeaway is that the current choice is a weighted vote, not an equal vote.

A common mix-up is that attention only adds context while generation uses a different tool. In practice the same weighting helps both reading and generation, because both need to know which prior items matter now. Reading uses it to link pronoun to noun. Generation uses it to pick the next word from relevant past words.

Scope: This form fits text spans, frame lists, and patch lists where some items matter more than others. It fits inside transformers and on top of RNN states.

Assumption: Queries, keys, and values share a learned space. Scores are comparable across \(i\). Long inputs may need sparse or windowed forms to bound cost.

Do not read weights as proof of cause. High weight means the model leaned on that slot. It does not prove that slot alone caused the label. Do not drop order codes in transformers. Without position marks, dog bites man and man bites dog look the same to pure attention.

Real-world systems lean on this daily. Chat systems and search systems use attention to link a pronoun to its noun, or a question span to its answer span, across long inputs. Caption tools use it to link a word to its image patch.

Recap: attention turns a query into weights over keys, then mixes values by those weights. Next, video work applies the same split: spatial codes per frame, then temporal mixing over the list.

7.2.3 Student Questions and Answers

Q: Is an RNN only for text, and does it just repeat the same net for epochs? Can it handle ordered data versus epochs, and is it text only?

A: No on both points. Any ordered data fits, not only text. Sensor traces, frame features and word lists all fit. The repeat is over time steps, not over epochs. Time \(t = 1, 2, 3\) drives the loop, with state passing forward. Repeat runs over time steps with state passing forward. Epochs sit outside as dataset passes.

Why did the doubt seem fair? Text is the most shown RNN case. Epochs also use the word repeat. It is easy to join the two repeats into one. The fix names two loops. Inner loop walks \(t\). Outer loop walks epochs. Only the inner loop shares the state.

Q: What does attention mean, and is it only one aspect at a time like dog bites man against man bites dog?

A: Attention scores relevance across positions. Word order changes meaning, as in dog bites man against man bites dog, and weights track that shift. The same scoring helps generation, because each new word leans on the most relevant prior words. The dog and man example shows why order and links matter.

7.3 Spatial, Temporal and Joint Spatiotemporal Features

7.3.1 Two-Stage Pipeline and Joint Learning

A single frame shows a person near water. Is that swimming or falling in? Why does one still image fail while a short clip decides at once?

Video brings two questions. What is visible in each frame. When does it move or change. The first question needs spatial features, per-frame vectors about objects, texture and scene. The second question needs temporal features, clip-level vectors about motion, speed and long links across frames. Joint learning gives spatiotemporal features, single vectors that hold space and time together. The bridge line for this section is direct. Spatial vectors feed temporal clip vector. Per-frame codes enter. One clip code leaves.

The plain two-stage path is easy to state. For each frame \(I_t\), get \(S_t\) with a 2D CNN. Then run temporal processing over the list \(S_1\) to \(S_T\) to get a clip vector \(G\). The clip temporal vector from spatial frame list is the core math here.

A clip vector, the summary of a whole frame list, written \(G\), might be \(G \in \mathbb{R}^{512}\) after an LSTM. A joint clip vector, space plus time learned together, written \(C\), might be \(C \in \mathbb{R}^{1048}\) in the class demo.

Two-stage temporal head:

\[ G = \text{Temporal}(S_1, S_2, \dots, S_T) \]

Here \(S_t\) is the spatial vector of frame \(t\) as above. The symbol \(T\) is the frame count. The symbol \(G\) is the temporal or clip vector for the full video. The symbol \(\text{Temporal}\) can be pooling with no learning, an RNN or LSTM with learning, or segment sampling with late fusion. This line says the clip temporal vector comes from the spatial frame list in one call.

Joint single-pass form for short clips:

\[ C = \text{ST-Net}(I_{t}, I_{t+1}, \dots, I_{t+K-1}) \]

Here \(K\) is the clip length in frames, for instance 4, 8 or 10. The symbol \(\text{ST-Net}\) is a 3D CNN or factorized network. The symbol \(C\) is the joint clip vector, for instance a 1048-number vector in the class demo. This line says a run of frames maps straight to one joint code.

Reading chapter by chapter with no links is like per-frame CNN output. Each chapter summary is fine, but the plot links across chapters are lost. An RNN over chapter summaries restores the plot. That is the same gap between \(S_t\) and \(G\). The chapter novel analogy shows missing plot links in one image. Chapters are \(S_t\). Plot is \(G\). Without the second step, the story never joins.

Joint paths learn space and time together for cases where split steps miss the link. Fast traffic is a good trigger. A car may enter once and leave for good. Its shape and its path must be read together. A 3D network over short clips does that in one pass and returns one vector \(C\) per clip.

When to pick which path matters. Use the two-stage path when objects alone almost decide, when data are few, or when speed matters. Use the joint path when shape and path must join, such as entry, exit, fast cross, or fine speed split. Task need sets the pick.

Picture the two paths side by side. The horizontal axis is time. The vertical axis is processing depth. The two-stage path shows \(T\) separate CNN towers feeding one temporal bar. The joint path shows one wide 3D block covering \(K\) frames at once. The landmark is the join point. Two-stage joins late at \(G\). Joint joins early inside \(C\). The takeaway is that join timing sets what links can be learned.

Scope: Two-stage fits variable-length clips with standard RGB frames and a fixed backbone width. Joint fits short fixed windows such as 8 or 16 frames.

Assumption: Sample frames keep true order. Backbone width stays fixed across frames. Joint nets see enough motion samples to learn time kernels without overfit.

Do not feed raw pixels to the RNN. Always feed \(S_t\). Raw frames are too large and too noisy for a small state. Do not shuffle before the temporal step. Shuffle turns ordered motion into a bag and breaks speed cues. Do not expect pooling to learn order. Pooling has no weights for order.

Real-world splits follow this logic. Sports tagging uses joint motion cues to split jogging from running. Pool safety uses spatial cues to spot water first. One task needs time. The other needs place.

Recap: \(S_t\) codes what is present, \(G\) codes how frames link, and \(C\) codes both in one pass for short windows. Next, backbones show how to get strong \(S_t\) without training from scratch.

7.3.2 Worked Examples

Example 1: swimming against jogging split by spatial water context. Frames show blue water, pool lanes, splash texture. Park or track points less firmly. The per-frame spatial vector already splits the classes well. A simple mean over \(S_t\) keeps water cues. Call is swimming by spatial water context with high margin. Sense-check: when water fills half the frame, space alone decides. Temporal detail helps less here. Simple action pairs of this kind fit fast pooling baselines.

Example 2: jogging against running split by speed stride cadence. Space looks alike. Both show a person upright in a park or on a track. Speed and stride split them. Arm swing rate, leg cadence and body bounce differ. Only ordered time data shows that split. Suppose cadence is 140 steps per minute for jogging and 180 for running. Stride is 1.1 m against 1.6 m. Speed is about 2.6 m per s against 4.8 m per s. A pooled \(G\) loses order and may still confuse them. An LSTM \(G\) keeps cadence and splits them. Call needs temporal speed stride cadence cues. Sense-check: faster cadence plus longer stride must give faster speed. This is level four or five among tricky action tasks discussed in class.

Plain prose joins the next two cases without a box so boxes stay spaced. Example 3 is birthday against wedding. Both show cakes and crowds. Surrounding acts differ. Song, dance, dress and rite order differ. Context plus act order must join to decide. Space narrows the field. Time order closes the call.

Example 4 is autonomous driving with entry and exit. A car enters at frame 20 and leaves by frame 60. A lone per-frame tag says car present. Only a joint trace says entered from the left, crossed, and left. That is why joint clip vectors matter when objects move in and out. A list of present tags cannot code path. A joint \(C\) can.

Exam note: Be ready to name which cue decides each pair: water context for swimming, cadence and speed for running, act order for rites, path trace for entry and exit.

7.3.3 Student Questions and Answers

Q: Will per-frame CNN features already sit at object or region level, or do they stay at low edge level?

A: Depth sets the level. Early maps stay at edges. Late pooled vectors sit at region and object level. The cut point, often the pooling output, sets which level feeds the next step. So \(S_t\) is already past edges when cut at GAP.

Many students then asked where sampling sits. We keep that as the canonical sampling entry.

Q: Should sampling happen before the backbone, and does the RNN then see only sampled frames? Does sampling come before backbone and does RNN see sampled order?

A: Yes. Pre-processing picks sample frames first. The loop then runs for each sample frame, not each raw frame. Sample frames feed backbone then sampled order feeds RNN. The RNN sees that sampled order. So the code line reads for each sample frame in spirit, even when shorthand says for each frame.

7.4 Transfer Learning Backbones for Spatial Features

7.4.1 Removing the Head and Reading the GAP Vector

Training a deep CNN from scratch on small video data often fails. How can a team get strong frame codes in an afternoon with no large train run?

Transfer learning, reuse of a network trained on a large image set, then adapted to video frames, gives a fast start. Common backbones are ResNet 50, ResNet 101, EfficientNet, MobileNet and ViT, where ViT means Visual Transformer. Common source sets are ImageNet and Kinetics. The backbone already knows generic shapes, textures and objects. Purpose is direct. Borrow generic vision, then spend learning budget on the video head.

A ResNet ends with convolution blocks, then pooling, then a classification head. For feature duty we drop the head and stop at GAP, global average pooling, which averages each last map to one number per channel. That GAP vector feeds the video task. It is a tensor in general, and a flat vector in the demo setup. The mantra for this step is short. Backbone stop at GAP features. No scores leave the backbone. Only features leave.

Inputs and outputs for this stage are fixed. Input is a pre-processed frame, often 224 by 224 by 3, normalized with ImageNet mean and std. Output is one vector per frame. Width is set by backbone choice. No time mixing happens here.

The ResNet50 GAP vector with 2048 numbers per frame is the reference shape for this lecture. In words, the spoken form was: remove the classification layers, stop at GAP, pull the features and use them downstream.

\[ S_t \in \mathbb{R}^{2048} \]

Here \(\mathbb{R}^{2048}\) means a real vector with 2048 numbers. With MobileNet cut at GAP, each frame gives a 1280-number vector. The count is fixed by the backbone choice and stays the same for each frame. The backbone cut at GAP feeds downstream steps rather than class scores. Scores belong to old labels. Features belong to the new video task.

Steps in code order are concrete. Load ResNet50 with pre-trained weights on. Replace the final fully connected head with an identity pass. Set the net to eval mode for pure feature duty, or train mode for fine-tune later. Resize each frame, take a center crop, turn it into a tensor, shift to RGB when needed, and normalize. Send each frame through to GAP. Store the vector. That stored list feeds pooling, LSTM, or TSN.

The input can be three-channel RGB or single-channel gray in the demo talk, and the backbone path stays the same: convolution blocks, then GAP, then stop. No class scores leave the backbone at this point. Gray frames are copied to three channels so old filters still fit.

Picture the cut as a diagram. Boxes run from left to right: conv blocks, last maps of \(7 \times 7 \times 2048\), GAP squeeze, then a crossed-out head. The horizontal axis is depth. The vertical axis is map size. Size falls while width grows. The landmark is the GAP bar with 2048 outputs. The takeaway is to stop there and never pass the crossed-out head.

Scope: This cut fits photo-style video where objects overlap with ImageNet and Kinetics content, such as people, cars, roads, pools, and rooms.

Assumption: Pre-processing matches training stats. Frame size, crop, channel order, and normalization match. Backbone weights stay frozen for pure baseline runs.

Do not pull logits for video heads. Logits collapse 2048 cues into 1000 old scores. Detail is lost. Do not mix widths in one list. ResNet gives 2048. MobileNet gives 1280. One list must hold one width. Do not leave the net in train mode with frozen batch stats by mistake. Eval mode gives stable baseline vectors.

Real-world teams follow this path first. Surveillance video, traffic video and self-driving baselines reuse ImageNet training because everyday objects transfer well. A baseline is live in hours. Custom training can wait until the baseline shows a real gap.

Recap: drop the head, stop at GAP, and bank one fixed-width vector per frame. Next, fine-tuning shows how much of the backbone to unlock when the baseline is not enough.

7.4.2 Fine-Tuning Mechanics and Depth Trade-off

Fine-tuning, short extra training of the new head, and at times the top backbone layers, on video frames, links the frozen backbone to the new task. Early backbone layers stay frozen with ImageNet weights. The GAP output feeds a fresh video head. Only that head, or head plus a few top layers, learns from video data.

The depth trade-off is direct. Pulling from the last layer means less new training. Pulling from an earlier layer means the network is shallower and more task-specific, so more training is needed. The spoken rule was: making the net shallower and shallower means doing more and more training. That is the catch to weigh. Early cuts lose generic depth. New layers must relearn what was cut.

A practical ladder helps. Level 0 freezes all backbone weights and trains only the video head. This fits tiny sets. Level 1 unlocks the last block plus head with a small step size. This fits medium sets with mild shift. Level 2 trains more blocks end to end with care and more data. This fits large shift but risks overfit on small sets. Cost and risk rise with each level.

Backbone choice also follows device limits. MobileNet fits edge devices with tight power and memory. ResNet50 gives richer vectors at higher cost. Teams often start with a backbone baseline to check direction, then switch to a custom net for product rules. PyTorch hosts both paths with 3D ops and pre-trained weights for fast tests.

Complexity is easy to state. Frozen baseline costs one forward pass per frame with no backward pass. Fine-tune adds backward passes for unlocked layers. Memory grows with unlocked depth and batch size. When data are few, frozen wins on stability. When shift is large, fine-tune wins if data cover the shift.

Scope: Fine-tune fits medium video sets where the baseline underfits the new scene but objects still share shape with photos.

Assumption: Head and unlocked layers see held-out clips for early stop. Step size for unlocked backbone layers stays well below head step size.

Picture the trade as two curves over unlocked depth. The horizontal axis is unlocked blocks from zero to full. The vertical axis is held-out score. Training score rises with depth. Held-out score rises, then flattens, then falls when overfit starts. The landmark is the peak of the held-out curve. The takeaway is to stop unlocking at that peak, not at max depth.

Do not unlock all layers on a tiny set. Training scores will climb while held-out scores stall. That split marks overfit. Do not use one large step size for backbone and head. Large steps wreck borrowed filters. Do not judge a backbone by one frame mean. Later action scores decide.

Real-world picks mirror cost. Edge kits in vehicles pick MobileNet-style backbones to run on device, while server baselines pick ResNet-style backbones for richer vectors. Both start frozen. Only the lagging case moves up the unlock ladder.

Exam note: Expect a short question on where to cut a backbone and why GAP output feeds downstream steps rather than class scores. State the cut, the width, and the frozen-versus-unlocked choice.

7.5 Custom CNNs and Input Domains

7.5.1 When Transfer Fails

Borrowed vision wins on photos. What happens when frames look nothing like photos, with odd bands and strange noise?

Three checks decide when to leave transfer learning and build a custom CNN. Custom nets fit thermal satellite scans and other odd inputs where borrowed filters misfire. That line is the gate for this section.

First, domain gap. Medical scans, satellite views and thermal frames look little like ImageNet photos. Thermal formation differs. Satellite depth runs deeper than RGB. Transfer then adds little. A PET scan is a clear case. Its pixels code uptake, not light. Edges learned on cats and cars do not parse uptake blobs.

Second, input structure. RGB or HSV with three channels fits standard backbones. Ultrasonic frames, thermal frames, or multi-band satellite stacks do not. Channel count, value range and noise differ. Special handling of the first layers is needed. A 12-band stack cannot enter a 3-channel first filter without surgery. Value range may span thousands, not 0 to 255. Noise may be speckled and bursty.

Third, organization rules. Product, privacy or license rules may bar outside weights. Proprietary data may need a fully owned net. Accuracy may drop relative to large-scale training, but control and compliance can matter more. Hospitals and defense shops often face this bar. Ownership beats a small score gap.

Think of it like shoes. Rental shoes work for a casual game. A final match on a strange surface needs fitted shoes. Strange pixels need fitted nets. The rental shoes analogy explains the switch. Rental is transfer. Fitted is custom. Strange surface is thermal, depth, or multi-band input. The analogy breaks at one point. Shoes only change fit. Nets change both fit and learned cues. Still, the rental shoes analogy keeps the choice rule clear. Odd surface means fitted build.

A quick table makes the pick fast.

Check Pass transfer Fail to custom
Look Photo-like RGB Thermal, scan, satellite
Channels 3 channels 1, 12, or odd bands
Rules Open weights allowed Owned weights required

End with a one-line rule. When to pick which: stay with transfer when look, channels, and rules all pass; else build custom.

Picture the gap as two histograms. The horizontal axis is pixel value. The vertical axis is count. Photo RGB clusters in mid range with smooth shape. Thermal clusters near extremes with spiky shape. The landmark is the mismatch in peaks. The takeaway is that the first filter sees a new world and needs retrain or rebuild.

Scope: This gate fits teams choosing between frozen backbones and fresh builds for non-photo video.

Assumption: A transfer baseline was already tried. Gap is measured on held-out clips, not on one frame mean. Rules review is done with owners, not guessed.

Do not judge domain by one frame. One thermal frame always looks odd. Score gap on tasks decides. Do not force 12 bands into 3 channels by blind squash. Band meaning is lost. Build a first layer with true width. Do not chase custom for fashion. Custom costs data, time, and tuning.

Real-world cases cluster here. Hospital imaging and satellite mapping often train custom first layers or full custom nets because band count and sensor noise differ from phone photos. Traffic and retail stay with transfer because their frames stay photo-like.

Recap: domain gap, input structure, and organization rules gate the custom call, with odd bands and strict ownership forcing fitted nets. Next, a small-to-large build loop keeps custom cost in check.

7.5.2 Building Small and Scaling Up

Start small and scale up. Begin with about five layers, with residual links and batch normalization, where a residual link adds the input back to the block output and batch normalization steadies layer inputs. Check scores and parameter counts. Then grow or reshape.

Transfer runs help pick the block style. Compare plain convolution stacks, residual blocks and inception blocks as baselines. Keep the winning pattern as a guide. Then build a custom net that mimics the idea without copying weights. Train end to end on video frames. This keeps design lessons while dropping mismatched weights.

7.6 Temporal Aggregation Paths

7.6.1 Temporal Pooling Variants

Sixteen frame vectors sit in a list. The classifier wants one vector. What is the fastest way to fuse them when order barely matters?

Temporal pooling, collapsing \(S_1\) to \(S_T\) into one vector \(G\) with a fixed rule and no learned weights, is the fastest path. Order is lost. Any shuffle of the same frames gives the same \(G\). Use it when order matters little, clips are short, data are few, or inference must be fast. Scene tagging and coarse action splits fit here. The pattern for this section is compact. Pooling LSTM fuse frame vectors. Pooling is the first of those three fuses. It is instant and needs no training.

Average pooling gives each frame equal say. The average pooling mean over frame features is the base rule. In words, the spoken form was: take the mean over all frame features.

A pooled clip vector, one vector from a frame list with no learned weights, written \(G_{\text{avg}}\), might be \(G_{\text{avg}} \in \mathbb{R}^{2048}\) when frames are 2048 wide.

\[ G_{\text{avg}} = \frac{1}{T}\sum_{t=1}^{T} S_t \]

Here \(T\) is the frame count. The symbol \(S_t\) is the spatial vector of frame \(t\). The symbol \(G_{\text{avg}}\) is the mean clip vector. Division by \(T\) is the extra step beyond a sum. This is the average pooling mean over frame features in full form.

Max pooling keeps the strongest reply per slot. In words, the spoken form was: take the element-wise max across frames with no sum. For slot \(j\):

\[ G_{\text{max}, j} = \max_{t} S_{t, j} \]

Here \(S_{t,j}\) is slot \(j\) of frame \(t\). The symbol \(G_{\text{max}, j}\) is slot \(j\) of the pooled vector. This keeps peak moments, for instance a jump into a pool or a sharp turn, but drops order.

Weighted pooling scores frame value first. In words, the spoken form was: give each frame a weight like attention, keep weights adding to 1, then take a weighted mean.

\[ G_{\text{w}} = \sum_{t=1}^{T} w_t S_t, \quad \sum_{t=1}^{T} w_t = 1 \]

Here \(w_t\) is the scalar weight of frame \(t\). Informative frames get larger \(w_t\). The weight sum rule keeps scale steady.

Concrete number first. Take \(T = 16\) demo frames with 2048 numbers each. Mean pooling sat near 0.42. Max pooling sat near 0.8. Spread across slots stayed under 0.2. Those three numbers show how the same list can read smooth or peaky based on rule. Mean smooths bursts. Max keeps bursts. Spread tells which view is stable.

Picture the three rules on one plot. The horizontal axis is frame order. The vertical axis is one slot value. Dots mark per-frame values. A flat line marks the mean near 0.42. A top tick marks the max near 0.8. A tilted mix marks the weighted mean. The landmark is the burst frame that lifts max but barely moves mean. The takeaway is to pick mean for stable scenes and max for peak events.

Scope: Pooling fits very short clips, tiny sets, and fast runs with no time learning. It fits scene tags and coarse splits like water against track.

Assumption: Frames share one width. Order carries little label signal. Burst strength, not burst timing, decides the tag.

Do not use pooling when order decides the label. Jogging against running fails here. Do not compare mean and max raw values across backbones. Scales differ. Do not forget the divide by \(T\). A sum without divide grows with clip length and breaks thresholds.

Real-world use is common. Live scene tags and quick baselines run mean pooling first because it is one line and needs no train step. Peak detectors add max pooling for jumps and turns.

Recap: mean smooths, max keeps peaks, weighted favors key frames, and all three drop order. Next, recurrent pipelines keep order when the task needs it.

7.6.2 CNN LSTM Pipelines

Pooling forgot whether the car moved left to right or right to left. How can the fuse step remember direction and speed?

A CNN LSTM pipeline, CNN for space plus LSTM or GRU for time, both learned, keeps order. Each sample frame gives \(S_t\). The sequence feeds a recurrent net. Hidden states track events. The last hidden state, or a set of per-frame states, becomes \(G\). This is the second fuse in pooling LSTM fuse frame vectors. LSTM is the learned fuse that keeps order.

In words, the spoken form was: send each sample frame to a CNN for \(S_t\), feed the list to an LSTM, and read the key hidden state as time content. The state update has the same two-in two-out shape as in 7.2, now with 2048-number inputs from ResNet in the demo.

A hidden state, the learned running summary at step \(t\), written \(h_t\), might be \(h_t \in \mathbb{R}^{512}\) with two stacked layers. A clip code from recurrence, the final summary, written \(G\), might be \(G = h_T\) for whole-clip tags.

Pipeline in steps. Encode frames to \(S_1\) to \(S_T\). Feed in order to LSTM or GRU. Collect \(h_1\) to \(h_T\). Read \(h_T\) for whole-clip tag or all \(h_t\) for per-frame tags. Shapes in the demo: input size 2048 from ResNet, hidden size 512, two stacked layers, sequence length 16. GRU twin uses the same sizes for fair compare.

Two output modes matter. Many-to-one reads the last hidden state \(h_T\) for whole-clip tags, for instance tagging a five-second clip as swimming. Many-to-many reads per-frame states \(h_1\) to \(h_T\) for per-frame tags, for instance marking each frame with its act. Stacking adds depth: layer one feeds layer two. Deeper stacks track longer links but need more data and care.

Demo settings were concrete. Input size 2048 from ResNet. Hidden size 512. Two stacked layers. GRU twin with the same sizes for comparison. In that short clip, LSTM traces looked more compact while GRU traces spread wider in the plots. That spread gap is a hint, not proof. Later scores decide which cell wins on the task.

Cost and limits are plain. Forward cost grows with \(T\) times hidden size squared. Memory holds states per step for training. Long videos strain both. That strain motivates segment nets next.

Scope: This pipeline fits short to medium clips where order and links must be learned, such as cadence splits and act order.

Assumption: Sample order is true order. Width 2048 matches ResNet. Hidden size and layer count are fixed before compare runs.

Picture hidden traces over time. The horizontal axis is frame index. The vertical axis is mean hidden value. LSTM draws a tight rising band. GRU draws a wider band on the same clip. The landmark is the split near the scene jump. The takeaway is that both react to change, but spread differs by cell.

Do not swap backbones without fixing input size. EfficientNet width breaks a 2048-wide LSTM. Prompts to coding tools must state the backbone width, or shapes will clash. Do not train deep stacks on tiny sets. They memorize. Do not read last state for per-frame tasks. Use all states instead.

Recap: CNN codes space, LSTM or GRU fuses frame vectors in order, and last state serves clip tags while all states serve frame tags. Next, segment nets scale the same idea to long videos.

7.6.3 Temporal Segment Networks

A five-minute match holds 9000 frames. How can a model see start, middle, and end without paying for 9000 CNN passes?

A temporal segment network, called TSN, a sparse sampling design that splits a long video into equal time parts and keeps few frames, cuts cost on long videos. A five-minute video at 30 frames per second holds about 9000 frames. Running a CNN on all 9000 is heavy. TSN splits first, samples little, then fuses late. No special pre-pass is needed because sampling lives inside the method. This is the third fuse in pooling LSTM fuse frame vectors. TSN fuses sparse segment views.

Steps in order. Split the full length into \(K\) equal-duration parts. Pick one frame per part, often the middle frame. Run the CNN on those \(K\) frames to get \(K\) spatial vectors. Fuse with a consensus rule such as mean or max to get \(G\).

A segment count, how many time parts the video is split into, written \(K\), might be \(K = 3\) in the demo. A segment vector, the spatial code of the sampled frame in part \(k\), written \(S_{(k)}\), might be \(S_{(k)} \in \mathbb{R}^{2048}\).

Consensus mean form:

\[ G_{\text{TSN}} = \frac{1}{K}\sum_{k=1}^{K} S_{(k)} \]

Here \(K\) is the segment count. The symbol \(S_{(k)}\) is the sampled vector from part \(k\). The symbol \(G_{\text{TSN}}\) is the fused clip vector. With \(K = 3\) on 9000 frames, each part holds 3000 frames, and only 3 frames reach the CNN. With 4 parts on a five-minute video, each part spans 1.25 minutes.

In words, the spoken form was: divide by time, sample one frame per segment, run the CNN, then average or max the \(K\) vectors. Within-part links can be added by sampling 3 or 5 frames per part and fusing inside the part first. Across-part fusion then joins part vectors into \(G\). Late fusion is the name for that last join.

Cost win is large. Dense pass pays 9000 CNN forwards. TSN with \(K = 3\) pays 3 forwards. Coverage still spans start, middle, and end. That is why TSN is the default pick named in class for long videos, pooling for tiny fast tasks, and LSTM when time order must be learned.

Picture coverage as a timeline. The horizontal axis is time from 0 to 5 minutes. Ticks mark 9000 frames. Three dots mark sampled middles near 1500, 4500, and 7500. Brackets show 3000-frame parts. The landmark is how one dot per bracket still spans the full game. The takeaway is sparse but full-span coverage at tiny cost.

Scope: TSN fits long videos where dense CNN passes cost too much and coarse order across parts is enough.

Assumption: One middle frame stands for its part. Parts have equal duration. Consensus mean or max suits the label.

Do not use TSN when fine order inside a part decides the label. Dense or recurrent views inside parts are then needed. Do not sample only the first frame per part. Starts bias the view. Middles are the neutral default. Do not set \(K\) too low on varied games. Start, middle, and end must all appear.

Real-world use is direct. Long match footage and day-long store footage use segment sampling to keep compute in bounds while still seeing start, middle and end. Highlights and counts come from few passes.

Exam note: TSN is the default pick named in class for long videos, pooling for tiny fast tasks, and LSTM when time order must be learned. Be ready to compute part size as total divided by \(K\) and to name middle sampling.

The cosine similarity between backbone feature vectors is the match rule. In words, it asks how much two vectors point the same way, ignoring length.

A cosine match, the angle score between two codes, written \(\text{sim}(a, b)\), lies in \([-1, 1]\) with 1 for same direction.

Here \(a\) and \(b\) are two feature vectors from two backbones on the same frame. The symbol \(a^\top b\) is the dot sum over slots. The symbol \(\|a\|_2\) is the length, or Euclidean norm, of \(a\). The result lies in \([-1, 1]\). High values mean the two nets stress similar structure on that frame. This is the cosine similarity between backbone feature vectors in compact form.

7.7.2 Temporal Pooling LSTM GRU and TSN Code

The temporal lab keeps ResNet50 as the only backbone to hold input size fixed. Pre-processing matches the spatial lab. The last layer is dropped. Raw 2048-number spatial vectors feed all later steps, with no mean reduction up front. Fixed width is the contract that lets pooling, LSTM, GRU, and TSN compare fairly.

Purpose per branch is distinct. Pooling branch gives instant baselines. LSTM and GRU branches learn order. TSN branch spans long range at low cost.

Inputs and outputs for the race. Input list is \(S_1\) to \(S_T\) with each \(S_t \in \mathbb{R}^{2048}\). Pooling output is one \(G\) with no weights. LSTM output is hidden states with hidden size 512 and two layers. GRU output mirrors it. TSN output is a mean over \(K = 3\) segment vectors.

Pooling branch computes mean, max, first, last and standard deviation over the frame list. LSTM branch turns the list into a tensor of shape sequence by feature, here 16 by 2048 in the demo, and runs a two-layer LSTM with hidden size 512. GRU branch mirrors it with the same input size, hidden size and layer count. Hidden vectors leave as time features. TSN branch sets segment count to 3, splits total frames by 3, finds start and end per part, picks the middle index, runs ResNet on those middle frames, stacks 3 vectors, and fuses with a mean to get the TSN vector.

Steps for TSN in code read like the math. Total frames \(N\) split by 3. Part size is \(N / 3\). For part \(k\), start is \(k\) times part size, end is start plus part size, middle is start plus half part size. Run ResNet on middles. Stack 3 vectors. Take the mean. That mean is the TSN clip code.

The mapping warning is key. Input size 2048 matches ResNet. Swap in EfficientNet and the same code breaks. Prompts to coding tools must state the backbone width, or shapes will clash. A one-line prompt fix saves hours. State backbone, width, hidden size, layers, and \(K\) in every ask.

Complexity contrast is stark. Pooling costs one pass over stored vectors. LSTM pays sequence steps with gate math. TSN pays only \(K\) CNN passes plus a mean. When \(N = 9000\) and \(K = 3\), TSN skips 8997 CNN passes.

Scope: This lab race fits short demo clips with 16 stored vectors plus a long-clip TSN demo with 3 segments.

Assumption: All branches read the same \(S_t\) list. Hidden size 512 and \(K = 3\) stay fixed across runs. PyTorch shapes use sequence by feature order as coded.

Do not change backbone mid-race. Width shift voids the compare. Do not feed normalized means into LSTM when raw vectors were promised. Scale shift changes gates. Do not read TSN dots as dense order. Dots sample order sparsely.

\[ C_{ij} = \frac{S_i^\top S_j}{\|S_i\|_2 \|S_j\|_2} \]

7.8 Joint Spatiotemporal Learning with 3D Kernels

7.8.1 Clips and Single Feature Vectors

Late fusion joins space and time at the end. What if shape and path must join from the start, like a car crossing fast?

Long videos become clips. Pick a window size \(K\) in frames. Slice frame 0 to 3 as clip one when \(K = 4\). Slice 4 to 7 as clip two. Continue to the end. Each clip feeds a joint net once and returns one vector \(C\). The full video then becomes a short list of clip vectors, not thousands of frame vectors. The rule for this part is short. Clips feed joint 3D kernels. Windows enter. Joint codes leave.

In words, the spoken form was: work with a run of frames, not lone frames, and learn space plus time in one pass. For a five-minute video at 30 frames per second, 9000 frames with \(K = 10\) gives 900 clip vectors. With \(K = 8\), the default in code, each clip spans 8 frames from its start. Smaller \(K\) tracks fast change. Larger \(K\) sees longer acts at higher cost.

A clip, a short run of \(K\) frames, written \(X\), might be \(X \in \mathbb{R}^{3 \times 8 \times 112 \times 112}\) for 8 RGB frames of 112 by 112. A joint clip vector, space plus time in one code, written \(C\), might be \(C \in \mathbb{R}^{1048}\) in the demo.

\[ C = \text{ST-Net}(I_{t}, I_{t+1}, \dots, I_{t+K-1}) \]

Here \(K\) is the window length. The symbol \(\text{ST-Net}\) is a 3D or factorized net. The symbol \(C\) is the joint code per clip. Clips feed joint 3D kernels in this call.

Two joint nets were shown. C3D uses full 3D kernels. R2 plus 1D, also called factorized 3D, splits each 3D step into a 2D space step plus a 1D time step. Both return a pooled clip vector \(C\), for instance a 1048-number vector in the demo, that jointly codes the clip.

Picture windows on a timeline. The horizontal axis is frame index from 0 to 9000. Brackets mark clips of length \(K\). Each bracket maps to one dot \(C\). The landmark is how 9000 frames shrink to 900 dots when \(K = 10\). The takeaway is a short list of rich codes that later heads can rank and match.

Scope: Joint windows fit short fixed clips with steady rate and size, such as 8 or 16 frames at 112 by 112.

Assumption: Clips keep true order with no shuffle. Rate and crop stay fixed so kernels see stable motion steps.

Do not set \(K\) blind. Tiny \(K\) misses slow acts. Huge \(K\) blurs fast acts and blows cost. Do not mix clip lengths in one batch without padding. Shapes must match for 3D ops.

Real-world search runs this way. Video search and highlight tools run such clip nets over windows to get compact clip vectors for match and rank. Each \(C\) becomes a retrievable item.

Recap: slicing turns long video into clips, and one joint pass turns each clip into \(C\). Next, code structure shows how C3D and factorized nets differ.

7.8.2 C3D and Factorized R2 Plus 1D Code

The code uses PyTorch with 3D ops throughout. The C3D path stacks three blocks of 3D convolution plus ReLU plus 3D max pooling, then 3D adaptive average pooling with no classifier. Kernel size reads as three numbers, for instance 3 by 3 by 3, where the three slots cover time, height and width. Padding also has three slots. ReLU follows each convolution.

A 3D kernel, weights spanning time plus rows plus columns, written \(W\), might be \(W \in \mathbb{R}^{3 \times 3 \times 3}\) per channel. A factorized pair, space kernel plus time kernel, written \(W_s\) then \(W_t\), might be \(1 \times 3 \times 3\) plus \(3 \times 1 \times 1\).

C3D block in order: 3D conv, ReLU, 3D max pool. Repeat three times. End with 3D adaptive average pool to one \(C\). R2 plus 1D block in order: space conv with time width 1, ReLU, time conv with space width 1, ReLU, pool. Repeat. End with adaptive pool to one \(C\).

The R2 plus 1D path splits the work. First a 2D-style convolution over height and width with time width 1, for instance a 1 by 3 by 3 kernel, pulls spatial structure. Then a 1D-style convolution over time pulls order. Max pooling follows. The pair repeats. Adaptive pooling ends the stack. ReLU follows each convolution. The split keeps space-plus-time power while trimming weights. Fewer weights need less data and run faster.

Tensor order needs care. Frames stack into a five-dimensional tensor with batch, channels, time, height and width. The spoken form flagged the flip: code first holds channels, time, height and width in one order, then moves axes to match what the 3D ops want. Clip loops then run window by window, not frame by frame. A typical train tensor reads \(B \times 3 \times 8 \times 112 \times 112\) for batch \(B\).

Cost contrast is plain. Full 3D with \(3 \times 3 \times 3\) pays 27 multiplies per channel per slot. Split with \(1 \times 3 \times 3\) plus \(3 \times 1 \times 1\) pays 9 plus 3, which is 12. Less than half the multiplies for similar reach. That saving funds deeper stacks or larger batches.

Scope: C3D fits small-data demos where full joint power matters most. R2 plus 1D fits larger runs where cost and overfit bite.

Assumption: PyTorch 3D ops get \(B, C, T, H, W\) order. Kernels, stride, and padding use three slots in the same order.

Picture the two blocks. C3D draws one cube covering time, rows, and columns. R2 plus 1D draws a flat sheet plus a thin time rod. Both cover the same span. The landmark is the weight count tag: 27 against 12. The takeaway is similar view at lower cost.

Do not pass \(B, T, C, H, W\) straight into 3D conv. Permute to \(B, C, T, H, W\) first. Do not forget ReLU between split halves. Without it, two linear steps collapse to one and the split gains nothing.

Recap: C3D learns joint cubes directly, factorized nets split space and time to save weights, and axis order must match PyTorch. Next, size math predicts outputs before any run.

7.8.3 Convolution Arithmetic and Output Size

A 4 by 4 frame meets a 3 by 3 kernel. How large is the reply, and how does padding change the answer?

Convolution, a sliding element-wise product plus sum, scales with dimension. Start with 1D over time. Move to 2D over height and width. Move to 3D over time, height and width. The rule stays the same, only the axis count grows. The size rule to master is one line. Convolution output size from input minus kernel plus one. That line holds per axis with stride 1 and no padding.

2D demo with numbers: place a 3 by 3 kernel over a 3 by 3 patch. Multiply paired slots, for instance 64 times 1, 65 times 0, 69 times 0, 62 times 0, 69 times 1, 63 times 0, 63 times 0, 64 times 0, 63 times 1. Add the nine products. Kept products 64 plus 69 plus 63 give 196. Shift with stride 1 or 2 and repeat. The full sweep over a larger image gives a 2D map, with 196 in one slot and values such as 116 nearby.

3D form adds time to the sum. In words, the spoken form was: apply the kernel over a short frame stack in one go and sum over time, height and width. A compact math form for one output slot is:

A kernel size, the span along each axis, written \(K_T, K_H, K_W\), might be \(3, 3, 3\) for a cubic kernel. An output slot, the reply at one position, written \(y_{t,h,w}\), pools one window.

\[ y_{t,h,w} = \sum_{i=1}^{K_T}\sum_{j=1}^{K_H}\sum_{k=1}^{K_W} W_{i,j,k} X_{t+i, h+j, w+k} \]

Here \(X\) is the input clip volume with time, height and width axes. The symbol \(W\) is the kernel with sizes \(K_T\) by \(K_H\) by \(K_W\). The symbols \(K_T\), \(K_H\) and \(K_W\) are kernel lengths along time, height and width. The symbol \(y_{t,h,w}\) is the output slot at time \(t\), row \(h\) and column \(w\). Stride sets the shift step. Padding adds border zeros to hold size.

Output size with stride 1 and no padding is direct. Time out equals time in minus kernel time plus 1, and likewise for height and width. This is convolution output size from input minus kernel plus one per axis.

\[ T_{\text{out}} = T_{\text{in}} - K_T + 1 \]

\[ H_{\text{out}} = H_{\text{in}} - K_H + 1 \]

\[ W_{\text{out}} = W_{\text{in}} - K_W + 1 \]

Here \(T_{\text{in}}\), \(H_{\text{in}}\) and \(W_{\text{in}}\) are input lengths. The symbols \(T_{\text{out}}\), \(H_{\text{out}}\) and \(W_{\text{out}}\) are output lengths for the convolution step alone. Same padding holds sizes equal, so a 3 by 4 by 4 input stays 3 by 4 by 4. Compute output sizes from input and kernel sizes, and use same padding holds sizes equal as the shortcut. That pair answers most exam size asks.

Picture size change as bars. Input bar length is \(T_{\text{in}}\). Kernel bar length is \(K_T\). Output bar is the count of valid placements, which is input minus kernel plus one. Padding adds ghost slots to keep output equal to input. The landmark is same padding where bars match. The takeaway is one rule per axis, no exceptions at stride 1.

Scope: These size lines fit stride 1 with zero or same padding. They fit 1D, 2D, and 3D by same logic.

Assumption: Input, kernel, stride, and padding use matching axis order. Dilation is 1. No holes in the kernel.

Do not mix \(T_{\text{in}}\) with \(T_{\text{out}}\). One is before conv. One is after. Do not forget plus one. Input 4 minus kernel 3 is 1, plus one is 2. That missing one is the classic off-by-one slip. Do not apply same-padding shortcut with stride 2. Sizes then shrink even with padding.

Recap: each output slot sums one window, and each axis shrinks by kernel minus one without padding. Next, worked sizes lock the rule with numbers.

14.1 Foundations of Spanning Trees and the Greedy Strategy

Core Question: How can a telecommunications engineer connect 100 cities with high-speed fiber-optic cables using the absolute minimum total trenching distance, while guaranteeing that every city can communicate with every other city without creating costly circular loops?

Answering this question requires bridging two foundational concepts in computer science: the structural properties of trees as subgraphs, and the algorithmic power of greedy optimization.

14.1.1 Trees as Subgraphs and the Spanning Tree Property

A graph (a network of interconnected points), written \(G = (V, E)\), consists of a finite vertex set \(V\) and an edge set \(E\). In general graphs, edges can form closed paths called cycles—sequences of distinct edges leading from a starting vertex back to itself. In contrast, a tree is a connected, undirected graph that is strictly acyclic (containing zero cycles). Every tree represents a minimal communication network: removing any edge disconnects the graph, and adding any edge creates a cycle.

Let \(G = (V, E)\) be a connected, undirected graph. A subgraph of \(G\) is a graph \(G' = (V', E')\) such that \(V' \subseteq V\) and \(E' \subseteq E\). When a subgraph is acyclic and includes every vertex in the parent graph (\(V' = V\)), it forms a spanning tree.

Spanning Tree Property and Edge Count Relation: For any connected, undirected graph \(G = (V, E)\) containing \(|V|\) vertices, every valid spanning tree \(T = (V, E_{ST})\) connects all \(|V|\) vertices using exactly \(|V| - 1\) edges:

\[ |E_{ST}| = |V| - 1 \]

where \(|V|\) denotes the total count of vertices in the graph, and \(|E_{ST}|\) denotes the number of edges belonging to the spanning tree.

The professor summarizes this core relation in plain language: "if you have vertices V, V minus 1 is equal to the minimal number of edges, all the nodes or vertices should be there and they should be connected using minimal number of edges".

To see why this theorem holds, consider building a tree vertex by vertex:

  1. The first vertex requires 0 edges.
  2. The second vertex requires 1 edge to connect to the first.
  3. Every subsequent vertex requires exactly 1 new edge to attach to the already-connected component without creating a closed loop.
  4. Therefore, connecting all \(|V|\) vertices requires exactly \(|V| - 1\) edges.

A single graph can yield multiple distinct spanning trees depending on which edges are selected. For a complete undirected graph \(K_n\) (a graph with \(n\) vertices where an edge connects every pair of vertices), the total number of distinct labeled spanning trees is given by Cayley's formula:

\[ T(K_n) = n^{n-2} \]

where \(n = |V|\) is the number of vertices. For instance:

  • If \(n = 3\), \(T(K_3) = 3^{3-2} = 3^1 = 3\) distinct spanning trees.
  • If \(n = 4\), \(T(K_4) = 4^{4-2} = 4^2 = 16\) distinct spanning trees.
  • If \(n = 5\), \(T(K_5) = 5^{5-2} = 5^3 = 125\) distinct spanning trees.

For general, non-complete graphs, the number of spanning trees is determined algebraically using Kirchhoff's Matrix Tree Theorem. We construct the graph Laplacian matrix \(L = D - A\), where \(D\) is the diagonal degree matrix (\(D_{ii} = \deg(v_i)\)) and \(A\) is the adjacency matrix. Any cofactor of \(L\) evaluates to the exact number of spanning trees in the graph.

Graphs fall into two broad categories based on edge attributes:

  • Unweighted Graphs: Edges possess no numerical values. We view all edges as possessing identical, uniform cost (such as 1). In this case, any valid spanning tree using \(|V| - 1\) edges has the same cost and is automatically a minimum spanning tree.
  • Weighted Graphs: Each edge \(e = (u, v) \in E\) carries a real-valued numerical weight \(w(u, v) \in \mathbb{R}\). Depending on the problem domain, edge weights quantify physical road distance in kilometers, fiber-optic cable latency in milliseconds, monetary construction cost in millions of dollars, or physical attributes such as pipe resistance.

Worked Example: Spanning Tree Enumeration on \(K_4\) Consider a complete graph \(K_4\) with vertices \(V = \{A, B, C, D\}\) and \(|E| = \frac{4 \times 3}{2} = 6\) edges.

  1. Applying Cayley's formula yields:

\[ T(K_4) = 4^{4-2} = 4^2 = 16 \text{ spanning trees} \]

  1. These 16 distinct spanning trees divide into two structural topologies:
  • Star topologies (degree 3 central vertex): Choosing any of the 4 vertices as the center connected to the other 3 gives \(\binom{4}{1} = 4\) star trees.
  • Path topologies (simple paths of length 3): Arranging the 4 vertices in a linear sequence gives \(\frac{4!}{2} = 12\) distinct path trees.
  1. Total trees: \(4 + 12 = \mathbf{16}\).

Sense-check: The sum of star and path topologies accounts for all 16 labeled trees predicted by Cayley's formula.

14.1.2 The Greedy Optimization Strategy

An optimization problem seeks a configuration from a set of feasible options that either minimizes a cost function or maximizes a profit objective. The greedy strategy is a paradigm for designing optimization algorithms. At each sequential decision stage, a greedy algorithm makes the choice that appears best at the present instant—a locally optimal choice—under the operating hypothesis that local choices will accumulate into a globally optimal solution.

The Daily Meal Budget Analogy: Think of a greedy choice like managing a daily food budget. Suppose a student receives a daily food allowance of 50 rupees and must purchase three meals: breakfast, lunch, and dinner. The objective is to eat all three meals while spending as little as possible, thereby maximizing total savings.

If food counters offer meal options priced between 10 rupees and 50 rupees, your local strategy at each mealtime is simple: choose the lowest-priced 10-rupee meal.

  • Breakfast spend: 10 rupees
  • Lunch spend: 10 rupees
  • Dinner spend: 10 rupees

The total expenditure is \(10 + 10 + 10 = 30\) rupees, leaving \(50 - 30 = 20\) rupees in personal savings. By making the minimal spend decision at each isolated step, you achieve a globally minimal expenditure.

As the professor highlights in plain words: "spend minimal to have the meal and save the remaining, in each step, if you take minimal solution, by end, you always end up the minimal possibility".

Where the analogy breaks: In real life, choosing the cheapest breakfast might leave you malnourished by dinner, forcing an expensive medical bill. A greedy choice works only when local choices never restrict or penalize future choices—a property called the greedy-choice property.

While dynamic programming solves problems by evaluating and storing overlapping subproblems through recursive formulation, a greedy algorithm never reconsiders or backtracks on a prior choice. For greedy algorithms to guarantee an optimal solution, two mathematical properties must hold:

  1. Greedy-Choice Property: A globally optimal solution can be reached by assembling locally optimal (greedy) choices without looking ahead.
  2. Optimal Substructure: An optimal solution to the overall problem contains within it optimal solutions to its subproblems.

Scope & Assumptions:

  • Spanning trees exist if and only if the underlying graph \(G\) is connected. If \(G\) has \(k > 1\) disconnected components, no single spanning tree exists; instead, each component yields a tree, forming a spanning forest with exactly \(|V| - k\) edges.
  • Edge weights can be positive, negative, or zero in minimum spanning tree algorithms (unlike shortest-path algorithms).
  • If edge weights are not strictly unique, multiple distinct minimum spanning trees with identical total weights can exist.

Common Pitfalls:

  1. Confusing Unweighted and Weighted Trees: In an unweighted graph, any valid spanning tree using \(|V|-1\) edges is automatically optimal. In a weighted graph, different spanning trees yield drastically different weight sums; finding the minimum requires deliberate algorithmic selection.
  2. Assuming the Spanning Tree is Unique: When two or more edges share the same minimum weight, multiple distinct spanning trees can exist with the identical minimal cost. Uniqueness is guaranteed only when all edge weights are strictly distinct.
  3. Over-connecting the Subgraph: Attempting to add a "safety edge" for redundancy immediately introduces a cycle, violating the acyclic definition of a tree.

14.1.3 Student Inquiries and Root Determination in Graphs

Q: How do we determine the root of a tree when constructing it from a graph, given that standard tree definitions require a hierarchical parent-child structure?

A: In computer science, data structures like binary search trees possess a distinct root node from which all child branches descend. However, an undirected graph contains no natural hierarchy: every edge is bidirectional, and no vertex possesses inherent priority over another.

In a directed graph, a vertex with only outgoing edges (in-degree zero) can serve as a natural structural root. In an undirected graph, root designation is entirely an artifact of execution:

  • The user or algorithm author explicitly specifies an arbitrary starting source vertex, which acts as the operational root during traversal.
  • If no starting vertex is provided, standard tie-breaking rules—such as selecting the vertex with the lowest alphabetical label (e.g., node \(A\)) or lowest numerical index—are applied.

The professor explicitly corrects this common misconception: "there is no standard definition as you talk in a tree where you say that, hey, I have to define particularly root node". The root is simply established when a user or algorithm picks a designated start vertex for execution.

Recap & Bridge: A spanning tree connects all \(|V|\) vertices of a graph using exactly \(|V| - 1\) edges without closed loops. When edges have weights, our goal is to find the Minimum Spanning Tree (MST)—the tree with the lowest total edge weight. In Section 14.2, we explore Prim's algorithm, a vertex-growing greedy algorithm that builds this tree starting from a single seed vertex.

In real-world engineering, spanning trees are central to physical civil infrastructure and telecommunications. Civil engineers designing municipal water distribution networks use spanning trees to guarantee that every neighborhood receives water pipelines with minimal pipe laying cost. Similarly, the IEEE 802.1D Spanning Tree Protocol (STP) implemented inside Ethernet network switches dynamically calculates a loop-free active spanning tree topology across local area networks, disabling redundant physical links to eliminate packet-destroying broadcast storms.

14.2 Prim's Algorithm for Minimum Spanning Trees

Core Motivation: Suppose you are connecting power lines across eight regional substations. If you start from the main power plant, how can you expand the grid one substation at a time so that every newly energized substation is connected via the shortest possible high-voltage line, guaranteeing no power loops and the minimum total copper wire cost?

Prim's algorithm solves this problem directly. It is a greedy algorithm that finds a Minimum Spanning Tree (MST) for a connected, weighted, undirected graph by growing a single connected tree outward from an arbitrary seed vertex.

14.2.1 Core Algorithm and Priority Queue Formulation

Let \(G = (V, E)\) be a connected, undirected graph where each edge \(e = (u, v) \in E\) has a real-valued weight \(w(u, v)\). The mathematical objective of Prim's algorithm is to find an acyclic subgraph \(T = (V, E_T)\) spanning all vertices that minimizes the total edge weight function:

Minimum Spanning Tree Objective Function:

\[ W(T) = \sum_{e \in E_T} w(e) \]

where \(E_T \subset E\) contains exactly \(|V| - 1\) edges, and \(w(e)\) represents the numerical weight of edge \(e\).

The professor captures this objective in plain language: "summation of all the edges should be minimal possible".

The correctness of Prim's algorithm rests on the Cut Property in graph theory:

  • A cut \((S, V \setminus S)\) is a partition of the vertex set \(V\) into two disjoint sets \(S\) and \(V \setminus S\).
  • An edge \(e = (u, v)\) crosses the cut if one endpoint lies in \(S\) and the other lies in \(V \setminus S\).
  • The Cut Theorem: If an edge \(e\) is a light (minimum-weight) edge crossing a cut \((S, V \setminus S)\), and \(S\) contains the vertices of a growing partial minimum spanning tree, then \(e\) can be safely added to the tree without precluding global optimality.

Throughout execution, Prim's algorithm maintains connectivity: the partial tree is connected at every single iteration. To select the lightest crossing edge efficiently, unvisited vertices are maintained in a min-priority queue \(Q\).

For each vertex \(v \in V\), the algorithm maintains two tracking attributes:

  1. \(D[v]\) (Key): The minimum weight of any edge connecting \(v\) to a vertex currently in the growing tree \(S\). If no such edge exists, \(D[v] = \infty\).
  2. \(P[v]\) (Parent / Predecessor): The specific vertex in \(S\) that achieves the minimal connection weight to \(v\).
ALGORITHM MST-PRIM(G, w, r)
1.  For each vertex v in G.V:
2.      D[v] = infinity
3.      P[v] = NIL
4.  D[r] = 0                           // r is the designated seed root
5.  Q = BuildMinPriorityQueue(G.V)     // Q ordered by D[v]
6.  While Q is not empty:
7.      u = ExtractMin(Q)              // Permanently adds u to MST (labeled T)
8.      For each adjacent vertex v in G.Adj[u]:
9.          If v in Q and w(u, v) < D[v]:
10.             D[v] = w(u, v)         // Relaxation: reduce tentative key
11.             P[v] = u
12.             DecreaseKey(Q, v, D[v])

Line 9–11 implements relaxation. In Prim's algorithm, relaxation updates the tentative connection cost of an unvisited neighbor whenever a strictly cheaper bridge into the growing tree is discovered.

Strict Relaxation Rule: Relaxation is applied if and only if the discovered edge weight is strictly less than the current key:

\[ w(u, v) < D[v] \]

As the professor explicitly clarifies: "relaxation is a method in which we reduce the weightage or the value but not increase and it is always done only if the value that you found is lesser than the current value". If \(w(u, v) \ge D[v]\), no update occurs, protecting existing optimal connections.

14.2.2 Worked Example 1: Eight-Vertex Graph MST Construction

Worked Example: Step-by-Step Execution on an Eight-Vertex Graph Consider a connected, undirected weighted graph with 8 vertices: \(V = \{A, B, C, D, E, F, G, H\}\). The graph contains 14 edges. We select vertex \(D\) as the designated starting root.

Initialization:

  • Distance keys: \(D[D] = 0\); for all other vertices \(v \in V \setminus \{D\}\), \(D[v] = \infty\).
  • Predecessors: all \(P[v] = \text{NIL}\).
  • Priority queue: \(Q = \{D, A, B, C, E, F, G, H\}\).

Step 1: Extract minimum key vertex from \(Q\): extract \(D\) (\(D[D] = 0\)). Vertex \(D\) joins the MST (labeled T).

  • Inspect adjacent edges of \(D\):
  • Edge \((D, C)\), weight 3: \(3 < \infty\), relax \(D[C] \gets 3\), \(P[C] \gets D\).
  • Edge \((D, G)\), weight 2: \(2 < \infty\), relax \(D[G] \gets 2\), \(P[G] \gets D\).
  • Edge \((D, F)\), weight 18: \(18 < \infty\), relax \(D[F] \gets 18\), \(P[F] \gets D\).
  • Edge \((D, E)\), weight 25: \(25 < \infty\), relax \(D[E] \gets 25\), \(P[E] \gets D\).

Step 2: Minimum key in \(Q\) is \(D[G] = 2\). Extract \(G\) (labeled T).

  • Edge \((D, G)\) with weight 2 is added to the MST.
  • Inspect adjacent edges of \(G\):
  • Edge \((G, H)\), weight 3: \(3 < \infty\), relax \(D[H] \gets 3\), \(P[H] \gets G\).
  • Edge \((G, E)\), weight 7: since \(7 < 25\), relax \(D[E] \gets 7\), \(P[E] \gets G\).

Step 3: Current minimum keys in \(Q\) are \(D[C] = 3\) and \(D[H] = 3\). By alphabetical tie-breaking, extract \(C\) (labeled T).

  • Edge \((D, C)\) with weight 3 is added to the MST.
  • Inspect adjacent edges of \(C\):
  • Edge \((C, F)\), weight 3: since \(3 < 18\), relax \(D[F] \gets 3\), \(P[F] \gets C\).
  • Edge \((C, B)\), weight 4: \(4 < \infty\), relax \(D[B] \gets 4\), \(P[B] \gets C\).

Step 4: Minimum keys in \(Q\) are \(D[F] = 3\) and \(D[H] = 3\). By alphabetical tie-breaking, extract \(F\) (labeled T).

  • Edge \((C, F)\) with weight 3 is added to the MST.
  • Inspect adjacent edges of \(F\):
  • Edge \((F, E)\), weight 2: since \(2 < 7\), relax \(D[E] \gets 2\), \(P[E] \gets F\).
  • Edge \((F, A)\), weight 10: \(10 < \infty\), relax \(D[A] \gets 10\), \(P[A] \gets F\).
  • Edge \((F, B)\), weight 7: current \(D[B] = 4\). Because \(7 \ge 4\), no update occurs.

Step 5: Minimum key in \(Q\) is \(D[E] = 2\). Extract \(E\) (labeled T).

  • Edge \((F, E)\) with weight 2 is added to the MST.
  • Inspect adjacent edges of \(E\): all incident edges connect to vertices already finalized in \(S\) or offer higher costs.

Step 6: Minimum key in \(Q\) is \(D[H] = 3\). Extract \(H\) (labeled T).

  • Edge \((G, H)\) with weight 3 is added to the MST.
  • Inspect adjacent edges of \(H\): edge \((H, A)\) has weight 4. Since \(4 < 10\), relax \(D[A] \gets 4\), \(P[A] \gets H\).

Step 7: Remaining vertices in \(Q\) are \(A\) with \(D[A] = 4\) and \(B\) with \(D[B] = 4\). By alphabetical order, extract \(A\) (labeled T).

  • Edge \((H, A)\) with weight 4 is added to the MST.

Step 8: Extract the final remaining vertex \(B\) with \(D[B] = 4\) (labeled T).

  • Edge \((C, B)\) with weight 4 is added to the MST.

MST Total Weight Calculation: All 8 vertices are finalized. Exactly \(8 - 1 = 7\) edges have been selected:

\[ W(T) = w(D, G) + w(D, C) + w(C, F) + w(F, E) + w(G, H) + w(H, A) + w(C, B) \]

\[ W(T) = 2 + 3 + 3 + 2 + 3 + 4 + 4 = \mathbf{21} \]

The total weight of the minimum spanning tree is exactly 21 units. Sense-check: Exactly 7 edges connect 8 vertices without cycles, and every cut edge was minimal at extraction.

14.2.3 Worked Example 2: Seven-Vertex Graph and Termination

Worked Example: Seven-Vertex Graph and Halting Condition Consider a second connected graph containing 7 vertices: \(V = \{A, B, C, D, E, F, G\}\). We initialize Prim's algorithm at seed vertex \(A\).

  1. Iteration 1: Start at \(A\). Incident edge \((A, B)\) with weight 2 is the minimal crossing edge. Add \((A, B)\) to tree. Tree set is \(\{A, B\}\).
  2. Iteration 2: From \(\{A, B\}\), minimal connecting edge is \((A, C)\) with weight 3. Add \((A, C)\). Tree set is \(\{A, B, C\}\).
  3. Iteration 3: From \(\{A, B, C\}\), minimal cut edge is \((C, F)\) with weight 3. Add \((C, F)\). Tree set is \(\{A, B, C, F\}\).
  4. Iteration 4: From \(\{A, B, C, F\}\), minimal cut edge is \((C, D)\) with weight 4. Add \((C, D)\). Tree set is \(\{A, B, C, D, F\}\).
  5. Iteration 5: Minimal connecting edge to unvisited vertices is \((F, G)\) with weight 5. Add \((F, G)\). Tree set is \(\{A, B, C, D, F, G\}\).
  6. Iteration 6: The sole unvisited vertex is \(E\), connected via \((F, E)\) with weight 5. Add \((F, E)\). Tree set is \(\{A, B, C, D, E, F, G\}\).

Summing the 6 selected edge weights gives:

\[ W(T) = 2 + 3 + 3 + 4 + 5 + 5 = \mathbf{22} \]

Summing the 6 selected edge weights gives a total spanning tree weight of 22 units.

At this stage, exactly \(7 - 1 = 6\) edges have been added and all 7 vertices belong to the tree. The algorithm must stop immediately.

Halting Condition Warning: The professor poses an urgent cautionary question: "stop if you continue what will happen?". If the algorithm fails to halt when \(|V| - 1\) edges are selected and continues extracting edges, any additional edge connects two vertices that already belong to the tree. This inevitably introduces a cycle, destroying the tree topology and turning the acyclic spanning tree into a cyclic graph.

14.2.4 Student Inquiries and Algorithm Analysis

Q: In the tabular trace of Prim's algorithm, what does the T label indicate and when is it assigned?

A: In the tabular trace of Prim's algorithm, the label T (standing for Tree or Permanent) indicates that a vertex has been extracted from the min-priority queue and officially added to the permanent MST solution set \(S\). Once a vertex is assigned the label T, its minimal connection cost into the tree is permanently locked, and it is never re-extracted or updated.

Q: Which data structure is used to implement Prim's algorithm efficiently?

A: Prim's algorithm is implemented efficiently using a min-priority queue backed by a binary min-heap. In a min-heap, the root node holds the element with the lowest key value, allowing Extract-Min to run in \(O(\log |V|)\) time. When adjacency lists represent the graph, edge updates invoke Decrease-Key, which also executes in \(O(\log |V|)\) time.

The asymptotic time complexity of Prim's algorithm depends directly on the priority queue implementation:

Asymptotic Complexity Formulation: When implemented using a standard binary min-heap and adjacency lists:

\[ T(|V|, |E|) = O(|E| \log |V| + |V| \log |V|) = O(|E| \log |V|) \]

where \(|V|\) is the total count of vertices, and \(|E|\) is the total count of edges.

The plain-language derivation notes: "the time complexity is the number of vertices plus the edges that you have used, order of V plus E, where edges part of solution is V minus 1".

Breakdown of operations:

1. Build-Min-Heap: \(O(|V|)\) time to initialize keys.
2. Extract-Min: Invoked exactly \(|V|\) times, each taking \(O(\log |V|)\) time \(\implies O(|V| \log |V|)\).
3. Decrease-Key: In the worst case, every edge is examined once during relaxation, triggering at most \(|E|\) key updates, each taking \(O(\log |V|)\) time \(\implies O(|E| \log |V|)\).

If implemented using a Fibonacci heap, Decrease-Key takes amortized \(O(1)\) time, improving the overall running time to \(O(|E| + |V| \log |V|)\).

Recap & Bridge: Prim's algorithm builds an MST from the perspective of vertices, growing a single connected tree outward until it encompasses all \(|V|\) vertices with \(|V| - 1\) edges. In Section 14.3, we explore Kruskal's algorithm, an alternative greedy approach that takes an edge-centric view, sorting all edges globally and merging disconnected forests.

Prim's algorithm is used in printed circuit board (PCB) design and VLSI microchip fabrication to construct clock distribution trees and ground planes. Electronic design automation (EDA) tools route clock signal pins from a central crystal oscillator across millions of logic gates, using Prim's algorithm to connect all terminals with minimal total copper track capacitance and wire delay.

14.3 Kruskal's Algorithm for Minimum Spanning Trees

Core Motivation: Instead of growing a single connected tree outward from one city like Prim's algorithm, what if we consider all possible highway links across the entire nation simultaneously? By sorting all potential links by cost and laying the cheapest road segments first anywhere in the country—stopping only when a road would form a redundant loop—can we guarantee the absolute minimal national infrastructure expenditure?

Kruskal's algorithm proves that this global, edge-centric strategy works. It is an alternative greedy algorithm that computes a minimum spanning tree by treating the graph as a forest of disconnected trees, gradually merging them until a single connected tree spans all vertices.

14.3.1 Edge-Centric Greedy Strategy and Forest Merging

Kruskal's algorithm begins by sorting all \(|E|\) edges of graph \(G = (V, E)\) in non-decreasing order of numerical weight:

\[ w(e_1) \le w(e_2) \le w(e_3) \le \dots \le w(e_{|E|}) \]

Starting with an empty edge set \(E_T = \emptyset\), the algorithm examines candidate edges one by one in sorted order:

  1. If the candidate edge connects two vertices that belong to different trees in the forest, the edge is accepted into \(E_T\), and the two trees are merged.
  2. If the candidate edge connects two vertices that already belong to the same tree, adding the edge would introduce a cycle. The edge is permanently discarded.
  3. The process terminates as soon as exactly \(|V| - 1\) edges have been accepted.

#### Conceptual Comparison: Prim versus Kruskal

The fundamental distinction between Prim's and Kruskal's algorithms lies in their structural evolution:

Architectural Dimension Prim's Algorithm Kruskal's Algorithm
Algorithmic Perspective Vertex-centric Edge-centric
Intermediate State Always a single connected tree growing outward Disconnected forest of trees merging incrementally
Edge Selection Scope Locally crossing the active cut \((S, V \setminus S)\) Globally lightest edge across the entire graph
Primary Data Structure Min-priority queue (Binary min-heap) Disjoint Set Union (Union-Find with path compression)
Prerequisite Processing None; edges evaluated dynamically All \(|E|\) edges sorted upfront
Asymptotic Complexity \(O(|E| \log |V|)\) \(O(|E| \log |E|) = O(|E| \log |V|)\)
Optimal Graph Density Dense graphs (\(|E| \approx |V|^2\)) Sparse graphs (\(|E| \ll |V|^2\))

The professor articulates this key architectural difference: "connected formation of connected spamming tree can happen in the last iteration whereas in print from first onwards your minimal spanning tree is always connected". In Prim's algorithm, the growing component is connected at every iteration from step one onward. In Kruskal's algorithm, the graph remains a disconnected forest of mini-trees until the final accepted edge bridges the last two components.

Despite these differing execution paths, the final objective value is invariant. When multiple valid minimum spanning trees exist due to identical edge weights, the professor emphasizes: "summation of minimal spanning tree the outcome will be always same but the ordering of choosing the adjust will vary". Every valid minimum spanning tree on the same graph achieves the exact same optimal weight sum.

Cycle Detection via Disjoint Set Union (Union-Find): To determine whether an edge \(e = (u, v)\) creates a cycle in nearly constant time, Kruskal's algorithm uses the Disjoint Set Union (DSU) data structure. Each vertex starts in its own singleton set:

  • MAKE-SET(v): Initializes a set containing only vertex \(v\).
  • FIND-SET(v): Returns the representative identifier of the set containing \(v\).
  • UNION(u, v): Merges the set containing \(u\) with the set containing \(v\).

For any candidate edge \(e = (u, v)\):

\[ \begin{aligned} &\text{If } \text{FIND-SET}(u) \neq \text{FIND-SET}(v): &&\text{Vertices are in disjoint trees; accept edge and call } \text{UNION}(u, v) \\ &\text{If } \text{FIND-SET}(u) = \text{FIND-SET}(v): &&\text{A path already connects } u \text{ and } v \text{; discard edge to prevent cycle} \end{aligned} \]

With union by rank and path compression, a sequence of \(m\) disjoint-set operations on \(n\) elements runs in \(O(m \cdot \alpha(n))\) time, where \(\alpha\) is the extremely slow-growing inverse Ackermann function (\(\alpha(n) \le 4\) for all practical values of \(n\)).

14.3.2 Worked Example 1: Sorted Edge Selection and Cycle Avoidance

Worked Example: Kruskal's Trace on the Eight-Vertex Graph We execute Kruskal's algorithm on the identical 8-vertex graph from Section 14.2, containing \(|V| = 8\) vertices and \(|E| = 14\) edges.

Step 1: Global Edge Sorting: All 14 edges are sorted in non-decreasing order of weight:

  1. \((D, E)\), weight 2
  2. \((D, G)\), weight 2
  3. \((E, G)\), weight 3
  4. \((D, C)\), weight 3
  5. \((G, H)\), weight 3
  6. \((C, F)\), weight 3
  7. \((B, C)\), weight 4
  8. \((B, E)\), weight 4
  9. \((F, B)\), weight 4
  10. \((B, H)\), weight 4
  11. \((A, H)\), weight 4
  12. \((D, F)\), weight 18
  13. \((A, B)\), weight 20
  14. \((A, F)\), weight 25

Step 2: Sequential Edge Evaluation:

  • Edge 1: \((D, E)\) (weight 2): \(\text{FIND-SET}(D) = \{D\}\), \(\text{FIND-SET}(E) = \{E\}\). Sets are disjoint. Accept edge. Merged set: \(\{D, E\}\). (Edge count: 1)
  • Edge 2: \((D, G)\) (weight 2): \(\text{FIND-SET}(D) = \{D, E\}\), \(\text{FIND-SET}(G) = \{G\}\). Disjoint. Accept edge. Merged set: \(\{D, E, G\}\). (Edge count: 2)
  • Edge 3: \((E, G)\) (weight 3): \(\text{FIND-SET}(E) = \{D, E, G\}\), \(\text{FIND-SET}(G) = \{D, E, G\}\). Identical component. Adding \((E, G)\) creates cycle \((D-E-G-D)\). Discard edge.
  • Edge 4: \((D, C)\) (weight 3): \(\text{FIND-SET}(C) = \{C\}\). Disjoint. Accept edge. Merged set: \(\{C, D, E, G\}\). (Edge count: 3)
  • Edge 5: \((G, H)\) (weight 3): \(\text{FIND-SET}(H) = \{H\}\). Disjoint. Accept edge. Merged set: \(\{C, D, E, G, H\}\). (Edge count: 4)
  • Edge 6: \((C, F)\) (weight 3): \(\text{FIND-SET}(F) = \{F\}\). Disjoint. Accept edge. Merged set: \(\{C, D, E, F, G, H\}\). (Edge count: 5)
  • Edge 7: \((B, C)\) (weight 4): \(\text{FIND-SET}(B) = \{B\}\). Disjoint. Accept edge. Merged set: \(\{B, C, D, E, F, G, H\}\). (Edge count: 6)
  • Edge 8: \((B, E)\) (weight 4): Both \(B\) and \(E\) belong to the same component. Discard edge (cycle).
  • Edge 9: \((F, B)\) (weight 4): Both \(F\) and \(B\) belong to the same component. Discard edge (cycle).
  • Edge 10: \((B, H)\) (weight 4): Both \(B\) and \(H\) belong to the same component. Discard edge (cycle).
  • Edge 11: \((A, H)\) (weight 4): \(\text{FIND-SET}(A) = \{A\}\). Disjoint. Accept edge. Merged set: \(\{A, B, C, D, E, F, G, H\}\). (Edge count: 7)

Termination and Weight Sum: Exactly \(|V| - 1 = 8 - 1 = 7\) edges have been accepted. The algorithm halts immediately.

\[ W(T) = 2 + 2 + 3 + 3 + 3 + 4 + 4 = \mathbf{21} \]

The total MST weight is 21 units. This matches the result found by Prim's algorithm. Sense-check: Exactly 7 edges connect all 8 vertices, and the total weight 21 matches Prim's algorithm exactly, confirming global invariance.

14.3.3 Worked Example 2: Edge Selection with Identical Minimal Weight

Worked Example: Seven-Vertex Graph and Forest Merging Trace We execute Kruskal's algorithm on the 7-vertex graph (\(V = \{A, B, C, D, E, F, G\}\)) from Section 14.2.3. The sorted edge list is evaluated sequentially:

  1. Edge \((A, D)\) (weight 5): Disjoint sets \(\{A\}\) and \(\{D\}\). Accept. Tree set 1: \(\{A, D\}\).
  2. Edge \((C, E)\) (weight 5): Disjoint sets \(\{C\}\) and \(\{E\}\). Accept. Tree set 2: \(\{C, E\}\). Notice that the graph currently forms two disconnected trees.
  3. Edge \((D, F)\) (weight 6): \(\{A, D\}\) and \(\{F\}\) are disjoint. Accept. Merges into \(\{A, D, F\}\).
  4. Edge \((A, B)\) (weight 7): \(\{A, D, F\}\) and \(\{B\}\) are disjoint. Accept. Merges into \(\{A, B, D, F\}\).
  5. Edge \((B, E)\) (weight 7): Merges tree component \(\{A, B, D, F\}\) with component \(\{C, E\}\). Accept. Merged set: \(\{A, B, C, D, E, F\}\).
  6. Edge \((B, D)\) (weight 9): Both \(B\) and \(D\) already belong to the merged component. Discard (cycle).
  7. Edge \((E, G)\) (weight 9): Connects isolated vertex \(G\) to the unified tree. Accept. Merged set: \(\{A, B, C, D, E, F, G\}\).

Summing Accepted Edges:

\[ W(T) = 5 + 5 + 6 + 7 + 7 + 9 = \mathbf{39} \]

The total minimal spanning tree weight is 39 units.

When this same 7-vertex problem is solved using Prim's algorithm, although edges are explored in a completely different sequence, the total weight evaluates to the identical sum of 39 units.

14.3.4 Student Inquiries and Cycle Detection Complexity

Q: How do we determine whether adding an edge creates a cycle in Kruskal's algorithm?

A: To determine whether an edge creates a cycle, check whether both endpoints of the candidate edge already belong to the same connected component within the current forest. Using the Disjoint Set Union data structure, we invoke FIND-SET(u) and FIND-SET(v). If both queries return the identical set representative, a path already exists between \(u\) and \(v\), meaning that adding \((u, v)\) would complete a cycle. The edge must be rejected. If the representatives differ, the edge bridges two separate components and is accepted safely.

Q: Will exam questions require writing out the full pseudocode or algorithm for Prim's and Kruskal's?

A: No. Examination questions focus on problem solving and design concepts rather than pseudocode memorization. Students will be provided with concrete weighted graphs and required to perform full step-by-step traces, record accepted and rejected edges, show intermediate forest states, calculate final total weights, and justify whether Prim's or Kruskal's algorithm is better suited for a given graph density.

Exam note: Expect numerical problem-solving and design trade-off questions on exams rather than pseudocode memorization. Practice performing full tabular traces of Kruskal's algorithm, explicitly listing the sorted edge array, marking accepted versus discarded cycle edges, and verifying that the final edge count equals \(|V| - 1\).

Common Pitfalls:

  1. Forgetting to Sort Edges Upfront: Kruskal's algorithm requires all edges to be sorted in non-decreasing order before any selection begins. Picking edges out of order destroys the greedy choice guarantee.
  2. Missing a Cycle: Blindly adding the next smallest edge without verifying set membership can introduce cycles, especially in later iterations when components become large.
  3. Assuming Different Minimum Spanning Trees Have Different Weights: While different tie-breaking choices on identical weights produce structurally distinct trees, the total weight sum is strictly identical across all valid MSTs.

Recap & Bridge: Kruskal's algorithm finds an MST in \(O(|E| \log |V|)\) time by sorting edges and using union-find operations to merge forests while avoiding cycles. While MST algorithms minimize the total collective weight across all vertices in an undirected graph, many engineering problems require finding the shortest path from a specific origin to various destinations. In Section 14.4, we transition to Dijkstra's algorithm for the Single-Source Shortest Path problem.

In data science and machine learning, Kruskal's algorithm serves as the algorithmic engine behind single-linkage hierarchical clustering. Data points in multidimensional space represent vertices, and pairwise Euclidean distances represent edge weights. By running Kruskal's algorithm and halting before all components merge (or removing the \(k-1\) heaviest edges from the completed MST), the data partitions into \(k\) natural geometric clusters. In computer graphics and computer vision, the Felzenszwalb-Huttenlocher algorithm uses Kruskal-based graph partitioning for real-time image segmentation.

14.4 Dijkstra's Algorithm for Single-Source Shortest Paths

Core Motivation: When you open Google Maps and enter your destination during rush hour, the app computes the fastest route among millions of possible street intersections in milliseconds. How does the routing engine efficiently identify the quickest path while bypassing heavily congested traffic bottlenecks without checking every possible combination of roads?

This computational task is solved by Dijkstra's algorithm. While Minimum Spanning Tree algorithms minimize the collective edge weight needed to connect all vertices in an undirected graph, the Single-Source Shortest Path (SSSP) problem seeks the path of minimum total weight from a designated source vertex to every other vertex in a weighted graph.

14.4.1 Problem Definition, Real-World Routing, and Algorithmic Components

Real-world digital navigation engines such as Google Maps and automotive GPS systems model municipal and continental road networks as weighted directed graphs.

  • Road intersections and highway junctions represent vertices (\(V\)).
  • Streets, avenue lanes, and highway ramps represent directed edges (\(E\)).
  • Rather than physical road length, the numerical weight assigned to each edge represents estimated travel time in minutes.

When vehicle traffic slows down due to an accident or heavy rush-hour volume, sensors and crowd-sourced GPS pings cause the edge weight to increase dynamically. The navigation engine then re-runs shortest-path calculations to guide drivers around the delay.

As the professor highlights: "google maps work on a principle of fastest truth it depends on the preferences that you but for easier understanding we'll say less time path".

#### Shortest Path Tree versus Minimum Spanning Tree

It is critical to distinguish between a Minimum Spanning Tree (MST) and a Shortest Path Tree (SPT):

  • An MST minimizes the aggregate weight of all selected edges across the entire network (\(\sum_{e \in T} w(e)\)). It is undirected and connects all vertices with minimal total cable or trench length.
  • An SPT minimizes the individual distance from a specific source root \(s\) to each destination vertex \(v\) along a directed path.
  • An MST does not necessarily provide the shortest paths between vertices, and an SPT does not necessarily minimize total edge weight.

Dijkstra's algorithm operates on a directed graph \(G = (V, E)\) with a non-negative edge weight function:

\[ w: E \to [0, \infty) \]

Given a designated source vertex \(s \in V\), the algorithm computes the shortest-path weight \(\delta(s, v)\) to each vertex \(v \in V\), where \(\delta(s, v)\) is the minimum weight among all paths connecting \(s\) to \(v\).

Dijkstra's algorithm comprises three core structural modules:

  1. Source Initialization (INITIALIZE-SINGLE-SOURCE): Sets baseline distance estimates and predecessor pointers.
  2. Min-Priority Queue Management: Extracts the vertex with the lowest tentative distance estimate.
  3. Edge Relaxation (RELAX): Evaluates outgoing edges and updates tentative path estimates whenever a shorter route is found.

14.4.2 Mathematical Formulation and the Relaxation Condition

Single-Source Initialization: Let \(s \in V\) be the source vertex. For every vertex \(v \in V\), the algorithm maintains a distance estimate \(d[v]\) and a predecessor pointer \(\pi[v]\):

\[ d[s] = 0, \quad \forall v \in V \setminus \{s\}: d[v] = \infty, \quad \forall v \in V: \pi[v] = \text{NIL} \]

where \(d[v]\) represents the upper bound on the weight of a shortest path from \(s\) to \(v\), and \(\pi[v]\) records the parent vertex on the current best path.

The professor describes this initialization sequence in plain language: "identify what is your source vertices and assign zero value to your source vertices and apart from source vertices all other vertices distance you are declaring infinite and parent as null".

The algorithm maintains a min-priority queue \(Q\) containing unfinalized vertices keyed by \(d[v]\), alongside a set \(S_{sol}\) of vertices whose final shortest-path weights have been determined.

In each iteration, the algorithm extracts vertex \(u = \text{Extract-Min}(Q)\) and adds it to \(S_{sol}\). For each directed outgoing edge \((u, v) \in E\), the algorithm tests whether passing through \(u\) yields a shorter path to \(v\) than the current estimate \(d[v]\):

The Strict Relaxation Rule:

\[ \text{if } d[v] > d[u] + w(u, v) \text{ then } d[v] \gets d[u] + w(u, v), \quad \pi[v] \gets u \]

where \(w(u, v) \ge 0\) is the non-negative weight of the directed edge from \(u\) to \(v\).

The plain-language rule emphasizes: "if distance of v existing is greater than summation of u plus weight of u v, then do update, parent node becomes u".

Strict Inequality Requirement: Relaxation requires strict inequality (\(d[v] > d[u] + w(u, v)\)). As the professor emphasizes: "relaxation is applied only when you find a value that is lesser than the existing one".

If the newly computed path weight equals the current estimate (\(d[u] + w(u, v) = d[v]\)), no relaxation occurs. The distance estimate remains unchanged, and the existing predecessor pointer \(\pi[v]\) is preserved. This prevents unnecessary pointer thrashing and avoids creating cycle ambiguities in path reconstruction.

14.4.3 Worked Example 1: Five-Vertex Directed Graph SSSP Step-by-Step

Worked Example: Complete SSSP Trace on a 5-Vertex Digraph Consider a directed graph with 5 vertices: \(V = \{S, A, B, C, D\}\). Vertex \(S\) is the designated source. The directed edges and non-negative weights are:

  • \((S, A) = 10\), \((S, D) = 5\)
  • \((D, A) = 3\), \((D, B) = 9\), \((D, C) = 2\)
  • \((A, B) = 1\)
  • \((C, B) = 6\), \((C, S) = 7\)
  • \((B, C) = 4\)

Initialization:

  • Distance estimates: \(d[S] = 0\), \(d[A] = \infty\), \(d[B] = \infty\), \(d[C] = \infty\), \(d[D] = \infty\).
  • Predecessors: all \(\pi[v] = \text{NIL}\).
  • Priority queue: \(Q = \{S, A, B, C, D\}\).
  • Finalized set: \(S_{sol} = \emptyset\).

Iteration 1:

  • Minimum key in \(Q\) is \(S\) with \(d[S] = 0\). Extract \(S\); \(S_{sol} = \{S\}\).
  • Inspect outgoing directed edges from \(S\):
  • Edge \((S, A)\): \(d[S] + w(S, A) = 0 + 10 = 10\). Since \(10 < \infty\), relax: \(d[A] \gets 10\), \(\pi[A] \gets S\).
  • Edge \((S, D)\): \(d[S] + w(S, D) = 0 + 5 = 5\). Since \(5 < \infty\), relax: \(d[D] \gets 5\), \(\pi[D] \gets S\).
  • Status: \(A(10, S)\), \(B(\infty, -)\), \(C(\infty, -)\), \(D(5, S)\).

Iteration 2:

  • Minimum key in \(Q\) is \(D\) with \(d[D] = 5\). Extract \(D\); \(S_{sol} = \{S, D\}\).
  • Inspect outgoing directed edges from \(D\):
  • Edge \((D, A)\): \(d[D] + w(D, A) = 5 + 3 = 8\). Since \(8 < 10\), relax: \(d[A] \gets 8\), \(\pi[A] \gets D\).
  • Edge \((D, B)\): \(d[D] + w(D, B) = 5 + 9 = 14\). Since \(14 < \infty\), relax: \(d[B] \gets 14\), \(\pi[B] \gets D\).
  • Edge \((D, C)\): \(d[D] + w(D, C) = 5 + 2 = 7\). Since \(7 < \infty\), relax: \(d[C] \gets 7\), \(\pi[C] \gets D\).
  • Status: \(A(8, D)\), \(B(14, D)\), \(C(7, D)\).

Iteration 3:

  • Minimum key in \(Q\) is \(C\) with \(d[C] = 7\). Extract \(C\); \(S_{sol} = \{S, D, C\}\).
  • Inspect outgoing directed edges from \(C\):
  • Edge \((C, B)\): \(d[C] + w(C, B) = 7 + 6 = 13\). Since \(13 < 14\), relax: \(d[B] \gets 13\), \(\pi[B] \gets C\).
  • Edge \((C, S)\): \(d[C] + w(C, S) = 7 + 7 = 14\). Current \(d[S] = 0\). Because \(14 \ge 0\), no relaxation occurs.
  • Status: \(A(8, D)\), \(B(13, C)\).

Iteration 4:

  • Minimum key in \(Q\) is \(A\) with \(d[A] = 8\). Extract \(A\); \(S_{sol} = \{S, D, C, A\}\).
  • Inspect outgoing directed edges from \(A\):
  • Edge \((A, B)\): \(d[A] + w(A, B) = 8 + 1 = 9\). Since \(9 < 13\), relax: \(d[B] \gets 9\), \(\pi[B] \gets A\).
  • Status: \(B(9, A)\).

Iteration 5:

  • Minimum key in \(Q\) is \(B\) with \(d[B] = 9\). Extract \(B\); \(S_{sol} = \{S, D, C, A, B\}\).
  • Inspect outgoing directed edge \((B, C)\): \(d[B] + w(B, C) = 9 + 4 = 13\). Current \(d[C] = 7\). Since \(13 \ge 7\), no update occurs.
  • Queue \(Q\) is now empty. The algorithm terminates.

Final Distance Vector and Shortest Paths:

  • Shortest distance to \(S\): 0 (path: \(S\))
  • Shortest distance to \(D\): 5 (path: \(S \to D\))
  • Shortest distance to \(C\): 7 (path: \(S \to D \to C\))
  • Shortest distance to \(A\): 8 (path: \(S \to D \to A\))
  • Shortest distance to \(B\): 9 (path: \(S \to D \to A \to B\))

Shortest distance to \(B\): 9 (path: \(S \to D \to A \to B\)). Sense-check: Destination \(B\) can be reached via paths \(S \to A \to B\) (cost \(10+1=11\)), \(S \to D \to B\) (cost \(5+9=14\)), \(S \to D \to C \to B\) (cost \(5+2+6=13\)), and \(S \to D \to A \to B\) (cost \(5+3+1=\mathbf{9}\)). The path found achieves the absolute minimal cost.

Exam note: Students must show the complete state of the distance vector and predecessor array at each iteration, followed by explicit path reconstruction from destination back to source. When answering exam problems, present a clean table showing the distance and parent values after each vertex extraction.

14.4.4 Worked Example 2: Seven-Vertex Graph SSSP and Path Backtracking

Worked Example: Seven-Vertex SSSP and Predecessor Backtracking Consider a second weighted directed graph with 7 vertices: \(V = \{A, B, C, D, E, F, G\}\), with source vertex \(A\).

  1. Initialization: \(d[A] = 0\); all other \(d[v] = \infty\); all \(\pi[v] = \text{NIL}\).
  2. Extract \(A\) (\(d[A] = 0\)): Relax outgoing edges to \(B\) (\(d[B] \gets 10, \pi[B] \gets A\)) and \(C\) (\(d[C] \gets 5, \pi[C] \gets A\)).
  3. Extract \(C\) (\(d[C] = 5\)): Relax outgoing edges:
  • To \(F\): \(d[F] \gets 5 + 2 = 7, \pi[F] \gets C\).
  • To \(D\): \(d[D] \gets 5 + 5 = 10, \pi[D] \gets C\).
  • To \(B\): \(5 + 3 = 8\). Since \(8 < 10\), relax \(d[B] \gets 8, \pi[B] \gets C\).
  1. Extract \(F\) (\(d[F] = 7\)): Relax outgoing edges:
  • To \(E\): \(d[E] \gets 7 + 4 = 11, \pi[E] \gets F\).
  • To \(G\): \(d[G] \gets 7 + 5 = 12, \pi[G] \gets F\).
  1. Extract \(B\) (\(d[B] = 8\)): Outgoing edge to \(E\) has weight 1: \(d[B] + w(B, E) = 8 + 1 = 9\). Since \(9 < 11\), relax \(d[E] \gets 9, \pi[E] \gets B\).
  2. Extract \(E\) (\(d[E] = 9\)): Evaluates edges to remaining neighbors; no improvements discovered.
  3. Extract \(D\) (\(d[D] = 10\)) and \(G\) (\(d[G] = 12\)): Final extractions confirm optimal path weights.

Predecessor Path Backtracking: Once the algorithm terminates, we reconstruct the shortest path from source \(A\) to destination \(G\) by following parent pointers backward from destination to source: Path to \(G\): predecessor is \(E\), predecessor of \(E\) is \(B\), predecessor of \(B\) is \(C\), predecessor of \(C\) is \(A\).

Reversing the chain gives the complete forward shortest path:

\[ A \to C \to B \to E \to G \quad (\text{Total distance: } 5 + 3 + 1 + 3 = 12) \]

Other shortest paths reconstructed identically:

  • Path to \(E\): \(A \to C \to B \to E\) (distance 9)
  • Path to \(B\): \(A \to C \to B\) (distance 8)
  • Path to \(C\): \(A \to C\) (distance 5)
  • Path to \(F\): \(A \to C \to F\) (distance 7)
  • Path to \(D\): \(A \to C \to D\) (distance 10)

14.4.5 Student Inquiries, Negative Weights, and Self-Loops

Q: In Dijkstra's relaxation step, why is strict inequality required, and what happens if the new path distance equals the existing distance?

A: Strict inequality (\(d[v] > d[u] + w(u, v)\)) ensures that an update is executed only when an objectively superior (strictly shorter) path is discovered. If the candidate path achieves the identical distance (\(d[u] + w(u, v) = d[v]\)), performing an update provides zero improvement to the objective function. Leaving the existing distance and predecessor pointer intact avoids unnecessary memory writes, prevents thrashing in priority queue keys, and ensures deterministic path reconstruction.

Q: Does Dijkstra's algorithm work if the graph contains edges with negative weights?

A: No. Dijkstra's algorithm relies fundamentally on the greedy choice property: once a vertex \(u\) is extracted from the min-priority queue, its distance estimate \(d[u]\) is assumed to be permanently optimal (\(d[u] = \delta(s, u)\)). If an edge has a negative weight (\(w(e) < 0\)), traversing that edge later could decrease the total path cost below an already-finalized distance, invalidating the greedy assumption. Furthermore, if the graph contains a negative-weight cycle reachable from the source, path costs can decrease infinitely (\(-\infty\)).

The professor cautions emphatically: "negative weights are there dykstra's will give you wrong answer". When negative edge weights exist, specialized algorithms such as the Bellman-Ford algorithm (running in \(O(|V| \cdot |E|)\) time) must be used instead, as Bellman-Ford correctly detects negative-weight cycles and updates paths across multiple relaxation passes.

Q: How does Dijkstra's algorithm handle self-loops where an edge connects a vertex to itself?

A: Dijkstra's algorithm inherently handles self-loops without any special logic. For any self-loop \((u, u)\) with non-negative weight \(w(u, u) \ge 0\):

\[ d[u] + w(u, u) \ge d[u] \]

Because \(w(u, u) \ge 0\), the sum \(d[u] + w(u, u)\) can never be strictly less than \(d[u]\). Therefore, the strict relaxation condition \(d[u] > d[u] + w(u, u)\) is never satisfied, and the self-loop is automatically discarded.

Common Pitfalls:

  1. Running Dijkstra's Algorithm with Negative Weights: Even a single negative edge can lead to incorrect shortest path distances because Dijkstra's algorithm never re-evaluates a vertex once extracted from the priority queue.
  2. Confusing Dijkstra's Key Update with Prim's Algorithm:
  • In Prim's algorithm, the key is updated to the edge weight: \(D[v] \gets w(u, v)\).
  • In Dijkstra's algorithm, the key is updated to the cumulative path distance: \(d[v] \gets d[u] + w(u, v)\).

Accidentally omitting \(d[u]\) is the most frequent beginner implementation bug.

  1. Failing to Halt on Disconnected Vertices: If a vertex \(v\) is unreachable from source \(s\), its distance remains \(\infty\). An implementation must check for \(\infty\) before attempting arithmetic to avoid integer overflow errors.

Asymptotic Complexity Analysis: The time complexity of Dijkstra's algorithm depends on the data structure used for the min-priority queue \(Q\):

  • Array / Linear Scan: \(O(|V|^2)\). Optimal for dense graphs where \(|E| \approx |V|^2\).
  • Binary Min-Heap:

\[ T(|V|, |E|) = O((|V| + |E|) \log |V|) \]

Each of the \(|V|\) vertices is extracted once (\(O(|V| \log |V|)\)), and each of the \(|E|\) edges triggers at most one Decrease-Key operation (\(O(|E| \log |V|)\)). For connected graphs where \(|E| \ge |V| - 1\), this simplifies to \(O(|E| \log |V|)\).
- Fibonacci Heap: \(O(|E| + |V| \log |V|)\), where Decrease-Key runs in amortized \(O(1)\) time.

Recap & Bridge: Dijkstra's algorithm solves the single-source shortest path problem on graphs with non-negative edge weights in \(O(|E| \log |V|)\) time by combining source initialization, priority queue extraction, and strict relaxation. Predecessor pointers record the optimal path tree, enabling linear-time backtracking from any destination back to the origin.

In enterprise network infrastructure, Dijkstra's algorithm powers core Internet routing protocols, including Open Shortest Path First (OSPF) and Intermediate System to Intermediate System (IS-IS). Autonomous routers exchange link-state advertisements (LSAs) describing network topology and bandwidth metrics. Each router independently executes Dijkstra's algorithm to compute the shortest latency forwarding path to every network subnet, populating its hardware IP routing table for high-speed packet switching.

7.1 Foundations of Graphs and Graph Definitions

A graph is a non-linear data structure. It is defined as a pair \(G = (V, E)\). Here, \(V\) is a set of vertices (also called nodes), and \(E\) is a collection of edges connecting pairs of vertices. Trees organize data with parent-child links and no loops. Graphs remove these limits. They allow arbitrary connections, loops, and disconnected parts.

Why do linear data structures like arrays and linked lists, and hierarchical structures like trees, fail when modeling complex interconnected systems like flight networks or power grids? Trees strictly demand a single root and forbid closed loops, while real-world networks feature interconnected bypasses, multiple alternative routes, and cyclic redundancy. Graphs provide the mathematical language to represent these unrestricted relationship topologies.

7.1.1 Formal Definition of a Graph

A graph consists of vertices and connecting edges. The formal definition is:

\[ G = (V, E) \]

where \(V\) is a finite set of vertices \(V = \{v_1, v_2, \dots, v_n\}\), and \(E\) is a set of edges \(E = \{e_1, e_2, \dots, e_m\}\). Each edge connects a pair of vertices from \(V\). The number of vertices is denoted by \(|V| = n\), and the number of edges is denoted by \(|E| = m\).

Formal Specification: A graph is simply a pair of vertices and edges... a graph is none other than a combination of vertices and edges where vertices is some set of nodes... and E is none other than collection of pair of vertices called edges.

  • Vertex set \(V\): A non-empty set of discrete entities or objects, \(V = \{v_1, v_2, \dots, v_n\}\).
  • Edge set \(E\): A collection of links connecting pairs of vertices, \(E = \{e_1, e_2, \dots, e_m\}\). Each edge \(e_k = (u, v)\) or \(e_k = \{u, v\}\) identifies a relationship between endpoint vertices \(u, v \in V\).
  • Labeling functions: Both vertices and edges can hold labels or payload attributes. For instance, a vertex label can store an airport code (e.g., SFO, LAX, MIA), while an edge label can store numerical weights such as geographical distance, flight duration, or monetary cost.

Vertices store data items or objects. Edges represent relationships or links between them. Both vertices and edges can hold labels. For example, a vertex label can store an airport code. An edge label can store distance, travel time, or cost.

7.1.2 Graphs versus Trees

A common point of confusion is the link between trees and graphs. Many people think a graph must have cycles that start and end at the same node. But that is not required. Any collection of vertices linked by edges is a graph.

Trees are a strict subset of graphs:

\[ \text{Trees} \subset \text{Graphs} \]

Every tree is an undirected, connected graph with no cycles. Stripping the root and parent-child terms from a tree leaves a valid graph. All trees are graphs, but not all graphs are trees. General graphs can have cycles or disconnected components.

Scope & Applicability Boundaries:

  • Trees as Acyclic Graphs: A tree is formally defined as a minimally connected, acyclic undirected graph. For any tree with \(n\) vertices, the number of edges is strictly \(m = n - 1\). Removing any edge disconnects the tree, and adding any new edge introduces an unambiguous cycle.
  • General Graph Freedom: General graphs impose no connectivity or acyclic constraints. A graph may have multiple disconnected components, isolated vertices with degree zero, multiple cycles, or redundant parallel edges.

Common Pitfalls:

  • Cycle Requirement Myth: Many people think a graph must have cycles that start and end at the same node. But that is not required. Any collection of vertices linked by edges is a graph, including disconnected nodes or linear chains.
  • Hierarchical Bias: Assuming a graph must possess a designated "root" vertex. Graphs are non-hierarchical by default unless an arbitrary traversal origin is chosen.
  • Empty Graph Confusion: While standard conventions require \(V \neq \emptyset\), the edge set can be empty (\(E = \emptyset\)). An edgeless graph with \(n\) isolated vertices is mathematically well-defined.

7.1.3 Real-World Network Analogies

Many real-world networks map directly to graphs:

Real-world: In an airline route network, airports represent vertices (such as San Francisco, Los Angeles, and Miami). Flight paths between airports represent edges. The physical distance between cities serves as the edge weight.

Real-world: In rail and road networks, train stations or road intersections act as vertices. Tracks or road segments form edges between them.

Real-world: In cellular systems, Base Transceiver Station (BTS) towers serve as network nodes. Mobile phones talk wirelessly to towers, but the towers connect to each other through physical optical fiber cables (OFC). The fiber cables form the physical edges.

Real-world: In social networks, user profiles represent vertices. Friendships or follower links form the edges.

Worked Example — Modeling an Airline Transportation Network: Consider a regional air transportation system serving 5 major hub cities: San Francisco (SFO), Los Angeles (LAX), Miami (MIA), Chicago (ORD), and New York (JFK).

  • Vertex set \(V\):

\[ V = \{\text{SFO}, \text{LAX}, \text{MIA}, \text{ORD}, \text{JFK}\} \implies |V| = n = 5 \]

  • Weighted Edge set \(E\) (with non-stop flight nautical miles as weights \(w\)):

\[ E = \{ (\text{SFO}, \text{LAX}, 337), (\text{SFO}, \text{ORD}, 1846), (\text{LAX}, \text{MIA}, 2342), (\text{ORD}, \text{JFK}, 740), (\text{MIA}, \text{JFK}, 1089) \} \implies |E| = m = 5 \]

  • Step-by-Step Topology Analysis:
  1. Connectivity: Every airport has at least one scheduled flight connection.
  2. Degree calculation: \(\deg(\text{SFO}) = 2\), \(\deg(\text{LAX}) = 2\), \(\deg(\text{ORD}) = 2\), \(\deg(\text{MIA}) = 2\), \(\deg(\text{JFK}) = 2\). Every vertex has degree 2.
  3. Cycle check: Tracing the path \(\text{SFO} \to \text{ORD} \to \text{JFK} \to \text{MIA} \to \text{LAX} \to \text{SFO}\) yields a simple cycle of length 5 spanning all vertices.
  • Sense Check: The edge count \(m = 5\) equals the vertex count \(n = 5\). Since \(m \ge n\), the graph contains at least one cycle and is therefore not a tree.

7.1.4 Student Questions and Answers

Q: Can family relationships be modeled as a graph rather than a tree?

A: Family relationships are typically structured as a family tree where generations descend without forming cycles between ancestral lines. However, because every tree is strictly a subset of a graph, family trees are technically valid acyclic graphs. Transportation and network topologies provide more direct examples of general graphs with cyclic paths.

A graph \(G = (V, E)\) generalizes trees by removing hierarchical constraints and acyclic restrictions. Vertices represent discrete objects and edges encode pairwise relationships, providing the structural bedrock for modern computational network modeling.

7.2 Directed versus Undirected Graphs

Graphs fall into two main types based on edge directions: undirected graphs and directed graphs (also called digraphs).

Does a connection between two nodes always mean traffic can flow in both directions? In street layouts, two intersections may be linked by a two-way avenue or a strict one-way street. In data engineering, asymmetric relationships fundamentally alter data flow, path reachability, and search mechanics.

7.2.1 Structural Definitions and Mathematical Representation

In an undirected graph, each edge is an unordered pair of vertices:

\[ e = \{u, v\} = \{v, u\} \]

where \(u, v \in V\). If an edge links vertex \(u\) and vertex \(v\), you can travel both ways. You can move from \(u\) to \(v\), and from \(v\) to \(u\). The edge represents a two-way link.

In a directed graph (digraph), each edge is an ordered pair of vertices:

\[ e = (u, v) \]

where \(u \in V\) is the source vertex, and \(v \in V\) is the target vertex. Movement along this edge goes only from \(u\) to \(v\). You cannot move from \(v\) to \(u\) unless an edge \((v, u)\) exists.

The verbal explanation outlines this directional rule: "Let us have got a node u and a node v which are connected... I wanted to always say your first visit should be u and then v... then I am putting some constraint that u should always be your start node and v should be your end node... connection is from u to v, but not from v to u."

A graph is a directed graph when all edges have designated directions.

Formal Mathematical Properties:

  • Undirected Edge: An unordered set \(e = \{u, v\}\). Traversal is symmetric: path existence from \(u\) to \(v\) automatically guarantees path existence from \(v\) to \(u\). The maximum number of edges in a simple undirected graph with \(n\) vertices is:

\[ |E_{\max}| = \binom{n}{2} = \frac{n(n - 1)}{2} \]

  • Directed Edge (Arc): An ordered tuple \(e = (u, v)\), where \(u\) is the origin (tail) and \(v\) is the destination (head). In general, \((u, v) \neq (v, u)\). The maximum number of edges in a simple directed graph without self-loops is:

\[ |E_{\max}| = n(n - 1) \]

  • Degree Distribution: In an undirected graph, each vertex has a single degree \(\deg(v)\). In a directed graph, vertex degree splits into in-degree \(\deg^-(v)\) (number of incoming edges arriving at \(v\)) and out-degree \(\deg^+(v)\) (number of outgoing edges leaving \(v\)):

\[ \deg(v) = \deg^-(v) + \deg^+(v) \]

The structural contrasts between both paradigms are summarized below:

Dimension Undirected Graph Directed Graph (Digraph)
Edge Representation Unordered set \(\{u, v\}\) Ordered pair \((u, v)\)
Traversal Symmetry Bidirectional (two-way) Unidirectional (one-way unless antiparallel edge exists)
Maximum Edges (\(n\) vertices) \(\frac{n(n - 1)}{2}\) \(n(n - 1)\)
Degree Classification Total degree \(\deg(v)\) In-degree \(\deg^-(v)\) and Out-degree \(\deg^+(v)\)
Handshaking Lemma \(\sum_{v \in V} \deg(v) = 2|E|\) \(\sum_{v \in V} \deg^+(v) = \sum_{v \in V} \deg^-(v) = |E|\)

Scope & Boundary Conditions:

  • Asymmetric Reachability: In a directed graph, the existence of a path from vertex \(u\) to vertex \(v\) does not imply a path from \(v\) to \(u\).
  • Self-Loops in Digraphs: A self-loop in a digraph is an edge \((u, u)\) where origin and destination coincide, contributing 1 to \(\deg^+(u)\) and 1 to \(\deg^-(u)\).
  • Mixed Graphs: In systems where some links are two-way and others are one-way, standard algorithms convert every undirected edge \(\{u, v\}\) into two opposing directed arcs \((u, v)\) and \((v, u)\).

7.2.2 Real-World Distinctions: Communication and Transportation Networks

Directional rules reflect real constraints in engineering systems:

Real-world: In air travel, the flight distance between city \(A\) and city \(B\) is undirected. The physical distance is symmetric. But a scheduled flight with a specific flight number from \(A\) to \(B\) is directed.

Real-world: In local computer networks, internet links act as undirected graphs. Data packets travel both ways between client devices and local routers.

Real-world: In radio and FM broadcasting, the transmission forms a directed graph. The central tower broadcasts signals outward to consumer radios. The radios cannot send signals back to the tower. The channel is one-way.

Real-world: In hardware design, printed circuit boards (PCBs) and integrated circuits (ICs) route electrical pulses along directed paths. In software, database Entity-Relationship (ER) models use graphs to define table relations.

Worked Example — Analyzing Directed versus Undirected Topologies: Consider a set of 4 server nodes \(V = \{1, 2, 3, 4\}\).

  • Undirected Network \(G_U = (V, E_U)\):

\[ E_U = \{\{1, 2\}, \{2, 3\}, \{3, 4\}, \{4, 1\}\} \]

  1. Total Edges: \(|E_U| = 4\). Maximum possible edges: \(\frac{4 \times 3}{2} = 6\).
  2. Degree Analysis: \(\deg(1) = 2, \deg(2) = 2, \deg(3) = 2, \deg(4) = 2\).
  3. Handshaking Verification: \(\sum \deg(v) = 2 + 2 + 2 + 2 = 8 = 2|E_U|\).
  • Directed Network \(G_D = (V, E_D)\):

\[ E_D = \{(1, 2), (2, 3), (3, 4), (4, 1), (1, 3)\} \]

  1. Total Edges: \(|E_D| = 5\). Maximum possible edges: \(4 \times 3 = 12\).
  2. Degree Breakdown:
  • Vertex 1: \(\deg^+(1) = 2\) (edges to 2 and 3), \(\deg^-(1) = 1\) (edge from 4).
  • Vertex 2: \(\deg^+(2) = 1\) (edge to 3), \(\deg^-(2) = 1\) (edge from 1).
  • Vertex 3: \(\deg^+(3) = 1\) (edge to 4), \(\deg^-(3) = 2\) (edges from 1 and 2).
  • Vertex 4: \(\deg^+(4) = 1\) (edge to 1), \(\deg^-(4) = 1\) (edge from 3).
  1. Sum Verification: \(\sum \deg^+(v) = 2 + 1 + 1 + 1 = 5 = |E_D|\), and \(\sum \deg^-(v) = 1 + 1 + 2 + 1 = 5 = |E_D|\).
  • Sense Check: Node 1 can reach node 2 via direct edge \((1, 2)\), but node 2 cannot reach node 1 directly since \((2, 1) \notin E_D\). Node 2 must traverse \(2 \to 3 \to 4 \to 1\), demonstrating how directionality governs traversal path lengths.

Common Pitfalls:

  • Assuming Edge Symmetry: Treating \((u, v)\) and \((v, u)\) as identical. In directed graphs, \((u, v)\) permits flow strictly from \(u\) to \(v\).
  • Forgetting Degree Division: Forgetting that directed graphs possess separate in-degree and out-degree values, and using total degree where directional flow is required.
  • Overcounting Handshaking: Applying \(\sum \deg(v) = 2|E|\) directly to directed graphs without separating in-degree and out-degree sums.

7.2.3 Student Questions and Answers

Q: Would a rail network be considered a directed or undirected graph?

A: The classification depends on the operational rules modeled. If train tracks allow two-way transit between stations, the track layout is undirected. If lines operate as strict one-way tracks or if the graph represents specific train schedules moving from an origin to a destination, it is modeled as a directed graph.

Q: Why is radio transmission considered a directed graph while local internet communication is undirected?

A: Radio transmission is a one-way broadcast. The central transmission tower sends signals to receiving radios, but the receiving radios cannot transmit audio back to the tower. Local internet networks require bidirectional two-way communication to exchange request and response packets.

The choice between directed and undirected graphs is dictated by system physics and operational logic: symmetric relationships yield undirected graphs, whereas asymmetric flows require directed graphs with separated in-degree and out-degree properties.

7.3 Graph Terminology and Structural Properties

Standard terms describe how vertices and edges connect in a graph.

Think of a road network to understand graph structural relationships: towns are vertices and roads are edges. A road is incident to the two towns it links, making those towns directly adjacent. The degree of a town is the total number of roads meeting at its central roundabout. A self-loop is a scenic ring-road that departs and returns to the same town without passing through any intermediate city.

7.3.1 Endpoints, Incidence, Adjacency, and Degree

Every edge connects two vertices. These vertices are the endpoints of the edge:

  • Endpoints: For an edge \(e = (u, v)\), vertices \(u\) and \(v\) are its endpoints. For edge \(a\) linking vertices \(U\) and \(V\), \(U\) and \(V\) are the endpoints of \(a\).
  • Incident Edges: An edge is incident to a vertex if that vertex is one of its endpoints. If vertex \(V\) links to \(U, W, X\) via edges \(a, d, b\), then edges \(a, d, b\) are incident to \(V\).
  • Adjacent Vertices: Two vertices are adjacent (or neighbors) if a single edge connects them. If an edge connects \(X\) and \(Y\), then \(X\) and \(Y\) are adjacent. If no edge links \(X\) and \(U\), they are not adjacent.
  • Degree of a Vertex: The degree of a vertex \(v\) in an undirected graph, written \(\deg(v)\), is the number of edges incident to \(v\):

\[ \deg(v) = |\{e \in E : v \in e\}| \]

where \(v \in V\) is the vertex being evaluated.

The verbal explanation describes counting degree: "The degree of vertex is how many edges the vertex is connected... now when you take X, X is connected with one, two, three, four, and five edges... all those five edges or the number of edges which it is connected is simply called the degree of the particular node X."

Formal Structural Theorems:

  • Handshaking Lemma: In any undirected graph \(G = (V, E)\), the sum of vertex degrees is exactly twice the total number of edges:

\[ \sum_{v \in V} \deg(v) = 2|E| \]

Proof: Every edge \(e = \{u, v\}\) has exactly two endpoints, contributing 1 to \(\deg(u)\) and 1 to \(\deg(v)\). Summing degrees over all vertices counts every edge exactly twice.

  • Self-Loop Degree Contribution: In an undirected graph, a self-loop \(e = \{v, v\}\) touches vertex \(v\) at both ends, adding 2 to \(\deg(v)\).
  • Even Degree Theorem: Every undirected graph contains an even number of vertices with odd degree.

7.3.2 Parallel Edges and Self-Loops

Special edges create distinct graph topologies:

  • Parallel Edges: Two or more edges are parallel edges (or multiple edges) if they share the exact same endpoints. For example, if two edges \(h\) and \(i\) both connect vertices \(X\) and \(Z\), they are parallel edges.
  • Self-Loop: A self-loop is an edge whose two endpoints are the same vertex. If edge \(j\) connects vertex \(Z\) directly back to \(Z\), then \(j\) is a self-loop.

A self-loop is an edge with identical endpoints, such that \(e = (Z, Z)\). It differs from a general cycle because it visits no intermediate nodes.

7.3.3 Paths, Simple Paths, Cycles, and Simple Cycles

Paths trace movement through a graph:

  • Path: A path is an alternating sequence of vertices and edges that starts at a vertex and ends at a vertex:

\[ P = (v_0, e_1, v_1, e_2, \dots, e_k, v_k) \]

where each edge \(e_i\) connects vertex \(v_{i-1}\) to \(v_i\). In an unweighted graph, a path is written as a sequence of vertices \((v_0, v_1, \dots, v_k)\). The length of path \(P\) is the number of edges traversed, \(k\).

  • Simple Path: A path is a simple path if all vertices in the sequence are distinct. No vertex is visited more than once:

\[ v_i \neq v_j \quad \text{for all } i \neq j \]

  • Cycle: A cycle is a path whose start vertex and end vertex are the same:

\[ v_0 = v_k \quad \text{with } k \ge 1 \]

A path starts and ends at different vertices. A cycle starts and ends at the exact same vertex.

  • Simple Cycle: A cycle is a simple cycle if all intermediate vertices are distinct:

\[ v_i \neq v_j \quad \text{for all } 0 \le i < j < k \]

No node is visited more than once, except for the shared start and end vertex.

Scope & Taxonomic Classification:

  • Simple Graph: A graph containing no parallel edges and no self-loops.
  • Multigraph: A graph that permits parallel edges between the same pair of vertices, but disallows self-loops.
  • Pseudograph: A generalized graph structure permitting both parallel edges and self-loops.

7.3.4 Worked Examples: Identifying Paths, Cycles, and Degrees

Consider a sample graph with vertices \(\{U, V, W, X, Y, Z\}\) and labeled edges:

Worked Example 1 — Endpoints, Incidence, and Degree Calculation:

  • Edge \(a\) connects vertices \(U\) and \(V\). The endpoints of \(a\) are \(U\) and \(V\).
  • Edge \(d\) connects vertices \(W\) and \(V\). The endpoints of \(d\) are \(W\) and \(V\).
  • Vertex \(X\) connects to five edges: one to \(V\), one to \(W\), one to \(Y\), and parallel edges \(h\) and \(i\) to \(Z\). So, \(\deg(X) = 5\).
  • Edge \(j\) starts at vertex \(Z\) and ends at \(Z\). Edge \(j\) is a self-loop.
  • Sense Check: The degree of \(X\) is verified by direct enumeration of incident edges: \(\{b, e, f, h, i\}\). The cardinality is exactly 5.

Worked Example 2 — Simple Path versus Non-Simple Path:

  • Walkthrough A: Consider the sequence \(V \to X \to Z\). The path starts at \(V\), visits \(X\), and ends at \(Z\). Every vertex appears once. This sequence is a valid simple path of length 2.
  • Walkthrough B: Consider the sequence \(U \to W \to X \to Y \to W \to V\). Node \(W\) appears twice in this sequence. Because node \(W\) is revisited, this sequence is a path, but not a simple path.
  • Sense Check: In Walkthrough B, vertex \(W\) occurs at index 1 and index 4. The definition \(v_i \neq v_j\) for \(i \neq j\) is violated, proving the path is non-simple.

Worked Example 3 — Simple Cycle Identification:

  • Walkthrough: Consider the sequence \(V \to X \to Y \to W \to U \to V\). The start node \(V\) matches the end node \(V\). The intermediate nodes \(\{X, Y, W, U\}\) are all distinct. This sequence forms a valid simple cycle of length 5.
  • Sense Check: Start vertex \(v_0 = V\) and end vertex \(v_5 = V\). All intermediate vertices \(v_1 = X, v_2 = Y, v_3 = W, v_4 = U\) are mutually distinct. Thus, the sequence satisfies \(v_0 = v_k\) and \(v_i \neq v_j\) for \(0 \le i < j < k\).

Common Pitfalls:

  • Self-Loop versus Cycle Confusion: A self-loop is an edge with identical endpoints, such that \(e = (Z, Z)\). It differs from a general cycle because it visits no intermediate nodes.
  • Off-by-One in Path Length: Defining path length by vertex count instead of edge count. A path visiting \(k+1\) vertices has length \(k\).
  • Double-Counting Degrees: Miscounting the Handshaking Lemma sum by forgetting that each edge touches two endpoints or counts as 2 on a single self-loop.

Vertex degrees, path simplicity, and cycle definitions determine the topological properties of a graph. The Handshaking Lemma guarantees that the sum of all vertex degrees always equals \(2|E|\).

7.4 Subgraphs, Connectivity, and Spanning Trees

Subgraphs and connectivity define how parts of a network interact.

What is the bare minimum infrastructure required to keep an entire distributed network connected without isolated islands? If a telecommunications engineer wants to link \(n\) communication hubs with the minimum number of fiber cables while guaranteeing every hub can communicate with every other hub, what structure must be built? The answer is a spanning tree with exactly \(n - 1\) edges.

7.4.1 Subgraphs and Vertex/Edge Subsets

A graph \(S = (V_S, E_S)\) is a subgraph of \(G = (V, E)\) if its vertices and edges are subsets of \(G\):

\[ V_S \subseteq V \quad \text{and} \quad E_S \subseteq E \]

Every edge in \(E_S\) must connect vertices that belong to \(V_S\).

The verbal explanation outlines this rule: "S is called a subgraph of G if S contains vertices such that the S vertices are subset of G and the edges are also subset of G."

Formal Definitions of Subgraphs and Connectivity:

  • General Subgraph: A graph \(S = (V_S, E_S)\) is a subgraph of \(G = (V, E)\) if and only if \(V_S \subseteq V\), \(E_S \subseteq E\), and for every edge \(e \in E_S\), both endpoints of \(e\) reside in \(V_S\).
  • Induced Subgraph: A subgraph \(S\) is an induced subgraph if \(E_S\) contains all edges of \(G\) whose endpoints are both in \(V_S\).
  • Connected Graph: An undirected graph \(G\) is connected if there exists at least one path between every pair of distinct vertices \(u, v \in V\). Otherwise, \(G\) is disconnected, partitioned into \(k \ge 2\) maximal connected components.
  • Spanning Subgraph: A subgraph \(S = (V_S, E_S)\) is a spanning subgraph of \(G = (V, E)\) if it contains all original vertices:

\[ V_S = V \quad \text{and} \quad E_S \subseteq E \]

  • Spanning Tree: A connected, acyclic spanning subgraph of \(G\). A spanning tree touches every vertex in \(V\) using the minimal possible number of edges.

7.4.2 Connected versus Disconnected Graphs and Image Segmentation

An undirected graph is connected if a path exists between every pair of vertices. If any two vertices cannot reach each other, the graph is disconnected. A disconnected graph consists of two or more separate connected components.

Real-world: In phone cameras, image processing separates foreground people from background scenery using graph partitions. Pixels act as vertices, and color differences form edges. Disconnecting the graph separates the portrait subject from the background.

Exam note: Graph partitioning methods like the Min-Max Cut algorithm are useful real-world tools in computer vision. However, the Min-Max Cut algorithm is not on the exam.

7.4.3 Spanning Subgraphs and Spanning Trees

A spanning subgraph of \(G = (V, E)\) contains all vertices of \(G\):

\[ V_{\text{span}} = V \quad \text{and} \quad E_{\text{span}} \subseteq E \]

A spanning tree is a connected spanning subgraph with no cycles. It connects all \(n\) vertices using the fewest possible edges. A single graph can have several distinct spanning trees.

7.4.4 Mathematical Formulation: Minimum Edges for Connectivity

Connecting a graph of \(n\) vertices requires a minimum number of edges:

\[ |E_{\min}| = |V| - 1 = n - 1 \]

where \(n = |V|\) is the total number of vertices, and \(|E_{\min}|\) is the minimum edge count needed for connectivity.

The verbal explanation outlines this minimum: "Can you draw me a graph which uses the minimal number of edges and still we call it as a connected graph... the minimal number of edges that I need to say that my graph is connected is if N is your number of vertices, N minus 1 edges is needed to say graph as connected."

If a graph with \(n\) vertices has fewer than \(n - 1\) edges, it is disconnected. If it has \(n - 1\) edges and is connected, it is a spanning tree.

Scope & Boundary Conditions:

  • Necessary vs Sufficient: Having \(n - 1\) edges is a necessary condition for a connected graph of \(n\) vertices, but not a sufficient one. If the \(n - 1\) edges contain a cycle, the graph will have at least one disconnected isolated vertex.
  • Disconnected Components: If an undirected graph has \(n\) vertices and \(c\) connected components, the minimum edge count required to sustain those components is \(|E| \ge n - c\).

7.4.5 Worked Examples: Validating Subgraphs and Spanning Trees

Worked Example 1 — Validating Subgraph Inclusion:

  • Setup: Graph \(G\) has vertices \(V = \{A, B, C, D, E\}\) and edges \(E = \{1, 2, 3, 4, 5, 6, 7, 8\}\).
  • Candidate 1: Subgraph \(S_1\) has vertices \(V_1 = \{A, D, C\}\) and edges \(E_1 = \{2, 4, 5\}\). Here, \(\{A, D, C\} \subseteq V\) and \(\{2, 4, 5\} \subseteq E\). So, \(S_1\) is a valid subgraph.
  • Candidate 2: Subgraph \(S_2\) has vertices \(V_2 = \{A, D, C\}\) and edges \(E_2 = \{9, 11, 12\}\). The vertices match, but edges \(9, 11, 12\) are not in \(E\). So, \(S_2\) is not a subgraph of \(G\).
  • Sense Check: Both conditions \(V_S \subseteq V\) and \(E_S \subseteq E\) must simultaneously hold true. Candidate 2 fails edge containment.

Worked Example 2 — Minimum Edges for a 5-Vertex Connected Graph:

  • Setup: Consider a graph with \(n = 5\) vertices.
  • Calculation: The minimum number of edges is \(|E_{\min}| = n - 1 = 5 - 1 = 4\) edges.
  • Conclusion: Any tree connecting these 5 vertices has four edges.
  • Sense Check: Removing any one of the 4 edges splits the graph into two disconnected components. Adding a 5th edge between any existing pair of vertices creates a cycle.

Common Pitfalls:

  • External Edge Injection: Creating candidate subgraphs that introduce new edges not present in the master graph \(E\).
  • Assuming n-1 Edges Always Implies Connectivity: Forgetting that an \(n\)-vertex graph with \(n-1\) edges can be disconnected if some edges form closed cycles, leaving other vertices stranded.
  • Confusing Spanning Subgraph with Spanning Tree: A spanning subgraph may still contain cycles and have more than \(n - 1\) edges; a spanning tree must be minimally connected and strictly acyclic.

7.4.6 Student Questions and Answers

Q: In the definition of a subgraph, what does it mean that some edges must be a subset of the original edges?

A: A valid subgraph requires that both the vertex set and the edge set are subsets of the original graph. If you select a valid subset of vertices like \(\{A, D, C\}\) from an original graph, but connect them using new edges labeled \(9, 11, 12\) that never existed in the original graph's edge set, it fails to be a subgraph. All edges in the subgraph must come directly from the original graph's edge set and connect vertices within the chosen subset.

Subgraphs inherit a subset of vertices and edges from a parent graph. To maintain connectivity across \(n\) vertices, at least \(n - 1\) edges are mandatory; a connected subgraph with exactly \(n - 1\) edges is a spanning tree.

7.5 Graph Storage and Representation in Data Structures

Graph representations balance storage space and search speed. The three main representations are the adjacency matrix, the adjacency list, and the edge list.

If a global social network of 3 billion users stored relationships in a 2D adjacency matrix, the table would require \(9 \times 10^{18}\) entries (exabytes of memory) for a graph that is over 99.999% zeros! How do systems engineers balance instantaneous \(O(1)\) edge lookups against memory-efficient sparse link chains?

7.5.1 Adjacency Matrix Formulation

An adjacency matrix represents a graph with \(n = |V|\) vertices as an \(n \times n\) square grid \(M\):

\[ M \in \{0, 1\}^{n \times n} \]

where row \(i\) and column \(j\) correspond to vertices \(v_i\) and \(v_j\). For an unweighted graph:

\[ M[i][j] = \begin{cases} 1, & \text{if } (v_i, v_j) \in E \\ 0, & \text{if } (v_i, v_j) \notin E \end{cases} \]

The verbal explanation outlines this matrix structure: "Adjacency matrix is always represent in n cross n matrix... if you have got eight vertices in your graph then we would be representing our graph with help of eight by eight matrices... with help of a node 1 which indicates that there is a connection between vertices 1 and 2 and if there is no connection I am representing with 0."

Special cases map into matrix cells:

  • Self-Loops: A self-loop on vertex \(v_i\) is recorded by setting \(M[i][i] = 2\) to distinguish the loop from an ordinary edge.
  • Weighted Edges: In a weighted graph, cell \(M[i][j]\) stores the weight \(w(v_i, v_j)\) rather than 1.
  • Directed Edges: In a directed graph, edge \((4, 6)\) with weight 5 sets \(M[4][6] = 5\). Opposing edge \((6, 4)\) with weight 8 sets \(M[6][4] = 8\).

Mathematical Properties of the Adjacency Matrix:

  • Symmetry in Undirected Graphs: For an undirected graph, \(M[i][j] = M[j][i]\) for all \(i, j\). The matrix is symmetric across its main diagonal, allowing compact storage of only the upper or lower triangular half (\(\frac{n(n + 1)}{2}\) cells).
  • Asymmetry in Directed Graphs: For a directed graph, \(M[i][j]\) represents the directed arc \((v_i, v_j)\). In general, \(M[i][j] \neq M[j][i]\).
  • Row and Column Sums:
  • In an undirected graph: \(\sum_{j=1}^n M[i][j] = \deg(v_i)\) (accounting for diagonal self-loops).
  • In a directed graph: Row sum \(\sum_{j=1}^n M[i][j] = \deg^+(v_i)\) (out-degree), and Column sum \(\sum_{i=1}^n M[i][j] = \deg^-(v_j)\) (in-degree).

7.5.2 Adjacency List Formulation

An adjacency list stores a graph as an array of linked lists. The array length equals the vertex count \(|V|\). Array slot \(A[i]\) points to a linked list of all vertices adjacent to vertex \(v_i\).

In an undirected graph, each edge \(\{u, v\}\) appears twice. Vertex \(v\) is in \(u\)'s list, and \(u\) is in \(v\)'s list. In a directed graph, vertex \(v\) appears in \(u\)'s list only if directed edge \((u, v)\) exists.

7.5.3 Edge List and Dictionary Representation

An edge list stores all edges as a list of pairs or triples: \((u, v)\) or \((u, v, w)\).

In modern languages, a hash dictionary often implements this structure. The dictionary maps each vertex to a list of its outgoing neighbors and weights. This allows dynamic growth without pre-allocating an \(n \times n\) matrix.

7.5.4 Space and Time Complexity Trade-Offs

Matrix and list representations offer distinct trade-offs:

\[ S_{\text{matrix}} = O(V^2) \quad \text{versus} \quad S_{\text{list}} = O(V + E) \]

where \(V = |V|\) is the vertex count and \(E = |E|\) is the edge count.

The verbal explanation describes this trade-off: "One disadvantage is pretty clear that it takes large amount of space... but why should someone use adjacency matrix... identification of connected edge vertices could be identified much faster... whether there exists an edge between any two vertices... is pretty fast. Disadvantage is space."

Operation / Metric Adjacency Matrix Adjacency List Edge List
Space Complexity \(O(V^2)\) \(O(V + E)\) \(O(E)\)
Edge Lookup \((u, v)\) \(O(1)\) instantaneous \(O(\deg(u))\) list traversal \(O(E)\) full scan
Enumerate Neighbors of \(u\) \(O(V)\) row scan \(O(\deg(u))\) list scan \(O(E)\) full scan
Insert Vertex \(O(V^2)\) reallocating grid \(O(1)\) appending list head \(O(1)\)
Insert Edge \((u, v)\) \(O(1)\) cell update \(O(1)\) prepending to node \(u\) \(O(1)\) appending record
Delete Edge \((u, v)\) \(O(1)\) zeroing cell \(O(\deg(u))\) removing node \(O(E)\) searching record
Optimal Graph Domain Dense graphs (\(E \approx V^2\)) Sparse graphs (\(E \ll V^2\)) Edge-centric algorithms (Kruskal)

Worked Example — Adjacency Matrix and List Representation of a Directed Weighted Graph: Consider a directed weighted graph with vertex set \(V = \{1, 2, 3, 4, 5, 6, 7, 8\}\). Suppose edge \((4, 6)\) carries weight 5, while the opposing edge \((6, 4)\) carries weight 8.

  • Matrix Entry Assignment:
  • In a directed graph, edge \((4, 6)\) with weight 5 sets \(M[4][6] = 5\). Opposing edge \((6, 4)\) with weight 8 sets \(M[6][4] = 8\).
  • Unconnected pairs default to 0 (or \(\infty\) in shortest-path algorithms).
  • Adjacency List Mapping:
  • In the adjacency list array \(Adj\):
  • \(Adj[4]\) contains tuple \((6, \text{weight}=5)\).
  • \(Adj[6]\) contains tuple \((4, \text{weight}=8)\).
  • Time Complexity Trace:
  • Querying whether edge \((4, 6)\) exists:
  • Matrix: Access \(M[4][6]\) directly \(\to O(1)\) time.
  • List: Scan linked list at \(Adj[4]\) for target 6 \(\to O(\deg^+(4))\) steps.
  • Sense Check: Because the graph is directed, \(M[4][6] = 5 \neq M[6][4] = 8\), confirming the matrix correctly captures asymmetric directional weights.

Scope & Boundary Conditions:

  • Sparse Graph Reality: In almost all real-world applications (web link analysis, road networks, social graphs), graphs are sparse with average degree \(d \ll V\). For \(V = 10^6\), an adjacency list consumes megabytes, while an adjacency matrix requires a terabyte.
  • Zero-Weight Ambiguity: In weighted graphs, if 0 is a valid weight (e.g., zero travel cost), matrix entries must use a sentinel value like null, -1, or \(\infty\) to represent edge absence.

Common Pitfalls:

  • Memory Exhaustion on Sparse Graphs: Allocating a full \(V \times V\) matrix for large sparse graphs.
  • Asymmetric Update Neglect in Undirected Graphs: Updating only \(M[u][v]\) and forgetting \(M[v][u]\) when representing an undirected graph with an adjacency matrix.
  • Neighbor Iteration Waste: Scanning all \(V\) entries of a matrix row to find 2 neighbors in a sparse vertex of degree 2, wasting \(O(V)\) time instead of \(O(\deg(u))\).

7.5.5 Student Questions and Answers

Q: Why should someone choose an adjacency matrix to represent a graph if it consumes so much memory?

A: Even though an adjacency matrix consumes \(O(V^2)\) space, it provides instantaneous \(O(1)\) time complexity to check whether a direct edge exists between any two vertices or to retrieve an edge weight. In applications where edge existence queries must execute at maximum speed, an adjacency matrix is preferred over linked lists despite the space penalty.

The choice of graph data structure balances memory efficiency against query performance: use adjacency lists for sparse networks (\(E \ll V^2\)) and adjacency matrices for dense graphs (\(E \approx V^2\)) demanding instantaneous \(O(1)\) edge lookups.

7.6 Breadth-First Search (BFS) and Level-Order Traversal

Graph traversal visits every vertex and edge in a systematic order. Traversal algorithms must track visited vertices to avoid infinite loops in cyclic graphs.

Imagine dropping a stone into a calm pond: circular ripples expand outward uniformly from the point of impact. Breadth-First Search operates on the exact same geometric principle, exploring vertices in concentric outward hops from a source vertex before moving deeper into the network.

7.6.1 Algorithmic Procedure Using a Queue

Breadth-First Search (BFS) explores a graph in outward rings. It visits all immediate neighbors of a start vertex before visiting two-hop neighbors. BFS acts as a level-order traversal.

BFS uses a Queue data structure governed by First-In, First-Out (FIFO) ordering.

Procedural Specification of Breadth-First Search:

  • Inputs: Graph \(G = (V, E)\) represented by adjacency list \(Adj\), and a designated starting vertex \(s \in V\).
  • Auxiliary Structures:
  • A boolean array visited[0 ... n-1] initialized to false.
  • A FIFO queue \(Q\).
  • Outputs: Traversal order, level distances \(d[v]\), and BFS spanning tree edges.
  • Algorithm Execution Steps:
  1. Mark start vertex \(s\) as visited: visited[s] = true.
  2. Enqueue \(s\) into queue: enqueue(Q, s).
  3. While queue \(Q\) is not empty:

a. Dequeue front vertex \(u\): u = dequeue(Q). b. Iterate through all adjacent neighbors \(v \in Adj[u]\). c. For each neighbor \(v\), if visited[v] == false: i. Mark \(v\) as visited: visited[v] = true. ii. Enqueue \(v\): enqueue(Q, v).

  1. Alphabetical ordering resolves tie-breaking when multiple unvisited neighbors are discovered.

The step-by-step algorithm runs as follows:

  1. Choose a start vertex \(s\). Mark \(s\) visited: visited[s] = true.
  2. Enqueue \(s\) into the queue: enqueue(Q, s).
  3. While the queue is not empty:

a. Dequeue front vertex \(u\): u = dequeue(Q). b. Find all neighbors \(v\) linked to \(u\) by edge \((u, v)\). c. For each neighbor \(v\), if \(v\) is unvisited and not in the queue: i. Mark \(v\) visited: visited[v] = true. ii. Enqueue \(v\) into the queue: enqueue(Q, v).

  1. End the search when the queue is empty.

Alphabetical order resolves ties when multiple unvisited neighbors exist.

7.6.2 Time Complexity Analysis: \(O(V + E)\)

The time complexity of Breadth-First Search is:

\[ T_{\text{BFS}} = O(V + E) \]

where \(V = |V|\) is the vertex count and \(E = |E|\) is the edge count.

The verbal explanation outlines this formula: "The time complexity of a graph traversal will be none other than visiting all vertices... so \(V + E\) ... order of \(V + E\) ... all vertices I will visit and to visit all vertices I will be taking help of edges."

Each vertex enters and leaves the queue once. This requires \(O(V)\) queue operations. When processing vertex \(u\), the algorithm checks all incident edges. Across all vertices, the total edge checks equal \(2E\) for undirected graphs and \(E\) for directed graphs. Total edge work takes \(O(E)\). So, total running time is \(O(V + E)\).

Formal Complexity Derivation:

  • Queue Operations: Every vertex \(v \in V\) is marked visited and enqueued at most once, and dequeued exactly once. Total queue overhead is:

\[ \sum_{v \in V} O(1) = O(V) \]

  • Edge Traversal: For each dequeued vertex \(u\), the adjacency list \(Adj[u]\) is scanned. Across the entire traversal:

\[ \sum_{u \in V} |Adj[u]| = \begin{cases} 2|E| & \text{for undirected graphs} \\ |E| & \text{for directed graphs} \end{cases} = O(E) \]

  • Total Time Complexity:

\[ T(V, E) = O(V) + O(E) = O(V + E) \]

(Note: If an adjacency matrix is used instead of an adjacency list, scanning each row takes \(O(V)\), elevating total time to \(O(V^2)\).)

7.6.3 Worked Example: Step-by-Step BFS Walkthrough

Consider a graph with vertices \(\{A, B, C, D, E, F, G, H, I\}\). Traversal starts at vertex \(A\). Alphabetical order breaks ties.

Worked Example — Comprehensive FIFO Queue State Trace:

  • Initialization:
  • Mark \(A\) visited. Enqueue \(A\).
  • Queue: \([A]\). Visited: \(\{A\}\).
  • Step 1: Dequeue \(A\)
  • Dequeue \(A\).
  • Neighbors of \(A\) are \(B\) and \(I\).
  • In alphabetical order, mark \(B\) and \(I\) visited and enqueue both.
  • Queue: \([B, I]\). Visited: \(\{A, B, I\}\).
  • Step 2: Dequeue \(B\)
  • Dequeue \(B\).
  • Neighbors of \(B\) are \(A\) (visited) and \(F\) (unvisited).
  • Mark \(F\) visited and enqueue \(F\).
  • Queue: \([I, F]\). Visited: \(\{A, B, I, F\}\).
  • Step 3: Dequeue \(I\)
  • Dequeue \(I\).
  • Neighbors of \(I\) are \(A\) (visited), \(E\) (unvisited), and \(F\) (in queue).
  • Mark \(E\) visited and enqueue \(E\). Node \(F\) is skipped.
  • Queue: \([F, E]\). Visited: \(\{A, B, I, F, E\}\).
  • Step 4: Dequeue \(F\)
  • Dequeue \(F\).
  • Neighbors of \(F\) are \(B\) (visited), \(E\) (in queue), and \(G\) (unvisited).
  • Mark \(G\) visited and enqueue \(G\).
  • Queue: \([E, G]\). Visited: \(\{A, B, I, F, E, G\}\).
  • Step 5: Dequeue \(E\)
  • Dequeue \(E\).
  • All neighbors of \(E\) are already visited or in the queue.
  • Queue: \([G]\). Visited: \(\{A, B, I, F, E, G\}\).
  • Step 6: Dequeue \(G\)
  • Dequeue \(G\).
  • Neighbors of \(G\) are \(F\) (visited), \(C\) (unvisited), and \(H\) (unvisited).
  • In alphabetical order, mark \(C\) and \(H\) visited and enqueue both.
  • Queue: \([C, H]\). Visited: \(\{A, B, I, F, E, G, C, H\}\).
  • Step 7: Dequeue \(C\)
  • Dequeue \(C\).
  • Neighbors of \(C\) are \(G\) (visited), \(H\) (in queue), and \(D\) (unvisited).
  • Mark \(D\) visited and enqueue \(D\).
  • Queue: \([H, D]\). Visited: \(\{A, B, I, F, E, G, C, H, D\}\).
  • Step 8: Dequeue \(H\)
  • Dequeue \(H\).
  • Neighbors \(C\) and \(G\) are both visited. No nodes are added.
  • Queue: \([D]\). Visited: \(\{A, B, I, F, E, G, C, H, D\}\).
  • Step 9: Dequeue \(D\)
  • Dequeue \(D\).
  • All neighbors of \(D\) are visited. No nodes are added.
  • Queue: \([\ ]\) (empty).
  • Conclusion: The queue is empty. Final visit order: \(A, B, I, F, E, G, C, H, D\).
  • Sense Check: Every vertex in the connected component was visited exactly once. Nodes at hop-distance 1 (\(B, I\)) were completely dequeued before nodes at hop-distance 2 (\(F, E\)), confirming strict level-order fidelity.

Common Pitfalls:

  • Late Marking Trap: Marking a node visited upon dequeue rather than upon enqueue. This allows multiple paths to discover and enqueue the identical vertex repeatedly, degrading space and time complexity.
  • Applying BFS to Weighted Shortest Paths: Assuming BFS finds the minimum-cost path in edge-weighted graphs. BFS only minimizes the unweighted edge count; algorithms like Dijkstra are required for weighted edge costs.
  • Disconnected Component Blindness: Assuming a single BFS traversal visits all \(|V|\) vertices in a disconnected graph. Vertices in other components remain unvisited without an outer loop over all nodes.

7.6.4 Student Questions and Answers

Q: How can an implementation prevent enqueuing the same node multiple times during Breadth-First Search?

A: We maintain a dedicated boolean visited array or flag array. The visited flag is set to true immediately when a node is enqueued, rather than waiting until it is dequeued. This guarantees that when examining neighboring vertices, any node already in the queue or previously visited is skipped.

Exam note: Expect questions on queue operations during BFS and \(O(V + E)\) time complexity.

Breadth-First Search systematically explores graphs level by level using a FIFO queue. With an adjacency list, it guarantees optimal \(O(V + E)\) linear time complexity and produces minimal hop-count shortest paths on unweighted graphs.

7.7 Depth-First Search (DFS) and Backtracking Traversal

Depth-First Search (DFS) explores paths deeply. It follows a branch to its end, then backtracks to earlier decision points to explore remaining branches.

How do you navigate a pitch-black labyrinth without getting hopelessly lost in circular corridors? The classical solution—dating back to Ariadne's ball of thread in the myth of Theseus and the Minotaur—is to unwind a string as you venture deeply down each corridor, and reel it back in to backtrack whenever you hit a dead end. Depth-First Search formalizes this exact strategy using a LIFO stack.

7.7.1 Algorithmic Procedure Using a Stack

DFS uses a Stack data structure governed by Last-In, First-Out (LIFO) ordering.

The step-by-step algorithm runs as follows:

  1. Choose a start vertex \(s\). Mark \(s\) visited. Push \(s\) onto the stack: push(S, s).
  2. While the stack is not empty:

a. Check the top vertex \(u\): u = top(S). b. Look for an unvisited neighbor \(v\) with directed edge \((u, v)\). c. If an unvisited neighbor \(v\) exists: i. Mark \(v\) visited. ii. Push \(v\) onto the stack: push(S, v). d. If no unvisited neighbor exists for \(u\): i. Pop \(u\) from the stack: pop(S).

  1. End the search when the stack is empty.

Alphabetical order breaks ties when multiple unvisited neighbors exist.

Procedural Mechanics of Depth-First Traversal:

  • Inputs: Directed or undirected graph \(G = (V, E)\) and start vertex \(s \in V\).
  • Core Operations:
  • Advance: When an unvisited neighbor \(v\) is found from current top node \(u\), mark \(v\) visited and push \(v\) onto the stack.
  • Backtrack: When the current top node \(u\) has no remaining unvisited neighbors (a dead end), pop \(u\) from the stack to resume searching from its predecessor.
  • Search Paradigm versus Implementation: A student asked whether DFS should be called recursion. While DFS can run recursively, the core search method is backtracking. The stack stores earlier branch points. This allows the search to return and explore remaining branches.

7.7.2 Time Complexity Analysis: \(O(V + E)\)

The time complexity of Depth-First Search is:

\[ T_{\text{DFS}} = O(V + E) \]

where \(V = |V|\) is the vertex count and \(E = |E|\) is the edge count.

The time complexity of Depth-First Search matches that of BFS. Each vertex is pushed and popped once, taking \(O(V)\) time. Each edge is inspected once during neighbor searches, taking \(O(E)\) time. Although BFS and DFS follow different paths, both share the same asymptotic running time.

Detailed Complexity Proof:

  • Vertex Lifetime: Each vertex enters the stack at most once when first discovered, and is popped exactly once upon finishing all descendants. Total stack manipulation costs \(O(V)\).
  • Edge Examination: In an adjacency list representation, each edge \((u, v)\) is examined during the scan of \(Adj[u]\). Over the whole search, each directed edge is checked once (or twice in undirected graphs), contributing \(O(E)\).
  • Total Asymptotic Bound:

\[ T(V, E) = O(V + E) \]

(With an adjacency matrix, scanning rows for unvisited neighbors takes \(O(V)\) per vertex, yielding \(O(V^2)\).)

7.7.3 Worked Example: Step-by-Step DFS Walkthrough on Directed Graph

Consider a directed graph with vertices \(\{A, B, C, D, E, F, G, H\}\). Traversal starts at vertex \(D\). Alphabetical order breaks ties.

Worked Example — LIFO Stack State Trace with Backtracking:

  • Initialization:
  • Mark \(D\) visited. Push \(D\) onto the stack.
  • Stack: \([D]\). Visited: \(\{D\}\).
  • Step 1: Explore from \(D\)
  • Top is \(D\). Outgoing neighbors of \(D\) are \(C, E, F\).
  • In alphabetical order, pick \(C\). Mark \(C\) visited and push \(C\).
  • Stack: \([D, C]\). Visited: \(\{D, C\}\).
  • Step 2: Dead End at \(C\) and Backtrack
  • Top is \(C\). Check outgoing edges from \(C\).
  • The edge runs from \(F\) to \(C\). No edge leaves \(C\).
  • Vertex \(C\) has zero outgoing edges.
  • Pop \(C\) to backtrack.
  • Stack: \([D]\). Visited: \(\{D, C\}\).
  • Step 3: Explore next branch from \(D\)
  • Top is \(D\). Unvisited outgoing neighbors are \(E\) and \(F\).
  • In alphabetical order, pick \(E\). Mark \(E\) visited and push \(E\).
  • Stack: \([D, E]\). Visited: \(\{D, C, E\}\).
  • Step 4: Explore from \(E\)
  • Top is \(E\). Outgoing neighbor of \(E\) is \(G\).
  • Mark \(G\) visited and push \(G\).
  • Stack: \([D, E, G]\). Visited: \(\{D, C, E, G\}\).
  • Step 5: Explore from \(G\)
  • Top is \(G\). Outgoing neighbors of \(G\) are \(D\) (visited) and \(H\) (unvisited).
  • Mark \(H\) visited and push \(H\).
  • Stack: \([D, E, G, H]\). Visited: \(\{D, C, E, G, H\}\).
  • Step 6: Explore from \(H\)
  • Top is \(H\). Outgoing neighbors of \(H\) are \(A\) and \(B\).
  • In alphabetical order, pick \(A\). Mark \(A\) visited and push \(A\).
  • Stack: \([D, E, G, H, A]\). Visited: \(\{D, C, E, G, H, A\}\).
  • Step 7: Explore from \(A\)
  • Top is \(A\). Outgoing neighbor of \(A\) is \(B\).
  • Mark \(B\) visited and push \(B\).
  • Stack: \([D, E, G, H, A, B]\). Visited: \(\{D, C, E, G, H, A, B\}\).
  • Step 8: Dead End at \(B\) and Backtrack Sequence
  • Top is \(B\). Vertex \(B\) has no outgoing edges. Pop \(B\). Stack: \([D, E, G, H, A]\).
  • Top is \(A\). All neighbors visited. Pop \(A\). Stack: \([D, E, G, H]\).
  • Top is \(H\). All neighbors visited. Pop \(H\). Stack: \([D, E, G]\).
  • Top is \(G\). All neighbors visited. Pop \(G\). Stack: \([D, E]\).
  • Top is \(E\). All neighbors visited. Pop \(E\). Stack: \([D]\).
  • Step 9: Explore last branch from \(D\)
  • Top is \(D\). Remaining unvisited neighbor is \(F\).
  • Mark \(F\) visited and push \(F\).
  • Stack: \([D, F]\). Visited: \(\{D, C, E, G, H, A, B, F\}\).
  • Step 10: Final Backtrack and Termination
  • Top is \(F\). Outgoing neighbor \(C\) is already visited.
  • Pop \(F\). Stack: \([D]\).
  • Top is \(D\). All neighbors visited. Pop \(D\).
  • Stack: \([\ ]\) (empty).
  • Conclusion: The stack is empty. Final visit order: \(D, C, E, G, H, A, B, F\).
  • Sense Check: Node \(C\) was visited second and immediately popped. The deep sequence \(D \to E \to G \to H \to A \to B\) reached maximum stack depth 6 before cascading pops brought execution back to origin \(D\). Finally, branch \(F\) was explored, covering all 8 reachable vertices.

7.7.4 Backtracking versus Recursion and Start-Node Selection

A student asked whether DFS should be called recursion. While DFS can run recursively, the core search method is backtracking. The stack stores earlier branch points. This allows the search to return and explore remaining branches.

Start-node choice is critical in directed graphs:

If you start at a node like \(B\), the search fails to visit the graph. Vertex \(B\) has incoming edges but zero outgoing edges. Starting at \(B\) causes the search to end right away.

So, when no start node is specified in a directed graph, always pick the vertex with the most outgoing edges (highest out-degree). This choice maximizes reach across the network.

Scope & Directed Graph Pitfalls:

  • Zero Out-Degree Trap: Selecting a sink vertex as the start node halts traversal after visiting a single vertex. In directed networks, always choose the node with maximum out-degree or execute an outer loop over all vertices.
  • Directional Ignorance: Attempting to backtrack along directed edges in reverse (e.g., trying to step from \(C\) to \(F\) when the edge is strictly directed \(F \to C\)). Backtracking operates exclusively along the LIFO stack history, never backwards against edge arrows.

7.7.5 Student Questions and Answers

Q: During Depth-First Search from node \(D\), why was node \(C\) pushed first rather than \(E\) or \(F\)?

A: When a node has multiple unvisited adjacent neighbors, the algorithm can technically explore any of them. In this walkthrough, tie-breaking follows alphabetical order among unvisited neighbors \(\{C, E, F\}\), which selects \(C\).

Q: Why did we not continue traversal from node \(C\) to node \(F\) during Depth-First Search?

A: The graph being traversed is a directed graph. The directed edge runs from \(F\) to \(C\), meaning travel is only permitted from \(F\) toward \(C\). There is no outbound edge from \(C\) to \(F\). Since \(C\) has zero outbound edges, traversal reaches an immediate dead end at \(C\), requiring the algorithm to pop \(C\) and backtrack.

Q: In a directed graph, what happens if we select node \(B\) as the starting node for Depth-First Search?

A: If node \(B\) has incoming edges but zero outgoing edges, starting at \(B\) causes the algorithm to visit \(B\) and stop immediately, leaving the rest of the graph unvisited. So, when choosing a starting node in a directed graph where none is specified, select the vertex with the highest number of outbound edges (maximum out-degree) to maximize graph reachability.

Depth-First Search explores graph paths deeply using a LIFO stack, backtracking when dead ends or visited vertices are encountered. It achieves \(O(V + E)\) time complexity, forming the procedural core for cycle detection, topological sorting, and strongly connected components.

Key Industry Applications

Graphs model structured interactions across software engineering, systems design, and data science:

  1. Mapping and Navigation Services: Route planning engines in mapping applications model street intersections as vertices and road segments as edges. Distance, travel time, and toll costs serve as edge weights to compute shortest paths.
  2. Telecommunications and Cellular Infrastructure: Network topology designs model Base Transceiver Station (BTS) towers as vertices and fiber-optic cables as physical edges, managing signal routing and fault-tolerant transmission.
  3. Social Network Platforms: Social graphs represent registered users as vertices and bidirectional friendships or unidirectional follows as edges, powering recommendation systems and community detection.
  4. Computational Photography and Computer Vision: Mobile camera image processing separates foreground objects from backgrounds using graph cut partitioning algorithms (such as Min-Max Cut), enabling synthetic bokeh and portrait effects.
  5. Circuit and Hardware Design: Electronic circuit layout tools model components as vertices and conductive traces on printed circuit boards (PCBs) or integrated circuits (ICs) as edges to analyze pulse propagation and electrical connectivity.
  6. Database Schema Modeling: Relational and graph databases use Entity-Relationship (ER) graph models to define primary-key and foreign-key dependencies between distinct entities.
  7. Hierarchical Supply Chain Logistics: Distribution systems use Depth-First Search to traverse regional retail branches from central warehouse distribution hubs before backtracking to cover adjacent territories.

Exam guidance covers structural expectations and preparation strategies:

  • Assessment Format: The assessment consists of 20 multiple-choice questions (MCQs) administered over a 30-minute duration (a strict 20:30 question-to-minute ratio).
  • Time Management: The tight 30-minute time constraint prevents external consultation and ensures individual mastery of algorithmic concepts.
  • Syllabus Boundaries: The assessment covers foundational data structures up to time complexity analysis. Advanced partitioning methods like the Min-Max Cut algorithm are excluded from testing.
  • Key Study Areas: Students should focus on:
  • Formulating adjacency matrices and adjacency lists for directed and undirected graphs.
  • Distinguishing between paths, simple paths, cycles, and simple cycles.
  • Calculating vertex degrees and minimum edge counts for spanning trees (\(n - 1\)).
  • Executing step-by-step queue operations for BFS and stack operations for DFS.
  • Applying the \(O(V + E)\) time complexity formula to traversal algorithms.

15.1 Single-Source Shortest Paths and Limitations of Dijkstra's Algorithm

Single-source shortest path algorithms find the minimum cost path from a designated start vertex to all other vertices in a directed graph. In a standard weighted graph, each directed edge \(e = (u, v)\) has an associated cost or weight \(w(u, v)\). The total path cost equals the sum of the weights of all edges along that path.

Can an algorithm be universally celebrated, proven optimal under standard conditions, and yet produce completely incorrect answers without raising any warning? That is the danger of running Dijkstra's algorithm on graphs containing negative edge weights.

To understand how shortest path algorithms work, imagine a GPS navigation system planning a delivery route. Each road segment charges a toll fee. If every toll road charges a non-negative fee, once you reach a junction along the quickest known route, taking a detour through an unvisited town can only add more fees. The decision to finalize that junction's travel cost is permanent. However, if a road segment offers a subsidy or cash rebate (a negative toll), a longer detour might eventually become cheaper than the direct route, invalidating the navigation system's earlier final decision. The analogy breaks down if a rebate loop exists (a negative cycle), where cycling endlessly generates infinite money, causing the shortest path cost to drop toward negative infinity.

Dijkstra's algorithm is a greedy algorithm designed for this single-source routing task. It operates by maintaining tentative distances for all vertices, iteratively picking the unvisited vertex with the smallest tentative distance, relaxing all of its outgoing edges, and marking that vertex as visited. This greedy strategy relies on a foundational constraint: all edge weights in the directed graph must be non-negative:

Non-Negative Edge Weight Invariant: Dijkstra's algorithm requires that every directed edge has a non-negative weight:

\[ w(u, v) \ge 0 \quad \text{for all } (u, v) \in E \]

where \(V\) is the set of graph vertices, \(E\) is the set of directed edges, and \(w(u, v) \in \mathbb{R}\) represents the weight assigned to edge \((u, v)\).

For a directed path \(p = \langle v_0, v_1, \ldots, v_k \rangle\), the total path cost \(w(p)\) is the sum of constituent edge weights:

\[ w(p) = \sum_{i=1}^k w(v_{i-1}, v_i) \]

The shortest path distance from source vertex \(s \in V\) to destination vertex \(v \in V\) is denoted \(\delta(s, v)\), defined as the minimum weight among all paths connecting \(s\) to \(v\). The algorithm tracks an upper bound distance estimate \(d[v]\) for each vertex, initialized to \(d[s] = 0\) and \(d[v] = \infty\) for all \(v \ne s\). Edge relaxation along directed edge \((u, v)\) updates this estimate:

\[ \text{if } d[v] > d[u] + w(u, v) \text{ then } d[v] = d[u] + w(u, v) \]

15.1.1 Negative Edge Weights and Failure Modes

The primary limitation of Dijkstra's algorithm arises when a graph contains negative edge weights. If any directed edge has a negative cost, such as \(w(u, v) = -1\), the algorithm fails.

The failure mode is silent. Dijkstra's algorithm does not detect that a negative edge exists. It does not stop execution, nor does it throw an error. It continues to run, makes greedy selections, and outputs an incorrect shortest path answer.

The algorithm assumes that adding an edge to a path never decreases total path cost. Suppose an edge has a negative weight. Reaching a vertex later through this edge can reduce the path distance. This new distance can drop below the value already finalized for an earlier visited vertex. Because Dijkstra's algorithm never re-evaluates visited vertices, it cannot correct this error.

Scope and Boundary Conditions: Dijkstra's algorithm applies strictly to graphs where every edge weight satisfies \(w(u, v) \ge 0\). When negative edges exist, the greedy choice property breaks down. The algorithm extracts a vertex from the unvisited set under the false assumption that its tentative distance cannot be improved by paths through currently unvisited vertices.

To see the silent failure in a concrete walkthrough, trace the execution on the 3-vertex graph shown in Figure 15.1:

  1. Initialize distances: \(d[s] = 0\), \(d[a] = \infty\), and \(d[b] = \infty\). The unvisited set is \(Q = \{s, a, b\}\).
  2. Extract source vertex \(s\) with \(d[s] = 0\). Relax outgoing edges:
  • Edge \((s, a)\) gives \(d[a] = \min(\infty, 0 + 3) = 3\).
  • Edge \((s, b)\) gives \(d[b] = \min(\infty, 0 + 5) = 5\).
  • Mark \(s\) visited.
  1. The remaining unvisited vertices are \(a\) (distance 3) and \(b\) (distance 5). The greedy choice extracts vertex \(a\) because \(d[a] = 3 < d[b] = 5\). The algorithm marks \(a\) as permanently visited with finalized distance \(d[a] = 3\).
  2. The algorithm then extracts vertex \(b\) with \(d[b] = 5\). Relaxing outgoing edge \((b, a)\) computes a candidate distance:

\[ d[b] + w(b, a) = 5 + (-4) = 1 \]

Because \(1 < 3\), the true shortest path from \(s\) to \(a\) is \(\langle s, b, a \rangle\) with total cost \(1\). However, because \(a\) was already marked visited, Dijkstra's algorithm ignores this improvement. It terminates and outputs \(d[a] = 3\), completely missing the optimal path.

Common Pitfalls:

- The Reweighting Fallacy: A common beginner error is trying to eliminate negative edges by adding a constant \(C = |\min_{(u,v)} w(u, v)|\) to every edge in the graph. This fails because paths with more edges have more copies of \(C\) added to their total cost than paths with fewer edges. Adding a constant changes the relative cost of different paths, which can turn a suboptimal path into the apparent shortest path.
- Assuming Dijkstra Re-evaluates Visited Nodes: Some assume Dijkstra's algorithm can be fixed simply by allowing relaxed edges to update visited vertices. While this finds the shortest path, it requires re-inserting vertices into the priority queue. This destroys the \(O((|V| + |E|) \log |V|)\) time guarantee, potentially requiring exponential time \(O(2^{|V|})\), and enters an infinite loop if a negative-weight cycle is reachable.

15.1.2 Comparison with the Bellman-Ford Algorithm

To handle graphs where edge weights can be negative, computer scientists use the Bellman-Ford algorithm. Like Dijkstra's algorithm, the Bellman-Ford algorithm solves the single-source shortest path problem on directed graphs.

When negative-weight cycles exist, a shortest path may be mathematically undefined. Traversing a negative cycle repeatedly decreases total path cost toward negative infinity. If negative edges are present, Bellman-Ford identifies the problem. The algorithm detects the negative weight edge or cycle and flags that the calculated path is invalid. Dijkstra's algorithm fails to detect the negative edge, while Bellman-Ford successfully flags negative-weight anomalies.

The following table summarizes the structural differences between both approaches:

Feature Dijkstra's Algorithm Bellman-Ford Algorithm
Algorithmic Paradigm Greedy selection Dynamic programming / iterative relaxation
Edge Weight Restriction Strictly non-negative: \(w(u, v) \ge 0\) Arbitrary real numbers: positive, zero, or negative
Negative Cycle Handling Fails silently; outputs incorrect distance Accurately detects and reports negative-weight cycles
Time Complexity \(O((|V| + |E|) \log |V|)\) with min-heap \(O(|V| \cdot |E|)\) using \(|V| - 1\) relaxation passes
Node Finalization Greedily finalizes each vertex once Updates tentative distances over multiple sweeps
When to Choose Road networks and routing with positive costs Financial networks and graphs with possible negative costs

Real-world systems regularly produce negative edge weights. In physical networks, edge weights can represent temperature differences between weather stations, where readings drop below zero degrees. In financial transaction networks, vertices represent asset states and edge weights represent financial gains or losses. A positive weight marks a profit, while a negative weight represents a financial loss or portfolio drawdown. In transportation systems, negative weights can model electric vehicle routes where regenerative braking restores battery power during descents.

Recap and Bridge: Dijkstra's algorithm achieves efficient \(O((|V| + |E|) \log |V|)\) execution by exploiting the greedy choice property, which holds only when all edge weights are non-negative. When negative weights appear, greedy finalization fails silently, requiring dynamic programming algorithms like Bellman-Ford. Next, we examine another optimization domain where greedy choices succeed: the Fractional Knapsack Problem.

15.1.3 Student Questions and Answers

Q: Is it the initialization step in Dijkstra's algorithm that prevents it from handling negative edge weights?

A: No, the initialization step is not the cause. The limitation comes from the greedy choice property. Dijkstra's algorithm marks a vertex visited and finalizes its shortest path distance under the assumption that path costs grow monotonically. A negative weight edge encountered later can shorten an already finalized path, causing the algorithm to output incorrect answers without detecting the error.

Q: What do negative edge weights mean in a real-world context?

A: Negative edge weights represent quantities where values drop below a baseline. In environmental monitoring, edge weights represent sub-zero temperatures. In financial modeling, negative weights represent financial losses or investment drawdowns. In energy systems, negative weights represent energy regenerated along downhill travel.

15.2 The Greedy Method and Fractional Knapsack Problem

Optimization problems require finding the best solution among many feasible candidates. The objective is to maximize a benefit (such as profit, bandwidth, or throughput) or minimize an expense (such as financial loss, delay, or cost).

In algorithm design, optimization problems are primarily solved using two distinct paradigms: the Greedy Method and Dynamic Programming. The greedy method builds a solution step by step. At each stage, it makes the locally optimal choice in the hope of reaching a globally optimal solution.

If you were exploring a treasure cave with a backpack capable of holding at most 15 kg, and the ground contained gold dust, silver bars, and raw gemstones, which items should you load first to leave with the greatest possible fortune?

To understand how greedy optimization works, imagine shopping at a bulk spice market with a canvas tote bag that holds at most 15 kilograms. You do not choose spices based solely on the total price of an entire sack, because a massive 50 kg sack of flour might cost 100 dollars but will not fit in your bag. Nor do you choose solely based on lightest weight. Instead, you look at the price tag per kilogram—the value density. Premium saffron might cost 10 dollars per gram, whereas common peppercorns cost 20 dollars per kilogram. You greedily scoop the highest-density spice first until the market runs out of it, then move to the second-highest density spice, continuing down the list. When your bag has only 2 kilograms of capacity remaining, you scoop exactly 2 kilograms of the next spice. The analogy breaks when items cannot be divided—such as indivisible antique vases or desktop computers—where taking a fractional piece is impossible.

15.2.1 Problem Formulation and Greedy Principles

The knapsack problem, also called the container loading problem, is a classic optimization problem. A shipping operator has a container with a maximum weight capacity \(W\). There are \(n\) distinct objects available for loading.

Each object \(i\) (for \(i = 1, 2, \ldots, n\)) comes with two known values:

  • A total profit \(p_i > 0\)
  • A total weight \(w_i > 0\)

The goal is to select objects and place them into the container so that total profit is maximized while total weight does not exceed the container capacity \(W\).

In the Fractional Knapsack Problem, items are divisible. A fraction \(x_i\) of object \(i\) can be placed in the bag, where \(0 \le x_i \le 1\). If \(x_i = 1\), the object is taken completely. If \(x_i = 0\), the object is completely omitted. If \(0 < x_i < 1\), a partial fraction of the object is loaded. Each object exists in a finite stock equal to its weight \(w_i\). Repetition is prohibited. Once an item's weight is loaded, no more of that item is available.

The fractional knapsack problem is solved optimally by the greedy method.

15.2.2 Mathematical Model and Optimization Objectives

The mathematical formulation of the fractional knapsack problem defines the objective function and the capacity constraint:

Optimization Formulation of Fractional Knapsack: The objective is to maximize the cumulative profit earned from loaded fractions:

\[ \max \sum_{i=1}^n x_i p_i \]

subject to the weight capacity constraint:

\[ \sum_{i=1}^n x_i w_i \le W \]

with the fractional selection bounds:

\[ 0 \le x_i \le 1 \quad \text{for each } i \in \{1, 2, \ldots, n\} \]

Here, \(n \in \mathbb{N}\) is the total count of objects, \(p_i \in \mathbb{R}^+\) is the profit of object \(i\), and \(w_i \in \mathbb{R}^+\) is the weight of object \(i\). The value \(W \in \mathbb{R}^+\) is the container weight capacity. The variable \(x_i \in [0, 1]\) is the continuous decision variable representing the fraction of object \(i\) placed into the container.

The greedy criterion relies on the profit-to-weight ratio \(r_i\):

\[ r_i = \frac{p_i}{w_i} \]

where \(r_i \in \mathbb{R}^+\) represents the profit density per unit weight of object \(i\). The greedy algorithm sorts all objects in descending order of their profit-to-weight ratio. It loads items greedily until the container is full.

The mathematical reason the greedy strategy achieves global optimality for fractional knapsack is the exchange argument. Suppose an optimal solution \(X^* = \langle x_1^*, \ldots, x_n^* \rangle\) differs from the greedy solution \(X\). There must exist an item \(j\) with higher profit density \(r_j > r_k\) where \(x_j^* < 1\) while some lower density item \(k\) has \(x_k^* > 0\). We can increase \(x_j^*\) by an amount \(\epsilon\) and decrease \(x_k^*\) by \(\epsilon \cdot \frac{w_j}{w_k}\), keeping total weight unchanged. The net change in profit is:

\[ \Delta P = \epsilon p_j - \epsilon \frac{w_j}{w_k} p_k = \epsilon w_j (r_j - r_k) > 0 \]

Because \(\Delta P > 0\), replacing lower-density items with higher-density items strictly increases total profit, contradicting the assumption that \(X^*\) was optimal unless it matches the greedy choice.

15.2.3 Fully Worked Numerical Example

Consider a container with maximum capacity \(W = 15\) kg and \(n = 7\) available objects. The profits and weights for the seven objects are:

  • Object 1: profit \(p_1 = 10\), weight \(w_1 = 2\) kg
  • Object 2: profit \(p_2 = 5\), weight \(w_2 = 3\) kg
  • Object 3: profit \(p_3 = 15\), weight \(w_3 = 5\) kg
  • Object 4: profit \(p_4 = 7\), weight \(w_4 = 7\) kg
  • Object 5: profit \(p_5 = 6\), weight \(w_5 = 1\) kg
  • Object 6: profit \(p_6 = 18\), weight \(w_6 = 4\) kg
  • Object 7: profit \(p_7 = 3\), weight \(w_7 = 1\) kg

#### Brute Force Exploration

Before applying the greedy ratio, consider trial-and-error selections restricted to whole objects:

  • First attempt: Select Objects 2, 3, and 4.
  • Total weight: \(w_2 + w_3 + w_4 = 3 + 5 + 7 = 15\) kg.
  • Total profit: \(p_2 + p_3 + p_4 = 5 + 15 + 7 = 27\).
  • Second attempt: Select Objects 1, 2, 3, 5, and 6.
  • Total weight: \(w_1 + w_2 + w_3 + w_5 + w_6 = 2 + 3 + 5 + 1 + 4 = 15\) kg.
  • Total profit: \(p_1 + p_2 + p_3 + p_5 + p_6 = 10 + 5 + 15 + 6 + 18 = 54\).

A beginner might conclude that 54 is the maximum possible profit. However, greedy selection using the profit-to-weight ratio yields a strictly higher profit.

#### Computing Profit-to-Weight Ratios

Calculate the profit density \(r_i = \frac{p_i}{w_i}\) for each object:

  • Object 1: \(r_1 = \frac{10}{2} = 5.0\)
  • Object 2: \(r_2 = \frac{5}{3} \approx 1.67\)
  • Object 3: \(r_3 = \frac{15}{5} = 3.0\)
  • Object 4: \(r_4 = \frac{7}{7} = 1.0\)
  • Object 5: \(r_5 = \frac{6}{1} = 6.0\)
  • Object 6: \(r_6 = \frac{18}{4} = 4.5\)
  • Object 7: \(r_7 = \frac{3}{1} = 3.0\)

Sorting by ratio descending gives the loading order: Object 5 (\(6.0\)), Object 1 (\(5.0\)), Object 6 (\(4.5\)), Object 3 (\(3.0\)), Object 7 (\(3.0\)), Object 2 (\(1.67\)), Object 4 (\(1.0\)).

Step-by-Step Greedy Selection Walkthrough:

We track remaining container capacity \(W_{\text{rem}}\), starting at \(15\) kg:

  1. Object 5: Ratio is \(6.0\). Weight is \(1\) kg. Because \(1 \le 15\), load the object completely:
  • \(x_5 = 1\)
  • Weight added: \(1\) kg
  • Remaining capacity: \(15 - 1 = 14\) kg
  1. Object 1: Ratio is \(5.0\). Weight is \(2\) kg. Because \(2 \le 14\), load the object completely:
  • \(x_1 = 1\)
  • Weight added: \(2\) kg
  • Remaining capacity: \(14 - 2 = 12\) kg
  1. Object 6: Ratio is \(4.5\). Weight is \(4\) kg. Because \(4 \le 12\), load the object completely:
  • \(x_6 = 1\)
  • Weight added: \(4\) kg
  • Remaining capacity: \(12 - 4 = 8\) kg
  1. Object 3: Ratio is \(3.0\). Weight is \(5\) kg. Because \(5 \le 8\), load the object completely:
  • \(x_3 = 1\)
  • Weight added: \(5\) kg
  • Remaining capacity: \(8 - 5 = 3\) kg
  1. Object 7: Ratio is \(3.0\). Weight is \(1\) kg. Because \(1 \le 3\), load the object completely:
  • \(x_7 = 1\)
  • Weight added: \(1\) kg
  • Remaining capacity: \(3 - 1 = 2\) kg
  1. Object 2: Ratio is \(1.67\). Weight is \(3\) kg. Remaining capacity is only \(2\) kg. Take a fractional slice:
  • \(x_2 = \frac{2}{3}\)
  • Weight added: \(\frac{2}{3} \times 3 = 2\) kg
  • Remaining capacity: \(2 - 2 = 0\) kg
  1. Object 4: Ratio is \(1.0\). The container is full. Do not load Object 4:
  • \(x_4 = 0\)

Total Weight Verification:

\[ W_{\text{total}} = (1 \times 2) + \left(\frac{2}{3} \times 3\right) + (1 \times 5) + (0 \times 7) + (1 \times 1) + (1 \times 4) + (1 \times 1) \]

\[ W_{\text{total}} = 2 + 2 + 5 + 0 + 1 + 4 + 1 = 15 \text{ kg} \]

Total Profit Verification:

\[ P_{\text{total}} = (1 \times 10) + \left(\frac{2}{3} \times 5\right) + (1 \times 15) + (0 \times 7) + (1 \times 6) + (1 \times 18) + (1 \times 3) \]

\[ P_{\text{total}} = 10 + 3.33 + 15 + 0 + 6 + 18 + 3 = \mathbf{55.33} \]

The greedy strategy yields a profit of \(55.33\). This outcome beats the brute-force whole-object result of \(54\).

15.2.4 Tie-Breaking, Sorting Mechanics, and Complexity

When two objects have identical profit-to-weight ratios, such as Object 3 (\(r_3 = 3.0\)) and Object 7 (\(r_7 = 3.0\)), either object can be selected first. Both provide identical profit density per kilogram. In practice, sorting algorithms like stable sorts or in-place sorts preserve the original relative order from the input array. Choosing Object 7 before Object 3 fills the capacity with identical marginal gain.

If the problem objective is reversed to minimize profit or cost, the greedy algorithm sorts items by profit-to-weight ratio in ascending order. It loads items with the smallest ratio first.

The time complexity of the fractional knapsack algorithm is determined by sorting:

  • Sorting \(n\) items by ratio takes \(O(n \log n)\) time using merge sort or quicksort.
  • The greedy selection loop inspects each item at most once in \(O(n)\) time.
  • The total time complexity is \(O(n \log n)\).

When the item count \(n\) is exceptionally large and an in-memory full sort is costly, an alternative selection algorithm based on median-of-medians (quickselect) can find the fractional cutoff item in \(O(n)\) average and worst-case time, partitioning items into those taken completely, the single fractional item, and items left behind.

15.2.5 Contrast with the 0/1 Knapsack Problem

The 0/1 Knapsack Problem introduces an extra restriction: items are indivisible. Each decision variable \(x_i\) must be strictly binary:

\[ x_i \in \{0, 1\} \]

An item must be taken completely (\(x_i = 1\)) or left completely (\(x_i = 0\)). Fractions like \(x_2 = \frac{2}{3}\) are forbidden.

The greedy profit-to-weight ratio does not guarantee an optimal solution for the 0/1 knapsack problem. An item with high profit density might occupy space that blocks a combination of items with higher combined profit. Solving the 0/1 knapsack problem requires Dynamic Programming.

The following table contrasts the two formulations:

Property Fractional Knapsack Problem 0/1 Knapsack Problem
Divisibility Divisible: \(x_i \in [0, 1]\) Indivisible: \(x_i \in \{0, 1\}\)
Algorithmic Paradigm Greedy method Dynamic programming
Time Complexity \(O(n \log n)\) due to comparison sort \(O(n W)\) pseudo-polynomial time
Greedy Optimality Guaranteed optimal by exchange argument Fails; greedy choices lead to suboptimal loads
Fractional Cutoff Exactly one item is taken partially No item is split; items are all-or-nothing

Common Pitfalls:

  • Picking by Profit Alone: Selecting items with the highest raw profit \(p_i\) fails because heavy items consume disproportionate capacity, leaving little room for other valuable goods.
  • Picking by Weight Alone: Selecting the lightest items first minimizes capacity usage, but yields low total value if those lightweight items carry negligible profit.
  • Applying Greedy Ratios to Indivisible Items: Applying the greedy profit density rule to the 0/1 knapsack problem does not guarantee optimality. For example, if capacity is 5 kg, item A has weight 3 kg and profit 18 (\(r_A = 6\)), while items B and C each have weight 2.5 kg and profit 12 (\(r_B = r_C = 4.8\)), greedy picks item A (profit 18) and cannot fit any more items, whereas taking items B and C yields combined profit 24.

Recap and Bridge: The fractional knapsack problem is solved to global optimality in \(O(n \log n)\) time by sorting items according to their profit density \(r_i = \frac{p_i}{w_i}\). However, the moment divisibility is removed—as in the 0/1 knapsack problem—the greedy strategy collapses. To guarantee optimality for discrete choices with overlapping subproblems, we turn to Dynamic Programming.

15.2.6 Student Questions and Answers

Q: Can objects be repeated or selected multiple times in the knapsack?

A: No, repetition is not allowed. Each object has a fixed finite stock equal to its weight. Once the available quantity of an object is loaded, it is exhausted.

Q: When two objects have identical profit-to-weight ratios, does their weight matter for selection order?

A: In theory, either object can be selected first because both yield identical profit density per kilogram. In practice, sorting algorithms like stable or in-place sorts maintain the original order of the input array.

Q: If the objective is to minimize profit, do we still use the profit-to-weight ratio?

A: Yes, the profit-to-weight ratio is still used, but the sorting order is reversed to ascending order, picking objects with the smallest ratio first.

Exam note: Expect a direct numerical problem on fractional knapsack on the final exam. 0/1 knapsack has been removed from the current syllabus.

15.3 Introduction to Dynamic Programming

Dynamic Programming is an algorithm design technique used to solve complex optimization problems. It decomposes a large problem into smaller subproblems. It solves each subproblem once and stores the results in a lookup table.

Dynamic programming applies when a problem exhibits two properties:

  1. Overlapping Subproblems: Recursive solutions solve the same subproblems repeatedly rather than generating new subproblems.
  2. Optimal Substructure: The optimal solution to the overall problem contains within it the optimal solutions to its subproblems.

How can a simple two-line recursive function computing the 50th Fibonacci number stall a modern computer for minutes, while an elementary loop calculates the exact answer in a few microseconds?

To understand the difference, imagine a student working through a long homework problem set that repeatedly asks for the product of \(17 \times 23\). If the student calculates \(17 \times 23\) by long multiplication every single time it appears on different pages, they waste hours on duplicate effort. If they write the result (\(391\)) on a memo slip the first time it is calculated, every subsequent occurrence takes one second to look up. That memo slip is memoization. If instead of waiting for questions, the student systematically constructs a multiplication reference table from \(1 \times 1\) up to \(20 \times 25\) before opening the homework, that is tabulation. The analogy breaks down when every subproblem is completely unique, such as in binary search or divide-and-conquer merge sort, where subproblems never overlap and table lookup provides zero benefit.

15.3.1 Overlapping Subproblems and Optimal Substructure

When a recursive algorithm evaluates identical subproblems multiple times, it wastes computational effort. Storing subproblem solutions avoids this exponential explosion. When a subproblem reappears, the algorithm retrieves the stored result in \(O(1)\) time.

Optimal substructure means that an optimal solution to the overarching problem is constructed directly from optimal solutions to its constituent subproblems. For instance, in shortest path problems, any subpath of a shortest path is itself a shortest path between its endpoints. When both optimal substructure and overlapping subproblems are present, dynamic programming provides a mathematically guaranteed, polynomial-time solution.

15.3.2 Motivating Recurrence: Fibonacci Numbers

The standard Fibonacci sequence illustrates overlapping subproblems. The sequence is defined recursively:

Fibonacci Recurrence Relation and Base Cases: The Fibonacci sequence is defined by the recurrence:

\[ F(n) = F(n-1) + F(n-2) \quad \text{for } n \ge 2 \]

with base cases:

\[ F(0) = 0, \quad F(1) = 1 \]

where \(n \in \mathbb{N}_0\) is the term index and \(F(n) \in \mathbb{N}_0\) is the \(n\)-th Fibonacci number.

Evaluating \(F(5)\) recursively requires computing:

  • \(F(5) = F(4) + F(3)\)
  • \(F(4) = F(3) + F(2)\)
  • \(F(3) = F(2) + F(1)\)

Notice that \(F(3)\) is computed twice, and \(F(2)\) is computed three times. The recursion tree branches exponentially. If \(T(n)\) represents the number of operations needed to compute \(F(n)\), the recurrence satisfies:

\[ T(n) = T(n-1) + T(n-2) + O(1) = O(\phi^n) \]

where \(\phi = \frac{1 + \sqrt{5}}{2} \approx 1.618\) is the golden ratio. The naive recursive approach exhibits an exponential time complexity of \(O(2^n)\).

15.3.3 Top-Down Memoization vs Bottom-Up Tabulation

Dynamic programming resolves redundant subproblem evaluation through two implementation strategies:

#### Top-Down Memoization

Memoization retains the recursive formulation. It allocates a lookup table initialized with sentinel values (such as \(-1\) or null). When the function is called for argument \(n\):

  1. It checks if the table already contains the answer for \(n\). If present, it returns the cached value in \(O(1)\) time.
  2. If absent, it recurses down the call tree until reaching the base cases.
  3. Upon returning from recursive calls, it writes the computed value into the memory table before returning it.

A limitation of memoization is that it must traverse down the recursion tree to the base cases before filling the cache. It also incurs call stack overhead proportional to recursion depth \(O(n)\).

#### Bottom-Up Tabulation

Tabulation avoids recursion. It creates an array of size \(n + 1\) for indices \(0\) through \(n\). It populates the base cases directly and iterates upward.

Worked Example: Bottom-Up Tabulation for \(F(5)\):

For \(n = 5\), allocate array F of size 6:

  1. Initialize base values: F[0] = 0 and F[1] = 1.
  2. Compute F[2] = F[1] + F[0] = 1 + 0 = 1.
  3. Compute F[3] = F[2] + F[1] = 1 + 1 = 2.
  4. Compute F[4] = F[3] + F[2] = 2 + 1 = 3.
  5. Compute F[5] = F[4] + F[3] = 3 + 2 = \mathbf{5}.

Tabulation computes \(F(n)\) using a single loop in \(O(n)\) time and \(O(n)\) auxiliary space. This reduces the time complexity from \(O(2^n)\) to \(O(n)\). Furthermore, because computing F[i] requires only F[i-1] and F[i-2], space complexity can be reduced to \(O(1)\) by maintaining only two scalar variables for the previous two terms.

15.3.4 Optimality Guarantees: Greedy Failure and the Coin Change Problem

A greedy algorithm makes local choices without revisiting them. While greedy algorithms are fast, they do not always find the globally optimal solution.

Consider the Coin Change Problem. A cashier wants to provide change for an amount using the minimum number of coins.

  • In the Indian currency system (denominations 10, 5, 2, 1), making change for 10 rupees using greedy selection picks two 5-rupee coins (2 coins), which is optimal.
  • In non-canonical currency systems, such as historical Russian rubles and kopek coin sets or custom denomination systems like \(\{1, 3, 4\}\) for a target of 6, greedy selection fails.
  • Greedy choice selects the largest coin first: \(4\), leaving \(2\). It then picks two \(1\) coins: \(4 + 1 + 1\) (3 coins).
  • The globally optimal solution is two \(3\) coins: \(3 + 3\) (2 coins).

A currency system is termed canonical if the greedy coin-change algorithm always yields an optimal solution for every target amount. Modern currencies (such as the Indian rupee or US dollar) are designed to be canonical. However, historical systems (including historical Russian ruble series containing 3-ruble or 3-kopek denominations) and arbitrary coin sets are non-canonical, meaning greedy heuristics can fail.

Dynamic programming guarantees 100% mathematical optimality by checking all valid subproblem choices. Even when dynamic programming requires polynomial time like \(O(n^2)\) or \(O(n^3)\) through nested loops, it guarantees the correct optimal answer.

Tree traversals (such as pre-order or in-order traversals) do not use dynamic programming. Tree traversal is an exhaustive search that visits every node, not an optimization problem. Standard recursion visits each node once in \(O(n)\) time, so dynamic programming is unnecessary.

Common Pitfalls:

  • Assuming Dynamic Programming Applies Everywhere: Applying dynamic programming to problems without overlapping subproblems (such as merge sort or divide-and-conquer) adds table allocation and hashing overhead without any performance gain.
  • Assuming Greedy Always Solves Coin Change: Relying on greedy coin selection because it works on canonical currencies like Indian rupees leads to incorrect code when applied to custom denomination sets.
  • Off-by-One Table Sizing in Tabulation: When computing the \(n\)-th value, an array of size \(n + 1\) is required to accommodate index \(0\) through \(n\). Allocating size \(n\) causes an out-of-bounds error.

Recap and Bridge: Dynamic programming replaces exponential recursive branching with polynomial tabular lookups by identifying optimal substructure and caching overlapping subproblems. Having examined the 1D tabulation model with Fibonacci numbers and Coin Change, we now advance to 2D tabular optimization in Matrix Chain Multiplication.

15.3.5 Student Questions and Answers

Q: In top-down memoization, is it required to run through to the bottom base cases at least once?

A: Yes, memoization must traverse down the call tree until reaching the base cases, after which results are cached in the memory table during the upward return.

Q: Can iterative dynamic programming ever perform worse than a naive recursive approach?

A: Yes, in certain problem spaces where only a small subset of subproblems is needed, tabulation fills the entire table unnecessarily, whereas recursion visits only reachable states. However, dynamic programming guarantees 100% mathematical optimality.

Q: Why do we not implement tree traversals using dynamic programming?

A: Tree traversal is not an optimization problem. Visiting every node is an exhaustive search requiring \(O(n)\) simple recursion, so dynamic programming overhead is unnecessary.

15.4 Matrix Chain Multiplication and Associativity

Matrix multiplication is a fundamental algebraic operation across computational science, machine learning, and graphics. Given matrix \(A\) of dimensions \(m \times n\) and matrix \(B\) of dimensions \(n \times p\), their product \(C = A \times B\) is valid because the column count of \(A\) matches the row count of \(B\).

If multiplying three scalar numbers like \(2 \times 3 \times 4\) always takes two operations regardless of how you group them, why does grouping a chain of matrices in different parenthesizations cause some computations to take orders of magnitude more CPU cycles than others?

To understand why grouping matters, imagine an assembly line building modular furniture. Suppose you have three components: tiny metal brackets, medium wooden panels, and a massive outer frame. If you attach the wooden panels to the massive frame first, you create a heavy, unwieldy intermediate assembly that requires high physical effort to lift and position just to bolt on the tiny brackets. If instead you fasten the tiny brackets onto the medium panels first, you handle compact, lightweight sub-assemblies with minimal physical exertion, bolting the combination onto the main frame only at the final step. The finished piece of furniture is identical in both cases, but the cumulative physical labor expended moving intermediate assemblies differs substantially. The analogy breaks when all matrices in the chain are square matrices of identical size \(n \times n\), where all intermediate matrices have identical dimensions and parenthesization produces identical operational costs.

15.4.1 Matrix Multiplication Mechanics and Compatibility

The resulting matrix \(C\) from the product \(A \times B\) has dimensions \(m \times p\). Each entry is defined by the inner product of the \(i\)-th row of \(A\) and the \(j\)-th column of \(B\):

Matrix Product Formulation and Operation Count: For compatible matrices \(A \in \mathbb{R}^{m \times n}\) and \(B \in \mathbb{R}^{n \times p}\), each entry \(C_{i, j}\) of the product matrix \(C \in \mathbb{R}^{m \times p}\) is computed by:

\[ C_{i, j} = \sum_{k=1}^n A_{i, k} B_{k, j} \]

Computing each entry \(C_{i, j}\) requires \(n\) scalar multiplications. Because \(C\) contains \(m \times p\) entries, the total number of scalar multiplications is:

\[ \text{multiplications}(A \times B) = m \times n \times p \]

For example, multiplying matrix \(A\) of size \(2 \times 3\) by matrix \(B\) of size \(3 \times 2\) yields a \(2 \times 2\) matrix requiring \(2 \times 3 \times 2 = 12\) scalar multiplications.

Matrix multiplication is not commutative: in general, \(A \times B \ne B \times A\). Indeed, if \(m \ne p\), the reversed product \(B \times A\) is not even dimensionally compatible. However, matrix multiplication is strictly associative:

\[ (A_1 \times A_2) \times A_3 = A_1 \times (A_2 \times A_3) \]

where \(A_1, A_2, A_3\) are compatible matrices. The final numerical values in the output matrix are identical regardless of how the multiplication chain is parenthesized. Algebraically, both evaluation orders yield the exact same sum over dual indices:

\[ [ (A_1 \times A_2) \times A_3 ]_{i, j} = \sum_k \sum_l (A_1)_{i, k} (A_2)_{k, l} (A_3)_{l, j} = [ A_1 \times (A_2 \times A_3) ]_{i, j} \]

15.4.2 Matrix Chain Associativity and Computational Cost

Although associativity guarantees identical matrix entries, the order of parenthesization changes the total number of scalar multiplications. In large computation pipelines, choosing an inefficient parenthesization order wastes computing time.

The Matrix Chain Multiplication Problem seeks the parenthesization of a chain \(\langle A_1, A_2, \ldots, A_n \rangle\) that minimizes the total count of scalar multiplications. Notice that the problem does not perform any matrix multiplications; rather, it determines the optimal sequence of parenthesizing the chain before any arithmetic is executed.

15.4.3 Fully Worked Numerical Example: Parenthesization Trade-Offs

Consider three matrices with the following dimensions:

  • Matrix \(A_1\): dimensions \(2 \times 3\)
  • Matrix \(A_2\): dimensions \(3 \times 4\)
  • Matrix \(A_3\): dimensions \(4 \times 2\)

We evaluate the computational cost under both valid parenthesization orders:

Option 1: Parenthesization \((A_1 \times A_2) \times A_3\)

  1. Compute product \(A_{1,2} = A_1 \times A_2\):
  • Input dimensions: \((2 \times 3)\) and \((3 \times 4)\)
  • Resulting dimension: \(2 \times 4\)
  • Scalar multiplications:

\[ 2 \times 3 \times 4 = 24 \]

  1. Compute product \(A_{1,2} \times A_3\):
  • Input dimensions: \((2 \times 4)\) and \((4 \times 2)\)
  • Resulting dimension: \(2 \times 2\)
  • Scalar multiplications:

\[ 2 \times 4 \times 2 = 16 \]

  1. Total scalar multiplications for Option 1:

\[ 24 + 16 = \mathbf{40} \]

Option 2: Parenthesization \(A_1 \times (A_2 \times A_3)\)

  1. Compute product \(A_{2,3} = A_2 \times A_3\):
  • Input dimensions: \((3 \times 4)\) and \((4 \times 2)\)
  • Resulting dimension: \(3 \times 2\)
  • Scalar multiplications:

\[ 3 \times 4 \times 2 = 24 \]

  1. Compute product \(A_1 \times A_{2,3}\):
  • Input dimensions: \((2 \times 3)\) and \((3 \times 2)\)
  • Resulting dimension: \(2 \times 2\)
  • Scalar multiplications:

\[ 2 \times 3 \times 2 = 12 \]

  1. Total scalar multiplications for Option 2:

\[ 24 + 12 = \mathbf{36} \]

Comparison of Costs: Both parenthesizations produce the same \(2 \times 2\) output matrix. However, Option 2 requires 36 scalar multiplications, while Option 1 requires 40 scalar multiplications. Choosing Option 2 saves 4 scalar multiplications, representing a 10% reduction in computational effort. In large chains of matrices, optimal parenthesization reduces computational cost by orders of magnitude.

Common Pitfalls:

  • Confusing Non-Commutativity with Non-Associativity: Matrix multiplication does not commute (\(A \times B \ne B \times A\)). You cannot reorder the matrices in the chain. Matrix chain multiplication only inserts parentheses; it strictly preserves the original linear sequence \(\langle A_1, A_2, \ldots, A_n \rangle\).
  • Ignoring Inner Dimension Alignment: Multiplying matrix \(A_{m \times n}\) by \(B_{p \times q}\) is algebraically defined only when the inner dimensions match (\(n = p\)). Any parenthesization grouping that pairs incompatible inner dimensions produces a runtime error.

Recap and Bridge: Matrix chain multiplication leverages the associative property to identify the parenthesization order that minimizes arithmetic cost without modifying output values. While checking all parenthesizations by brute force is intractable because the count of parenthesizations grows as the Catalan number \(C_{n-1} = \Omega(4^n / n^{3/2})\), dynamic programming solves the problem in \(O(n^3)\) time. In upcoming lectures, we will develop the full 2D dynamic programming table and back-tracking matrix to construct optimal parenthesizations for arbitrary chains.

15.4.4 Student Questions and Answers

Q: Why does matrix chain multiplication focus exclusively on minimizing scalar multiplications rather than additions?

A: Scalar multiplications are computationally much more expensive than additions. In nested loops, multiplication instructions dominate CPU cycle consumption, whereas addition counts scale directly with multiplication without altering optimal parenthesization.

Key Industry Applications

The algorithmic paradigms and data structures examined in this lecture underpin critical systems across modern engineering, logistics, finance, and scientific computing:

  1. Graph Routing and Transportation Networks:
  • Shortest path routing in terrestrial road networks, air traffic management, and telecommunications packet routing relies on Dijkstra's algorithm for rapid single-source path calculation under non-negative weights (distance, latency, or transit time).
  • Electric vehicle (EV) navigation systems use graphs with negative edge weights to model energy recovery through regenerative braking during mountain descents, requiring Bellman-Ford or generalized shortest-path algorithms to compute battery-feasible travel routes.
  1. Financial Engineering and Algorithmic Trading:
  • High-frequency trading and cross-currency arbitrage detection algorithms construct directed exchange-rate graphs where negative cycles indicate risk-free currency arbitrage opportunities.
  • Portfolio risk engines model transactional drawdowns and margin shifts using negative-weight edges, tracking asset transitions where negative weights correspond to portfolio losses or liquidation penalties.
  1. Logistics and Cargo Container Packing:
  • Freight shipping operators, air cargo carriers, and maritime container lines use fractional knapsack formulations to maximize the monetary yield of bulk cargo (such as crude petroleum, grains, and liquefied natural gas) loaded into weight-constrained holds.
  • Cloud resource orchestrators (such as Kubernetes and AWS ECS) use fractional knapsack models to allocate divisible computing resources (vCPU shares, memory bandwidth, and disk I/O throughput) across physical server clusters.
  1. Currency Dispensing and Automated Cash Handling:
  • Automated teller machines (ATMs), automated checkout terminals, and banknote sorting hardware use coin change algorithms to dispense the minimum count of bills and coins for requested withdrawals.
  • Multi-currency point-of-sale payment terminals employ dynamic programming to support international currencies with non-canonical denominations, guaranteeing exact minimal-token payouts where simple greedy heuristics fail.
  1. Computer Graphics, Robotics, and Scientific Computing:
  • 3D rendering pipelines and robotic kinematic simulators compute chains of affine transformation matrices (rotations, translations, scalings, and camera projections) to position objects in 3D space.
  • Hardware-accelerated graphics libraries (such as DirectX, Vulkan, and OpenGL) optimize matrix parenthesization to minimize scalar floating-point multiplications on graphics processing units (GPUs).
  • Modern deep learning frameworks (such as PyTorch and TensorFlow) use matrix chain dynamic programming algorithms to optimize tensor contraction paths in transformer self-attention layers and convolutional neural networks.
